# 战斗、修行与纸娃娃：详细设计与实施拆分：原型与设计场景

> 详细设计与候选：具体机制、参数、样本和验收意图须验证；已确认规则见[规则目录](../../rules/README.md)。

## 5. 原型场景

### 5.1 首次可玩原型应该能做什么

在既有世界边缘的安全校场/独立测试fixture中，用真实人物状态和明确起始物品验证：穿三套不同常服，练一次招架，学习一个护持动作，主角与伙伴应对两名风格不同的对手，主动撤退，途中保存读回。

正常世界的校场需要比试同意、非致命动作与停止规则；测试fixture可以独立重建用于重复测试，但不能把“重置测试”按钮当世界中的免费回血/复制装备。原型还没有完整供给/社会后续时明确标记其范围，不假装一场校场已经完成开放世界战斗。

## 6. 未来定义和持久化的必要字段

只列规则需要，不在本轮预建JSON、脚本或空场景：

| 定义 | 必需语义 | 运行实例需保存 |
|---|---|---|
| 动作/招式 | 获取条件、可用媒介、阶段、形状/高度、成本时点、取消/中断、冷却组、目标/友伤规则 | action_id、参与者、锁定意图、阶段/时刻、已付成本、已命中对象 |
| 功法/持续效果 | 运转条件、资源流、兼容、心神、停止和代价 | 来源实例/人物、开始/结束、占用、剩余和已提交脉冲 |
| 物品/穿戴 | 堆叠规则、用途、占用/覆盖、形态资源/锚点、质量的实际意义 | 稳定实例、唯一位置、损坏/染色、必要来源与权利引用 |
| 修行节点/教学内容 | 所属领域、可见线索、路径、前提、学习机会、规则效果和取舍 | 人物所知、来源、学会/练习进度、证据引用、准备方案 |
| 观察/身份主张 | 线索/距离/光照、所需知识、核验渠道、失效/更新条件 | 谁看见/认出、何时、来源、判断上下文版本 |

堆叠材料不为每份生一实例。模板定义只读，保存资料的内容版本；人物持有书卷/秘本和脑中所学分别存。缓存、描边、粒子、UI排序不是权威状态。

新字段引入同包就有schema、合法范围/引用检查、旧格式迁移或明确拒绝策略。必须支持进行中的挥击/符术、半完成穿脱、借物、已学/准备/冷却、飞行物、观察与未结世界责任共同恢复。坏档在独立候选拒绝，不能只恢复衣服丢掉借用债务。

## 7. 整体验收：不是三个菜单各自能开

全部为未来验收。领域细节分别见三个设计文件，本表验证相互配合。

| ID | 场景 | 通过标准 |
|---|---|---|
| CC1 | 同人同招同兵器，分别穿素袍、工服、礼服 | 衣色/价格不凭空改攻击；用途、防护/负担和社会线索各自可解释 |
| CC2 | 不会剑术的人借到名剑，学过剑术的人拿普通剑 | 器物有实际长短锋刃/功能，熟练与招式不同；不自动授整套技能，也不保证普通剑必胜 |
| CC3 | 药师、工匠、商旅各完成一次自己的局势 | 有生计/成长/求助/避险，未点攻击盘仍能生活；守卫和物资真有来源 |
| CC4 | 看见剑术节点但没有教学；读书、观察、练习和实战后再学 | 图连接不是付点解锁；每阶段学到什么/缺什么可查，木桩/杀人不能刷所有领域 |
| CC5 | 学会多招，准备4招并运转功法/护持/器物 | 学习数与同时运转分开；超预算/不兼容有解释；非战斗手艺不挤战斗栏 |
| CC6 | 衣物被借走/武器被缴械，中途读档 | 同一物品唯一位置；外观/可用动作更新；借物责任/冷却不丢失 |
| CC7 | 乔装守门→进入接待处→申请支取 | 不同观察者可先信或核验；公仓仍查真实许可；熟人不因换衣失忆 |
| CC8 | 受伤、穿脱、修补、切换功法、投掷后丢拾法器 | 没有回血、回灵、刷新冷却/符纸或失物责任漏洞 |
| CC9 | 重击前摇、短缓冲、招架、连续控制、救助 | 前摇/范围可读；正确回应有效；无无限连控；救治有资源与中断 |
| CC10 | 调整服饰图层/帽高/LOD/缺帧回退 | 只改表现；碰撞、射程、人物身份、隐藏信息与装备事实不变 |
| CC11 | 暂停下令→等待快进→受袭→切区/重启 | 一个世界时间；世界事务连续、危险在边界打断；已提交结果不重抽 |
| CC12 | NPC在玩家缺席时学习、换衣、护送、战败 | 依自身所知/资源行动，有因果可追踪；不因入场重新装备/治疗/生成资产 |
| CC13 | 宗门管事在冲突中失能，仓库有旧账与借物 | 预约/职位清理或代办，基本生活可接续；机构和私人物权没有随身体删除 |
| CC14 | 导出测试包下多套衣服/技能/中文说明 | 资源族匹配、动作关键提示不被遮挡，无开发机器字体或节点路径依赖 |

原型可以选择相应场景子集；已开放行为仍需覆盖失败和存读边界。

## 8. 怎样判定这套设计是否有趣

作者自测先回答：能否靠看招与行动改善结果；停手/退让是不是有价值；伙伴不是纯增加血条；换衣是否表达生活又不过度强迫；修行图是否让人想到下一步去学什么而非只找最短加伤路径。

之后让未读方案的人完成三个短任务：赴会交涉、护送受袭、为一个实际问题学习新本领。记录他是否知道为何遭拒/受伤、如何换装/改准备、是否觉得非战斗路线被迫补攻击装。人玩不明白时先改信息与规则，不先添100个节点。

## 9. 设计风险与最小处理

| 风险 | 最小处理 |
|---|---|
| 五个参考作品互相拉扯 | 只取动作衔接/可读性/指令/网络结构各一层；统一正交俯视和共同世界 |
| 无职业最后变成万能全学全开 | 学习渠道/时间机会、训练与准备/运转取舍共同作用，不用出身锁定；普通手艺无需遗忘 |
| 社交穿衣变成全世界魅力评分 | 只给观察线索、场合判断和实际核验，不把衣价自动折成人情/权限 |
| 外观为主被误解成防具毫无作用 | 有真实覆盖/材质/负担，特殊法器有功能；普通衣饰无通用攻击词条 |
| 持久伤亡破坏动作游戏试错 | 先受控切磋与倒地/撤退；危险有预警，普通模式可存读，不靠无原因满血重生 |
| 图很大但内容空 | 第一包8–12节点验证学习/生活，40节点是首内容集预算，完整大图按实际选择增补 |
| 秒级战斗与分钟模拟各走各的 | 验证共同时间、格内位置和受支持存档的迁移；正式数值由试验确定 |
| 多套战斗/物品/社会真值失步 | 各领域明确负责人，runtime与UI只意图/查询；穿戴引用不存第二套实例 |

动画或内容编辑确有需要时，可按[资源候选](../../research/godot_resource_candidates.md)比较工具和许可。

## 10. 补充设计约束

应战映射与真实拔取、收放分开；近战与飞行物友伤和身体阻挡遵循一致规则；纸娃娃表达连续瞄准；同刻命中、倒地、打断与输入缓冲需要持续；自动降速不得泄密，学习节点不锁基础人类行动。逐方向外观依据[八方向合同](../../../docs/specs/presentation/eight-directions.md)。这些约束仍需原型验证。
