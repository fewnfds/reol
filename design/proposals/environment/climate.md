# 天地、气候与地势：世界基础环境方案：历法与气候

> 详细设计与候选：具体机制、参数、样本和验收意图须验证；已确认规则见[规则目录](../../rules/README.md)。

## 1. 采用的基本结构

```text
唯一世界时间 ─→ 历法/昼夜/四季 ─→ 地区气候与天气过程
                                      ↓
原地形/水源/材质 ─→ 室外背景条件 ─→ 局地温湿、风、积水/积雪
       ↓                              ↓
万物五行构成 ─→ 非消耗环境影响场 ─→ 建筑、材料、身体的实际响应
       ↑                  ↑
       └── 地势/水路/开口/布置 ──┘
                  ↓
           堪舆者观察与解释
```

每条箭头只传递已定义的具体作用。太阳可为现实热量和某种修行提供不同来源，但二者不共用一个万能能量值；雨水和五行环境影响中的水通道也不是同一份状态。身体、植物、物品、库存仍由原领域保存，环境不能复制它们。

### 状态归属

以下为建议模块职责，按需要创建，不提前注册一套空autoload。

| 领域 | 唯一保存的状态 | 从别处读取/派生 |
|---|---|---|
| 原GameClock | 世界整数毫秒、暂停/快进及欠算 | 日期、季节不另走时钟 |
| 历法规则 | 版本化历法定义，无第二份当前时间 | 年/月/日、节气阶段、太阳位置与季节曲线 |
| 气候 | 地区气候定义、已排定天气过程/序号及进行中风雨 | 地形高度、季节、日照；不依镜头生成随机数 |
| 环境 | 室外固定空间响应、室内唯一室温与可核对归属、湿润/积水积雪、结算时刻和启用边界 | 季节中性温度、冷热等级/圆形场、房间围合；不复制原物或依赖可变房间编号 |
| 原材料/结构/生命领域 | 组成、含水/耐受、真实热源/水源/生长/损坏等对象状态 | 环境条件，不能把湿衣/库存水另存一份 |
| 五行环境/灵气接缝 | 原物品/材质派生的五通道影响；可吸收灵气仍由原物品持独立储量 | 来源强度/范围、地势/布局、修炼环境响应；积攒与容量细则后置，场强不作可花库存 |
| 风水 | 布局/连接版本和必要的解算进度；大部分缓存可重算 | 同一山水/建筑/灵源；不保存万能吉凶或幸运条 |
| 原个人认识/观察 | 当时感受到什么、方法/来源、估计与报告 | 只读环境投影；不能查询就免费鉴定 |

### 新规则启用与旧档接续

气候、冷热、生态响应与灵源分别记录规则版本及`activation_ms`，同一作用只有一个启用边界，不另走时间。新世界按开局定义初始化；旧世界从迁移时的原保存时刻启用新增作用，记录初始状态的来源与策略，不用新历法重算此前的风雨、寒热、生长或灵气消耗。不得因冬季读入旧档就倒造过去的冻伤、歉收或灵源枯竭。

固定晴雨切换为天气过程时，保留原`epoch_ms`所确定的当前雨相与剩余时段；可用有界的兼容过程完成这一段，再接新气候序列。迁移不改变原衣物/床的湿润、真实已收雨水、温石储量和进行中动作。尚未存在的温度/灵源按明确的当前初值登记，不能把它们当作已积累多年、可免费兑现的历史收益。后续修改历法或气候参数也须按版本迁移，不能静默覆盖已排定过程。

## 2. 时间、历法与四季

沿用`GameClock.elapsed_ms`。日常保持可暂停实时生活；主动等候/修炼可快进，重要危险、当事消息和必须选择的事务打断。年度变化从原时刻推导，不能用系统日期或新增倒计时。

开发默认采用**360日一年、12月、每季90日**的虚构简历，开局春季；一天仍为现有24世界小时。先采用简历，避免把真实阴阳历/闰月当玩法前置。24个时令节点可作为同一年度曲线的名称，不另引入天文精算。年长、寿命和转生仍须其原人生领域实现，历法换页不自动完成人口世代系统。

季节不是全地图同时换皮：各地有不同基温、季节幅度、海拔、雨季与昼长；山顶结冰时谷地仍可生长。过季连续改变温度/日照/雨量概率，阈值发生作用时才产生具体后果。季节长度是可调整定义，禁止为一次截图而改时钟导致所有旧档日期漂移；正式迁移要保留原时间并记录采用的历法版本。

**首步出口**：能读日期/季节，两个地区有不同日夜温度曲线；到冬季不会仅因为名称变冬就扣每个人精力。跨季快进与逐段推进得到同一已支持环境状态。

## 3. 气候与天气

气候回答“这里长期通常怎样”，天气是一次有起止、强度与变化过程的局面。晴/阴/雨/雪/雾、风向/风力、云量先服务具体用途，不一次加入台风、全流体和全球大气。

地区以明确的地理气候区域归属查询，不沿用目前“离哪个住处近”的原型作为完整世界规则。天气从世界seed、地区/气候单元、过程序号独立取样，排定后保存；镜头、读取顺序、NPC人数、开关雨线均不能改变下一场雨。相邻气候单元可以共享天气锋面ID或相关源，避免穿过聚落边界立刻从暴雨变烈日；第一版先做相关过渡而非气象数值预报。

降水有明确落点和去处：屋面遮蔽、地面入渗/径流、有限泉源/容器接水、衣物湿润。河道供给与取水仍引用真实来源。改变水路需要原地形/施工与守恒的水量事务，不能因为“下雨”直接给仓库无限加水。雪需要低温与真实降水过程，融雪计相应水量；取雪造水需要积雪质量账。

表现从真实天气投影：雨线、雾、风摆、积雪图只在附近绘制；暂停、卸载视图、关闭特效不影响雨量。看到远处云并不意味着知道远方每个人当前处境。
