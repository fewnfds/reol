## 素材：先把用途与权限弄清楚

“免费”“开源”“允许商业使用”是不同判断。代码仓库的 MIT/GPL 文件不自动覆盖仓库中的贴图、音乐、字体、商标或从别处引入的素材。商业参考游戏用于理解机制，其贴图、角色、音效、名称和标志不属于可直接借用的开源素材。

下表是候选来源，**未下载、未导入、未最终选型**。页面许可信息支持初筛；真正引入时必须核对下载包中的文件和许可。

| 候选 | 本轮核实与拟用途 | 使用条件与选择 |
|---|---|---|
| [Kenney Tiny Town](https://kenney.nl/assets/tiny-town)、[Kenney 支持说明](https://kenney.nl/support) | 官方页面标为 CC0；适合初期地表、房屋和道具的样例 | CC0 可商用和改作；仍保存包内许可证。现成包不必作为最终国风方向，避免和代码人物产生比例冲突 |
| Screaming Brain Studios：[Top Down Dungeon Pack](https://opengameart.org/content/top-down-dungeon-pack)、[作者下载说明](https://screamingbrainstudios.com/downloads/) | 具体 OGA 条目标为 CC0；作者说明素材包为 CC0。可用于洞府/遗迹占位 | 选择正交俯视版本，核对尺寸和视角；不因为同作者就忽略实际文件内容和包内说明 |
| [Whispers of Avalon: Grassland Tileset](https://opengameart.org/content/whispers-of-avalon-grassland-tileset) | OGA 条目列有 CC BY 3.0 等选择；是“非 CC0 仍可能可商用”的具体例子 | 若选 CC BY 3.0 路径，按作者、标题、来源、许可链接和修改记录署名，并检查分发条件；不是推荐直接混搭的最终包 |
| [Universal LPC Character Generator](https://github.com/LiberatedPixelCup/Universal-LPC-Spritesheet-Character-Generator)、[许可与署名说明](https://raw.githubusercontent.com/LiberatedPixelCup/Universal-LPC-Spritesheet-Character-Generator/master/README.md) | 可组合身体、服装和动画；README 明确不同部件对应 CC0、CC BY、CC BY-SA、OGA BY、GPL 等许可，提供导出署名表 | 不把 LPC 当统一 CC0 包；按实际部件选择可兼容许可并导出完整来源。若改色/拼装后的义务不清，先用自制人物替代，不把整个生成器作为运行依赖 |

许可原文入口：[CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/)、[CC BY 3.0](https://creativecommons.org/licenses/by/3.0/)、[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)、[CC 官方 FAQ](https://creativecommons.org/faq/)。它们说明可商用范围及条件；不能从“可商用”推导出“不需要署名、可施加任意限制、可任意更换许可证”。CC BY-SA/GPL 不是不能商用，但引入之前需要评估改作、再分发和分发平台条件，不列为默认省事路线。NC、ND、来源不明或授权链不清的素材不用于计划中的可修改商业资源库。

音乐、环境声和音效也逐项登记。编曲授权、录音授权、音源授权不能互相代替。字体、音频和界面图标不因体积小而豁免来源记录。

### 可复核的引入记录

沿用 [Assets 约定](../../../assets/README.md) 和 [第三方声明](../../../THIRD_PARTY_NOTICES.md)，按实际需要创建清单，不先堆空目录。每个包至少记录：

| 字段 | 必须回答的问题 |
|---|---|
| 名称、作者、原始来源 URL | 具体文件是谁创作、从哪里取得？不能只写“GitHub”或“OGA” |
| 发布版/commit、下载日期、原包 SHA-256 | 后续能否找到同一份内容、发现被替换？无版本号用哈希固定 |
| 许可证标识、版本、原文、所选许可路径 | 多重许可究竟采用哪一个？源码与素材是否分别授权？ |
| 文件/部件范围、署名文本 | 实际用了哪些，不只记录素材包封面？LPC 要到部件级 |
| 修改记录与产物映射 | 哪些经过改色、裁剪、拼装、子集化、重录或转换？ |
| 技术规格 | 视角、原生尺寸、帧表、透明度、锚点、滤镜、色盘、音频格式、内存预算 |
| 审核状态 | 候选、占位、已核许可、已引擎验证、可发布；未完成核查不得标“可发布” |

发布包提供可发现的 Credits 和必要许可文本；从清单生成署名，抽查不漏项。不自动宣称改变游戏自身许可证；项目自身发布许可尚待发布阶段确定。

## 代码生成表现：能延续现有工作的路线

本轮实际读过的现有表现代码：

- [PawnVisuals](https://github.com/fewnfds/reol/blob/a493bf0/scripts/entities/pawn_visuals.gd)：衣襟、发髻、地影和选中标记，共用绘制人物；不拥有身体状态。
- [FacilityVisuals](https://github.com/fewnfds/reol/blob/a493bf0/scripts/world/facility_visuals.gd)：井、药圃、山门与建筑的几何剪影。
- [TerrainVisuals](https://github.com/fewnfds/reol/blob/a493bf0/scripts/world/terrain_visuals.gd)：稳定变体和小型地表图集。
- [ReolUITheme](https://github.com/fewnfds/reol/blob/a493bf0/scripts/ui/reol_ui_theme.gd)：颜色、文字、按钮和面板的共用样式。

推荐延续它们的职责：纯模拟只输出状态；表现层决定衣着、动作、材质和特效。换精灵不得改库存、人物 ID、格子占用、命中判定或权限。

| 对象 | 玩法开发期 | 正式美术期 |
|---|---|---|
| 人物 | 共用剪影＋衣色/头饰/工具表示角色；需要时先补走、做事、受伤、施法的清楚状态 | 先锁一个人物的正交比例、真八方向与动画，再做同族服饰和装备层；不一次生成海量互不一致人物 |
| 建筑 | 明确占地、入口、工位和仓储容量；轮廓区分功能；施工/损坏/停工能辨认 | 按村舍、宗门、工坊等模块做屋顶/墙/门/招牌，保证同类尺度、遮挡和切换规则 |
| 地形 | 稳定色块、边界、道路和可走提示；渲染不反过来决定规则 | 制作少量拼接正确的地形族，检验连续3×3拼接、海量重复和远近缩放 |
| 战斗/修炼 | 瞄准范围、前摇、命中、闪避、受伤、突破结果可读；廉价几何特效足够 | 补冲击、剑气、符箓、灵气和少量音色；先保证拥挤战斗可辨认，再添粒子 |
| UI/地图 | 信息组织、键鼠焦点、缩放与因果说明随玩法实现 | 统一图标、字体、装饰和音效；文字保持代码/本地化资源，不烘焙进图 |

代码生成图集时固定种子和生成参数；能离线烘焙的族图集优先烘焙，不每帧重画复杂纹理。生成器不复制商业图片或轮廓。AI 栅格图可作为后期绘制工具，但也必须经过尺寸、透明度、拼接、逐帧稳定性和实际游戏比例检查；记录工具、日期和人工修改，不把“生成成功”当素材验收通过。

### “玩法先行”的实际门槛

玩法阶段仍需要可读的画面、基础反馈和可用 UI，否则无法判断操作本身是否好玩；这里推后的是大量正式资产和装饰，而不是推后所有体验验证。

正式美术批量生产前需要同时满足：

1. 个人生计、修炼冒险、据点生产经营三条循环都能用占位资产完成，并出现真实取舍。
2. 离场推进、失败恢复、跨区域事务和完整存读通过各自验收，换图不会掩盖规则缺陷。
3. 画布、逻辑格尺寸、人物/门/道路比例、相机缩放范围、碰撞与锚点约定稳定；地图规则不依赖最终贴图分辨率。
4. 选一张“宗门院落＋几个人物＋工作＋小战斗”的样板图，在实际尺寸和缩放下验证色盘、剪影、昼夜、迷雾和信息密度。
5. 样板的许可、资源预算、中文字体和音频路径能进入发布包；再按清单分族替换占位。

采用“样板→小族→场景验证→批量”的顺序。若公开包难以统一国风方向，就以现有代码剪影和自制模块为主，开放素材补充合适的基础图块/音效；不为利用某个免费包改变整个玩法或视角。
