## 从资料与场景中保留的设计判断

- **人物要有数值，但数值服从实际用途。** 体魄、筋力、灵巧和悟性是可验证的候选，不能通过改名就获得修仙感，也不能因反对传统属性而删掉一切个体素质。身体、掌握、修持、资源、认识与身份分别成立。
- **宗门的核心资产包含传承与共同条件。** 真实可用的资料、愿意投入时间的老师、修行来源、住所、照护和合作，让共同生活能支持个人道路；不靠一座粮仓或宗主战力总分证明宗门成立。
- **回报不只有币。** 履职历史、实物、具体服务安排与私人感激不同；记录不能凭空创造商品，师承不能凭空创造本领，亲近不能凭空创造授权。
- **有限认识不取消真实后果。** 行动失败、材料短缺、教师缺席和消息晚到都可成立。目的、承诺、方法与原宿主反馈要接起来，而不是用全知后台替成员瞬间办妥。
- **从个体到共同生活逐片建设。** 简单材料、公私取用、教习和关系各在真实样本中接入，不先写完一个通用ERP、社交网络或容器引擎才开始游戏。

这些是开发者的产品/工程判断，不声称是上述来源可直接证明的唯一正确设计。生成的日常片段仅用于暴露共同机制的缺口，不作为固定剧情与功能承诺。

## 顾问复核与独立纠偏

原提示、完整原答和错误报告均留忽略目录`.local/advisor/sect-foundation-20261116/`。完成三轮咨询：第一轮分角色/关系、宗门/资源两题，各取得hydrogen完整回答，两题argon均为上游503；第二轮`integration-r2/`与第三轮`final-r3/`均取得两模型完整回答。合计6份完整答复已通读，2次失败不算有效意见。第三轮基于正式草案静态复核，未新增可独立验证的外部来源；所有轮次均未运行本机。

第一轮促成传承/照护与供给相接、关系拆分、具体时间/资源和文学场景反推共同能力。第二轮两份完整回答均已通读，促成了**堆叠材料的公私批次/受托加工合同**、移动容器的访问失效边界、同一教学结果的多方义务关联与设施竞争的明确验证问题。没有把顾问的主张全部照收：

| 顾问论断/扩展 | 独立判断 |
|---|---|
| HP与伤病不同就是双账，应把HP0改倒地 | 急性受创与持续状况可以各有含义；不擅改死亡玩法，仅禁止同一事实重复管理 |
| 资源分存不同owner必然有双账，立即砍mana并表 | 物理位置不同不等于语义重复；原访问/作用接口可演进，保持单一资源身份与提交责任，保留P4范例与存档边界 |
| 悟性导致差异便等于锁死人生，应删去 | 有界效率差异与永久禁入不同；需要指导、经验、适配和可改条件相互作用，不预设天才必占全部资源 |
| 四点心神、固定主兼修/四槽、恒定后勤人数已定 | 均不是用户已定规则；旧候选也不因顾问重复引用而变成事实 |
| 一水可做1.5餐，使用引水必然第四日断炊 | 配方是2粮1水得3餐；可用机会成本还取决于其他限制。引水与手工养护共用后果/耗水，现有术法未另扣qi；无产水时两种做法都需供水，不能据此推出必崩时日 |
| 木愈可医好持续旧伤、救治他人或修工具；短休可按0.5秒分段补给 | 当前样例是人物自疗HP；持续伤病/他人治疗另需方法。休息按实际完成时刻提交，不能按线性均值假造中途收益 |
| 百人必然活锁，必须预建所有服务远距队列 | 当前交互可在接近阶段预约，短操作的路程占用确需测；但已有个人失败反馈/退避。先测到场、占用、重试与争用，再选择分布、方法、预约或限定安排，不把推演当现存缺陷 |
| 必须10～14日、固定初值和劳动比例才算通过 | 观察窗口按真实代谢、再生与事务周期确定；用重复净流量、最低存量、真实教学进展和扰动辨别，不用未经验证的固定门槛 |
| 固定配给扣罚、老师爽约必降信任、师承无教学必薄情 | 这些是特定制度/评价候选，不是统一心理规则；取决于已有背景、当事人知情、承诺、价值与实际原因 |
| 一课只许公差/私约二选一；逾期即可知道谁侵吞 | 同一结果可按明确约定支持多方目标/责任，但不能重复同一支付；逾期不是原因真值，出库记录不提供未目击事件的全知结论 |
| 办理必须永远静态实物、悟性学成后无用所以必须附加术法降耗 | 首轮可采用局部记录点，仍保留明确条件的其他投递；属性在有关活动中消费即可，不为常驻用途扩作用范围 |
| 所有法器必须主动有代价、永禁嵌套、必须保住搬运工 | 法器可有定义明确的被动功能；有内容容器套装是首轮范围限制；允许术法真实改变劳动，不以保岗位强加琐碎 |

本节的取舍不会把尚未实现的未来能力登记成当前缺陷。顾问没有运行本机，长答、多答一致和故事的可信感均不能替代源码与实际验证。

第三轮审查后补清了：批次加工/交付的稳定结果关联与约束解除、未来单次赴约的加入窗与有界等待、部分交付不等于全部履责、转托后余料责任，以及已知在途份额对缺口重检的影响。公私批次细则仍只维护在物品正文，其余页面引用，未另造覆盖全部领域的事务引擎。

未采用第三轮的“半成品/损耗都按已交餐数乘配方倒算”“部分交付一律自动结清全部责任”“所有容器入公库立即清掉所有用途”“跨域物资、责任和奖励必须一次大事务提交”等过度收束。正常办理的社会准入与物理上能否强取分别说明，同一结果可支持多个合法目的但不能重复同一支付。对“所有取餐都独占预约”的推断再次核源码：`take/put/eat`不走该独占锁；不能由床位串行推导餐箱吞吐。

顾问曾建议用生活/履职/求学的小规模样本贯通接缝；用户进一步明确，应先审查和补齐共享顶层框架，不能把小功能做成独立demo。当前源码审查与迁移边界归[共享框架审查](../../docs/engineering/architecture/foundation-audit.md)，建设次序只归主计划。没有采纳固定8～12人/院落数、80%例行比例、必然帧超时、零底层开发和简单复制便扩到百人的断言：实际粮水来源、取水与通用教学尚需补；小规模检查只检验同World公共机制，不代替正常运行链和百人组合。

## 静态算术的用途

按源码基础代谢与设施参数所做的独立算术保存在本机`baseline-arithmetic.json`，可读结论只维护在[宗门生活的参数说明](../systems/sect_life.md#源码参数告诉了什么尚未告诉什么)。它用于识别初值遮蔽、测试窗口和需要测的流量，不宣称粮水、住房、医疗、修行或百人性能已经配平。
