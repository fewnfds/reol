# 世界与交互原则：环境、众生与自主行动

日期：2026-11-03。状态：**理念与后续设计依据，不是全领域玩法交付**。用户已恢复实施，原Goal为active。三项统一请求有[首包验证](../../docs/qa/20261103_interaction_requests.md)；其余方向按实际包推进。实际功能见[当前功能清单](../../docs/FEATURES.md)，已有验证见[BASELINE](../../docs/BASELINE.md)。

本文把最新讨论接入[世界总纲](self_consistent_world.md)。下文明确区分用户表达的方向、对例子的澄清与开发建议；具体模型、参数和实现顺序可通过原型调整。树、五行、风水等名词不因写入文档就成为已实现系统。

## 1. 本轮收集到的方向与边界

| 主题 | 用户表达的方向 | 边界与当前状态 |
|---|---|---|
| 天气与温度 | 天气有视觉、环境和生活影响；温度是影响万物的环境条件 | 当前已有固定局地晴雨及有限实物后果；温度/四季待做，[环境实施合同](../../docs/plans/world_environment.md)已补齐，温火石仍不是通用热力学 |
| 植物与生态 | 植物参与自然循环、提供材料，也可拓展为有意识的可玩存在 | 当前只有有限再生来源；没有完整植物生命周期 |
| 非人与妖怪势力 | 普通动物、妖兽、精怪及其组织都属于同一世界 | 有雀妖与寄魂局部样本，完整种族/妖怪势力未实现 |
| 五行 | 借中国传统五行组织物性、环境与修仙用途 | [新方案](../../docs/plans/world_environment.md)区分物性/亲和/真实灵机与有成本转化；待实施/验证 |
| 风水堪舆 | 地形、房屋、物品与人物相互影响 | [新方案](../../docs/plans/world_environment.md)按真实山水/建筑/源流推导局地条件；待实施，不是万能吉凶分 |
| 建筑与破坏 | 墙、门窗、家具组成房间；建筑、植被与地块可受改变 | 模块化方向明确；成品建筑是否需要，保留为体验/技术选择 |
| 自动战斗 | 玩家可编排自己及下属的策略；下属是否执行归社会规则 | 尚无玩家策略编辑器或可编程战斗运行器 |
| 势力经营 | 联盟、密教、山寨、宗门等可由玩家组织，避免固定发展模板 | 机构记账有样本；通用组织创建/治理未实现 |
| 移动 | 希望接近 Warcraft III 的顺滑移动与即时战斗；性能优先 | 当前已有连续位置，路线仍依格路，后续须实测手感与规模 |
| 通用交互 | 玩家向对象提出事项，由对方理解、判断并反馈 | 三项请求已有共同意图门面；任意交互/条件/能力发现与AI仍待做 |
| 世界对象 | 活物、植物、物品都能成为地上可选择、可作用的对象 | 同等可寻址不等于拥有相同组件/心智/更新频率 |

两项用户明确的补充：

- **自由文字主要面向未来 AI；动作、对象、条件补全主要面向脚本操作；没有 AI 也必须能玩。** AI 不限于风味对话，但实际行动仍须受世界规则约束。
- **树开局是扩展思路的例子。** 优先讨论已有微弱意识、能作选择的树类生命；不随机强迫玩家作为无行动余地的普通树终老。缓慢或被动的一生可以是玩家主动选择，不意味着所有树都应觉醒或最终化为人形。

## 2. 交互首先是沟通与行动过程

建议把一次请求写成“谁向谁，通过什么方式，请其对什么对象做什么，在什么条件下做”。玩家提交请求，与对方实际执行是两个过程。

例如：玩家向一只普通小鸟请求鉴定未知宝剑。玩家成功发出声音，并不意味着小鸟听懂“鉴定”，更不意味着它拥有识剑的方法。它可能只受惊、注意到亮光或继续觅食。若它是懂人言的鸟妖，也可能不懂剑、无法接近、索要条件、推荐别人，或作出错误判断。

建议采用以下共同流程，而不是直接调用接收者的能力：

```text
表达意图 → 信号能否抵达 → 接收者怎样理解
    → 自认为能否办理 → 是否愿意/有权承担 → 协商或回应
    → 取得工具与执行条件 → 花时间执行 → 观察结果并留下经历
```

“没听懂、不会、不愿、暂时没空、没有权限、实际没做成”应能分别成立。情义、职责、风险、报酬、当前工作、身体条件和替代办法影响决定；内部可用有边界的社会骰表达不确定性，不用一骰跳过不可能的身体/知识条件。同条件重复请求沿用已有判断，情境或证据确实变化才重评。

交流可以用来发现能力：问“你会看这把剑吗”，得到的是对方的自述、推荐或可观察表现，未必可靠。不能向普通玩家暴露后台完整工具列表，也不能把领域阅历压成一个万能智力门槛。工匠、武痴、鸟妖可能理解同一物的不同方面。

## 3. 按钮、脚本与 AI 共用有限的行动入口

推荐的意图内容包括：发起者、接收者、动词/事项、目标引用、工具/媒介、条款、完成条件和停止条件。这里是语义约束，**尚不是已实现的数据格式或类名**。

| 输入入口 | 建议职责 | 实际结果由谁决定 |
|---|---|---|
| 游戏界面 | 提供可发现的动作、对象、条件、追问与回应；保存常用安排 | 世界规则与实际参与者 |
| 玩家脚本 | 组合已开放动作，按所知观察触发；可暂停、撤销、人工接管 | 同上；脚本不额外获得全知或权限 |
| 未来 AI / 自由文字 | 理解表达、提出澄清、协助选动作/条款、组织对话与计划 | 同上；生成文本不能自行结算物资、许可或伤亡 |

AI 不可用时，玩家仍能找到当前受支持的事项、补全必要对象并看懂回应。对没有实现的动作，诚实说明边界；不能只生成一段“已完成”的故事。普通交易、已有协议和固定职责可一键复用，不要求每次买饭都重新谈判。

脚本动作补全可以只展示主体有根据知道的对象和方法；开发诊断另行查看内部原因。玩家脑中记住的信息不等于角色已学会方法、持有证据或拥有控制权。

## 4. 自动策略是计划，组织命令需要传达

用户要求的可编程战斗可先表达为有限的观察—条件—行动规则，例如“看见近处同伴倒下时先掩护撤离”“对方起势且退路可达时侧移”。开发建议先有可用模板，再提供条件编辑与人工覆盖，避免编程成为参与战斗的门槛。

策略只使用本人可感知的信息；命令需要通信与实际接收。玩家可以发布常备命令或职责，已同意的正常执行不每帧重掷社交骰；风险突变、失去通信、违背底线或承诺时才重新判断。人物可以不懂、拖延、撤退或拒绝，反馈须区分原因。

这套语义也可用于护送、巡守、运货和救援。它不承诺开放任意代码执行，也不在本轮决定脚本语言、图形编辑器或依赖插件。

## 5. 物、生命与环境有共同接触面，内部各不相同

同一把剑、树木、活物和房屋都应能回答：在哪里、被谁保管/使用、能接收哪些作用、留下什么变化。可被点选或作用，不代表都有背包、血条、工作表或人类头脑。

推荐按实际需要组合身体/结构、材料、容纳、生长、感知、意图、通信等能力。普通树有生长与受损过程；树妖另有主体与认识。戒指是载体，戒中人是有意志的主体；持戒者不自动控制后者。具体引用、所有权与执行权沿用[众生](beings_and_lifeways.md)和[现有架构](../../docs/ARCHITECTURE.md)的分工，不能靠共同“单位”名词造第二份状态。

生态既产生压力，也产生新办法：雨水影响路况和用火，遮阴影响作物和居所，鸟类迁移改变种子/虫害与见闻来源。不同生命依赖不同条件，不能只给所有人统一增减心情。区域、房间与少数关键对象可分层计算；远区按重要变化推进，不逐帧模拟每片叶子。采样精度与误差须随原型验证。

## 6. 五行与风水要产生可理解的作用

五行是世界方向，具体模型由开发验证。建议允许复合材质、加工和状态变化；“属木”不能代替含水、构造、燃点、药性等具体属性，也不表示任何“火”都必然瞬烧一切“木”。实际效果需方法、媒介、投入、环境与承受条件成立，不能凭标签配对生成产物。

建议让风水从可影响的地形、水路、朝向、房间开口、材料、摆设、用途和灵机流动中产生。不同生活/修行目的可以需要不同条件，避免一种最优布局供全体复制。堪舆者的认识有方法、观察与误差，也可能形成相互竞争的理论。

这保留仙侠法则的空间，不强迫所有现象符合现实物理。隐藏条件应真实存在并可追查；不能因为玩家找出好办法便临时改规则。具体模型已由开发按本次授权写入[环境方案](../../docs/plans/world_environment.md)，数值与精度仍须原型，尚未实现。

## 7. 建筑、场景改变与持续后果

推荐先让墙、门窗、家具和用途共同构成房间，实际结构决定通行、遮挡、保温或其他已支持作用。若需要少量可直接摆放的建筑，优先作为同一构造的预设蓝图或装配便利；是否采用仍须看操作量与性能。

砍树、拆墙、焚毁、挖改地块应改变实际对象与可达性，带来材料、废物、修复需求或损害责任。拆建不能重复发放同一批材料；离开或读档不能恢复原样。具体返还、结构稳定和蔓延只在首个场景需要时实施，不一次构建完整破坏物理。

移动方向维持正交俯视。建议身体使用连续位置，格子继续负责地形索引、寻路与建筑边界，表现层做插值与合理避让；这接续现有连续位置，不另起坐标宇宙。最终方案以同机性能和实际战斗手感为依据，未测量前不宣称一定更快或已达到 Warcraft III 的顺滑程度。

## 8. 组织是可构建的关系与制度

用户希望玩家自行形成联盟、秘密组织、山寨、宗门等范式。建议从以下内容组合：共同目的、参与者、成员资格、承担的义务、资产及保管、决定权、通信渠道、履行/追责方式与退出条件。

组织可没有固定领地，成员可重叠，权限可以分散；秘密组织的对外身份与真实协作网络可以不同。妖怪组织沿用同样的合作机制，但栖地、身体、食性、修行方法与文化会改变实际利益。不能把所有组织改名后仍做成同一座“招人—种田—升级大厅”的基地。

尊敬、信任、私人欠情、官方资格、资产使用权和愿意卖命分别判断。机构贡献由有权者及记录载体维护；换掌门可能改变兑现和承认，不能删除已经发生的交付历史。当前账本有逻辑实现，物理载体及完整继任仍待接入。

## 9. 用跨系统场景验证，不以百科名词验收

一个未来样例：商队改引水路帮助作坊→下游灵树缺水→鸟群离开→药田虫害变化→居民与妖怪各按所知求助、协商或反对。玩家可以疏水、迁植、补偿、隐瞒来源或离开。**这是设计样例，当前游戏没有运行此链条。**

后续最小验收应包含：

- 不接 AI 也能通过结构化入口提出一个受支持的请求；听不懂、不会、不愿和执行失败有不同可知反馈。
- 同一请求由不同身体/阅历/处境的接收者产生合理差异；能力自述与真实结果允许不一致。
- 自动策略和人工操作使用同一权限、资源和时间；指挥他人不能绕过通信、同意与职责。
- 一种环境或材料变化至少连接两个用途；离场、快进和存读后继续，不能只改一句场景描述。
- 有意识的植物样本有可作选择的生活，不把随机被动终老强加给玩家。
- 新世界规则适用于玩家与 NPC；测试区分内部事实和角色能够知道的结果。

这些是未来验收方向，尚未新增自动测试、游戏接口或玩法。工作包顺序见[ROADMAP](../../docs/ROADMAP.md)，原Goal已恢复active；本页早期暂停措辞不覆盖最新实施授权。
