# 单位决策与持续任务

**P5候选设计，未实施。** 将生活、工作与战斗中的自主选择接到共同框架，支持可绑定的策略、个体参数与独立记忆。它属于既有[认识与自主选择领域](../../docs/engineering/architecture/05-framework-domains.md)，通过意图连接[公共行动与作用](action_effect_framework.md)。实施边界只归[主计划](../../docs/plans/foundation-priorities.md#下一阶段候选)，选型证据归[研究](../research/action_editor_references.md#8-可编排单位策略p5研究未实施)。

## 1. 覆盖范围

需要自主选择的单位，可以用共同接口选择目的、持续任务与局部行动。玩家、开发者或AI辅助制作策略是内容制作方式；不要求游戏运行时调用大模型。普通玩法使用预设程序，模组与创造模式编辑工具可另行建设。

| 过程 | 决策职责 | 执行职责 |
|---|---|---|
| 采集、吃饭、休息、合作 | 根据本人需要、职责与所知选任务，决定继续、放弃或换目标 | 原工作/交互宿主处理接近、预约、耗时、材料和结果 |
| 交战与Boss阶段 | 选择自卫/逃离、距离、目标、招式与多步战术 | 导航和P4处理移动、相位、取消窗口、成本、碰撞及结算 |
| 玩家直接操作 | 玩家已给定的移动/瞄准/出招不再经自主策略重选 | 共用原准入与执行；显式交接控制，不能松手即被策略夺回 |
| 路径跟随、逐格位移、后摇推进 | 遇任务失效或需要新选择时才反馈 | 连续执行，不逐格重跑高层选择 |
| 受击、强制位移、状态周期、自然变化 | 相关单位实际感知到结果后可重评 | 效果与自然过程由各领域按规则发生，不等待单位同意 |

人物、动物、随从等按实际能力选择策略；器物/炮台可以只用局部索敌与行动选择。弹体、静物或植物不因能受作用就获得完整目标、生活需要和持续思考。既有周期器物是否需要接入，只按其是否真的产生可复用选择决定。

## 2. 分层与交接

`本人观察与记忆 → 目的/任务选择 → 持续任务 → 行动意图 → 原宿主执行 → 可知反馈`

| 层次 | 要解决的问题 | 示例 |
|---|---|---|
| 目的与当前行为选择 | 当前优先处理什么，何时改变重点 | 进食、履行已有工作、自卫、逃离 |
| 持续任务 | 如何把选定目标推进到完成，当前等什么 | 前往采集点并采集；找到射界后打一轮；等待合法取消点 |
| 行动意图 | 当前希望采用哪些控制输入/操作 | 前往位置、维持距离、瞄准并请求某技能、发起交互 |
| 原执行 | 此请求是否允许，实际怎样发生 | 路线推进、动作相位、预约、资源消费、领域效果 |

这些是职责，不要求四套类或每个行为都有四层。简单射击策略可直接给出意图；多步任务按需要保存少量阶段。高层选择不在每次普攻后无条件重跑，局部策略也不能自行推翻上层控制来源。

共同协调能力负责策略绑定、当前任务选择、交接、唤醒和反馈路由。生活、战斗、合作保留各自候选生成与选择逻辑。首版沿用现有生活的需要/距离选择，战斗使用少量优先级规则；多阶段行为可由明确的阶段状态与任务组合表达。行为树、Utility、GOAP、HTN是可选算法，是否引入取决于实际内容，P5不同时建设多个通用解释器。

## 3. 状态归属与执行合同

| 状态或责任 | 建议归属 |
|---|---|
| 策略定义与默认参数 | 共享只读定义；项目内用Resource/Inspector制作 |
| 单位绑定、个体参数、当前任务/阶段及唤醒依据 | 共同决策上下文，每单位独立，纯值可保存 |
| 生活线索、战斗接触与最后所见 | 复用现有known，拆清engagements中混合的接触记忆与追击控制；字段可迁移，但各事实只保留一个owner |
| 路线、工作/交互/ACT运行与占用 | 原Units/World/Combat及ActionGate继续持有事实 |
| 材料、资源池、预约、合作回应与实际效果 | 实际领域owner唯一提交，决策不能直接改写 |
| 决策追踪与查询缓存 | 可丢弃的诊断/派生数据，不写成个人认识或重复持久事实 |

任务身份与执行run身份分开：一个任务可以先移动、再多次请求动作；某次动作结束不自动等于任务完成。任务只引用自己启动或接管的执行身份；旧任务回执不能覆盖新任务。沿用原owner/run和必要的决策上下文版本检查，不建立另一份动作相位或费用账。

已有World.actions/work_runs管理的靠近、预约、耗时直接作为执行任务接入，上层不复制它们的阶段。只有跨多次执行的目标或战术确实需要时，才保存额外的组合任务阶段；简单任务可以只关联一个宿主过程。

持续、等待、完成、失败与中止需有明确区别。接受、实际开始、进入输入缓冲与完成也须区分：受理/缓冲不证明效果发生，任务不能据此推进到完成或重复请求。缓冲未转正而过期/作废也要能结束等待。任务推进条件可按语义选择命中确认、合法取消窗口或自然结束等实际信号，不能把所有连招都强制等到动作彻底结束。等待说明等待什么变化或到期，不能靠每帧重新请求表示等待；不可执行的高优先级候选允许回退，不让单位长期停在冷却技能上。距离带与任务持续条件要避免来回切换。

查询仅暴露本人状态、实际观察、已有记忆和有界局部候选。可用性预检只据本人可知条件估计；计划不能预先读取隐藏真值筛掉假线索。执行宿主仍检查真实条件，可知失败再反馈给单位。策略代码的受限接口是代码合同；共享Resource仍需只读与明确线程归属。

移动、瞄准和出招可同时存在，各控制通道有明确采用来源；既有即时使用与并行效果沿各自合同处理，不因引入主导目标就一律互斥。手动输入、生活任务、战术控制不能逐帧相互覆盖。紧急选择提出交接请求，原宿主决定能否立即取消或须等合法边界；强制受击与死亡依原规则生效，不能被策略承诺阻止。ActionGate仍是执行占用索引，共同协调能力不冒充它已有的功能。

中止任务只终止尚未完成的生产/占用；已经造成的伤害、消耗和物资转移保留。续做只恢复明确支持的任务状态；一般情况保留必要目的线索后重新选择、重验目标和重新预约。没有通用的世界回滚、无限挂起栈或自动恢复所有旧动作。

## 4. 两个交接过程

### 4.1 采集与交战

1. 单位根据本人线索选采集任务，原工作宿主处理到达、预约和采集进度。
2. 实际观察到威胁或受击后，唤醒有关选择。策略可选择自卫、逃离或继续工作目标，不为全体角色固定同一优先级；受击必需的中断/死亡先按原规则处理，继续目标不代表保住已被打断的执行run。
3. 要切换时先按原宿主合同终止/交接工作，释放应释放的预约；已交付物资不回退。必要时保留“原本想采集何处”的线索，不保留失效的资源占有。
4. 战斗任务选择移动与招式，全部经过原执行。失视仅沿本人记忆搜索，不因宿主知道隐藏目标死亡而提前结束。
5. 脱离威胁后重新选择：继续原工作、换采集点、进食或休息均取决于当时所知和需要。若决定续做，重新验证和预约；不得写死自动回岗。

多方交互的任务只能提出请求，不能直接替对方接受。合作方的意愿、可用性、等待与终止继续由Society等原宿主处理；P5接入其反馈，不重做整个社会决策。

### 4.2 战斗阶段与局部任务

阶段条件选择当前战斗策略；策略根据本人观察和动作可用性选择接近、调整射界、连段或撤离等任务。多步任务等待实际移动/动作结果再推进，P4决定何时锁向、生效、打断和结束。阶段改变可以停止后续任务步骤，但已承诺动作只能合法终止，已离手攻击继续依原生命周期推进。

P5用轻敌、重敌、射手及少量阶段/序列配置检验这些接缝，不据此承诺完整Boss或新增预警系统。

## 5. 调度、制作与恢复

- 复用World时间及现有到达/到期、接触发现和结果采用入口。领域通知需要重评，协调器合并同单位的唤醒；身体工作到期与下次思考是不同语义，不能用一个字段互相覆盖，也不为每个策略另建调度器。
- 发现威胁先更新本人线索，再选择是否交战；不能先调用会终止工作的engage再决定逃离。强制清理、原过程的到期提交与合法延续保持既有因果顺序；高层重评按明确的安全边界与反应节拍采用。不能把全部回调简单挪到区间末，或在已模拟完的区间内补写新行动。具体插点须在实施时沿原事件排序核实。
- 按当前任务所需的事件、相关状态变化和必要的到期复查触发选择；观察发现和连续条件仍可稀疏轮询。战斗局部选择可沿现有50ms节拍，运动/结算继续原精度，生活高层不跟随战斗频率全量重跑。
- 候选与空间查询有界，同次求值复用观察；只对需要自主选择的活跃单位准备上下文。不每次复制整个世界、每单位构造SceneTree或默认向所有单位广播全部事件。反应节拍/判断偏好可表达玩法差异，CPU时间与求值上限是工程成本控制，不直接等同于单位智力。并行与新增缓存按实际瓶颈再选，不承诺本设计带来特定性能提升。
- 首个低代码形式是条件—动作优先级规则与有限任务组合；复杂算法可沿同一合同注册受信项目脚本。声明数据的步骤/候选/引用可校验和限量，受信GDScript不能靠事后计时强制中断无限循环。未来外部导入先校验纯数据，不直接加载任意Resource/Script作为隔离方案。
- 决策反馈来自原宿主采用的结果及角色实际可知渠道；显示日志、World.emit输出和person_events冷记录不成为权威决策输入。记录“为何选择、当前等什么、谁拒绝、为何换任务”。策略模板/版本、单位必要任务记忆和下次唤醒依据进入对应恢复校验；缓存可重建，不保存对象引用、Callable或GDScript调用栈。不因读档重新支付成本、重复提交已完成任务或启动新一轮攻击。

## 6. 现有落点与P5交付

当前不存在上述共同协调与持续任务层。入口分布在`livelihood.gd._think/after_action`、`combat.gd._think/engage/finish`，World工作/交互的完成与失败会直接回调生活；Society另有对方等待和回交，Entities还直接维护随从跟随。迁移需核对这些真实入口，不能只增加统一名称后保留多个互相发号施令的循环。

P5先建立共同合同并接入现有生活选择与战斗选择，再完成低代码与战斗风格；既有领域执行、社会意义与自然规则按实际接口受影响范围修改。必须用采集→威胁→应对→重选的跨领域过程证明复用，同时保留正常手动ACT。

可观察结果：同一策略可绑定多个单位且记忆隔离；同兵种换策略/参数能形成打法差异；生活与战斗不会争抢控制，动作承诺/预约/成本不被绕过；失视、目标失效、手动接管及中途存读按合同处理，诊断能说明选择与等待原因。具体内部施工顺序归主计划，不另建一份阶段清单。

主要实施风险是旧直调漏迁导致两个选择循环互抢、边界条件导致任务反复切换，以及缓冲失效后仍等待不存在的动作结果；验证优先覆盖实际改变的这些接缝。规则与有限任务组合能执行作者编排的流程，不能自动推导未编排的长前置依赖；如果未来要求自主寻找并组合造桥、找材料或破障等办法，再局部评估规划器。
