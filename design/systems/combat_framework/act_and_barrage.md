# 近远双路线：ACT与弹幕战斗改版规格

状态：**P1直接操控、P2单剑切片与P3原生技能框架/八套范例已交付；P4通用基座与近远组合已实现，第13节记录采用合同和实际范围**。用户已确定改为2D正交俯视的ACT＋弹幕，并选择“近战武器强调ACT，远程武器强调弹幕，各自形成完整玩法”。用户明确取消原A攻击移动、S停止、H警戒、点击追击与剑弓模式切换。当前能力/键位只查FEATURES；本页其余数值、最终武器、正式分层动画与技术扩展仍是候选，不因部分实现而宣称全部完成。

实施顺序只维护在[主计划](../../../docs/plans/foundation-priorities.md)；当前能力仍查[FEATURES](../../../docs/status/features.md)。源码核查与外部证据见[研究资料](../../research/act_barrage_references.md)。用户所写“硅谷八荒”暂按《鬼谷八荒》理解。

## 1. 要达到的实际体验

近战以“接近→试探一二段→确认硬直/危险→接终结或技能→取消脱离”为循环。远程以“移动瞄准→持续发射→选射线和安全空间→主动爆发/控场→换位”为循环。两条路线共享移动、判定、资源和技能底座，不要求玩家同时经营两套主攻击。

| 目标 | 可观察结果 | 会破坏体验的做法 |
|---|---|---|
| 操作跟手 | 按键立即表达意图，动作在合法窗口开始；松手能停止移动和持续射击 | 点击寻路代替即时移动；按键需要等下一轮长批处理 |
| 出招有节奏 | 一二段容易接，终结有分量；停手/取消也是有效选择 | 三张不同贴图共用同一个600ms扣血冷却 |
| 弹幕可读可避 | 先读发射者和花型，再选可达路线；失败能解释 | 颜色很多、数量很多，但通道太窄或落点没有反应时间 |
| 近远都有价值 | 近战能打断/压制并抓短窗口；远程能连续输出和改变射线 | 全屏自动锁敌盖过两路线，或近战只能冒险打同样DPS |
| 后果属于世界 | 用过的资源、飞行物、伤势、误伤和NPC反应持续存在 | 进入战斗创建第二套HP，退战/换装/读档刷新冷却 |

“ACT”首先来自启动、有效、收招、取消和受击关系，不以大技能数量衡量；“弹幕”首先是有组织的空间压力，不等于给每个角色增加几十个追踪弹。自动发射是某些武器/功法的选择，不是所有人物的免费全知能力。

首版分别准备近战与远程装备，战前在安全处选一条路线。战中自由切武器、双持、换武器连段和几十个构筑节点后置；以后做切换时也保留冷却组、已付成本和已发射效果。

## 2. 操作、朝向和移动

### 2.1 建议默认键位

直接操作为正常游玩入口；营造/观察/命令需要明确上下文，不把同一点击同时解释成攻击和选人。

| 输入 | 直接操作 | 交互/营造/窗口上下文 |
|---|---|---|
| WASD | 连续移动，斜向归一化 | 文本框获得焦点后停止世界输入 |
| 鼠标 | 连续瞄准，落点技能预览 | 原选择、工具预览与界面指针 |
| 左键 | 当前武器主攻击；近战点按连段，可选按住连击；远程按住发射 | 选择/确认工具 |
| 右键 | 武器技/关键主动1 | 对象上下文/取消工具；空地不移动 |
| Q / E | 主动2 / 主动3 | 旧取放等功能转入上下文按钮 |
| Space | 有移动输入沿移动方向闪身；无输入朝瞄准反方向短后撤 | 不再兼任暂停 |
| F | 附近交互，多个候选时显示选择 | 停用旧“跟随镜头”快捷键 |
| Tab | 开关交互/营造上下文；显示模式名称与指针变化 | 切换时停止持续移动/发射并清短缓冲 |
| Esc / 暂停按钮 | 暂停/菜单 | 保持逐层关闭逻辑；菜单遮挡期间不发世界动作 |
| I、F5、F9 | 背包、保存、读取 | 沿用现有入口与阻断规则 |
| 顶部倍率按钮 | 生活/旅行快进 | 原1/2/4/8快捷键不与未来技能栏争用 |

键位经InputMap表达，提供改键和冲突提示。首版以键鼠为验收设备；接口保留双摇杆语义，手柄映射/辅助瞄准不宣称同时完成。威胁察觉与倍率政策见[世界后果](consequences.md#9-世界时间与扩展边界)。切换上下文是输入解释变化，不凭空拔剑、腾空双手或取消已经飞出的箭。

短按/松开边沿不能只依赖每帧轮询：事件捕获后进有界顺序队列；连续移动/瞄准取最新值，不把每次鼠标移动塞成可靠命令。暂停、失焦、打开窗口、读档、切模式都清除本机持续按住状态；恢复要求新的按下边沿，防止关背包立即误砍人。暂停中不接收直接战斗按键积压；交互上下文如保留“一项生活待执行意图”，只在明确下令后保存，恢复世界推进才执行。

### 2.2 四个不同的方向

1. `move_vector`：WASD产生的连续移动方向，控制身体位移。
2. `aim_vector`：从人物的统一瞄准原点指向鼠标世界位置，连续360°，控制射线和技能方向。
3. `visual_facing`：把瞄准方向量化到八向，带约5°滞回，避免方向边界闪动。
4. `action_facing`：某次动作锁定的方向。前摇前段允许转向，有效阶段按招式规定锁定，不让刀弧随鼠标瞬转成360°伤害。

静止也能转身；往南退时仍能朝北射。普通移动/后退先保持相同速度，避免未提示的后撤减速破坏弹幕间隙判断；武器开火和攻击阶段是否减速由具体招式定义。

鼠标进入人物中心约0.15–0.25格的死区时保留上个有效瞄准方向；零向量不重置为东。攻击按下时固定需要的方向/落点，下一段连击可重新取方向。近战基础辅助只帮助对准已知目标的小角度，不自动追踪隐藏目标或修正玩家的闪避方向。

屏幕震动、视角前探和视觉后坐力不改变规则瞄准。先用不含震动的相机变换求世界目标，再给渲染相机叠偏移；缩放、UI缩放、逻辑位置到脚点的0.5格偏移必须分别处理。落点技能的光标、实际落点和射线使用同一转换链。

### 2.3 八向移动不必先制作64套全身动画

八个朝向×八个移动方向是64种关系，不能靠“八向行走已经有了”自动表现正确。但关系可以用分层和相对方向复用，不必把64种都逐帧手绘。

| 路线 | 能力与代价 | 本次建议 |
|---|---|---|
| 整身64关系 | 姿态最完整，衣物/武器变体会放大成本 | 不作为原型前置 |
| 八向朝向＋相对前进/后退/左移/右移 | 把斜移并入相近步态；最多约32组移动片段，仍需检验脚滑 | 可作为最终整身素材方案 |
| 腿按移动八向、躯干按瞄准八向、武器连续旋转 | 组合空间大；需要正确分层、腰部接缝、持物锚点和前后遮挡 | 优先做一套人形样本验证 |
| 现有整身素材＋脚底瞄准/锁向/运动提示 | 最快验证方向和判定；侧移姿态不完全自然 | P1采用仅主角的简洁近身标记；具体产物/出口只维护在主计划，不以独立武器或正式步态阻塞 |

先验证静止转向、面北向南退、面东向北侧移、斜移、贴墙、快速跨八向边界这六种情况。倒放现有前进动画只能临时帮助原型，不能当正式后撤步；攻击姿态与命中弧必须一起转向。规则时间驱动动作相位，美术动画的帧事件不决定何时扣血。

## 3. 近战：一套能打出节奏的三连

本节为**P2当前单剑配置**，规则与图形检查见BASELINE；不是DNF/Hades实测帧表，也不代表主观手感已收敛。现有三连不重新计作新功能；本包为现有铁剑收敛一种“轻击抢先手、小步跟进、确认后进退、重击兑现破绽”的风格。动作内移动、推进、取消与控制效果属于武器配置，未来武器不必继承这套性能。

以下均为世界毫秒，时刻相对本段启动，区间采用左闭右开。P2沿用60Hz共同时间和已有动作边界切分，不改为新时钟。

| 动作 | 前摇 / 有效 / 收招，总长 | 扇区半径 / 全角（半角弧度） | 伤害倍率 | 沿锁向的额外推步 | WASD移动倍率 |
|---|---|---|---|---|---|
| 一段：横斩 | 70 / 60 / 150，280ms | 1.55格 / 约115°（1.0） | 1.0 | `[40,100)`内共0.10格 | 0.40；190ms后0.80 |
| 二段：反斩 | 80 / 70 / 170，320ms | 1.65格 / 约126°（1.1） | 1.1 | `[50,120)`内共0.18格 | 0.30；220ms后0.75 |
| 三段：终结 | 140 / 90 / 230，460ms | 1.90格 / 约86°（0.75） | 1.6 | `[80,170)`内共0.24格 | 0.18；360ms后0.75 |
| 右键：重斩 | 180 / 100 / 240，520ms；CD3200ms | 2.40格 / 约132°（1.15） | 2.0 | `[100,200)`内共0.22格 | 0.10；420ms后0.65 |

三段由当前更宽的扇区改成较窄、较远的终结，与右键的大范围重斩分工。轻击停手后逐步恢复走位，重击前段保持承诺，不能全程只有一个低移动倍率。推步是有限距离的招式位移：与输入移动合成后走原身体扫掠/滑墙，不寻路、不吸目标、不自行转向；接触前方身体时只截短额外推步，不改变普通WASD可穿人的现状。墙阻、取消或阶段结束后不补偿未完成的距离。开发对照可将推步设为0，若它让玩家穿身或被强拉进危险，先缩减推进，不增加追踪修正。

P2每段在该次按下意图时取方向，启动即锁向；新一段可重新瞄准，本段有效弧不随鼠标旋转。不为这把剑增加前摇追鼠标/自动锁敌。敌人具有单独的慢起手与锁向配置，仍走同一动作执行器，见第5节。

### 3.1 缓冲与复位

- 每个角色最多一条待执行意图，普攻/右键寿命120ms，闪步80ms；不排满三段。意图由`combat`拥有，含按钮、按下时瞄准/移动向量、生成/过期时刻；玩家/NPC共用合同。连续瞄准仍更新自由尖标，但不改已提交意图的方向。
- 仅围绕当前动作临近的合法取消/结束点缓冲；闪步另允许在硬直最后80ms新按下后等待脱控。不提供独立“等CD转好就自动施放”的队列；冷却在预期执行点仍不满足则拒收。临近命中可能打开的提前续刀/技能/闪步窗也可短存，只有实际确认且未过期才执行，未命中不延长寿命等整刀结束。
- 同一短窗口优先闪步→右键→普攻；同类新按下覆盖旧方向与时刻，低优先级不刷新高优先级寿命。成功启动任一互斥动作就清槽；过期/条件失效丢弃，不能先出一刀再补旧闪步。系统重复按键不产生新意图，P2默认点按，不新增近战按住辅助。
- 缓冲到期使用绝对世界时间，不被刀痕/闪光延长。取消/缓冲执行/避伤结束/移动倍率变化纳入到期边界，避免只在原前摇/有效/结束三个时刻检查。
- 一二段保留到完整收招后300ms的续段资格；超时、第三段启动、闪步、右键、真正受击打断、死亡或换武器复位。只掉血但未打断不清当前动作/连段；不加入默认的“闪步保留连段”。
- 开UI、暂停、失焦、切模式和改键沿P1输入代次，仅清玩家未开始意图，保已开始动作、当前链资格、CD、在飞物及NPC状态。存档保存NPC待执行动作；成功读档清玩家本地待执行意图，不恢复持键，不重放已发生反馈。新字段随功能同步校验，不靠放宽存档验证接入。

### 3.2 命中/挥空取消表

以下为可执行时刻，括号内为挥空时刻；“命中”须在伤害提交后确认，见第4节。进入缓冲不等于动作已经执行。

| 当前动作 | 下段普攻 | 闪步 | 右键重斩 |
|---|---|---|---|
| 一段 | 190ms（240ms）接二段 | 实际命中确认后立即（160ms） | 160ms（210ms） |
| 二段 | 220ms（280ms）接三段 | 实际命中确认后立即（190ms） | 190ms（240ms） |
| 三段 | **460ms完整结束**后重开一段 | 300ms（360ms） | 460ms完整结束 |
| 右键重斩 | 520ms完整结束后重开一段 | 340ms（420ms） | 不自取消，CD从启动计 |
| 闪步/后撤 | 220ms完整结束后重新起招 | 不自取消，保持共CD | 220ms完整结束 |
| 受击硬直 | 不靠普攻连点解除 | 仅最后80ms缓冲，脱控后执行 | 本包无解控技 |

一二段提前闪步会立即关闭剩余攻击区，不继续扫后面的目标。第三段不能用普攻或右键免费洗掉收招；命中也要承担一部分后摇，再允许晚段闪步。高优先级不越过这些时间、硬直或CD。

正常命中接续时，一二段命中约在70/270ms，三段约在550ms命中，完整收招约870ms；挥空连段更慢。它们是无额外停顿、及时输入、目标仍在范围内的纸面时序，不保证每套必连。右键是一二段后的CD换范围/控制收益，不是所有稳固起手的无条件破招键。原型以保留当前铁剑基础伤害、调整测试敌人合理交手次数起步，不为让表格成立先重做全局数值。

## 4. 受击、弹体和地形判定

### 4.1 四种几何各司其职

| 几何 | 负责什么 | 起点与约束 |
|---|---|---|
| 通行身体 | 墙/门净空与运动 | 沿用约0.35格量级；与实际体型对应 |
| 受击体 | 近战/弹体能否接触 | P2暂与约0.35格身体共用；P3若真实弹幕需要再拆独立核心，0.20–0.24格仅为后续候选 |
| 攻击形状 | 弧、胶囊、线束、圆区 | 来自HitSpec，不从刀光像素透明度反推 |
| 视觉包络 | 发光、拖尾、刀痕、衣物 | 可以大于核心，但危险核心必须清晰，装饰不可制造假判定 |

当前32px/格下，P2约0.35格半径对应约11px，不能说整个48px人物精灵都是受击框，也不能把后续6–8px核心候选写成现状。首版不逐骨骼制作器官碰撞。脚点、逻辑位置、武器锚点、受击中心分别给调试标记，确认后再制作正式素材。

保留当前人物不硬阻挡的基础语义；P2先用清楚站位与出手节奏避免三敌堆成一团，确实妨碍读招时才做小范围软分离，不把群体硬碰撞/推箱和编队避让塞进本次前置。普通接触不自动扣血，危险冲撞是明确动作。闪身可以越过人物，但不能穿墙；以后如设盾墙/大型不可穿单位，必须有清楚资格。

### 4.2 命中流程

1. 按攻击类型、来源、目标资格、友伤政策筛选；不能把“可点选”当命中规则。
2. 空间索引按扫掠包围盒取候选；包含弹体和目标两者运动的范围。
3. 按本时间段的分段轨迹求相对运动首次接触，和墙体首次接触比较；同位置优先墙，防止穿墙后打人。
4. 应用接触时刻的闪身避伤、格挡/护持、硬直抗性、防护，生成可追溯的命中候选。
5. 单一owner提交健康、位移、控制和消耗，再发显示/声音事件。

P2将`confirmed`从几何候选收集移到实际伤害接受之后；受伤但抗打断仍算命中，墙阻、已死、被更早攻击打断、保护拒绝和成功避伤不算确认。单次近战脉冲的“已接触”和“已造成伤害”分开：闪过本次斩击会消耗该激活对本目标的接触资格，不在避伤尾端补中，但不提供命中取消收益。持续区、多段旋风以后另定义周期，不能继承整次免疫。

同刻互中先固化接触资格再提交双方结果，保留已有相杀语义；较早的真实死亡/打断取消后到的近战。多人横扫逐目标扣血，镜头/声音按同一激活合并；确认提交时检查仍是原激活，不能改写已被替换的新动作。事件携带接触时目标位置、来向、动作/激活和实际伤害/控制结果，不用步末位置伪称精确接触点。

当前普通箭半径0.10格，同时带入**人物与墙**的扫掠查询；以后每种弹也须使用其真实半径。大弹不能只因中心没碰墙就穿过门边。近战也不能沿扇区绕过墙角打到背面；AOE默认按作用类型检查遮挡，震地、气浪、火焰不可共享一个未说明的“全部穿墙”。

每个动作激活有`attack_id`，每次命中段有`hit_group`；用`(attack_id, hit_group, target_id)`去重。持续光束/场域另定同目标命中间隔，多段招显式允许多次；对象池复用和身体槽位换人不能继承旧去重记录。穿透弹按接触时刻排序消费穿透次数；反弹、消弹和反射以后增加，不能由多个回调争抢同一弹。

弹体/刀弧在步内出生、激活、到期时，只计算实际存在的那段时间。不能在步末生成一发弹却补走整步，也不能用步末已经无敌的状态抹掉步初已发生的接触。新发弹第一次扫掠需要出生时刻的双方位置/剩余轨迹；运动历史按实际需求保留，不能简单删除旧代码的空弹短路就宣称修好了首发判定。

友伤沿用当前设计的实体后果：实体箭/刀在有效阶段可碰及友军和中立者，准备阶段对已知危险挡线提示/停手，已发出的攻击不凭阵营消失；有辨友能力的术式可显式过滤。首个测试场使用受控敌我队伍，随后必须加入一名非战斗者检查误伤。不同阵营颜色仅用于读图，不代替实际伤害政策。

## 5. 闪身、后撤、硬直与近战生存

本节为**P2当前受击与闪步配置**，具体已实现能力查FEATURES。受击选择“常态可短打断、稳固动作抗打断、重击抓破绽”，不引入倒地/起身/浮空体系，不在每次受伤后自动给全局长无敌。普通走位没有无敌；战斗闪步是一项明确本领，同等能力的NPC按同一合同结算，不无条件授予所有村民，也不让AI读玩家按键。

### 5.1 闪步与后撤

| 项 | P2默认 | 边界 |
|---|---|---|
| 有方向闪步 | 160ms位移＋60ms收招，13格/秒，共2.08格；CD700ms | 有移动输入沿该次意图方向，身体连续扫掠/滑墙；不自取消收招，不穿墙 |
| 无方向短后撤 | 同为160＋60ms，10格/秒，共1.60格 | 沿按下时瞄准反方向，与闪步共用一个动作/CD/避伤窗，不另开一份免疫 |
| 避伤区间 | **`[启动,启动+90ms)`** | 只避标记可闪避的离散近战/普通箭；后70ms位移＋60ms收招可受伤；不免疫身体环境/持续火场/明确不可闪避效果 |
| 撞墙 | 只截短/滑动实际位移 | 避伤按原绝对起止时刻结束，不提前剥夺、不延长、不退款；被堵后仍有有风险的尾段 |
| 受击硬直 | 不可靠闪步即时解控 | 可在最后80ms新按下预输入，脱控且CD满足才执行；不是被打前存一条闪步等到醒来 |

避伤从启动生效，风险留在短窗后的尾段；它不能替代敌人读招和可达安全路线。成功闪过不扣血、不施控制、不给攻击者命中确认；当前单次剑弧消耗本次对目标的接触资格，其他独立攻击仍可命中。

普通箭**穿过并继续飞行**，不是接触闪步角色后消失。按真实接触时刻依序比较目标与墙：略过避伤目标后继续寻找后方最先的有效目标/墙，不给墙后的候选先发闪避事件。同一普通直飞弹记录已掠过身份，避免留在交叠区后在下一片段补中；稳定ID/记录随在飞物保存，槽位复用不继承。持续区域与未来反弹/多段弹另定义接触周期，不将本规则扩成全程免疫所有来源。

P2基础轻/重敌不主动使用闪步，先保证其攻击窗口容易学习；规则不按玩家身份特判。敏捷敌AI以后启用时须经过真实观察、反应延迟和已承诺动作检查，不因准星/按钮即时躲避。

### 5.2 分层受击与抗连控

| 实际命中 | 常态人形 | 稳固出招中的目标 | 表现与保护 |
|---|---|---|---|
| 剑一/二段 | 默认90/110ms硬直，约0.12/0.16格击退 | 正常受伤，0硬直/0击退 | 命中确认成立；只有真实控制才播打断后的受击姿态 |
| 剑三段/右键 | 默认200/240ms硬直，约0.35/0.45格击退 | 正常受伤，不无条件穿透稳固 | 终结与范围重斩有不同轮廓；重敌收招另有一次惩戒机会 |
| 低频普通箭 | 本包不附硬直/击退 | 同样扣血 | 制造路线/血量压力，不把近战频繁锁死；不清当前连段 |
| 硬直预算耗尽 | 继续受伤，短暂抗打断/击退 | 不额外叠保护 | 可辨的抗打断标记；没有免伤、没有无前兆反击 |

普通人形从首次真实硬直开启1200ms控制窗口，默认最多累计400ms**新增**硬直；重叠受击不缩短已有硬直，同刻控制取最强结果，不把持续时长重复相加。剩余不足40ms时不制造碎硬直，余下窗口抗打断/击退并清楚提示。90＋110＋200ms允许一套普通三连，继续追第四刀不能无穷锁人；这同样保护被围攻的同等身体玩家，不是NPC专有免控。

击退有自己的有限距离/持续曲线，沿同一权威身体扫掠；不能因为硬直预算只剩20ms就把终结击退随机缩到0.09格。稳固/抗连控拒绝控制时不另补击退，墙阻不产生穿墙/碰墙伤害。真正打断清除目标当前动作、旧下一招和链资格；新按下的脱控闪步按3.1处理。

同一激活/弹幕组保留当前280ms伤害防重合同；不同激活与不同来源仍可命中。不扩成“同一射手所有攻击都免疫280ms”，不让防重保护挡掉正常三连。重敌稳固标签来自动作/能力；如玩家获得同一动作也遵守它，不因`target == 1`改变受击规则。

### 5.3 两种敌人与一个低频射手

以下为练习场配置与参数起点，不改所有NPC为同一属性。每名敌人只需要一项清晰的招式，原`heavy`“技能转CD就退回70ms快剑”的行为取消；独立慢起手动作由同一执行器按能力配置选择，不另写伤害路径。

| 角色 | 测试HP / 作用量起点 | 前摇 / 锁向点 / 有效 | 强制收招 / 收招后最早再出手间隔 | 主要交互 |
|---|---|---|---|---|
| 轻剑客 | 120HP、无额外护甲；命中约12伤害 | 400ms / 100ms后锁向 / 70ms；约1.55格、100° | 420ms / 200ms | 常态和起手可被短打断；抗连控后仍从完整400ms预警重新出招，不瞬间回砍 |
| 重剑客 | 220HP、护甲2；约25伤害 | 550ms / 200ms后锁向 / 100ms；约2.30格、120° | 800ms / 250ms | 前摇/有效带稳固标记，所有本包攻击正常扣血但不打断；收招稳固消失，第三段/右键可触发失衡 |
| 现有射手 | 70HP；约11伤害，单箭14格/秒 | 480ms / 240ms后锁向 / 1ms | 450ms / 950ms | 同一次瞄准后只发一箭，间隔约1.88秒；不追踪，近身仍用可读招式，不自动瞬发反击 |

锁向前仅按真实可见目标有限调整，目标进入盲区后不追踪其新位置；锁向后预警与实际方向一致。射手发射后撤去瞄准线；重敌未惩戒的收招以淡青色侧标提示，稳固金弧与抗连控蓝弧分开。现有四帧攻击素材按起手/有效/收招取帧，收招保持末帧，不循环伪造挥击。每次动作或受控结束只更新一次再决策期限，不能在每次`prepare()`不断后推；所有起招仍有完整前摇。动作被外部受击打断也不能洗掉已经承诺的强制收招/最早再出手期限。

P2**不加累计破势值/第二资源条**。重敌收招中，三段/右键分别给约260/400ms失衡与对应击退；同一次重劈最多一次收招惩戒，不靠连续重击叠成长失能。原收招破绽的期限/是否已惩戒要独立于可被受击删掉的当前动作保存：轻击先打断收招，也不能洗掉第三刀/右键的本次破绽资格。下一次可出手时刻取“原定期限”和“受控结束后180ms再决策”的较晚者，不因受击抹掉原收招而提前回击；失衡不保证固定额外增加一整段输出时间。

时序检查：从重敌起手同时正面出三连，第三刀约550ms到达，正好进入其有效期，不能靠整套普攻累计到某个阈值必定打断。可选一二刀确认后退出；待其挥空进入800ms收招，三连约550ms能兑现终结，完整870ms收招略越窗口，但仍可在晚段闪步退出并面对下一次完整起手。实际接近距离、墙与射手压力必须试玩，不能只凭相加认定必无伤。

保留铁剑现有基础伤害时，一套约3.7倍作用量（逐段取整/减甲另算），轻敌约一套、重敌约两个输出窗口作为首次调参目标。HP用于支撑交手次数，不当作风格本身；若第三刀只会换血，先调取消/推进与敌人破绽，不只提高它的伤害。

近战对弹幕的补偿来自这些读得懂的射击承诺、压制窗口、取消退路和短闪步，**P2不加每刀消弹**。专门武器技的有限消弹、反射、完美弹反、处决演出以后逐项论证。

## 6. 远程、主动技能与构筑

### 6.1 完整远程循环

首个普通弹体样本可用能量法器，先验证连续瞄准与移动，再扩实体器物及落点攻击。左键按住向鼠标连续发射，移动不改变射向；起点约每140–180ms一发，弹速约12–18格/秒，有明确最大射程/寿命。持续火力不锁死移动，首轮以100%步速为对照，再试开火85–90%，以实际躲弹感受决定。

射速、单发数量、散角、弹速、穿透/反弹次数、持续时间、触发频率分别是参数；不能让“+1弹数”无上限同时乘射速、分裂、追踪和命中触发。先做2–3个行为变体，例如单线穿透、三向低单发伤害、慢速范围爆发；均以同一武器底座表达。

基础攻击不消耗灵气，确保CD空窗也能玩。需要实物弹药的武器以后从现有库存实际扣除；原型法器的消耗设定明确，不把“暂时无限箭”误写成所有弓箭的最终规则。

远程风险来自射线、弹速、需要看准的瞄准、地形与侧翼夹击，不通过给近战敌人全程加速贴脸来抵消射程。近战的风险回报来自压制和终结收益，不能只比较站桩DPS。

### 6.2 三类目标语义、两套准备

以下工作名仅用于原型，不代表最终内容。每条路线最多准备三个关键主动；先各做一个，再扩全，不能以“规划有六招”当开工就要全部完成。

| 输入 / 目标语义 | 近战准备示例 | 远程准备示例 | 起始CD |
|---|---|---|---|
| 右键：方向/武器技 | 破势重斩：短前摇、强失稳，可接普攻后摇 | 聚束齐射：少量窄角高价值弹，需认真瞄准 | 4–6秒 |
| Q：方向/位移 | 进身刺：向鼠标方向短推进，撞墙停止 | 扇形驱离：近距离推离，普通弹有限消除作AB选项 | 5–8秒 |
| E：鼠标落点 | 震地圈：短延迟区域，制造近身窗口 | 定点阵：短延迟区域压制，逼敌改变路线 | 7–10秒 |
| 替换槽：自身/维持 | 护势：短时稳定或有限格挡 | 护环：自身周围短时防御 | 替换现有一槽，不扩快捷栏 |

每个技能必须有：目标类型、最大距离、有效/非法落点显示、前摇/锁向点、实际出效时刻、成本与CD提交点、可取消窗口、持续时间、遮挡和友伤政策。方向技能锁射向；落点技能保存位置而非不断追鼠标；自身技能不伪装成需要点击的落点技。

默认快速施法按键时提交；按住预览/松开施放作为可选模式。超距落点可投影到最大射程并显示最终位置；墙后/不可达落点按技能拒绝，不能偷偷寻路替玩家走到那里。准备失败不扣资源；已发射后取消不会退还箭/符和CD。HUD同时表达冷却、资源不足、动作锁定、落点非法，不用一个灰图标涵盖全部失败。

### 6.3 自动弹幕与成长的界限

环绕物、周期飞剑、命中触发弹幕可以作为明确功法/法器特色。先做一个可开关的辅助样本，观察是否遮住危险、抢走目标选择、让主攻击失去意义。自动目标只能来自本人观察/已知线索；不是全地图最近敌人。

成长先改变“怎么打”：扇角变窄换穿透、三段终结留下短波、闪身后下一发改变形状。新手用原始基础武器也必须完成测试场；不能先堆词条把无聊底座填满。永久本领、临时状态、装备能力分别归原owner，死亡重开和房间奖励不随参考作品一起移植。

### 6.4 三类交付方式与共用效果

下表把用户提出的远程方向作为框架样例，**尚未实现，也未锁定技能名/数值**。它们描述攻击怎样到达目标；散射/追踪是发射与运动方式，减速/持续伤害是命中后的效果，可以跨类型组合。

| 类型 | 规则上的区别 | 用来检验复用的样例 |
|---|---|---|
| 普通弹体 | 发射生成一次攻击载体，碰撞/寿命结束后消散；是否另扣箭/灵气由成本配置决定 | 火弹散射；同一弹体/效果底座改出减速追踪弹 |
| 实体器物 | 有逐件身份和耐久；派出占用同一件物品，存在去程/活动/召回/回收或损毁状态 | 一把可受损、可召回的飞剑；不把它当可无限补发的外观弹 |
| 无飞行弹道 | 合法落点/方向经过前摇或预警，到期直接作范围查询；不要求生成飞行弹 | 一次落雷或地突；后续持续区域需另有周期作用能力 |

实体器物复用命中、遮挡、效果与表现协议，但独立保存寿命过程；普通弹不承担库存物品身份。追踪只读本人观察所得目标/最后可见信息，丢失目标后的直飞或搜索策略必须明确。无弹道不自动等于穿墙、无视屋顶、全知选点或不可闪避，相关资格与遮挡逐技能配置。

减速和周期伤害首先各支持一项明确的刷新/叠层策略，状态到期与下一次跳伤进入共同时间边界；不因施放者或表现节点退出就重置计时。器物的墙阻返航、失主/死亡和损毁后果须在样例闭环时明确，永久损毁、修理经济与自主编队尚不属于已定规则。

## 7. 敌人与弹幕编排

先制作四个职责样本：近身轻敌（横斩/可打断）、慢重敌（明显蓄力/侧移）、定向射手（瞄准后锁向）、花型精英（少量花型/射击与回收交替）。每个样本既考近战也考远程；近战接近花型精英后能抓真实收招，远程不会只在视距外无风险磨死。

| 花型 | 让玩家做什么 | 首次实现的公平条件 |
|---|---|---|
| 定向一/三连射 | 看抬手后侧移 | 发射前约120–200ms锁向，不能最后一刻全知追踪 |
| 扇形 | 移到扇外或穿缝 | 缝宽按受击直径和反应时间设计；给近身可读的停火/偏转窗口 |
| 有缺口圆环 | 提前选缺口再穿越 | 缺口与角色实际能到的位置相连，不只是一张几何上有洞的图 |
| 慢旋转列 | 预测移动方向，保持节奏 | 角速度/持续时间受限，不与所有其他花型同时叠满 |
| 延时地面区 | 离开预告范围 | 固定落点、清楚边界；不要整块安全区同时封死 |

基础预警先试350–600ms，重攻击600–900ms；普通射击可以短些，但“读发射动作＋飞行时间”仍须留足转移距离。短距离直接在玩家受击体内出生不公平：检查枪口到第一合法出生位置，碰墙立即处理，不能把弹推出墙后；贴脸开火应靠可读的抬手/后撤/近身攻击变招解决，不能神秘删除已经成立的命中。

用近似关系检查花型：`到达时间≈可见飞行距离/弹速`；`通道净宽≥受击直径＋操作余量`；`可移动距离≈步速×(预警＋飞行时间－操作/显示延迟)`。这只是筛错，不能证明玩家一定有安全路线；必须叠加地形、当前承诺动作、其他弹/地面区和运动轨迹检查。

测试场要有开阔地、L形墙角、窄门三种形状。出生/预警前选符合地形的花型或延后攻击；已承诺的危险不为性能/镜头移动随机删几发。使用攻击令牌限制同时发起高压攻击者，限制的是出手机会，不是命中后暗改伤害。令牌只面向已接触的局部战斗，不给AI全知的玩家位置。

离屏危险必须先让玩家得到可解释的视觉/声音/边缘方向线索与反应时间；未实现声音认识前，测试敌人安排在可读视野，不用全屏UI暴露隐藏射手。玩家自己的弹幕、数字和光效在高压阶段主动降低视觉占用。

## 8. 手感与视听：先保证反馈可信

有效反馈从真实事件触发：挥空有挥空声和刀风，命中才有打击声/火花/受击反应；发射不等于打中，暴击/破势/击杀也不能共享同一层强度。用稳定事件ID避免Frame重复采用时重播音效/停顿。

| 事件 | 角色/敌人表现 | 镜头与声音起点 | 高频约束 |
|---|---|---|---|
| 挥空 | 有效期内的刀弧/风痕，起手与后摇不伪造危险 | 挥砍声，0震动，无命中火花/停顿 | 一次激活一声主刀风，三段/重斩音色较重 |
| 普通近战命中 | 接触点小火花、目标约40–60ms短闪；实际控制才显示受击姿态 | 默认不震或最多0.8px短脉冲；挥砍＋轻接触音 | 一刀扫十人不叠满十个重音；无攻击者权威停顿 |
| 三段终结/收招失衡 | 明确反冲、失衡姿态与较大定向火花，冲击叠影驻留约35–45ms | 约1.5–2.5px震80–100ms；低频重音 | 一个终结最多一个镜头脉冲，不冻结人物位置/刀弧判定 |
| 受伤但抗打断 | 短金属/稳固闪点，当前攻击姿态继续，不播假后仰 | 短促硬物音，默认无震 | 仍是实际伤害事件，不能错播成格挡免伤或失衡 |
| 普通远程命中 | 小火花/短亮；关键目标可有轻反应 | 常规不做攻击者停顿和镜头震动；短接触声 | 命中声按同目标/同类短窗合并，不每弹都播全套 |
| 玩家受伤 | 姿态/短边缘提示、伤害方向、可辨保护状态 | 约40–70ms短亮；清楚但不过响的受伤音 | 不持续全屏闪白；保护期不重复触发伪受伤反馈 |
| 重技能/精英死亡 | 主要效果清楚，次级碎片逐渐退场 | 重要音占优，短时压低次要音效 | 保留敌弹与危险区可见，不能演出中被遮死 |

P2从六个已有声音通道扩至最多八个，常用音类先各2–3个轻微变体，预留高优先受击/关键预警通道；按声音类型短窗合并，不能用一个45ms全局门槛吞掉玩家受击。一刀多人同批取最高主重音，跨显示帧出现更高重音时替换原声道而非叠加；玩家受伤保留独立层。单激活最多一个镜头脉冲，接触小火花可逐目标显示；不自动增加飘字密度。

像素震幅以1280×720参考视口表达，随相机缩放校准；不对角色真实Transform加随机抖动。瞄准转换显式排除表现镜头偏移，不是先算一次鼠标世界位置便保证后续帧不受震动影响。P2本机设置至少有战斗音量、震动强度/关闭、闪光减弱；不改规则或写入世界档。程序合成可以继续占位，但须实际听一二段、终结/重斩、稳固和受击是否可区分、是否刺耳；正式采样制作不作为前置。

### 8.1 P2反馈时序与停顿取舍

**P2默认无额外攻击者权威停顿**。真实硬直/击退负责控制，接触处的短驻留刀痕/冲击叠影、音色与有限镜头脉冲负责重量。驻留图形是发生过的接触，不保持危险扇区高亮，不冻结人物、受击核心、当前武器判定或已飞弹；不改`Engine.time_scale`、世界时间、CD和输入寿命。下一招/闪步开始后旧刀痕只按原处短暂衰减，不跟着新位置拖行。

原因是当前World先完成短区间身体轨迹，再按接触时刻排序提交伤害；发现命中时不能简单倒带回接触点冻结身体。统一加`hold_total`到前摇/有效/结束会把已发生的有效阶段推回未来，单加到有效尾又会扩大判定时间。这些不能靠两个字段就保证正确。若交付切片仍缺重量，再独立比较局部停顿：须定义哪条相位可延后、何时开始生效、期间身体/新命中如何处理、取消收益及存读，不把一次近似实验写成正式卡肉已完成。全局停时以后作为明示能力另论。

音画采用同一个`render_ms`只是必要条件：P2命中事件还须保存真实接触时目标位置/来向、动作与激活、伤害/控制/抗打断结果。世界坐标上的火花用事件接触位置；附着角色的短闪/姿态用同身份显示位置和有效状态区间，不能混用最新`frame.positions`。`population.gd`已改为按实际受控区间显示HURT，短闪另由命中事件驱动；只扣血不打断时保留重敌的稳固攻击姿态。

反馈稳定键可用`epoch＋actor＋activation＋target＋事件种类/命中段`，只为尚不能区分的事件补序号，不为P2重做全世界事件总线。同一世界事件重复采用不重播；暂停停在既有反馈时刻，不重复响，切会话清旧声音/火花/震动，成功读档不重放过去命中。保持可见性/距离门控，不用命中反馈暴露未感知的隐藏目标。

### 8.2 视觉层级与可访问性

视线优先级：玩家受击核心/当前危险→敌人关键前兆→可战斗轮廓→自己的伤害效果→装饰与数字。敌弹有稳定实心核心、轮廓和方向性尾迹，玩家弹偏低对比/半透明；不能只靠红绿区分阵营。地面危险要显示生效边界、填充进度与到期，屋顶/树冠在战斗视野中不能盖住核心。

P2提供战斗音量、震动强度/关闭、闪光减弱；后续按实际内容再补伤害数字密度、友方特效透明度和按住连击辅助，不将这些全列为P2交付项。设置不改变伤害判定。暂停可以学习当前动作和技能含义，普通HUD不暴露隐藏NPC的准确CD/内心/全局计划。

## 9. 共同时间与低延迟的技术选择

### 9.1 已核查的现状

P1源码`489dc0f`已采用**60Hz整数共同心跳**，单步16/17ms，`World.step()`再按动作到期与既有50ms服务边界切分。所有身体轨迹仍共同推进，环境/植物/感知各按其到期语义运行；尚无远区LOD。Runner每心跳发布轻姿态，人物、弹体、动作使用共同历史片段与`render_ms`显示。输入代次已区分未开始意图与已承诺动作，不能再把旧20Hz/固定50ms箭运动写成现状。

一次区间仍先积分身体，后由`combat.step(start,end)`收集相对轨迹接触、按时刻提交伤害；P2增加取消/避伤等到期边界，而不引入接触回滚。第8.1节的停顿取舍建立在这个实际顺序上。自定义Runner不依赖`Engine.physics_ticks_per_second`或`Engine.time_scale`来推进规则，渲染FPS也不等于战斗频率。

旧20Hz对照、60/100Hz候选争论及实际负载边界留在[研究](../../research/act_barrage_references.md#12-p0旧链路的合成移动基线)。当前60Hz按用户要求收口，不追加100Hz比较、完整设备延迟或高压人口测量作为P2前置；当前普通世界证据与未验证项查BASELINE/研究，不外推目标低配整机或大量活跃弹容量。

### 9.2 怎样保持一个世界

以下约束用于维护当前共同World及以后确有需要时的跨频扩展；P2沿用全体身体共同积分，不为凑齐此清单建设新的升降频框架。

- Runner按60Hz心跳受理/发布，动作到期再切边界；低频环境/生活按其原到期语义运行，不复制第二个World。不承诺任意10ms设备到屏幕延迟。
- 同一人物的位置、HP、资源只有原owner可写。进入高频集合只改变执行频率，不复制身体；原50ms页任务必须跳过已移交的运动行，避免双推进。
- 高频集合覆盖参与者、可能接触的弹/区域和即将进入的移动者；范围按最大速度/射程/下次检查前可达距离扩展，不能仅按镜头框。转移前先结算到同一时刻，已受理的移动/行动继续，移交后撤销旧任务对相关行的写权。
- P0少人数对照可先让全部可移动身体的轻量轨迹积分跟随高频边界，导航/决策/生活保持低频；它用于建立成本基线，不是全地图长期高频的产品要求。数量或实测阻塞要求分层时，让无接触者按可查询轨迹/到期分批推进；不先假定升降频框架必然更快。
- 非高频单位若可能被弹命中，要么提前升频，要么提供同一时间段可重建的真实运动轨迹参与查询；不能拿50ms旧位置当静止靶。远处交战保留同一能力/资源规则，是否逐招、逐弹细算按[大世界取舍](#93-大世界为战斗让步的条件与次序)验证，不永久绑定近场计算精度。
- 定时工作只处理已到期事实，不预先把整村推到未来50ms再让玩家在过去10ms交战。路径计算可准备未来候选，但采用时复核版本；慢任务需拆成可控批次，避免一次join堵住高频提交。
- 发布高频小型CombatView/Pose，按版本共享慢速静态/库存/地形视图；不能100Hz复制所有人的完整Frame。显示插值滞后应随新发布节奏缩短，摄像机/拾取/弹体共用显示时刻。
- 预测最多先用于准星、转向、出招意图/有限玩家视觉位移。HP、命中、CD、资源和NPC动作不由预测提交；纠偏不能靠让危险弹暗穿人。

真正引入跨频移交时，再验证共同时间和写权边界。当前常规人数采用全体身体共同积分，先交可玩战斗；完整跨频/设备延迟证据不是用户要求的P2门槛，不能以架构未铺齐为由继续拖延手感切片。

### 9.3 大世界为战斗让步的条件与次序

**用户接受：实测大世界拖慢ACT/弹幕时，以战斗响应为先，允许次要世界过程降低精度、频率或延后；未拖慢就保留。**连续大地图、世界时间继续经过，与全地图逐帧高精度计算是不同要求，不先改成箱庭，不把历史最大人口当成新战斗必须同时承载的指标。

目前512×512地图常驻，但需求/温度、植物、感知和静态变化已有不同周期；不是262144格每帧全部重算。真正需拆的是`World.step()`的共同等待链，以及全量Frame、人物显示准备与长调用。地图面积、活跃人口/交战数量、不可让出的最长批次和可见透明特效是不同成本；历史高人口样本已显示容量风险，却没有证明默认24人＋新ACT一定过载，证据边界见[研究](../../research/act_barrage_references.md#11-大地图与高频战斗的性能证据)。

按测到的瓶颈逐级选择，后一级不自动成为施工范围：

| 次序 | 可选改动 | 代价与采用条件 |
|---|---|---|
| 先减少重复工作 | 战斗姿态/弹体轻量发布；慢视图按版本共享；诊断按需聚合；显示只准备可见及边缘需要的实例；保持现有空间查询并按新弹量验证索引成本 | 不改变世界精度。不要把100Hz全量复制/全人口排序当战斗提频的固定成本；裁剪显示不删除世界实体或危险 |
| 处理长批次 | 打散后台决策/观察、环境采样和提交准备；对路径、拓扑、来源重建量出单次耗时；必要时生成可作废候选，分批复核采用 | 平均够快但周期卡顿时优先。立刻join仍会阻塞；外层耗时配额也不能中断已经进入的原生长搜索。拆准备可保持原效果时刻，错开采样/伤害相位则需说明语义误差。墙体先按约定时刻挡弹，不能等房间温度重建 |
| 降低远处逐身体工作 | 沿已有路径按路程/到达事件推进；远处观察/生活决策更稀疏，路线失效或新直接事件才唤醒 | 可先试250–1000ms的远处运动服务、1–5秒的生活决定，均为待测候选。不能按秒瞬移、吞到达事件或等玩家走近才补一次；查询/转入接触前须结算到同一时刻 |
| 降低远处环境细节 | 房间/区域聚合，植物沿旧rate积分，平稳输入时延长采样，来源/天气实际改变时局部失效 | 只在该项昂贵时做。远处房间可试2–5秒、植物10–30秒；接受短暂热源、精确生长/成熟时刻等误差。采收、消耗与已成立的伤害仍原子提交；会影响近场危险的输入及时升级，不能用旧值伪造安全 |
| 简化远处交战 | 无玩家可干预、无近期跨区影响的交战，用较稀疏的交战事件/局势结算代替每招动作与逐弹轨迹 | 可能改变胜负与消耗分布，需对代表性战斗另做细算/粗算对照。不是先给所有NPC套胜率抽签；没有测到远战成本就先保留细算 |
| 最后处理驻留与规模 | 冷区只留状态/事件，按需装入细节；或根据产品目标限制常驻活跃人口/同时交战规模 | 只有内存、活动规模或面积相关重建确实成为瓶颈才引入。区块化不自动省模拟CPU；不能借ACT改版顺带建设无限世界/全套LOD框架 |

数字描述候选服务间隔，不是每次把该区域全部对象一起计算。减少周期调用数只能改善吞吐，若集中大批仍超过动作预算，就要改变粒度/算法；反过来，切碎同样多的工作也不能解决持续算不过来的总量问题。后台延后必须有可观察的最大积压，不能战斗一开就无限欠账、结束后一次补算卡死，也不能因进入战斗让世界饥饿/生产时间停止。

接触层按**可干预与可到达范围**选择，不能按镜头内外一刀切。近场保留精确动作阶段、受击/攻击几何、位移、弹体扫掠和防御窗口；外圈为接近者、追击者、长射程攻击和即将跨界危险预留提前量。可用`最大相对速度×下次检查间隔＋接触半径＋误差余量`筛查边界，再考虑具体射程/技能；不是固定半径就能保证安全。非战斗村民也可能被误伤，进入可接触范围后用同一几何与资格规则。分层确有必要时才加升降级滞回，避免边缘反复移交；升频不赋予全知目标或跳过应有反应时间。

远处运动、CD和作业不一定需要逐tick执行：保存最后结算时刻、路径/速率、下一到期事件，可以在需要查询时求当前状态。但到期完成涉及共享库存、死亡或目标更换时，仍需按事件先后采用，不能先提交未来结果。无损的惰性求值与允许改变结果的近似应分别验收。

远处粗算交战的底线是共用能力/装备/HP/资源/CD和阵营政策，近似的是空间与交换过程；不能按玩家/NPC身份加减伤害。它与全程细算不保证同胜负，误差必须如实报告。已有飞弹、延迟伤害、玩家可能介入的追击和可回到近场的危险不能凭降级删除或重抽；必要时保留细算/可查询轨迹，直到安全收尾才降级。升频时承接已提交的生命、消耗、目标与世界时刻，不回滚战果、不满血重开、不复制在飞物。没有保留来源/发射时刻/轨迹承诺的“粗算在途伤害”，不能在入场时随意变成贴脸真弹；先限制转换到安全边界或保留相关细算。

本次ACT验收首先针对1×直接战斗；生活/旅行快进及察觉危险后的回落沿[倍率政策](consequences.md#9-世界时间与扩展边界)另测。历史高倍率吞吐不自动成为新战斗的承诺，不要求1×/16×各自维持同样高频接触次数来证明世界连续，也不静默改变玩家选择的实际世界速度。

因此首版不把远区粗算列为必做，也不再一概禁止：P0若证明远处细算妨碍目标战斗负载，它可以成为P6之前的条件依赖。取舍优先保留地图连续、世界有进展和玩家可解释的因果，放弃无必要的场外毫秒级复现；只有前几级都无效且容量目标仍不满足，才讨论人口/内容密度，而不是默认缩小地图。

## 10. 数据与文件落点

下面是提案级职责，名字可调整。目标是项目内玩家/NPC、近战/远程共用的战斗框架；先用真实技能扩展，跨项目发布的通用插件/SDK不是首版前置。选型依据见[研究4.1～4.2](../../research/act_barrage_references.md#41-可复用技能框架与内容编辑工具)。

当前手动与AI已走共同动作入口，旧RTS攻击指令已移除。后续技能栏、装备赋予能力与AI选择都提交稳定技能ID和目标语义，共用资源/CD/动作规则；CD按人物及技能/共享组归属，不再让所有新技能挤进唯一`skill`按钮冷却键。

同刻处理采用：到期状态→命令与动作启动→运动轨迹→按接触时刻收集效果→汇总HP/控制→倒地/死亡与清理→观察/发布；有效区间统一`[开始,结束)`。若需要按10ms内的精确接触时刻区分闪身边界，必须拆到相应边界，不能拿步末状态覆盖整段。相同时刻已成立的攻击可以互中，已发射弹不随射手死亡撤销。

### 10.1 定义、施放和表现的接入合同

当前采用**Godot原生Resource＋原World执行器＋轻量Inspector增强**。22份动作定义、11套配置与八套可玩范例已接入；YARD仍是后续可选编辑提效工具，没有安装运行时战斗插件。本节描述当前制作合同，超出现有机制的部分另注明。

```mermaid
flowchart LR
    A[Inspector / 可选资源表格] --> B[技能与效果 .tres]
    B --> C[校验 / 转换为脱离的值快照]
    C --> D[World共同动作与效果执行]
    D --> E[动作 / 弹体 / 状态 / 器物实例]
    E --> F[纯值存档与候选验证]
    D --> G[姿态与真实结果事件]
    G --> H[动画 / 批量绘制 / 音效]
```

`CombatAbilityDef`保存身份/颜色、伤害取值属性、阶段/取消/连段/移动、成本/CD组；`CombatDeliveryDef`定义交付/目标/几何/运动；类型化`CombatEffectDef`列表配置伤害、控制、减速与DoT。`CombatLoadoutDef`绑定primary/skill/step与练习装备，`CombatLibrary`显式引用全部动作和配置。当前一次动作只在有效段开始交付一次，散射由发射数量表达；多个独立阶段事件、条件分支和触发链尚未实现。

装载器校验稳定ID/引用、有限数值、阶段顺序、取消窗、目标/交付所需字段和周期/次数边界，报出具体资源与字段。通过后将规则转为脱离编辑对象的纯值快照，再在受控边界交给Runner；贴图、音频与PackedScene留在主线程表现目录。共享模板不持CD、去重、当前目标或阶段游标。多人学会同一模板、同人两次重叠施放分别拥有运行状态。

内容资源集中在现有`data/definitions/`下的战斗主题目录；Resource类型/编译接入沿现有`scripts/`职责组织，编辑插件才进入`addons/`。实现时按首个样例建立必要文件，研究/顾问/验证原件留`.local/`，不预建空目录或在根目录散放工具。

首批只补实际样例需要的交付/运动/效果处理器，按**机制类型**执行；技能名称只作为内容ID，不进入“若是某某火球则特判”的主循环。目标/遮挡与伤害资格共用原查询，HP/位置/库存仍由原owner提交。新效果产生的控制继续服从P2预算/稳固合同；DoT不默认每跳造成硬直。表现消费事件，动画轨道不直接扣血或生成权威弹体。

### 10.2 制作者新增技能的实际流程

1. 在Godot文件系统中复制一个已有模板，另存为独立`.tres`，设置新稳定ID；复用效果子资源时明确“共用修改”还是“创建独立副本”，不能只复制外层文件就假定所有子资源独立。
2. 在Inspector调整阶段、移动/推进、取消、目标方式、射法/轨迹、效果列表与表现；表格适合横向比较伤害/CD/射速，深层效果继续在Inspector编辑。
3. 通过“工具→Reol 战斗技能库”进入`data/definitions/combat/library.tres`，或直接选技能文件；Inspector上方预览起手/有效/收招及攻击弧/散射/圆区，按钮校验本资源字段。库装载还会校验重复ID、引用、物品成本/练习装备、同一DoT标识的周期；预览不取代真实碰撞试玩。
4. 将新技能加入library的abilities，并把ID写入已有或新建loadout的primary/skill；新loadout也加入library的loadouts，playable决定是否列入练习下拉框。武器通过`items.json`的`combat_loadout`/`ai_loadout`赋予配置，人物的`ability_loadout`可显式绑定，玩家/NPC共用入口。保存后**关闭游戏窗口并重新运行**，再从顶栏选择范例；仅按重练不会重新装载定义。
5. 在开阔地/墙边体验，再在对应在途状态保存恢复。制作出口是新增实例能玩、能恢复、不会影响共用模板的另一名使用者。

首版编辑使用Resource＋Inspector。范围/阶段预览与错误定位作为轻量增强；是否采用YARD由隔离试用的实际编辑体验决定，不按技能达到某个数量就强制安装。YARD若采用，仅用于编辑/装载辅助，存档不依赖其Registry对象；卸载后技能Resource仍可读取，但下拉提示、扫描/索引和Registry引用需显式替换。`GraphEdit`只在大量真实分支/循环无法清楚编辑时再评估，不预先做通用蓝图语言。

### 10.3 配置复用的边界

| 样例 | 首次补齐的通用能力 | 随后可只改定义的部分 |
|---|---|---|
| 火弹散射 | 参数化发射器与普通弹体载荷 | 数量、夹角、半径、速度、寿命、命中效果/表现；不重新写一个火球脚本 |
| 减速追踪弹 | 有限角速度追踪、个人观察退化、限时移速修正 | 转向强弱、速度、减速量/时长；当前叠层语义固定，改策略须扩机制 |
| 落雷/地突 | 落点合法性、独立预警/到期区域、统一效果结算 | 距离、延迟、圆形范围、周期、伤害与状态；已用持续雷区/毒潭验证周期能力，其他形状须扩几何 |
| 飞剑派出/召回 | 单件身份/占用、有限部署状态机、在途受损与回收 | 速度、耐久、接触间隔、已有路线模式和效果；自主绕墙、编队/协同不随普通追踪自动获得 |

首次增加新运动、链式目标、地形改变或触发时机，仍需要实现一个可复用机制，并补对应状态/校验与表现接缝。已有机制的组合才进入配置制作。首批不建设任意回调脚本/任意递归触发；后续确需“命中生子弹”等组合时，先明确定义来源、命中组、有限派生次数及触发是否再次传播。

### 10.4 编辑版本与存读

当前采用**保存资源、关闭并重新运行游戏后采用新定义**，不做运行中任意热改；练习重置不重新编译库。规则值递归只读并有内容签名，持久状态保留稳定技能/效果ID与签名。P4采用独立format11，P3保留format10旧包；新增字段按[兼容政策](../../../docs/engineering/compatibility.md)处理，不为保留旧格式少存过程。

首版不维护历史定义兼容链：逻辑定义不匹配时，在独立候选验证中明确拒载并保留当前世界/旧文件，提示需要对应内容版本或新开局。文件改名不等于逻辑ID改名；纯表现修改可与规则签名分开。不得为“兼容”静默清除在飞弹、延迟落雷、已付成本或派出的器物。

以后若实际需要战斗中受控重载或改数后继续旧档，再保留版本目录或完整的在途规则快照；只快照动作结束时刻而继续读取新版效果/取消窗并不完整。已有施放、状态与器物收尾按其采用的规则执行，新施放才采用新版本。

### 10.5 可观察的制作出口

框架验收与可玩远程样例同步：**新增一个同类技能只改资源/槽位绑定，不改战斗主循环**；玩家与NPC并用同模板时CD/连段/去重互不串；错误定义在进入World前指出字段；编辑后重开可实际施放；追踪/状态/区域/器物各在引入时补一个中途存读反例。P2迁移只验证受影响的连段、取消、命中时序、控制与墙阻，不为重构再跑完整人口/弹量矩阵。具体施工次序只见[主计划](../../../docs/plans/foundation-priorities.md#p3方案技能制作与远程样例同步推进)。

### 10.6 当前机制语义与新增机制的落点

| 机制 / 所有者 | 当前合同 |
|---|---|
| 动作 / `combat.gd` | 以配置决定伤害属性、按住重复、连段、取消、CD组、位移和稳固；成本在合法启动时由库存扣除。既有样例没有额外弹药成本。下一个技能实例不增加名称分支；新的动作阶段语义仍需扩机制 |
| 弹体 / `combat_projectiles.gd` | 状态仍归Combat；直线、散射、有限追踪、穿透共用体积扫掠。追踪每50ms按出生相位更新，仅锁定本人已观察目标，失去视野/来源死亡后保持直飞。来源阵营与伤害取发射快照 |
| 区域 / `combat_areas.gd` | 鼠标点在启动时捕获、限制距离并检查本人视野/墙；自身点取启动时位置。交付后区域独立存在，预警至少1ms；一次触发或在`[trigger,expire)`内周期触发，来源死亡不删除已交付区域。当前是固定圆区，不能配置成跟随光环或任意形状 |
| 持续状态 / `combat_effects.gd` | DoT按发射伤害快照乘magnitude取整，每跳不默认硬直、不可用闪步免除；同来源+status_id刷新、保留节拍与较高跳伤，不同来源分别存在。同status_id须使用同周期。减速同标识取最强并延长到期，不同标识相乘、最低0.15，同时作用于直控和寻路；不影响闪步/固定推进速度 |
| 器物 / `implements.gd` | 一个owner+派出能力对应一个独立ID/耐久记录；再派在外器物转召回，不生成第二件。出程直飞，到时/撞墙返航；返程向主人行进，受墙阻掉落；回收不回满，归零损毁，主人死亡在接触时刻掉落并停止后续输出。现为绑定练习件，尚无转赠/维修/普通库存入口 |
| 命中 / Combat提交 | 刀、弹、区域和周期效果按接触毫秒统一提交；同毫秒已成立攻击可互中。弹丸只在提交时消费穿透/销毁，飞剑较早损毁/失主后不能吞后到弹；接回不能抹掉较早在途受击。`hit_group_ms`默认280，配置0允许同次散射每颗独立伤害，区域保护不超过周期，器物另用接触间隔 |

持续状态使用`[born,until)`，恰好到期的跳伤不触发；到期前的真实命中续期则保留原周期并在本区间末正常结算该跳。减速、硬直和击退对已积分身体的速度变化从下一小段准备生效，不倒带位置。追踪/器物不是通用心智，目标选择、个体保管、身体运动与HP仍各有实际owner。

新增一种现有机制不能表达的技能时：在对应交付/状态/器物领域增加有限处理器及Resource字段→接入共同时间的触发/到期→将原状态和校验加入该owner→发布真实结果事件/姿态→补一个相关存读或先后反例。运行实例不保存Node、Resource或Callable；不把所有新领域压成带大量可空字段的“万能实体”，也不先造一套任意脚本图解释器。机制间接口和实测原件见[运行架构](../../../docs/engineering/architecture.md)与BASELINE。

## 11. 性能、存读与验收证据

### 11.1 密集弹幕

沿已有弹表与空间查询扩展，稳定ID不依赖数组/池槽位。弹量实际成为瓶颈后再选择紧凑列、池化与按类型批量更新；只查询扫掠附近可命中的受体，不进行每弹×全人口扫描。弹与弹默认不碰，仅特殊消弹范围查询相关弹层。动态目标的索引要覆盖段内运动，不能只索引段末位置。

可见弹用批量绘制/MultiMesh，少量重要爆发用池化特效节点。分组考虑纹理/材质和排序；透明叠加/全屏辉光可能先受GPU填充限制，不只看draw call。CPU先保留权威碰撞，GPU用于表现；没量到瓶颈前不引入GPU读回、C++扩展或第三套物理状态。

预算在**发射前**决定，保留已承诺的整套花型/危险边界。降级先减拖尾、装饰粒子、数字和次要音效；不能随机删除正在围住玩家的弹来达FPS。渲染裁剪不删除规则弹体；实际离场/寿命到期才释放。

确有相关容量问题时，可按需要选战斗负载：1玩家＋8敌/约100活跃弹；1＋20/约500弹；1＋40/约1500弹。它们是后续可选诊断阶梯，不是承诺上线数量，也不是P3交付门槛；当前按用户要求只做相关短验证。选定可玩负载按[后台对照](#114-怎样证明大世界确实拖慢战斗)放回生活世界；不据“插件展示一万弹”推断项目也能达到。

### 11.2 存读与中断

保存真实方向、动作阶段/结束边界、已付成本、CD、受伤保护/避伤、控制、在飞物、范围区、命中记录/下一次脉冲、已受理缓冲及随机状态；索引、纹理、粒子和显示插值重建。绝对世界时刻/剩余量选一个规范，不能两份各减一次。输入按住状态、预览、摇屏和未受理悬停不进入世界档。

中途保存后恢复，不能重播已经结算的命中、增加弹药、延长无敌或让已消费的三段重来；慢速生活和高频动作都捕获于同一提交点。加载成功提升epoch，丢弃旧输入/效果，失败保留活世界；新字段按现有兼容政策决定开发格式，不为保留旧测试而维持第二后端。

### 11.3 手感如何验收

| 试验 | 固定条件 | 记录与判断 |
|---|---|---|
| 响应链 | 相同地图/敌人/渲染设置，分别20Hz与候选高频 | 输入捕获→受理→规则启动→可见帧的p50/p95；区分动作前摇与系统等待 |
| 三连与取消 | 无敌木桩、轻敌、会反击重敌 | 早按/晚按/停手/转向、能否一二段后主动离开、是否无意多砍一刀 |
| 近远对照 | 同等学习阶段、同场景、换起始顺序 | 完成时间、受伤次数、有效近身/射击时间、误操作及主观控制感；不强求同DPS |
| 弹幕公平 | 开阔/墙角/窄门、近/中/远距离 | 预警后有没有可达安全路线；攻击承诺是否让近战必挨，远程是否只剩绕圈 |
| 反馈AB | 同一命中与规则，仅切停顿/声/震动/粒子组合 | 分别打击重量、目标辨认、舒适度；小样本属于定性证据，不当统计结论 |
| 性能 | 记录CPU/GPU/分辨率/人口/活跃弹/真实速度 | 帧时p95/p99、最长规则间隔、准备/计算/提交/发布成本与内存 |

响应链建议目标：60FPS显示条件下，普通有效输入到第一帧可见意图p95≤50ms，到权威动作启动p95≤35ms（不含有意设计的前摇/不可取消段），稳定战斗至少60FPS且无明显规则追赶；120FPS是进一步目标。以上均是**验收候选，尚无测量**，不能用线程内计时冒充完整按键到屏幕光子的延迟，真实端到端可另用高帧率录像校验。

规则反例只围绕相关行为增加：短按不丢/不重复；近战单段去重/多段可中；墙边大弹；移动目标/急转/闪身边界；同刻互中；发射后射手死亡；技能取消/资源/CD；切模式/暂停/失焦；同动作中途存读。图形试玩必须实际看、听、操作，headless通过不证明手感。

### 11.4 怎样证明大世界确实拖慢战斗

保留同一512×512地形/种子、近场敌人/花型、输入回放、移动镜头、视距、分辨率和效果设置，只改后台负载。先由P0测最小动作链，P2/P3具备相应玩法后再复核真实近战/密弹切片，不等待全部技能完成才首次测量。

| 对照 | 固定近场之外的差别 | 用途 |
|---|---|---|
| A：最小后台 | 只保留近场及验证共同时间所需的少量生活工作；地图大小不变 | 测战斗本身的响应与余量；若A已不达标，不能归咎于大世界 |
| B：正常世界 | 同一近场放回正常24人配置，其余人照常生活；近场需另加实体时明确总数 | 判断目前产品规模是否真的需要精度让步 |
| C：选定高人口 | 同一近场扩大后台生活/交战到一个有意义的人口档，可先选历史900人档 | 判断增长瓶颈；ACT先以1×比较。历史900人/4×报告是另一负载，不冒充同场景60Hz战斗结果 |

三组记录输入捕获→受理→动作启动→姿态发布→可见反馈的p50/p95，帧时p95/p99、最长/高分位权威发布间隔、实际世界速度、内存及CPU/GPU；分开记录后台准备、计算、join、采用和快照耗时，避免嵌套计时重复相加。观察窗口覆盖整秒环境更新、到达/批量作业、跑图跨格观察与一次受控地形变化；普通交战和拆建尖峰分开报告。

单窗口只能提供方向；若差异接近噪声或会改变取舍，才按开发循环补同条件复核，不重跑全人口寻极限。A/B都达标且差异不构成体验问题，就保留世界精度；B失标则定位实际阻塞，依9.3逐项改一个再同负载比较；仅C失标则记录容量边界，并判断目标是否确实需要它。平均成本过高对应总工作量/算法，平均够而尾部坏对应长调用/批次；降低无关植物刷新频率不能替代消除真正的战斗或决策瓶颈。

## 12. 资源制作与范围纪律

近战先以一把剑建立风格；远程按6.4的普通弹体、落点与实体器物分小包验证，少量变体共用模板。整体仍围绕一套人形基础、三种普通敌人与一个精英、四至五种花型及含三种地形结构的测试场逐步交付，不同时扩建武器库。世界场景仍使用原身份和状态，不把练习重置按钮带进正常世界。

素材优先级：动作轮廓/方向与脚点→三段起手与终结差异→敌人预警/受击→敌我弹核心→命中声→有限刀光/火花→高级装饰。现有八向每片段4帧、单一melee循环不等于三段已完成；三段若每向4–6关键帧，本身就是约96–144张姿态图（分层可复用），另有后撤、侧移、闪身和施法。先做一套样本确定层级和制作方式，再扩衣物/武器，避免把整个换装组合乘进去返工。

首版暂不承诺：DNF式横版浮空/倒地无限追击、跳跃高度判定、数十职业、全自动最优连招、全武器战中切换、完整弹反/反射链、房间制肉鸽、多人、无限地图与完整远区LOD。远处降频/粗算仅按9.3的性能条件进入范围，不为凑齐架构而必做。

P2先收敛三项：第三刀是否值得兑现、推步是否抢走走位、无攻击者权威停顿时重量是否足够；默认取消/闪步窗按第3/5节。后续开火移动速度、第三主动价值、最终可玩弹量和整身/分层动画仍由所属阶段同场景试玩决定，不将所有选择一起扩成P2前置。

## 13. P4通用战斗基座

P4将P3的“可编辑技能实例”扩为可供全游戏引用的能力。**公共行动/条件/作用/结果/反应合同归[行动与作用框架](../action_effect_framework.md)，本节定义其战斗应用**：近战、弹幕、法术、召唤与装备被动。施工顺序与出口只维护在[主计划P4](../../../docs/plans/foundation-priorities.md#p4方案通用行动基座与战斗组合)。本节为实现合同；P3基础制作仍见10.1～10.6，当前P4的具体范围和简化见13.10。

### 13.1 要补的能力与抽象边界

| 制作者想做的内容 | 底座表达 | P4可观察结果 |
|---|---|---|
| 碰撞/定时分裂、子弹落地生火区 | 交付生命周期事件→有限子交付 | 子弹有自己的载荷与分裂配额，不再借隐藏伪技能覆盖父弹效果 |
| 暴击触发落雷、受击反击、破盾爆炸 | 结构化结果→带条件、次数与CD的触发规则 | 各种伤害来源共用规则，挡住伤害、真正失血、击杀不再都叫“命中” |
| 毒/流血/燃烧、减速、加速、易伤 | 持续状态＋周期效果/属性修饰 | 来源、叠层、强弱覆盖、节拍与移除原因能配置并保存 |
| 定身、沉默、眩晕、击退、抗控 | 动作权限＋控制裁决＋连续位移 | 定身仍能原地攻击；眩晕可打断；护盾和霸体分别生效 |
| 血、蓝、怒、能量与技能消耗 | 资源定义＋原子成本＋结果驱动的增减 | 技能可同时耗蓝与实物，取消/换装/读档不刷成本或回复 |
| 护盾、格挡、吸血、治疗 | 统一结算＋有来源/时限的盾层＋实际结果 | 能解释挡掉、吸收、损血和有效治疗各多少 |
| 主动瞬移、冲刺、击退/拉近 | 空间交付＋身体运动合同 | 落点合法、贴墙截短，瞬移不在两点之间扫出一条伤害路径 |
| 毒传染、标记引爆、死亡扩散 | 状态选择/转移＋有界传播 | 保留原来源和明确的剩余时长，兄弟传播不绕回来无限互传 |
| 灵兽/骷髅/炮台、无人机/飞剑 | 能力明确的实体＋生产动作；原物器物独立生命周期 | 生物可独立移动受击；器物保留逐件耐久/归属；虚体装饰无需伪造人物 |

这些不是十几个新顶层系统。动作、属性、资源、持续状态、作用/结果和反应采用公共合同；战斗保留自己的结算、控制、空间交付与接触时序。所选生活交互通过原领域适配，不在Combat里实现采矿/烹饪算法。散射、吸血剑、破盾冰环、死亡传染是组合内容，不各建一个管理器。

基础原语先覆盖伤害、治疗、资源增减、施加/移除状态、加盾、交付、连续位移/瞬移、召唤和器物命令。条件先支持事件类型、所需/禁止标签、生命/资源阈值、状态层数、次数与CD；目标选择先支持自身、事件来源/目标、指定落点附近的圆/扇区/线及有限邻近目标。复杂公式、控制流和新运动模式仍须新增具名机制处理器，不把GDScript重做成资源语言。

### 13.2 数据组合与运行职责

```mermaid
flowchart TD
    A[原生 Resource 与 Inspector] --> B[类型校验 / 引用校验 / 组合上限 / 内容签名]
    B --> C[脱离资源对象的只读规则]
    C --> D[动作阶段 / 交付 / 周期生产]
    D --> E[接触与目标查询]
    E --> F[战斗规则裁决 / 原 owner 提交]
    F --> H[实际结果与已提交事实]
    H --> G[公共有界反应 / 战斗因果波次]
    G --> D
    F --> I[存档候选与恢复校验]
    H --> J[只读表现事件 / HUD / 诊断]
```

| 定义/合同 | 内容 | 运行状态归属 |
|---|---|---|
| `ActionDef`＋ACTprofile（原`AbilityDef`迁移） | 公共准入/目标/占用/成本/CD，ACT专属相位/取消与交付列表 | Combat持唯一ACT运行事实，共同占用协议只绑定owner/run，不复制相位/CD/已付费；交互保自己的推进记录 |
| `DeliveryDef` | 几何/运动、目标资格、生命周期行为、载荷引用 | 弹体/区域/近战/位移各自owner |
| 公共效果载荷 `EffectBundle` | 按战斗结算阶段分组、阶段内有序的有限操作列表，可供弹/区/状态及其他合法入口共用 | 只读定义；每次执行带独立上下文，变化由具名领域操作提交 |
| 公共`StatusDef` / `ModifierDef` | 寿命、节拍、层数/刷新、控制标签、属性修饰与移除规则 | 扩现有Effects；可供料理/工具等引用，受击预算继续归控制裁决 |
| 公共`ResourcePoolDef` | 上限来源、初值、回复/衰减、可用成本与显示条件 | 新池记录及原HP/身体池适配；物资、温度等不强行搬成战斗池 |
| 公共`ReactionRuleDef`（原触发规则） | 事件、条件、目标选择、概率、次数/CD、后续载荷或普通行动请求 | 稀疏规则索引、冷却/计数、共享因果链记录；不只归Combat |
| `SummonDef` / 器物配置 | 身体/感知/动作能力、寿命、数量与所有者政策 | 唯一对象/身体＋召唤元数据；器物仍归Implements |
| 公共执行上下文/结果的战斗扩展 | 接触/来向、战斗采样、命中组与实际结算分量；公共头持来源/归因/时间 | 随交付/状态保存必要值；结果派生有界事件，不把各域结果压成一个数 |

一个动作允许在预定阶段发射多批交付；一个交付可同时造成伤害、施加状态和产生后续交付。子弹不必继承父弹的全部效果；载荷不是技能名，也不需要注册一个玩家不可用的假动作才能产生不同子效果。触发既可来自技能，也可由装备/被动/状态赋予，使用相同的规则与撤销合同。

“触发效果”默认执行声明的次级载荷，遵守规则自身的成本/ICD/次数；不假装按下主角的技能键。确需完整出招的自动技能则请求普通动作，接受原动作承诺、控制门禁、成本和CD。两者不能通过一个“自动施放”开关互相混用。

Resource继续只负责制作。编译检查重复ID、引用、目标所需能力、操作字段、阶段顺序、周期/寿命、目标数量及派生配额；拒绝循环嵌套资源对象及能直接识别的无界即时自环。通过稳定ID表达、带跳数/次数/周期上限的传染等逻辑回路可合法存在；复杂跨实体回路由运行时共享配额兜底，不试图证明任意图都会停机。不运行任意脚本，不保存Resource/Node/Callable执行栈。原生Inspector先补效果列表、触发条件、叠层与来源追踪；GraphEdit只可作为以后编辑同一套数据的界面，不成为另一套执行格式。

有限载荷在一个交付边界内同步完成，不提供跨步骤结果引用、算子、通用分支/循环或协程栈；延时/周期由ACT帧表、弹体、区域、状态和器物负责。内容分类、真实机制能力与组合适用条件分别检查，不能因标为“火”就自动允许分裂。特殊轨迹、标记引爆等可绑定显式注册的项目GDScript策略，状态归宿主；这是受信任代码扩展，不是从资源/存档执行任意脚本。具体扩展/恢复合同归[公共规格3.2](../action_effect_framework.md#32-程序员怎样接入特殊行为)。

### 13.3 身份、归因、目标与个人认识

公共执行上下文的战斗扩展按需要包含：实际发射实体、来源阵营、接触位置/来向、命中组、源属性快照和效果标签；激活、归因、目标与请求/实际交付时刻使用共同语义，有后续反应时携带链引用和必要事件序号。已有同义字段合并，不为每一跳复制整个人物对象，也不强迫每帧飞行生成完整封套。来源可以是设施或世界过程，不要求虚构施法单位。

人物/召唤生物/设施引用原Objects身份，器物、弹和区域用明确命名空间；不同表中相同整数不代表同一实体。通过少量适配查询目标的位置、受击体、生命/耐久、阵营、可挂状态/资源和行动能力，不创建“全字段可空”的万能实体。

已发射弹、已交付区域和已施加DoT不会因来源死亡自动消失。后续伤害保留来源及责任归属；吸血、回蓝等向具体受益人写回前检查其仍具相应能力且存活。召唤物攻击同时保留召唤物和主人的身份，不能把一切事件都改成主人亲手攻击。玩家与NPC共用这些规则。

自主索敌只使用执行者可知目标。召唤生物默认有自身感知，主人下达的目标作为明确传达的信息；不免费共享全图知识。器物自主输出先沿用主人的可知目标，独立传感能力以后显式配置。盲射、范围爆炸和毒的物理传播可以命中未被施法者看到的实体，但命中不自动给施法者补全目标身份/全图视野。

### 13.4 统一结算、格挡、护盾、吸血与同刻死亡

战斗结算从`combat.damage()`抽出明确合同，近战、弹、区域、周期、器物/召唤输出共同调用。生命/耐久仍由原owner提交；所选生活流程按P4-A2接公共作用合同，本节不定义其经济算法，也不把整个人物状态搬进结算器。环境/植物继续批量运行，跨域作用调用相同领域处理器。

默认流水线：**资格/去重→闪避或相应免疫→伤害属性与防御→格挡减免→盾层吸收→实际损血→独立控制裁决→结构化结果→次级反应**。格挡还检查攻击类型、有效姿态/时窗和接触来向，可有资源成本；普通护盾只吸伤，不自动免控。稳固/抗控、伤害免疫、闪避资格和护盾掩码分别定义，不能互相替代。所谓无视防御伤害是否穿盾由明确规则决定，不从“真实”二字推导全部例外。

伤害结果区分原始值、减免、格挡、各盾吸收、实际损血、过量伤害和死亡；治疗结果区分请求值、有效回复与溢出。P4-A保留P3现有伤害公式作为迁移对照；新增伤害通道的公式、最低伤害与接收修饰单独声明，验证相应边界。

动作类别、交付方式与伤害类别分别保存：近战/法术不等于物理/法伤，飞弹也不天然属于普通攻击。当前P4沿用护甲减伤，近战/远程选择基础伤害列，元素/毒先作效果身份；独立防御通道/抗性/转化尚未增加。若后续增加暴击，应采用伤害包的显式资格/随机/倍率和结果标记，同包多个分量共享结果，DoT和反伤不默认暴击；P4样例没有暴击。按整次施放共享骰的特殊技能以后显式配置，不能因多段攻击无意多掷几十次。

| 结果事件 | 何时成立 | 典型消费者 |
|---|---|---|
| 接触尝试 / 闪避 / 格挡 | 几何成立并完成相应规则裁决 | 格挡反击、闪避提示；不等于已经损血 |
| 确认命中 | 目标在命中桶入口合法、未被闪避/整次免疫，含盾吸收的接触 | 挂印记、命中固定回血；同组重复候选不产生第二次 |
| 实际损血 | `hp_loss > 0`，携带直击/周期/反伤等原因 | 按损血吸血、受伤获怒、受伤阈值被动 |
| 盾耗尽 / 到期 / 驱散 / 替换 | 独立的盾层结束原因 | 破盾爆炸只听耗尽，过期不冒充被打破 |
| 状态施加 / 叠层 / 刷新 / 移除 | 状态owner实际提交变化 | 层数引爆、驱散反噬；移除携带原因 |
| 死亡 / 击杀 / 销毁 / 到期消散 | 相应实体生命周期真正提交 | 死亡传染、击杀回蓝；召唤到期不发击杀奖励 |

**同一毫秒的基础命中与主动交付先固定合法集合**，保留P3同刻可以互中的行为。防御、格挡资源和盾层按公开的稳定键消耗；同目标实际损血最多到桶内剩余HP，后到超量部分记过量，不凭空给吸血重复制造血量。生命降至0即锁入不可逆的待死亡状态，普通治疗/加盾不能解除；全部基础包提交后完成死亡与清理，再处理吸血/反伤/破盾/击杀等次级反应。

每个因果波次先冻结攻击/交付有效性与目标姿态、闪避、免疫资格，盾/格挡资源/剩余HP依次消费，不能让先序打断把后序本应闪避的同刻攻击变成命中。由本桶命中造成的动作终止和必撤姿态贡献，在基础包闭合后的控制/死亡交接中执行，再进入后续波次；此时仍走公共的同步终止合同，不把收尾留给可选监听。

载荷顺序受结算阶段约束：明确的前置处理在本包伤害计算前执行，命中状态/控制结果在死亡清理前记录；需在致死接触上附着的标记必须显式声明，必须要求实际损血的效果另加条件。非姿态类新修饰只影响尚未计算的伤害包，不回算已提交值；属性脏标在对应查询时刷新。姿态及其绑定防御贡献按本波次入口资格采样，不能一边冻结闪避资格一边因提前清理姿态改变同桶后序判定。

不依赖伤害结果的主动治疗/护盾属于基础交付，与同刻攻击按稳定键排序；先于致死包的可以救场，已经锁入待死亡后的无效。吸血、命中固定回血、受击加盾等**结果驱动**效果统一在结果后的次级波次，不能通过把`Heal`挪到攻击包前面绕过死亡裁决。效果列表的顺序不能跨越阶段、逆转致死或重复消费同一结果。

后续反应进入下一因果波次，事件仍保留原时间和前后关系；相同来源链按规则顺序/事件序号/目标稳定排序。击杀归属与竞争同一层盾可能受确定性决胜顺序影响，这是明示的同刻规则，不承诺所有结果对实体ID交换完全不变。死亡传染读取清理前捕获的状态/位置快照；尸体不重新挂活体状态，死亡与销毁后续只发一次。

默认吸血按**实际损血**算，盾吸收与过量伤害不贡献，周期/反伤不默认吸血；“命中固定回血”是另一条可配置规则。多弹丸触发概率系数和回复量系数分别命名，不能用一个模糊系数同时暗改层数、控制时长和伤害。

### 13.5 属性、战斗资源与持续状态

属性从装备/身体基准与活跃修饰集合重建：`(base + add之和) × multiply各项之积`，再按属性声明的上下界/覆盖优先级裁决；不靠添加时乘、移除时除恢复。按变化标脏，只缓存实际需要的热属性；P4不做任意跨属性公式/依赖求解器，少量比例效果走明确操作。根本动作权限不通过`speed=0`或`armor=无限大`假装实现。

默认在**实际交付时**采样源攻击属性，后代沿用该快照；目标防御、盾和接收增减在结算时读取。持续状态的源威力在施加时固定，周期读取声明为动态的目标防御；不把已扣防后的直击值再当周期基础重复套源增伤。持续生产者每次自主出手可独立采样。需要动态源/目标最大生命比例的操作必须显式声明，来源已移除时不能默读零值。

先支持移动速度、攻防、生命/资源上限与回复、伤害/治疗/格挡/吸血所需属性。**移动加速、动作加速、冷却恢复和独立发射频率是不同属性**；P4先做移动加速，不顺手把动画倍速套到已承诺动作、DoT节拍、CD和无人机射速。动作加速以后有实际样例时再补完整时间重映射合同。

| 资源/状态规则 | P4默认合同 |
|---|---|
| HP与其他池 | HP继续是`Units.health`/对象HP；蓝、怒等是独立可选战斗池。UI只显示当前配置实际使用的池；不强迫每个角色同时有四条资源 |
| 回复与衰减 | 按共同世界时间结算，保存累计余量和已结算时刻；快进/读档不重复回复。怒气来源由命中/实际损血结果定义，不按渲染帧数增长 |
| 成本 | `costs[]`可同时含多池与实物；同一次合法启动先全量验资，再一次扣费和启动CD，失败不部分扣。HP成本默认不能致死，是支付而非受击，不触发吸血/受伤被动 |
| 取消/失败 | 已合法启动的普通动作沿用先付费；取消不返费/重置CD。确需预留/交付扣费的引导或蓄力技能以后另定义交易过程 |
| 上限变化 | 增加最大生命不白送现血；下降仅钳制超额现血且活体上限至少1。不是伤害/治疗，不发吸血、反伤或击杀；资源上限同样按明确钳制政策 |
| 盾层 | 每层有ID/来源/类型掩码/优先级/剩余量/到期/结束原因；默认较高优先级→较早到期→层ID，耗尽不等于过期。汇总盾条只是视图 |
| 状态合并键 | 声明按目标全局、按来源或独立实例；不能只用状态显示名覆盖其他来源 |
| 叠层 | 支持refresh、stack并刷新、replace、independent四种策略；加层不刷新尚无样例。强度更新、时长更新、最大层数与周期相位分别声明；保持现有P3减速/DoT语义可迁移 |
| 周期与移除 | 寿命`[born,until)`，默认续期不重置下次tick；`tick==until`不发生。自然到期、驱散、死亡、消耗、替换各有原因，不用一个on_end混用 |
| 生活/环境接缝 | 饥饿、生活精力、世界灵气不改名当蓝。以后需要时，经明确修饰或转化过程耦合，仍由原领域持有原值 |

控制按自主移动、攻击、施法、闪步/位移技、强制位移等权限裁决。定身阻止自主位移与带位移动作，但不默认封住原地攻击；眩晕打断互斥动作并禁止相应操作；击退/拉拽经同一身体扫掠贴墙。受击短硬直承接P2原预算/稳固窗口；主动眩晕、定身分别有同类重施限制/累计保护，强制位移有独立的免疫/抗性政策，减速用强弱合并和速度下限。P4样例还需验证轮换眩晕/定身不会绕过脱控机会，不把所有控制挤进P2的400ms池，也不允许换个状态ID就重置同类控制记录。

原AI接收统一的失败原因：定身时不反复请求无效寻路，缺蓝/缴械/沉默时选择已知可用动作或有限退避，不能每个思考桶重试同一失败出招。这里扩现有动作选择与失败反馈，不另建战斗AI框架。

跟随光环/图腾另持有范围成员关系与下次查询时刻：进入时创建带`aura_source`的贡献，离开、来源到期/销毁时只撤本来源贡献；不删除其他施法者的同名增益。允许的短查询间隔、边界滞回与最后一次贡献寿命明确记录，避免每帧全图扫描或依靠无限续短Buff掩盖遗留状态。它与“固定区域按周期伤害”可以共享目标查询，成员生命周期不同。

### 13.6 触发链、分裂、传播与持续生产

触发只接收World内部已经提交的结构化结果；`World.emit`、HUD信号和动画事件继续只作输出。规则按事件类型、拥有者及必要标签索引，不在每帧遍历全世界所有装备和技能。概率使用可恢复随机状态或稳定事件派生随机，保存必要ID/序号，不使用全局`randf()`改变规则。

| 限制 | 解决的问题 | 不能代替什么 |
|---|---|---|
| 命中组/每目标频率 | 同刀重复接触、同组散弹过量重复 | 不能阻止跨目标无限触发 |
| 规则ICD与触发次数 | 高频命中、周期状态刷被动 | 不能阻止一次分裂生上千个实体 |
| 因果深度与共享总配额 | 跨技能、延时、跨目标的反应循环 | 不能只给每个子弹复制一个满额计数 |
| 传播访问集/跳数/目标数 | 同一传播波的兄弟分支反复互传 | 不能让一次中毒后永久免疫所有新来源 |
| 活跃实体数量与生产频率 | 长期召唤、炮台、区域持续生产的总负载 | 不能在满额时任意删掉已经飞出的危险 |

每条反应链共享`chain_id`记录中的预算与去重，延时、DoT续期、分裂和传播不会凭空换新根重置。规则声明派生效果是否能继续触发哪些事件；默认DoT产生周期事件，反伤不反伤、不吸血、不触发普通命中特效，显式开启的特殊链仍受总预算约束。

共享预算按实际派生需求创建，分支深度保存在各待处理项，规则自身CD/次数不随新链重置；传播访问集有明确范围，不用于封禁无关来源的合法施加。必要链记录和未来承诺随存档保存，不做全游戏永久事件树。只读详细追踪归有界开发诊断。

执行次级效果/子交付的反应通过资格/目标/概率检查后，生成前原子预留共享配额、支付声明的成本并启动规则CD；已接受的延迟交付持有同一次预留，不重复扣费。

请求**完整行动**的反应另走正常门禁，进入13.7的共同网格受理点；规则资格/共享配额和ActionGate的取消/目标/动作成本联合通过后，才在同一点采用规则CD、配额、动作付款与新run。拒绝不视为成功触发，不先扣CD再因门禁失败白耗；每规则/受益人默认至多一条待受理候选，概率对该候选只取样一次，失败不自动逐帧重试。待受理与已接受的延迟承诺分别保存，不能恢复时重掷/重复支付。

链记录仅在没有在途弹、状态、延迟请求或传播引用后回收，不能按固定时间抹掉仍有后代的预算；引用索引可重建，不另存一份互相矛盾的计数事实。

分裂分为“命中确认”“撞墙”“寿命结束”“定时阶段”等原因；父弹是否继续、行为顺序、可分裂次数与子弹继承载荷分别声明。普通样例选一种明确优先顺序，既不同时无条件穿透/分裂/弹射，也不把PoE所有版本的优先级硬编码成Reol唯一答案。子弹默认继承父弹的已接触排除集，至少排除本次触发目标，另有射击组决定是否允许后续再次命中。

传染先选定要复制的具体状态实例，保持原来源、源威力和传播链；默认复制**剩余时长**，不自动把快到期的毒续成满时长。刷新、保层/拆层、目标上限、墙阻/距离和下一代跳数都是有限规则。共享的有界访问集属于传播链，兄弟分支不各拿一份互不相知的集合；一个新的主动上毒可以开启新的传播链。

同一状态的续期不重新分配传播链和预算；独立新实例/显式替换才建立新链。替换时旧实例所持引用正确释放，仍在途的旧后代继续引用原链。普通重新施毒仍可按该状态的合并规则生效，不把传播访问集做成目标永久免疫。跨来源合并的数值状态须声明强度归因；周期伤害先用按来源或独立实例，拒绝未定义来源/预算归属的多链混并。

P4传播状态按`状态定义/来源/chain_id`隔离实例，实例内可叠层/刷新；不同主动根产生的新链不与旧链隐式混层。每目标/每来源并存上限与拒绝/替换政策明确配置；显式替换释放旧引用，旧在途后代仍用旧预算。启用传播却仍按无链隔离的来源/目标键合并，编译拒绝。普通不参与传播的P3状态保原合并语义，不能为这个新约束无意改掉全部旧DoT。

长期光环/自主召唤物不能一辈子共用一次出手预算。它们作为显式获准的**持续生产者**，在有限频率和活跃上限内，每次自主出手创建新的攻击激活；同时保留生产者的创建来源、生成代数和禁止再生产标签。反应临时生成的弹/毒/爆炸不能通过“下一秒重新出手”伪装成独立生产者。召唤再召唤默认关闭，确需繁殖时单独定义代数/数量/频率，不能重置祖先限制。

只有按自身合法行动/CD/正周期节拍发生的自主出手可开新攻击链；事件、联动被动或命令要求的**额外射击/脉冲**必须继承命令的因果链和剩余预算。数量替换、寿命结束和普通死亡分别标记，替换/到期不默认触发再召唤；定时器重置也不能伪装成独立出手洗掉原限制。

数量组与生产限额按明确的最终控制者共享统计，不能让每个后代换一个名义owner就各自获得一套上限。原作者可配置不同生产者各自的出手节拍，但互相触发仍继承本次反应链；只有真正的自主生产激活可以创建新攻击预算。

配额是内容规则：编译发现静态失控分支时拒绝该定义；动态不足在生成前按稳定顺序拒绝派生或采用声明的替换政策，并给出诊断原因。已付费主交付、正在飞行的弹和场内器物不能被性能兜底悄悄回收。预算数值由样例和短测决定，不在方案中凭空指定行业标准。

### 13.7 空间时序与瞬移

P4保留P3“身体先积分一小段，接触按毫秒提交；速度变化从下一运动段生效”的结构。计划为有活动战斗/待交付命令的World运动段设置明确上界，不能只依赖Runner默认60Hz；快进与长`World.step()`同样受控。**分裂/瞬爆与身体位移分别处理**，不把所有空间反应都拖到下一帧，也不为每次命中回滚全世界。

| 交付 | P4计划时机 | 必须兑现的合同 |
|---|---|---|
| 命中分裂子弹、即时范围爆炸 | 在真实接触`at_ms`加入有界战斗事件队列 | 子弹只扫剩余区间；瞬爆取目标在该时刻的位置。更早爆炸造成的死亡能取消较晚的近战，不等整段末才爆 |
| 预定的直接数值/领域交付 | 已知交付时刻的基础桶 | 主动治疗/护盾、直接命中/照料/非拓扑工作完成与接触按稳定阶段/键裁决，不一律排在死亡之后 |
| 主动瞬移/新空间交付 | 已知动作交付边界，在后续运动前执行 | 重查落点/能力，提交位置断点和索引；恰好同刻先闭合旧段接触/死亡，再执行轨迹/拓扑变化 |
| 受击触发瞬移、新身体/占位器物、反应生成的持续区域 | 事发后严格下一50ms共同网格起手，动作交付在后续合法边界 | 有`requested_at`与`activated_at`，请求起手延后最多50ms，前摇另计；额外状态切片不提前激活，不让长step放大延后 |
| 反应请求完整行动 | 事发后严格下一50ms共同网格，闭合已有命中后联合准入 | 当前动作承诺/控制/成本与规则CD/预算一起裁决；新动作不回填已闭合接触桶 |
| 减速/硬控/连续击退的运动变化 | 下一运动小段 | 动作可在接触时打断，身体不倒带；沿已有P3合同，明确运动误差 |

局部子扫掠只读当前已积分轨迹：角色和器物均按`[max(段开始,出生), min(段结束,到期)]`双端截取折线、重新归一化时间，再调用原Motion几何；不能把子弹出生配到目标的整段起点，也不能在子弹已到期后继续算目标运动。段末恰好新生、尚无正长度区间的弹只注册，下一运动段首次扫掠，不对零时长除法或重复点碰撞。瞬时爆炸是单次事件，不用空的`[born,born)`持久实例表达。

分裂出生点取**父弹当刻的轨迹位置**及来向，另保留目标中心供受击反馈；现有`impact.position`混用二者，不能直接作为新弹出生点。新候选插回按时间/因果波次/稳定键排序的队列，沿统一提交资格消费穿透/寿命/器物接触。瞬爆用`Motion.at`取当刻位置；身体、器物、静态受体共用候选合同，静物按对象ID去重，不将静态ID塞进`actor_slots`。

宽搜覆盖实际轨迹位移与最大受击体积，需修正当前`combat_scan`未计入寻路`move_scales > 1`的假设；瞬爆也扩大到历史位置可能所在范围，不能只查步末桶。已知死亡/器物停用会使较晚候选失效且不消费弹，较早硬控可取消较晚近战；已离手交付继续。地形阻挡和身体轨迹在本段保持承诺：墙体当刻毁坏不再损血/吸血，但阻挡在段末拓扑提交后才更新，撞墙分裂需选墙外方向/合法出生点或明确留到下一边界。无需重跑寻路或全体身体积分，但这些查询与提交边界必须一起验证。

固定边界一侧捕获请求的锚点/方向：接触衍生默认原接触点，自身技默认生效时自身位置；寿命从实际出生计，不补飞过去十几毫秒。延迟从原事件计时；瞬时操作按其目标时间进事件队列，边界型操作取不早于目标时间的可用网格边界，不在每次排队时重加完整延迟。这批操作新产生的边界请求留下一网格边界，禁止同边界零时间无限生产。

**边界同刻默认顺序**：先按时间闭合`<B`的事件；进入`B`时按半开寿命移除恰到期的状态/盾，恰到期的旧DoT不发末跳、接触重施也不续旧实例。该移除必须在收集/结算`B`桶前闭合，不能仅依赖下一轮步初prepare；按时刻查询资格也须一致。

随后将`B`的合法接触、有效周期和**不重构轨迹/拓扑的预定直接交付**同入基础桶，沿13.4完成控制/死亡及有界派生；主动治疗/盾可按明确稳定顺序先于致死包。最后采用`B`的瞬移、新空间实体/区域、改变拓扑的原子领域提交及完整行动受理。包含结构出生/拆除的原子操作整体归对应空间阶段，不拆成先付材料后发现占地失败。要避开`B`的旧段接触，瞬移须在`B`之前完成；恰好同毫秒接触先中。已承诺的脱源交付依自身政策执行，不能统一因源亡而删除。

区间内新建的短到期/数值交付继续加入当前有界事件队列；改变运动/拓扑的交付必须落在明确空间边界，采用时同步刷新索引并使其后受影响的准备作废/重算，不让新墙或拆墙规则沿用错误的未来碰撞。必要时细分相关运动准备，不回滚已经提交的过去，也不人为给全部交互增加读条下限。新受理动作的零时间数值交付若合法，进入后续波次；新空间交付只影响之后的运动区间，不重开旧基础桶。

新落点从下一运动段起接管身体轨迹；与尚未接触过自己的在飞弹重叠时，段初的零距离检测可在同一整数毫秒成立，属于**交付之后的阶段**，不合回此前已闭合的旧接触桶。持久危险区保持原`next_ms`相位，瞬移进出不凭空额外送一跳或跳过下一预定作用。事件序号/阶段与命中排除防止重复，表现轨迹保留位置断点。

新子弹首次自动寻敌不能读取步末的未来认识/位置；固定角度分裂先继承来向与排除集，追踪沿出生相位在后续合法转向边界获取本人可知目标。即时物理范围选择用当刻轨迹，不默认泄露身份；若交付要求已知锁定，使用事件时已经成立的观察/锁定记录。

主动瞬移不从旧位置到落点画连续碰撞线，不默送无敌。受伤触发瞬移必须活到约定边界，期间可能被后续攻击杀死，已死则不执行；若内容需要“免死逃脱”，须另有显式、可结算的保命效果，不能由位移框架赠送。落点按新位置正常承受危险；不能只作废旧路径命中而漏查新位置。真正步中瞬时身体跃迁以后确有需求再做完整的相关轨迹/索引/攻击重检。

本方案的代价是身体反应存在明确有界延后，并增加局部事件调度/轨迹截取的实现工作；收益是分裂与死亡爆炸不会累计多跳帧延迟，且无需把原World改成全局回滚调度器。P4-C用高速分裂/贴脸目标/死亡爆炸先后反例验证，P4-D再验证危险落点与被动逃脱。未经测量不承诺额外成本或任意step切分下的全世界长期结果完全一致。

### 13.8 召唤物、器物和身体能力

| 类型 | 身份/状态 | 共用能力与明确区别 |
|---|---|---|
| 临时生物/机械兵 | 原Objects唯一ID＋Units唯一身体/HP；召唤元数据持owner、寿命、数量组与消散原因 | 共用运动/寻路/受击/动作/本人感知；通过明确能力profile排除工作、吃饭、社交和人口计数，不把普通human出生函数当作成品召唤接口 |
| 可回收飞剑/无人机 | 原Implements逐件ID、归属、耐久、部署状态 | 可扩悬停/环绕/周期发射；不占村民身体页，不因派出/回收复制库存，不借到期机制修满耐久 |
| 临时炮台/图腾 | 可破坏静物或有限能力的召唤实体 | 不需要寻路就不初始化完整移动/生活能力，仍能被统一目标与伤害查询识别 |
| 无实体环绕光球/灵体特效 | 周期状态/交付及表现 | 无独立可攻击身份、无耐久，就不造隐形村民代放技能 |

扩`spawn_actor`前需逐项核对出生、死亡、移除、环境采样、生活调度、认识与帧发布的能力过滤。只增加`no_livelihood`却继续每秒扣饥饿/更新人口不是闭合方案。空间、身体和HP仍复用原owner，不能为了避开这些过滤另造召唤物运动/血条系统。

死亡在事件时刻锁定，身体槽/几何引用的物理回收等当前接触段闭合后执行；段中不能重用一行身体而让未提交候选引用到新实体。出生/消散的轨迹按身份与有效区间记录，扩页/复用行同步处理World的轨迹起点与Frame插值，不把旧尸体到新召唤物连成移动线。普通人口、总身体槽和可战斗实体数量分别统计，避免召唤物不计人口后反而漏出身体批次。

数量组声明拒绝新召唤或替换旧召唤，替换产生明确消散原因，不给击杀收益。临时召唤默认主人死亡后消散；已发出的弹/区域按承诺结束。持久器物仍按原物掉落/损毁规则处理。多件器物需要槽位/实例引用，不能继续用`owner:ability`等同于“全世界只有一件同类器物”；普通转赠/维修经济另选题。

### 13.9 原生制作、诊断、恢复与性能

制作出口：**复制载荷/状态/触发资源→绑定技能或装备→校验→同一练习场试玩→看真实结果链→中途保存恢复**。每批机制落地时同步增加Inspector字段和最小预览，不把工具全部拖到最后，也不先造大型技能编辑器。

诊断应能对选中激活解释：谁在何时交付→碰到谁→挡掉/吸收/损血多少→哪条规则通过/失败→生了几个后代→哪个预算/CD限制了它。诊断环形缓冲有界，只在开发模式按需开启；详细失败条件只对选中实体/激活采样，不在正常热路径为所有未触发规则生成字符串。正常HUD只给玩家需要的资源、状态/层数、技能可用性与清楚的预警，框架字段不进入玩家流程。

每步新增运行状态随功能保存：池值与回复余量、状态/盾实例、周期相位、触发CD/次数、因果链共享配额与访问集、待激活空间请求、召唤/器物寿命、ID/随机序号。保存发生在一致的World边界，不保存半截函数栈；恢复重建派生属性和索引，不重新施加状态/重新付费/重复发事件。规则签名或格式变化按现有兼容政策处理，先验独立候选，失败保留原档/活会话；不默认承诺P3的format10能直接读进未来P4。

性能先控制真实工作量：有限目标/分支/生产频率、稀疏触发索引、变化时属性重建、复用空间候选/热列，不为每弹每状态创建Node，不给全图铺高频光环扫描。主线程只做可重建表现；必要时先减少装饰与重复快照。保留512²世界与现有日常精度，使用当前24人同场景做一次相关短窗比较；只有实际瓶颈涉及世界后台，才按9.3选择对应让步。机制配额是规则正确性，不能拿极端弹量KPI替代可玩性。

P4完成应满足：同类技能新增主要改资源，独特编排可通过既有机制内的注册脚本接入；一个新原语接好其必要结算/时间/恢复后可供多个入口引用；多机制组合仍能解释来源、先后和失败原因；八套P3范例可继续玩，新增样例不是只在孤立测试脚本里成立。具体样例与验收反例只列于主计划。

### 13.10 P4实际范围与局部裁决

公共实现映射见[行动框架13](../action_effect_framework.md#13-p4实现映射与制作出口)。完成的是可复用工程基座与两套组合，未实现的更强数值合同不得反推为现有能力。

- 命中/受伤/击杀/格挡/破盾/采集/计时/到期/满层有界反应；规则在来源局部至多8项、Loadout至多8项，不做全图广播。根预算64，规则采用消耗1、每个子项再消耗1；剩1不足接生产规则。深度/链次数/ICD/概率/访问集分别控制，仍有后代时保留链。
- `emit`只可生成projectile/area；有前摇、成本、身体出生或瞬移的完整行动走request，在**严格下一50ms**网格起手，端点请求也晚一格。按FIFO联合准入，拒绝不占缓冲、不扣规则CD/预算或动作成本；动作前摇另计。区域以area_pulse事件在实际桶内选目标/发通知，分裂只扫出生后的残段。
- 状态隔离和实例上限、属性公式与伤害通道范围见行动框架。当前没有独立暴击、伤害转换、完整控制递减表、仇恨/职业或词缀系统；它们不会以未接线字段冒充成品。移速增益不改动作/CD/周期。
- 临时身体可定义跟随或出生点驻守，初始指定目标仍须其自身可见；复用原感知/AI/导航/HP，禁生活需求与人口。静态图腾有HP，近战/弹/区/器物可击毁；光环以自己的状态ID收回贡献。自主御剑周期是新攻击激活，碰撞和命令追加保持祖链；同主数量组、持久槽位和耐久不因召回重置。没有额外的随从指挥面板。
- `owned_marks`是受信项目代码，处理同一激活的2～8个标记，状态随宿主保存；逻辑版本参与资源签名。不是用户任意代码入口。新机制仍需程序实现其所属宿主与必要恢复合同。
- 蓝/怒/盾、三项主动＋闪步HUD、E/C改键、原生Resource引用导航与有界追踪已经接入。血刃与星焰行者完整路线及约十类机制样例见FEATURES。正式素材/混音、长局/低配、密弹极限与成长平衡另行验收。
