# 建造、空间与共同生活：环境、状态与场景

> 详细设计与候选：具体机制、参数、样本和验收意图须验证；已确认规则见[规则目录](../../rules/README.md)。

## 美观与功能共同表达生活

场景应看得出人在哪睡、写字、取物、开炉：铺盖、桌面工具、衣物、残料、书卷、私人物件表现经历和偏好。先用可读像素占位，后换正式资源，功能不绑一张贴图。

装饰可分为纯样式、实际影响通路/遮蔽/光照的物件，以及携带来历/礼俗/知识/器性的对象。纯细节可批量绘制；会被移动、借用、损坏或参与争议的东西接真实对象/物品批次，不复制“装饰法宝”和“隐藏可用法宝”。

同类墙桌柜可有材质、风格、磨损与陈设变体，外观不暗改占地。若材料确有导热/易燃/避水/五行作用，来自同一材质定义，并能被对应人物认识。整齐华美影响具体人物感受或接待判断，不默认对全宗门叠全局效率。

切开屋面、近墙淡出、分层选取应保持真实覆盖和障碍；藏屋顶不等于没屋顶。座位/操作朝向与真八方向持物、前后遮挡一致。新摆件不挡关键提示，生活故事也不全靠功能按钮列举。

## 环境、破坏与搬迁

屋面、开口、材质和真实来源决定遮雨、通风与热/五行作用。围合、覆盖、用途、环境适性分别查。按2026-11-05已定规则，木柜等普通物品也持续贡献非消耗的五行环境影响，摆放可以改变适性；这不自动发行可领取的无限灵气余额或通用吉凶。可吸收灵气由原物品另持储量，环境中积攒的容量/速率/变化后置；炉的热量和阵法实际消耗仍回各自领域。

同日最新温度方向为室外中性温度＋欧氏圆形场、室内一房一温。冷热有效等级先抵消再查表，房内按各格净等级的面积平均生成目标，火墙/冰墙是原物来源，普通家具不按数量参与平均。房间温度由环境域唯一保存、结构只推导空间；拆合接续及门漏热见[规范](../../proposals/environment/temperature.md#室内一间房一个温度)。这一温度近似不要求五行影响也全房均匀。

改建先结算旧布局到变更时刻，再改结构并失效受影响空间/路径/工位缓存，最后影响未来过程。拆墙可只改遮蔽，不使整坊所有动作瞬消；拆炉膛、毁唯一账簿、封操作位分别处理必要依赖。维护复杂度逐包定，不为生活感先铺整套维修劳动。

移动家具处理内容、占用者、在制品、连接和搬运能力。迁办事房还要有效记录、人员/使用权和通知；旧地址记忆可保留并导致跑空。空间分合不重生成库存，门锁不传送室内人。容器损坏、火灾、盗窃、围攻与逃离以后服务冒险和组织冲突，这些后果仍须按对象和过程具体设计。

## 状态归属、存档与近远连续性

以下是扩展约束，不要求现在创建同名新模块：

| 事实 | 当前归属或后续单一所有者 | 可派生信息 |
|---|---|---|
| 地形/旧高度 | 原`WorldMapData`；历史样本含单地表高度，新世界先采用平面地块；可变地表有真实施工来源后再接 | 静态空间候选 |
| 结构/家具 | 原工地`SimConstruction`；固定值事房原`places.records.workspace`，通用化须显式迁移 | 阻挡、覆盖、围合、操作面 |
| 身体/动作 | 原人物/非人及领域活动，共用身体占用查询 | 可达与是否有空 |
| 实物/预约 | 原`SimInventory`及唯一器物领域；容器不复制库存 | 柜内目录、余量、画面 |
| 过程/在制物 | 原领域已有活动或其扩展 | 工位忙碌、可续工 |
| 权利/任职/约定 | 原机构、个人约定或明确新物权事实 | 可办理/取用/分配者 |
| 记录与知识 | 载体内容、公账、个人认识分别保存 | 本人可读信息与可核查结果 |
| 环境/源流 | 原天气、余热、灵源等领域 | 适用条件与风险 |

连通、房间用途汇总、服务可用性和画面是派生查询，不与墙/物品各存矛盾的完成状态。命名区域、归属、床位、整理政策是人的持久安排；拆墙后可保留为失效/争议安排。缓存按受影响地块/连接失效，不逐帧全图扫房柜。

远处可不展动画和逐步脚步，不能离场免费完工或归来重抽结果。保留参与者、输入物/在制品、阶段、条件、关键时刻、未结责任；到缺料、受伤、源枯竭或设备受损等边界就停下/改走真实后续。近远成本与结果一致，重大事件和消息再影响当事人。

存档保存变化和进行中上下文，独立候选查位置/占地/容量/物品唯一性/引用/预约/权限/时间，不反查活世界。迁移不以新模板重建旧屋、补造家具、清旧账。自由装修的存档格式与迁移需明确验证，不能只放宽检查。

## 情境验收

以下是用于检验设计的候选情境，不构成开发顺序。

| 给定与行动 | 应有结果 |
|---|---|
| 空房摆同样桌柜，无人获授权 | 可放物书写，不能记官方贡献或领公库 |
| 同桌上午抄书、晚上吃饭，争同一操作位 | 按实际容量/约定安排，不复制桌子或同时完成互斥动作 |
| 修士在院中用真实御火替燃料 | 方法允许则付实际代价，不因无炼器房匾额拒绝 |
| 食物入柜，柜子搬到另一处 | 总量/产权不变，取食者须认识并到新位置 |
| 秘籍入柜，一人借走后另一人来读 | 不能远程读已不在的原本，借阅者是否理解另判 |
| 账簿遗失，但有抄本/证人/既存公账 | 不凭柜空抹债，可访问性、证据、机构承认分开 |
| 开炉中途撤人、熄火或拆必要器具 | 已用燃料保留支出，在制品有位置，按阶段暂停/受损 |
| 炉旁门墙改变或拆屋面 | 先结旧环境再影响未来，不依赖受损部件的过程可继续 |
| 小妖/巨兽尝试同床、门、工作台 | 按尺度/能力/替代工具判断，不统一套人身资格 |
| 同过程近场、离场、保存再重启 | 身体/实物/阶段/成本/结果一致，归来展开当前状态 |

## 后续新增设定的准入

用户已授权开发在玩法需要时主动扩展。新增床具、工位、储藏或场所，先说明让谁能做什么、接哪些已有对象、来源/知识/权利、失败和中断留下什么、玩家怎样察觉、远区和存档如何保持同一事实；复用动作、容量、物品和授权接缝。

仅有名字、图标或被动倍率的建筑先留候选；纯为美观就明确可选陈设，不假装生产必需。工时、容量、配方和偏好由开发测试；改变世界概念或玩家控制方式再请用户拍板。不预建万能ECS、全量设施目录、数十空autoload或插件来替代一个可玩的组合。
