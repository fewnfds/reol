# 社会关系、机构记录与继任

> 详细设计与候选：已确认体验原则见[社会与认识](../rules/society-and-knowledge.md)；具体记录、权重、机构政治和继任规则仍待评审。

## 已确定的体验与边界

- 同一个世界中，人物、组织、阵营和地方群体各有目的、经历与认识。组织通过具体成员、职位、资产与程序行动，成员不必有一致立场。
- 贡献由有权机构及其记录持有；人情来自具体人物的经历和承诺；名声来自有限传播；礼数随人、场合与文化发生。它们相互影响，但不自动合成一个全局声望、货币或统一好感。
- 认识、尊敬、信任、实际授权、资源支配和愿意冒险分别判断。点头之交通常不自动提供实利，陌生人也可能因善意或职责提供帮助；具体行动有时间、风险和成本。
- 人与职位分开：以职位办理的组织事务与个人承诺各有来源。人员离职、死亡或更替可改变后续办理，不能凭此抹除真实发生的交付、其他人已有记忆或仍被承认的组织债务。
- 见证、个人记忆、实物和记录可以冲突、丢失、伪造或过时。玩家个人记下的内容不自动成为机构账目、游戏权威事实或人物已掌握的技能；它可以成为调查、表达或依法核验的依据。
- 玩家和NPC使用同样的实际条件；提出意图、理解和回应、执行与后果分开。社会骰只处理客观可行条件下的不确定反应，原处境没改变时不靠反复点击重抽。
- UI只表达主体能看到、听说、查到的信息；玩家可以看自己的确切余额、金额与期限，不需要把所有数值藏起来。开发诊断与人物认识分开。

## 共同生活如何推动社会

```text
需求/目的 → 按所知选择行动 → 实际执行与结果
    → 当事人观察或收消息 → 各自解释/记录/回应
    → 后续行动、关系、组织安排与未结责任
```

社会不要求所有事都有人目击或进入账本：无人看见的桥被破坏仍然破坏，只有知情者才会据此改变认识。人物可能出于职责、善意、互惠、利益、恐惧或误会作出不同选择。记录获得社会效力需要当地有权者、可访问的载体、程序和实际执行能力；记载真实与否、是否被承认、能否兑现也是不同问题。

## 对象与归属

| 对象 | 应承担的事实 | 不可混同 |
|---|---|---|
| 人物关系与经历 | 两个当事人各自的记忆、身份、信任、情感、期望、承诺 | 不是可任意转卖的统一凭证，也不对称地自动复制 |
| 机构及职位 | 成员、职责、决定权、资源、政策、现任者及空缺 | 组织整体不等于每名成员的私人意愿 |
| 公共记录与凭据 | 签发与登记者、对象、依据、范围、状态与可核验内容 | 真实记录不保证所有人知道，也不保证一定能兑付 |
| 私人记录、见闻与说法 | 某人所写、所见或所听到的内容及其来源 | 私记不自动变成公账，传闻不等于发生事实 |
| 实物和实际控制 | 真正的库存、保管位置、出入条件与使用能力 | 账面有权不等于已经持有；钥匙或持有不自动意味着合法 |

记录可以由账房、长老、实物账册或具备相应规则的法器管理。储存设施和物件本身不会凭空产生官方权力：工作需要实际人员或有授权的设施、可访问记录和相应资源。设施、房间和操作条件见[建造与空间](construction_and_space.md)。

## 当旧友去世或失去职位

例：玩家与旧掌门交好，过去因为其个人引荐、组织政策和个别门人的情谊，得到礼遇和便利。闭关归来时新掌门接任，值事者可能仍客气，但新规不再允许通行，某些旧账须核验，旧友弟子仍愿意私下帮忙。

这些变化应从实际职位、权限、保管人、资源、政策、个人交往和消息传播产生；不能让人物离场后整个门派冻结，也不能用统一声望衰减直接计算所有结果。怎样获得新授权、核账、求助、协调或另谋出路，取决于当事人已知信息与实际权力。

## 尚未确定的模型

- **Claim** 是可记录的权利、义务、凭据或身份的候选模型；不能默认统包情感、记忆、传闻与一切社会事实，也不能把一次公式计算当作全体社会过程。
- **关系维度、行为判定与机构流程**：关系可由经历、情境预期及少量摘要表示；各维度、权重、衰减和骰判尚需基于真实互动测试，不预设所有关系必然随时间降低。
- **争议路径**：协商、调解、核验、裁断、行动与报复等都是候选，是否发生及先后由机构、权力、当事人和情境决定，非全世界强制固定队列。
- **死亡与继承**：个人感情、私人债务、公账、职位、实物与证据逐项按事实、关系、制度、遗愿和承认处理；不强制人情一律消失或承诺一律传给后人。
- **内容与资源**：贡献是否可转让、能否继承、能换什么，法器是否承认特定签发者，均为具体机构与法器规则，不先规定整个世界共用的汇率。

## 5.7 继任原型的地位

早期[历史草案的5.7](https://github.com/fewnfds/reol/blob/8c3deaa972f932e999167b61ea6b166b928cfe5f/docs/archive/documentation_consolidation_20261104/design/systems/social_system.md)及`SuccessionResolver`提出两阶段方案：先对候选人和权势形成结果，再考虑逐笔旧账是否承认、折价、冻结、谈判或拒绝。名分、派系、实力、控制、资源、证据、受益者、前任联系等都可能是候选因素；**权重、阈值、硬门槛及五种结果只是隔离原型，不代表用户已拍板，也没有接入完整组织与人物行为。**

未来若重新采用，应先基于候选人本人所知、组织程序、实际资产与有关人的选择，区分提议、承认和执行，再用可解释的多个场景验证；不能默认空位时全部旧账冻结，也不能以一次总分决定所有部门和成员的反应。原型如何被迁移、替代或保留由实际设计验证决定。

## 共同验收情境

以下是目标，不表示当前已通过：

1. 交付真实存在，但无见证和无授权登记，私记不能直接兑换公库；知情人可出面举证。
2. 原账簿存在但管事不在、权限被撤或库存不足，账面权利与实际兑现分别表达。
3. 敬重者拒绝高风险请求、陌生人因职责愿意帮忙；改变条件或引入证据才重新判断。
4. 换掌门后不同部门、旧友门人与新任者作出不同反应，已发生的账目、私情和传闻不被整体清零。
5. 自主NPC在玩家缺席时发起请求、执行承诺并传递有限消息；入场、保存、恢复不重抽已发生结果或复制资源。
6. 未知的暗账和内部动机不能通过价格、按钮理由或UI排序无意泄露给玩家。
