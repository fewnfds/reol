# 社会系统（Social System）

> **2026-11-02 评审前提（用户重新明确）**：目标是在模拟经营与角色扮演游戏中，让人物自身的生活、动机、认知、人际关系和互动后果共同形成持续运行的社会循环。社会变化应有具体行为与因果来源，不能用一套顶层加减数值代替社会过程；隐藏数值或改成定性词也不足以满足这一目标。
>
> 本文既有的 Claim 中心模型、统一关系维度、继任权重、死亡后人情处理、争议顺序与首版范围均作为待重新评审的方案，不因旧 AI 摘要而视为用户已经确认。当前讨论尚未批准替代架构；暂不直接进入旧交接的 ClaimBook 实现顺序。
>
> 用户补充允许内部骰判，要求因素参考心理学、社会学并保持简洁。新的讨论提案及研究来源见 [社会互动评审笔记](social_interaction_review.md)，其中具体算法与参数尚未定稿。

- **状态**：草案（待评审）
- **最后更新**：2026-11-01
- **相关 ADR**：ADR-0020（提议）
- **一句话**：人物的声望、贡献、人情、职位不是人物属性，而是由他人、机构和法器记录并承认的**社会事实**；社会靠记录、承认、兑付、继任和维护运转。

## 0. 一页速览

- **社会事实 = Claim**：谁发行、谁记账、对谁、在什么范围、什么状态、有什么证据。
- **五层分开存**：物质、关系、制度、记录、叙事；不要混成一个声望值。
- **四种账本**：机构账、职位账、私人账、法器账。
- **五种社会资本**：面子、实利、人情、名声、账目；可以同时高/低。
- **运行循环**：行动 → 目击 → 解释 → 记录 → 承认 → 兑付 → 维护 → 继任。
- **玩家只看人话**：词、账页、对话、通行、价格、座次；不显示真值，不做信任进度条。
- **扩展靠事件**：事件日志 + 投影 + 数据定义 + 稳定 API + 版本迁移。
- **v1 只做**：1 个宗门、3 种 Claim、1 次继任、老掌门坐化、私记对质。

## 1. 设计前提（现实逻辑）

这套系统不是“声望条 + 好感度”，而是试图复现现实社会的几条基本规律：

1. **社会事实需要被承认**。你做了什么不重要，重要的是谁看见、谁记下、谁认账。
2. **记录有成本、有权威、有偏差**。不是所有人都有资格记账；记账的人会漏、会错、会收钱、会伪造。
3. **制度比人长寿，但制度会变**。职位还在，坐在职位上的人换了，规矩就可能变。
4. **关系是双向、多维度、会衰减的**。信任、亲近、敬重、畏惧、亏欠不是同一个东西；你信他，不代表他信你。
5. **面子和实利必须分开**。可以当面恭敬，同时一件事都不给你办。
6. **权力不等于权威，权威不等于合法性**。有兵不代表有人认；有人认不代表坐得稳。
7. **信息不对称是常态**。官方账、私记、传闻永远对不上；玩家看到的不是“真值”。
8. **交换需要信用，信用会贬值**。贡献像银行存款，银行可能挤兑、冻结、赖账。
9. **继承不是复制，是重新谈判**。老领导的承诺，新领导没有义务全认。
10. **秩序需要维护，否则熵增**。关系会淡，账会烂，合法性会掉，规矩会松。

### 1.1 一条设计铁律

> **每一个社会算法，都必须能用一句玩家听得懂的话解释。**

例如：

- “他记得你帮他挑过水。”
- “新掌门要立威，所以先冻旧账。”
- “长老怕你抢他的位置。”
- “宗门今年缺灵石，兑付要排队。”
- “大家都在传你杀了人，虽然没人看见。”

解释不了，就是设计太复杂，应该砍掉。

### 1.2 术语

| 术语 | 含义 |
|---|---|
| **Claim** | 一条社会事实/凭证：谁承认谁拥有什么权利、义务或身份 |
| **Issuer** | 发行方：有资格签发这条 Claim 的机构/职位/个人/法器 |
| **Registrar** | 记账人：实际把这条 Claim 写进账本的人或法器 |
| **Scope** | 适用范围：这条 Claim 在哪个机构/地域/人群中有效 |
| **Ledger** | 账本：一组 Claim + 索引 + 记账/兑付/继承规则 |
| **Projection** | 投影：从事件日志算出来的当前状态缓存，可重建 |
| **Office** | 职位：制度里的位置，和坐这个位置的人分开 |

## 2. 玩家体验

### 2.1 玩家看到什么

玩家不看到一个“声望 73”的面板，而是看到：

- **人的态度**：执事还行礼，但话变少了；厨娘偷偷给你留饭；新掌门当众夸你，却不批你的申请。
- **门的开合**：秘境通行被拒；功法阁只让你进第一层；任务板不再给你高贡献差事。
- **价格与排队**：同样的丹药，你买比别人贵；兑付贡献要等三个月。
- **纸与印**：功德堂的账页、掌门的批红、长老的私信、你自己的笔记本、告示栏上的传闻。
- **仪式与座次**：宴席坐哪一桌；祭典站第几排；谁先敬酒；谁被当众训斥。

### 2.2 玩家做什么决策

- 这份贡献，记在功德堂、记在某个长老名下，还是只留在自己笔记本里？
- 现在兑成功法，还是赌新掌门认旧账？
- 讨好记账长老，还是绕过他找掌门批红？
- 把贡献分散在几个机构，还是集中换一个大位子？
- 老掌门快不行了，是先变现、找见证人、还是押注下一个掌门？
- 被赖账了，是申诉、私了、闹大、还是换一个宗门？
- 要不要伪造一份记录？被查出来怎么办？
- 要不要替别人担保？他还不上，账算谁的？

### 2.3 反馈

- **语言**：NPC 的称呼、语气、话里的保留。
- **行为**：帮不帮、带不带、让不让进、给不给折扣。
- **文件**：账页上的印章、批注、状态；私记与官方账的差异。
- **后果**：任务、价格、通行、座次、婚配、收徒、保命。

### 2.4 失败

失败不是“读档”，而是社会性死亡的一种：

- 账被冻结，贡献取不出来；
- 被拒付，多年积蓄变空头；
- 被当众羞辱，面子崩了；
- 被逐出宗门，旧账全部作废；
- 被通缉，换身份才能重新开始。

**失败要能继续玩**：冻结不是删除，拒付不是消失，而是变成新的任务、官司、仇怨或流亡线。

## 3. 核心本体：五层社会

| 层 | 内容 | 主要时间尺度 | 核心问题 |
|---|---|---|---|
| **物质层** | 身体、资源、土地、法器、武力 | tick / 日 | 谁控制什么？谁能伤害谁？ |
| **关系层** | 信任、亲近、敬重、畏惧、亏欠、身份 | 日 / 月 | 谁信谁？谁欠谁？谁恨谁？ |
| **制度层** | 机构、职位、规则、派系、合法性 | 月 / 年 | 谁有权？规矩是什么？谁说了算？ |
| **记录层** | 凭证、账本、契约、证词、秘密 | 事件驱动 | 谁记的？凭什么？现在算不算？ |
| **叙事层** | 传闻、名声、面子、舆论、历史 | 日 / 年 | 别人怎么说？大家信什么？ |

社会运行，就是这五层之间不断转换：

```
物质行动 → 事件 → 被看见 → 被解释 → 被记录 → 被承认 → 可兑付 → 改变物质/关系/制度
```

## 4. 核心对象

### 4.1 社会事实（Claim）

**Claim 是社会系统的最小单位**。它表示“某个发行方承认某个主体拥有某种权利/义务/身份”。

| 字段 | 含义 |
|---|---|
| `id` | 稳定 ID |
| `type` | 贡献、人情、债务、契约、头衔、证词、悬赏、誓约、秘密、名声标签 |
| `issuer` | 发行方：机构、职位、个人、法器 |
| `registrar` | 实际记账的人/法器 |
| `subject` | 被记录者（受益人/义务人） |
| `counterparty` | 相对方（债务/人情的另一头） |
| `scope` | 在哪个机构/地域/人群范围内有效 |
| `amount` / `unit` | 面额与单位；非数值型可为空 |
| `created_tick` / `expires_tick` | 生效与失效时间 |
| `status` | 见 4.1.1 |
| `confidence` | 证据强度/可信度 |
| `provenance` | 来源事件、父凭证、见证人 |
| `witnesses` | 见证人 |
| `visibility` | 公开 / 私密 / 秘密 |
| `tags` | 扩展标签，给规则和 UI 用 |

#### 4.1.1 Claim 状态机

```
签发 → 记账 → 承认 → 可用 → 兑付
                  ↘ 冻结 → 解冻 / 重新登记 / 拒付
                  ↘ 争议 → 审计 / 调解 / 审判 → 有效 / 无效
         ↘ 转让 / 抵押 / 拆分
         ↘ 过期 / 丢失 / 继承
```

状态不是全局的，而是**按 scope 分别成立**。同一份贡献可以“功德堂认、掌门不认”；同一件事可以“宗门不追究、江湖已传遍”。

#### 4.1.2 Claim 类型（首版）

| 类型 | 发行方 | 能否转让 | 能否继承 | 典型兑付 |
|---|---|---|---|---|
| 贡献 | 功德堂/宗门 | 可（收手续费） | 按继任政策 | 月例、功法、职位、通行 |
| 人情 | 个人 | 通常不可 | 通常不可 | 私下帮忙、担保、通风报信 |
| 债务 | 个人/机构 | 可 | 可 | 灵石、物品、劳役 |
| 契约 | 机构 | 可 | 可 | 长期服务、供货、婚姻 |
| 头衔/职位 | 机构 | 不可 | 按制度 | 权限、座次、资源 |
| 证词 | 个人 | 不可 | 可（作为证据） | 官司、审计、对质 |
| 悬赏 | 机构 | 可 | 不可 | 赏金、通缉、赦免 |
| 誓约 | 个人/机构 | 不可 | 不可 | 背叛代价、天谴、信誉 |
| 秘密 | 个人 | 可（作为筹码） | 可 | 威胁、交易、保命 |
| 名声标签 | 人群/机构 | 不可 | 会失真 | 初见态度、任务、价格 |

### 4.2 账本（Ledger）

账本不是“一个数字”，而是一组 Claim + 索引 + 政策。

- **机构账本**：宗门、功德堂、任务板、库房。
- **职位账本**：掌门、执事、长老的职权记录。
- **个人账本**：私记、欠条、信件、回忆。
- **法器账本**：由器灵/玉简/石碑记录，权威高，但可能损坏、被篡改、认旧主。

账本要有：

- **记账规则**：谁可以记、记什么、需要什么证据。
- **兑付规则**：什么能换什么、汇率、排队、手续费。
- **审计规则**：谁能查账、查出来怎么办。
- **继承规则**：换人之后旧账怎么处理。

### 4.3 机构（Institution）

机构 = **规则 + 职位 + 成员 + 账本 + 资源 + 合法性 + 派系**。

机构不是铁板一块。它至少有四种“态度”：

1. **官方政策**：掌门/长老会当前执行的规矩。
2. **派系力量**：谁掌权、谁反对、谁观望。
3. **成员私意**：每个成员自己的好恶。
4. **对外叙事**：对外怎么宣传、怎么解释。

玩家感受到的“宗门态度”，是这四者的合成，而不是一个好感度。

### 4.4 职位（Office）

职位是**制度层的关键**，必须和人分开：

- 职位有：权限、职责、待遇、账本、继任规则。
- 人只是**现任者**。
- 人死了，职位还在；职位可能空缺、被争、被废、被架空。
- **职位签发的 Claim 是“公账”**；个人签发的 Claim 是“私账”。
- 新官上任，可以认旧账，也可以不认；这取决于他的派系、合法性、资源和个人恩怨。

> 这就是“人走茶凉”的底层逻辑：茶是职位给的，不是人给的。

### 4.5 关系（Relationship）

关系是**有向、多维、会衰减**的：

| 维度 | 含义 | 典型来源 |
|---|---|---|
| 信任 | 相信对方不会害我/会履约 | 守约、共患难、长期合作 |
| 亲近 | 情感上的喜欢/亲近 | 相处、礼物、共同经历 |
| 敬重 | 认可对方的能力/德行/地位 | 战功、修为、学识、身份 |
| 畏惧 | 相信对方能伤害我 | 暴力、权势、威慑 |
| 亏欠 | 欠对方的恩/债 | 恩惠、救命、担保 |
| 身份 | 亲族、同门、师徒、主仆、仇敌 | 出身、拜师、婚姻、结拜 |
| 历史 | 关键事件记忆 | 救助、背叛、羞辱、承诺 |

关系不是“好感 60”。玩家看到的是词：

- 信任：戒备 / 试探 / 信任 / 托付 / 生死相托
- 亲近：冷淡 / 客气 / 亲近 / 知己 / 挚爱
- 敬重：轻视 / 平视 / 敬重 / 钦佩 / 敬畏
- 畏惧：无 / 忌惮 / 畏惧 / 恐惧
- 亏欠：无 / 小恩 / 大恩 / 命债

**不对称**：你信任他，不代表他信任你。**会衰减**：久不往来会淡；但畏惧和血仇衰减很慢。

### 4.6 信念、传闻、面子

- **信念（Belief）**：某个 NPC 认为某事是真的，带置信度、来源、时间。
- **传闻（Rumor）**：信念在社交网络中传播、变形、衰减。
- **名声（Fame）**：广泛但浅的公共信念，容易失真。
- **面子（Face/Deference）**：公开场合的礼数表现，不等于实利。
- **合法性（Legitimacy）**：大家相信某个权威/规则是正当的。

这五者必须分开存储。一个人可以“官方无罪、民间传凶、掌门欣赏、长老忌惮、百姓畏惧”。

## 5. 社会如何运行（循环）

### 5.1 总循环

```
① 行动       做工、送礼、救人、杀人、交易、修炼、告状
② 事件       发生了什么；时间、地点、参与者
③ 目击       谁看见/听说；距离、视线、声音、渠道
④ 解释       目击者用自己的价值观、关系、利益去理解
⑤ 记录       有资格的人/法器记下；可能漏、错、收钱、伪造
⑥ 承认       相关机构/人群决定认不认；按 scope 分别成立
⑦ 兑付       贡献换权限；人情换帮忙；债务要还；头衔给权
⑧ 关系/叙事  信任、敬重、畏惧、亏欠变化；传闻扩散；面子涨落
⑨ 维护/衰减  拜访、送礼、审计、惩罚、仪式；否则关系淡、账烂、合法性掉
⑩ 继任/改制  换人、换规矩、换账本；旧账重新谈判
```

### 5.2 时间尺度

| 频率 | 处理 |
|---|---|
| 每 tick / 每帧 | 行动、移动、战斗、即时感知 |
| 每游戏小时 | 目击、传闻扩散、局部关系微调 |
| 每日 | 工作记账、需求、关系衰减、价格 |
| 每月 | 月例、贡献结算、派系博弈、审计 |
| 每年 | 继任、改制、记忆压缩、账本归档 |
| 每代 | 制度兴衰、文化变迁、旧账彻底重估 |

### 5.3 感知与目击

一个行为要被社会记住，至少要过三关：

1. **有人看见**：距离、视线、声音、潜伏、遮挡。
2. **有人在意**：这件事对目击者重不重要；是否值得记。
3. **有人能记**：目击者有没有记账权；他愿不愿意记；他记的是不是真的。

因此：

- 没有见证人的善行，可能只有你自己的笔记本记得。
- 当众的恶行，即使官方不记，传闻也会记。
- 密室里的交易，只有参与者和秘密记得。
- 法器可以记账，但法器可能坏、可能认旧主、可能被篡改。

### 5.4 记录与记账人

记账人是一个**有私心的人**：

- 他可能漏记、错记、拖延、收贿、勒索、伪造。
- 他可能怕担责，只记“安全”的事。
- 他可能把功劳记在自己派系名下。
- 他可能把账本当成权力工具。

玩家可以：

- 讨好他、贿赂他、威胁他；
- 找另一个记账人；
- 找见证人；
- 自己记私账；
- 伪造；
- 绕过他，直接找更高权威批红。

### 5.5 承认与机构态度

一个 Claim 是否有效，取决于：

1. **发行方当时有没有权限**；
2. **记账人是否可信**；
3. **证据是否充分**；
4. **当前政策是否承认**；
5. **承认它是否符合当权者的利益**；
6. **有没有能力强制执行**。

机构态度不是“成员好感平均值”，而是以下五者的加权合成：

- **官方政策**：掌门/长老会当前执行的规矩。
- **派系力量**：谁掌权、谁反对、谁观望。
- **成员私意**：每个成员自己的好恶，按职位/影响力加权。
- **对外叙事**：对外怎么宣传、怎么解释。
- **物质利益**：资源、贸易、战争、财政的现实约束。

所以完全可能出现：

- 掌门公开称赞你（面子）；
- 功德堂冻结你的旧账（实利）；
- 阿禾偷偷帮你（人情）；
- 外面传你是功臣（名声）；
- 长老忌惮你（畏惧）。

这五条同时成立，不矛盾。

### 5.6 兑付与信用

贡献不是金币，是**机构负债**。它的价值取决于：

- **发行方信用**：宗门稳不稳、有没有资源、说话算不算数。
- **兑付能力**：功法、月例、灵石够不够。
- **政策风险**：换掌门、改制、战争。
- **记录完整性**：账本在不在、有没有被改。
- **流动性**：能不能转让、要排多久队、有没有黑市折扣。

玩家看到的信用词：

| 词 | 含义 |
|---|---|
| 铁账 | 随时兑，大家都认 |
| 稳当 | 能兑，但有限制 |
| 勉强 | 能兑，但要排队/打折 |
| 不稳 | 政策一变就可能冻 |
| 空头 | 大概率兑不出来 |

### 5.7 继任与改制

继任不是“换一个名字”，而是一次**宪法危机**：

1. **空缺**：死亡、退位、被废、失踪、闭关不出。
2. **竞争者**：血亲、弟子、派系领袖、外部势力、法器择主。
3. **合法性来源**：血脉、功劳、选举、任命、武力、天意、法器认可。
4. **竞争手段**：游说、送礼、许诺、威胁、黑料、决斗、政变。
5. **结果**：新掌门、新政策、新合法性。
6. **旧账处理**：认、冻、折、赖、清。
7. **人事调整**：旧臣留任/外放/清洗；新贵上位。
8. **叙事重写**：官方历史、赦免、替罪羊、禁令。
9. **网络重组**：旧关系贬值，新关系升值；中间人、派系领袖起落。

旧账怎么处理，不由一个全局百分比决定，而由**两个阶段**算出来：

```
阶段 A：谁继位，以什么合法性继位
        ↓ 输出：合法性、不安全感、派系接受度、未解决竞争者
阶段 B：新掌门逐笔决定旧 Claim 怎么办
        ↓ 输出：全认 / 折价 / 冻结 / 谈判 / 拒付 + 理由
```

#### 5.7.1 为什么不用固定百分比

固定“恢复 80%”或“默认冻结”有三个问题：

- 它假设所有新掌门都一样，忽略继任者得位正不正、库房空不空、性格如何。
- 它假设所有旧账都一样，忽略凭证强弱、持有人强弱、公开程度、是否旧朝遗产。
- 它让玩家很快学会“最优解”，而不是读人、读势、读账。

现实里，新掌门对每一笔旧账问的是同一个问题：

> **“认这笔账，对我坐稳位子有什么好处？不认，会付出什么代价？”**

所以继任策略是**逐笔算出来的政策**，不是全局汇率。

#### 5.7.2 阶段 A：候选人结算

每个有资格的人先过**硬门槛**（职位章程、血脉、境界、长老会推举、法器认可），不满足就出局；剩下的按八项打分：

| 因素 | 含义 | 0 分 | 1 分 |
|---|---|---|---|
| 名分 mandate | 血脉、任命、章程、法器认可 | 无依据 | 名正言顺 |
| 派系 backing | 加权派系支持 | 无人支持 | 一致拥戴 |
| 实力 power | 自身境界 + 亲信 + 战力 | 远弱于对手 | 压倒性 |
| 控制 control | 已掌握印、账、门禁、护卫 | 什么都没有 | 已控制要害 |
| 声望 standing | 功绩、口碑、丑闻 | 声名狼藉 | 众望所归 |
| 财力 purse | 可调动资源 / 需要 | 空库 | 充裕 |
| 前任 predecessor | 前任信任、指定、师徒 | 被防备 | 指定继承人 |
| 外援 outside | 盟友、靠山、外宗 | 孤立 | 强援 |

默认权重（数据可覆盖）：

```text
名分 0.25 · 派系 0.20 · 实力 0.18 · 控制 0.14
声望 0.08 · 财力 0.06 · 前任 0.05 · 外援 0.04
```

`S(c) = Σ 权重 × 因素`。最高分者继位；但有两种特殊情况：

- **相对差距 < 0.15**（`(第一 − 第二) / 第一`）：争议继位。赢家仍上位，但合法性 ×0.8（争议惩罚系数，可调），第二名成为“未解决的竞争者”（可发难、可分裂、可被外部利用）。
- **无人过门槛**：空位期。职位空缺，由长老会/摄政/法器代管；旧账默认全部冻结，直到新权威产生。

合法性：

```text
legitimacy = clamp(0.60 × S(winner) + 0.25 × 派系接受度 + 0.15 × 前任背书, 0, 1)
insecurity = 1 - legitimacy
```

其中“派系接受度”取赢家的 `backing`，“前任背书”取 `predecessor`。

合法性不是“王霸之气”，而是**别人愿不愿意按你的规矩办**。合法性低的新掌门会更需要立威、清算、买支持或拖延。

#### 5.7.3 阶段 B：逐笔旧账结算

对每一条旧 Claim，候选动作只有五个：

| 动作 | 做什么 | 典型代价 |
|---|---|---|
| 全认 honor | 原额承认，立即或按期兑付 | 财政压力、继承旧包袱、先例扩散 |
| 折价 discount | 承认但按比例兑付 | 信用受损、持有人不满 |
| 冻结 freeze | 暂不承认，等重新登记/审计 | 怨气、行政成本、支持者流失 |
| 谈判 bargain | 承认一部分，换取忠诚/服务/背书/放弃 | 需要对方有筹码，谈判耗时 |
| 拒付 repudiate | 明确不认 | 信用崩、报复、派系冲突、先例反噬 |

每个动作的效用：

```text
U(action) = Σ 权重[action][factor] × factor + 性格偏差[action]
```

因素全部归一到 0..1：

| 因素 | 含义 |
|---|---|
| validity 凭证效力 | 发行权限 × 记账可信 × 证据 × 印章/法器 × 见证人 |
| burden 财政负担 | 这笔账相对库房/年入的压力 |
| continuity 稳定收益 | 认账能换来多少稳定、信用、人心 |
| affinity 政治亲疏 | 持有人是赢家阵营、中立，还是对手阵营 |
| bond 个人恩怨 | 新掌门对持有人的感激/记恨 |
| leverage 反制能力 | 持有人相对新掌门的实力、盟友、闹事/报复能力 |
| visibility 公开度 | 这件事有多少人看着 |
| precedent 先例压力 | 同类旧账有多少；这一笔会不会成为判例 |
| need 新掌门需求 | 新掌门多需要这个人的支持 |
| old_regime 旧朝关联 | 这笔账有多深地绑在前任个人身上 |
| insecurity 不安全感 | 1 − 合法性 |
| legitimacy 合法性 | 阶段 A 输出 |

你提到的现实因素，落在这些变量上：

| 现实说法 | 算法里的变量 |
|---|---|
| 门派声誉 | 阶段 A 的 `standing`；阶段 B 的 `visibility`、`continuity`；拒付还会反过来改机构信用 |
| 个人恩怨 | `bond`（私人感激/记恨）；`affinity` 是政治亲疏，两者分开 |
| 审时度势 | `burden`（库房）、`insecurity`（位子稳不稳）、`need`（需不需要此人）、`old_regime`（旧朝包袱）、`precedent`（会不会认一笔来一片） |
| 人物实力差距 | `leverage`（持有人相对新掌门的反制能力），对照阶段 A 的 `power`、`control`、`legitimacy` |

**输入不是客观真值，而是新掌门“以为”的值。** 他可能低估你的实力、错判账目真伪、被派系蒙蔽、不知道你和前任的私交。调用方传入的是**感知/情报**，不是世界真相；玩家只能通过对话、账页、行为和第三方打听去推断。这样同一局面在玩家看来“应该全认”，新掌门却可能算成“冻结”——这不是 bug，是信息不对称。

首版权重（正号 = 该因素让动作更有吸引力，负号 = 抑制；必须用黄金场景校准，不要当真理）：

| 因素 | 全认 | 折价 | 冻结 | 谈判 | 拒付 |
|---|---:|---:|---:|---:|---:|
| 凭证效力 | +0.32 | +0.22 | +0.03 | +0.14 | −0.40 |
| 财政负担 | −0.30 | +0.12 | +0.18 | −0.06 | +0.30 |
| 稳定收益 | +0.18 | +0.10 | −0.06 | +0.08 | −0.20 |
| 政治亲疏 | +0.08 | +0.04 | −0.05 | +0.06 | −0.10 |
| 个人恩怨 | +0.08 | +0.03 | −0.04 | +0.04 | −0.09 |
| 反制能力 | −0.08 | −0.03 | −0.10 | +0.16 | −0.24 |
| 公开度 | +0.06 | −0.03 | −0.04 | +0.03 | −0.16 |
| 先例压力 | −0.10 | −0.04 | −0.05 | 0 | +0.08 |
| 新掌门需求 | +0.05 | +0.02 | +0.04 | +0.12 | −0.10 |
| 旧朝关联 | −0.10 | −0.10 | +0.14 | −0.02 | +0.08 |
| 不安全感 | −0.08 | −0.04 | +0.18 | +0.04 | −0.10 |
| 合法性 | +0.10 | +0.02 | −0.06 | +0.04 | +0.12 |

读法：

- **全认**吃“证据硬、财政轻、能换稳定、对方是盟友”；怕“负担重、旧朝包袱、先例扩散”。
- **折价**是“账是真的，但我不想全付”；证据越硬、越能换稳定，折得越少。
- **冻结**吃“库房空、旧朝账、新掌门心虚、对方暂时闹不动”；怕“公开度高、对方有反制力”。
- **谈判**吃“对方有筹码、新掌门需要他、账本身站得住”；对方越强越可能谈，而不是赖。
- **拒付**吃“账可疑、财政紧、对方弱、新掌门坐得稳”；怕“证据硬、公开度高、对方能报复”。

#### 5.7.4 硬门槛（先于打分）

以下情况直接禁用某些动作，避免算法算出荒唐结果：

- `validity < 0.20`：无凭证、无见证、无登记 → 不能全认/折价/谈判，只能冻结待查或拒付。
- `burden ≥ 0.90`：库房见底 → 不能全认。
- `leverage ≥ 0.75` 且 `visibility ≥ 0.60`：对方有实力且事情公开 → 不能拒付。
- `insecurity ≥ 0.65` 且 `visibility ≥ 0.70`：新掌门立足未稳且众目睽睽 → 不能拒付。
- `sealed_artifact` 且 `validity ≥ 0.70`：法器封存的账 → 不能拒付。
- `expired` 且无续期条款：不能全认（可折价/冻结/谈判）。
- 人情账的相对方死亡：默认失效；有遗嘱/信物/见证人时，转成对继承人或遗产的 Claim，再走同一算法。

#### 5.7.5 性格与解释

权重是“制度理性”，性格是“个人偏差”。同一局面，不同新掌门会做出不同选择：

| 性格 | 偏差 |
|---|---|
| 重诺 honorable | 全认 +0.10，拒付 −0.10 |
| 多疑 paranoid | 冻结 +0.08，拒付 +0.05，全认 −0.04 |
| 务实 pragmatic | 谈判 +0.08，折价 +0.04 |
| 贪利 greedy | 拒付 +0.06，全认 −0.05 |
| 好名 populist | 全认 +0.05，拒付 −0.08 |
| 记仇 vindictive | 拒付 +0.08，冻结 +0.02 |
| 软弱 weak | 冻结 +0.08，拒付 −0.12 |
| 果决 decisive | 拒付 +0.04，冻结 −0.04 |

若前两名效用差 < 0.02，且冻结与第一名也在这 0.02 内，取冻结——这是官僚系统的拖延本能，不是全局默认。否则取第一名；性格偏差已经计入分数。

输出不只给动作，还要给**理由标签**，取对结果贡献最大的 3 项：

```text
treasury_strained     库房紧张
weak_mandate          新掌门立足未稳
old_regime_loyalty    这是旧朝的人情账
claim_well_evidenced  账目证据确凿
retaliation_risk      对方不是能随便打发的人
precedent_flood       同类旧账太多，认一笔就得认一片
personal_grudge       新掌门记恨此人
needs_support         新掌门需要此人支持
```

UI 把标签翻成人话：

> “新掌门刚继位，库房又空；这笔账是老师父当年许下的，认了怕旧党抬头。先冻着，让他重新登记。”

#### 5.7.6 动作的后果

动作不是终点，而是新事件的起点：

- **全认**：Claim 保持有效；库房减少；信用上升；同类持有人可能来兑付。
- **折价**：Claim 面额 × 折价率；折价率由 `0.20 + 0.45×validity + 0.20×continuity + 0.15×(1−burden)` 算出，clamp 到 15%–90%，不是固定 80%。
- **冻结**：状态 `FROZEN`；记录复核条件（见证人、旧账页、法器核验、期限）；持有人可申诉/找关系/闹事。
- **谈判**：旧 Claim 部分恢复，同时产生一条新的**义务 Claim**（效忠、服役、公开背书、放弃部分旧账）；任一方违约都会产生新争议。
- **拒付**：状态 `REPUDIATED`；机构信用下降；持有人可能获得一条**怨恨 Claim**（复仇权/申诉权）；公开拒付还会改派系关系与传闻。

同一份旧账在不同局面下会得到不同结果。例如：

| 局面 | 新掌门 | 旧账 | 结果 |
|---|---|---|---|
| 得位不正、库房空、持有人弱、旧朝账 | 不安全感高 | 证据中等、公开度低 | 冻结 |
| 名正言顺、库房足、持有人是拥立者 | 合法性高 | 证据硬、公开度高 | 全认 |
| 新掌门弱、持有人强且公开支持过前任 | 需要其支持 | 法器封存、反制力高 | 谈判 |
| 新掌门稳、账目伪造、持有人无势力 | 合法性高 | 证据弱、公开度低 | 拒付 |
| 新掌门中等、账真但太贵、持有人弱 | 合法性中等 | 证据硬、负担重 | 折价 |

#### 5.7.7 与“冻结重登记”的关系

“冻结 + 重新登记”不再是默认政策，而是**算法在特定局面下的一个输出**。它通常出现在：

- 新掌门合法性低、需要时间；
- 库房紧、暂时付不起；
- 旧账证据不足、需要补证人；
- 旧朝关联深、直接全认会养大旧党；
- 持有人暂时没有反制能力。

如果持有人强、账又硬，算法会倾向谈判；如果新掌门稳、账可疑，算法会倾向拒付；如果财政宽裕、对方是盟友，算法会倾向全认。玩家要读的是**人、势、账**，不是背一个百分比。

### 5.8 争议、审计、审判

当两份记录冲突：

- 先调解（长老、中间人）；
- 再审计（查账、对质、见证人）；
- 再审判（掌门/执法堂）；
- 最后私斗/暗杀/政变。

证据类型：

- 官方账页、印章、批红；
- 法器记录；
- 见证人；
- 私记、信件；
- 誓言/天谴；
- 传闻（弱证据，但能影响舆论）。

结果不仅决定这一笔账，还会形成**先例**：以后类似的事怎么判。先例本身也是一种 Claim。

惩罚阶梯（从轻到重）：

```
闲话 → 失面 → 赔礼/罚款 → 降职/夺权 → 体罚/禁闭 → 逐出 → 通缉 → 处死/血仇
```

惩罚不只是“扣血”，它会改关系、改账本、改合法性，也可能制造新的 Claim（赔偿、赦免、复仇权）。

### 5.9 社会流动与身份

现实社会里，人不是靠“经验值”升级，而是靠**制度承认的身份**流动。Reol 的杂役→外门→内门→真传→长老→掌门，每一步都应是 Claim/职位，而不是人物等级。

主要流动渠道：

| 渠道 | 靠什么 | 谁承认 | 典型代价 |
|---|---|---|---|
| 功劳 | 贡献、战功、任务 | 功德堂/掌门 | 时间、风险、被冒领 |
| 修为 | 境界、战力、天赋 | 宗门/江湖 | 资源、师承、闭关 |
| 血缘 | 家族、子嗣、联姻 | 家族/宗门 | 被安排、被利用 |
| 师承 | 拜师、传承、推荐 | 师父/长老 | 人情、站队、义务 |
| 财富 | 灵石、产业、礼物 | 商人/长老 | 被敲诈、被觊觎 |
| 名声 | 传闻、威望、事迹 | 江湖/百姓 | 被夸大、被挑战 |
| 暴力 | 决斗、政变、暗杀 | 强者/恐惧 | 合法性受损、仇怨 |
| 婚姻 | 联姻、道侣 | 两家/宗门 | 自由、继承纠纷 |

身份不是“永久 buff”，而是**一组 Claim 的集合**：

- 你有“外门弟子”的身份 Claim，才有资格进演武场、领月例。
- 身份 Claim 可能被暂停、降级、剥夺。
- 不同机构对同一身份的承认不同：宗门认，江湖未必认；正道认，邪道未必认。

### 5.10 衰减与维护

没有维护，社会关系会熵增：

- 关系随时间和距离衰减；
- 记忆随年岁模糊；
- 账页会虫蛀、受潮、丢失；
- 合法性会因失败、腐败、灾难下降；
- 规矩会因无人执行而松弛。

维护手段：

- 拜访、送礼、书信；
- 宴席、祭典、公开表彰；
- 审计、惩罚、平反；
- 修桥铺路、赈灾、办学；
- 定期兑付、公布账目。

这给玩家制造“不能一劳永逸”的压力，也给日常玩法提供理由。

### 5.11 派系与集体行动

派系 = 一群有共同利益的人 + 一个领袖 + 一个议程。

- 派系有：议程、支持者、资源、合法性、对外关系。
- 派系在机构内部争夺职位/政策/资源。
- 继任往往是派系战争的结果。
- 玩家可以加入、背叛、创建、调停派系。
- 派系让“宗门态度”有了政治过程，而不是一个开关。

### 5.12 修仙世界的特殊性

Reol 不是现代社会学模拟，必须处理修仙世界的几个特殊变量：

- **寿命长**：金丹/元婴可以活几百年。关系、账本、制度要能跨百年；一次闭关就是一次社会时间跳跃。
- **力量差距大**：高境界个人可以压倒制度，但长期统治仍需合法性；别人怕你，不等于服你。
- **闭关**：玩家闭关 100 年，出关后旧友坐化、旧账冻结、旧制度改制。社会不会等你。
- **法器/玉简/阵法**：可以做法定记录载体，权威高、寿命长；也可能被篡改、损坏、认旧主。
- **境界**：提供敬重/畏惧，但不自动提供信任/合法性；高境界散修可能被忌惮、被利用、被排斥。
- **宗门/家族/散修**：不同社会结构，账本、继承、互助规则不同。

### 5.13 长寿命与闭关：社会时间跳跃

普通游戏里“离开几个月”关系还在；修仙游戏里“闭关 100 年”是常态。

闭关结算要做：

1. **关系衰减**：旧友、旧敌、旧情人；大部分关系淡了，少数刻骨铭心的还在。
2. **人事更替**：同辈坐化，晚辈掌权；旧盟友变成祖辈传说。
3. **账本重估**：旧贡献可能被冻结、折算、遗忘；旧法器可能认新主。
4. **制度变迁**：宗门可能兴盛、衰败、分裂、改制。
5. **叙事变形**：你的事迹可能变成传说、被夸大、被冒认、被抹去。
6. **重新接入**：出关后要重新建立关系、证明身份、认领/放弃旧账。

玩家可以在闭关前布置“社会保险”：

- 立遗嘱/信物/令牌；
- 托付给弟子/盟友；
- 把贡献兑成实物/功法；
- 在多个机构留账；
- 留下私记/传承；
- 安排代理人。

### 5.14 秩序为什么能维持，什么时候会崩

社会秩序靠六根柱子：

| 柱子 | 作用 | 崩的时候 |
|---|---|---|
| 强制 | 惩罚违规、保护履约 | 武力失控、执法腐败 |
| 合法性 | 大家相信规矩正当 | 得位不正、丑闻、灾难 |
| 互惠 | 长期合作有好处 | 分配不公、赖账、通胀 |
| 信息 | 账本、传闻、命令能流通 | 账本丢失、谣言失控、封锁 |
| 物质剩余 | 有资源可分 | 财政危机、战争、天灾 |
| 共同叙事 | 大家讲同一个故事 | 分裂、异端、历史改写 |

崩溃往往不是单点，而是连锁：

```
财政危机 → 兑付不了 → 信用崩 → 合法性掉 → 派系分裂 → 内战/改制
```

这套系统要让玩家看到“柱子”在晃，而不是突然 Game Over。

## 6. 数值与可读性

### 6.1 内部可以数值化，外部不要

内部用 0–100 或 -100–100 的数值、权重、阈值，方便模拟。

外部只显示**词、行为、文件、价格、通行**。

| 内部 | 外部 |
|---|---|
| trust 0–100 | 戒备 / 试探 / 信任 / 托付 / 生死相托 |
| respect 0–100 | 轻视 / 平视 / 敬重 / 钦佩 / 敬畏 |
| claim.status | 已入账 / 待认 / 冻结 / 有争议 / 已拒付 / 已兑付 |
| issuer.credit | 铁账 / 稳当 / 勉强 / 不稳 / 空头 |
| legitimacy | 名正言顺 / 有争议 / 勉强维持 / 风雨飘摇 |
| evidence | 铁证 / 可信 / 人证 / 传闻 / 存疑 / 伪造 |

### 6.2 不显示“真值”

玩家永远看不到：

- 别人的真实信任值；
- 机构的真实信用分；
- 新掌门的真实政策倾向；
- 传闻的真假。

玩家只能通过：

- 对话语气；
- 办事结果；
- 账页状态；
- 价格/排队；
- 第三方打听；
- 试探/冒险；

来推断。

### 6.3 比较，不给绝对值

少用“信任 72”，多用：

- “他比上次冷淡。”
- “他更信你师弟。”
- “长老这次没留你吃饭。”
- “账房说，你的名字排在第三页。”

### 6.4 每个状态都要有下一步

- 冻结 → “去找见证人重新登记。”
- 有争议 → “找长老对质 / 查旧账。”
- 拒付 → “申诉 / 私了 / 换宗门。”
- 信用不稳 → “尽快兑付 / 换成实物 / 分散风险。”

## 7. UI 原则

### 7.1 三层认知面板

玩家看到的不是“我的声望”，而是三列：

```
我所知（私记）        官方所记（账本）        别人所说（传闻）
----------------      ----------------        ----------------
我救过阿禾            功德堂：挑水 30          “他好像得罪了新掌门”
我替石头担保          掌门批红：无              “听说旧账不认了”
陈守拙欠我一次        旧账：冻结，待登记        “他还是挺有本事的”
```

玩家自己判断哪一列可信。

### 7.2 账本要像账本

- 有日期、经手人、印章、批注、涂改痕迹。
- 有“正册/副册/私账”之分。
- 有状态章：已兑、冻结、争议、注销。
- 可以翻页、对照、抄录、拓印。

### 7.3 对话要像人

NPC 不会说“我对你好感 -20”，而会说：

- “不是我不帮你，是上面有新规矩。”
- “你的事，我记着呢。只是现在不方便。”
- “掌门说了，旧账要重新登记。”
- “你当年救过我，我不会忘。但这件事，我真的做不了主。”

### 7.4 反馈要跨渠道

同一个社会变化，至少在两个渠道可见：

- 对话 + 通行；
- 账页 + 价格；
- 座次 + 任务；
- 传闻 + 陌生人态度。

### 7.5 不做进度条

信任、敬重、畏惧、合法性都不做进度条。用行为、称呼、座次、价格、文件状态表达。

## 8. 扩展性架构

数据结构和算法会经常改，所以**不要把当前模型写死**。

### 8.1 事件溯源（Event Sourcing）

核心是**只追加的社会事件日志**：

```
SocialEvent {
  id, type, tick, actor, targets, location,
  witnesses, source, schema_version, payload
}
```

所有状态变化都由事件产生。当前状态是**投影（Projection）**，可以重建。

好处：

- 改算法：换一个投影，重放历史即可。
- 改数据类型：加事件版本 + 迁移，不破坏旧档。
- 可回放、可调试、可测试。
- 可以“如果当时……”做模拟。

事件类型示例：

- `claim_issued` / `claim_recorded` / `claim_recognized` / `claim_frozen` / `claim_redeemed` / `claim_repudiated`
- `relationship_changed` / `gift_given` / `favor_called` / `insult_public`
- `office_filled` / `office_vacated` / `succession_started` / `succession_resolved`
- `policy_changed` / `faction_formed` / `faction_split`
- `rumor_started` / `rumor_spread` / `rumor_debunked`
- `witness_recorded` / `secret_learned` / `secret_exposed`
- `audit_started` / `audit_resolved`

### 8.2 投影（Projection）

| 投影 | 内容 |
|---|---|
| `ClaimBook` | 按主体/发行方/状态索引的 Claim |
| `RelationshipBook` | 关系边与维度 |
| `InstitutionState` | 职位、成员、派系、政策、合法性 |
| `NarrativeState` | 传闻、公共叙事、面子 |
| `KnowledgeState` | 每个 NPC 的信念 |
| `EconomyState` | 资源、价格、汇率 |

投影是缓存，不是真值。可以随时重建。

### 8.3 数据定义

把“会经常改”的东西放进数据：

- `ClaimTypeDef`：类型、有效期、可否转让/继承、发行权限、证据要求。
- `ExchangeRuleDef`：什么换什么、汇率、条件、限额、手续费。
- `SuccessionPolicyDef`：旧账怎么处理、折算率、重登记条件。
- `ValueProfileDef`：不同人群看重什么（忠诚/功劳/血缘/面子/财富/荣誉/法律/实用）。
- `InstitutionDef`：机构、职位、规矩、禁忌、资源。
- `OfficeDef`：权限、职责、待遇、账本、继任规则。

### 8.4 稳定接口

- `SocialAPI`：命令（签发、记账、承认、兑付、转让、争议、见证）+ 查询（账目、关系、机构态度、面子）。
- 玩法系统只调 API，不直接读投影字段。
- UI 只调“可读摘要”查询，不碰内部数值。

### 8.5 版本与迁移

- 每个存档带 `schema_version`。
- 每个事件带 `schema_version`。
- 迁移函数按版本链执行。
- 定义数据带 `version`，可 `extends`/覆盖。
- 旧档不能读时，给出明确错误，不静默损坏。

### 8.6 时间与 LOD

- 具名人物/机构：完整模拟。
- 背景人物/远区：聚合模拟（cohort）。
- 事件驱动，不每帧轮询。
- 每 tick 有预算：最多处理多少 Claim、多少关系、多少传闻。
- 关系衰减、账本归档按日/月批量处理。

### 8.7 性能

- Claim 按 subject/issuer/status/scope 建索引。
- 关系只保留“有意义”的边；背景 NPC 用聚合态度。
- 传闻传播采样，不做全图广播。
- 旧 Claim 归档成“余额 + 来源摘要”，保留关键凭证。
- 目标：v0.1 1,000 Claim / 200 关系 / 10 机构，tick < 2ms。

### 8.8 存档

- 快照（投影）+ 事件日志尾部。
- 定期压缩：已结算的旧账合并成余额，保留关键凭证。
- 玩家私记单独保存；可以缺失、错误、被偷。
- 原子写入 + 备份 + 校验。

### 8.9 测试

- **单元**：Claim 状态机、兑付不重复、转让守恒、继任策略。
- **属性**：没有无发行方的 Claim；没有无机构的职位；状态转换合法。
- **黄金场景**：老掌门坐化、旧账冻结、重新登记、争议、伪造。
- **回放**：同 seed + 同事件 → 同状态。
- **数据校验**：所有引用存在；无孤儿；无循环（除非设计允许）。
- **性能**：预算内完成。

### 8.10 首版算法（可替换）

以下是“第一版够用”的算法，不是最终公式。所有系数放数据，算法走策略接口，后续可替换。

#### 关系更新

```
Δ信任   = 守约 + 共患难 + 长期合作 - 背叛 - 失约 - 伤害
Δ亲近   = 相处 + 礼物 + 共同经历 - 冷落 - 羞辱
Δ敬重   = 战功 + 修为 + 学识 + 地位 - 无能 - 丑闻
Δ畏惧   = 暴力 + 权势 + 威慑 - 保护 - 亲近
Δ亏欠   = 恩惠 + 担保 + 救命 - 还债 - 背叛
```

每次事件只改相关的 1–2 个维度，不要全改。所有维度 clamp 到区间，按日衰减向基线：

```
value += (baseline - value) * decay_rate * elapsed_days
```

畏惧、血仇、救命之恩衰减更慢；日常好感衰减更快。

#### Claim 承认分数

```
承认 = 发行权限 × 记账可信 × 证据强度 × 政策契合 × 利益契合 × 执行能力
```

不显示分数，只映射到：

- **已入账**：高
- **待认/存疑**：中
- **冻结/争议**：低或有条件
- **拒付**：负

#### 机构信用

```
信用 = 资源背书 × 合法性 × 政策稳定 × 记录完整 × 执行能力
```

映射到“铁账/稳当/勉强/不稳/空头”。

#### 机构态度合成

```
态度 = 官方政策权重 × 政策
     + 派系权重 × 主导派系倾向
     + 成员权重 × Σ(成员态度 × 职位权重)
     + 叙事权重 × 公共叙事
     + 利益权重 × 物质利益
```

权重由机构类型/文化决定；同一机构在不同议题上可以有不同权重（例如：收徒看资质，分资源看派系）。

#### 继任结算

继任不再查固定的“全认/冻结/折价”策略表，而是走 **5.7 的两阶段算法**：

```text
阶段 A：候选人打分 → 新掌门、合法性、不安全感、未解决竞争者
阶段 B：对每条旧 Claim 调 SuccessionResolver.resolve_claim：
  输入 factors = 凭证效力、财政负担、稳定收益、政治亲疏、个人恩怨、
                 反制能力、公开度、先例压力、新掌门需求、旧朝关联、
                 不安全感、合法性
  硬门槛先禁用荒唐动作
  五个动作各算加权效用：全认 / 折价 / 冻结 / 谈判 / 拒付
  取得分最高者，输出 action + 3 个理由标签 + 折价率

个人人情：相对方死亡后默认失效；
  有遗嘱/信物/见证人 → 转成对继承人或遗产的 Claim，再走同一算法。
```

`SuccessionPolicyDef` 只保存**权重、硬门槛、性格偏差、理由映射**，不保存“恢复 80%”这类固定结果。换一套权重或性格，同样的局面可以产生不同的继任政策。原型提供 `apply_policy()`，可以只覆盖指定权重，不必替换整张表。

#### 传闻传播

```
每跳：confidence *= source_trust * salience * (1 - distance_penalty)
      distortion += framing_bias + repetition_error
```

传闻不改官方账，但会改：

- 面子/名声；
- NPC 初见态度；
- 机构合法性；
- 任务/价格/通行（间接）。

#### 衰减与维护

| 对象 | 衰减 | 维护 |
|---|---|---|
| 关系 | 每日向基线回落 | 拜访、送礼、书信、共同经历 |
| 账本 | 每年少量丢失/损坏 | 审计、抄录、法器备份 |
| 合法性 | 每月按绩效/丑闻变化 | 仪式、公共品、惩罚、宣传 |
| 规矩 | 每次被违反且无惩罚则减弱 | 执法、审判、先例 |

## 9. 最小可玩版本（v1）

不要一次做完整社会。先做一个能验证核心体验的切片。

### 9.1 范围

- 1 个宗门、1 个山门聚落。
- 新增 2 个具名 NPC：老掌门（玩家旧交）、新掌门（老掌门的死对头师弟）。
- 3 个机构/职位：
  - **功德堂**：贡献账本；记账人陈守拙。
  - **任务板**：差事发布；功德堂背书。
  - **掌门**：职位；老掌门 → 新掌门。
- 3 种 Claim：
  - **贡献**：可兑付月例/功法/通行。
  - **人情**：个人恩情，不可转让，随人失效。
  - **见证**：证词，用于争议/重新登记。
- 1 次继任事件：老掌门坐化，`SuccessionResolver` 结算继任与旧账；基线局面（新掌门合法性低、库房空、玩家无势力）输出“冻结”，其他局面可输出全认/折价/谈判/拒付。
- 玩家私记：自动记录经历，可展示，但不具官方效力。
- UI：三列认知面板 + 账本页 + 对话语气 + 通行/价格变化。

### 9.2 验收场景

**Given**：玩家在功德堂有 30 贡献，和陈守拙有 1 次人情，和老掌门有 1 次人情；玩家是杂役，没有自己的派系。
**When**：老掌门坐化，新掌门（得位不正、库房空、与老掌门不睦）继位；`SuccessionResolver` 先算合法性，再逐笔算旧账。
**Then**：

- 新掌门合法性低（<0.5）、不安全感高；旧贡献的凭证效力中等、财政负担高、公开度中等、持有人弱 → 算法输出**冻结**。
- 功德堂账面显示“旧账 30（冻结，待重新登记）”。
- 老掌门的人情失效；陈守拙的人情仍有效。
- 新掌门对玩家仍然客气（面子），但功法阁/秘境通行被拒（实利）。
- 玩家可以：
  - 找阿禾作证：`validity` 提高，重新结算；可能全认、折价或继续冻结，取决于新证据与新掌门处境，**不是固定恢复 80%**；
  - 请陈守拙担保：提高 `need`/`affinity`，可能把结果推向折价或全认，但陈守拙承担风险；
  - 拿私记找新掌门对质：私记单独只提高少量 `validity`；有见证人/印章/法器时提升更大；
  - 把旧账折价卖给黑市：黑市按宗门信用和凭证强度报价，通常低于账面，报价不是固定 40%；
  - 转投其他宗门：旧账作废，但带走人情/技能。
- **对照情境**：同样一笔账，如果继任者是名正言顺的师兄、库房充足、玩家曾公开拥立他，阶段 A 合法性高，阶段 B 会输出**全认**；如果玩家手握法器封存的旧账且自身实力强，则会输出**谈判**。同一个算法，不同局面，不同结果。
- 不同选择改变：Claim 状态、关系、派系、后续任务。

### 9.3 对现有 M2 代码的改造

- 删除 `PawnState.contribution`；`PawnState` 只保留身体/精神/需求。
- 新增 `SocialAPI`、`ClaimBook`、`Ledger`、`Office`、`Institution`。
- 新增 `SuccessionResolver`（纯函数，已实现于 `scripts/social/succession_resolver.gd`）：输入归一化因素，输出继任者、合法性、逐笔旧账动作与理由标签。
- `JobBoard` 完成差事时，不直接加贡献，而是调用 `SocialAPI.issue_claim(...)`，由功德堂记账。
- HUD 选中面板改为查询 `SocialAPI.get_claim_summary(pawn)`，显示“账面/私记/传闻”。
- `ContentDB` 增加 `claims.json` / `institutions.json` / `offices.json`。
- 老掌门、新掌门作为具名 NPC 加入 `pawns.json`。
- 存档先存 Claim/关系/职位快照；事件日志与投影重建后续接入。

## 10. 案例：老掌门坐化

### 10.1 背景

- 玩家是杂役，和老掌门有旧交（当年救过他一命）。
- 功德堂账上 120 贡献；陈守拙欠玩家一次人情；阿禾是朋友。
- 老掌门在位时，玩家可以自由进出秘境，功法阁打八折。

### 10.2 事件

老掌门坐化。新掌门是原掌门的死对头师弟。

新掌门面临的问题：

- 合法性不足（得位不正/资历不够）。
- 旧臣多，库房空。
- 需要立威，又不能逼反旧人。

他的策略不是拍脑袋定的，而是算法在“合法性低 + 库房空 + 旧朝包袱重 + 玩家暂时无势力”这组输入下的输出：

- **面子**：公开表彰老掌门旧友，保留礼数。
- **实利**：冻结旧贡献，要求重新登记；秘境通行收紧；功法阁恢复原价。
- **人情**：不承认老掌门的私人承诺；但不敢公开羞辱玩家。
- **叙事**：说“旧账混乱，需要清理”，不说“赖账”。

如果换成一个名正言顺、库房充足、玩家又曾拥立他的新掌门，同一笔账会输出“全认”；如果玩家手握法器封存的旧账且自身实力强，则会输出“谈判”。

### 10.3 玩家看到

- 执事仍然行礼，但不再叫“先生”，改叫“道友”。
- 功德堂账页盖了“冻结”章，批注“待新掌门核验”。
- 功法阁掌柜说“上面有新规矩”。
- 阿禾偷偷说“新掌门怕旧人串联”。
- 告示栏说“整饬账目，清查冒领”。

### 10.4 玩家可选

| 选择 | 操作 | 结果 |
|---|---|---|
| 尽快兑付 | 在继任前把贡献换成功法 | 最稳，但可能错过更大的位置 |
| 重新登记 | 找见证人、填表、等核验 | 按新证据重新跑阶段 B；可能全认、折价或继续冻结，不是固定 80% |
| 找陈守拙担保 | 消耗人情 | 提高 `need`/`affinity`，可能推向折价/全认，但陈守拙被新掌门记恨 |
| 拿私记对质 | 展示笔记本 | 单独只提高少量 `validity`；有见证人/印章/法器时提升更大 |
| 与新掌门谈判 | 以效忠/服役/公开背书换承认 | 旧账部分恢复，同时产生一条义务 Claim；违约会再起争议 |
| 折价出售 | 找黑市/商人 | 按宗门信用和凭证强度报价，通常低于账面，不是固定 40% |
| 公开闹大 | 在宗门大会上诉 | 提高 `visibility`，可能逼出新谈判，也可能被逐 |
| 转投他宗 | 带走技能/人情 | 旧贡献作废，重新开始 |

### 10.5 结果

- Claim 状态变化：冻结 → 有效/拒付/折价。
- 关系变化：新掌门（信任/畏惧）、陈守拙（亏欠/风险）、阿禾（亲近）。
- 派系变化：玩家可能被某派系拉拢或敌视。
- 叙事变化：传闻“他闹了”“他忍了”“他走了”。
- 后续任务：审计、查账、黑市、宗门斗争。

## 11. 不做什么（v1）

- 不做每个 NPC 的完整双记账。
- 不做全球动态经济。
- 不做完整法律条文/判例系统。
- 不做每个 NPC 的完整心智理论。
- 不做 LLM 驱动的核心社会模拟。
- 不做玩家自由绘制账本/合同。
- 不做多宗门货币汇率（先做 1 个宗门）。
- 不做完整家族继承法。
- 不做 100+ 具名 NPC 的完整关系网。
