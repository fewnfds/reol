# 社会关系、机构记录与继任

> 详细设计与候选：已确认体验原则见[社会与认识](../rules/society-and-knowledge.md)；具体记录、权重、机构政治和继任规则仍待评审。

早期草案保留在[历史档案](https://github.com/fewnfds/reol/blob/8c3deaa972f932e999167b61ea6b166b928cfe5f/docs/archive/documentation_consolidation_20261104/design/systems/social_system.md)；其中数值、排序和发行或继承条件都是提案。决策因素与来源见[社会互动评审](https://github.com/fewnfds/reol/blob/8c3deaa972f932e999167b61ea6b166b928cfe5f/design/systems/social_interaction_review.md)，共同原则见[世界总纲](https://github.com/fewnfds/reol/blob/8c3deaa972f932e999167b61ea6b166b928cfe5f/design/systems/self_consistent_world.md)。

## 已确定的体验与边界

- 同一个世界中，人物、组织、阵营和地方群体各有目的、经历与认识。组织通过具体成员、职位、资产与程序行动，成员不必有一致立场。
- 贡献由有权机构及其记录持有；人情来自具体人物的经历和承诺；名声来自有限传播；礼数随人、场合与文化发生。它们相互影响，但不自动合成一个全局声望、货币或统一好感。
- 认识、尊敬、信任、实际授权、资源支配和愿意冒险分别判断。点头之交通常不自动提供实利，陌生人也可能因善意或职责提供帮助；具体行动有时间、风险和成本。
- 人与职位分开：以职位办理的组织事务与个人承诺各有来源。人员离职、死亡或更替可改变后续办理，不能凭此抹除真实发生的交付、其他人已有记忆或仍被承认的组织债务。
- 见证、个人记忆、实物和记录可以冲突、丢失、伪造或过时。玩家个人记下的内容不自动成为机构账目、游戏权威事实或人物已掌握的技能；它可以成为调查、表达或依法核验的依据。
- 玩家和NPC使用同样的实际条件；提出意图、理解和回应、执行与后果分开。社会骰只处理客观可行条件下的不确定反应，原处境没改变时不靠反复点击重抽。
- UI只表达主体能看到、听说、查到的信息；玩家可以看自己的确切余额、金额与期限，不需要把所有数值藏起来。开发诊断与人物认识分开。

## 共同生活如何推动社会

```text
需求/目的 → 按所知选择行动 → 实际执行与结果
    → 当事人观察或收消息 → 各自解释/记录/回应
    → 后续行动、关系、组织安排与未结责任
```

社会不要求所有事都有人目击或进入账本：无人看见的桥被破坏仍然破坏，只有知情者才会据此改变认识。人物可能出于职责、善意、互惠、利益、恐惧或误会作出不同选择。记录获得社会效力需要当地有权者、可访问的载体、程序和实际执行能力；记载真实与否、是否被承认、能否兑现也是不同问题。

## 对象与归属

| 对象 | 应承担的事实 | 不可混同 |
|---|---|---|
| 人物关系与经历 | 两个当事人各自的记忆、身份、信任、情感、期望、承诺 | 不是可任意转卖的统一凭证，也不对称地自动复制 |
| 机构及职位 | 成员、职责、决定权、资源、政策、现任者及空缺 | 组织整体不等于每名成员的私人意愿 |
| 公共记录与凭据 | 签发与登记者、对象、依据、范围、状态与可核验内容 | 真实记录不保证所有人知道，也不保证一定能兑付 |
| 私人记录、见闻与说法 | 某人所写、所见或所听到的内容及其来源 | 私记不自动变成公账，传闻不等于发生事实 |
| 实物和实际控制 | 真正的库存、保管位置、出入条件与使用能力 | 账面有权不等于已经持有；钥匙或持有不自动意味着合法 |

记录可以由账房、长老、实物账册或具备相应规则的法器管理。储存设施和物件本身不会凭空产生官方权力：工作需要实际人员或有授权的设施、可访问记录和相应资源。设施、房间和操作条件见[建造与空间](construction_and_space.md)。

## 当旧友去世或失去职位

例：玩家与旧掌门交好，过去因为其个人引荐、组织政策和个别门人的情谊，得到礼遇和便利。闭关归来时新掌门接任，值事者可能仍客气，但新规不再允许通行，某些旧账须核验，旧友弟子仍愿意私下帮忙。

这些变化应从实际职位、权限、保管人、资源、政策、个人交往和消息传播产生；不能让人物离场后整个门派冻结，也不能用统一声望衰减直接计算所有结果。怎样获得新授权、核账、求助、协调或另谋出路，取决于当事人已知信息与实际权力。

## 本地宗门原型

以下是服务于[自主生命方案](beings_and_lifeways/agency.md)的首轮候选，**尚未实现**。先让本地约百人的宗门由成员自行运转，组织政治、完整继任/司法和复杂命令系统后置；不因本节需要职位与在办事项，就默认采用下文的Claim或SuccessionResolver原型。阶段依赖只归[主计划](../../docs/plans/foundation-priorities.md#下一阶段候选)。

### 最少需要的共同记录

| 记录责任 | 必要内容与用途 | 与原事实的边界 |
|---|---|---|
| 组织与成员 | 组织身份、成员关系、可访问的规则和有关记录 | 不代表所有成员同意或知道全部组织事项 |
| 职位与任职 | 职位身份、当前任职者、已有授权、职责/责任范围和报告/代理关系 | 一人可兼任、职位可空缺；任免改变后续资格，不抹除已经发生的责任 |
| 持续职责 | 要维持/达成的条件、适用对象/区域、检查机会和职责内可自行处理的范围 | 提供目标来源与处理方法，不另造职业AI或每秒下达动作的管理器 |
| 住所与服务使用安排 | 分配给谁/哪些成员、对象、范围、有效条件 | 社会使用资格与实际空间、床位、作业位置/预约分别维护；不能复制房间占地 |
| 在办事项 | 发起者、实际接收者、目标/范围、来源职责、版本、受理状态、期限/结束条件与有关回报 | 个人目标引用事项，P5任务关联执行；收到、接受、开始和完成分别成立 |
| 有依据的报告/记录 | 谁提交、何时获知、说了什么、相关证据、谁可查阅/已送达 | 账面内容不等于库存真值，私人说法不自动成为正式认定 |

这些是职责分类，不要求立即建六个框架或统一的社会事实数据库。共享的任职、使用安排和事项由社会/交互记录持有；个人认识与评价只保存本人已知部分。实际物品、容器、能力、占地、费用和成长继续归原owner，不能顺便集中进Society。数据具体布局在实现时按读写与恢复需要确定。

### 职责怎样变成成员行动

开局成员可接受与其职位相容的持续职责，不用由玩家一条条指挥。任职者按本人熟悉的范围、已获记录和实际报告检查条件，形成个人目标或具体事项，选择自己处理、请求协助或上报；其他成员在实际获知并受理后安排方法。履职回报必须关联真实交付/执行结果，提出者再按其取得的依据复核。成员的个人目的、处境和关系影响手段与取舍，职务本身仍有可预测的正常履行倾向。

职责内的例行工作应有事先授权，做一餐饭不必先找掌门审批。公共事项清单是可选通道，不能变成把全图所有潜在工作与空闲人实时配对的全知工单池。同一职责下的缺口检查和已建立事项需要去重/修订，避免每次巡检都重复发单或多人对同一交付重复记功。

有限名额/份额的共同事项，由该记录的唯一owner按版本、剩余额度与受理条件提交承接；同时看到同一张单不等于都已接到。可以允许多人分担，但份额、转托、超时和撤回要明确，已完成部分不重复计入。事项承接不替代现场工位预约，也不凭远程意向锁住所有自然资源或他人的物品；普通个人目标仍可竞争同一机会。本人暂时停下不一定解除责任，释放/失效按事项自身条件处理。

职位的实际意义来自持续责任、处理范围、信息渠道、可作出的组织决定与协作，不要求任职者垄断某个独门技能。有能力的其他成员能自助或代理是有效结果；负责人不在时应观察具体协调/服务怎样改变，而非为证明职位有用强制造锁或让宗门停摆。

### 首轮消息与记录的简化边界

首轮优先用局部交谈和指定位置可查阅的公共记录，避免全图追逐移动接收者；有需要的简化组织投递明确内容、接收范围和投递条件，不要求先做跑腿传令、邮递路径与全部通信设施。直接交谈仍有互动距离，查记录需满足该记录的访问条件；抽象投递只传已提交内容并明确何时送达，不自动附上实时库存和人员位置。只有实际取得内容才更新个人认识，不能把“在同宗门”解释为全员即时共享一切状态；未来不同通信能力沿相同接缝扩展，不将“所有消息永远只能走实体簿”定成世界规则。

正常交接可留下实际办理的记录，例如已受理的事项、经共同物资接口完成的交付和签收。记录的来源与时刻要明确；它并不自动记录未目击的物资损失、越过正常办理的拿取、角色私藏或真实内心。盘点或现场发现才能校正账实差异。本人知道某人任职，也不能由此实时知道其位置、体力或是否愿意接事。

### 缺席、冲突与补位

负责人未回应、事项逾期或成员检查发现其无法履职，可以产生核查/上报目标。已有代理在其授权内办理；超出授权的替任需有权者实际作出决定并送达。全知调度器不得因看到一个状态位变化就立即安排替身、开放全部公库或给所有成员写入新知识。

权限要区分社会许可与物理条件：拒绝授课或公库服务可由有权办理者按规则执行；门锁、阻挡、实际持有与强取是不同机制。没有相应锁具/执法能力时，不能仅凭无权标记让物品物理上不可触及。普通驱动先验证可靠履职、有原因的拒绝和请求改换方法，不预建食物惩罚、贡献货币、升迁竞争、偷窃与告密全套制度。

短缺和缺席可以产生延误、降级自助或恶化；首轮不承诺任何扰动都能自动恢复。关键是实际有资源、有条件、有知情者和可用方法时能推进；确实做不到时能保留事项、合理等待/求助并让原因可理解，不能用无限重试或后台补给掩盖缺口。

## 尚未确定的模型

- **Claim** 是可记录的权利、义务、凭据或身份的候选模型；不能默认统包情感、记忆、传闻与一切社会事实，也不能把一次公式计算当作全体社会过程。
- **关系维度、行为判定与机构流程**：关系可由经历、情境预期及少量摘要表示；各维度、权重、衰减和骰判尚需基于真实互动测试，不预设所有关系必然随时间降低。
- **争议路径**：协商、调解、核验、裁断、行动与报复等都是候选，是否发生及先后由机构、权力、当事人和情境决定，非全世界强制固定队列。
- **死亡与继承**：个人感情、私人债务、公账、职位、实物与证据逐项按事实、关系、制度、遗愿和承认处理；不强制人情一律消失或承诺一律传给后人。
- **内容与资源**：贡献是否可转让、能否继承、能换什么，法器是否承认特定签发者，均为具体机构与法器规则，不先规定整个世界共用的汇率。

## 5.7 继任原型的地位

早期[历史草案的5.7](https://github.com/fewnfds/reol/blob/8c3deaa972f932e999167b61ea6b166b928cfe5f/docs/archive/documentation_consolidation_20261104/design/systems/social_system.md)及`SuccessionResolver`提出两阶段方案：先对候选人和权势形成结果，再考虑逐笔旧账是否承认、折价、冻结、谈判或拒绝。名分、派系、实力、控制、资源、证据、受益者、前任联系等都可能是候选因素；**权重、阈值、硬门槛及五种结果只是隔离原型，不代表用户已拍板，也没有接入完整组织与人物行为。**

未来若重新采用，应先基于候选人本人所知、组织程序、实际资产与有关人的选择，区分提议、承认和执行，再用可解释的多个场景验证；不能默认空位时全部旧账冻结，也不能以一次总分决定所有部门和成员的反应。原型如何被迁移、替代或保留由实际设计验证决定。

## 共同验收情境

以下是目标，不表示当前已通过：

1. 交付真实存在，但无见证和无授权登记，私记不能直接兑换公库；知情人可出面举证。
2. 原账簿存在但管事不在、权限被撤或库存不足，账面权利与实际兑现分别表达。
3. 敬重者拒绝高风险请求、陌生人因职责愿意帮忙；改变条件或引入证据才重新判断。
4. 换掌门后不同部门、旧友门人与新任者作出不同反应，已发生的账目、私情和传闻不被整体清零。
5. 自主NPC在玩家缺席时发起请求、执行承诺并传递有限消息；入场、保存、恢复不重抽已发生结果或复制资源。
6. 未知的暗账和内部动机不能通过价格、按钮理由或UI排序无意泄露给玩家。
