# 知物、用器与创法：有限认知下的修仙世界：器灵、创法与场景

> 详细设计与候选：具体机制、参数、样本和验收意图须验证；已确认规则见[规则目录](../../rules/README.md)。

## 5. 戒中老人既不是完整百科，也不是免费技能树

老人拥有独立主体ID、记忆来源、感知渠道、目标、关系和合作条件。戒指的结构/封印属于载体；储物、护持、传意、寄魂等功能可以分属不同规则。修好戒指外壳不自动修复老人记忆。

老人能说真话、误记、隐瞒、猜测或故意误导。对三百年前的机关很熟悉，不表示知道如今城主和商价。没有收到消息，就不能因游戏后台已更新而知道旧宗门被灭。

合作可以包括：提供线索、演示一段方法、在约定条件下代操、验证某种反应。它占用注意/能量/准备与个人意愿。所谓“老爷爷帮你开挂”在世界里应是具体代理行为，能够拒绝、失误、履约和留下关系。

使用者也可成为戒中老人；核心操作围绕自己能感知和传达的范围展开。两方知识界面分别授权，玩家不能切到戒指面板就免费读完另一主体的秘密。

## 6. 工法不是只能掉落，也可以被创造

### 6.1 功法、技法与实现分开

功法是一套长期调节与实践的方法；技法是可以执行的局部操作；记录只是它们的某个版本说明。一本书可能残缺、误抄、吹嘘、加密或只适配某种身体。拥有文本不等于理解，理解不等于练成，练成不等于当下能安全执行。

世界里的知识图不是预先公布的宇宙全部答案，而是某主体已知的方法与依赖。创造、翻译、改造和失传会改变图；40节点只是人类入门内容候选池。

### 6.2 玩家怎样创造，而不写游戏代码

以“想解决的问题”进入创法：让染料慢慢受热、让鸟妖携物时不脱爪、让传音只被某个载体接收等。选择自己理解的作用、媒介、步骤和约束，先搭可试验的草案；可以命名、写原理笔记和记录试验。

每份可执行方法至少包含：

| 内容 | 需要定义什么 |
|---|---|
| 意图与效果 | 实际改变的对象/状态，不用方法名代替效果 |
| 媒介与目标 | 通过什么作用于什么、范围/接触/传播条件 |
| 施行步骤与控制 | 顺序、时长、输入、可中止点、所需精度 |
| 适配与基础 | 身体/载体、已学基础、工具/场所、可接受替代 |
| 供给与限制 | 起动/持续代价、来源、容量、排出或副产物 |
| 故障与痕迹 | 条件变化时怎么失效、风险、观察者能察觉什么 |
| 验证与传承 | 方法ID/版本、创造者、已试范围、证据、谁获知哪个版本 |

首版先允许组合/调整已定义作用与过程，像做一次有条件的实验；不是把任意词拼在一起就自动实现。描述超出现有作用时，可以保留研究目标和原理草案，但须明确“尚无已验证的实现”，不消耗材料后编造全能成功。

后续内容开发可以扩充作用族，使以前不可做的设想成为可执行方法。设计边界应可扩展，不能把第一轮几个积木永久当宇宙定律；也不能宣称一套自然语言框架已支持无穷术法。

### 6.3 创造过程

    已知基础与目的 → 原理草案 → 小规模隔离试验 → 记录反应
          → 定位缺陷/调整步骤 → 在已验证条件下重复 → 形成可传授版本

- 高手的优势来自能观察、理解、控制更多过程，并掌握更好的试验条件；可以跨领域顿悟，但灵感不直接替代验证。
- 试验成功与掌握方法分开。偶然做成一次，可能还说不清原因；反复出现的证据才能支持更可靠的用法。
- 成功有适用域：只试过干燥木料，不能宣称对雨中湿木和活体都安全。
- 缺陷是条件关系，例如“潮湿时漏流”，而非随机生成一个永远看不懂的诅咒词条。
- 改名不改变规则，不刷新消耗和冷却；不允许把同一方法换十个名字就得到十份独立能力。
- 原版与改版分别保留。老师教旧版，弟子不自动获得新修订；翻译、误抄、保密和专门适配会形成不同传承。
- NPC也可在少量已知办法中改良、求证和学习；首版用有界候选与事件触发，不要求NPC凭空发明整个规则引擎。

### 6.4 一个例子：《缓火养息法》

学徒本想做火弹，却只得到很慢的热流。若热流真实稳定，可试验隔热壳、限流与材料反应，把它改成温养药材的方法。

第一版或许需要一直看守，潮湿时会漏流；第二版加入断流条件，耗材更多却可安全停机。匠人、药师、鸟妖和修士可以贡献不同信息；发明者不因独占命名权就自动拥有全世界的收益。

传播后，别人可模仿、购买指导、抄书或独立发现。社会是否承认秘传、收徒义务或商业限制，要靠具体组织和约定；没有全宇宙自动生效的专利系统。

## 7. 共同接口与状态归属

| 信息 | 持久负责人 | 其他系统怎么用 |
|---|---|---|
| 物的结构、位置、储能、损伤 | 物品/载体状态 | 行动执行查询，界面按观察权限呈现 |
| 主体掌握的性质/方法及来源 | 个人知识与实践记录 | 计划生成、鉴定、风险预期与可见图 |
| 器灵/寄魂者的意图和秘密 | 独立主体状态 | 合作/请求、传意与代理行动 |
| 方法定义与版本 | 内容定义＋保存的已验证新方法 | 多主体引用同一版本，学习程度各自记录 |
| 误导、试验、交接等进行中过程 | 行动/事务状态 | 保持预约、投入、阶段、取消与幂等提交 |
| 官方签发与撤销 | 机构记录 | 正式受理、兑现、争议；不覆盖个人所知 |

新方法由数据定义并通过规则校验，不在存档中运行用户字符串代码。知识变化与事实变化分别发送事件；调试广播不让所有主体获得秘密。

## 8. 组合场景验收

| 场景 | 必须验证的区别 | 允许的惊喜与后果 |
|---|---|---|
| 凡人工匠检验仙器 | 材料知识与灵性操控分开 | 能找出修补痕迹，仍不能使用核心 |
| 低阶者借一次护符 | 有预存功能、有激活条件 | 可保护自己一次；次数真实消耗、不因归还重置 |
| 鸟妖尝试人类法器 | 操物、接口与负载分别检查 | 可找转接/代操，不必升级成人；不自动适配一切 |
| 已知裂戒高功率输入 | 过量和裂损确实相关 | 预警、泄漏或碎裂符合机制；低功率可能可用 |
| 骗子冒名通过守卫 | 守卫所知与职责/风险 | 可能放行、核验或有条件接待；不凭成功直接获得官职 |
| 同一骗术碰见印契核验器 | 设备实际检查哪个信号 | 伪外观可能失败；复制对应信号需另一套方法 |
| 账房被诱导签发真凭据 | 真实签发与依据虚假分开 | 可能先被承兑，后续冻结追责保留当时交易 |
| 老人教出过时法门 | 记忆有时效，世界条件已变 | 小试发现异常；持有者可核实、改良或承担风险 |
| 工法试验失败却有稳定副效果 | 真实效果不依赖原用途标签 | 可改作工艺，需新的验证，不自动“获得传说功法” |
| 同法改名并重复装配 | 名称不等于独立实例 | 共享真实资源/过程约束，不能凭改名无限叠加 |
| 新方法跨聚落传播 | 教授/记录/消息需要实际渠道 | 到达者可学、未接触者不知；旧版与改版共存 |
| 驱器或行骗中离场存读 | 进行中过程与知识分别保存 | 不退还已耗材料、不重复签发、不重掷既定结果 |

## 9. 首次实现的最小范围

先用一件有显性用途和隐藏功能的器物、两种观察方法、一种限流试验、一段有条件的指导验证前述分离。随后加入一种伪装/核验与一个方法改良，不同时建设完整幻术、誓约、炼器、夺舍和法术编程。

对外应能说清：我知道哪些性质；这些认识从哪里来；我准备怎么试；缺什么；我看到了什么结果。先把这种探索做成可玩的过程，再扩充传说宝物与更多效果。
