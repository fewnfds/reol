# 八方向人形技术样本

本目录是 Reol 的**原创代码生成像素占位样本**，用于验证八方向、分层换装、解剖左右、附着点与共同动作相位。正式人物美术后置；当前无需外部图像模型继续批量制作衣饰。它不是正式人物美术，也不代表完整战斗或服装内容已经实现。

## 来源与权利记录

- 来源：本项目 `tools/build_humanoid_assets.py` 的参数化几何与离线正交投影；2026-11-03。当前呈现采用原生 96×96 网格硬边覆盖、每种材料三档明暗和二值 alpha，无抗锯齿、抖色或柔化。
- 没有下载、复制或使用第三方人物、动作、纹理、模型，也没有使用生成式图片服务。
- 生成工具：Python 标准库和本机已有 Pillow；不新增游戏运行时依赖。
- PNG、JSON 和生成器作为本项目原创文件管理。项目总许可证尚未决定，本记录不为整个项目另行指定 MIT、CC0 等许可证。
- 可重新运行生成器替换本样本，正式素材须继续遵守同一合同及单独来源记录。

## 文件与技术合同

数据入口为 `data/definitions/humanoid_appearance.json`。九张 `spr_<layer>.png` 都是透明 RGBA、3840×768，单格 96×96。绘制原点固定 `[48,65]`，代表身体的地面参考点；脚步围绕它前后交替，不用逐帧裁图重设原点。

人物实际高度约 44–45 px，不是单格占满 96 px。直接在 96 网格生成，没有先降到 48 再放大；硬边只改变图像呈现，不改变原人物尺度、几何、方向、锚点、图集格数或动作时序。原锚点可见性保留旧采样基准，不能为让像素造型好看而移动握点或改左右。每张图集至多 64 个 RGBA 颜色，透明度只允许 0/255。

当前保留原技术样本的示意投影，不是严格按 55° 相机烘焙的正式素材；本次硬像素替换没有修改其几何或锚点来修镜头。固定俯视方向和左右关系可用于原型，不能据此宣称正式镜头规范已验收。

行依次是 `N NE E SE S SW W NW`，屏幕上方是北。列为待机 `0–7`、行走 `8–23`、短展示动作 `24–39`。三动作分别使用 8、16、16 帧，周期为 1600、900、1200 毫秒。最后一个动作只是左手短展示，不能据此触发攻击、伤害或装备效果。

正面（南向）解剖左手出现在屏幕右侧；北向则在屏幕左侧。生成器直接旋转同一解剖模型独立渲染八个方向，从不翻转整张图片或交换左右名称。

| 顺序 | 层 | 用法 |
|---|---|---|
| 1 | `sword_far` | 左手剑的后片，技术预览开关 |
| 2 | `jade_far` | 右腰玉佩的后片，技术预览开关 |
| 3 | `cape_far` | 蓑衣后片，用实际外层衣色调色 |
| 4 | `body` | 肤色、头发、发簪、基础内衣、手脚，不调色 |
| 5 | `robe` | 常服与袖子，用实际身衣颜色调色 |
| 6 | `detail` | 中性领口和腰带，不调色；当前与基础长袍占位同显 |
| 7 | `cape_near` | 蓑衣前片，与后片同色 |
| 8 | `jade_near` | 右腰玉佩的前片，技术预览开关 |
| 9 | `sword_near` | 左手剑的前片，技术预览开关 |

常服和蓑衣是有限明暗的灰度原图，使用乘法调色，透明度只应用一次。身体为同一人形样本，常服可用两种或更多实际衣色；这不另造衣物所有权或装备数值。剑和玉佩只用来检验非对称轮廓与附着，不能向正常角色凭空授物。

本批只有 `idle / walk / gesture` 三种呈现。奔跑、受击、倒地、起身、施术等完整动画没有因此完成；既有闪身/对练等玩法沿原呈现或明确占位，不为补美术另造规则。正式动作、美术家族和服装变化留后续逐项验证。

行走沿共同世界时间使用固定 900 ms 周期，尚未按实际路程/步幅锁脚；8/16/16 帧的时序合同保留，但硬栅格会使部分相邻帧相同，不代表每帧都有独立可见变化。未穿实际身衣时仍显示基础长袍轮廓，是当前人形的明确占位约定，不是完整脱衣表现或新衣物实例。

每方向、动作和帧都具有 `left_hand / right_hand / left_waist / right_waist / head / back` 的像素坐标、二维朝向角、相机深度和相对身体可见性。`visible` 是制作辅助信息，不代表游戏世界中的观察者认识。`layer_order` 明确片段顺序，不以世界建筑的排序代替人物内部遮挡。

主体与常服按原身体深度遮挡，分层底图不因外层衣物被永久挖孔。前后片在离线投影阶段计算。此样本为特定身体与三动作制作；未来长披风、其他体型、兵器和招式仍须按各自遮挡内容验收，不能自动套用本样本宣称全部正确。

## 重建与检查

```powershell
python tools/build_humanoid_assets.py
python tools/build_humanoid_assets.py --check
```

生成器检查单元边缘无裁切、八方向内容独立、二值透明度、每图集颜色数、全帧脚点及磁盘字节一致性。`--check` 只在内存重新生成发行资源，不改现有 PNG/JSON；默认会刷新忽略目录 `logs/` 的检查产物。`--no-previews` 可跳过这些日志。

本轮像素替换后 `--check` 与 `--check --no-previews` 均通过，九张 PNG 与 manifest 共 10 文件逐字节可复现；每图集实际 4–17 色，manifest 与原帧/锚点合同未变。局部近邻过滤已接 Player、Pawn 和 V 页实际绘制子节点 `PreviewBody`；未修改全局 UI/字体或地图过滤。实际运行与完整回归的状态见[八向 QA](../../../docs/archive/qa/20261103_eight_direction_sample.md)和[BASELINE](../../../docs/status/baseline.md)。

视觉检查产物（不作为发行资源）：

- `logs/humanoid_sample_plain_contact.png`：八方向 × 三动作各四个相位，常服与剑佩。
- `logs/humanoid_sample_cape_contact.png`：相同相位，加蓑衣。
- `logs/humanoid_sample_idle.gif`、`walk.gif`、`gesture.gif`：八向同步动作，2 倍近邻放大。
- `logs/humanoid_sample_asset_report.json`：尺寸、alpha、文件哈希与未压缩纹理预算。
- `logs/humanoid_pixel_native.png`、`humanoid_pixel_nearest_3x.png`：当前像素占位的原生大小与 3 倍近邻对照，仅裁透明边距，不缩小人物。
- `logs/humanoid_pixel_game_world.png`、`humanoid_pixel_game_v.png`：run170 的 1280×720 实机世界与 V 页静帧；不替代全部动作、方向与规模性能验证。

九张原图未压缩 RGBA 合计 101.25 MiB，磁盘 PNG 明显更小；减少颜色不代表降低解码后的 RGBA 纹理预算。这只是纹理预算，不能代替 Godot 的实际驻留、帧时间及可见人物测试。运行时应共享纹理，不为每位 NPC 复制图片，不在每帧重新合成人物位图。保持无 mipmap、无有损压缩；硬像素应在人物呈现范围使用近邻过滤，不能为单套占位改全局 UI/字体过滤或人物实际连续位置。源图是硬像素，不代表相机任意小数缩放后仍会逐屏幕像素稳定，需按实际画面核定。

原 A1 的 48 视图测量尚未达到约 1 ms 人物脚本 CPU 目标，见 QA；本轮像素替换没有减少九层或重测该规模预算，不能以 PNG 更小或可重建代替性能通过。
