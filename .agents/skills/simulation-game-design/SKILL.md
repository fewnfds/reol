# 模拟规则怎样成为可玩的世界

按Reol重写、收窄自pbzona/godot-skills的game-systems-design与game-balance；来源及MIT声明见[NOTICES](../../../THIRD_PARTY_NOTICES.md)。本技能审查玩法模型，不替代已有领域owner、资源编译器或性能方法。

- 从玩家希望作出的判断与可观察结果开始，区分体验目标、解释假说和已实现事实。例子用于找张力，不自动变成功能清单；“像其他玩家”也不要求运行时LLM或完整人类心理模拟。
- 只画本次相关的状态和因果链：谁知道什么、谁能改变什么、输入/产出/损耗、占用的人力时间与设施、反馈何时回来。新数值要说明改变哪种选择或后果；只提供人物风味的描述可以保留为表现数据，无需进入每步计算。
- 检查循环中的稀缺、延迟和替代方法。正反馈可能滚雪球，负反馈可能抹掉努力，延迟可能导致囤积或反复补救；稳态供养本身可以是目标，不强制制造危机或规定所有院落必须不对称。看初始库存耗尽后、受阻后和成熟期，不能只算平均净产量。
- 把玩家放回循环：玩家作为一个角色，能否通过行动、求助、信息、资源或权限改变处境，并在之后看见影响？NPC自行运转不等于玩家必须微操每个人，也不等于玩家只能旁观。选择是否有价值，要看当时可知、可达、付得起的替代项。
- 低美术优先表达对象、动作、阶段、受阻原因和后果，再考虑额外图像。区分世界事实、角色所信与玩家所知；反馈从真实结果和允许公开的证据产生，不能为一句生动台词杜撰未发生的经历或泄露他人私心。
- 选能推翻本次模型的验证：规则守恒、个人动机的单因对照、跨周期资源/等待变化，或玩家能否预测并干预。自动模拟不能证明有趣，玩家口头认可也不能证明守恒或容量；只做能影响本次取舍的检查。

较大经济/社会改动按需读[模拟设计与实验方法](../../../docs/engineering/simulation-methods.md)，来源与未采方案查[研究取舍](../../../design/research/development-paradigms.md)。小改不额外产出系统图、实验矩阵或设计报告；长期结论更新原领域主题。
