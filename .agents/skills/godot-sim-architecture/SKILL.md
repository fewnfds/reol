# Reol 模拟架构

先按任务查 `docs/ARCHITECTURE.md`、`docs/BASELINE.md` 和相关设计；本文是工作原则，不是已实现系统清单。面向当前目标引擎查对应官方 API；不据旧示例创建新的全局单例。

## 共同时间与执行

- 规则由现有共同时间和明确的模拟边界推进，呈现插值不得推进世界状态。当前架构使用共同整数毫秒；实际精度、触发边界和持有者以代码及架构文档为准。
- 时间分片、近远区调度和有序事件应保持所要求的因果与结果。为限制单帧工作而延后处理时，保留待处理时间和事件；不要把积压清零，也不要用粗更新抹掉重要边界。暂停、加速、取消和读档需保持相同时间合同。
- 同时发生的动作按既有明确顺序结算；跨区写入前同步相关区域，条件改变后使失效预测重新计算。不要凭渲染帧或全局扫描构造第二个世界时钟。

## 所有权、数据与存读

- 身体、位置、实物、资源、任务及知识各有原状态所有者；跨域使用 ID/引用与公开接缝，不建立暗中分叉的副本。区分个人所知、客观事实、视图投影和设计愿景。
- 定义和参数数据驱动；系统组合与事件通信按现有实现选择。避免每帧扫描场景树、重复加载和无根据的新框架。
- 保存所有不可重建的变化与在途状态，维护版本、迁移和引用校验；不能假设仅靠 seed 或玩家改动即可还原持续世界。保留历史 fixture 与原始存档，失败迁移不能替换活世界。

## 设计与验证

先确定边界、状态所有者、时间/取消及存档影响；性能先测量，再优化真实热点。用相关领域的定向测试核对分片推进、冲突顺序、中断恢复和新旧档迁移；不要宣称所有物理轨迹或远区规模已被覆盖。最终验收依 `godot-verify` 和当前任务要求执行。

需要处理调度积压、跨域状态或迁移时，读[时间与持久化要点](references/time_and_persistence.md)。
