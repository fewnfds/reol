# Reol 生活、工作与场所

以 `docs/FEATURES.md`、`docs/ARCHITECTURE.md` 和相关系统代码核对已实现范围；房间、设施、家具与容器的长期规则见 `design/systems/construction_and_space.md`。未接入的设计不是现成功能。

## 规则边界

- 多种生命有不同身体、需求、认识和生活方式；不要把人形 Pawn、固定职业或单一宗门工作模式当作宇宙通则。人物有自己的意愿、能力、负担、记忆和活动。
- 请求被接收、被理解、有能力、愿意执行与实际完成是不同结果。工作可等待、失败、取消或被打断；不要用 UI 声明代替真实移动、消费和完成。
- 物品、房间、设施、工位和关系沿已有所有者与访问规则操作。预约/认领冲突需有确定的归属，并在完成、中断或对象消失时释放；不要复制或凭胜利自动转移真实物品。
- 使用共同时间及原身体/任务接缝；近远区、在途动作和存读恢复不能把生活重置。本人可知信息不得自动变成全体事实。

## 做小而可验证的改动

按玩法需求选取一个闭环，明确输入、执行者、资源、结果、取消和可读反馈；不先假定所有工作、房间或完整经营系统已存在。对冲突预约、对象消失、资源不足、个人意愿、暂停/中断及保存恢复等相关边界写有意义的验证；测量规模与性能后再调整预算。

新世界交互先读 `design/systems/world_interaction_principles.md`；跨域时间和状态归属用 `godot-sim-architecture`，验收用 `godot-verify`。

涉及预约、事务中断、场所或库存时，读[工作与设施要点](references/work_and_facilities.md)。
