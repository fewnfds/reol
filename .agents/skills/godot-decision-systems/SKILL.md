# 决策、持续执行与个人所知

本地合并重写原game-ai及ai-behavior-trees-utility-ai；归属见[NOTICES](../../../THIRD_PARTY_NOTICES.md)。当前由`agency_selection.gd`、`agency_planner.gd`与`decisions.gd`接原host执行；不自动引入BT插件或替换现有策略解释器。

- 将个人目的/意愿、候选选择、寻路和实际执行分开。查询条件不预付资源、不预约位置；只有原owner接受提案才能产生承诺。后台仅在脱离的本人输入上选择，不读取活World或借全知状态假装个人判断。
- 扩状态机时分开独立变化的状态轴，避免把装备×移动×意图的所有组合枚举成超级状态机；跨轴约束仍在原owner核。简单枚举/规则足够时不强制每状态一个类或Node。
- 每个持续行为定义开始、进行、成功、失败、中断及可再试条件。Running保持原run，不在每次选择时重启；抢占释放本次仍持有的预约、伙伴和未付承诺，保留已完成后果。手动接管、死亡、目标丢失和读档替换均有结果出口。
- 若用行为树，明确记忆Sequence与反应式条件：Running之后重要guard仍须在适当变化时复核，不能永久追失联目标；Reset不应重置真正的冷却而允许反复抢占绕过。若用效用，统一可比较的量纲/范围、说明组合规则，检查乘法零值/极端值，利用迟滞或最短承诺避免近似平分时抖动。
- 事件负责相关唤醒，到期负责已知时间条件，连续热数据按原批服务；不要每事件广播全员或在每候选复制世界。战斗反应与生活新选择有不同截止，等待软选择时继续已有可行工作。具体成本按原模拟范式，不以固定“每秒N次”代替语义。
- 请求已受理不等于NPC愿意。失败原因区分无资格、不同意、不知道、无路、暂时占用和陈旧输入；追踪实际转移与原因，避免每tick刷日志。随机选择由模拟RNG负责，画面随机不能影响NPC选择。

验证不只看某次得分：观察持续任务被打断、目标消失、无路后相关变化重试、两个近似候选不抖动、一个受饥饿/职责/个人认识限制的真实选择。计有效完成与等待，不靠“AI都动了”判通过。

设计事实查[单位决策](../../../design/systems/unit_decision_framework.md)；组合方法参考[状态模式](https://gameprogrammingpatterns.com/state.html)，它是解释工具，不要求为每个状态创建类或Node。
