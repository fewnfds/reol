## ADR-0001 — 引擎、版本与语言

- **日期**：2026-11-01
- **状态**：已接受
- **背景**：项目是 Godot 4.7.2 初始工程；开发者有 Unity 基础，无 Godot 经验；目标 2D 俯视开放世界/殖民 sim/RPG。
- **决策**：Godot **4.7.2** 标准版 + **GDScript**；不使用 C#/.NET；目标平台先 Windows。
- **后果**：
  - 可以使用 Godot 4.7 新特性（TileMapLayer、typed arrays 等）。
  - 不能直接复用 C# 生态/Unity 代码。
  - 升级引擎要跑全量测试和截图对比。
- **替代方案**：
  - Godot 4.7 .NET + C#：生态更强，但本项目不需要，且 Godot AI 对 C# 仅文本支持。
  - Unity：已有经验，但用户明确选择 Godot。

## ADR-0002 — 先做垂直切片，不做“大而全”

- **日期**：2026-11-01
- **状态**：已接受
- **背景**：目标包含开放世界、建造、殖民模拟、RPG、战斗；一次性做完不现实。
- **决策**：v0.1 只做 **“一山一宗”** 垂直切片：512×512 区域、1 个杂役主角、1 个小宗门 + 5 个具名 NPC、杂役工作/修炼/1 次晋升、1 个敌对前哨 + 1 个秘境、可暂停战斗、存档。**（v0.2 修订；原“One Camp”方案作废）**
- **后果**：
  - 大量想法进入 backlog，不进入首个版本。
  - 每个系统必须服务于 30 分钟可玩循环。
- **替代方案**：先做纯 RPG / 纯殖民 sim / 纯建造；都会失去“组合”的验证。

## ADR-0003 — 视角与美术方向

- **日期**：2026-11-01
- **状态**：被 ADR-0013 取代（2026-11-01）
- **背景**：参考 Warcraft 的俯视角；开发者无美术团队；需要快速占位。
- **原决策（已废弃）**：**2D 俯视 + 32×32 像素风**；先用 Kenney/LimeZu 占位；M4 再统一风格。
- **v0.2 说明**：不再采用“纯俯视 32×32”；改为 2D 正交俯视 + 正方形格 + 高度层，见 ADR-0013。
- **后果**：
  - 纹理 Filter 用 Nearest；相机/UI 按像素风调。
  - 不做 2.5D 高度层；遮挡用 Y-sort + 简单层级。
  - 后续转 HD/2.5D 成本较高。
- **替代方案**：16×16（更复古，细节少）、手绘 HD（成本高）、2.5D（复杂度高）。

## ADR-0004 — 架构：节点组合 + 数据驱动 + 固定 tick

- **日期**：2026-11-01
- **状态**：已接受（v0.2 确认）
- **背景**：殖民 sim 需要可预测的模拟；Godot 节点树适合组合，但 `_process` 不适合做模拟。
- **决策**：
  - 实体用 **Node 场景 + 组件子节点**，不做完整 ECS。
  - 定义/数值用 **Resource + JSON**，不硬编码。
  - 模拟用 **GameClock 固定 10 tick/s**；渲染/物理分开。
  - 系统间用 signal/EventBus 解耦。
- **后果**：
  - 需要自律：不在 `_process` 写模拟。
  - 实体数量上限比纯 ECS 低，但对 12–50 Pawn 足够。
  - 测试可以手动推进 tick，不依赖真实时间。
- **v0.2 补充**：模拟分 World / Region / Settlement / Local 多层时钟（ADR-0014）；本地仍 10Hz，渲染/物理分离。
- **替代方案**：完整 ECS（过度）、纯节点每帧（不可测）、Unity DOTS（换引擎）。

## ADR-0005 — 世界模型：手工骨架 + 程序填充

- **日期**：2026-11-01
- **状态**：被 ADR-0015 取代（2026-11-01）
- **背景**：全程序生成难做出“有意义的地标”；全手工地图内容量有限。
- **原决策（已废弃）**：
  - v0.1：单张 **128×128** 手工/半程序地图。
  - v1+：**64×64 区块**，seed + 规则生成地形，POI 数据表放置，只存 deltas。
- **v0.2 说明**：首区改为 512×512，区块流式从 M1 就做；见 ADR-0015。
- **后果**：
  - 需要设计地图数据格式（JSON/ASCII）。
  - 需要区块加载/卸载/持久化。
  - 不能承诺“无限世界”。
- **替代方案**：全手工（内容少）、全程序（地标弱）、无限 chunk（性能/存档复杂）。

## ADR-0007 — 存档：版本化 JSON + deltas

- **日期**：2026-11-01
- **状态**：已接受（v0.2 确认）
- **背景**：殖民 sim 状态复杂；改字段频繁；需要可读/可迁移。
- **决策**：
  - `user://saves/*.json`，带 `version`。
  - 地形只存 deltas；实体存 ID/定义 ID/状态，不存节点路径。
  - 原子写：`.tmp` → flush → rename；保留 `.bak`。
  - 每次存档结构变更加迁移函数 + roundtrip 测试。
- **后果**：
  - JSON 体积较大；后期可压缩/分片。
  - 需要严格的序列化约定。
- **替代方案**：二进制（快但难调试）、Godot Resource（版本迁移麻烦）、SQLite（过度）。

## ADR-0010 — 单人优先，不做联机/C#

- **日期**：2026-11-01
- **状态**：已接受
- **背景**：联机/账号/服务器会显著增加复杂度；本项目核心是模拟与沙盒。

## ADR-0012 — LLM 不进核心模拟

- **日期**：2026-11-01
- **状态**：已接受
- **背景**：Microverse 证明了 LLM NPC 的趣味，但 API 成本/延迟/不确定性不适合做核心需求/工作/经济。
- **决策**：
  - 核心模拟（需求/工作/战斗/经济）用确定性规则。
  - LLM 只用于可选对话/风味/文本生成，后期再做。
  - 不把 API key 写进仓库；不做离线依赖。
- **后果**：
  - NPC 对话初期是模板/分支，不是自由生成。
  - 游戏可离线运行。
- **v0.2 确认**：脚本 AI 优先；LLM 只做后期对话风味 / AI 托管（ADR-0018）。
- **替代方案**：LLM 驱动 NPC（成本/稳定性风险）、本地小模型（性能/质量风险）。

## ADR-0013 — 2D 正交俯视 + 正方形格 + 高度层，固定视角

- **日期**：2026-11-01
- **状态**：已接受
- **背景**：目标是 RimWorld / 了不起的修仙模拟器 / 矮人要塞式的平面系统深度、低美术高玩法。先试了 2D 等距（菱形 2:1），但坐标/排序/迷雾/寻路都更绕；用户明确要求“直上直下的坐标”，优先可处理性。评估过 3D/2.5D，成本过高。
- **决策**：
  - **2D 正交俯视（正方形格）**；`x` 向右、`y` 向下；格子 1:1 映射到世界坐标。
  - TileSet 正方形 **64×64**；`TileMapLayer` + Y-sort；相机只做**平移 + 缩放**，固定俯视，**不旋转、不俯仰**。
  - 高度用数据表达：每格 `elevation`（0–3），实体 `altitude`（0=地面，1=低空，2=高空）。
  - 渲染高度：屏幕空间 Y 偏移 + 影子偏移/缩放；悬崖用侧面/暗边表现；不做真 3D 物理。
  - 飞行：忽略地面障碍，但受“禁飞区/室内”限制；地面近战不能打空中，远程/对空技能可以；高度差影响射程/命中/视线。
  - 美术：俯视/微 3/4 视角贴图 + 国风有限色盘（墨黑/纸白/青玉/朱砂/金）；先用占位。
- **后果**：
  - 坐标/寻路/碰撞/迷雾/存档最简单；美术和迭代成本低；单位可读性最好。
  - 没有 WC3 的菱形等距观感；高度只能靠偏移/影子/悬崖侧面表现，立体感弱于等距。
  - 多层建筑/洞穴用独立场景或分层图层；不做真 3D。
  - 将来若转等距/3D，模拟/数据/存档可复用，渲染与美术需重写。
- **替代方案**：
  - 2D 等距（菱形 2:1）：更像 WC3，但坐标/排序/迷雾/寻路更绕；已试作后被放弃。
  - 3D 正交 + billboard：真高度/自由镜头，但 3D 美术、导航、遮挡、UI 成本高。
  - 2.5D：3D 地形 + 2D 角色，两套管线，首版不划算。
- **取代**：ADR-0003。

## ADR-0014 — 分层世界模拟与远区算法结算

- **日期**：2026-11-01
- **状态**：已接受
- **2026-11-02 用户澄清**：离场后的日常与大小事件持续推进、归来无重置，是基础体验要求；“百年闭关”只是例子。下一轮优先用两聚落验证连续性，算法方案见 `design/systems/world_continuity.md`；不将体验要求视为具体粗算参数已定。
- **背景**：玩家要的“像网游”不是联机，而是除主角外，势力/NPC/世界事件也随时间发展；远区不能逐个模拟，重大事件要能算法结算（类似全战/Paradox 的战略层）。
- **决策**：
  - 分层：**World**（每游戏天）→ **Region**（每游戏小时）→ **Settlement**（每几秒/游戏分钟）→ **Local**（10Hz）→ **Detail**（每帧）。
  - 远区只跑 World/Region：不创建场景、不跑物理；靠近时“提升”为 Local 实体，离开时“降级”为数据。
  - **具名 NPC 个体持久化**；普通 NPC 按 cohort/统计聚合，相关时再提升。
  - 玩家不在场的战斗用统计模型结算（兵力、地形、士气、将领、补给），产出伤亡、领土、战利品、仇怨；玩家在场则切入实时战斗。
  - 每个领域独立种子 RNG；存档记录 `sim_time`；读档按粗粒度补算并设上限。
  - 远区事件生成**传闻/新闻/任务**，通过 NPC、告示、信件传到玩家耳中。
- **后果**：
  - 世界“活着”但成本可控；需要事件日志、势力状态、结算公式和传闻系统。
  - 结算结果是近似值，不保证与逐实体模拟完全一致；可接受。
  - 存档/读档必须确定性，不能依赖 wall clock 或全局随机。
- **替代方案**：全量模拟每个 NPC（成本爆炸）、只做脚本事件（不涌现）、LLM 实时推演（不确定/贵/慢）。

## ADR-0015 — 512×512 首区、区块流式与 delta 存档

- **日期**：2026-11-01
- **状态**：已接受
- **背景**：目标是无缝大世界、尽量少过图；但首个 demo 不能一开始铺满大陆。需要一套可从 512×512 扩到更大世界的结构。
- **决策**：
  - 首个区域 **512×512** 格；区块 **64×64**（8×8）；加载半径 2（5×5），卸载半径 3。
  - 一个持久的 `World` 场景，不切地图；POI/洞府作为子场景异步加载。
  - 每帧最多加载 1 个区块；按玩家移动方向预测；地形由 seed 重建，存档只存 deltas。
  - 地图尺寸不硬编码；区域元数据 + 世界分区；后续可扩到 1024/2048 或区域拼接。
  - 存档字段：world seed、clock/sim_time、chunk deltas、faction state、named NPCs、player rank/reputation、fog explored、quest flags。
  - 存档格式：版本化 JSON；原子写（`.tmp` → rename）；迁移函数 + roundtrip 测试。
- **后果**：
  - 首区内容量可控，流式/存档从 M1 就能验证；后期扩图不改核心系统。
  - 需要稳定的 chunk delta 格式、ID 分配和异步加载预算。
  - 512×512 不是最终世界大小，只是第一个可玩区域。
- **替代方案**：单张 128×128（太小，验证不了流式）、一次性 2048×2048（内容/性能风险）、真无限世界（存档/生成复杂）。
- **取代**：ADR-0005。

## ADR-0016 — 身份、阵营、声望的数据模型

- **日期**：2026-11-01
- **状态**：已接受
- **背景**：玩家要从杂役到长老/掌门/散修/邪修；后续希望任意身份/位置开局；阵营/声望/关系要像 WoW，内政要像战锤一样简约。
- **决策**：
  - **FactionDef**：id、类型（宗门/王朝/部族/散修联盟/邪道）、领袖、领地、资源、教义、关系矩阵、职位表、颜色/徽记。
  - **RankDef**：杂役→外门→内门→真传→长老→掌门；每级定义义务、权限、声望门槛、修炼门槛。
  - **OriginDef**：起始势力/职位/位置/物品/任务/flags；Demo 只做“杂役”一条线，后续多出身靠数据扩展。
  - **Reputation**：对势力 + 对具名 NPC；事件驱动；阈值解锁职位/商店/对话/任务。
  - **Relationship**：师徒/同门/仇敌/道侣/债主等边；影响对话/援助/背叛。
  - **Edict**：资源分配/招募/建设/戒律/外交/战争；玩家作为首领只做少量决策。
  - 系统通过 tags/permissions 查询身份，不写 `if rank == "杂役"` 的硬编码。
- **后果**：
  - 多出身、多阵营是内容/数据工作，不是重写系统。
  - 需要 schema、条件查询、对话/任务条件；首版只验证一条线。
  - 声望/关系必须能被远区事件修改，否则世界不“记仇”。
- **替代方案**：硬编码单线（快但不可扩展）、完整政治/宫廷模拟（首版过重）。

## ADR-0017 — 可暂停即时战斗、局部时间缩放与高度规则

- **日期**：2026-11-01
- **状态**：已接受
- **背景**：战斗要即时 + 可暂停；战术慢放是后期高阶技能（敌人慢、玩家正常）；飞行/高度用 WC3 式视觉高低差，不做真 3D 空战。
- **决策**：
  - 实时 + 暂停（空格）；速度 0/1/2/4；暂停时 UI/指令仍响应。
  - **局部时间缩放**：每个 actor 有 `time_scale`；高阶技能让敌人 0.3、玩家 1.0；移动/AI/冷却/投射物各乘自己的 delta；**不用**全局 `Engine.time_scale`。
  - 战斗规模：玩家 + 3–5 同伴 vs 5–10 敌人；不做百人团战。
  - 高度：`altitude` 0/1/2；地面近战不能打空中；远程/对空技能可以；高度差影响射程/命中/视线；渲染用偏移 + 影子。
  - 可读性：阵营颜色、血条、施法条、地面预警、威胁提示。
  - 技能：1 普攻 + 2–4 主动；剑诀/符箓/阵法/身法；后期解锁时间领域。
- **后果**：
  - 暂停 + 局部慢放带来战术深度，但 AI/动画/投射物都要支持独立 delta。
  - 高度是规则抽象，不是 3D 空间；空中缠斗表现有限。
  - 小规模战斗更适合 2D 俯视和同伴 AI。
- **替代方案**：全局慢放（会拖慢 UI/玩家）、回合制（与即时幻想冲突）、真 3D 空战（已随 ADR-0013 放弃）。

## ADR-0018 — AI 分层：脚本优先，LLM 后期

- **日期**：2026-11-01
- **状态**：已接受
- **背景**：网上有鬼谷八荒/魔兽单机机器人/辐射 mod 等 LLM NPC 案例，但瓶颈在模型能力/成本/延迟，不在游戏架构；首版必须离线、可测、可存档。
- **决策**：
  - 核心 AI：**Utility AI + 行为树/FSM**；日常需求/工作用 utility，复杂战斗/逃跑用 BT/FSM。
  - **Action API**：玩家输入、脚本 AI、未来 LLM/AI 托管主角都走同一套动作接口；AI 不直接改状态。
  - **记忆/关系**：结构化表（事件、好感、亏欠、秘密、仇恨），不是 prompt 文本；LLM 只负责把表翻译成话。
  - LLM：后期可选，用于对话风味/文本变体；必须有模板降级；不进入核心模拟。
  - AI 托管主角：后期功能；复用 Action API；v0.1 不做。
- **后果**：
  - 首版可离线、确定性、可测试；对话自由度较低。
  - 后期接 LLM 只需加适配层，不用重写 AI。
  - 需要从第一天记录结构化事件/关系，否则后期没有“记忆”可用。
- **替代方案**：LLM 驱动核心 NPC（成本/延迟/不确定）、纯模板对话（可接受但上限低）。

## ADR-0019 — 内容生产：数据包、校验、世界生成管线

- **日期**：2026-11-01
- **状态**：已接受
- **背景**：后续希望用多线程 agent 批量构造世界/势力/NPC/任务；但 agent 生成代码/资源容易失控，必须先把数据格式和校验定下来。
- **决策**：
  - 内容以**数据包**（JSON / Resource）交付；schema 校验、稳定 ID、版本号；不运行时生成代码。
  - 世界生成管线：地形 → 群系 → POI → 势力 → 历史 → NPC → 掉落/任务；每步 seed 可复现、可单独重跑。
  - 大世界优先**离线烘焙**；运行时只生成局部细节；`WorkerThreadPool` 只做地形/网格等纯数据工作，不碰 SceneTree。
  - agent 产出必须过 schema + 设定圣经 + 人工抽查；多 agent 并行要有合并/冲突校验。
  - 预留薄接口：`WorldGenStep`、`ContentPack`、`ActionAPI`；首版不做完整 mod API。
- **后果**：
  - 内容可批量生产、可 diff、可回滚；需要写校验工具和 ID 规范。
  - 比“让 agent 直接写场景”慢一点，但可控。
  - 数据驱动要求系统不硬编码具体内容。
- **替代方案**：全手工（慢）、运行时 LLM 生成（不可复现/难校验）、直接生成 .tscn（难合并/易坏）。

## ADR-0020 — 社会事实是机构账本中的 Claim，不是人物属性

- **日期**：2026-11-01
- **状态**：提议
- **设计文档**：`design/systems/social_system.md`
- **背景**：
  - 现有 M2 代码把 `contribution` 放在 `PawnState` 上；这会把“社会承认”错误地建模成“人物属性”。
  - 目标设计里，宗门贡献由功德堂/长老/法器记录；人情由个人记忆；名声由传闻；面子由礼数。它们会随记录者、制度、继任变化而升值/冻结/作废。
  - 后续要频繁改数据类型/算法，不能把某一版数值模型写死。
- **决策**：
  - 社会事实统一表示为 **Claim**：有发行方、记账人、主体、适用范围、状态、证据、见证人、来源。
  - **机构/职位/法器**才能发行和记账；个人可以记私账，但私账不具官方效力。
  - **职位与人分离**：职位签发的 Claim 是公账；个人签发的 Claim 是私账。继任政策决定旧账“全认/冻结重登记/折价/拒付”。
  - Claim 的有效性**按 scope 分别成立**；机构态度 = 官方政策 × 派系 × 成员私意 × 叙事 × 利益，不是单一好感值。
  - 运行时用**事件日志 + 投影**：状态可重建，算法可替换，存档可迁移。
  - 玩家 UI 只显示**定性词、账页、对话、通行、价格**，不显示信任/信用的真值。
  - 删除 `PawnState.contribution`；贡献改为账本查询的派生视图。
- **后果**：
  - 比“声望 +10”复杂，需要 Claim/账本/职位/继任/证据等系统；首版只做 3 种 Claim、1 个宗门、1 次继任。
  - M2 的 JobBoard、对话、晋升必须先改用 Claim 模型，否则会返工。
  - 换来的是：人走茶凉、旧账冻结、私记对质、贡献贬值、跨宗门不通用等真实社会体验。
  - 需要严格的 UI 纪律：内部数值化，外部人话化。
- **替代方案**：
  - 单一 reputation 数值（快，但无法表达“面子还在、实利没了”）。
  - 阵营声望条（常见，但把机构当铁板，无法表达派系/继任）。
  - 完整双记账 + 全球动态经济（首版过重）。

## ADR-0021 — 继任由两阶段效用算法结算，不用固定百分比

- **日期**：2026-11-02
- **状态**：提议
- **设计文档**：`design/systems/social_system.md` 5.7
- **原型**：`scripts/social/succession_resolver.gd`（纯函数，10 个无头测试）
- **背景**：
  - 旧草案用“冻结 + 重新登记”作为默认策略，并给“恢复 80%”“黑市 40%”这类固定数字。
  - 固定百分比假设所有继任者、所有旧账、所有局面都一样；玩家会背最优解，而不是读人、读势、读账。
  - 现实里，新掌门逐笔问的是“认这笔账对我坐稳位子有什么好处，不认要付什么代价”。
- **决策**：
  - **阶段 A**：候选人按名分、派系、实力、控制、声望、财力、前任关系、外援八项加权；硬门槛先过滤；差距过小记为争议继位并削减合法性；无人合格进入空位期。
  - **阶段 B**：每条旧 Claim 在 `全认/折价/冻结/谈判/拒付` 五个动作中按效用打分；因素包括凭证效力、财政负担、稳定收益、政治亲疏、个人恩怨、反制能力、公开度、先例压力、新掌门需求、旧朝关联、不安全感、合法性。
  - 先过硬门槛（证据不足、库房见底、对方太强且公开、新掌门太弱且公开、法器封存、过期），再比效用；输出动作、折价率、前三个理由标签。
  - 权重、门槛、性格偏差放数据；`SuccessionPolicyDef` 不存固定百分比。性格（重诺/多疑/务实/贪利/好名/记仇/软弱/果决）只做小幅偏差。
  - UI 不显示效用分，只显示动作与 2–3 条人话理由。
- **后果**：
  - 同一笔旧账在不同继任者、财政、派系、实力、公开度下会得到不同结果；固定 80% 被删除。
  - 算法可单测、可回放、可调参；但需要调用方先把因素归一到 0..1，并维护“证据/财政/派系/关系”的数据。
  - 首版权重是校准起点，不是真理；必须用黄金场景和实际游玩继续调。
  - 比单一策略表复杂，但比完整政治模拟轻；不会自动生成阴谋、政变、暗杀，只结算“谁上位、旧账怎么办”。
- **替代方案**：
  - 固定百分比/固定策略表（简单，但无法表达局面差异）。
  - 纯随机（有意外感，但不可解释、不可学习）。
  - 完整多代理人政治模拟（真实，但首版过重、难调、难测）。

## ADR-0022 — 共用行动规则与分层社会模拟

- **日期**：2026-11-02
- **状态**：已接受（用户授权实施总体骨架；具体数值与扩展仍待验证）
- **设计文档**：`design/systems/living_world_framework.md`
- **背景**：用户要求人物、门派和阵营有自身目的及立足之本，关系与评价分层，任意身份进入仍有成立的处境与玩法；需要总体架构与开发计划。
- **方案**：
  - 按世界状态、人物行动、信息与关系、组织与制度、局势演化、玩家呈现划分职责；不据此一次建立全部 autoload。
  - 玩家与 NPC 共用行动成本、执行和后果；选择根据各自所知，实际执行检查真实条件。
  - 发生记录、个人认知、机构记录与玩家笔记分别表达；信号广播不授予人物知识。
  - 职位、任职者、授权、承认与执行分开，贡献归机构账目；Claim 不统包情绪、记忆和私人关系。
  - 按模拟基座→宗门日常→人物互助→离场与归来验证→组织办事→局势与冒险→世界规模与世代变化推进；信息边界、版本快照与随机状态连续性提前建立。
  - 用少量具名 NPC 的资源短缺与合作闭环验证，再扩展制度与长期演化。
- **后果**：
  - ADR-0016 的单一声望阈值设想需在接入社会系统前迁移；ADR-0020/0021 保持提议与原型状态，不能替代整个社会过程。
  - 必须处理 NPC 执行、资源预约、消息传播、未结事务与存档连续性；首个常驻聚落骨架已接入，区域粗算、跨区事务与远近接续仍待实现和验证。
  - 用场景验收和实测逐步定参，不先追求完整心理、政治或全球经济模型。
  - 首个运行版本已实现；当前交付与未接入部分见 `docs/LIVING-WORLD-IMPLEMENTATION.md`。不将总体方向的接受理解为旧继任权重的接受。
- **替代方案**：继续先铺声望与阈值（无法覆盖用户目标）；直接铺完整世界模拟（验证成本过大）；全部依靠预设剧情（难以支撑不同身份与 NPC 自主行动）。

## ADR-0029 — 世界先行、众生多样与有因果的组合交互

- **日期**：2026-11-02
- **状态**：用户最新方向已明确；共同规则与W0–W7为待实现设计。本轮继续仅设计，不改游戏代码
- **依据**：[世界总纲](../design/systems/self_consistent_world.md)、[众生](../design/systems/beings_and_lifeways.md)、[知识/法器/创造](../design/systems/knowledge_artifacts_and_invention.md)、[实施与验收](plans/world_first_sandbox.md)、[一手参考](../design/research/emergent_sandbox_world_references.md)。
- **用户方向**：战斗者、创造者、角色扮演者能通过不同选择生活；先构成自洽世界与“这样也行？”的发现，再调平衡。不预设所有人有同一RPG属性表、人身、装备栏和固定职业/技能清单；《骗经》、未知/难用的法器、反噬、戒中独立意志、创法、鸟妖与古兽均进入架构设计检验。
- **方案**：主体、身体/载体、控制与社会识别分开；真实作用、主体认识和实际操控/承受条件分开。知识有来源，物资和执行责任不重复；跨域作用有媒介、条件、代价、故障和痕迹。自然语言可描述意图与处境，执行须有支持规则，不因AIRP比喻自动安装语言模型或宣称任意文本可运行。

- **旧默认适用范围**：ADR-0028的四招/心神4/六衣位/40候选节点和三境界仅原型或内容建议；“一主体一身体一背包”仅现有人形简化，不再作为长期不变量。不同生命共享执行与因果约束，不强制共用所有字段和界面。
- **后果**：保留当前Demo，不重做已验证的双聚落/账本/互助。非人主体、器物认知、创法和规模尚未实现；五种生活样本、十个组合场景与W-A至W-L均为未来验收。设计完成不变更BASELINE游戏通过数。
- **替代方案**：先堆满职业/战斗词条再添加叙事（限制生活多样）；任意文本直接改变世界（无法保证因果与连续）；全面模拟现实全部细节（无法先得到可玩验证）。采用有限作用与完整小样本逐步扩展。

## ADR-0030 — 单角色人生接续、地方术法文明与可打断快进

> 后续修订：ADR-0033将死亡接续明确为有限新生候选；机会耗尽结束本局，退隐不再提供免费换人旁路。本文保留当时选择记录，接续预算/方式以ADR-0033为准。

- **日期**：2026-11-02
- **状态**：三项方向由用户通过提问工具明确选择；详细实现提案仍待原型，本轮只评审/改文档

- **已确定**：主要扮演一名角色，死亡或退隐后可用新身份继续同一世界；术法因地方资源、知识与权力具有不同普及程度，并真实改变当地社会；日常亲历与主动快进并存、可跨年，重要消息或危险可打断。

- **评审建议（不是用户逐项拍板）**：主体/载体、错误/冲突认识、作用语义、共同过程与有限规划在小样本中分别验证；把“不复制/守恒”限定为账实与事务一致，允许具有明确来源和条件的超自然创造。
- **实现状态**：W0与P0时间试验仍待做，不能将方向选择或本轮文档检查标成游戏功能通过。

## ADR-0033 — 不回滚的有限转生、新生候选与防人口筛选

- **日期**：2026-11-03
- **状态**：用户概念已明确；执行细则与L1–L12为待实现设计，本轮不改游戏代码
- **依据**：[有限重生与新生候选](../design/systems/rebirth_and_new_lives.md)、[众生](../design/systems/beings_and_lifeways.md)、[状态契约](plans/world_state_contracts.md)。
- **用户决定**：世界不回滚，提供随机若干新生儿人选，涵盖人类/动物/妖类，可小范围前跳；可以设计重随机、自选、增加稀有度等功能。次数有限且随难度升高减少；机会耗尽结束本局，极难增加，暂不考虑补充渠道。须防屠杀普通幼体、只留少数极品孕育者后自杀等方法操纵候选。
- **替代旧提案**：不再允许次数耗尽后免费创建普通新人、随意附身或以退隐切人延续。普通存读与游戏内转生仍区分，未授权铁人/跨档扣次。
- **执行提案**：本局连续性与各世身体/身份分开；预览有实际来源的待出生机会，在出生边界绑定，保留生理成长与旧世界后果。主角跨生记忆作为可细化的连续性方案，旧物/职位/他人认识不自动继承。
- **防利用提案**：按专用随机流先确定有限槽位的档位/范围，再匹配真实新生来源；不在幸存者中归一抬高稀有概率，不自动将落空配额转给极品。世次/刷新索引与已展示批次持久化；死亡ID仅作幂等关联，不以可由杀人数量改变的事件序号重新摇种子。
- **时间/失败**：只向前处理实际过程，候选寻觅小跳时与出生后成长分开；无合格出生、计算未完成、内容故障分别处理。无候选终局与具体退款/扣次边界为开发方案，仍待原型与对抗测试；不宣称已排除全部漏洞。
- **参数与范围**：剩余机会建议指还能转生的次数，最后一次成功进入的新生命可玩，之后再死亡无机会才终局。初始次数、每批数量、时间窗、刷新/自选/升档成本由开发定；当前不加剧情赠命系统。
- **实现状态**：尚无出生/成长/候选抽选/有限次数实现；设计检查和原Demo测试不当作L场景验证。

## ADR-0035 — 劳动获得实物与按来源形成库存预期

- **日期**：2026-11-03
- **状态**：有限样本已实现并有自动/运行/重启证据；通用认识、骗术与完整经济仍待做
- **依据**：[实际交付](qa/20261103_world_foundation.md)。
- **决策**：统一面板恢复旧劳作规则入口，以原身体/库存/时间完成劳动→凭据→机构登记→兑换现货→吃饭。山门劳作不能在河湾任意调用，也不能借原生动作绕过访客收费。
- **认识**：说话发生是真实事件，话的内容不等同仓库事实。复用已有个人观察记忆与事件来源链；近期亲见、说法时间、对具体来源的可靠性共同形成预期，NPC补给查预期，实际取物仍查实物。亲自查看只纠正本人，不自动全局定罪。
- **持久化**：新增的是已有可扩展事件中的stock_statement种类，不加同义仓库或全局声望；支持量/来源语义校验。重复同句窗口内复用事件；变化的说法记录新发生。同tick按数值事件序判新旧，避免JSON字典顺序改变判断；查询不耗随机、不教知识。
- **呈现与边界**：交谈输出“某某说/你亲见”，移除面板后台仓库总量。首版只做山门库存谈话；短交互与现有请求同类即时记录，不宣称完整长对话、域理解、法器鉴定、《骗经》或多载体已实现。信任/时限参数可测试校准，由开发负责。

## ADR-0036 — 主体/载体/排他控制的首个真实接缝

- **日期**：2026-11-03
- **状态**：已实现现有人类适配及旧档迁移；非人形仍为纯代用品，完整众生/换身未实现
- **依据**：[实际交付](qa/20261103_world_foundation.md)、[实施Goal](plans/implementation_goal.md)。

## ADR-0037 — 唯一器物、个人试用与真实生活作用首样本

- **日期**：2026-11-03
- **状态**：温火石生活用途已实现并实际跨进程验证；通用器物、穿戴/寄魂/创法未实现
- **依据**：[实际交付](qa/20261103_world_foundation.md)、[实施Goal](plans/implementation_goal.md)。
- **决策**：唯一器物以容器引用记录实际保管，不在堆叠库存再复制一份；持有不代表学会。本人行动留下带主体/动作/耗时/投入的来源记录，面板只用获准认识。循纹探查获得具体手法，错误催动有实际灵气/体力损失；有限储能替代燃料，但真实米水和时间仍须投入，产物和机构认可分开。
- **执行与持久化**：器物边界加入原区域世界时间；和原生/访客事务互斥，取消不退已投入灵气、不发未完成产物。材料transform先全量预检再单次提交，保留预约/容量与幂等性。根schema 4/区域快照3迁旧档为空器物领域，不倒造历史物品/学习；真实v3与v4完成档作为不可改写的回归来源。JSON数值按语义比较，不因整数归一误拒合法档。
- **范围与取舍**：当前依旧分钟轴，复用原凭据而不架空原生活循环；不把此样本冒充动作战斗时基、热力学或完整学习系统。新开局装配可在非零时刻创建候选以便读档，完整验证后由存档替换候选；不因此在已加载旧世界偷偷新增物品。

## ADR-0050 — 自由表达、结构化动作与无AI可玩

- **日期**：2026-11-03
- **状态**：已接受用户方向；通用交互协议/策略编程尚未实现
- **依据**：用户确认自由文字主要面向未来AI，动作/对象/条件补全面向脚本；无AI辅助也应能玩。希望交互是提出事项、由NPC依自身状况回应，而不是固定服务按钮直接兑现。
- **方向**：后续AI、界面与脚本应通过共同且有限的行动规则影响世界。接收信号、理解、能力、意愿/权限与实际执行分别成立；“玩家请求鉴定”不等于接收者已鉴定。交流可发现对方声称能做什么，不能自动读取后台完整能力表。
- **开发建议**：先以已有一项请求验证表达→理解/评估→协商/回应→实际执行→有限观察，逐步合并专用入口；常用安排可复用，避免每次日常都重复交涉。具体意图字段、AI模型、脚本语法与编辑器由原型决定，不当作已拍板实现。
- **自动策略边界**：用户希望可编排本人及下属战斗策略；下属是否听令由社会规则负责。建议以常备职责/计划减少逐帧重判，变化时再评估，且受实际所知、通信与控制约束。
- **后果**：修订早期“LLM只做风味”的限制，未来可参与意图理解、对话与计划；基础世界不依赖LLM，生成文字不直接改账、出货或结算伤亡。当前没有新增AI依赖或玩家编程系统。
- **详细记录**：[世界与交互原则](../design/systems/world_interaction_principles.md)。当前Goal继续paused，本轮仅文档。

## ADR-0051 — 环境、众生与组织的扩展理念及记录边界

- **日期**：2026-11-03

## ADR-0075 — 野药由原空间环境生长，照料消耗原私水与身体劳动

## ADR-0076 — 有限地火隙接回原身体与器物，不凭休息补满灵力

- **日期**：2026-11-03
- **状态**：E4-a有限规则、运行接线与真实进行中停开已验证；最新完整构建证据只看[BASELINE](BASELINE.md)。

- **边界**：固定一个灵源/一种媒介/适用人身，不是完整五行场、风水阵法、境界突破、源产权或长期恢复平衡。地表delta需先解决独立候选地图，再做真实集雨/地表改造；不为本包伪造地图编辑。正式美术后置，沿现有代码像素占位。

- **认识**：警告需要本人真实可见、同高/距离/遮挡与双方通信；源开始回调只是调度提示。转述固定簿上的签注保留个人来源和`direct=false`，不远程审计整账；看护可误信自己尚未发现已用的旧依据。提前说明只能绑定随后亲见的一次具体引息，不成为永久豁免。
- **升级**：初始90秒宽限不取消引息、不消费源或许可。原源完成先于同毫秒升级；只有到期且仍成立的具体warning可以走可信内部入口。真正开场才中断原源并建立双向cause，一job至多一警告/一驱离。普通玩家入口不获得内部时间保护豁免。
- **身体与自动方**：逐参与者依据原自主前态和真实控制通道决定自动动作，主动NPC不再依赖defender身份，玩家成为defender仍手动。全部场次先采同刻线索再提交起势；成本/命中/挫伤/退让归原域，双方所属区都刷新原调度边界。
- **持久化与提示**：根38/区域34/看护1/交锋3；旧根37仅迁空看护/空cause，不追补社会历史。观察只核可证明的原静止job与有限历史几何，不用今天的墙重判过去。读档恢复当前主体后先展示本人活警告并暂停，不给鸟/残识转发原人身私事。
- **边界**：一源一石一人，非通用巡逻、产权、偷窃追偿、没收、任免平台、全机构敌意或战争。胜负不夺产，不刷新体力/气力；下一转向有来源本领组合与新地点冒险。


## ADR-0085：本领来源投影、有限实际练习与共同时刻步行

- **状态**：2026-11-04实施；最终验收以BASELINE为准。
- **认识**：七项目录只读原教学/器物/温养/木牍证据，持有、听说、读过和练成不合并，不另存全人物learned表。
- **新增过程**：行气护身付原qi/体力，实际调息、四段短步和收束；完成证据才生效，中断保留原费用与真实停位。NPC同API，不声称已做自主长程学习。
- **动作**：仅原500ms护障动作内允许45%缓步；新投影不取消动作排他、ready反应锁、闪身/行旅限制，也不重新授予原动作结束后的正常行走。
- **时间**：原手动身体按Regional真实规则边界提交，单体内部毫秒积步保证任意外部切片一致，空闲立即退出；无世界毫秒唤醒或第二位置执行器。新命中锁在同边界钳速度，不撤销已经走过的路。
- **历史**：根38→39、区域34→35仅迁空练习与源2→3的费用floor1；不造旧练习/老师/能量。现代混版与伪来源/成本/移动候选拒绝，失败不换活世界。
- **范围**：不是大型天赋盘、突破、通用创法/种族框架；下一包把能力带出灶旁，接新地点冒险。


## ADR-0086：野外地点与原身体、个人线索及原实物分属

2026-11-04，U3-a实施。首个野外地点不创建第三Village；地点域只保存固定槽/有限个人意图和路线史，身体/行囊/唯一器物/记忆继续归原所有者。原归属聚落只决定账本所有者，显示和相遇按实际位置/FOW，不能把离开聚落的人隐藏。C问路以真实当面、本人来源与意愿形成具名分享，地点旧闻不追踪宝物的现在。

同一枚环在开局显式装配，玩家不接事也可被原NPC真实取走；胜利不自动夺物，不造任务领奖副本。旧档只迁空新域，不倒造过去。根40/区域36明确迁移与候选因果；原器物4/灵源3保持。引物功能与私物交换留下一包，外形研究不等于掌握使用法。两秒亲见采样和最多64路线史是首包有限预算，不代表多年大世界远区验收。

## ADR-0087：私人器物交割沿原身体、钱包和来源提交

- **状态与范围**：2026-11-04接入[U3-b2私人器物交换](plans/private_artifact_exchange.md)；验证及最终验收状态以[BASELINE](BASELINE.md)为准。首包只处理具名双方对同一枚环的固定报价和平交接，不是通用市场或产权司法；U3-b1引物局部样本已验收。
- **提案与同意**：`SimPrivateExchange`保存提案、当次同意引用、双人过程和交割凭证。提案身份包含买卖双方、具体环、卖方本次取得来源和报价；相同身份复用原`SimSocialMemory`判断与随机依据，无关变化、重试或读档不重掷。旧接受不是永久同意，每次开工须本人当面提出并记录当次同意；卖方明确撤回后不能借旧判断自动重启。
- **共同时间和原物**：双方在同一整数毫秒时间线上占用原身体与环，实际相遇以连续位置和通信条件判断；原登记区只决定身体、行囊的所有者。原库存预约报价，未完成时钱与环仍在原处；受击、失控、移动、主动停止或条件失效会中断并释放预约和占用。完成前同步原区域并重新核验，所有成功变更在无等待的同一提交段发生。
- **钱与来源**：同原区共用一份候选账本，以带预约的原`transfer`记付款；跨原区预检各自候选，在买方原账本记`consume`并在卖方原行囊加钱。交换域`transfers`记录本次转移凭证及当次同意/原器物事件引用；唯一环的保管位置与`exchanged`来源事件仍归`SimArtifacts`，不复制钱、环或身体。凭证、原操作和来源事件按可保留证据交叉核验，不声称只凭当前余额重建完整历史。
- **顺序与持久化**：器物动作、交割事件及取消/失败的`artifact:release`共享序号，区分同毫秒先后；释放不是虚构交割。旧根41/区域37/器物5显式升根42/区域38/器物6，交换域迁空，不创造旧提案、同意、实物或交易。独立候选先恢复形状与原账本，再联合验证引用、来源和在途占用，坏候选不替换活世界。
- **验证与规模边界**：受控规则及坏候选测试和普通产品路线分别记录，旧档保持只读，具体结果以BASELINE为准。不同域没有统一序号时，只能比较已有的半开毫秒区间，不能证明所有同刻顺序或历史遮挡。恢复时的来源与部分历史扫描尚未经多年规模性能验证；未来宜统一身体占用区间接缝并按实际测量建立索引，不逐域假装补全缺失历史。
