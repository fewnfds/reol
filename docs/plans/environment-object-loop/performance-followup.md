# 世界底座性能的有限接续

2026-11-07用户明确授权并要求主代理创建Goal。当前任务与接续仍只看[HANDOFF](../../status/handoff.md)；本页限定范围和停止条件，不成为第二条自动队列。依据[成熟项目研究](../../../design/research/large_simulation_optimization.md)，延续[初建QA](../../qa/20261106_environment_cold_build.md)的剩余热点。

## 顺序与停止条件

1. **原物创建/来源装配。** 先以已有真实生命周期基准拆测，改善重复空间查询等通用热路径；不为压测绕过原账本/成本/回执。批量接口只在有必要且边界可控时增加，不把26万件编辑器瞬时生成当日常玩法负载。
2. **大档存读。** 分测捕获、编码/解析、完整性、原世界候选恢复与派生重建。优先减少脚本逐字节与重复字符串处理，保留所有类型/长度/深度、引用、完整性、末尾、原子拒绝及中断恢复；只维护当前写格式。
3. **移动来源吞吐。** 在原单实物联合事务上比较1/8/32序列与同强密集极值负载，记录累计准备和吞吐/分片/发布。当前没有真实行走携源，不能把瞬时变更测试写成走路尾迹完成；最多尝试有测量依据的局部裁剪或已有GPU复用。

每项最多两条有依据的优化路线：先64²/128²，明确收益后才递增512²；每项完成一个可验证小包、记录证据再推进。若合理路线仍无收益、算法复杂度/成本已触及目标边界，或需改变规则/规模，立即停下报告实测与最小简化选项，不继续强行探索。不自动换引擎、引原生依赖、加房间/玩法或普通Main接管。

## 共同验收

- 原owner、位置/数量/成本/幂等、共同整数时间、近远因果、逐通道max保持；失败/取消/坏档不改变活世界。不得删断言/校验、丢时间或冻结远区凑性能。
- PC16GB整机/单3060为目标；大样本沿用合理约10GiB进程守卫，每个进程有超时。开发机32GB的采样不冒称16GB整机通过。
- 干净隔离检出保留四份既有WIP字节；串行引擎，主代理统一定向/规模/适用存读。每代码包一次原生Sol/custom静态审查，完整check或准确SHA CI一次，不默认双跑。
- Git分包commit/push；只在真实提交检查点查相关SHA/run一次，不轮询/被动等待代理。最终CI未结束保持待验，不拿旧绿色代证。
- 不改可见功能/美术；涉及呈现再做实际运行观察。本包纯模拟/存读优化的无头测量不能证明FPS/手感。

不创建第二份位置索引、不改变实际物品和存档结构。若该优化已经显著改善创建，停止第一包尝试，不为“批量”名称另造大事务框架。
