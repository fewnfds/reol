# 来源候选与大档内存优化

> 制定时方案快照；正文的旧版本、待验与“下一包”只描述当时，不能作当前施工依据。现有接入见[技术总表](../../status/technical-status.md)，适用性见[本目录说明](README.md)。

2026-11-06用户授权实施；当前状态只看[接续](../../status/handoff.md)。这是一个基础性能小包，针对[前包实测](../../qa/20261105_environment_response.md)的两个热点，不扩Main、携行、房间或玩法。

## 1. 降低单来源候选的无效搜索

前包同负载约3.6秒，不是同步发布耗时（仅几十至数百微秒），而是候选逐格逐通道的搜索。唯一热源移走时，原保守最大值不下降，又仍包含被排除的旧来源，导致搜索许多不可能受影响的格。

在原FieldCache单一索引上使用当前地面专用实现，维护七通道非零强度计数及不同强度的最大堆。原物仍唯一，堆只是派生上界，不存第二份位置。准备单源变更时，按计数排除旧来源，取剩余最大值；新来源沿原候选单独计算。多个同强来源、次强接替、最强消失和改半径仍须整数完全一致。

保留原prepare/step/proof/commit/cancel与GPU过期校验。使用继承接入唯一当前地面构造，不复制另一个长期场；受保护的原field_cache/temperature及两份测试字节不变，也不混入其未提交批量草稿。增加差分测试，和原实现/直接参考逐通道核对，不改max世界规则换速度。

## 2. 降低保存恢复的中间内存

前包512²全量JSON解析触及10GiB守卫，而纯计算峰工作集约3.84GiB；重点是中间表示，不能靠增大守卫凑过。

- 实际响应按16²块保存packed整数时间/双精度列，替代每格字典与浮点文本；不保存来源缓存/GPU缓冲/第二份物品。
- 原世界仍由原`to_dict/restore`校验，不另写物品恢复器。文件采用白名单、分段二进制树，不创建全量JSON字符串及解析副本；禁止Object/Callable/Resource等运行对象。
- 版本、大小/计数/深度、类型、完整性与末尾校验必须在候选提交前通过。失败文件不得覆盖活档/活会话；现普通存档schema不变。开发验收格式升级只写一版，不扩无止境兼容链；历史真实fixture不改。
- 恢复仍构建独立原世界，原领域语义校验保留；响应目标逐格校验分片，不以一次数秒全图检查阻塞呈现。不因压缩或内存优化删掉引用、时间、digest与目标检查。
- 首轮512²紧凑文件已完成写读，但在原地面物品候选恢复触及同一10GiB守卫。对实测重复元数据补原账本的材料转移紧凑回执，复用已有生成回执机制；decode保留完整请求/结果、成本、幂等及进行中动作核验，不删除来源历史、不新造物品恢复器。文件提升同时补固定可发现恢复点，不能假定Windows覆盖重命名是原子的。

## 验收与停止点

1. 定向差分：源覆盖/同强/次强/冷热独立/多格/取消/旧proof/GPU快照；响应精度、坏文件/篡改/截断/进行中动作/候选不改活世界。
2. 64²先测，确认收益后再128²/512²近满格半径16。每图一个在途动作及1/8/32序列，区分初始化、候选累计、单次pump、同步发布、保存/解析/恢复、峰工作集；CPU/GPU范围分别声明。
3. 初始期望是单次候选至少明显数量级下降、512²完整存读在原10GiB守卫内终态成功；参数不作为通过证据。若另一个热点占优，记录具体时间与下一步，不顺带重写整个世界。
4. 完整停开用新文件路径验证同一未来；原生只读审查一次，最终准确SHA完整check一次（或相同SHA CI），不并发整套引擎验证，不轮询CI。

目标仍为16GB整机、单RTX3060，开发机实测不能替代真实低规格整机联合负载。结果写独立QA，完成后停止讨论；仍有未达项如实保留，不扩引擎更换或玩法。
