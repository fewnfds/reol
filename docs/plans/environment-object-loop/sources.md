# 来源定义、投影与原物事务

> 制定时方案快照；正文的旧版本、待验与“下一包”只描述当时，不能作当前施工依据。现有接入见[技术总表](../../status/technical-status.md)，适用性见[本目录说明](README.md)。

这是[环境首轮](README.md)的技术候选，字段名可随实施收敛。固定规则见[环境规则](../../../design/rules/environment.md)；不记录实现进度。

本页包括后续联合事务候选；A1的实际只读接口、默认定义、支持范围和预算以[来源查询合同](../../engineering/environment-source-query-contract.md)为准。A1不持持续来源库或响应锚点，不能按本页后续章节推断原物联合事务已接入。

用户已撤回全对象格位置权威的临时结论，并在[调研](../../../design/research/spatial_models.md)后授权开发者选型。首版保留人物权威子格位置，环境按格缓存；未来移动场从原位置派生所在格发源。当前A1只接地面来源，不据此强制移动单位格化或调整其多格中心约定。

## 支持对象与来源身份

| 原对象 | 本轮来源身份与行为 |
|---|---|
| 普通地面独特实物 | 原 `artifact:id` 一实例一来源；绑定定义，位置读ground/原器物归处 |
| 地面数量材料 | 原 `stock:domain:region:container:item` 一活堆一来源；数量大于0时强度不乘数量 |
| 多格实物 | 同一个原引用及完整占地，只登记一个点源；不按占格复制实物或增加强度 |
| 身体、随身物、普通容器内部物 | 本轮不计算向外映射；查询明确标未支持，不把放入背包说成已实现屏蔽术 |
| 植物、墙、地表 | 保留接入形状，实际注册后续各域处理；资源点不假装是完整植物 |

同一全局坐标的影响按真实来源合成，账务region不能被解释成互不影响的平行地图。来源slot只是派生查询键，存读后可重建，不可成为永久物品身份。

## 版本化定义

来源配置采用profiles及原定义绑定表，不按显示名写分支。候选结构：

```json
{
  "version": 1,
  "profiles": {
    "ordinary_earth": {
      "elements": {"wood": 0, "fire": 0, "earth": 1000, "metal": 100, "water": 0},
      "thermal_grade": 0,
      "radius_cells": 4, "activation": "intrinsic", "origin": "footprint_anchor"
    }
  },
  "bindings": {"artifacts": {}, "materials": {}}
}
```

五行等级为有限非负整数定点；冷热统一为一项有符号整数定点 `thermal_grade`：负冷、正热、零无影响。若以1000表示1级，则−5000为5级冷、+5000为5级热；单位在schema固定，示例不是已确认平衡。不再给同一个普通来源同时配置 `hot_grade` 和 `cold_grade`。五行火通道与冷热热是独立能力，不从火属性自动推导温度。冷端/热端等级上限、映射表和响应owner安全范围必须一致，越界明确拒绝，不静默clamp。

本轮activation先接普通物 intrinsic。已启用热器物的开关必须读原实例 `enabled`，不能另建开关；它们在Main整体接管前不获得新玩家操作或改变原付费流程。不能为了演示而给普通石料加时间、法力和任务专用脚本。

支持集合中的定义必须有合法绑定或显式无辐射配置；缺绑定返回 `profile_missing`，不当作已知零场。普通物料可共用profile；改一个profile不改实例，存档/验收包绑定其确切内容digest。旧内容不从当前磁盘偷偷补新属性。

**来源坐标职责：** 读取原模拟位置，不能从画面插值回推权威事实。A1地面静物仍按锚格加 `floor((size-1)/2)` 定位，偶数尺寸向左/上；该约定不要求移动身体只能停在格心。未来移动来源首版从子格位置派生所在格，按真实跨格时刻切换，详见[调度](scheduling.md)；直接用子格距离保留为有证据再评估的替代方案。多格物仍是一件实物，完整占地不因点源简化而消失；不在本包改其中心或扩任意offset。旧QA只描述原SHA。

## 覆盖与聚合

- 半径首轮采用2/4/8/16格少量模板，预先生成欧氏圆核。source中心基础权重1，圆外0；所有通道复用几何。
- 五行各通道 `D[k]=max(P[i,k]×K[i])`；每源冷热有效值 `v[i]=thermal_grade[i]×K[i]`。合成时派生 `H=max(0,max(v[i]))`、`C=max(0,max(-v[i]))`，净等级 `q=H-C`。H/C是最大值比较用的临时量，不是物品的两项属性；不能只对有符号值取max，否则冷源会被忽略。普通场不求和，弱来源保留以便最强者移走后接替。
- 地面堆1份改成10000份时，只要仍是同一合法堆，来源强度不变；拆成不同位置按各处真实一堆一源，重叠仍取max。减少到0才撤销该堆来源。
- 一次数量转移可能同时改变两处堆。收集全部旧/新来源差异后联合准备，不能只更新被点击的目标堆；同处合堆不制造第二来源。
- 旧/新覆盖区分别裁剪、取块并集并去重；远距离移动不把两端中间整条地图标脏。最大来源移除要重新比较剩余来源，不能从max缓存减去旧值。

已提交HEAD候选支持单来源变更、单笔最多64个16×16块；多编辑批量接口仍在受保护WIP，不能当已完成能力。下一[受限响应包](response-ground.md)先按单个独特实物两端变化实施，仍按实际并集预检。超出限额返回 `unsupported_coverage`，物品和环境保持原状。上文材料拆合的多来源联合是后续候选，不在该小包承诺内。较大地图的初始化按阶段装配全部来源/锚点后才发布，不分块公开一个未完整生效的世界；大型单笔变化后续再设计。

## 原物—来源—响应共同提交

候选接口以明确状态返回，不把一个bool同时表示失败与待算：

| 接口职责 | 候选返回 |
|---|---|
| `project(reference, context)` | `ok/no_source/unsupported/stale`，来源参数及原状态指纹 |
| `prepare_object_change(request, at_ms)` | `ready/pending/rejected`，原物计划和环境句柄 |
| `resume_preparation(handle, work_budget)` | 进度与已消耗工作，未完成不发布 |
| `commit_prepared(proof)` | 完整复验后一次提交；同command返回原回执 |
| `cancel_preparation(handle)` | 释放准备，按原动作规则释放预约/控制 |

顺序固定：

1. **读旧事实。** 在共同事件时刻验证原实例、源位置、目标完整占地、可用数量/预约、权限前置和内容版本。建立纯变更计划，不扣新增成本、不改原对象。
2. **准备候选。** 旧环境结算到该事件时刻，推导全部来源差异和响应新锚点；分片仅改变私有候选，活对象/场仍保持旧版本。
3. **处理待算。** 原动作保留预约和截止事件，新增明确待准备状态；世界不能越过尚未提交的边界。预算不足不是行动失败，也不能把deadline改到更晚来藏欠算。一次性权威调用可返回pending句柄，由世界推进器统一续算。
4. **最终复验。** 原对象指纹、目标占地、数量预约、世界实例世代、共同时刻、定义digest和三个环境候选revision全匹配，才签提交proof。相同数字revision但换过世界的旧句柄也无效。
5. **同步发布。** 在没有yield、外部回调或再做业务预检的区间内提交原物/原数量、地面索引、来源场、温度/五行锚点、回执和动作结果。所需容量及候选分配在之前完成；失败不依靠事后补偿。
6. **最后通知。** 继续用冻结的 `committed` 触发视图/诊断失效。订阅者读到的已经是完整共同状态，不能靠通知再补权威环境。

同毫秒动作沿既有稳定排序提交。上一动作回调取消下一动作时，下一动作不能执行快照中的旧任务。不同请求顺序可能产生真实不同结果，测试要求给定事件顺序下可重复，不声称世界事件可任意交换。

取消/源改变/目的格被占时销毁候选，不复活旧对象、不重扣已付费用；已发生的原耗时和成本按原域保留，不能靠回滚抹掉历史。普通旧器物的bool guard只能当同步预检，不能冒充已支持这种挂起。

## 内容与存档边界

A/B用从当前普通会话取得的原内容和原世界独立候选装配，外加版本化来源配置，形成明确标记的开发验收包。包包含原会话摘要、来源配置digest及新增响应，不冒充新的普通游戏存档。普通存档schema51/区域42在本轮不增加半接管域，不生成第二种普通运行模式。

正式接管时将来源定义纳入同一个内容包路径集合/digest，并制定从届时当前格式的有限迁入。本轮先验证来源schema及绑定解析；不能为了让验收包读入而放松原内容包校验。没有新增定义绑定的旧档不会凭读取补发能力。
