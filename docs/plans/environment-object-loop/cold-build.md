# 基础场初建的有限优化

2026-11-06用户授权尝试优化；实际进度只看[接续](../../status/handoff.md)。依据[成熟项目调研](../../../design/research/large_simulation_optimization.md)，本包只改善全域基础场初建，不扩普通Main、携行、房间、玩法或存档格式。

## 预算与停止点

- 最多评估两条算法路线：CPU局部空间上界；若其收益不足，再比较复用已有GPU冷建的可行性。不是同时建设两套新框架。
- 先在64²同环境、同负载、同预算做前后对比；只有有明确收益才扩大到128²/512²。不循环试几十个微调参数。
- 每个引擎进程有时间/内存守卫，串行验证。目标仍16GB整机、单3060；沿用10GiB大样本进程守卫，不提高预算掩盖失败。
- 若两条路线不能显著改善，停下报告分项瓶颈、已核成熟方案及可简化要求；不自动引原生依赖、改场规则或换引擎。

## 1. 建立可比基线

使用真实原物生命周期，构建半径16的近满格木材背景和少量强来源；分开计时原物创建、来源投影/索引装配、CPU基础场重建。记录累计work、pump p95/p99/max、总耗时及工作集/private；与原物直查抽样差分。补混合半径/同强等差分，避免只对一种石头分布有效。

旧`sources`550.9秒包含装配与CPU重建，旧GPU0.616秒不是同分布/同范围，不能直接比较。新基线不默认重复漫长512²旧全流程，先用同版本64²对照。

## 2. CPU路线：来源块局部上界

在已有GroundField的唯一槽位/链表/候选/修订之上，为16²来源块维护七通道非零等级计数和最大堆。只记录派生计数，不复制实物/位置，不存第二份场。

每个待构建目标tile只读取扩展最大半径后相交的来源块，分work累计保守逐通道最大强度；原距离有序搜索使用此局部上界，远处无覆盖极值不再强迫搜索。仍用原欧氏距离表、整数舍入和max。

直接来源增删/改强/移动与候选提交都更新同一派生索引；同强及次强接替保持。候选本身沿已有全局排除旧slot算法，不顺带重写。未受影响的在建tile仍可保留，块上界只裁剪不决定所有权/事件时间。全零源、不同半径、跨块和边界不能漏算。

## 3. 验证与收尾

1. doctor与隔离干净检出；保护主工作区四WIP字节，不把草稿当基线。
2. 普通rebuild/候选/直接原物/compute/响应定向差分；小work预算可续，过期和取消不能发布。
3. 同条件64²前后，确认收益后递增规模；记录装配额外成本而非只报内核提速。
4. 一次原生Sol/custom静态审查，首个真实问题修复后定向复验；完整check本机一次或准确SHA CI，不默认双跑、不轮询CI。
5. 更新真实QA和接续，分批提交；完成本性能包即停下。存读编码/校验/I/O仍另包，不以初建改善冒称完整加载已快或大世界实时吞吐达标。
