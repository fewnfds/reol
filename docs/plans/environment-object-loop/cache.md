# A2a：真实地面来源的分块基础目标缓存

> 制定时方案快照；正文的旧版本、待验与“下一包”只描述当时，不能作当前施工依据。现有接入见[技术总表](../../status/technical-status.md)，适用性见[本目录说明](README.md)。

这是A1之后的A2a工作包规格，不单独维护当前任务或通过状态。实际接口见[缓存合同](../../engineering/environment-ground-cache-contract.md)，受检范围见[QA](../../qa/20261105_environment_ground_cache.md)，授权和停点只看[HANDOFF](../../status/handoff.md)。依赖[A1来源接口](../../engineering/environment-source-query-contract.md)，只解决批量计算、重复读取和原物变更后的可靠失效。

用户在[空间模型调研](../../../design/research/spatial_models.md)后授权开发者自主选型。采用方格地形/建造、人物权威子格位置、按格缓存环境；未来移动场首版以所在格发源。本包只做A1地面静物缓存，不实施身体/战斗改写或移动场。

## 目标与停止点

让真实地面物品驱动一份可丢弃的派生基础目标缓存：一块地完整计算一次，随后快速读取；物品变化只使旧/新邻域失效，按预算重建。保留原物/数量/位置的唯一归属，不再为每个受影响格反复读取附近上千件原物。

交付出口是开发侧CPU缓存服务及真实物品测试，不增加玩家菜单。**本包完成后停止报告；实际温度/五行渐变、原物与实际环境联合提交、房间、Main接管和GPU运行接入均不自动连做。**

预算与真实刷新不得混为一谈。后续动态场接入按[时间、刷新与过载合同](scheduling.md)统一世界时间、移动段、输入与背压；本缓存包只提供可预算的计算接缝，不宣称已完成10Hz场调度或持续超载控制。

## 为什么先做这个

A1精确提交512²、262144件真实物品、半径16的局部查询p99为11.619ms。它适合查证及小范围参考，不适合把每帧大量地块各自重算。现有packed缓存已经有 `read_base/request_area/rebuild`、七通道max、局部失效及预算续算；先把真实原物接上，复用它而不是另写一个场引擎。

旧合成来源基准测过512² CPU初建约9.7秒、缓存查询较快；这只能用于选择技术路线，不是本包真实对象性能证据。真实对象→来源装配、首次建场、局部变化和反复读取仍须分别量测。[旧基准](../../qa/20261105_field_compute_acceleration.md)与[A1基准](../../qa/20261105_environment_source_bindings.md)保留原范围。

原计划下一步直接做原物—来源—实际响应联合事务，会同时牵动动作挂起、世界时间、温度和存档。当前目标只是可重建缓存，允许返回pending，先无需改造成那种大事务。

## 采用方案

### 1. 先统一一次计算合同

当前A1对外五行顺序为木/火/土/金/水，旧packed内部为金/木/水/火/土；A1衰减取整数截断，旧CPU/GPU场原型取最近整数。直接接数组会串行，直接对照也可能相差一个最小单位。

下一包建议保留对外具名顺序，通过明确适配转换旧内部布局；衰减统一采用现有CPU/GPU的最近整数：

`effective = floor((strength × weight + SCALE/2) / SCALE)`

冷热先按绝对强度套同一规则，再合成H−C，保证正负对称。1000代表1级，舍入变化最多一个最小单位，即0.001级；不是改变冷热对抗或五行max法则。更新A1参考实现、接口说明与相应断言，并在结果/验收上下文标明统一的计算规则版本。只保留一套当前规则，不长期维护截断/舍入两个开关；旧QA继续描述其原SHA。

本包只接A1支持的地面静物，沿其现有锚格及偶数多格发源格约定，不把静物放置规则扩展为全部单位运动规则。后续移动源首版从原权威位置及游戏时刻派生所在格，在跨格时切换发源，不读绘图插值；须在动态包验证误差和负载，必要时再评估子格距离。详见[调度](scheduling.md)，不在缓存包顺手修改身体、停止位置或战斗。

本包不修改已有GPU shader或引入GPU后端；它现有舍入方式可作为对齐依据，不能由此宣称真实对象GPU已验。

### 2. 从原物装配派生来源索引

在明确世界实例、原生命周期/ground实例、内容digest及共同起点下装配。遍历原ground的空间桶，分批读取活跃原引用，再通过A1投影得到配置、点源和七通道；多格实物跨桶须按原引用去重，一堆只登记一次。

复用现有packed源数组。原引用到临时slot的映射仅用于适配，slot不是物品身份；移除后回收复用，不随搬运历史无限增长。零辐射物件可不进入场源数组，但仍要验证其显式配置；不因缺profile就当作零。来源参数只是原owner的派生副本，不可修改原物，不落普通存档。

装配期间不对外宣告就绪。每批复核输入世代与来源事实；若发生世界恢复、配置变化或原物变化，取消或重启这次候选，不能把两个时刻拼在一起。首次完整装配是明确加载成本，不能藏在第一次普通格子查询里。

不先调用 `world.to_dict()`、不复制全世界库存，也不在每个step用 `slots.keys()` 全量分配。当前真实ground上限512²，原型能配置更大数组不构成扩大真实地图的验收。

### 3. 按16×16块请求和读取

服务采用以下最小职责，名称可按实施收敛：

| 接口职责 | 结果与限制 |
|---|---|
| 开始/继续装配 | 有界扫描/projection预算，building/ready/error；完成前无可读当前场 |
| `request_area(rect)` | 按块裁剪/去重/排队，不立即全图计算 |
| `advance(work_budget)` | 复用CPU rebuild分片处理；预算耗尽保留任务，不改变世界时间 |
| `read_base(cell)` | ready才返回五行、净冷热和版本；未完成返回pending，不带部分值 |
| `diagnostics()` | 装配/待同步源/脏块/工作量/内存/取消与失效次数 |
| 关闭/重建绑定 | 释放派生数据；旧句柄不能指向恢复后的新owner |

块内数据用packed数组，干净块直接读值，不重复调用A1的逐格附近原物搜索。脏块完整计算后才发布，途中不暴露半块结果。重复request不制造重复队列；同一查询不推进世界模拟。

本包初始最多保留1024个完成块，正好覆盖当前512²；七通道int32纯数值约7MiB。来源数组、引用映射、工作候选和字典开销另计，不能把7MiB说成总内存。窗口请求可以只建立局部块；大范围冷启动仍按加载/预算处理。

### 4. 原物改变时先失效，再异步重算

支持原生命周期的spawn/move/remove/stock_transfer及其正常耗时完成。原物成功提交后、外部 `committed` 订阅者可以读取前，通过一个明确的内部接缝同步执行：

1. 标记这次缓存同步边界，确保旧结果立即不可被当作当前结果读取。
2. 登记本次涉及的全部旧/新原引用及其影响范围；拆堆/合堆要处理两端。
3. 只使旧/新覆盖块的并集失效，去重；远距离移动不把两端之间的长条地图标脏。
4. 原物通知之后，预算服务再读取原owner、更新派生来源并重建请求块；失败或尚未完成时明确pending/error。

这一步是**缓存失效保障**，不是提交后补写权威实际温度。缓存预算不足不应让已经合法完成的搬运失败，不重新扣数量、费用或时间。将来接实际响应时，仍需变更前结算/准备/复验及联合提交，不能拿本接缝替代。

这里的旧/新邻域是一次离散位置提交的缓存处理，不表示走路搬运只影响旅程起终点。当前耗时转移没有行走路径，携物也未接来源。真实移动须按原轨迹和共同时间处理沿途暴露、余温及速度差异，见[运动来源合同](continuity.md#真实搬运与运动来源)；不能把本包基础目标的即时更新当作地块瞬间升温。后续响应不可用合并后最终缓存值抹掉途中历史。

失效不能依赖普通signal订阅顺序。需覆盖回调内读取/嵌套执行下一动作：在登记未完成、通知乱序或观察到未覆盖的owner修订时，拒绝读旧缓存，必要时丢弃派生索引重建。此接缝只用于缓存，不建立全项目通用事件总线或可扩展插件框架。

同堆正数量1→10000且profile/位置未变，不重建场；只更新需要的诊断数量。清空才撤源。强源移走须重新比较其他来源；不从max值减去旧源，不按堆数相加。

### 5. 明确什么能证明缓存仍有效

`ground.revision`只覆盖一部分位置变化，不能单独充当全部原物版本。服务还需核对原生命周期/ground/artifacts实例、世界世代、配置/计算版本，以及受支持变更入口的连续失效序列。恢复后原对象实例替换，即使时间和数字revision相同也不能复用旧绑定。

当前SimInventory没有覆盖所有写入的通用revision。实施前须枚举实际支持的地面数量写入口；正常地面堆以原生命周期为受控入口。若还有运行代码能旁路改地面堆到0，必须让该受支持路径同样失效或明确拒绝绑定，不能仅补一段文案假设它不会发生。不在本包把所有库存域改造成新框架。

共同时间欠算、来源区域未同步、配置缺失或无法证明输入一致时，不发布“当前已就绪”。本包基础目标不含天气/tide和历史响应，但时刻/来源事实仍须可证明；时间推进本身不应迫使静止内禀源全图重建，允许通过同一失效序列证明来源事实未变。

关闭、取消冷块计算或世界重绑时，旧计算结果一律不可发布到新世界。不保存缓存，也不扩普通schema51/区域42；候选恢复后从原物重建并核对同一配置。

## 分步实施与文件范围

1. 固化通道映射、整数舍入及规则版本，完成小图独立参考对照。
2. 新增一个原物到现有cache的薄适配服务，先打通有界装配/请求/预算/快速读取/关闭。
3. 接原生命周期同步失效边界，覆盖材料两端和回调读取，补恢复/取消/过期拒绝。
4. 真实物品定向与密度测试，记录失败、热点和支持规模，完成审查及一次完整回归，更新实际合同和接续后停止。

预计改动为 `environment_source_bindings.gd`、`environment_field_rules.gd` 的共同算术、一个薄缓存适配脚本、`object_lifecycle.gd` 的明确失效接缝和测试。现有 `environment_field_cache.gd` 优先使用已提交的read/request/rebuild/set/remove能力；四份保护WIP保持原样，不把未提交的多来源候选当作前置。若复用必须触碰WIP，先单独说明范围再排包，不覆盖半成品。

不改 `environment_source_change.gd` 的温度事务、不改动作挂起/耗时语义，不建第二份温度或新存档。无需新插件、依赖、全量ECS或引擎切换。

## 功能验收

| 情况 | 必须证明 |
|---|---|
| 两个定义同profile、混合五行/冷热、半径2/4/8/16 | 小图所有格与统一规则的A1参考完全一致；通道不串，冷热对称 |
| 1×1/2×1、多格跨块、地图边缘 | 一原物一源，覆盖正确，没有漏halo或双登记 |
| 1/4/16/10000同堆、拆合/最后一份移走 | 强度不乘数量，移空撤源，两端一致 |
| 强源离开、远移/往返、收起/落地/删除 | 弱源接替，仅相关邻域失效，干净远块不被重建 |
| 小预算/反复request/取消/失效途中再移动 | 不暴露半块，不发布旧结果，不丢待算任务 |
| 通知回调立刻查场或再次搬运 | 只能读正确新值或pending，不能把旧值标为当前 |
| 相同时间/revision的新候选世界 | 旧绑定失效，重新从原owner装配结果相同 |
| 缺配置/未同步区域/欠算/损坏输入 | 明确拒绝，不改物品、账本、时间或玩家认知 |

大图只做声明数量的采样对照；不能把小图逐格或大图抽样写成大图全格核对。查询顺序、预算大小和请求是否出现不改变完成后的基础目标。

## 性能验收与止损

顺序测试64²/128²/256²/512²真实地面物品，半径16及混合半径，CPU先行；不并发压力测试。独立计原物生成、来源装配、全图冷建、首个局部窗口、热读、1/16/64件局部变动、1%分散变化和释放。1%变化可能覆盖全图，这是实际最坏负载，不能要求它只脏少量块。

初始目标而非已验证承诺：

- 1024次热缓存读值合计p95≤5ms，且不随地图总来源数线性增长；与同硬件A1真实物品基线比较。
- 每次CPU推进以约2ms为调度目标，p99优先控制在4ms内；完整计begin/核初始化/step/finish/commit/释放，不用工作计数掩盖同步尖峰。未达则优化热点或如实报告，不为通过偷偷减少真实对象密度。
- 内存与GPU统一引用[全项目性能基线](../../engineering/architecture.md#全项目性能基线)。撤销本页自行提出的256MiB缓存警戒，不作为门槛或额外优化任务；记录加载/重建/稳态峰值和原世界/缓存增量，避免无界增长，不只统计packed数组。
- 单次原物动作的同步失效只做有界元数据工作；缓存不能让普通一次移动隐式重建全图。全图初始化允许加载阶段分片，记录其总耗时，不承诺一帧完成。

采用PC优先、外部有限时间/内存守卫；单个基准的守卫不是整款游戏内存上限，本机32GB不能当16GB实测。无头数据不称游戏FPS。GPU已获用户允许，可利用已有服务对大范围场重建做相同真实负载的端到端比较；本包先完成CPU正确性，GPU隔离成绩不冒充真实物件管线收益，接入须包含装配/提交/回读而不只报核函数耗时。

## 本包完成后能做什么

开发调用者可以对真实世界请求一片区域，按预算生成基础目标，再快速反复读取；物品变化后可靠失效并重算。下一次讨论才决定实际环境响应与原物事务怎样接上。此时仍不能宣称冰火石移动后的余温/五行残留已在普通游戏生效。
