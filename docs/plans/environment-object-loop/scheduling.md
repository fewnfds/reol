# 动态场的模拟时间、刷新和过载合同

这是用户关于低帧率/场刷新讨论后的候选方案，不是已实现或实施授权。当前状态只看[HANDOFF](../../status/handoff.md)。本页约束[缓存](cache.md)与[连续响应](continuity.md)的接合，不能把预算续算等同于完整过载控制。

## 先区分三种时间

| 概念 | 含义 |
|---|---|
| 现实耗时 | CPU/GPU用了多少真实毫秒，是性能测量与工作预算的依据 |
| 世界时间 | 原共同整数毫秒，决定来源位置、暴露时长、场建立/消散、动作和后果 |
| 呈现帧 | 屏幕多久画一次；只能呈现已接受的世界状态，不能自行推进场或人物 |

用户最新明确来源中心只认所在格，取代此前100ms/半格连续空间切片候选。建议普通世界仍50ms一大步，步内按整数游戏毫秒的跨格/其他真实事件切段；没有单独的全图10Hz重算周期。渲染30/60/120FPS不改变同一轨迹下的场变化结果。

## 当前代码实际行为

- `GameClock._process` 接收引擎delta，乘1/2/4倍速加入时间累积；项目代码不主动截掉普通长delta，但这不证明引擎传入值等于所有系统挂起的真实时长。
- `data/definitions/local_actions.json` 规定普通时钟步50ms，即1倍速20步/游戏秒；每个渲染帧最多80个普通步。50ms不是新动态场刷新率，80步也不是硬毫秒预算。
- 原世界按事件边界细分；区域event_budget=4096限制一次推进调用的边界数，不是整帧CPU时间上限。主线程仍可能被单次昂贵调用阻塞。
- 世界先返回真正完成的时间，时钟才发布；部分或零进度保留原区间及帧债，后续帧继续，不用较大dt把未完成事件抹掉。[共同时间证据](../../qa/20261105_clock_world_commit.md)只证明其已测旧世界范围。
- 持续算不足时，时间债会增长，游戏世界落后于现实；负载恢复可能追赶。没有实用的长期积压上限/自动降速方案，不能说现在已处理好严重过载。
- 原身体沿已完成世界区间移动，但手动方向用最近一次采样，没有带世界时间戳的输入队列。极低帧率可能延迟/漏采按键，追赶时不能证明和流畅运行有相同轨迹。
- 新来源A1只有同步按需查询，packed场原型由调用者推进工作预算；尚未接动态来源、场目标周期、普通Main或统一插值。不存在已经运行的新场10Hz调度，也没有卡顿下真实尾迹通过证据。

## 建议的刷新策略

### 静止来源：无需反复全图重算

来源配置、位置和其他依赖未变时，距离场的基础目标复用缓存。实际场值按锚点与世界时间直接取建立/消散曲线；一次查询和多次查询结果一致。已经知道一段时间的目标时，可直接求段末，不逐毫秒或逐帧更新每个地块。

天气/tide、来源变化、碰撞/移动、作用方式切换和受体过程等真实边界仍须处理；不能把未知目标历史当作恒定目标跳过去。画面读取频率不是世界发生变化的频率。

### 移动来源：中心跨格才更新距离场

来源格从原模拟所有者的逻辑格状态与带游戏时刻的移动过程读取；不能对画面插值坐标调用 `world_to_cell` 来决定发源。对象最终落格或有确定中心格，格间动画只呈现移动。模拟何时将来源格从A切为B由共同移动合同规定；不在本包擅定起步/中途/抵达哪一时刻提交，也不让渲染帧决定。逻辑来源格、强度等未变时不重建距离场；来源开关/暴露、天气或其他源改变仍可构成边界。

50ms世界步内记录发生过的跨格时刻，并按时间顺序结算。例如23ms从A进入B、41ms进入C：该步分成A持续23ms、B持续18ms、C持续9ms。每次先用旧目标曲线求事件时刻实际场值，再变更源格、聚合新目标，沿同一实际值接续。只更新旧/新影响范围的相关块，源仍只有一个；不沿途注册常驻来源。

整数毫秒是时间精度，不是全图计算频率。原移动器已有1ms子步时，直接采用其已发生的整数跨格时刻；批量线性路段若算出小数边界，统一将绝对时刻向后量化到下一整数毫秒，再用相邻整数时间戳相减求持续时间，不逐段分别舍去小数导致长期丢时间。单边界延迟小于1ms。

不保留亚毫秒场状态。同毫秒多个跨格事件按稳定顺序更新来源，0ms停留的中间位置不产生持续建立；该时刻合成最终目标后进入下一正时长段。精确小于1ms的停留可能量化成0或1ms，这是已声明近似，不能一边保证每段严格舍弃、一边声称总时间完全守恒；极高速情况需验误差与边界数。

多来源同毫秒先结清此前正时长区间，再按既定max/冷热抵消合成下一段目标；不逐来源顺序重复推进时间。半格分段和每100ms定时截图不再是来源位置算法，快速穿多格仍须记录其中具有正整数时长的来源格。

当前2×1静物A1的偶数尺寸发源格向左上取整；它与按画面几何中点取右侧格的算法不同。最新要求是模拟中有明确中心/基准格，不要求从渲染几何中点重新反推；下一实施前统一原对象给出的逻辑发源格与多格占地约定，替代此前本方案直接按几何中点改为右/下格的建议。实际A1原约定见工程合同，代码尚未修改；不永久维护两套当前规则，也不把多格改成单格。

### 呈现：可少画帧，不能少算已接受的历史

角色和场显示尽可能共享已提交模拟快照的时间，必要时在两个已知状态间做视觉插值。不得显示人物已经走过而权威场仍无时长地停在过去；也不能通过插值制造未经计算的温度后果。

插值只能改善两帧之间的观感，无法让一秒只能呈现几帧的设备看起来始终流畅。物理场结果完整也不等于画面帧率达标，二者分别验收。

## 算不过来时的取舍

例如每50ms世界步包含该步真实跨格/环境事件，设备每真实秒只能完整完成10步：保持同等规则与精度时，最多完成约0.5秒游戏时间。处理能力不足无法同时保证原速度、原精度和原画面帧率。推荐整个相关世界放慢/短暂等待，保持人物、场、战斗和时钟一致，不让人物按现实速度跑、场在身后补账。

分两类处理：

1. **短暂尖峰。** 保留已经请求的逻辑区间，按有界工作量/现实时间片续算；暂时降低呈现流畅度或模拟推进速度。能追赶时有限追赶，不能在一帧无限补算而再次卡死。
2. **持续超载。** 通过背压限制新时间请求，自动撤去2x/4x等加速；必要时让世界整体低于1x并显示实际模拟速度/待算状态。达到安全阈值可暂停等待，保留已请求区间；不持续制造无限时间债，也不清掉旧债冒充完成。

尚未接纳为世界请求的墙钟时间，在受控慢动作期间不持续排成未来债务；已接纳的请求必须保留。需要把这个区别写入时钟接口，不能简单把 `_accumulator` clamp到较小值。阈值/恢复条件需防来回抖动，由真实压测决定，不让机器负载改变既有世界历史。

CPU调用的工作计数只是算法预算。应同时测现实耗时，把目标约2ms的可续算片分配到帧内；某些同步begin/分配/finish不天然受step预算限制，要单列并优化。GPU异步也只可发布匹配世界/来源版本的结果，不能用设备线程完成时刻当作世界时刻。

允许先降低调试叠层刷新、粒子和其他纯呈现成本。不能因低配随机跳过路线段、改场强、把移动间隔放大却不算途经过程，或让不同电脑长期采用不同逻辑采样精度来掩盖超载。

## 输入与因果

输入应采样后附到下一可接受的世界边界，正在结算区间使用已冻结的意图。不能追赶旧时间段时反复读取“现在按的方向”，把新输入追溯应用到旧区间。严重掉帧期间没有被操作系统/引擎采到的操作无法凭空还原，不能承诺完全相同的现实按键体验。

结果一致性验收使用同一按世界时间标记的输入/轨迹，比较不同渲染帧率、工作预算和暂停/续算；另做真实按键响应延迟测量。当前代码还未具备上述完整输入排队合同，实施须安排明确接缝，不默认为已有能力。

## 必须新增的验收

- 同一来源路线在30/60/120FPS、不同工作预算下，沿途及路旁场值在声明误差内一致；快跑跨格无逻辑空洞。
- 人为令服务只能每真实秒完成10个50ms世界步：世界时间、人物、场及受体推进一致；测出慢速，不能仍宣称1x完成。
- 同格亚格移动不重建几何场；50ms内多个跨格按各整数驻留时长接续；同毫秒/0ms停留及偶数多格中心边界明确，极高速时不累计舍时误差。
- 注入短暂停顿后有限追赶，检查所有段只结算一次；持续超载时新请求受控，已请求的债务/事件不丢失，队列不无限增长。
- 停顿期间输入变化不反写旧区间；取消、暂停、保存忙状态和恢复保留同一因果。
- 空闲世界/静止场不会每秒扫描全部来源10次；密集移动场分别测主线程p95/p99、总吞吐、内存及积压曲线。

本合同应在动态场接管前落实。A2a缓存阶段先证明可预算、可取消、可靠失效和实际耗时，不能声称仅缓存通过就完成此调度、输入或过载出口。
