# 环境首轮：真实来源与连续响应

本目录是第二阶段首轮的详细候选方案。当前授权、执行和停点只写 [HANDOFF](../../status/handoff.md)，本目录不建立第二条任务队列。依赖顺序见[基础优先级](../foundation-priorities.md)，固定概念遵循[环境规则](../../../design/rules/environment.md)。

**制定时快照，非当前状态。** 下面保留接管前的范围与方案来源；其中旧Q、根51、待接Main和“下一讨论”均只描述当时。普通Main后来已统一接管新场；当前接入只查[技术总表](../../status/technical-status.md)与[普通环境合同](../../engineering/world-environment-contract.md)。

针对连续响应首包实测热点的[来源候选与大档内存优化](optimization.md)独立列为基础性能小包；是否完成以[优化QA](../../qa/20261106_environment_optimization.md)和HANDOFF为准，不自动接管普通Main。

动态场接合前须遵守[时间、刷新与过载合同](scheduling.md)：区分游戏时间/渲染帧/计算耗时，移动区间不漏途经格，预算不足不跳历史，并补长期积压与输入边界策略。该合同仍是候选，不能当作现有20Hz普通时钟已经具备的新场能力。

## 本轮选定两个方向

| 方向 | 实现出口 | 顺序 |
|---|---|---|
| A：真实地面对象成为环境来源 | 原实物/材料堆按版本化定义形成来源，生成、移动、收起、落地、拆合和移除不会使原物与场脱节 | 先完成 |
| B：温度与五行连续变化 | 同一来源变化带动旧处散逸、新处建立；实际值、共同时间、预算、取消和重启一致 | 依赖A |

A、B组成一个受限的集成闭环，按用户最新要求拆成可验证小包：A1落实来源定义、原实物投影和局部基础目标查询；A2a落实[分块基础目标缓存](cache.md)，随后补[真实来源GPU计算](gpu-ground.md)。具体完成范围见[来源查询合同](../../engineering/environment-source-query-contract.md)、[缓存合同](../../engineering/environment-ground-cache-contract.md)和HANDOFF。下一讨论候选为[真实静止来源连续响应闭环](response-ground.md)：单个已存在实物取/放/移，接实际温度/五行与原物共同提交。材料拆合、动态携源与普通Main接管另排，不因本页列出完整闭环就自动连做。

**制定时交付边界：真实世界对象驱动的通用环境接入底座及开发验收入口。普通Main当时仍由旧Q模型负责实际冷热。** 当时开发观察是候选预览，不写第二份人体/植物后果；后来普通接管已将消费者、动作、内容和存档一起切换，不能继续按此旧起点规划接管任务。

选择这个边界是因为当前来源/温度原型尚缺原物三方事务和五行实际残留；若现在把Main切换也算进本轮，就会同时牵动照明、施工、身体、草木、历史收据和旧档转换，超出本轮两个基础项目。

## 制定时起点

- 第一阶段已经有原物、地面位置、材料拆合、共同耗时搬运和独立候选恢复，不再造一套实体库。
- `environment_field_cache.gd` 已有七通道基础目标场和来源候选；`environment_temperature_state.gd` 已有packed温度锚点与分片准备。它们不是普通世界的实际环境。
- `environment_source_change.gd` 能协调场和温度候选，但不拥有物品、材料、动作或时间，且现协调器仍只接受单个来源编辑。
- `object_lifecycle.gd` 在改变原物后才发 `committed`；耗时动作目前把非成功结果直接判失败。二者需要可预检、可续算接缝，监听提交后通知不能解决原子性。
- 五行通道目前只有基础目标，没有真实响应/残留owner；本轮必须明确补齐，不能用七通道缓存更新冒充五行渐变。
- 当前根档51/区域42，旧F2资料里的50/41是当时快照。实际切换规格实施前按当前版本核对，不照抄旧数字或恢复旧队列。

## 工作步骤与检查点

1. **保护起点。** 核对原四份环境WIP的差异和哈希，保存只读证据；以已提交代码与WIP差异分别判断可复用范围。若需纳入本轮，在HANDOFF登记具体文件和范围后逐段验证，不覆盖或把已有单源QA自动当批量WIP通过。
2. **落实来源定义及投影。** 接独特实物、真实材料堆和明确的多格点源几何；完成多类同能力定义复用和查询，不改世界时间。[来源合同](sources.md)给出字段与限界。
3. **接原物事务。** 从生命周期入口生成完整物件变更计划，准备来源差异，处理待算、复验、取消及同步发布。数量和位置失败不部分写入，不能在物品移动后才发现环境无法更新。
4. **补实际响应。** 复用原温度owner；新增五通道实际响应，先max后响应。源变化先结旧段再接新段，气候与微潮汐读取共同时间。[连续性合同](continuity.md)定义状态和算法。
5. **贯通可观察链。** 从普通Main会话捕获独立候选，在同一个RegionalSimulation和原生命周期中操作真实对象，开发面板显示来源/目标/实际值、准备进度及版本。这里展示的是候选，不修改活会话的旧Q、身体、物品或时钟。现成画面适配够用，不做独立编辑器产品。
6. **联合验收。** 规则、原子失败、预算、同刻事件、完全停开、密度与真实呈现按[验收](acceptance.md)执行。原生审查及最终回归由主代理统一安排，不在每个步骤重跑整套。
7. **停止与报告。** 报告接口、实际采用参数、受检代码、性能、失败与支持范围；完成A/B不代表普通Main接管，更不自动进入房间或GPU。

## 文件职责草图

名称可按代码复用调整，不要求机械新增下列所有文件。

| 位置 | 预期改动 | 原状态所有者 |
|---|---|---|
| `data/definitions/environment_sources.json`及内容包验证 | 新增版本化来源profiles和原定义绑定 | 内容定义，不持实例位置或数量 |
| `scripts/sim/environment_source_bindings.gd` | 新增纯投影和派生slot映射，能力缺失/不支持可区分 | 原物仍在artifacts，数量仍在inventory，位置仍在原owner |
| `scripts/sim/object_lifecycle.gd`、`object_actions.gd` | 扩准备/挂起/复验/联合提交接缝 | 原命令、动作、预约和回执 |
| `scripts/sim/environment_source_change.gd` | 扩原物计划及多来源差异的协调，不再只提交场/温度 | 只持短期准备，不成为物品或时间库 |
| `scripts/sim/environment_field_cache.gd` | 复用空间max与局部候选，验证相关WIP | 派生索引和基础目标 |
| `scripts/sim/environment_temperature_state.gd` | 复用唯一实际温度；测量现有大快照成本 | 温度锚点 |
| `scripts/sim/environment_element_state.gd` | 五通道packed实际响应，复用纯响应函数 | 五行环境锚点，不是灵气库存 |
| `scripts/runtime/`、`scripts/persistence/`、`tests/` | 候选开发观察、独立验证包、定向与基准 | 视图/文件适配不拥有原事实 |

## 本轮不扩展

房间拓扑/均温、墙窗传递、地形逐格发源、完整植物与生态、身体/携物向外辐射、物品蓄灵与相变、定向能量、风水利用、自由工艺和新任务均后置。已有地表五行亲和不冒充已注册的实物来源，也不被叠算两遍。

GPU服务已有合成来源测试；A2a真实来源CPU负载已暴露吞吐限制。候选小包以同真实负载核对CPU/GPU的端到端收益和失效安全，不新做玩家GPU开关，也不因此宣称实际响应已接入。
