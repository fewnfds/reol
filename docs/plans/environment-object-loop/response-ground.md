# 下一小包：真实静止来源的连续环境闭环

本页是下一包建议与验收规格，尚未实施。当前授权/停点只看[接续](../../status/handoff.md)；本轮只写方案。沿[环境规则](../../../design/rules/environment.md)及[连续响应合同](continuity.md)，不另定一套世界法则。

## 要得到什么

把已能计算的“此处应该受到多少影响”，接成“此处现在已经受到多少影响”。同一真实地面实物取起、放下、移位后，旧处逐渐恢复、新处逐渐建立，冷热与五行都沿共同游戏时间连续变化；退出重开仍接着原过程运行。

下一包只选两个紧密依赖的能力，组成一个可验闭环：

1. **实际环境响应。** 每格一份实际温度和五份实际五行影响，复用现有响应曲线与目标计算，不增加邻格传热、能量守恒或普通地块积分。
2. **原物与环境共同提交。** 原物位置、来源缓存和实际环境在同一个游戏时刻变更，不能先搬物品、之后靠通知补历史。

这是通用接口：选择至少两种实物定义、不同来源配置与静态材料堆共同验证；不存在某个具名宝物专用函数、任务、付费或NPC服务。

## 真实起点与本包范围

已完成：真实地面原物/材料堆投影、16×16基础目标缓存、可靠失效、可选CPU/GPU后端。GPU只加速基础目标；准确512²满密度测量约0.62秒，不意味着能每50ms重算全图。范围与数值见[计算QA](../../qa/20261105_environment_ground_compute.md)。

已有`environment_temperature_state.gd`及`environment_source_change.gd`可作为温度锚点/候选准备的基础，但已提交协调器只联合单来源场与温度，没有原物、动作或五行实际状态。四份保护WIP不能当已交付接口，计划使用HEAD既有能力并保持其字节不变；确需改动时先重新说明范围，不覆盖或偷偷纳入。

| 本包接通 | 暂缓 |
|---|---|
| 已存在、受控独特实物的同区域地面取起、放下、移位 | 新生成/销毁、多来源批量变更和材料拆并堆 |
| 其他真实实物/材料堆作为静止背景共同参与max | 人物携物整体中和、遮掩及沿途发源 |
| 开局来源初始化、天气/气候/微潮汐目标边界、实际响应/残留 | 新天气品种、复杂农务、生物受热或修行收益 |
| 直接权威命令与已有耗时动作的ready/pending/rejected | 新搬运寻路、输入系统重写、完整持续过载治理 |
| 原世界上的独立验收会话、响应存读及最小开发观察 | 普通Main替换旧Q、普通档迁入和房间均温 |

运行时一次只准备一个来源变更；单次旧/新覆盖区按实际块并集预检，沿现候选最多64块。半径≤16的两端常见上界约18块，不把这一估计代替真实检查。超限在写入原物之前明确拒绝。取起后本包只表示该物停止作为地面来源，持有期间不模拟携物辐射；地面移位命令是瞬时位置转移，不能宣称已经有行走尾迹。

## 环境值的逻辑

目标计算沿已定规则：五行逐通道max；热侧max与冷侧max相减，结合当地中性气候查温度映射。微潮汐沿已有环境端共同相位，不逐物tick。

实际值复用`environment_field_response.gd`的端点求值：保存旧实际值、游戏毫秒锚点、目标段、响应时间；在已知目标不变的一段内直接求时刻值。读取不重置锚点、不推进时间。响应速度用少量版本化参数，首版以阶跃试验确定，不作为固定世界法则。

例如原地20°C，放入来源使当地目标变成80°C：放下这一刻仍是20°C，随后升温；取走时保留已达到的温度，再向届时的背景或其他来源目标恢复。五行相同：来源离开后留下实际影响，残留不是新来源，反复取放不凭空增加强度。

同强冷热同位置抵消的是**目标等级**；该格过去的温度不会被强行清零。弱来源在最强者离开后接替，已有残留可以暂时高于当前目标，不能为满足“峰在物体处”而删除历史。

### 初始化与时段

- 验收会话有明确生效时刻。温度取该时刻可证明的原背景/已有权威读数；五行初始按已存在静态场建立完成配置，之后新放入的来源从原实际值建立。全部策略存入验收配置，不倒称世界过去已有新场历史。
- 初始来源覆盖与必要锚点装配完才发布可操作会话；未被来源影响的格可用明确背景规则，不因首次被看见才开始运转。新覆盖进入的格在真实事件边界建状态。
- 来源、天气/气候和潮汐各有目标边界，按同一整数游戏毫秒有序接续，不能用快进终点目标代替中间全部时段。
- 只提供已知时段及已提交世界时刻的实际查询；缺少过去历史返回unknown，不用现来源回算。保留有残留块；首版不做未经误差证明的残留删除。

## 最重要的接缝：改变物品前先准备

```text
原命令/到期动作到达游戏时刻 t
  → 预检原物、完整占地、预约和版本，形成只读变更计划
  → 在 t 结清旧目标段的实际值
  → 私有候选里算新来源目标、温度和五行锚点（可分帧）
  → 再核原条件全部有效
  → 一次提交原物、位置索引、来源缓存、响应、回执和动作结果
  → 最后发送现有 committed 通知
```

1. 现`Bindings.project`只读当前位置；增加从已预检的变更计划纯投影未来来源，不先改原物试算再回滚。
2. **仍只有一份地面派生场。** 在原GroundCache内准备/提交槽位分配、reference→slot映射、旧/新来源、代次和原owner epoch；不另建一个长期索引。取起撤源、放下预留slot、移位复用slot。候选只复制涉及的块/小计划；全世界克隆不进入每次动作路径。
3. 联合提交后不再由`objects_changed→_sync_reference`重复改来源。缓存失效通知仍供旧只读路径使用，联合路径有明确提交入口，旧GPU快照按代次作废；两者不能同时写同一候选。复验到提交之间不yield、不发外部回调、不再做可能业务失败的预检。
4. 同毫秒按原稳定事件顺序处理；0ms中间状态不重复加热。若上一动作通知取消后续动作，后者必须重新检查active/预约，不能按过期列表继续执行。
5. 验收会话中其他可能改变地面来源的写入口必须在写前接入或明确拒绝，不能提交后才发现不支持。普通容器转账及保持正数量的同类堆可在证明来源不变后放行；直接旁路epoch变化仍拒绝旧环境查询，不能悄悄补算不存在的历史。

## 共同时间、待算和取消

预算耗尽返回pending，原耗时动作仍active并保留预约、控制权、原due_ms；不当作失败，不把GPU完成的现实时间当作事件时间。直接命令同样可返回句柄，调用者续算或取消，重试command不重扣/重复发物。

当前世界推进器先移至事件时刻并依次执行各域，本包必须为**一个未完成事件边界**保存阶段/动作游标，续算只恢复尚未完成的阶段，不能重跑之前已执行的移动、交易或天气。新世界请求可保留target债务，但不得执行之后事件或向公共时钟/视图发布半边界状态。挂起期间沿最后完整呈现快照显示，其他命令/保存/消费环境事实的入口受边界状态约束；只冻结时钟数字而仍让外部读半成品不算通过。验证直接命令和到期动作两条入口；若不能安全挂起，就不能声称本包闭环通过。

GroundCache当前要求world无欠算且区域同刻；到期动作可能处于target>elapsed。增加仅供协调器使用的受控事件上下文：明确原world/绑定、事件t、已完成阶段和相关区域同步证据。不直接删除现有backlog检查，不允许任意调用者用未来时间访问缓存。

取消销毁私有准备，保留已发生的旧世界时间/成本，释放原预约且不写成功回执；原物不移动、来源不切换，实际场从原锚点继续投影。若此前边界某些阶段已执行，则沿游标收尾，不能将它们回滚或再执行一次。外部新输入不得追溯应用到准备中的旧区间。

## 文件职责与落地顺序

| 顺序 | 工作 | 复用及改动位置 |
|---|---|---|
| 1 | 原物只读预检计划；列出联合模式全部来源写入口；准备状态/句柄与事件边界续算 | `object_lifecycle.gd`、`object_actions.gd`、`regional_simulation.gd`；不重排其他同刻领域 |
| 2 | 单来源旧/新目标候选与ground槽位/映射共同提交，失败/取消不写活事实 | `environment_ground_cache.gd`、`environment_source_bindings.gd`、现`environment_source_change.gd`；复用HEAD单源场能力 |
| 3 | 原温度owner与五通道实际owner接目标时段，处理背景/潮汐/残留 | 现temperature状态/segments/response；新增五通道响应状态，名称实施时按复用定，不建全量通用ECS |
| 4 | 原世界+配置+响应联合存读，最小观察面板显示目标/实际及pending | 原会话候选和runtime/persistence接缝；不向身体或植物写第二份后果 |
| 5 | 因果、失败、完整停开、硬件/规模验证，记录误差、审查和回归 | 定向测试、受控基准及QA；完成后停止报告 |

这些是同一包的依赖步骤，不是五个自动连续授权的独立阶段。若事件边界重构实测超出本包安全范围，先在这一接缝停止报告具体阻碍，不能跳过它去做另一种演示。

## 存读与观察

只保存不可重建的实际温度/五行锚点、目标段与规则版本，并与原世界、共同时间、原动作/回执及来源配置digest一起校验。来源、GPU缓冲和max缓存由原物重建，不保存第二份实物位置/数量。

先做明确标记的开发验收快照，使用同一个原RegionalSimulation和原动作域；普通存档schema/Main接管另排，不把它变成第二套玩家存档或长期可玩模式。独立候选全部校验后才能替换验收会话；当前格式坏引用/错时刻/错digest都拒绝且不改原文件或活会话。进行中正常动作可存读；跨帧准备/半事件边界尚未持久化时明确busy，已有文件与备份不受影响，完成或取消后恢复可存。

观察入口只复用最小诊断：同一地图显示物品位置、冷热/五行目标与实际、世界时刻、pending阶段；选任意受控实物配置取放/移位即可观察，不做新任务UI。以实际运行、日志和截图证明可见结果；诊断全知不写入玩家所知。

## 验收与性能

| 验收 | 通过条件 |
|---|---|
| 多定义、多半径、五行和冷热、强弱/对立来源 | 地图真实原物驱动；放入渐建、取走渐散、强源移走弱源接替，逐通道符合参考 |
| 同一事件在10秒/1秒/小时间片推进 | 相同已发生事件与时刻下结果在声明数值误差内一致；反复查询不影响结果 |
| 快速A→B→A、同毫秒取放、未观察地点 | 不漏有正时长的区间，不复制来源，不因观察才初始化历史 |
| 极小工作预算/人工长等待、到期动作及同刻取消 | pending不判失败；未执行后续事件，已执行阶段不重复，原due_ms和已请求时间不丢失 |
| 目的格被占/原物变化/旧proof/owner恢复 | 原物、来源、温度、五行、账本与回执不出现部分提交 |
| 进行中动作、残留、完全退出重启 | 同一未来对照一致；缺源仍可保有合法残留；坏档及准备中保存按合同拒绝 |
| 真实画面 | 同一物品操作带动目标立即切换、实际值连续；诊断无半状态/假尾迹 |

复用现有双精度响应端点，不新写积分器。CPU/GPU基础目标继续要求整数一致；响应采用明确绝对/相对误差，常规温度对照目标≤0.001°C，五行≤一个既有定点最小单位，极端大数单列相对误差。阈值附近另测，不靠界面舍入掩盖差异；参数与误差实际采用值随QA记录。

沿[16GB整机/单3060性能基线](../../engineering/architecture.md#全项目性能基线)。64²/128²/512²静态真实背景，分别测初始化/存读、一个在途来源动作及连续1/8/32次单来源变更（不冒充批量事务或大量移动源）。测实际覆盖块、来源候选计算、结旧段、温度/五行准备、同步提交/释放、主线程p95/p99/max、总延迟、工作集及锚点增长。推进约2ms为续算目标，预检/提交等同步尖峰另报；不设新几百MB模块门槛。

不每帧重建全图，不因微潮汐重算静态几何，不逐源逐毫秒tick。**本包联合候选先沿CPU确定正确性，现GPU仅继续承担已验基础目标任务；不宣称GPU已加速原子候选或实际响应。** 仅当实测候选热点阻碍声明负载，再报告是否值得单独接GPU，不能在本包顺带重做显卡服务。

主代理统一运行doctor、定向及可见验证，一次原生审查和准确SHA一次完整回归；测试等待沿项目工作流，不让模型定时扫描进度/数PASS，不派等待代理。CI仅提交检查点查看。

## 完成与停止点

交付一个可复用、可观察、可保存的真实静止来源连续响应接缝，证据包含原物、时间、旧/新处残留和失败一致性。到此停止报告。此包不宣称普通游戏新环境已上线，更不连做房间、移动携物、生态、战斗或修行内容。下一方向再讨论普通接管/多来源变动与移动来源的先后。
