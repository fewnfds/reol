# 温度与五行连续响应合同

这是[环境首轮](README.md)方向B的候选实现；依赖[来源事务](sources.md)。它复用现有核，重点补原物接入、五行实际状态及共同提交，不重新开发一套数学模拟器。

## 数据由谁拥有

| 状态 | 所有者 | 保存方式 |
|---|---|---|
| 原物身份/开关/可花灵气 | 原器物域；数量在原inventory | 沿原普通会话/世界快照 |
| 原位置/占地/容器 | 原位置owner | 不在环境档另存第二份权威位置 |
| 来源slot及空间max | 派生bindings/cache | 可按绑定版本和原物重建，恢复须交叉校验 |
| 实际温度 | 原温度状态owner | 必要格的值/时间/已知目标段 |
| 实际五行影响 | 新五通道packed响应owner | 各通道必要锚点和目标段；不是可领取的资源 |
| 世界时间/积压 | 原共同推进器 | 不创建Timer或新的独立时钟 |
| 开发观察与GPU/CPU工作 | 只读投影/私有候选 | 不作权威事实保存 |

原物定义采用五行五通道及单一有符号冷热等级。现有缓存的七通道可以暂作五行＋热侧最大值＋冷侧最大值的派生布局，两个极值只为正确合成来源，不重新暴露成原物两项冷热属性。持久实际环境为五行五通道及一份温度，不能再保存可各自变化的“热温度”和“冷温度”。旧Q未接管时，仅候选验收世界使用这些新owner，活Main不混用两套读数。

## 从目标到实际值

五行：先逐通道取当前来源最大值D，再乘环境端共同潮汐得到目标G。每格每通道只有一个实际值y，向G趋近。旧残留不增加来源列表，也不与新目标相加。

冷热：先取有效热最大值H和冷最大值C，按 `q=H-C` 抵消，乘潮汐，再结合当地中性气候查温度目标表；唯一实际温度向该目标响应。不把各源摄氏温度平均，不先把每个冷热源分别延迟再抵消。

一个常目标时段采用一阶响应：

`actual(t)=target+(actual_at_anchor-target)×exp(-(t-anchor)/tau)`

首版使用已有 `environment_field_response.gd` 的仅端点路径（关闭integral）；必要时预计算exp曲线并插值，只有测出收益且误差合格再换实现。普通地块不累计温度积分，不做邻格能量搬运。温度与五行可共用纯响应函数，但各自只保一份实际状态。

tau为版本化的少量环境预设，不逐物tick、不为每次查询重置锚点；最终具体秒数由阶跃试验确定。不同外部帧率、推进切分和查询次数不应改变实际过程。实现需覆盖0.1°C阈值附近，输出与重启对照用确定的误差合同，不能用四舍五入隐藏不同结果。

## 开局、移动与残留

新开局用已接受的共同起点：温度来自当地原背景；五行按本轮开局配置明确选择初始目标已建立的静态场。此选择只适用于新建验收世界，不重置已有历史。运行后首次放入来源才从当地既有实际值开始形成。

从已有普通Main会话生成开发候选时，以捕获时刻为新环境预览的生效点：温度起值必须取原环境权威可验证的该时刻读数，五行预览初值按包内明确的初始化策略记录。候选不把它说成该世界过去已经运行的新五行历史，也不替代正式旧档迁入；旧Q只作为只读初始化/既有行为的证据，不向新响应反复注入初值。捕获失败、时钟欠算或原读数不可证明时拒绝生成预览。

来源变动在事件时刻先求旧段实际值，再为旧/新覆盖区生成新目标、沿同一个实际值接续。若一个格从未单独跟踪，也必须证明其在开局到当前之间的目标历史，或在第一次来源影响它时就建立锚点；不能第一次查看时直接给0或当前目标。进入来源覆盖的格在真实事件边界按预算建状态，不等玩家看见才开始运转。

最强来源移走后，旧格可能转向较弱来源目标，也可能转向零五行影响/气候中性。反复A→B→A不会不断添加残留。只要目标非负且普通倍率不超过1，实际五行值不超过该格历史目标与合法初值的最大值；可以暂时高于当前目标，这是旧影响，不应强行clamp清掉。单源的空间目标峰在其发源点，历史实际环境不要求永远以当前物件处为唯一最高格。

首轮不以单帧极小值直接回收残留。若要回收，需明确ε、零目标持续条件、已结算受体边界及未来最大读数误差，证明后才能归零；否则保留锚点并测其内存增长。不得以“稀疏”承诺必然小内存，满图影响时会有满图实际状态。

## 真实搬运与运动来源

当前 `object_actions.gd` 的schedule只是原位置等待、截止时一次转移，期间还要求人物位置不变；它不是实际寻路搬运。A1只接地面来源，不读取携物。本节是后续必须具备的连续性合同，不能据现有“move”或耗时字段宣称沿途环境已运行。

真实搬运分取起、实际行走、放下：物品仍是原物，携带位置读取原承载者当时的真实位置/已发生轨迹，不另造物品坐标或按A/B直线插值虚构穿墙路径。临时容器或手持只是原归属；是否遮蔽、以何强度对外暴露，仍属未定的携物整体规则。本节先讨论给定对外暴露强度的移动源，不默认包里每件物品独立发场。

移动时热源只有一个，位置是共同时间的函数。每个沿途格先按那一时段所有真实动/静态来源得到热侧max和冷侧max，抵消后映射目标温度，再让原实际温度向目标响应。五行同样先合成后响应；不能把同一个移动源的旧采样位置同时留在来源列表，也不能把同一源不同时间的强度求和。

尾迹是沿途地块已升高/降低的实际温度（或五行实际残留）。源离开后地块向届时的新目标回归，强弱源接替、气候和其他来源仍参与。同强度、同路线、同初始环境及其他条件下，较慢经过通常带来更长暴露、更多升温；快速经过影响较小。源自身的温度和地块温度分开，新处地块不会因为源到达就瞬间变成源温。

计算候选是按真实轨迹段及其起止毫秒处理：空间位移过大、转弯、停步、暴露状态改变或达到选定的模拟时长时分段。每段处理轨迹扫过范围再加影响半径，包含路旁格，而不是只处理中心踩过的格。即使高速在一次外部帧里跨越多格，也必须计入中间的短时暴露；只有已发生的真实瞬移才只处理两端。响应快、来源强的情形可能需要更细分段，不能假定高速影响永远可忽略。

首版对段内目标做有界取样/分段近似，段长及误差用更细步参考测定，不声称对连续移动目标数学精确。复用已有端点响应，无需开启累计积分或对每格每毫秒tick。静止段跳到下一真实边界；运动段只访问扫掠的相关块，多来源同刻先聚合再响应，不能逐来源顺序“加热一次”。

移动期间的路线改变、停留、中断、丢下/再拾起均在真实时刻闭合旧段。快进、离场和不同渲染帧率保留同一轨迹与暴露时长；CPU预算不足保留未结算段和欠算，不能先发布未来再漏掉途中热过程。在途保存要保留原运动/携带关系及必要未结算边界，不永久保存每帧历史。

A2a只缓存某一时刻的基础目标，可以合并等待重算的失效通知；它不拥有温度历史。后续接实际响应时，不能只读取合并后的最终目标来倒推中途暴露，须逐段先结算旧目标再接新目标。这也是实际响应与原物运动提交联合验收的前置。

## 潮汐与气候边界

沿现有候选使用环境端98%–100%缓慢波动，默认10个游戏分钟、64格粗相位；幅度/周期是开发参数。五行基础max不因微波动重建；冷热净等级为0仍保持0。波动调等级，不直接给摄氏温度乘倍率，也不消耗物品灵气。

调度沿共同时间处理来源、气候、天气及目标分段边界。现温度段原型有全局时间格点持值，需测量其相对连续波形的等级误差与温度映射后的误差；不自动为每个格每秒调度一次。稳定时缓存基础目标、共享相位/规则，批量处理真正到期段；不能只拿快进终点当整个过程中环境。

五行通道在同一位置共用潮汐相位；冷热和五行响应锚点在同一物件事件时刻提交。查询不回写，非法未来/缺少目标历史返回unknown/pending，不借当前来源倒算过去。

## 预算与保存恢复

复用16×16块和packed数组，只有受影响及有残留的格持必要状态。候选按块复制写入，整个准备完成才发布；同步begin/finish/释放、root复制及kernel初始化也要测量，不用step计数掩盖帧尖峰。

验收包保存：格式/规则版本、来源配置digest、原会话快照和共同时间、温度锚点、五行锚点、已发生原物动作/回执。索引、max缓存、潮汐相位及GPU缓冲由校验后的原物重建，不把缓存当真实来源存第二遍。

读入先独立校验原会话，再绑定来源定义，恢复响应并核对位置/时间/引用/数值范围，全部成功后才发布候选。损坏输入不改活Main、原档或原对象。来源在消失后留下的合法残留不能要求当下仍有源才允许保存。

进行中的正常耗时动作要保存并恢复；CPU准备或世界欠算尚未能完整持久化时返回busy，保留现有文件及备份，继续推进后允许保存。不能只存一半环境候选并把它算成已提交。
