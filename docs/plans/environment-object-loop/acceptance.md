# 本轮验收、性能及停止条件

本页只列[环境首轮](README.md)应证明的出口，实际结果另写QA。原fixture及四份保护WIP不会被测试或文档重写。

## 功能矩阵

| 场景 | 必须得到的结果 |
|---|---|
| 同profile的两个普通定义 | 只改定义绑定即可复用，不增加按物品名分支 |
| 一件1×1和一件2×1实物 | 原物各只有一个身份/来源，发源点近似明确，覆盖和源中心不混淆 |
| 同一材料堆1/4/16/10000份 | 堆强度相同，真实数量仍守恒；最后一份移走才消失 |
| 拆堆、合堆、异物掉落 | 两端来源共同更新；异类不混，合法平铺，预约/保管不绕过 |
| 单热源、单冷源、等强冷热 | 目标按等级计算，对冲回中性；实际温度连续，冷端不低于绝对零 |
| 五行单源移动，旧新范围重叠 | 同格只处理一次；旧处逐渐散、新处逐渐建，不叠残留 |
| 强源旁有弱源，移走强源 | 旧处转向实际弱源目标，不能直接把缓存减成错误值 |
| 反复往返移动/收起放下 | 身份/数量唯一，实际值不超过合法历史包络，无刷峰值或重抽潮汐 |
| 来源改变后取消或目标被占 | 原物/位置/数量/环境均无半提交，原费用和已耗时间按原合同保留 |
| 不同预算、外部切分、快进 | 同一事件序列到同一时间的结果一致或在事先声明误差内；不丢积压 |
| 同截止动作、通知回调取消下一动作 | 顺序确定，已取消动作不能继续结算或形成场 |
| 创建/改变后从未观察该处 | 环境仍沿真实时间发展，首次查询不从零冷启动 |
| 在途及有残留时完全退出 | 两独立进程沿真实原物候选恢复，继续到相同未来；坏包不改活世界 |

## 可观察交付

开发入口从真实普通会话捕获独立候选，不克隆一份会回写到玩家身体/库存的影子世界。显示原引用、物件位置与堆数、基础目标/实际温度、五行目标/实际值、事件时刻、待算进度、作用范围和被影响块数。明确标“候选环境预览”，玩家普通属性观察不展示开发全知。

验收操作沿原生命周期生成/搬运/拆合/移除；几种输入用于验证接口复用，不新增任务、奖励或具名器物剧情。记录同一对象移动前、刚移动、响应途中、稳定后及重开后的画面和日志。仅有平面数学热图或合成索引成功不算原物集成完成。

## 联合性能负载

目标16GB整机RAM、单张中低端独显；本机3060和5060Ti分别记录实际所用设备，不相加。CPU先作为正确基线。本轮不需GPU计算验收，但正常画面必须实际测帧时。

| 负载 | 数据和变化 |
|---|---|
| 递增静态来源 | 无障碍受控开局测64²/128²/256²/512²，每格一个真实物品或材料堆；来源来自原定义与投影，不只在索引塞引用。普通Main会话另测合法格满载，原地形/结构占格单列，不为填数覆盖原物 |
| 通道与半径 | 五行混合＋有限冷热能力，半径2/4/8/16的均匀和混合分布；零通道也核对不误发源 |
| 真实变化 | 静止、一次移动、1/16/64件连续操作；1%对象变化作为吞吐探测，逐事务保原子性，记录耗时和积压，不要求一帧做完 |
| 来源最坏比较 | 强源移除露出弱源、不同强度/半径、长容器历史及多种响应锚点；声明实际数量，不伪造地面混堆 |
| 时间与残留 | 有限长时推进、离场/返回、密集锚点、移动后无源残留；稳态不能每帧扫描全部来源 |
| 存读 | 原物＋场＋实际状态联合捕获、序列化/读回/验证、重建索引及候选峰值；完整停开场景与满密度候选容量分别记录 |

每次记录完整代码SHA/工作区差异、源配置digest、seed、硬件、Godot、守卫、开始可用内存/低点、进程工作集/私有峰值，初始化/prepare/step/finish/commit/释放及查询p50/p95/p99/最大。来源半径和变化比例不可漏记。无渲染的吞吐不当FPS；真实物品规模不当NPC规模。

原物生成、来源装配、全图首次建立与局部移动分别计时；全图预热允许加载阶段分批完成后发布，不能隐藏在一帧或把它删出总成本。单帧模拟初步预算2ms，超出时应继续准备并保留世界欠算；这个目标需由实测校准，不等于所有半径/负载已经满足。

真实呈现按当前阶段口径预热后至少1800帧，p95≤16.7ms/p99≤33.3ms，单列世界暂停/推进及操作频率。联合负载若无法达到，记录热点、守卫和可声明规模，不能仅把密度缩小或只展示无操作平均帧率来通过。

不并发压力测试。主代理根据运行前可用RAM选择有限超时和内存上限，为系统留余量；达守卫安全停止，保留失败输出。已有26万物品单独通过不证明新增五行响应及密集目标都能在同样内存内运行。

## 验证与提交顺序

1. 实施前doctor；解析及纯schema/投影定向先行，随后原物事务/共同时间/失败隔离测试。
2. 连续性核对整段/分片、阈值与确定误差、在途和两独立进程；画面及性能由主代理统一顺序运行。
3. 一个工作包一个主要审查者；代码阶段commit后一次Sol/custom原生只读审查，窄修另步，不递归审查或让代理等CI。
4. 最终行为用一次适当的完整check或对应准确SHA CI，不默认双跑。只在准备真实提交时集中核前推送CI一次，未完留下一次，不轮询。
5. 更新status/QA和实际接口；不得把方案、旧原型QA或预定测试数量当本轮已经实现。

## 到这里停止

当两个方向的真实原物闭环、五行及温度连续性、失败/预算合同、独立重启和声明负载均有证据时，本轮完成并报告。仍明确Main未切换。若任何出口未通过，报告实际缺口并停在真实状态，不顺手扩房间、GPU、工艺或单物玩法。
