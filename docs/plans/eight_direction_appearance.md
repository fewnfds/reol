# 真八方向人物与模块外观方案

2026-11-03，用户插入的架构审查方案。**A1八方向技术样本已接通，完整动作与正式美术仍待完成。** 当前人物/NPC/V页使用原创代码生成的八方向分层像素占位；正式美术后置，不要求用户继续批量生成复杂资源。当前功能/验证仅见[FEATURES](../FEATURES.md)/[BASELINE](../BASELINE.md)。来源、版本与许可见[调研](../../design/research/eight_direction_sources.md)。

A1技术样本按[首包规格](eight_direction_sample.md)/[QA](../qa/20261103_eight_direction_sample.md)接通，本轮九张PNG改为原生96网格硬像素、有限明暗与二值alpha，manifest/原点/方向/解剖锚点不变；Player、Pawn、V实际绘制节点已用局部nearest。运行仅有`idle / walk / gesture`，行走固定900ms世界时间周期、未按路程锁脚；基础长袍仍作占位。当前旧示意投影不是严格55°美术镜头；九层解码101.25MiB与原48视图约1ms人物CPU目标未达的限制保留，不能把像素替换当规模优化。本文后续目标不都已实现；[外部提示词](../art/character_generation/README.md)保留供未来使用，暂不继续制作。

目标：一个角色沿任意路线平顺移动，停步不乱转；左手持剑始终属于左手，右腰玉佩始终属于右腰，换向时有正确的透视与遮挡。人物、衣服、头发、手持物和挂件共享同一身体动作与相位；外观继续是原实物用途，不另建一套装备真值。

## 1. 历史起点、当前接线与边界

- **本方案提出时、A1前的起点**：`scripts/entities/pawn_visuals.gd::draw_actor`只画同一正面矢量轮廓、衣色与蓑衣，没有方向帧或骨架。此句是历史记录，不能再用作当前功能说明。
- **当前接线**：`Player`、`Pawn`和V页仍复用`PawnVisuals`，其主体已调用`HumanoidAppearance`采样/绘制八方向九层图集；原矢量只作缺资源回退。`HumanoidPose`只读原身体/路线/支持的短过程，V转向和剑佩预览不改真实状态。
- 连续身体位置归`SimLocalMotion`/原actor，路线归`SimRouteTravel`，不因添加动画改回格子位移或让动画节点移动真实身体。
- `SimClothing`拥有唯一衣物与实际穿法。未来佩剑/佩饰须引用原物件和其用途；画面附着点不意味着物件已被合法取得或已经装备。
- 本方案只规定呈现合同与生产路线，不把下一包直接扩成完整种族骨骼、战斗、服装产业或物理布料。

## 2. 采用的路线

运行时保持Godot原生2D：**八方向分层图集＋统一采样器＋逐动作附着点/遮挡表**。当前已有可替换的代码像素技术样本，后续仍沿同一合同扩展；不为此安装动画插件或改变已定相机。

美术生产可二选一，导出同一合同：直接画八方向分层序列，或在离线3D模型/骨架里做左右不对称外观，再按固定相机烘焙成八方向2D图层。后一条能复用动作并自然产生各向透视，但还须整理分层、透明边缘、遮挡与小尺寸可读性；不是换成运行时3D，也不承诺工具会自动补出合格美术。

Godot原生`AnimationPlayer`适合编辑动作与工具预览；`AnimationTree`适合状态过渡。逐帧方向切换使用`BlendSpace2D`的`DISCRETE_CARRY`思路，保留相位；正式分层采样由一个播放器统一驱动。不能给十件衣服各放一个自由运行的播放器，指望它们长期同步。Godot4.7新增`sync_mode`，不要照旧教程只写`sync=true`。

## 3. 方向与左右的合同

方向固定为`N, NE, E, SE, S, SW, W, NW`，与本项目屏幕/地图坐标约定显式对应。八个方向都是可寻址内容，不能只存四个方向或五个方向后全身自动镜像。

附着点用身体解剖位置命名：`left_hand`、`right_hand`、`left_waist`、`right_waist`、`back`、`head`。它们不等于屏幕左/右。一个右腰玉佩转到背面或远侧时可以被遮住，但不能跳到左腰；左手剑向东、西时可能位于不同屏幕侧，也不能因此交换持有手。

每个适配动作/体型/方向至少提供：

| 内容 | 用途 |
|---|---|
| 帧矩形、脚底原点与绘制偏移 | 裁图不会导致身体或脚底跳动 |
| 标准相位与每帧时长 | 衣物与身体对齐，长短不同的片段也能映射同一相位 |
| 各解剖附着点的位置、角度、可见性 | 手中与腰间物件跟随真实动作 |
| 层序/深度组与必要的局部遮挡 | 远臂、近臂、剑、衣袖、腰饰正确互挡 |
| 明确的方向/动作覆盖与适配体型 | 导入时发现缺图，不在游玩中偷偷镜像 |

完全对称的小部件可以由生产工具显式声明复用并生成结果；不能据此默认整个人体或非对称衣饰可以翻转。发布内容缺少一个必须方向或动作就验收失败。开发中的缺图可显示明确的占位外观，但不把它算正式八方向资产。

## 4. 遮挡不能只靠固定装备层

一张“武器永远盖在身体上”的表不能满足挥剑和转身。采用每个方向的默认层序，加每个动作/关键相位的覆盖：远侧手/袖→躯干/下衣→腰部远侧物→近侧手/物等。实际顺序由样本画面核定，不把这条示意写成宇宙固定规则。

遇到剑身一部分在前、一部分在后的情况，整件物品只有一个`z_index`不够。源素材可以分为前/后片段，或输出与身体同步的遮挡掩码；二者都仍引用同一物件。长披风、剑鞘、腰佩也允许按需要分片。先用最少分片解决样本，不先做通用每像素3D深度系统。

角色整体与墙、树、别人之间的排序，以原地面脚点/高度层为基础。角色内部的分层是另一层排序，不能让一只手的局部z值越过整栋前景建筑。选择圈与地面阴影独立于身体抬高和衣物层；姓名与交互命中区域继续走原视图布局。

## 5. 流畅来自共同运动、正确相位与适当帧数

1. **位置**读取原连续身体，视图做插值；碰撞、路程、消耗仍由原模拟结算。不能把每个tile到达当成一次瞬移。
2. **行走方向**由实际位移/速度求得；受阻时不能一直原地跑。停止后保留上次有效朝向。
3. **面对方向**与移动方向分开。普通行走面朝前进方向；交谈面向对象；攻击可锁定招式方向；后退/侧移需要对应内容，不能直接套正向走路。
4. **转向防抖**在八个扇区边界使用小角度滞回，低速时保留朝向。参数放定义中，先以约5°滞回、短视觉过渡作为试玩起点；不延迟真实命中和输入响应。
5. **步态相位**优先与实际累计路程/步幅连接，速度改变时自然改变步频；换方向/换衣保留相位，不能每次重置第0帧。闲置呼吸与具体动作使用原共同时间和动作开始时刻。
6. **片段采样**按统一归一化相位取身体、衣服和挂件的各自帧，不要求所有层具有完全相同的帧数；附着点/遮挡与同一相位一致。
7. **像素与平滑**先在原生尺度比较清晰逐帧与非像素插值。可以平滑位置/附着变换，不能通过两张不同朝向身体半透明叠加来假装出现新透视。

首样本可用待机8帧、行走16帧、生活动作16帧、短动作24帧作为内容预算。必要时提高到24/32帧或增加过渡，但先检查脚滑、相位和枢轴。帧数本身不能保证流畅；高帧率屏幕也不要求每件外观每秒重绘60张新图。

## 6. 真实时间与可卸载视图

模拟只拥有行为需要的最小朝向/动作事实：原身体的面对方向、动作ID/开始时刻/阶段、必要的步态基准。呈现从这些事实与原穿法生成只读投影；不用每个NPC保存一棵AnimationTree。

远区不运行人物节点、骨架或逐帧动画。若朝向影响攻击/感知，它属于原动作规则；仅转头呼吸等装饰不消耗模拟时间，也不生成社会事件。再进入时按当前动作时刻、原路线进度和稳定步态基准重建视图，不能统一从待机第0帧冷启动，也不能为接续重演已发生的命中/脚步业务效果。

保存时引用原动作与原物品，并记录确需持续的朝向/相位基准；图集缓存、当前Sprite节点、纹理和预览播放器不进世界存档。旧档显式给出确定默认朝向，不随机补过去的动画经历。仅视图滞回等短暂状态可重建，但同一行动的方向/左右不能重开改变。

战斗命中、治疗完成、生产产物一律由原模拟时间提交；动画Call Method轨只能播放声光反馈，不能成为第二个规则执行器。暂停/倍速/主动快进都用共同世界时间，不擅用现实墙钟或另改`Engine.time_scale`。

## 7. 文件职责（当前骨架与后续内容）

| 位置 | 职责 |
|---|---|
| `data/definitions/humanoid_appearance.json`，后续可按家族扩展 | 体型、动作、八方向、锚点、相位、遮挡、合法内容引用 |
| `assets/characters/<family>/` | 经许可/自制的图集、必要遮罩和来源清单 |
| `tools/`的离线导出/校验工具 | 方向完整性、脚点、图集坐标、缺层、素材许可证；不放运行玩法 |
| `scripts/entities/humanoid_appearance.gd`与`pawn_visuals.gd` | 采样、排序、挂件与缓存；玩家/NPC/纸娃娃共用 |
| `scripts/runtime/humanoid_pose.gd`与原运行适配 | 把原位置、动作、穿法和有限可见性送给视图 |
| 原`sim/`身体/动作领域 | 仅在玩法必要时持有面对方向与稳定阶段；不保存美术节点 |

不把每种衣物变成一套完整人物脚本，不扩大`RegionalSimulation`使其知道具体sprite帧。原物件、身体、动画定义和可见投影各有一个所有者。

## 8. 数量、纹理与绘制预算

八方向模块动画的主要成本是**素材组合和驻留纹理**，不是八个朝向变量。按未压缩RGBA估算：128×128像素、16帧、8方向，一层单一行走片段约8MiB；10层就约80MiB，尚未计待机/动作/其他衣服。不能为所有NPC身份复制一份纹理，也不能把每套外观组合全部预生成。

当前首包共享身体/动作与调色，但九张3840×768图集仍全幅缓存，解码RGBA合计101.25MiB；紧裁小挂件、家族/片段按需加载和淘汰仍是后续建议，没有因像素颜色变少而完成。图集保留稳定脚点偏移，不能为了裁小图而抖动。材质与图集尽量共享，实际批处理以Godot profiler为准。

初始工程目标而非已验性能：48名附近人形、主角约12个可见绘制片段、普通人约6–10片段；角色纹理驻留先控制在128MiB级，首单人家庭样本应更少；2D人物部分目标CPU约1ms、GPU约2ms，最终仍须同机与全场景实测。48×10是480个绘制片段，不等于480个GPU draw call；阴影、名字、遮罩、材质切换会改变实际结果，不能靠纸算宣布过关。

原A1同机48视图测量的人物绘制脚本CPU约2.477ms中位数，未达到约1ms初始目标，且未测独立GPU时序，详见QA。本轮像素替换保留九层，未重新测该规模，不覆盖或升级原性能结论。

远处可降动作采样频率/隐藏极小挂件，常见固定着装可离线合并主体；关键不对称轮廓和持有手不能因LOD改变。图集/合成缓存有上限和释放策略；不在每帧CPU重新拼整张人物图片，不为每个NPC开独立SubViewport。

## 9. A1范围与尚需继续的验收

范围：一套人形基础，八方向待机/行走/停步/短动作；两种常服、一层蓑衣、明确左手剑与右腰玉佩。全部可以先用代码生成的方向一致占位素材验证技术，再替换为通过美术验收的资源。技术样本不能冒充正式动画完成。

A1已交付的有限技术样本和本轮像素实机画面见QA；下列条目继续作为合同目标，尤其步幅锁脚、全部动作、严格镜头和规模预算不能从已有站姿/三动作推定完成。剑玉只属预览；未穿身衣的基础长袍也是占位，不得据画面反造衣物实例。

顺序：先锁定相机/脚点/像素尺寸→建立动作/方向/锚点合同与校验→玩家/NPC共用播放器→接原穿法和连续路程→验证遮挡、暂停/倍速/重启→测48人视图→再扩更多生活动作和外观。

验收必须包含：

- 同一非对称角色按八方向绕行，四个斜向也有独立内容；任何方向不自动交换左右手/左右腰。
- 以8方向×至少关键4相位的接触表检查左手剑/右腰玉佩；面北/面南、斜向挥剑、蓑衣覆盖、剑刃跨躯干各有正确遮挡。
- 任意方向急停/再走、扇区边界轻微摇杆输入、转弯、受阻、低帧率，脚底不跳、步态不复位、不持续抖方向。
- 进行中换衣/取放仍走原实际动作；图像变化只在原状态提交后出现，不凭外观授物或权限。
- 玩家和NPC相同外观合同；V页预览同一真实穿法，预览转向不旋转真实人物。
- 暂停不偷偷走动画业务时间；1/2/4倍和可中断快进保持动作反馈与原时间对齐。
- 离场/卸载再来与进行中完整重启重建正确方向/相位，不重复动作业务效果；缺方向/不合法锚点候选有明确诊断。
- 1280×720实机录像/逐帧截图、原生比例接触表、当前回归与纹理/CPU/GPU/draw-call实测。通过前保留当前占位回退，不声称动画系统已完成。

## 10. 调研决策

优先采用Godot内置运行能力，借鉴FLARE的“按方向排列动画槽位”设计；需要更复杂穿越遮挡时加动作相位与分片。LPC适合研究模块素材与署名管理，但其标准四方向不能满足本需求。Blender八方向导出插件和CC0人形动作可作离线生产候选，须另验版本与内容许可，不先安装。详见[来源与许可表](../../design/research/eight_direction_sources.md)。
