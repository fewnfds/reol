## 选资源的顺序

优先级不是“哪个更出名”，而是能否解决当前阶段的真实缺口：

| 顺序 | 建议与理由 | 重新评估的触发 |
|---|---|---|
| 现在继续用 | 现有37项项目Skill、Godot AI、备用Godot MCP、Context7、本地无头测试与代码表现 | 读写调用/版本真的失效、明确缺能力或实测瓶颈 |
| 最早需要准备 | Windows同版本导出模板与预设、可分发中文字体；到P0/P4对应包核对 | 首独立包缺字/无法导出；不能提前声称已安装 |
| 工作量出现后再评估 | Dialogue Manager等内容工具、GUT/GdUnit4等测试工具、地形编辑工具 | 现有模板/测试runner/编辑流程确有成本，隔离试验能证明收益 |
| 不急于引入 | LimboAI/行为树addon、Pandora、Phantom Camera等 | 现有简单策略、JSON和Camera2D无法清楚维护时再比较，不能只因名称适合就迁移 |
| 正式资源阶段 | 可商用开源或免费图块/人物/UI/音频，代码自制模块与按需图像生成 | F8玩法闭环后先做统一样板，再批量替换 |
| 暂不采用 | alpha且许可/兼容不适合、C#核心依赖、重复MCP、把全游戏状态交给外部框架 | 前提改变且有实际必要，单独解释收益/迁移成本 |

原生替代默认保留：TileMapLayer/地形规则、AStarGrid2D与现有导航、Resource/现有JSON定义、Camera2D、AnimationPlayer/Tween、AudioServer、现有自测runner。候选成熟不代表一定优于已工作的简单实现。

## 候选的合格记录

每项至少具备：准确名称与原作者、一手URL、确切版本/tag/commit或仍未固定的说明、核查日期、许可/商用与再分发条件、维护信号、Godot版本证据、用途、原生或现有替代、在哪个阶段有收益、测试/移除成本。

将证据分开写：

- **已在本机运行**：只有实际调用、导入或独立包验证才能使用。
- **作者声明支持**：README/发布说明/资源条目的版本范围；不是Reol兼容测试。
- **候选待核**：搜索索引、网页抓取失败、未读取下载包或alpha发行，说明缺少哪部分证据。
- **不采用/仅学习**：与语言/许可/架构不符，或当前没有价值；不能偷偷放进依赖表。

不以星数证明维护；不使用`latest`；不把主分支许可证推断到所有历史包。引入时保留锁定版本、许可原文、来源与修改记录，在隔离检出/临时工程验证导入、导出和移除后再按项目规则决定。新插件/库先给用途、版本、许可、维护、替代；用户已允许利用免费资源，但未授权无条件安装全部候选。
