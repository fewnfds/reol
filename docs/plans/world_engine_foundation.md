## 1. 交付目标与代码起点

地理和天气提供背景；真实物品、身体、地形和建筑改变局部条件；不同环境作用按各自规则传播，被生命、物品、工作与修行查询，玩家能观察改造结果。显示只是投影，卸载画面不清空世界。

完成标准是可扩展的实际运行链，不是架构图或剧情事件。保留已有状态所有者、共同时间、独立候选恢复及正常玩法，不整仓重写、不引入第二时钟、不每格挂Node。

| 领域 | 可复用的实际代码 | 必须补齐 |
|---|---|---|
| 地图 | `WorldMapData`节点外查询、`ReolWorld`区块绘制 | 稳定空间键、地理映射、稀疏地形改动与候选存读、局部失效 |
| 气候 | `world_calendar`、`climate_rules`、`weather`、`environment` | 从home/river预设曲线扩为纬度/海陆/水汽/风及季节天气；太阳与极昼极夜；海拔/山地雨影暂缓 |
| 热 | 当前`local_heat`四邻Q、固定冷热器物/背景和有符号受体，正式仍限512活热格 | 改为普通源场max＋有界温度目标/渐进响应，验性能后有限迁入并退役旧Q；不继续将守恒回收/特殊压缩作为前置 |
| 灵气与五行 | `spirit_sources`有限资源样本、`natural_environment`静态亲和 | 万物持续五行影响及稠密五通道场；可吸收灵气由物品另持储量；场浓度促进修炼不被消耗，积攒/容量/物品变化后置 |
| 建筑 | `construction`真实材料/工序/门墙顶、`enclosed_space`围合；结构变更前后结算 | 值事房与工地统一查询、多种介质特性、增量连接、自动墙形和批量蓝图 |
| 对象 | 主体/身体登记、数量库存、独特器物、衣物、鸟兽 | 环境作用引用原对象、位置和容器链；对象/结构查询入口，不复制ID/位置/物资 |
| 运行 | `RegionalSimulation`边界调度、联合快照与候选校验 | 变更依赖、分段源轨迹、稀疏场预算、远区批算和误差；不全图每帧扫描 |

## 2. 状态与接口

| 职责 | 权威状态/查询 | 约束 |
|---|---|---|
| 地理与地表 | 版本化生成基线、地理范围/比例、平面地形delta与材料 | 512×512是地方地图，映射宏观坐标，不在一山塞所有纬度 |
| 结构与空间介质 | 原墙门窗顶/家具；派生邻接边的通行、导热、通气、透光及各相导通 | 墙可挡人却导热，窗可透光却挡人；不用一个blocked决定全部 |
| 原对象与位置 | 原实体ID、持有/容器、真实位置、储量及开关 | 源引用原对象；携带、放下、入箱、拆除不复制物品或储能 |
| 环境场 | 室外实际温度/残留、室内唯一室温、五行响应及必要时刻；目标按原来源派生 | 冷热等级先抵消后查温度，房间保存可核对空间归属，不依赖重建编号；原物灵气另持 |
| 派生缓存 | 房间几何/面积、圆形场最大值、光可达性、热图和墙形 | 不复制房间实际温度，结构变更按新室内平均规则接续 |
| 接受作用的领域 | 原身体/植物/材料/工作/修行状态 | 查询相关环境并提交结果，不复制人物属性或给万物同一面板 |

先给现有领域补清晰接口，不预建几十个autoload或全面改ECS。类型定义、实例、操控/保管与呈现分开。单位生成、背包、寻路可复用入口，但不因此宣称这些完整系统已实现。

## 3. 三类传播

### 热：物品影响场与环境响应

2026-11-05用户明确放弃将全世界逐格传热/热量守恒作为目标，冷热也用源场近似。当前已验的四邻Q代码尚未改写，规格和证据仍可追溯；后续不继续将全场热流账、D4压缩/守恒回收扩容当成新框架前置。

按[普通冷热场规范](world_environment.md#普通逸散与多来源换热)，室外背景读季节气候，来源是欧氏距离圆形场，冷热有效等级各取最大，再H−C抵消、查表映射温度，实际读数逐渐趋近。**不采用上一版摄氏温度权重平均**：同等级冰火应对等，即使冷端受绝对零限制、热端可达万度。10冷/10热净零，分数等级按同一规则抵消，温度映射是可调表。

室内按房内各格净等级的面积均值形成全房目标，环境域只存一份实际室温/时刻；火墙/冰墙作为原实物来源，普通家具不按数量稀释。门用少量漏热预设，分房继承室温、合房面积平均旧实际温度是明确近似；开敞后原室温沿释放格继续响应。来源能力可持续或耗既有燃料/法力，不逐焦耳核算，定向/反射后置。具体映射、空间索引及存档绑定仍待原型验证。

### 五行环境影响与物品灵气：持续场及独立储量

万物按五行构成持续对周围产生强度/半径各异的影响，远处衰减消散；修炼/外物不会抽走这份场浓度。环境浓度可以促进修行，类似催化条件，不保存为能被修炼者分走的五份资源余额。冷热主动作用仍来自相应物品能力，不能将全部五行物品自动注册成冷热器物。

可吸收灵气是原物品的独立状态；物品可浸泡在场中积攒灵气，积攒不扣场浓度。容量、积攒速率/条件、吸取后物品变化及详细用途后置，先稳定大世界的源、空间、查询和性能框架。已有`spirit_sources`有限资源演示保持真实状态，不用它反推普遍五行场也会被吸空。相生相克的具体场作用和灵气转化以后分别定义。

按[地面堆叠合同](world_environment.md#地面堆叠与本轮来源边界)，同类一堆只贡献一件强度，数量不乘入源值；异类铺开放，人物/携物新增五行源暂缓。源图为派生数据，不转移物品归属/位置/灵气。五行逐通道max、普通冷热按等级抵消；新建立/旧消散不相加。微潮汐采用[接收环境端](world_environment.md#潮汐在接收环境端计算)，不逐物修改强度，不先复刻热场逐格传递。

算法按max而非sum选择：优先紧凑块与空间索引，比较模板最大值滤波、适用的距离变换；不能直接套普通卷积。移走最强源需在其旧/新影响范围重求，保留可能接替的弱源；跨块/遮蔽/异质模板均按实际规则验。来源静止复用结果，少量变更局部失效，大量变更比较全块批算。响应过程、数据结构和声明精度仍待验证，不因规则更直观便宣称已提速。

环境潮汐采用共享粗空间波形，名义强度98%–100%（围绕99%约±1个百分点），周期/空间间距候选10游戏分钟/64格；冷热先H−C再乘倍率、五行五通道共用倍率。室内在平均净等级后只乘一次房间倍率，实际响应仍只有一份。无需逐物相位组场缓存；潮汐不会使静态赢家反复交替或触发空间重建，但累计和阈值仍要按共同时间正确处理。首包须同时测基础场与微潮汐，不把完全静态缓存的成本当成完整模型成本。
风水/气韵从地形、水路、开口、材质、方向和灵流持续格局派生，可表现聚集、散逸、偏相、冲突或稳定。新增超凡作用沿源/通道/反应扩展，不用一个全局吉凶分决定万事。

### 光：来源、衰减与遮挡

第一版查询日月背景与局部光源叠加，按距离、方向/层和遮挡衰减，不像气体一样储存在格内。夜明珠移走后光更新；热量按原状态继续变化，五行影响的时延/残留以后按明确规则处理。明暗影响感知及已定义的生命/修行用途。

规则照度与Godot灯光引用同一来源和结构，渲染亮度/Light2D.energy不等于热量。关特效、远区和无头运行不取消规则照度；初版不做全局照明和真实光谱。

## 4. 地理、季节与天气

1. 宏观地理定义纬度、经度/当地太阳时、海陆和水汽来源；经度主要影响当地时间，不直接决定冷热。海拔暂缓，不要求本轮加入。
2. 历法定义太阳倾角、昼长与季节，处理极昼/极夜边界。仙侠历法可配，首版明确默认。
3. 依日照、海陆调节及风和水汽形成气候。赤道通常暖，湿润还取决于水汽与环流；沙漠不等于高温。山地/雨影留待后续研究。
4. 天气为背景上的有起止过程，相邻区域相关，按独立seed/过程序号决定并保存；换镜头/聚落边界不能重掷。
5. 建筑、植物、实际水源和术法修改局地；生物群系由长期气候/土壤/水分决定，一场雨不把沙漠瓦片变雨林。

先做可解释的简化风/水汽与统计天气，不做全球流体气象。长期气候、一次天气、地表水和空气湿度是不同状态；完整水利/腐败/农业不因接口存在自动启用。

## 5. 改造、共同时间与近远区

移动/开关源、变更容器、开关门、拆墙、塌顶或改地形：先结旧条件到命令时刻，再验证并提交原对象/结构变化，局部更新连接与依赖，后续按新条件推进。失败不得留半份源/半面墙。

移动连续源按共同步或跨格/结构边界分段累计，不只在到达时写终点；快进不能根据最终位置倒推历史。允许携带作用的来源沿原承载位置解析，再扩嵌套容器和各场透过率；这不要求本轮把人物/携物登记进新五行场，未来五行携带源按人物整体映射，已有携物微光仍依原规则。

室外稳定背景可粗算，热场可按作用区细化；五行来源必须支持大范围每格有物，不能以来源稀疏为前提或静默丢弃弱源。环境单元、气候格、寻路区和显示chunk不强求同分辨率。紧凑数组/块存储与原对象变更通知优先，不为每个来源建灯光节点；是否更新由场变化和依赖决定，不由镜头是否可见决定。

近远转换保来源、本体状态、实际环境响应及必要梯度/时刻，按温度/场强和受体累计的明确误差验，不再强求环境热量守恒。衰尽单元按有界近零误差回归背景，不能永久占满后静默拒绝新源。预算不足保留待处理范围/时间并反馈。

存档保存地形delta、源开关及原对象储量、不可重建场状态、天气过程/随机依据、最后时刻及必要在途状态，缓存重建。旧档从明确启用时刻接新规则，不补过去热/灵机；坏候选不替换当前世界。

明确支持导入的格式须将旧实际温度/环境响应、原物品和天气/湿润/在途状态映入同一个当前模型，不能用新目标覆盖旧实际，不补过去后果。环境热量收据链是否退役由有限迁入包确定，不强制新模型重现旧守恒算法的未来；完整识别、候选校验和失败不改活世界保留，未承诺的格式明确拒绝，历史fixture不改写。

## 6. 自动围墙与功能空间

首选内置TileMapLayer Terrains或四邻位掩码，自动端头、直墙、角、T/十字。增删刷新所在格/邻格，包括跨chunk。逻辑墙归原施工域，贴图不反向决定墙、碰撞或保温。

拖线/框选生成逐格蓝图，反馈非法点和成本；施工仍走原材料、工时、人员和中断，蓝图不提前挡路/保温。房间由真实围合/屋顶/开口派生，功能由家具能力、储物、人员、权限和工作组成。先统一值事房/工地空间查询，不凭命名自动生产，也不先列房型百科。

## 7. 实施顺序与验收

以下为待实施建议，每包交付通用能力，不围绕戒指任务增加特例。

| 顺序 | 可用出口 | 验收重点 |
|---|---|---|
| W0 空间与变更 | 原地图/结构/对象定位查询，地形delta、局部失效，保原存读 | 同次改造影响显示/通行/空间；可保存恢复、坏候选拒绝 |
| W1 气候地理 | 可配地理范围、太阳/昼长、气候背景与相关天气 | 热带/温带/极区及海陆/水汽对照；不改旧历史、不依镜头随机 |
| W2 多源环境 | 共用来源/介质接口下热、光、灵机的独立规则，移动源 | 参数化多源布局、源汇叠加/关闭/移动/装箱，原物品/场不复制 |
| W3 房屋改造 | 墙门顶/材质参与传播，自动墙形与批量蓝图 | 分/合房、开门/拆墙/跨块；成本/场状态连续 |
| W4 世界响应 | 人、非人、植物/材料及工作/修行查询同一环境 | 不同类受体复用；热/光/灵机与布局产生不同结果，保有限认知 |
| W5 稳定扩展 | 活跃集回收、远区批算、联合存读、观测和性能报告 | 多源多区压力、离场/返回、快进/细算、长时累计与重启 |

W0先做W1/W2所需最小空间，W2即接现有墙门顶验证，不等W3才处理边界；每包检查存读/性能，W5负责规模出口。不用空框架替换正常主局。

W2实施再拆为可独立验收的W2a（共用源/空间接口及冷热）、W2b（规则照度）、W2c（万物五行影响、密集源及环境查询），分别接真实对象并验存读、远区和性能，再验共存。物品灵气保留独立状态边界，积攒/容量/吸取变化后置；不把所有传播和养成一次合成大改。W0也只收拢所需对象入口，通用单位模型按实际接入渐进扩展。

自动验收用参数化地图/来源组合：原物资/灵气实际账、场取最大值/响应有界、更新顺序、结构、跨块、移动路径、整段/分段/中途存读、近远误差及容量/预算失败。新环境不再以全世界热量守恒作为门禁，但同一时间轨迹仍须满足声明精度内的连续性。

冷热测试覆盖圆形欧氏距离/衰减边界、单源/八源同位等强、最强者移走后次强接替、同级冰火抵消/强弱交换、季节中性/冷端下限与热端扩表、反复搬物不叠高；室内验一房一温、按面积平均净等级、普通家具不稀释、火冰墙/共享墙、门/拆合/开敞、长时回归及存读。新模型不要求复现旧模型未来，历史证据不改写。

普通主局验可见变化：冷热/照度/灵机调试图和原因查询、搬物/改墙/开门、关特效不改规则、远行和重启。开发热图可精确读数，玩家仍依观察/工具/阅历获知，不强迫以热图玩游戏。

首轮测512×512，并递增活跃单元、源与结构变更；记录硬件、模拟毫秒/步、p95/p99帧时、活跃内存和存读耗时。性能目标沿项目现有预算，未测前不承诺百万平方公里逐格模拟、无限来源或具体帧率。

## 9. W1a：自然日照的第一个普通运行出口

实施合同，不作为通过证据；实际结果归BASELINE。整张地方地图只设一处宏观纬度/经度与中央经线，home/river不代表纬度带。`climate`定义2在原37路径内容包内增加`solar`，角度以千分度、透射以万分比、亮度以显式相对尺度表达。默认北纬30°、经度与中央经线0°、倾角23.5°，本历法春分日0；参数可由内容编辑，不依赖当前真实日期或OS时间。

太阳赤纬简化为倾角的年度正弦，春分日民用正午为零相位；经度相对中央经线每度平移太阳时4分钟。太阳高度满足`sin(h)=sin(latitude)sin(declination)+cos(latitude)cos(declination)cos(hour_angle)`，日长由几何地平线交点求解，极点与极界显式分类，不对不存在的日出取反余弦。取共同整数毫秒的年/日余数后才转浮点，输出量化为角度/相对照度；浮点投影不参与热量账本。

依据为[NOAA太阳位置公式](https://gml.noaa.gov/grad/solcalc/solareqns.PDF)的几何关系和经度时间偏移，以及[NWS曙暮分类](https://www.weather.gov/lmk/twilight-types)的太阳中心低于地平线6°边界。我们的季相位、零度几何日出、晴雨透射和明暗曲线是游戏简化，不使用NOAA完整历日、均时差、折射或实测气象，不能宣称天文台精度或lux。昼长是此时赤纬下的理想几何日长，不是跨一整天积分的精确日出预报。

`SimSolarRules`为无状态算术；`SimNaturalLight`从已接受世界的environment定义、物理elapsed_ms、原天气epoch/相位和施工屋顶读取。`total_relative=direct_relative+diffuse_relative`，只有总照度送到普通天色；屋面仅按内容定义压低该格自然光，不把进入房间改成全屏变暗，不模拟窗口/侧向散射。曙暮有弱漫射，深夜自然太阳照度为零；画面仍保留可读的夜间基色，不把像素色值当规则亮度。

普通场景DayNight、环境文字及当前可见地块观察读取同一规则。加载/换身份/移动后重读已接受世界；钟表目标领先物理时刻时不能显示未来天光。无缓存写档、第二时钟、光量存储或凭查询发行探索知识。当前包不改变Fog、NPC感知、植物生长、太阳供热、月光或局部法器光源；后续受体沿共同规则接入，不只改玩家视图。

根50标记当前内容合同。原49必须先验digest、严格climate1、environment.rules_version1和完整独立旧候选，再仅加入固定迁入solar默认及rules_version2、重算digest并完整复验。原47/48热转换固定输出历史49，再走同一个日照入口，不借新版VERSION跳过旧校验。旧v1定义仅在明确导入边界存在，不成为当前新局/写档选择，不从磁盘补参数，不补造历史光后果；原温度、样本、物品、热账、时间与在途事实不改。真实旧fixture只读。
