# 天地、气候与地势：世界基础环境方案

定位：环境领域目标与模型；当前优先级、平面边界和工作包见[世界引擎总计划](world_engine_program.md)、[环境分项](world_engine_foundation.md)、[执行记录](world_engine_execution.md)，研究见[来源](../../design/research/world_engine_references.md)。Goal现暂停，不继续细化争环或复杂农务。下文海拔、山势和高差均仅为未来选项，不属于本轮平面地块实施要求。

既有[自然地块与办事场所样本](natural_world_and_workplaces.md)含派生地表、植被覆盖、普通山雀、五行亲和基础和固定真实值事房；它不覆盖下文完整环境目标。具体未实现元素与验收见该包及BASELINE。

超凡者玩法优先；凡人生产维持基础世界循环。E3-b1浅沟/导流与复杂农务暂缓，环境服务术法、灵地、冒险、阵法和战术。下文E编号是领域设计，不构成最新执行顺序。

2026-11-03，用户授权开发决定具体模型。**方案按包实施**；原共同时间、地形/高度、固定局地晴雨及有限雨水/床/衣着作用保留。E1已接历法四季/地区室外温度曲线、真实穿着与原精力、NPC整理外层及进行中重启，见[首包规格](calendar_temperature.md)/[QA](../qa/20261103_calendar_temperature.md)。E2随后接原温石有限释热、固定空间近场、门墙导通/屋面散失和未来环境/NPC，见[首包规格](local_heat.md)/[QA](../qa/20261103_local_heat.md)。完整气候/生态、绝对室内热力学、五行和风水仍待实现。实际起点见[架构审查](../ARCHITECTURE-REVIEW-20261103.md)，功能与验证以[FEATURES](../FEATURES.md)/[BASELINE](../BASELINE.md)为准。

目标：同一片山水能够支持凡人的衣食住行、鸟兽草木的生活和修行者的特殊方法；改变环境会留下可追查的后果。环境无需对所有存在使用同一种属性面板，也不要求对整个世界逐格逐帧求解。

## 1. 采用的基本结构

```text
唯一世界时间 ─→ 历法/昼夜/四季 ─→ 地区气候与天气过程
                                      ↓
原地形/水源/材质 ─→ 室外背景条件 ─→ 局地温湿、风、积水/积雪
       ↓                              ↓
真实灵机来源 ─→ 五行灵机/流动 ─→ 建筑、材料、身体的实际响应
       ↑                  ↑
       └── 地势/水路/开口/布置 ──┘
                  ↓
           堪舆者观察与解释
```

每条箭头只传递已实现的具体作用。太阳可为现实热量和某种修行提供不同来源，但二者不共用一个万能能量值；雨水和水行灵机也不是同一份资源。身体、植物、物品、库存仍由原领域保存，环境不能复制它们。

### 状态归属

以下为建议模块职责，按首包需要创建，不提前注册一套空autoload。

| 领域 | 唯一保存的状态 | 从别处读取/派生 |
|---|---|---|
| 原GameClock | 世界整数毫秒、暂停/快进及欠算 | 日期、季节不另走时钟 |
| CalendarRules | 版本化历法定义，无第二份当前时间 | 年/月/日、节气阶段、太阳位置与季节曲线 |
| Climate | 地区气候定义、已排定天气过程/序号及进行中风雨 | 地形高度、季节、日照；不依镜头生成随机数 |
| Environment | 固定空间键下的局地温湿/储量、热过程/积水积雪、最后结算时刻、规则版本与启用边界 | 室外基准、房间围合/覆盖、原火源和材料；房间编号不是储量身份 |
| 原材料/结构/生命领域 | 组成、含水/耐受、真实热源/水源/生长/损坏等对象状态 | 环境条件，不能把湿衣/库存水另存一份 |
| SpiritualEnvironment | 已登记的灵源、有限储量/补给、五类灵机的局部存量与交换过程 | 原地势、材质亲和、具体阵法/方法 |
| Geomancy | 布局/连接版本和必要的解算进度；大部分缓存可重算 | 同一山水/建筑/灵源；不保存万能吉凶或幸运条 |
| 原个人认识/观察 | 当时感受到什么、方法/来源、估计与报告 | 只读环境投影；不能查询就免费鉴定 |

### 新规则启用与旧档接续

气候、冷热、生态响应与灵源分别记录规则版本及`activation_ms`，同一作用只有一个启用边界，不另走时间。新世界按开局定义初始化；旧世界从迁移时的原保存时刻启用新增作用，记录初始状态的来源与策略，不用新历法重算此前的风雨、寒热、生长或灵机消耗。不得因冬季读入旧档就倒造过去的冻伤、歉收或灵源枯竭。

固定晴雨切换为天气过程时，保留原`epoch_ms`所确定的当前雨相与剩余时段；可用有界的兼容过程完成这一段，再接新气候序列。迁移不改变原衣物/床的湿润、真实已收雨水、温石储量和进行中动作。尚未存在的温度/灵源按明确的当前初值登记，不能把它们当作已积累多年、可免费兑现的历史收益。后续修改历法或气候参数也须按版本迁移，不能静默覆盖已排定过程。

## 2. 时间、历法与四季

沿用`ReolGameClock.elapsed_ms`。日常保持可暂停实时生活；主动等候/修炼可快进，重要危险、当事消息和必须选择的事务打断。年度变化从原时刻推导，不能用系统日期或新增倒计时。

开发默认采用**360日一年、12月、每季90日**的虚构简历，开局春季；一天仍为现有24世界小时。先采用简历，避免把真实阴阳历/闰月当玩法前置。24个时令节点可作为同一年度曲线的名称，不另引入天文精算。年长、寿命和转生仍须其原人生领域实现，历法换页不自动完成人口世代系统。

季节不是全地图同时换皮：各地有不同基温、季节幅度、海拔、雨季与昼长；山顶结冰时谷地仍可生长。过季连续改变温度/日照/雨量概率，阈值发生作用时才产生具体后果。季节长度是可调整定义，禁止为一次截图而改时钟导致所有旧档日期漂移；正式迁移要保留原时间并记录采用的历法版本。

**首步出口**：能读日期/季节，两个地区有不同日夜温度曲线；到冬季不会仅因为名称变冬就扣每个人精力。跨季快进与逐段推进得到同一已支持环境状态。

## 3. 气候与天气

气候回答“这里长期通常怎样”，天气是一次有起止、强度与变化过程的局面。晴/阴/雨/雪/雾、风向/风力、云量先服务具体用途，不一次加入台风、全流体和全球大气。

地区以明确的地理气候区域归属查询，不沿用目前“离哪个住处近”的原型作为完整世界规则。天气从世界seed、地区/气候单元、过程序号独立取样，排定后保存；镜头、读取顺序、NPC人数、开关雨线均不能改变下一场雨。相邻气候单元可以共享天气锋面ID或相关源，避免穿过聚落边界立刻从暴雨变烈日；第一版先做相关过渡而非气象数值预报。

降水有明确落点和去处：屋面遮蔽、地面入渗/径流、有限泉源/容器接水、衣物湿润。河道供给与取水仍引用真实来源。改变水路需要原地形/施工与守恒的水量事务，不能因为“下雨”直接给仓库无限加水。雪需要低温与真实降水过程，融雪计相应水量；首包未交付积雪质量账前不开放取雪造水。

表现从真实天气投影：雨线、雾、风摆、积雪图只在附近绘制；暂停、卸载视图、关闭特效不影响雨量。看到远处云并不意味着知道远方每个人当前处境。

## 4. 温度、湿度与生存条件

### 模型与量纲

室外基准来自地区气候、季节、时刻、海拔/地形遮蔽与天气；局地叠加实际热源、屋面、墙门通风、水和材质热容。**围合、覆顶、保温是三个判断**：有墙不等于有顶，有顶不等于密闭温室，开门会改变交换。

| 量 | 首版表示 | 用途 |
|---|---|---|
| 温度 | 有符号0.1°C定点 | 热交换/凝冻/材料与身体耐受 |
| 湿度/表面湿润 | 定点比例或原物件现有湿润 | 蒸发/干燥/霉变条件；不替换实际存水数量 |
| 风 | 有方向、有界强度 | 通风、体表换热、火/气息传播的条件 |
| 热源/储热 | 定义热容量/有界释放率与原成本引用 | 炉火、温石、日照，不无限叠加抽象“暖和” |
| 积水/积雪 | 有来源的真实数量或未开放的展示量 | 未有守恒实现时不允许兑现成可取资源 |

温度不简单相加。房间/环境小块按热容和相邻交换导热，源释放有上限，至少满足“流出的热不能比源提供的更多”。第一版允许使用简化的一阶温度趋近模型，状态和环境分段内可用闭式或固定点积分；不能每次查询重新从室外温度开始，也不能在卸载房间时清掉余热。温石现有charge必须先定义有界供热转换才能给房间加热，不能既不扣原charge又供免费热。

不为262144格各挂一个节点。室外用8×8格左右的环境小块/背景曲线；独特火源附近、室内和关键物体建立稀疏覆盖。64×64是现有显示区块，不强迫气候、寻路、房间和环境都使用相同分辨率。房间跨显示区块时仍是同一个实际空间。

### 改布局与精度切换时保留什么

当前`SimConstruction._reindex()`会重新检测围合，房间没有可持久依赖的稳定实体ID。因此局地权威量采用**地区ID＋固定空间坐标/物性层**归属；室外均匀背景按块紧凑表示，需要独立演化的局部才建立稀疏状态。房间仅是这些空间单元的求解聚合与连通缓存，不保存第二份总热量或灵机。物件自身储热/灵机仍归原物件，不并入房间账后又留在物件账。

拆墙、隔房、开门、改变屋面时，先用旧布局把受影响过程结算到变更时刻，再提交原施工/物件变化，最后切换连接与交换条件。热状态同时有明确的储量和容量基准；只改变保温/通风不能清空余热或瞬间恢复到室外温度。搬入/移走材料的储量随原物件过程处理，不能因房间容量变化凭空生热。

近远精度转换沿用同一固定空间归属。均匀块展开为细单元、或细单元压缩为聚合表示时，须保总量、容量/体积基准与舍入余数，采用确定的分配顺序；旧表示退出后新表示才成为权威，不能同时结算两份。若某种分布无法在声明误差内聚合，就保留稀疏细状态。初次激活背景允许按定义初始化，曾经激活的单元不能卸载后再次免费初始化。

### 对万物的作用

- 人身：衣着/湿润、劳动、热源、遮蔽与适应共同影响冷暖负担。先影响已存在的精力/恢复/行为选择，具体冻伤、中暑须沿健康域有来源地实现，未完成人生后果前不偷偷开放致死。
- 鸟兽：体型、羽毛/皮毛、栖地、食性与水需求不同；不共用人类衣位和“喝一杯热水”方法。普通动物和有意志妖类也不共用规划精度。
- 植物：季节/水分/温度作用于原生长过程、休眠与受损；木行亲和不能自动免疫冻害。个别妖木有例外能力，须有定义和成本。
- 材料/器物：药草干燥、食物保存、燃料潮湿、容器冻裂各有适配规则。食物不因新增温度场就立即启用未做完的腐败或疾病系统。

玩家可通过修屋、换衣、移炉、改开口、选时劳作、请人帮忙、迁移或掌握具体术法应对；不会只剩叠一条耐寒属性。

## 5. 五行：材料特性、灵机与方法分开

采用金、木、水、火、土五相，但不把一切物体分成互斥的五个箱子。一个物件可由复合材料组成，有不同的导通、吸纳、释放/排斥倾向。以下三层分开：

1. **普通物性**：重量、结构、含水、燃烧/热性等具体规则。金属会导热，不等于装有一罐火灵气。
2. **五相亲和/通性**：材质与生命对各类灵机和方法的响应系数，是质量/结构/加工影响的特性，不是可被花掉的蓝条。
3. **实际灵机/作用**：有来源、种类、数量/容量、传输损耗与过程，归灵源/容器/身体或已登记环境储量。修炼/法器不能重复花同一份。

相生顺序采用木→火→土→金→水→木；相克采用木→土→水→火→金→木。它们规定**特定方法可能如何转化或抑制**，不是无条件执行的增殖表。相生转化需媒介/工法/输入，产出受效率与容量限制，剩余成为耗散/废物或定义副产物；绕五次不能凭空变多。相克受量级、接触和承载限制，一滴普通水不能因标签克火便浇灭上古灵焰。

灵源可来自地脉存量、昼夜/时令有界补给、真实燃料/灵材、活物自身运转。源与补给是仙侠世界法则，并不冒称现实物理；仍须把来源和边界写清。允许罕见逆相/化生、特殊体质和传承，但它们改变具体过程，不由剧情临时越过已定成本。

普通人只见“湿冷石室、铜环发热、草木蔫败”；相关阅历者可能感知水行充盈、火行躁动。门派学说可以有误，材料真相不能因某个人说它属金而改变。做一次鉴定只新增其可知报告，不开全图后台五相热图。

**首个闭环**：同一有限灵泉能支持一类修炼/药圃用途；一种导流材质与一处真实炉源改变局地灵机条件。玩家可选择分流、储存、换材、换方法或迁位置；两用途会竞争，不能两边各取全额。

## 6. 风水：真实布局形成环境，不设全局吉凶分

风水描述地形、水路、植被、建筑开口、材质和灵源怎样共同影响一个地点的条件。堪舆是认识这些条件、提出解释与改造的能力。**同一事实可以适合药圃而不适合人住，适合水行修炼而不适合焙药。**

可按局部有向连接图表达空间作用：平面地表、水路、通风口、墙门、材料和已登记阵具决定连接/导通；灵源为节点注入，消耗者为出口，泄漏/耗散去向明确。山势/高差连接留待未来研究。第一版用有界小图/场求解，不全地图逐格每帧扩散，也不把八卦图的外观贴图直接加成。

| 改造 | 实际改变 | 由何者承担成本/后果 |
|---|---|---|
| 开口/堵口、增屋面/改墙 | 通风/遮蔽与灵机导通，不必同一种系数 | 原施工材料、工时、通行与权限 |
| 导水/移源/种植 | 实际水/灵源输入、吸纳和生态条件 | 原水量、土地/植株、劳动与资源权利 |
| 放置导流器/阵具 | 已实现的边、方向、容量/漏损 | 原唯一物件、供能、维护与使用权 |
| 室内换摆设 | 有定义且确实接触/导通的局地作用 | 原搬运与实物位置，不按物件数量刷美观buff |

图的拓扑和导通由布局决定；灵机现有存量是持续状态。拆一堵墙会改变未来流动，不能重算缓存时把全区灵机重置/瞬间加满。更新按确定顺序、双缓冲或同刻联合提交，源先扣量、再按容量分配，结果与容器/RNG遍历顺序无关。

房间/地形/器物改变发出局部失效标记，仅重新求受影响区域；相邻块边界交换相同的量，不能近区流出、远区没收到。达到稳定态可跳过稳定时段；源枯竭、开门、改道、消耗或季节阈值使预测失效。真正阵法作为在相同图上作用的物件/方法，不与“风水系统”各建一套会重复加成的灵气。

不实现随机“家宅气运+5”、全体好感/掉宝率加成或所有人共享的最佳格局。小说中的命数、诅咒、因果等若以后采用，另有明确来源/作用机制，不塞进万能风水分。玩家找到稳定好办法允许成立；世界的代价来自真实资源、维护、他人的利益和环境变化。

## 7. 地图、事件与远区如何接续

### 地图

保留现有TileMapLayer作为显示与编辑适配。世界地图数据采用“生成器版本/seed/地区坐标＋稀疏修改delta”；高度/地表/阻挡/房间/覆盖/环境各有权威来源，共用查询接口。地形被挖改才写delta并使寻路、水路、环境与视图的对应缓存失效，不把每一帧瓦片像素写入存档。

未来大世界使用地区/区块ID＋局部坐标；角色本地仍使用连续位置。TileMapLayer序列化坐标有限，不能把全世界长度无限堆到单一Node/一张tile图中。先扩实际持久地图数据，再扩世界尺寸，保留原512×512样本回归。[官方TileMapLayer](https://docs.godotengine.org/en/4.7/classes/class_tilemaplayer.html)

### 事件

各领域继续拥有事实和成本。逐步统一事件引用的信封：作用域/ID、因果来源、发生时刻、当事者、地点、已提交的影响引用、可观察线索。事件信封不再保存另一份库存/伤势真值。待执行事件与已发生事实分开，不能靠重放提示文字补发物资。

事实提交→附近感知/目击→当事记忆→传递消息→对方形成认识，是不同过程。“冬季到来”的可推导时间通知不意味着所有NPC知道远方冻死人；“房间降温”也不应每分钟生成数千条社会事件。只有有玩法意义的阈值/行动/变化留下有界摘要或详细来源，细粒度环境样本按需要保存。

不为此先造无所不包的全局EventBus。原信号做运行时通知，领域日志做持久事实；共用工具先规范ID、时间和来源校验，再逐个迁移。任务剧情只能提出意图/条件，不能绕环境和社会规则写出一个不存在的结果。

### 更新精度与快进

| 范围 | 起步精度/策略 | 不允许丢失的东西 |
|---|---|---|
| 身体/短动作 | 沿原共同时间与必要动作边界 | 接触/成本/取消/完成顺序 |
| 衣着/生存暴露 | 现有分钟脉冲；关键热过程按需细分 | 有来源的累计暴露，不用末尾一天状态代整天 |
| 气候/天气 | 持久过程起止、小时/日/季节段 | 降水积分、独立随机序列与跨区来源 |
| 室内/局地热与灵机 | 活跃稀疏块/房间，稳定段批算 | 原存量/余热/边界交换、阈值交叉 |
| 生态/区域生产 | 日级或其真实阶段结束 | 生长/消耗/死亡前置；不按玩家到场才生成过去 |
| 远区/多年快进 | 相同法则的分段积分/必要事件推进 | 原人名/物件/承诺/过程与可解释的区域后果 |

不会只因离开就换一套概率故事覆盖精确历史。活动可能引起跨域阈值时切细；无变化则跳稳定区间，记录积分基准和舍入余数。显示LOD不改变世界真值。精细/批算在各包声明的误差或精确范围内比较，不承诺没有实现的全物理逐位同一。

现有“每分钟全局环境边界”适合双聚落原型，**不能当多年快进已优化**。扩规模前要把安静环境改成可预测边界、区间累计与局部激活，并测一天/一年/长期空区的成本；预算耗尽保留欠算，不丢世界时间。源、区块或对象事件都不能因视图卸载被删除。

## 8. 表现与玩家可知

基本界面先显示日期/时令、本地可感冷暖/风雨、衣物湿冷、房间烟/潮等具体线索。记录能回看“谁在何时用什么方法说了什么”；普通玩家不必打开开发热图管理生活。

堪舆与修炼观察提供按方法产生的局部报告、工具读数或不确定描述；传闻可能旧、误或故意欺骗。调试热图明确标作开发工具。真实黑箱条件须有可学的线索，不能借“认知有限”让玩家完全无法发现为何失败。

## 9. 分包与验收顺序

| 包 | 最小交付 | 依赖/验证重点 |
|---|---|---|
| E0 契约收拢 | 原时间/事件引用/地图查询接口、固定空间键、规则启用边界和局部失效 | 不先改全部状态；旧档与现有双聚落不变 |
| E1 历法与局地冷热 | 同时间四季/日照投影、两地室外温度，真实衣着/湿润改变生活选择 | 明确fiction历法、保留旧雨相/湿润/雨水、新作用不追补过去、跨季存读 |
| A1 八方向外观 | 原人物/两层衣着的真八向、左手剑/右腰佩玉呈现样本 | 见[专项方案](eight_direction_appearance.md)；素材有八向才算 |
| E2 屋舍与热源 | 同一寒雨局面：原屋顶/开口/实际有成本热源改善条件；药草干燥等第二用途 | 围合≠覆盖≠保温；隔房/拆墙不丢或复制存量，热源不能免费，NPC离场继续 |
| E3 地表与生态 | 持久地形delta、有限水与至少一种植物生长/休眠响应 | 采集/施工/水量/寻路同一事实，远区累计 |
| E4 五相用途 | 材料亲和与真实灵源分离，一处灵源的两种竞争用途 | 转化无增殖、量级/媒介/人物认识、已有方法接续 |
| E5 堪舆首场景 | 墙门/水路/材质能改变有源局地灵流，支持两种不同生活目标 | 改造耗材/失效缓存/有限观测、粗细/重启一致 |
| E6 扩规模 | 多地区气候与长期推演、内容复用与性能预算 | 长年不逐分扫全图；不重复生事件或补发资源 |

这些包穿插回原P1–P4生活/创造/冲突切片，不为了百科完整暂停所有玩法。温度、五行、风水的**最小可玩链纳入基础世界建设**；复杂水利/全热力学/完整阵法与海量工艺仍留后续。与旧长期表中“复杂温度/风水后续”并不矛盾，但基础子集优先级已按本次用户要求明确提前。

所有环境包至少验证：同一局面可用两种办法应对、NPC同规则、离场/快进/中途完整重启继续、坏候选原子拒绝、无AI也看懂原因。动画验收另含视频与逐方向接触表，不用单张截图替代流畅度。

跨包边界还须验证：①一个有余热/灵机的空间被隔成两间再拆通，固定空间存量、源与消耗总账不增不灭；②同一局面细算/聚合/细算及进行中存读，误差在声明范围且不重复初始化；③真实旧雨天档迁移后，当前雨相剩余时段、湿衣/湿床与已收雨水保持，新增冷热/生态/灵源只从各自启用时刻生效。实施时随实际领域添加对应自动化与实机证据，不把本段当已测试结果。

## 10. 当前主要困难与控制办法

1. **组合规模**：作用链太多容易失去可解释性。每包只接一来源、两用途和少量反例，给玩家实际可知的原因。
2. **远区积分**：天气、热源、活动变化会打断稳定段。先保留原必要边界/欠算，再逐域证明批算，不因快进偷偷跳成本。
3. **架构膨胀**：当前区域组合/恢复与身体排他入口已有重复。新增通用小契约收拢调度/快照/动作占用，逐个领域迁移，避免一把重写损坏所有真实旧档。
4. **内容成本**：八方向×动作×外观比程序变量昂贵。先一身体家族/少量模块建生产与校验链，全部不对称外观保留真实方向，批量内容在技术样本通过后生产。
5. **功能边界**：没有植物、地形改造、温度、完整灵源或死亡接续时，不能以天气/五行标签宣称它们已完成。按FEATURES与BASELINE逐包更新证据。
