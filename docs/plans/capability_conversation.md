# 有限交谈 — 询问对方能帮什么

2026-11-03历史工作包，有限交谈已实现，见[QA](../qa/20261103_capability_conversation.md)。它接续P1-f，不代表通用对话或独立技能表。

目标：玩家能向眼前的人询问“你能帮什么”，从对方自愿介绍的经历、所学与任职发现办事方向。自述只说明他说了什么，不保证愿意接下一项请求，不授予技能、货物或机构权限。

## 规则与边界

- C共用verb `converse`、公开话题`ways`；口头问答可理解，复杂自述不能靠指物手势表达。鸟/山兽仍按原理解边界回应，不给所有生命套人类服务菜单。
- 询问前复核在场距离/通信控制，凝神研究、对练、睡眠等专注过程优先；原普通劳动可短答而不中断。回答意愿复用原个人社会判断、精力/忙闲/关系与同条件缓存，不每点一次重新赌。
- 无状态SimCapabilityConversation只在询问时投影说话者自己的身体经验、辨材背景、温石亲历/学习，以及本人当前任职；内容白名单在data。不读取他的仓库余额、他人的秘技或全局“可用服务”表。不声称穷人不会搬柴，也不以固定职业决定全部能力。
- 答复只写原SimSocialMemory的私下双方事件；同村用原村落账，跨聚落交谈用已有服务社会记忆。说话者/听者/时刻与原社会决定都保留，不向旁观者广播。不增加第二记忆库、背包、动作队列或世界时钟。
- 短答是即时通信事件，像已有询问库存，不占用新的长时身体任务。后续辨材/交易/劳动仍独立判断和实际执行；知道“他曾说能付款”不等于他现在仍有任职或预算。当前不做撒谎、自主宣传或多轮议价。
- 重开C/读档可回想本人实际听到的最新自述，不远程刷新对方能力。记忆仍是过去的说法，换任/新学之后须再次当面交流；界面不能因刷新而自动读新事实。

## 实现与存档

数据新增`capability_conversation.json`，content_db加载/验证；增加无状态`capability_conversation.gd`，路由原interaction_requests，C进度使用有界可滚动文本。原村落与服务候选校验自述事件、白名单内容和对应社会决定；事实真伪不作为能力授权。

不增加新的持久字段/领域，根/区域/服务版本保持26/23/5；旧档无自述则无自述，不补造过去交谈。真实v1～v26及wage_claim_v26/overload_v10不可改写。

## 验收与顺序

1. 纯规则：新人/辨材者/操纵者/现任说法不同；学习/换任后再问可变，旧听闻不随查询改写。
2. 边界：远方/手势/鸟/专注状态无有效自述；不透露预算和他人私技；不授予听者掌握/权限/物资。
3. 来源：同条件不新增事件/随机数，旁人不获内容，第三人不能查询他人私答；NPC可经相同接口发问，跨聚落在场也能交谈。
4. 候选：私下答复/决定引用坏档拒绝、活世界不变；原真实v26迁接后不补自述。
5. 运行：实际C鼠标问答、记忆重开、正常保存/完整停开同一未来；`python tools/godot.py check`与1280×720截图/日志后才记完成。
