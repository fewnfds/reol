# 统一请求首包：当面辨物与请鸟取药

2026-11-03，首包已实现并验收，见[QA](../qa/20261103_interaction_requests.md)。本文根schema14/区域11是包交付时的历史版本，当前格式和Goal状态见[BASELINE](../BASELINE.md)/[HANDOFF](../HANDOFF.md)。

目标：无需AI，通过接收者/事项/对象/表达方式提出真实请求；普通同门、雀妖按自己的条件回应，答应后由原执行器继续。

本包复用现有辨材/探查和雀妖取药，不新增第二份人物、关系、动作、背包或请求历史。不做自由文字、任意条件脚本、全NPC规划、普通鸟/植物新物种或完整对话系统。

## 规则与所有者

- 意图包含发起主体、接收主体、动词、带领域的对象引用、表达方式和条件。只开放当前三个事项；未支持的条件明确拒绝，不静默忽略。
- 先验证结构、真实主体/对象、发起者控制、信号距离、理解和基本身体条件，再调用原请求决策。口头说明与指物比划不是相同媒介；本样本雀妖能理解具体取药手势，不能理解辨器请求，不泛化为全部鸟的智力规则。
- 人身要伸入现有狭缝取药时受原尺寸限制；以后有工具/新方法可改变办法，本包不假造新工具。
- 人类辨物沿原社会骰/缓存、个人阅历/灵气、耗时与在场听取；雀妖沿原饥饱/精力、投喂经历、所知药源、携重与实物交付。指定药源必须真被执行，不能换目标后仍偷偷去默认最近点。
- 回应区分无效、未传达、不理解、做不到、暂时不便、拒绝、开始执行；开始不发成果。具体结果继续归器物/鸟域。
- 协议是无状态门面，不改schema。进行中请求从原动作/约定恢复；完成认识从原个人记录读取。不能用远处鸟域内部交付事件给玩家全知确认。

## 文件与呈现

新增 `data/definitions/interaction_requests.json`、`scripts/sim/interaction_requests.gd`；ContentDB校验定义。调整原请求API提供稳定原因码，鸟域支持明确药源；不改变既有无参数调用含义。

新增运行适配/Control面板，C打开。事项不是接收者后台技能清单，目标仅列眼前可见对象；UI不显示隐藏能力/储能/精力。原辨物/衔药快捷入口也走同一规则，避免界面选择绕过协议。

## 验收

1. 同一辨材请求给同门可拒绝或开始实际耗时；给雀妖不理解，不创建辨物动作/知识/物资。
2. 人身无法凭请求进入现有窄口；雀妖只有理解手势且愿意/有条件时才取药，指定药源的实物减少。
3. 相同社会请求不重掷；已有动作不重启/重扣。无效/远处/未知对象/无控制/未支持条件不会改变世界。
4. NPC人类可用同一入口；原专用快捷入口保持行为和有限认识。
5. 中途联合存读、全新场景与完整重启后同一未来；真实v1–v14/overload_v10保持原样。
6. 无头check、实际面板操作/截图和日志复核；最新总数只更新BASELINE。
