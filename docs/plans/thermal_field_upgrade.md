# C1：原热场升级规格

状态：分包实施中，承接[世界引擎基础](world_engine_foundation.md)的W2a；授权和实际进度看[HANDOFF](../HANDOFF.md)，已有行为和证据分别看[ARCHITECTURE](../ARCHITECTURE.md)、[BASELINE](../BASELINE.md)。C0只让投影区分数值与未知；C1a-0先补来源金额，现有场仍是正余热，固定参考与冷热源尚未完成。

## 1. 分包与所有权

- **C1a**：在原`SimLocalHeat`接固定参考能量、双向背景交换、原温石有限脉冲和带金额的来源凭据，迁移明确支持的存档及受体；先不引入寒冰石、连续移动源或回收。即使只有热源，背景升温也可能使活跃格低于室外，人体和药草必须能接收负温差。
- **C1b**：接真实火石和寒冰石的持续源汇，验证共同步竞争、开关和移动。原`SimArtifacts`拥有唯一器物、储量和过程；热场只拥有空间能量和可核对的转移记录。
- **C1c**：单独完成可回收/聚合空间及其误差、历史样本和压力验收。各包均沿原共同时间、结构和候选恢复，不另建热引擎、时钟或物品副本。

C1a先以**C1a-0**补齐原器物成功`warmed.heat_amount`与原热收据的金额互核，根47/区域39/器物7；热状态和定义仍v1，内容包及digest不变，成本、热物理和人体/药草采样不改。旧区域38/器物6只能从已有配对收据补金额，其他字段留给原独立候选严格验证；已有新字段或无法配对的旧事件拒绝。此机械转换不需要第二套旧热求解器，也不声称补齐了所有温石历史charge审计。**C1a-1**先收人体/药草的共同背景投影和精确气候边界，保持物理/格式不变；**C1a-2**才处理固定参考及有符号受体。

## 2. 定参能量与时间

候选采用固定参考`T_ref = -10000`（十分之一摄氏度）和非负整数`Q`；容量`C`的单位是每0.1°C的能量，来自存档绑定的热定义。格温度按`T_ref + Q / C`投影；定义下限、容量、整数取整及安全上限，验证背景和旧最大余热都可表示，超界前拒绝而非截断。这个参考是数值零点，不声称完整热力学。

已分配格保存`Q`，未分配空间按当地背景查询。激活格时从外界账转入`C × (当时背景 - T_ref)`，并记录实际分配；后续天气或昼夜变化只改变边界温度，由交换逐步改变`Q`，不直接重设存量。每个冻结段从同一旧状态算邻边及室外流，实际天气相位变化和十秒步边界需成为可结算边界；无流但背景可能变化时不能永久停调度。内部一出一入相等，所有取整和余数有确定规则。

当前日/季曲线按整数毫秒插值，分段长度`D`、端点差`Δ`时第`k`次分量变化在`ceil(k×D/|Δ|)`，负斜率仍用正幅值阈值。天气相位以保存的`epoch_ms`及地区offset为锚，旧档可有非整分epoch；现有天气`next_boundary_ms`只管全球分钟湿润脉冲，不得塞入相位时刻改变`last_pulse_ms`合同。C1a-1只读API提供日/季分量变化与真实相位的候选并集，跳过平段、不逐毫秒扫描，结果严格向前并在MAX截止。分量同刻可抵消，因此候选不保证合计温度必变；未来热求解器若采用它们，须把这些候选明确作为确定的冻结边界，不能随分帧增删重冻。

历史背景由存档绑定的气候/天气、原epoch和样本自己的格/时刻查询。旧`last_sample_cells`省略零余热和当时未分配格，不能仅凭同毫秒收据猜完整激活集合；可保留其原正余热偏量事实，不补造旧绝对热量。新有符号偏量转温度应先重组非负`Q`再整除，或明确数学floor，避免负整数向零截断错一档；药草较早activation样本若无对应热切片，仍只按原可证范围校验。

同一账以非负累计量表示：`现存格能 + 汇吸收 + 外界流出 = 初始能 + 源输入 + 外界流入`。初始/分配、旧散失、释放、吸收和回收必须各有明确去向；计算和累加不得超过可精确存档的安全整数。查询不推进时间；投影沿C0的`supported/value`或失败原因，不以符号表示未知。

## 3. 原物成本、竞争与结构

C1a沿用原温石操作：完成时重新核验持有、方法、身体与储量；实际放热量、原charge成本、动作/对象/时刻/格坐标一并提交并记录。取消、容量不足或校验失败不扣原物储量。新`warmed`事件携明确金额，与唯一热凭据及定义比例双向核对；现有有效事件不携`heat_amount`，不能假定该字段已经存在。

C1b寒冰石有有限吸热容量，**实际吸走的热进入该原器物的热储量**；施术另有成本时也只扣原资源，满容量即停。持续火石消耗真实储量。到同一时刻的多个源、汇、邻边和外界交换先汇集，按旧状态算候选，再对每格可用量/剩余容量及每个器物预算统一限额；建议按比例分配、稳定ID处理整数余数。分别合法但总和超限不能提交；冷热同格净变化接近零时，两者的实际收支仍可非零。

源开关、移动、装箱、开门、拆墙、塌顶均先结旧段，成功后更新原对象/结构并冻结新段；失败不留半次成本或半份场。移动源按真实跨格/结构及共同步分段，不能只用终点倒推；关源或搬走不删除已留在原格的热。保存未完成过程和必要余数，重启不重复扣费。

## 4. 有限空间与回收合同

C1a保留明确有限激活域：现有5×5和512格可作为首版配置，域外是背景边界；满额时明确拒绝新源并保留原状态，不丢共同时间积压。近远区使用同一规则，不能随镜头卸载热场。边界材料、墙门顶沿原结构查询，不用房间ID复制能量。

C1c候选只在已结算、无在途源汇引用、无未结流的格或连通块回收；样本和凭据独立于活跃格存留。回收整格`Q`记入外界，额外记录相对当时背景的有符号残余及其绝对累计误差。首个阈值候选为单格`|Q - Q_bg| ≤ C - 1`，单次合计不超过`25 × (C - 1)`；由此限制回收瞬间的局部偏差，而不是抹掉能量。

背景变化还会令已省略格跟随室外、保留格却有热惯性。拟回收区须证明在原气候及晴雨突变下，与保留细格对照，自回收起至少24小时并覆盖相关季节极值、或更早的下一真实源/结构事件，逐格温差不超过0.5°C；再激活的背景能量也要入外界账。一次24小时对照不能外推为永久保证：永久删除细格须另证整个允许气候包络的误差界，或保留带守恒状态的聚合并在证据期限重新评估。证明不了则保留细状态，不把瞬时阈值冒充长期误差保证。参数和误差上限须随实现定义版本保存，预算耗尽要可见且不静默丢热。

## 5. 格式与内容候选

来源金额和只读背景接缝单列前置包。建议C1a-2明确迁移根`47→48`、区域`39→40`、热状态/热定义`1→2`；器物状态已是7，没有新增器物字段时不再升号。人体环境`2→3`、药草生态状态`1→2`以支持有符号温差，嵌套土地资源`3→4`及村落快照`6→7`随实际字段和语义变化同步升级。上述后续号码是实施候选，落地时以当时版本核对，不能只改标签。C1b/C1c新增过程和回收账再各自递增受影响版本。

内容包v1已封存`local_heat.json`等定义及digest。保持文档清单不变时可显式转换包内旧定义并重算digest，其他文档保持原样；若增加文档路径则另升内容包版本和清单。旧包先验原digest和定义，不能用工作区新文件替代其参数；`legacy_v42`固定基线也须经明确转换或拒绝。根43–45迁移目前引用动态区域版本，升级时须固定其历史版本，不能让新常量误拒合法输入。

## 6. 旧档转换与失败隔离

固定参考转换首批候选支持根47/区域39、热状态及定义v1、器物v7且完整可校验的存档；更旧输入须先通过C1a-0的严格配对和原候选验证，再决定是否纳入固定参考升级。更早格式及缺失依据的档不自动承诺支持，实施时列明支持清单，无法合法转换就报不兼容，不猜历史。

先按旧规则核验来源、旧账、冻结段、结构和原内容，在独立候选以**保存时刻**激活新模型。每个旧格转换为`Q = C × (保存时当地背景 - T_ref) + 旧余热`；背景底量记外界流入，保留原来源投入、散失和收据，逐格保留当时可见温度。按旧包中经验证的固定脉冲金额和一对一收据补足对应事件金额，缺失或冲突则拒绝；不反推不存在的源历史。

过去的绝对热量与背景交换没有记录，故不回放、也不补造。保留旧人体暴露、药草温度/进度及其原采样时刻；已有历史热样本按原采样时背景独立转换，不能用保存时背景重算或重价身体。缺少更早样本但旧候选可证的范围只保留已有事实，无法验证即拒绝。所有字段、成本、在途过程和受体交叉验证成功后才替换活世界；原fixture和原档不原地改写。旧导入器只负责有限范围转换，退役后不保留第二套运行求解器。

## 7. 验收与规模

- 分包先做定向：旧账与当前温度、历史人体/药草样本、真实温石金额/取消/重复凭据、损坏包/事件/候选隔离；验证日夜及天气变化不凭空增删热量。
- C1b验同格与分离冷热、多汇竞争、有限储量耗尽、墙门顶、移动/关源、进行中及完整停开；整段/任意分片/受限预算/近远区得到同一明确因果，极值、整数余数、顺序和容量无超支。
- C1c用细格对照验证瞬时及24小时误差、累计账、采样格先回收再恢复；在真实补给和分散空间条件下重复至少512次释放，核对可回收空间和后续来源，不能仅靠清空热量通过。
- 首轮512×512地图，逐档测25、128、512活跃格及1、4、16个源，并加结构变化和远区推进；记设备、版本、每步耗时及p95/p99、峰值内存、存读耗时和实际预算/失败。初轮单样本30秒、子进程1 GiB上限按[执行页](world_engine_execution.md)执行，超限记原因。场景画面验真实搬物、改墙及重启，玩家只获其可观察信息。对应包最后运行规定完整检查或同SHA CI；这些是验收要求，尚未证明通过。
