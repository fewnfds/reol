# U1-b建议：让交锋围绕真实资源、承诺与职责发生

日期：2026-11-04。历史U1-b总体设计；有限感知、借源和看护驱离后续各已有样本，见[BASELINE](../BASELINE.md)及对应QA。下文原动机和验收意图保留，不视为完整潜行、产权或任务系统已完成；当前工作转为[通用世界引擎](world_engine_execution.md)。

## 1. 推荐顺序与最小出口

当时建议先做U1-b利害场景，再推进U2能力组合；两者已有有限样本。暂不先铺大型天赋网，也不继续扩展农业。理由是：现有三种手段已经能够产生距离、施法成本、伤势与撤退，但玩家为什么冒险、打赢之后改变了什么、为何有人愿意帮忙，仍缺实际规则。先让一次取用影响自己与他人的处境，才能检验下一种能力是否值得加入。

U1-b分成三个可独立验证的小包：先补NPC感知，再接一处受托照看的灵源及有限借用，最后接警告、驱离与持续后果。整条出口是：**玩家需要恢复原灵力或为真实温石蓄热，面对他人的职责与有限源息，可以协商借用，也可以冒险取用、抵挡或驱离；获得的是实际一批源息和之后的社会后果。**

这不是完整领地、产权、任务或AI系统。最小场景暂用现有山门地火隙、温石、值事房和具名人物，不新增人类、不增加第二份灵源库存。后山新灵地、妖患和遗迹在U2/U3接入；避免为了把第一场争端搬远，先同时重写灵源装配、地图和所有历史内容基线。

| 原顺序 | 本建议如何交叉推进 |
|---|---|
| [U1超凡冲突](transcendent_conflict.md) | 用现有动作处理有原因的取用争端，补全其玩家出口 |
| [U2学习/器物构筑](transcendent_focus.md) | 场景验收后再做2–3个改变条件的能力组合；不等完整战斗，也不把普通换色视为新构筑 |
| U3冒险/任务 | 本包提供一条有对象和凭据的事项；之后迁到实际新地点，增加自主争夺者，不预建万能任务图 |

| `scripts/sim/spirit_sources.gd` | 原有限量、真实预约、完成才扣源、原qi/储热对账 | 所有权或借用许可；当前还限定地区、place和温石类型，并非任意世界源 |

| `scripts/sim/social_admission.gd` | 个人相信/临时放行和正式签注分开、同条件请求不重掷 | 通用灵源协商；现有schema明确绑定gate/collect_herb，不直接塞入新scope |
| `scripts/sim/interaction_requests.gd` | 传达/理解/能力/意愿/实际后续的边界，以及原领域过程引用 | 自然语言任意行动；新事项仍须有明确规则执行器 |
| `scripts/sim/standing_work.gd` | 承诺只改变本人意图，身体仍由原执行器活动 | 守卫/护送；现有常备计划校验只支持haul，不把值守伪装成搬运 |
| 原健康、旅行、共同调度/候选 | 实际挫伤、持续恢复、连续路线、远处运行与联合存读 | 击败后自动夺产、万能治疗、完整死亡或高效远区战斗粗算 |

设计须遵守最近的ADR-0079/0080/0081：场所、任职、实物与知识分开，原身体和记录各归原所有者。本文没有要求改变这些决定。

## 3. 必须先补：NPC只能根据自己察觉到的线索反应

U1-a时`_ai_action`的护障分支读取`phase(target)`，incoming只按同一encounter筛选，没有再次检查眼前距离、同高度与遮挡。`_ai_motion`也直接以目标当前坐标追近。U1-b0现已按[有限感知规格](conflict_perception.md)实现并完成定向/实机停开验证，最终完整回归以BASELINE为准；这些旧问题保留作本包动机，不再当作当前实现。有限看护样本后续已交付；完整潜入仍未交付。

U1-b0先建立小型、纯规则的感知投影，供冲突和后续看护共用：

1. 以观察者的实际身体为原点，核验观察距离、双方所在高度与真正视线/实体遮挡；用各NPC自己的条件，不能借玩家Fog，也不能用actor所属地区替代物理位置。
2. 仅在看见对方时读取可见姿势和起势线索。飞弹须是眼前可见、位于可作用高度、轨迹可能威胁本人的对象，不能因为世界上或另一地区存在飞弹就开盾；也不应仅因它属于另一场交锋就对眼前可见的威胁失明。
3. 失去视线后只保留最后见到的地点/时刻/线索来源；允许短暂戒备、走向旧位置或放弃。不能持续更新隐藏目标坐标，不能凭旧线索精确追踪、瞄准或确认其新招式。何时过时是数据参数。
4. 感知结果按共同动作边界或有限采样更新，关键已知线索存入所属交锋/事项。不能在每帧渲染时制造记忆，也不引入全世界逐格扫描。
5. 已形成的护障可按原时限继续存在；目标突然消失不退款，也不凭“仍有旧威胁”免费刷新。玩家不知道的远处线索不进入HUD或取消快进。

这不是完整潜行系统。先验收隔墙起势、不同高度、眼前飞弹、最后所见地点与停开接续，再把这组接口用于值守。旧U1-a保留其有限AI说明，不能倒写成早已完成本包。

## 4. 最小场景：地火隙的一次借用

新局显式装配一份“宗门公源由人照看、一次借用须说明用途”的地方安排。使用现有`hearth_seam`和`hearth_stone`；管事仍从原steward职位查现任者，首个受托看护候选使用现有石头。人物名字是新局内容引用，不是代码中的永恒身份或无条件服从。

看护不是全天冻结石头：他要吃、休息、完成正在承担的事，也可能受伤、无力守候或撤回承诺。值守安排不铸造新本领、新灵力或武器；他只能用原来实际会的手段与已有余额。地火隙的现有供给也不因场景启用、接单、挑战或胜利补满。

玩家从近旁人的说明、看见的值守/源息活动或值事房办理中了解安排。任务接受不是世界启动按钮；玩家不接、不在场，原NPC仍会按自己已知的职责和需要去用源、休息和处理取用争执。

### 非战斗路径：讲清用途，借一次，按约收尾

- 走到实际有权办理的人面前，通过统一请求说明“以这块温石为媒，引入本人/温石一次”。没有见过的源、拿不到的石头、自己尚不会的手法，不能被一句话代替。
- 现任管事在实际可办理的值事场所查明后，签发具名、限对象/目标/次数/期限的借用依据。首版不靠刷贡献作硬门槛；能否答应取决于本人已知的安排、已有请求、当地需要与可兑现条件。
- 借用不是库存保证。走到地隙后仍须原源量足、没有冲突预约、原温石完好且可用、本人能引息，原两分钟过程才能完成。
- 若借的是公用温石，归还只由原器物`place`产生实际归处，办理人实际见到或查到可信记录后才记“履约”。这条具名记录不是全局好感奖励，也不代表玩家取得该法器或灵源产权。
- 可补一个较小分支：与看护人商量等当前真实引息完成后使用。其私人答应只能改变本人这一段的阻拦意图；不替机构签永久通行。若这分支会让第一包扩散，先交付正式借用路线即可。

### 冒险/驱离路径：冒险取用，承担实际反应

- 玩家可拒绝安排、偷偷等看护人离开，或在看护人明确提出停止后选择抵挡/驱离。争端因可感知的实际取用、明确侵扰或违约而发生；单纯走过、看物或被人物不喜欢不自动开战。
- 没有许可不等于地形不通。地火隙首版没有魔法锁：仍可物理到场并尝试原引息；看护人只有实际看见、能理解且决定介入时才警告，宽限期也走共同时间。原始脚本调用和UI遵循同一规则。
- 玩家可取消未完成引息而退出；原预约正常释放，无提前回灵。若继续且看护人仍看得见、具备能力和意愿，才由其以“制止这次取用”的原因开始原驱离冲突。不是看护人按下按钮远程扣源或强制传送玩家。
- 真正驱离后，暂时无人阻止只提供行动窗口。玩家仍得接近原地隙、操作原温石并完成原过程，不能因胜利生成掉落或跳过引息。源量被别人用尽时，打赢也可能没有可取的源息。
- 受伤的看护人按实际伤势和自保目的退开休养；恢复到愿意继续承担职责后才重评。不要用一个脱离伤势的“已击败五分钟”倒计时清掉人物。重新接近也不重生满状态守卫。
- 取到源息不改变机构产权或正式资格。目击者记住实际警告、攻击、取用与归还；不在场的人需经传话/记录才知道。首包只做有来源的个人记忆和当前拒绝/撤回，不做全门派瞬间敌对或全局恶名条。

两条路不保证相同收益或耗时。和平者较容易保留合作与再次申请的门路；强取者可能拿到实际资源，也可能受伤、错过源息或丢掉一位愿意照看的同伴。自洽即可，参数由测试调配。

## 5. 归属与最小新增数据

建议新增一个有界纯规则域，暂名`SimSiteAffairs`。它只拥有本处安排、具名借用、相关凭据和看护意图，不持有身体/qi/库存/伤势/物权总表。先一个case，不新增autoload、通用任务引擎、ECS或第二套Claim。

| 事实 | 唯一所有者 | 新事项域只保存/查询什么 |
|---|---|---|
| 地隙量、补给、预约、一次引息结果 | `SimSpiritSources` | 源ID、真实job/record引用；不另存剩余源量 |
| 温石位置、损坏、储热与取放 | `SimArtifacts` | 实例ID、取放/归还事件引用；不复制器物 |
| 谁任职、哪些原权限可办理 | 原`SimInstitutionBook`与场所规则 | 签发人/office/机构/实际办理依据快照；不冒充已经实现通用授权账 |
| 有限借用许可 | 新事项域的具名note | 受益人、scope、source/object/target、签发依据、期限、真实reservation/result引用 |
| 人是否相信/答应、自己记得什么 | 原个人社会记忆 | 决定和事件ID，不复制好感；相同条件重请不重掷 |
| 看护目的与原承诺 | 新事项域的duty | 请求者/受托人、scope、期限、接受/撤回来源；不保存另一份`autonomous` |
| 行走、吃住、正在做事 | 原actor/原执行器 | 只在下一可决策时建议实际任务，不瞬移或强清原活 |
| 警告/敌意/开招/退让 | 警告由事项域，交锋由`SimConflicts` | 互引真实警告/encounter ID；不重复结算战斗 |
| 挫伤/恢复 | `SimHealth` | 只查询是否还愿意承担风险，不另造生命值 |

建议的新内容文件是`data/definitions/site_affairs.json`与`data/scenarios/source_loan.json`，具体名称可实施时调整。以下是拟新增字段说明，不是现有API或已经能加载的数据：

- `case`：稳定ID、定义版本、启用时刻、机构/source/object引用、规则依据、有限duty/note/event集合、稳定序号。
- `duty`：委托人与受托人、受托范围、期限、已接受的请求ID、撤回/到期记录；当前身体活动从原域查询。
- `note`：签发人/职位/机构、受益主体、`use_source_once`范围、实际source/object/target、签发与截止时刻、证据、`reserved_by`/`used_by`/`revoked_by`。
- `warning`：发出者/接收者、具体观察依据、警告时刻/宽限截止、明确要求、相关source job与encounter；没有看到取用就没有全知警告。
- `event`：因果ID、发生时刻、真实过程引用及具名见证/收到者。原领域已有详情只引用，不再抄一份余额或完整action。

正式资格检查、私下答应、实际库存预约和现场阻止是四件事：

1. 许可只承诺一次使用范围，不替源域预留虚构库存，也不预发qi。
2. 原引息开始时可把该job绑定到一份未使用许可；同一许可不能同时绑定两笔用源。完成的原record才消耗该次权利，中断释放绑定，已投入的其他真实成本照原规则保留。
3. 未获许可时原物理操作仍可成立，但记为未获认可的取用；谁察觉、是否介入分别结算。这里不加“无证的空气墙”。
4. 许可不授温石保管/转赠权，不授武学，不保证道路可达。击败看护人也不自动更换任职者、产权或许可登记。

历史签发人的名字不会因换人而改写。首包采用“到期或有权者明确撤回”的有限许可规则；新任者是否推翻旧账沿后续U4另做，不能在本包暗接尚隔离的继任resolver。

## 6. 触发、调度与后续流程

事项不是一个`quest_stage`掌控全世界。值守是否仍有效、玩家有何依据、某次警告是否结束、原引息/交锋是否在途分别保存，界面把这些事实组合成人话。

1. **新局装配**：实际人/物/源/职位齐备才创建case；看护人若答应，形成有限职责。不是玩家点接受后才生成对手或源量。测试fixture不默认启用。
2. **原自主决定**：需求/伤势/已承担事项优先，之后才读取看护意图。首版可复用实际`check_kitchen`的走近/查看能力作为此处接近手段；它仍不是通用守卫，不能把所有常备haul计划改成值守。到场后通过新感知判断实际取用。
3. **当面办理**：统一请求增加一个有明确object kind的事项入口，有限动词分到新域；仍检查距离、沟通、场所、当前任职与个人决定。接请求、答应、签发、用源完成分别呈现。
4. **开始用源**：先按原规则检查媒介/方法/身体/源量，再建立原预约；事项域关联许可或未获认可的尝试。原操作入口、脚本和NPC不能各自绕过或重复登记。
5. **观察和警告**：只由实际可感知的开始/持续线索产生；宽限到期前可停手/解释。到期复核人、视线、身体、职责和原过程，不能执行已失效的旧警告。
6. **冲突与退让**：实际敌意交给原conflicts。结束后看实际位置、伤势和用途是否继续；不把“战斗结束”当任务成功，也不把一次退让当永久失去自主。
7. **结案与记忆**：成功取用、未完成退出、真实归还、争执未决等均有可追溯结果。机关记录和个人记忆是否知道某件事分别判断；玩家可以继续探索或以后再来。

调度进入原共同毫秒与固定域目录。只在请求、源job变化、感知采样、警告截止、职责期限/伤势门槛等有意义边界重评；玩家离场不删除case，也不依渲染节点判定结束。短期继续使用原冲突精算，事件化远区大规模优化另包做。

## 7. 失败与恢复

| 失败或变化 | 处理要求 |
|---|---|
| 管事不在、有新任者、房间/记录当前不能办理 | 保留请求与历史来源；需等人/找实际有权者，不能由面板代签 |
| 许可已获但源量不足/别人真实预约/温石被占 | 不产生qi或复制第二块石；保留尚未用掉的权利，允许等待、退回或过期 |
| 路被墙柜挡住、地形/高度不合 | 真实路线失败；授权不改地形。可以走可达路线、另约时间，未来再用适当能力 |
| 看护人吃饭、受伤、离岗、撤回或期限结束 | 继续原生活与恢复，不强行拉回；现场窗口可以被利用，机构记录仍在 |
| 已警告后失去视线/玩家取消或离开 | 按有限旧线索重评；不隔墙自动攻击，不把已解除的source job追认为仍偷取 |
| 任一方出手/受击打断借用或说明 | 已发生效果保存；原预约/许可绑定正确释放；已付qi不退，不出现半份奖励 |
| 玩家败退 | 原伤势、实际器物和成本保留；可原时间休养、有限引息恢复、请求说明后再来，不要求重建农场 |
| 新承诺与旧承诺冲突 | 请求被拒或等原活收尾；不覆盖旧差事/货物责任。重复同条件请求不能洗决定 |
| 取用后未归还公器 | 实物仍在原保管位置；形成有依据的未履约记录/当前拒绝，不把器物瞬间传回 |

## 8. 旧档、固定人数和内容基线审查

**本包不应加新人来规避自主冲突。** 复用原玩家与具名人物；不改`pawns.json`数组，不复制河湾居民、不生成可无限复活的挑战者。新增看护职责仍会改变人物日程，必须用显式新局内容开关隔离，不能借`workplaces_version`等无关旧特性来猜是否启用。

存档策略：新增持久事项域只在迁移时补空状态，旧档不补过去的值守、公源规则、许可、警告或社会事件。当前根/区域版本以BASELINE为准；实际引入持久字段时再按需要升级，不在本文预留/宣称新版本。旧档若以后启用该玩法，必须是当前世界的一次明确新委托，而不是读档自动重装新局。

继续保留原灵源和温石定义/现有源ID与库存基线。首版不把第二个后山源塞进所有旧世界；将来新增源须先补规则/场景装配分离、合法位置和跨所属区取用的明确语义。目前`near/medium_allowed`的地区与类型限制不能靠换显示名掩盖。

具体回归影响：

- 原小型runtime fixture仍只按原装配创建一块温石，`objects.size()==1`等契约无需放宽；新主局仍有原木剑，不为此场景再添假武器。
- 新主局相关测试须走真实请求/风险路径；不能因守卫打断测试而把生产场景的守卫关掉或改成永不介入。旧档/小fixture的原无值守行为应保持。
- 人数不变也不代表未来不变：新局日程、源量竞争和记忆会改变，新的场景测试单独记录；历史fixtures、旧未来证据只读，不重写为新故事。
- 新局→老档→新档切换时，case、提示、临时排队输入和感知缓存随会话清理/重建，旧档中无职责的人不能继续带着下一条守卫命令。
- 候选独立地图/职位/原域恢复后再交叉校验permit、source record、看护/冲突、见证和物件引用；坏档不能借“兼容”改写活会话或默认补齐缺失证据。

| 包 | 分包实现状态与合同 | 可验证出口 |

| U1-b2 有利害驱离 | 有限看护、警告与驱离已实现，见[QA](../qa/20261104_source_care.md)；完整系统仍未实现 | 玩家强取/退让/趁空都按真事实结算；不打也可玩，离场世界继续 |

每包先纯规则与候选，再运行适配/UI，最后共同存读与实机。U1-b1已新增`site_affairs.gd`、`site_affair_schema.gd`并接原请求/服务适配，实际范围见[QA](../qa/20261104_source_loan.md)。不要把审批规则继续塞进`main.gd`或温石UI。

以下为原验收情景；各自实际覆盖范围见对应QA，未列出的行为仍待验证：

1. **有证不等于有货**：签下真实许可后，另一人先完成原引息；源不足时无收益、许可未虚耗，等真实补给才能再取。
2. **无证不等于不可达**：同一地隙可物理到场；看护人在可见处警告，看护不在或看不见时不全知干预。正式记录和实际取用结果仍分开。
3. **和平通路**：普通新局、原旅行/当面请求/真实温石和方法→实际用源→真实归还→现场核验，期间无伤、无战斗也能得到实质恢复。
4. **风险通路**：同一现场继续未获认可的取用→被看见/警告→原气弹/木剑/护障或逃离→真实伤势/成本→再次取用/休养。胜利无新增源量、产权或正式资格。
5. **守卫是人**：吃饭/原承诺/耗尽灵力/伤势可使其离岗或求稳；已有任务不被神秘删除，期限结束后回原自主，复返不满血满蓝重置。
6. **未知事件不读心**：隔墙起势和远区弹不触发无依据防护/HUD；旧目击只支持旧位置判断，移位后不得追读实时坐标。
7. **没有玩家也推进**：玩家去河湾时NPC继续原用源/值守/休息，收到消息之前玩家不能知道全部结果；回到现场接续原状态。
8. **并发与撤回**：两人争一次许可/一块温石/一批源量，只能各按原预约实际提交；撤回、过期、动作中断不双扣/双给，也不让旧警告重新执行。
9. **真实在途停开**：许可已签但未取、警告宽限中、用源/飞弹中途分别用普通保存；完整停止游戏进程两次，从同源档到同未来的完整联合JSON一致。记录人物/物资/伤势/许可及消息，而非只比任务stage。
10. **候选拒坏与历史**：伪造签发人/职位、引用他人的用源记录、重复消耗许可、双占用/假见证均拒绝且活会话不变；旧档无新历史，新旧反复切换通过。

实机入口用对象/事项补全和自然语言反馈表达“向谁提出何事、什么依据、还没办成的原因”；不给每条支路长期堆一排新的专用按钮。正式画面/声音后置，使用现有像素示意即可。

## 10. 何时接U2/U3

当上述两路都能实际改变资源与局势后，挑一个确实存在的障碍做U2：例如需要远处协作传递一份已登记的许可、需要特定媒介在真实狭口引息、或需要另一种方法承受同一风险。每种能力都要有本领/媒介/身体/环境条件及不同代价，不能只是增加百分比。

第一包不直接实现这些例子；尤其不能把现有“温石熟悉”“木剑熟悉”当成已经有通用学习网络。下一能力组合经过该争端验证，再带入U3的新地点和自主对手，会比先做空的千节点盘更容易看出缺口。战斗者、交涉者、懂器物者的结果可以不同，但都必须改变同一个持续世界。
