# 计划与依赖

本目录按“顶层框架交付目标→模块职责与接口→内部实现与验证”组织建设；领域划分只看[领域归属](../engineering/architecture/05-framework-domains.md)，当前能力与缺口看[技术总表](../status/technical-status.md)，实际授权看[接续](../status/handoff.md)，证据看[基线](../status/baseline.md)。

- [基础建设计划](foundation-priorities.md)：唯一的框架建设依赖、交付范围与完成标准。授权范围内持续推进，内部算法/提交不自动成为停止或再次确认边界。
- [统一运行效率方案](runtime-efficiency/README.md)：长期候选边界与原审计；已选的通用索引/环境/健康实现见[工程接口](../engineering/sparse-execution.md)和[技术总表](../status/technical-status.md)，其余迁入未自动实施。
- [世界骨架实施参考](world-foundation/README.md)：对象/生命周期/动作/装配等框架模块的内部步骤和验收口径；旧A–E编号不承担顶层排期。
- [环境首轮方案快照](environment-object-loop/README.md)：来源、缓存、响应和接管前的制定时依赖；当前Main已由后续包接管，目录中的旧“下一包/旧Q/51档”不再决定施工。
- [路线图](roadmap.md)：从基础运行到游戏玩法、内容及发行的层次关系，不再维护第二套编号队列。
- [长期产品目标](product/full-game.md)：完整世界与可玩切片的目标，尚不代表实现。
- [产品验收](product/acceptance.md)：长期出口需要什么证据，不是当前待办列表。
- [多生命沙盒](product/multiple-lives.md)：较早提出的体验目标；其中编号不决定当前顺序。

详细接口候选已移到 [specs](../specs/README.md)，固定世界规则在 [design/rules](../../design/rules/README.md)，旧样本工作包在 [历史规格](../archive/specifications/README.md)。不要因为旧页写了“下一步”就恢复施工。
