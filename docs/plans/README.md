# 计划与依赖

本目录只有一条基础框架施工顺序：[基础建设与改造计划](foundation-priorities.md)。它按“顶层框架交付目标→模块职责与接口→内部实现与验证”给出保留、改造、补齐和出口；研究、内部检查与历史收尾页不形成平行队列。领域划分只看[领域归属](../engineering/architecture/05-framework-domains.md)，当前能力与缺口看[技术总表](../status/technical-status.md)，实际授权看[接续](../status/handoff.md)，证据看[基线](../status/baseline.md)。

- [基础建设与改造计划](foundation-priorities.md)：六个交付阶段覆盖七个框架；最小行动贯穿基础承载，近期重点为共同接入、通用建筑和植物实例。授权范围内持续推进，内部算法/提交不自动成为停止或再次确认边界。
- [统一运行效率方案](runtime-efficiency/README.md)：长期候选边界与原审计；已选的通用索引/环境/健康实现见[工程接口](../engineering/sparse-execution.md)和[技术总表](../status/technical-status.md)，其余迁入未自动实施。
- [世界骨架实施参考](world-foundation/README.md)：对象/生命周期/动作/装配等模块的接入检查和验收口径；普通接入与主线收尾已归证据，不保留旧包的待办口吻。
- [环境首轮方法与历史入口](environment-object-loop/README.md)：来源、缓存、响应的原方案及对应现行工程合同；旧正文按制定时资料读取，后续环境建设回到主计划。
- [路线图](roadmap.md)：从基础运行到游戏玩法、内容及发行的层次关系，不再维护第二套编号队列。
- [长期产品目标](product/full-game.md)：完整世界与可玩切片的目标，尚不代表实现。
- [产品验收](product/acceptance.md)：长期出口需要什么证据，不是当前待办列表。
- [多生命沙盒](product/multiple-lives.md)：较早提出的体验目标；其中编号不决定当前顺序。

详细接口候选已移到 [specs](../specs/README.md)，固定世界规则在 [design/rules](../../design/rules/README.md)，旧样本工作包在 [历史规格](../archive/specifications/README.md)。不要因为旧页写了“下一步”就恢复施工。
