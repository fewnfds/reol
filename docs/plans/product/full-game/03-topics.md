# Reol 完整游戏长期开发方案：6. 里程碑与依赖

> 历史长期产品规划：阶段编号、Goal、当时状态和下一步均为成文时的建议，不是当前工作队列或实现证据。当前优先级见[基础优先级](../../foundation-priorities.md)。

## 6. 里程碑与依赖

P编号保留为领域和长期验收索引，旧M0–M5保留为历史术语，避免把已完成重标为待做。**它们不是当前排队顺序**：U0公共接缝→U1超凡冲突→U2学习/器物构筑→U3冒险/任务→U4组织/权力→U5首小时与规模；每包从开始就接远区事件和存读。P1/P2只补这些玩法需要的基础循环，不等待完整农业/产业/全建造。独立研究、内容和评审可并行，同一状态所有者不得竞相写入。

| 阶段 | 达成的玩家体验 | 核心工作包 | 依赖和出口 |
|---|---|---|---|
| P0 基础可靠性 | 当前生活能可靠保存、恢复；扩大前知道哪里慢 | 测量基线、动态世界存档、版本迁移、战斗时间原型 | 不重写已有模拟；出口F0 |
| P1 生计与生产 | 不靠初始赠币，能谋生、吃住和应对短缺 | 资源来源、有限生产、工资与本地交易、需求耗尽后果 | P0存档约定；出口F1 |
| P2 建造与经营 | 有权获得土地、安排劳动，建成一个有用的据点 | 蓝图/材料/通行、储物/生产、岗位和分配 | P1真实资源；出口F2 |
| P3 冲突与小队 | 能战斗、逃跑、受伤、救人并承担损失 | 战斗时基、伤势/医疗、武器技能、小队/俘虏 | U1优先；复用已有供给，不等P1/P2全完成；出口F3 |
| P4 修炼与一小时切片 | 一个人从杂役取得修炼和身份上的实质进展 | 功法/修炼/突破、冒险据点、动态委托、引导 | U2/U3与U1交叉；不等全生产；出口F4 |
| P5 多区经济与人口流动 | 商旅、迁居、远行有意义，留下的地方继续生活 | 动态地区装配、价格/贸易、旅行/定居、资源再生 | P0/P1/P2/P4；出口F5 |
| P6 组织与权力 | 管事/掌门通过人和制度办事，换人会改变实利 | 任免/授权、派别目标、争端处理、继任与旧账 | U4先做有限组织行动；不等完整P5市场；出口F6 |
| P7 战争与长期人生 | 多身份进入同一局势，战争、死亡与历史可以继续 | 远区冲突/补给、据点变化、人口接续、3种出身与换角 | P3/P5/P6；出口F7 |
| P8 玩法Alpha | 主要玩法已接通，持续长局能产生可理解的变化 | 内容补齐、长期稳定、平衡、信息可读与陌生人试玩 | P1–P7出口全过；出口F8 |
| P9 正式视听 | 玩法含义清楚，画面、声音和操作语言统一 | 风格样板、模块角色/建筑/地形、VFX、音效/音乐、无障碍 | F8后正式批量制作；出口F9 |
| P10 Beta与1.0 | 新电脑可安装、开始、保存、继续、完成一轮 | 缺陷清理、优化、导出、发布资料/许可/备份恢复 | P9与目标机器验收；出口F10 |

没有按日历承诺工期。一个阶段可包含很多实施轮次；完成一个工作包交出可运行构建、测试与进度记录。新发现可调整后续顺序，但不得跳过既定出口并把未解决问题埋到美术阶段。

### P0：可靠基础，先解除真实风险

- **P0.1 测量与回归固化**：独立运行当前场景，区分主线程、模拟、寻路、视野和渲染；重跑真实办事闭环。保存固定种子、硬件和测量条件。
- **P0.2 会话/世界存档边界**：给生成种子/生成器版本、探索信息、可变地形与未来建筑预留明确分区；已有持久事实仍由原模块拥有。实现当前有内容的区块，后续领域随其工作包接入。
- **P0.3 迁移与恢复**：版本化快照、最小迁移链、候选验证、坏档保留原世界、备份恢复；旧格式能迁移的显式迁移，无法可靠迁移的解释原因，禁止猜字段静默修补。
- **P0.4 时间语义试验**：在隔离最小战斗中验证细步进/分钟边界/暂停/倍速/远区消息同刻顺序。确定时间与空间单位后再写战斗正式规则；不在纯研究阶段重写所有分钟字段。

### P1：从“能花初始钱”到“能持续生活”

- **P1.1 生存后果**：饥饿、疲劳、休息和健康的有限状态；缺食有预警与救济/求助/离开路径，不用心情条替代全部行为。
- **P1.2 资源与生产**：有数量/产出周期的采集点、田地和至少两条加工链；输入→劳动/工具→产物，库存预约与失败释放复用现有账本。可堆叠耗材继续按数量记；需追踪使用/损坏的工具采用实例ID，装备/携带/出售不能重复占有。
- **P1.3 劳动收入**：雇主有预算、真实需求、验收和工资；贡献奖励与现金工资分别记录，重复交付不能重复领奖。
- **P1.4 本地交易与救济**：真实卖方库存、钱包和需求；卖出资源→支付食宿/购买工具→继续生产。商人无钱时能拒收/换物，不能无限收垃圾。
- **P1.5 有限自主计划**：短缺→选择生产/采购/雇工→执行/验收的两三步计划及有预算的需求发单。玩家不介入也有人尝试解决；按事件和失败重评，不引入无限规划器。P4再扩到寻材、修炼与冒险。

### P2：建造确实改变生活

- **P2.1 土地与施工**：使用权/侵占、占地预览、蓝图、材料预约、运送、施工与取消；落地时再查地形和通行，不在点击时凭空完工。
- **P2.2 据点闭环**：住处、仓储、田地/药圃、灶/工位；简单封闭房间与用途判定，设施受损/不可达有后果。
- **P2.3 劳动组织**：工作优先级、排班/工单、岗位能力与允许区域；自有/雇用/同门的指挥权限不同，人员过劳、缺薪或职责冲突可拒绝/离职。
- **P2.4 经营分配**：公私库存、口粮/工钱/贡献、维护与补给。代理人可负责常务，玩家出门不需要每分钟远程点按钮。

### P3：冲突产生损失和后续

- **P3.1 最小战斗**：目标选择、走位/招架/身法、前摇/作用/后摇与取消、近战/远程、施法/打断、伤害与战斗结束；按[动作设计](../../../../design/systems/combat_framework.md)先小场景验证，规则与表现分开。离场后原纯规则战斗上下文继续无头细算、可重入/存读，P7才增加高效粗算；不能中间冻结。
- **P3.2 人员后果**：伤势、倒地/死亡、治疗材料与照护、负重/战利品保管；同样适用于 NPC。武器/穿戴沿用工具实例与唯一保管规则；死亡当包交付动作/预约/背包/承诺/职位空缺清理，并提供最小临时代办或空缺冻结及基本生活替代路径；公账债务不能随人删除，复杂争议继任留P6。
- **P3.3 小队意图**：跟随、保持距离、集火/护送/撤退；战斗快进回1倍，暂停可下令，危险有预警。
- **P3.4 败而不灭**：求饶、缴械、俘虏或逃脱至少形成一种可继续的败战；世界不得为惩罚玩家额外生成无来源追兵。

### P4：修仙成为改变策略的成长

- **P4.1 功法与训练**：资质作为倾向、功法作为选择、修炼消耗时间和供给，师承/秘本有实际获得渠道；按[修行网络](../../../../design/systems/cultivation_and_learning.md)先12节点再扩候选40节点，生活与战斗本领都可成长；不能用职业锁定、杀怪通用点数或装备孔自动授技替代学习。
- **P4.2 突破与修养**：材料、环境、认知/准备、风险和伤后恢复；NPC同样可以寻材、错过机会、突破或失败。具体概率通过场景校准。
- **P4.3 冒险与委托**：一个后山资源/秘境、一个敌对据点、至少两种解决途径；委托来自欠缺/冲突，也保留少量精写入门剧情。
- **P4.4 一小时切片**：工作谋生→认识人物→争取资源/授权→修炼/突破→冒险或经营解决短缺→得到身份变化；完整存读，离场后两聚落继续变化。独立Windows试验包验证中文界面/字体分发与正常操作；正式大规模资源尚不投入。
- **P4.5 可操作的交涉**：人物会话中用模板选工作/物品、报酬、期限、风险与担保等适用条件；附条件回应后能实际修改提议并履约。提议按当事人所知形成，只有结构合法性/已确知硬条件可提前拒绝，秘密真值留执行时复核；P6复用此入口办旧账，而非只增加调试API。

### P5：走出去仍是同一个世界

- **P5.1 动态地区装配与生成**：消除仅home/river才能运行的装配假设；地区ID与全局格/路径层级明确，首区512×512不变成整个宇宙硬上限。按资源/道路/聚落/秘境约束生成并校验种子，确保三种起点可达基本食宿、生计和核心材料链；失败有限重试/可诊断回退，不生成不可玩的随机空地。
- **P5.2 区域贸易**：地区生产优势、有限需求、价格报价、路线时间/损失/补给；至少能靠一次有风险的商旅取得净收益，也可能亏损。
- **P5.3 人物旅行与迁居**：出发/在途/抵达/住址/工作转移；带走原身体、背包、知识与未结责任；迁居不在两地各生一人。
- **P5.4 人口与资源容量**：资源再生、就业/食宿容量、迁入迁出和新人来源；新增者有来历，招募/迁入不凭空附赠无限物资。

### P6：组织是可行动的人与制度

- **P6.1 职位与办事**：职责、任期/任免、授权委托、代签范围、分配和审计；制度记录的存在、承认和执行各有条件。
- **P6.2 内部差异**：少量有实际资源基础的利益团体与议题；行动由成员、预算和消息触发，不能只有抽象派系支持分。
- **P6.3 争端与继任**：调解/查账/裁决/私下交易/暴力升级；候选人有资格、支持、能力和控制条件。原继任算法仅作候选实现，先让场景结果正确。
- **P6.4 旧账与新局**：公账/私情、任职更替、履行成本、证据、担保与反制；实现“礼数仍在，收益可能拿不到”，同时给玩家申诉、找见证、谈判或离开的动作。

### P7：战争、时间和不同人生

- **P7.1 有目的的冲突**：目标、动员、成员、粮饷、行军、交战、撤退和谈和；有补给约束与事后恢复，不让所有组织永远打到灭亡。
- **P7.2 远区战斗**：同一参战名单、装备/健康/补给/地形条件和随机上下文；交接只改变算法精度，不重掷既成结果。近远不承诺逐位同轨，但战略倾向与资源/伤亡约束必须一致。
- **P7.3 人口与历史接续**：NPC寿命、死亡、接班、招聘/成年迁入的有限来源；重要事实归档，未结权利和义务保留，私人秘密不因死者消失变公共。
- **P7.4 多出身与有限转生**：多起点验证不同生活；同局主角通过有限次数的新生候选转生，范围不限人类、世界不回滚，机会耗尽结束本局。主角记忆连续与新身体成长分开，财产/贡献/权利不自动继承；加入出生来源、候选域/档位、有限刷新与防筛选测试。普通存读另行保留，不用退隐或免费新人绕过预算。详细规则以rebirth_and_new_lives为准。

### P8：玩法冻结前的系统验收

- **P8.1 完整内容通路**：三起点、三可玩境界、生活/经营/冒险的转向均可用；没有“菜单能点但规则未接”的假功能。
- **P8.2 长局与经济调参**：多种子30/365游戏日、多次切区/存读；增加临界寿命、任期/债务到期、待压缩证据的短fixture，并至少一个小人口10年以上推进案例。更长时间作降密度压力测试，检查饥荒、人口崩溃、钱粮膨胀、垄断死局、永战；不把未跨寿命边界的365日测试当世代已验。
- **P8.3 解释与恢复**：每种关键拒绝/失败/停工都有可查原因与下一步；历史能解释地区变化，开发者全知不进入玩家UI。
- **P8.4 玩法Alpha出口**：先完成作者自测，再做至少3轮陌生人任务试玩；问题形成工作包。没有用户在场也能完成自动和作者验收，但不能把作者自测冒称陌生人试玩。

### P9：正式美术与声音

- **P9.1 风格样板**：同一小场景验证草地/水/山、一个建筑、三人物、战斗效果和界面；色盘、像素密度、方向、光照和缩放一致后扩量。
- **P9.2 模块资源**：角色按身体/衣物/装备组合，设施按用途/等级/损坏组合；代码绘制、图集和可商用许可素材混用，以可读性和一致性取舍。
- **P9.3 反馈与音频**：命中/施法/受伤/施工/交付、环境音、音乐分层、音量总线和静音；反馈不改变真值，快进和批算不会播放成百上千个过时音效。
- **P9.4 素材交付**：每包有原许可、来源/版本/哈希、修改与署名；正式字体、音效、音乐同样核对，打包验证缺图/乱码/漏许可。

### P10：可发布构建

- **P10.1 性能与容量**：在记录的目标Windows机器、独立窗口/导出包测量；优化实测热点，保持规则不变量。失败先缩规模，不更换技术栈碰运气。
- **P10.2 存档与长稳**：更新前后迁移、断写/备份恢复、长局、损坏输入、异常退出后的恢复体验；固定支持版本，退出支持要明确说明。
- **P10.3 发布**：导出预设、版本号、说明、操作/新手教程、资源许可清单、已知限制；项目自身许可证及商业发行主体需用户在发布前决定，不阻塞玩法开发。
- **P10.4 1.0出口**：F0–F10验收通过，已知严重缺陷清零；可用正常操作从新档完成三种起点的核心通路，无开发工具依赖。
