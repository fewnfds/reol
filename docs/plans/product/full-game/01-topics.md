> 历史长期产品规划：阶段编号、Goal、当时状态和下一步均为成文时的建议，不是当前工作队列或实现证据。当前优先级见[基础优先级](../../foundation-priorities.md)。

## 1. 要做成什么游戏

一个以修士、妖魔、侠客和领袖等超凡者为主要成长方向的修仙沙盒，可以独行、创造、交往、冒险或经营组织。玩家与NPC处在同一套世界规则里：有自己的认识和目的，占用真实时间与物资；组织依靠成员、资产、制度和外部关系存在。凡人生产先提供可信的补给循环，不以复杂农务挤压修行、功法、战斗和世界冒险。玩家离开、失败或换身份，世界仍能接着运行。

完整游戏应支持三种相互连通的重心，而不是三个割裂的模式：

- **亲历**：一个人的生活、修炼、冒险、交往、受伤、谋生与选择。
- **经营**：有权限地安排劳动、设施、生产和分配；经营洞府、农庄、商队或宗门。
- **局势**：生产与贸易形成依赖，竞争与争端改变道路、人口、权力和机会；玩家可介入，也可离开。

这些体验通过资源、人物、信息、权利、时间互相连接。例如：宗门缺药→药师求购→商人组织采药→道路遇匪→护卫受伤→供给变少→弟子争夺分配→管事需要处理。每一步有原因、行动者和可改变的条件，不用一条“势力发展度”同时决定所有结果。

**完成目标是可持续游玩的有限世界，不承诺把所有参考游戏的内容总量相加。** 第一版完整游戏先让一套地区生活成立，再扩地貌、境界与生活方式。人类、鸟妖、寄魂者和古兽等应以不同处境检验共同规则，不能因旧预算默认三种人类出身而永久排除；逐步实现的具体范围按W包原型与试玩确定。切片中的“暂不做战争、建造、多出身”是旧阶段范围，不是永久禁止。

## 2. 现有基础与缺口

当前可复用的代码边界见[ARCHITECTURE](../../../engineering/architecture.md)，各项可玩范围见[FEATURES](../../../status/features.md)。本表仅说明接续，避免沿用初稿中已过时的“探索未保存/仍分钟轴”等判断。

| 已有基础 | 可继续复用 | 尚未完成 |
|---|---|---|
| 生活/库存/服务/有限来源 | 真实劳动、预约/携回/交付、报工/兑换、互助/托管与三日供给样本 | 农业、市场、产业、通用产权与健康后果 |
| 社会记忆/机构/临时放行 | 有向关系、所知来源、请求判断、个人采信与正式记录分离 | 通用信念、物理账本、组织治理/司法/继任 |
| 区域调度/共同毫秒 | 双聚落连续日常/运输/消息、手动/自动路线、有限短动作 | 任意规模、多区生成、迁居/战役 |
| 主体/器物/鸟/魂 | 真实载体引用、温石跨用途/裂损、人鸟魂短开局与控制边界 | 通用实体/作用、植物/古兽真实生活、完整种族/修行/创造 |
| 联合存读/探索/迁移 | 一致取样、独立候选校验、原子文件、真实历史档接续 | 后续建筑/地形改造/伤亡/出生等领域随实现接入 |
| 世界/实体/UI | 当前地形/视野、有限可知面板与呈现 | 规模/长稳、正式视听、顺滑战斗和独立发布 |
| 隔离继任resolver | 两阶段算法原型与反例 | 实际掌门更替/逐账执行，权重仍需场景验证 |

不重做contribution删除、MCP/目录迁移、Demo重构或双聚落骨架。按真实场景抽取小模块，不继续把所有业务塞入大型Simulation/Runtime。

## 3. 用什么标准取舍

最新取舍优先于下列旧阶段举例：能改变超凡者的行动方法、成长、冒险或组织局势的规则优先；普通生产做到来源/劳动/消耗/恢复成立即可。装备与法器可以复杂，衣着的独立社会/生活价值同时保留。用户对《修仙模拟器》重种田轻修仙的评价作为本作方向警示，不在研究中冒充客观测量结论。

1. **先解释过程，再使用数值。** 内部允许需求、价格、关系估计与成功率；必须能追溯来源、作用对象、适用范围与实际执行者。
2. **玩家与 NPC 共用成本与后果。** 玩家可以更会规划，不能靠切换视角复制粮食、免除受伤或赋予组织全知。不同 AI 可以简化推理，规则权利不能凭空改变。
3. **命令需要权限，承诺需要履行。** 熟人可拒绝，雇工可辞职，掌门也不能让空仓发粮；制度的承认和实际强制力分别表达。
4. **有限认知。** 事实、亲历、转述、机构记录和玩家笔记分开；远方变化通过人、信件或渠道被知道。
5. **失败继续产生选择。** 缺粮、败战、受伤、失职、流亡都要有后续路径；避免每个失败都迫使读档。
6. **精度改变，责任不断。** 近处行动，远处批算；同一人物、同批货物、同份合同和同个时间线不能有两套真值。
7. **新机制必须产生选择。** 无法改变行动成本、风险、机会或关系的复杂度先删去。
8. **先玩法后正式资源。** 玩法开发仍需清楚的按钮、轮廓、预警和战斗反馈；整套美术、音乐、装饰与宣传资源放在玩法闭环后制作。
9. **本领与穿搭各有价值。** 修行网涵盖战斗、生活与协作，出身不锁职业；衣物的外观、用途、防护和社会识别分别成立，不能把非战斗人生变成刷满攻击装备的前置任务。
10. **先让众生生活，再调平衡。** 身体/载体、所知、目的与关系产生可行办法；同一作用能跨场合使用。允许强弱悬殊，优先修复复制、全知、离场重置和因果矛盾；固定面板与人形槽位不决定全部世界存在。

本次基础架构review补充[环境E0–E6](../../../../design/proposals/environment.md)与[真八向外观A1](../../../specs/presentation/eight-directions.md)。基础四季/冷热、五行用途和局地堪舆纳入世界分步建设；下表后续扩展中的复杂温度/风水仍指完整精算与海量组合，不排除这些基础子集。所有不对称外观需独立方向/身体左右/动作遮挡合同，普通四向镜像素材不能代替。均未因方案写成而实现。

## 4. 推荐的完整1.0边界

以下是执行规划的**推荐默认值，尚非用户逐项拍板**。容量是测试档和内容预算，不是当前性能承诺。发生瓶颈先减少密度和无价值更新，再讨论扩大。

| 维度 | 1.0推荐范围 | 后续扩展 |
|---|---|---|
| 世界 | 有边界、可重复种子的地区世界；12–24个模拟区、约12个聚落/据点；道路、野地、资源点和少量秘境 | 更大地图、新气候、跨海与地下世界 |
| 社会 | 3–5个主要组织，组织内有职位、利益差异和对外依赖；个人可多重隶属 | 大型国家行政、多层法域、复杂宗族谱系 |
| 人口 | 300–600个持久人物目标；本地最多约60名，战斗先20–30名；大队伍以有名单的群组处理 | 千人以上目标须独立验证，不作为1.0前提 |
| 出身 | 宗门杂役、自由散修、小聚落经营者3个开局；共享同一个世界 | 更多遭遇式开局和职业专属篇章 |
| 生计 | 工作报酬、采集、农业、少量加工、交易与运输；组织不能无限发钱或发粮 | 完整金融、期货、复杂税制 |
| 建造 | 土地/使用权、蓝图、材料、劳动、通行、储物与简单房间用途；一个自营据点 | 城市美学、复杂水利/温度/结构力学 |
| 修炼 | 炼气、筑基、金丹三个可玩层次；无职业学习网络、功法/招式/生活本领组合、准备/运转、突破与师承 | 更多境界、完整飞升、极多秘传与大型图内容 |
| 战斗 | 实时可暂停；小队、撤退、士气、伤势、救治、俘虏与简单据点攻防 | 全面战争级千人实时会战、复杂攻城机械 |
| 穿戴 | 分层纸娃娃、真实物品/衣着/持物、用途/防护/借用、有限外观观察与身份核验 | 海量动作服饰、复杂隐形/幻化、无限嵌套容器 |
| 工艺 | 种植→食物、药材→基础丹药、矿料→基础装备；每条少量有差别的配方 | 百种材料、复杂炼器/风水/阵法组合 |
| 政治 | 任免、分配、利益冲突、继任、旧账处理、谈判/制裁/冲突 | 全套诉讼、自动阴谋策划、议会模拟 |
| 长线 | 生计→自立→掌握一项生产或武力优势→对组织/地区产生影响；角色可死亡，世界可用新身份接续 | 完整血缘遗传、育儿、跨世修行 |
| 内容 | 每种起点有成立的前30分钟；至少一轮约5–10小时具有不同选择的完整历程，再以长局测试证明循环可持续 | 这个时长是试玩校准目标，不用重复劳动强行填满 |
| 发布 | Windows独立包，离线运行，常规存读、多槽/自动备份、可理解的新手引导 | 联机、云账号、模组API、跨平台同时首发 |

高境界人物若出现在背景，仍须有行程、立场和可理解的行动边界；不得把“世界强者”写成堵住全部出路的无敌脚本。正邪是教义、行为、利益和组织立场的差异，不是全世界统一的道德分。
