# 源场接管实际环境的实施合同（F2）

更新：2026-11-05。本页是待实施的具体接入合同，不代表新源场已成为游戏世界规则。现状与证据以 [HANDOFF](../HANDOFF.md)、[BASELINE](../BASELINE.md)、[FEATURES](../FEATURES.md) 为准；空间/冷热/五行概念以 [环境规范](world_environment.md) 和 [施工与空间](../../design/systems/construction_and_space.md) 为准。本合同不覆盖普通场同通道取最大值、欧氏圆形衰减、同类一堆一源、人物及随身物五行暂缓等已定规则。

实施状态：F2a-1已完成少量显式格/已知目标段的实际温度owner及独立存读，见[证据](../qa/20261105_actual_temperature_state.md)；源变更事务和完整调度仍未完成，不能把这一步标为整个F2a或Main替换完成。

后续F2a-2已完成纯目标段编译与O(1)下一边界查询，见[证据和误差/成本界](../qa/20261105_temperature_segments_and_budget.md)。实际温度16384格整批prepare/commit约198/500ms，故当前逐格对象表示不作为密集世界的最终运行承诺；先解决紧凑/有界处理，再接Main。完整调度、源事务和房间仍未完成。

## 现有依赖与切换原则

- 当前普通世界仍由 [`RegionalSimulation`](../../scripts/sim/regional_simulation.gd) 持有 `local_heat`；其 `advance_to_ms` 在推进人物/区域前调用 `can_settle_at_ms(next_ms)`，然后以既定同毫秒顺序结上一段、处理到达/器物/施工、人体环境分钟采样、草木采样与后续行动。新系统要替换这些入口，不能在 `_process` 上另跑一份物理时钟。
- [`SimLocalHeat`](../../scripts/sim/local_heat.gd) 现在拥有 Q、来源收据、冻结流、热样本和累计账；[`SimEnvironment`](../../scripts/sim/environment.gd) 每分钟沿原场采样并缓存人体负担，草木在 `RegionalSimulation._sample_herb_conditions` 单独取其分钟环境。`SimLocalLight` 还通过 `device_emission_rates` 引用火石放热率；器物动作、施工前后钩子及存档候选均直接依赖旧域。上述调用必须作为同一替换包的一部分迁走，不保留看似“新环境”却仍持续推进旧 Q 的主局。
- 当前根档 **50**、区域 **41**、环境 **3**、热定义/状态 **3**、器物 **8**、climate **2**。新内容/状态须使用新版本与保存包 digest，最终只写一种新格式；编号落地时取当前值的下一个，旧格式仅在明确声明的有限导入边界被接受，不把版本号当运行完成的证据。
- `environment_field_rules/index/cache/tide/response` 是已写出的隔离核和候选基础；CPU/GPU 数值、线程交接和规模结论只能引用对应版本的实测证据。GPU、缓存、气候查询和视图都只是派生结果，不拥有物品、真实温度或共同时间。GPU 不可用或工作未完成时，使用等价的有界 CPU 路径；均未完成则显式 pending，不能把占位零值当环境事实。
- 适度拆为 **三包**：F2a 先完成与真实物件/场索引可联测的实际温度所有者及独立存读；F2b 将普通 Main 一次性切到该所有者和新规则；F2c 补真实房温与拓扑事务并收束遗留。F2a 不是第二套上线运行世界，F2b 的验收包含旧路径退役检查，F2c 不允许将旧 Q 再接回来。

## F2a：实际温度所有者、边界与独立存读

**责任。** 在 `scripts/sim/` 新建唯一环境状态域，具体文件名由实施确定；规则的纯几何/等级转换继续复用现有纯核。域按空间坐标持久化室外必要的实际温度、锚定共同时间与可恢复的响应段；默认无来源、无残留格可共享气候中性曲线而不逐格建对象。当前真实温度可用一次纯闭式或有限表求值；投影不推进时间，真实事件边界由 `RegionalSimulation` 调度。受体、本体、场缓存、房间划分均不能各自保存一份可独立变化的真实温度。

**最小接口。** 提供显式成功/原因的 `actual_at(cell, at_ms)`、`prepare_change(old_new_areas, at_ms, budget)`、`commit_change(...)`、`next_boundary_ms()`、`snapshot/restore`；接口名称以最终代码为准。读取欠算、无效位置、超出可证明时间范围或未完成场缓存时返回 pending/unsupported，不产生看似可用的温度。`prepare_change` 在物件移动、开关、生成/移除及施工提交前，先准备旧/新各自覆盖区、对旧目标结到事件时刻，核预算和数值范围，再由原动作域无 yield 提交真实物件变更与新目标；失败不扣新成本、不改原物或环境。覆盖区各自裁剪、去重，不用跨地图移动的外包矩形把中间全图标脏。

**响应和时间。** 对一个没有其它边界的已知目标段，选择明确版本化参数及固定曲线表或常数次闭式，使实际值从已保存锚点向目标趋近。普通场只需端点查询，不要求为每格保存积分；人体与植物沿现有分钟采样持有上一分钟速率。温火石一次脉冲是实际事件：在原动作/费用完整预检后，按版本化强度规则一次性改变该处实际响应起值，随后残留是环境状态，不是持续场源；仅成功支付一次、同一动作不会重放第二次。

目标由当地中性气候与 `H−C`、共享环境端潮汐和等级温度表共同决定。气候原有整数十分度与天气边界、潮汐三角波拐点、等级映射分段、来源/拓扑变化都要考虑；不能只用快进末端目标代表整段。首版可固定世界时间量化格点并持有每段目标：例如潮汐每 1000 游戏毫秒采样一次，区间 `[k·1000,(k+1)·1000)` 持有该区间起点的倍率；天气/气候发生更早真实边界时立即结旧段，但仍沿当前全局格点的潮汐倍率而不因额外边界重新采样。默认周期 600000 ms 时，三角倍率连续理论值相对于持值的误差上限为 `20000/300000×1000 + 1 ≈ 68` 百万分之一，最后 `+1` 是整数倍率量化；其他周期应根据实际斜率重算，而不是套这个上限。净等级整数舍入和非线性温度表可能放大温差：按该段 `|H−C|`、最坏倍率误差、查表相邻斜率及温度定点舍入计算**每个受支持等级范围的上界**，不得把倍率误差直接宣称为摄氏误差；若当前 `Rules.MAX_GRADE_MILLI` 映射超出现有 response 的 `MAX_ABS_VALUE`，先统一受支持数值界或明确拒绝而不截断。若定量证明过高，缩小时间格点/幅度或选解析段；这是可测平衡参数。每秒全区逐格调度只是精度示例，并非性能通过的方案；可对稳定段做等价表/批计算且保留边界，或换有证误差的解析实现，不能为省成本只采末点。

这些格点是规则分段，不要求为每个物件/每格创建 Timer。任意外部推进切分不改变共同规则边界：临时查询不得改锚点，真正目标/气候边界结段，测试同输入 `advance(A→C)` 与 `advance(A→B→C)`、快进跨多个潮汐/天气边界、同刻移除/变更和存读后的未来。闭式浮点若不同平台非逐位一致，应先声明同平台保存一致和跨平台的定量误差上界，并测 0.1°C 人体阈值附近的行为；不能因反复外部调用反复舍入而制造可利用差异。跨时段精确温度积分不是本包出口；确需连续积分的未来炼丹/修炼过程另给自己的可证误差合同，不能冒称已实现。

预算不足时保留旧实际状态、未完成范围、共同 `target_ms` 和待处理边界；不同线程/显卡返回结果只有原世界/原 revision 的完整块可提交。当前保存不能表达共同时间欠算时，沿现有 `ERR_BUSY` 拒绝写入并保护主档/备份，直到某个新格式明确、完整地持久化并验证积压为止；不能把待算标为完成。按 `SimEnvironment` 既有分钟次序，在旧身体速率结完、本时刻真实事件完成后冻结人体样本，草木沿自身采样规则取同一实际温度，保持旧样本作为过去事实而不从当前源场倒算。未来投影只在目标/气候边界和位置均有证据时成功，否则返回范围/未知。

**独立验收。** 小图与 F0 精确源场对照；源开关/移动、负温/极值、无源回归、同刻取消与脉冲单扣；缓存未就绪和预算不足不推进错误时间；量化误差、分段/重启同未来；坏状态/不支持格式构建候选失败时原对象、时间、原档和活世界不变。暂不声明普通主局已切换或完整房间已实现。

## F2b：普通 Main 一次切换、有限旧档导入

1. **定义与来源。** 在版本化内容中明确每个已接入地面物/植物/结构的五行来源定义、冷热能力等级/半径与启用条件；没有通用物品实例/地面堆时只标明当前已接类型，不以孤立样本冒称“万物均已登记”。数量兼容的同类一堆一源，异类铺开依赖真实生成/掉落域，不能仅在场缓存伪造堆或改变原物数量。原 `SimArtifacts` 保存 `enabled`、位置、`stored_q` 与动作；固定火/寒石的**普通持续辐射不消费 `stored_q`，寒石也不把环境影响凭空存回它**。启用行动如果原定义要求灵气和时间仍支付；`stored_q` 保留为原物的可花储量，后续明确用途，旧档不得重置、充满或删除它。将旧定义里的 `rate_q_per_ms`、有限余热说明与 `thermal_exchange` 解释迁到新版能力，不误导玩家说持续辐射靠扣储量。成功启停/取放仍只修改原物一次，是否允许启用时搬动需接通原跨格时间事务后再放开；不借位置查询倒推过去。
2. **保留不同动作含义。** `warm_stone` 的 `warm` 仍是需要实际物件、本人方法、时间和一次 `warming_charge` 的有限脉冲，并与行动 `warmed` 事件一一对应；不能把它重解释为常开永久源，也不能再维护旧 Q 收支充当实际环境。寒/火石源与这次付费脉冲分别是持续目标和一次起值变化，均通过共同时间边界提交。
3. **照明接缝。** 当前 `SimLocalLight` 从旧 Q 的 `device_emission_rates` 取火石光，切换时改从同一个已启用且实际可定位的原火石照明能力派生；亮度规则在新版定义里明确，不能继续读取已退役 Q 出流或复制器物。固有携物光原能力保持，认识/视野、遮挡和加载失败仍按原接口约束；光不扣 `stored_q`。既有历史档若档内没有照明能力不能按现行磁盘内容补发。
4. **联合迁入。** 根 50 的支持入口先以其原内容/digest、地图、结构、器物、在途行动、热 Q/收据/样本/身体与草木，在**独立旧候选**完成严格校验；不借当前活局或新开局补物/知识/资源。按保存时刻 `t_save` 对每个旧已分配格取旧模型在该时刻可验证的实际绝对温度：旧 `current_tenths` 是相对于气候的偏量，须与该格保存时刻的原背景合成；也可直接按旧 Q 参考值转换，两个路径按旧整数舍入规则交叉核对。旧 Q 内不到 0.1°C 的余量虽然不能由 `current_tenths` 显示，却可能影响未来；以 `reference_tenths + Q/capacity_per_tenth` 的完整有理值，或等价的保存精度作为新锚点，而不是先向下取整再丢余量。新数值编码对该值的有界舍入误差须声明、验证，不能默称逐位守恒旧 Q。未分配格保留原气候中性，不凭空建立受影响状态。低于绝对零、非有限、缺失/冲突、时间未结、不能证明的源/受体则拒绝整个候选，**不得 clamp、清空残留或改写输入**。沿旧内容做显式版本化定义转换、重算 digest，不从当前磁盘替换旧设定。已有在途 warm/enable、旧实际余额和已结算成本保留：之后仅按新规则完成一次，迁入时不预付也不补发动作。

   人体/草木上一次真实样本、动作与收据先按旧模型核验；转换后保留其采样时刻与当时读数作为过去事实，建立新模型在 `t_save` 的实际锚点，不用新场反推旧样本或伪造历史。将旧收据中仍用于验证“温石已支付一次”的必要事实转换为紧凑的原动作凭证/受体历史；旧 `continuous_input`、`absorbed_energy`、`ambient_in`、`loss_energy`、冻流和守恒校验仅供旧候选验证，不变成新世界的余额或持续时钟。完整新候选再次核内容、真实对象、结构、在途、采样及导航后，才可替换活世界。历史原档、fixture只读。旧于 50 的输入是否继续支持须先经当时明确可用的有限导入到**真实经过校验的 50**，不得把旧标签直接改成 50；如不能在无长期旧执行器下维持其正确验证，则按兼容政策明确收缩并留下历史证据，而不静默接受。
5. **主运行替换。** `RegionalSimulation` 的装配、`_next_boundary`、推进预检、结算、样本、`to_dict/restore`、`SimEnvironment` 与植物读数、器物动作、`construction` 事务和 `local_light` 一并转到新域。一次普通新局与已声明的旧档导入均只推进新温度所有者；独立旧候选仅在有限导入期存在，不能发布成可游玩第二套世界。根格式/区域/环境/器物及内容版本按实际更改递增，版本和字段校验以代码确认；不依靠“旧数据没有字段就填默认”掩盖不同世界法则。

**真正普通 Main 出口。** 玩家在正常新局找到并启用固定冷热源、关闭后移动再放置合规源并重新启用、进行一次温火石付费脉冲，能从同一物件动作、场和实际温度观察逐渐建立/回归；启用中搬动只有在跨格事务实际接通后才作为额外出口。人体与药草取该温度，同步已有有限认知。保存含动作在途和残留、完全退出进程、普通加载后续同一未来；再完成真实根 50 迁入、离场/返回、失败加载不改原活局与未完成场工作保护。旧 Q 上的原测试作为历史/有限导入验证，新的普通行为测试不能只测纯核；最终提交对应 SHA 的完整 CI 或一次本机完整 check。源场/热环境是基础组件，不称完整沙盒完成。

## F2c：房间一温、拓扑与旧核退役收束

- 围合与覆顶必须按真实结构推导：当前 `SimConstruction` 的有限工地区域和 `SimWorkplaces` 固定开局房只是起点，不假定已有任意大地图完整房间。新增有界几何查询支持四邻围合、门独立开关和屋顶覆盖；空间归属可重建，但实际房温/锚点属于唯一环境域。功能室依然由人、实物与过程组成，不能由房名自动生成能力。
- 封闭且符合覆顶条件的房间只有一个实际温度。每个房内地块分别取当前冷热源最大值并得净等级，再按实际地面面积平均净等级；普通家具占据的格仍在分母中，火/冰墙作为原结构来源参与，随后房间只乘一次其固定锚点潮汐、查表成目标。门开关使用有限漏热预设，初版不建逐墙热流网络；“开门”与“拆除分隔墙合房”是不同事实。五行场仍可逐格，不强制全房同值。
- 变更前将受影响室外格/旧房按旧目标结到同一事件时刻，完整预检新结构、连带塌顶、物料/空间与全部新空间映射；分房继承旧实际温度，合房以覆盖面积加权平均**旧实际温度**，开敞转室外以旧室温作为相关格的起值，之后才开始趋向新目标。合房瞬时均匀是明确近似；共享墙引用一个原实物，不能双发材料/掉落。失败不扣新增成本或更改任何结构/温度，预算不足保积压；重排房间编号不能错绑持久状态，恢复时须用空间归属及结构独立校验。
- F2b 主路径已经不再运行旧 Q；F2c 的结构/受体/历史导入用例全部通过后，删除只服务旧运行的热流、冻流、分组、压缩和 Q 账接口，有限旧档校验/转换留在 persistence 的有界只读导入边界，不能把原 `SimLocalHeat` 当第二个可推进世界域长期载入。删除前逐引用清点 `thermal_schema/history/sample`、`ThermalImport`、构造工地、照明、身体/草木样本与原测试；若某旧入口仍必须跑完整旧求解器才可验证，先明确其有限支持、真实旧档和退役替代，不能为了删除静默放宽校验。历史数据与 fixture 不改写。
- 房间/开门/拆墙分合、火墙/普通家具分母、源覆盖跨房、原生真实建造/观察、进行中材料成本和停开同未来通过后，更新 FEATURES/BASELINE 为实际范围；1024²/2048² 每格来源的分块 CPU/GPU、对象与房屋联合预算分别记录。不能用单次 GPU 静态图、纯规则数量、全图缓存读或房屋名称替代完整世界规模证明。

## 执行顺序与退出

F2a 先落实可存读与可拒绝边界；F2b 再一次接入普通运行与旧档转换，避免上线双引擎；F2c 把房温/拓扑补成明确可用合同并清旧依赖。每包由主代理协调定向测试、需要时真实画面和版本审查；最终仍需编辑→新局→实际改造→离场返回→保存完全停开重启、长时间/密集场受限性能及准确 SHA 回归。以上是开发计划和验收门槛，未交付的项目不应在功能清单标为已完成。
