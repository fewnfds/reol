# 世界先行：多种生活与组合交互工作包

方案成文：2026-11-02；本文保留多种生命与组合交互的目标/验收，已有若干有限样本，不能整包视为全部实现。功能与证据见[FEATURES](../FEATURES.md)/[BASELINE](../BASELINE.md)；现优先平面世界引擎，[执行顺序和暂停状态](world_engine_execution.md)优先于这里的W编号和历史下一包。

W0主体/载体/控制首步、W1温石两用途/NPC有限办法、W2真实雀妖与玩家开局、W3个人理解/请人检查/裂损、W4独立寄魂者与玩家残识、W5-a口头资格/私人核验/一次取药已有有限交付；共同毫秒、有限自然来源与当前呈现复查也已接。W6已有有限温养试验/教学与[实物记录传播](method_records.md)，W7-a已有[真实3×3尺度样本](large_bodies.md)。各包完整出口、W7共同灾害/五种主体演练仍待做。旧“全待实施/时间仍分钟/非人仅代用品”不再描述当前游戏。

规则入口：[世界总纲](../../design/systems/self_consistent_world.md)、[众生](../../design/systems/beings_and_lifeways.md)、[知识/法器/创法](../../design/systems/knowledge_artifacts_and_invention.md)、[人物视角](../../design/systems/perception_and_understanding.md)。[交互原则](../../design/systems/world_interaction_principles.md)补充环境、组织、策略与无AI可玩；环境已有若干有限首包，通用组织/策略等仍待完成，不能整篇视为已实施。正式人生接续依[有限转生](../../design/systems/rebirth_and_new_lives.md)，需出生/成长和有限候选同包，不能把三开局当成已完成转生。

以下保留各工作包原验收意图；是否通过逐项看实际工作包/QA，不从未来场景文字推断当前能力。

## 1. 方向与目标验收

目标：让不同生命与不同选择都能在同一世界成立，而不是先把战斗、刷取和建造各做一套再拼接。

体验：玩家能发现跨用途做法；一个解决办法迁移到另一处仍有用；世界对新做法作出持续、可理解的反应。

范围：以共同契约、样本场景、接入路径与未来测试组织实施。Goal现暂停，原W/U排列保留为领域参考；不安装未经授权的依赖，不把全部未来样本当当前前置。

设计验收：用户提出的《骗经》、认不出/驾驭不了宝物、反噬、戒中老人、创法、麻雀、古兽均有明确因果、操作入口与失败后续；旧人形默认不再作为通用宇宙规则。

## 2. 与已有长期计划如何接续

保留[P0可靠基础](world_foundation.md)的测量、存档和共同时间工作，但不再把“完整建造→完整战斗→人类修炼完成”当检验非人主体与知识创造的前提。

W包是跨长期阶段的**前置样本验证**：只提前做足够回答架构问题的一小段，验证后再回到P1–P8生产、经营、战斗、组织、战争与长局内容。完整游戏范围仍见[长期方案](full_game_program.md)，先后安排以[世界引擎执行记录](world_engine_execution.md)为准。

建议顺序：P0相关契约/测量 → W0 → W1 → W2 → W3 → W4 → W5 → W6 → W7。每次只实施一个可验证小任务；不同时迁移所有主体、库存、时间与存档。

| 工作包 | 回答的问题 | 依赖与出口 |
|---|---|---|
| W0 共同身份与执行契约 | 人形假设在哪里，怎样接新存在而不破坏旧Demo | 读当前代码并固化回归；只迁移后续实际需要的接口 |
| W1 对象与跨用途作用 | 同一效果能否在两个领域执行，且保存真实后果 | W0、P0快照约定；两种用途共用作用规则 |
| W2 麻雀的生活 | 不做人、不打怪，是否仍能活、行动、交往 | W1；完整早期生活与一种跨领域帮助 |
| W3 知物、限流与试验 | 知道、会用、能承受是否真的分开 | W1；同一器物对不同观察者有不同已知与可用方式 |
| W4 独立寄魂者与协商 | 身体持有者和意志是否能分开并持续 | W0/W3；双主体知识边界、合作、载体交接与存读 |
| W5 欺骗与核验 | 欺骗是不是具体的信息操作，而非全局数值钥匙 | W3、已有社会/机构规则；伪装与正式核验能产生不同结果 |
| W6 方法改良与传播 | 玩家/人物是否能创造一项有用做法，而非选预写奖励 | W1/W3、已有消息；同一新方法跨人/跨地使用，版本与缺陷保留 |
| W7 尺度与共同局面 | 大身体、不同生活是否能参与同一局势 | W2/W4，P0相关时间；多格几何试验及五种主体场景回归 |

这不是八个0.5小时任务，也不承诺一轮做完。每包下面的动作需拆成单一纯规则、适配、UI或持久化任务，再逐个验证。先获得可运行证明，再批准扩大内容与容量。

## 3. W0：先找出真正要改的接缝

检查当前人物/库存/执行/快照的所有者，列出“人名＝主体＝身体”“必须双手/背包”“吃住是唯一维持方式”“原地格唯一表示所有尺度”的实际依赖。不要仅凭文件名判断已支持非人主体。

建议最小契约：

- 稳定主体引用，与当前载体/控制关联分开；人形Demo先保持一对一适配。
- 按行动查询所需能力和处境，不全量引入ECS或复杂能力框架。
- 物品实例唯一位置，与可堆叠数量账目有明确桥接；不把每粒粮都升成独立对象。
- 行动保存执行者、目标、方法、资源/位置预约、阶段与幂等提交标识；已有执行入口可继续复用。
- 知识、机构记录与真实对象分工不变；扩展时新增明确字段与版本，不互相镜像成第二份真值。

W0出口：现有双聚落办事/运输/互助/快照回归保持成立；最小契约有一项非人测试替身可查询，不宣称已有非人玩法。若需改时间表示，先按P0独立验证与迁移，不顺手重写全部时钟。

评审后的拆分：W0-a只做状态/单位/反例目录，W0-b才接最小主体/载体引用与通行条件。权威结算唯一不等于只许单参与者；作用冲突、占用通道与共同过程只在首次真实需要处做薄实现，不作为W0一次性铺全的清单。

## 4. W1：先证明两件事能相接

从一种有可观察条件的热/干燥作用开始：它能加热工作对象，也能影响保管；先用有界对象/区域状态，不实现连续流体。

1. 定义热输入、介质/目标、耗时、供给、散失/上限及中止条件，实际数值进data定义。
2. 选择湿布与待保管药材两个情境；相同作用检查不同材料与工艺条件。
3. 提供低功率试用、停止、查看可见反应；错误使用留下损伤，不凭用途名称自动安全。
4. 保存过程与对象状态，离场再回来继续；测试供给耗尽、对象被拿走、同时预约和重复提交。

W1出口：不是两个按钮分别改完成flag，而是同一规则在两个情境生效。新效果须能解释输入、成本、结果和可见痕迹；不能凭空造一件“产物”忽略材料。

同时给一个NPC提供两种已知办法，验证其能按处境选用；世界支持一种方法不等于人物自动知道。造物若由明确术法支持，可以产生有来源的新实例；“不复制”约束重复记账/提交，不能误作禁止所有超自然创造。

## 5. W2：麻雀不是换皮快递员

先做飞行/落点、狭缝、轻物抓持、适食/休息和有限交流。保持2D正交与高度规则，不扩成自由3D。

在现有聚落边缘装配鸟妖的食源、巢/避风点、危险路线和至少一位可交互者。让玩家可以觅食、选栖地、观察、展示/交付轻物、求助；也可不接运输任务而探索或维持生活。

至少一个NPC鸟妖使用同样条件选择觅食或避险，不能所有特殊动作只给玩家。容量与体积限制必须对地面拾取、背负和远区运输同时生效。

W2出口：一段约15分钟的鸟妖生活样本目标成立；无需战斗胜利或化形。相同缝隙与轻物规则在第二处地点也成立。具体时长是未来试玩目标，文档没有实测结果。

## 6. W3–W4：器物、未知和另一个意志

W3开始前补一个最小认识命题闭环：消息内容可以错误、两来源可以冲突，主体依据所信行动，实际执行检查世界条件。保留旧真实事件转述/隐私校验，为命题与验证状态另作适用校验；不能等到W5才发现知识数据结构只支持真实快照。

W3先装配一件有普通功能、隐藏功能和裂损风险的旧炉/戒中装置，任选其一，不同时实现两套复杂系统。至少两名主体知识不同：一位懂材料，一位懂某段操作法；二者所见与可做确实不同。

观察/试验独立成行动；示范与消息能传达具体知识。低功率安全使用、高功率越界、错误媒介和中止各有测试。执行者不知道风险，不会阻止真实规则发生；界面也不能免费泄漏全部真值。

W4再增加寄魂主体：有限感知、独立目标、若干有来源旧知、指导/代操条件与拒绝。先支持“同处一戒、传意、协商与载体转交”，暂不接完整夺舍或多身并行控制。

出口：两主体不共享全部秘密，持有者违约可影响合作；载体交接、休眠/唤醒、离场/存读保留同一主体和裂损状态。给扮演寄魂者的人提供能做的事与退出/等待路径，而非只有只读描述。

## 7. W5：只做一条骗术链，也要能复用

以冒名来访为样本：伪装/出示一个可观察线索→守卫按所知与风险判断→核验者检查不同依据→真正的办事动作。

- 守卫可能相信，机构却无权/无货，或印契核验失败；这几个阶段分别发生。
- 若账房被诱导签发真凭据，保留签发事实、虚假依据与后续审计路径，不立即神谕纠正。
- 控制随机状态与尝试记录；同一条件连点不重掷，改证据或方法才构成新尝试。
- NPC也能误导与被骗；被识破不等于全世界立刻同步知道骗子真实身份。

W5出口：一条手法在第二名接收者处根据不同所知得出可解释差异。先不接全套幻术树、天机与读心。

## 8. W6：让新方法成为世界中的东西

基于W1已能执行的作用，开放少量过程组合与参数试验，不增加任意运行字符串代码。

最小样本：缓慢供热→发现稳定但效率低→增加限流/隔离→形成一种保温方法。方法有适用条件、故障、版本、创造者与试验记录；学习者掌握哪个版本另存。

把新方法用于第二种容器/工坊，并教给一名NPC。其学习花费时间和条件，之后能独立选择使用；远处获得方法须有真实传播渠道。改名不能刷新成本，旧版本不会自动升级。

W6出口：至少一种方法不是从固定职业菜单直接领取，并能跨主体使用；NPC能够照所知学习/采用。NPC自主研究先只在有限候选中触发，不宣称具有无界发明智能。

## 9. W7：尺度验证与共同世界演练

2026-11-03校正：W7-a真实3×3山兽首包已接，完整占地/净空、动态扫掠、边缘递食和离场/进行中重启见[规格](large_bodies.md)与[实际证据](../qa/20261103_large_bodies.md)。它不是可选古兽人生；以下共同灾害与五种主体矩阵仍是未来验收，不因尺度首步通过而勾完。

先以3×3载体做几何测试：通路、净空、转向、边界递物、不得穿过窄桥。再单独研究超过当前场景/区块的巨体怎样保持区域位置与局部接触面一致；前项通过不等于后项已实现。

随后装配“断桥、寒潮与旧炉”样本。只组合已完成规则，不为每种身份另写专属完成开关。五种主体各检查：维持、交流、特有机会、实际限制、失败接续。

## 10. 文件、数据与保存边界

以下是职责建议，具体文件在实施前按当前代码确认；不预创建空目录：

| 位置 | 可能的最小变化 | 约束 |
|---|---|---|
| scripts/sim/ | 小型主体/载体引用、能力查询、效果/试验/方法规则 | 不继续把全部领域塞进VillageSimulation；不反向依赖节点/UI |
| scripts/runtime/ | 新主体视图与执行适配、形态输入、状态交接 | 不另建身体位置/库存真值 |
| scripts/persistence/与快照协作者 | 新领域版本、候选验证和恢复 | 保留旧联合快照原子切换，先迁移再覆盖 |
| data/definitions/ | 身体条件、作用/方法、观察方式、代价/风险 | 只读内容；动态知识、新方法与关系属于存档 |
| data/scenarios/ | 鸟妖/寄魂/尺度与共同局面初始装配 | 场景只装配，不兼作运行中状态 |
| tests/sim/、tests/runtime/ | 条件、过程、知识边界、组合与恢复测试 | 回归已有生活/运输/办事，增加反例与中断 |
| scenes/、scripts/ui/ | 对应身体/载体的呈现与上下文操作 | 到适配步骤才改场景，按项目验证流程 |

新增状态必须明确单位、允许范围、引用完整性与未知/缺失的含义。当前人形快照不能直接声称能保存寄魂、变形或新方法；每域随自己的工作包加入、迁移与验证。

## 11. 风险与停止条件

- **又造一个万能框架**：若一种抽象没有第二个真实用途，先写薄规则；W1不通过就不扩一百种效果。
- **非人形只有困难**：每个样本必须同时有独有机会和生活入口，不能只是灰掉人类菜单。
- **创造变成表单劳动**：提供模板、试验预览和少量有意义参数；能直接使用成熟方法，不强迫人人研究。
- **模拟太忙没有闲暇**：先保证基本生活存在稳定区间；不能以永无止境维护代替多样体验。
- **大地图掩盖局部无趣**：同地三解、不同生命生活与离场连续未过，不扩大地理与人口。
- **巨体/分身复杂度失控**：分开做几何和远区原型；保留目标，明确尚不支持的尺寸与控制关系，不伪装完成。
- **所谓涌现其实脚本奖励**：改地点、对象或执行者再试；只有原剧本能过则退回规则修正。

每个游戏行为包最终由对应提交运行一次`python tools/godot.py check`或取得对应SHA的CI结果；有可见交互则实际运行、读首错并截图。结构与文档验证不能代替这些行为测试。方案成文当时做过文档检查与既有Godot回归；这不构成W包行为验证，也不新增游戏通过数。最新证据见BASELINE。
