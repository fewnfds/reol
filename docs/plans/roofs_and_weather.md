# P2-c：屋顶与局地雨水

状态：已实现并自动/实机/完整重启验证，2026-11-03。承接[围合/床铺](rooms_and_rest.md)，不是完整气候或生态完成；实际证据见[QA](../qa/20261103_roofs_and_weather.md)，当前验证与格式只维护在[BASELINE](../BASELINE.md)。

## 本包实际闭环

原材料/搬运/劳动造木屋面 → 得到有支撑的实际覆盖 → 局地降雨 → 露天木床受潮、遮雨床不继续淋湿 → 原身体休息效率变化；雨水同时回补有限泉源，仍需实际汲取/搬运才进入生活库存。玩家离开不冻结，已有床位/施工/物资/同一时钟全部复用。

## 具体规则

- 木屋面是原施工项目的上层构件，能与地面床/墙同格；不占地面阻挡，不把蓝图当覆盖。地面与屋面查询分层，原引用和材料凭证不另造。
- 屋面需同高度的已完工墙/门在有限跨度内支撑。材料/工时完成时复核；支撑拆掉导致无支撑屋面失效并塌回有限余料，不留下永久悬空遮雨。拆屋面不删除下方床，拆侧墙是否仍有其他支撑按真实结构算。
- 覆盖与围合分开：棚能挡雨，敞开门也不自动抹去上方屋面。只有实际有支撑屋面才遮雨，不因围了一圈墙自动获得屋顶。
- `SimWeather`持有本轮气候起点、整分钟环境相位与稀疏床铺湿润度。两聚落按内容定义的有限晴/雨循环和偏移变化，先以可复现规则验证，未来可换气候生成器；不是最终季节/气象模型。天气时间与共同世界毫秒一致，不用渲染帧率结算。
- 环境整分钟脉冲在本刻施工变动之前结算上一个区间；床在建成前不受潮，屋面完工不倒算之前一分钟的遮雨。湿润程度有上限，晴天或遮雨后逐步干燥，盖屋面不立即烘干床。
- 淋湿的木床仍可用，但原精力恢复较慢；屋顶本身不凭空加精力。NPC只在已能注意/有权/可达候选间考虑床铺湿润，仍保留饥饿优先和无床原休息。
- 降雨回补原`SimLandResources`泉源，有容量上限，满源不银行式累积未来雨水。新增雨水来源计数与自然定期生长分别记录，原库存仍是唯一数量真值。不能以天气为由放宽任意资源注入或旧凭证校验。
- 界面只显示所在地的晴雨、眼前屋面/湿床，雨线是程序绘制且有上限；无全图当前天气透视，不引入美术/插件依赖。原有火石/鸟/魂不冒称全部环境耦合已完成。

## 持久化

根17→18、区域14→15、施工1→2，新增天气v1；自然来源状态升级，明示雨水流入计数。旧v17以读入时刻为新环境起点，已有床视为当时干燥，不回填过去降雨/水量/受潮经历。真实v1～v17及overload_v10不改写。现代缺域、错相位、假湿床/覆盖、雨水账损坏须在独立候选拒绝，失败不改活世界。

## 验收

1. 同格床与屋面、实际搬料/工时、未完成无覆盖、支撑复核/拆除塌回、地面通路无误。
2. 两地晴雨随共同时间变化；真实有限雨水、露天/覆顶床不同结果、覆顶后渐干、湿床用原精力恢复。
3. 施工/下雨同刻顺序、近远/粗细、预算分步、进行中存读一致，无事后补造/重复雨水。
4. 新旧真实档、坏候选原子拒绝；现有劳作/器物/非人/床铺完整回归。
5. 实机正常造顶/降雨/遮雨/拆改；1280×720截图、日志、进行中完整停开后联合未来一致。
