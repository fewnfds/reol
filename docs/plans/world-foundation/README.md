# 世界骨架内部实施参考

本目录保留对象查询、生命周期、数量/动作、装配与规模验证的实施知识。它服务于[顶层框架](../../engineering/architecture/05-framework-domains.md)中的模块，建设依赖和完成标准统一见[基础建设计划](../foundation-priorities.md)；旧“第一阶段”和A–E编号用于定位，不再构成独立顶层排期或自动停止点。

## 模块归属

| 内部参考 | 主要归属 | 交接对象 |
|---|---|---|
| 对象、能力与空间查询 | 实体、物品与容器框架；世界地块与空间框架 | 各原owner提供只读事实，行动/环境/工具按合同消费 |
| 生命周期与位置变更 | 实体、物品与容器框架 | 空间、来源和相关过程沿真实提交维护或失效 |
| 数量堆拆与耗时动作 | 实体、物品与容器框架；单位行动与交互框架 | 原库存负责数量/预约，行动负责时序/取消，效果归原领域 |
| 装配、共同时间与存读 | 各框架共用的运行合同 | 各领域提供候选恢复和在途状态，联合接受后发布 |
| 普通接入与规模验证 | 所属框架的联合出口 | 创作/呈现/诊断和实际负载共同验证 |

详细检查项见[内部步骤](steps.md)，跨类型、持续性和负载口径见[验收参考](acceptance.md)，成熟项目经验见[参考](references.md)。实际接入、缺口和证据分别查[技术总表](../../status/technical-status.md)与[基线](../../status/baseline.md)，不从本文的制定时编号推断进度。

## 使用原则

- 在已授权框架范围内选用适用的内部步骤，复用已有原owner、共同时间、地图和存读，不从零重写正常游戏。
- 共同引用和能力接口不合并所有对象的状态；地块承载实体，多格覆盖引用同一实例，派生索引可重建。
- 查询不改变世界或角色知识；缺失、未支持、滞后和预算耗尽不能伪装成完整空集。
- 局部变更与到期执行保持必要时间和因果，离场不冻结世界。保存原事实和必要过程，完整候选失败不能修改活世界。
- 内部小步与提交便于验证，完成后进度归回所属框架并继续授权范围内的工作；框架完成按公共接口复用、普通接入及证据判断。

性能目标只沿[全项目基线](../../engineering/architecture.md)；独立数据结构、静态对象或隔离计算的成功不外推为完整动态世界容量。原阶段起点和历次包结果从Git及对应QA追溯，不在现行入口保留过期运行快照。
