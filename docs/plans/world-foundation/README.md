# 第一阶段：通用世界骨架

本目录是第一阶段的实施说明，具体步骤见[分包](steps.md)，结束条件和负载口径见[验收](acceptance.md)，已有公开经验及取舍见[参考](references.md)。当前授权和工作区以[接续](../../status/handoff.md)为准；全项目工作顺序只由[基础优先级](../foundation-priorities.md)统筹。

## 要交付的基础

从版本化定义和开局数据装配一个平面世界，让人物、自然资源或植物、材料及多格物体使用共享的身份、位置、能力、变更与查询边界。世界沿已有共同时间推进，可脱离画面处理事实；保存、完全退出和重开后保持同一世界。为稠密对象、局部变更和查询建立可重复的性能证据。

这是一阶段**目标**，不是当前已完成清单。各包按依赖推进并在边界记录真实结果；当前授权、执行项和停点只由接续登记。发生需要用户决定的概念变更或真正外部阻塞时再另行说明。逐包范围与验证见[分包](steps.md)。

## 制订时起点与边界

以下说明本阶段为何需要这些工作，不作当前完成清单；实际接入程度见[功能](../../status/features.md)与[基线](../../status/baseline.md)。

- [地图数据](../../../scripts/sim/world_map_data.gd)可在场景外查询底图及地表修改，正式开局使用 512×512；地图本身尚未提供通用实物所有权。
- [共同时间和区域](../../../scripts/sim/regional_simulation.gd)与现有域已接，在既定范围内保留未结算目标；这不证明任意新对象、任意装配或大规模远区全部成立。
- [对象查询](../../../scripts/sim/entity_query.gd)、[库存查询](../../../scripts/sim/storage_query.gd)、[结构查询](../../../scripts/sim/structure_query.gd)分别读取原所有者；引用、空间与能力未形成覆盖所有领域的统一合同。[自然来源](../../../scripts/sim/land_resources.gd)是有限资源点，不等于完整植物实体。
- [存档装配](../../../scripts/runtime/world_session_snapshot.gd)有独立候选验证，但运行适配仍受既有场景限制；不能因此宣称任意世界可存读。
- 普通 Main 的冷热仍使用旧 Q，新场、温度状态和 GPU 服务为隔离候选。四处环境源/温度及测试工作区改动有未提交 WIP，需按接续保护；不以其代码存在推断已验收。

## 始终成立的边界

1. **唯一事实**：身体、物品、材料数量、位置和共同时间归各自原所有者；查询结果、空间索引、画面只可引用或投影，可重建，不持第二份事实。
2. **定义与实例分离**：类型定义可以共享；状态变化归具体实例或库存条目。新增同能力对象可复用既有能力，不能按对象显示名扩特殊分支。
3. **位置与物品分离**：地块承载实体；一个实体可以跨多格，所有覆盖格指向同一引用。容器、携带者、地面和区域不是同一种位置；区域指定不拥有植物或家具。
4. **查询不改变世界**：开发侧查询须显示来源时刻及未结算状态；无法判定、缺失、未支持和空结果不可混淆。玩家信息必须经过实际观察与认识过滤。
5. **增量与预算**：静止对象不逐帧执行，局部变更只使相关派生索引失效；需要续算时保留明确进度，过期结果不可发布。不能把不可见区域的世界事实当不存在。
6. **单一世界与兼容**：已有共同时间和真实所有者继续使用。候选加载完整校验后才切换，明确支持的旧输入转换成当前模型；历史资料保留，不无限保留旧运行实现。

性能目标统一引用[全项目性能基线](../../engineering/architecture.md#全项目性能基线)，本页不再独立维护硬件规格。实际测量明确单次设备，不能将多卡显存相加或把目标当已达容量；测试守卫及具体口径见[验收](acceptance.md)。

天气、冷热/五行场的普通 Main 接管、完整房温、生态、战斗和社会过程属于骨架之后的领域包。环境源和 GPU 的接口保持可接入，但本阶段不把隔离原型当成已运行世界。

## 结束判断

只有同时达到[联合验收](acceptance.md)中的跨类型、世界时间、生成转移、数量、保存重启和声明规模负载，才能称第一阶段完成。独立原型或合成数据的成功各自记录范围；没有证明普通世界承载能力时不能外推。
