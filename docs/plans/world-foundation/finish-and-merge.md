# 世界引擎收尾与主线合并

本包由用户2026-11-07授权；完成后停止开发，讨论流程。当前实施只在隔离工作树，原工作区四份未提交环境草稿已逐字备份，不混入验收。

## 固定交付

1. 集中已有世界调度目录与阶段合同，领域状态仍由原所有者持有；请求、持续动作和已提交通知不混用，不重写ECS或通用事件平台。
2. 将已有冷热/五行算法接入普通世界。普通入口只有一个实际环境所有者；真实地面物与固定设备提供来源，目标变化保留实际残留，人物与植物消费同一温度。源改变与原物写入在同步提交段内完成，再发外部通知。首版选择同步局部更新，性能须实测，不声称无卡顿。
3. 内容包固定来源定义；普通存档保存实际响应、临时来源与在途状态，缓存重建。旧Q历史不能精确推导新场，旧环境格式明确拒绝并保留原档、活世界；不伪造迁移、不运行双模型。
4. 普通入口联合验证生成、变更、单位响应、暂停中断、保存完全退出、重启继续。保留当前格式在途/失败隔离回归；历史Q算法与旧迁移验收按兼容政策登记退役，不改写原fixture。
5. 一次主要原生静态审查，最终完整回归与普通负载测量。阶段提交/推送，核对main差异，合并验收代码并推送。随后停止。

## 不新增前置

完整房间均温、携物遮掩与连续尾迹、任意聚落UI、大规模NPC生态、GPU玩家开关、战斗修炼和组织玩法不是本次合并前置。结构仍承担围合、遮挡与通行；若新环境尚无隔热模型，须明确显示/记录这个边界，不以空适配器冒称保温。

## 验证与证据

先定向检查调度、来源事务、环境连续性、当前存读及真实拒绝边界；最终只做一次完整check或对应SHA CI。可见结果需普通Main实机画面与日志。性能目标按[架构基线](../../engineering/architecture.md)，本包不新增极限密度探索。

成熟架构参考：OpenRA的World.Tick/Orders/通知、Mindustry的Logic.updateEntities、Veloren的rtsim规则组合；复用明确执行阶段与领域状态，不照搬其完整引擎。世界顶层接口是生产装配和调度合同，单独样本不能代替接入。
