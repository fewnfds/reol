# 世界骨架内部实施步骤

这些检查项服务于[目录中的框架模块](README.md)，旧A–E编号用于定位；顶层职责见[领域归属](../../engineering/architecture/05-framework-domains.md)，框架出口见[基础建设计划](../foundation-priorities.md)。使用前先核现有代码与已完成能力，在授权范围内选取内部步骤并持续推进；小步完成后报告模块进展，不自动停止或重新询问。概念决定和真正外部阻塞另行说明，不为具名物品扩特殊玩法。

## 包 A：对象、能力与空间查询合同

**输入与所有者**：现有区域、身体、器物、数量库存、自然资源与结构分别保有原状态。先核对 [SimEntityQuery](../../../scripts/sim/entity_query.gd)、[SimStorageQuery](../../../scripts/sim/storage_query.gd)、[SimStructureQuery](../../../scripts/sim/structure_query.gd)、[SimEmbodiment](../../../scripts/sim/embodiment.gd) 的真实入口，不新建第二个对象库或时钟。

**首包接口及覆盖**：`SimWorldObjectQuery.describe(world, reference)` 和 `capability(world, reference, name)` 提供只读描述与能力查询，接入既有人身、鸟身、器物、大型身体、数量条目、有限自然来源及施工/固定场所结构。`SimObjectSpatialSnapshot` 根据调用者显式提供的引用集合捕获派生空间快照，为这些引用提供有预算的范围查询；这不是全世界对象目录或实时权威索引。接口具体字段和支持能力以该包代码与验收为准。

**步骤**：

1. 统一引用和只读结果约定：引用保留领域限定与原身份；结果说明状态所有者、区域/位置来源、共同时间和来源是否滞后。库存条目是容器与物品类型下的数量记录，不能凭查询创造独立实例。
2. 将人的身体、鸟或大型身体、独特器物、库存材料、现有自然资源点与施工结构按实际支持范围接入同一查询入口或明确的适配器；不存在的事实标为未支持，资源点不伪装成可砍伐植物。覆盖多格对象时所有格引用同一个原对象。
3. 能力查询复用身体形态和器物定义已有能力；区分对象不存在、来源不可用、能力类型未支持、可判定不存在、时间滞后和世界积压。不能将未知当作 `false` 或让查询推进世界。
4. 对范围查询建立有界空间接缝：快照只保存可重建的引用、几何和来源信息，不复制身体、库存余额或第二份位置事实；带出区域、空间层和包含关系时不得将保存所属区误作真实物理区域。携带物的锚点不自动构成地面实体或导航障碍。查询预算耗尽须明确表示未完成，不得返回貌似完整的空集。
5. 首包没有跨所有原域的全局修订号或实时失效通知：快照只表示捕获时刻及所提供的集合，调用方有责任在原事实变化或存档恢复后丢弃并重新捕获，不能跨世界事件宣称内容仍实时。与原所有者变更同步的 hook、修订及可重建实时索引属于后续生命周期包，设计时继续保证读取不到被静默篡改的旧缓存。
6. 用多类真实所有者检查一致输出、不同领域同名 ID、缺失、未知能力、跨格覆盖、时钟积压/来源滞后及只读性。新增另一种同能力定义检查没有以名称特判；测试不暴露内部全知到玩家 UI。完成存读后重新捕获，核对快照来自恢复后的原所有者。

**验收与边界**：通过定向与相关联合测试；对本包实际可运行的数据结构测初始化、查询和更新成本。明确哪些域、场景、保存路径和对象量已覆盖；不声明全地面实物、通用生成/转移或 512² 真实世界已经完成。首包不增加使用物品、种植、战斗或交易功能。

## 包 B：实物生命周期与位置转移

**依赖**：包 A 的引用与空间边界可区分原物、数量记录和空间投影。

1. 由原定义和目标所有者受控创建/移除；验证身份唯一、位置合法、失败没有部分写入。保留领域负责其具体初始化和终止的规则。
2. 在合法地面位置、携带者和容器之间移动真实对象。位置及包含关系只有一份事实，空间索引随提交局部更新或显式失效；物品无法放置时不覆盖、删除或复制其他物品。
3. 支持至少一种独特实物和一种数量材料的实际转移。重复请求、资源不足、冲突、移除后引用失效和保存恢复按合同明确失败或幂等。
4. 准备至少一种多格对象实际占地的注册与解除；不能把一格画面中的多个投影当成多个实物。领域尚不具备创建条件时，记录缺口而不是用假对象补齐。

**验收与边界**：真实原物从生成到合法移除沿相同接口操作，失败、重试、跨容器/跨块及重建索引后守恒；未完成动作合同和领域生态不算已实现。

## 包 C：数量堆拆与最小动作执行

**依赖**：包 B 的位置和变更已经具备唯一事实及原子提交边界。

1. 数量材料在同类且状态相容时合并、拆分及移动；异类不混堆，数量与产权/保管状态不能被折叠抹掉。已有不可堆叠实例各保留 ID 和状态。
2. 将已有动作过程所需的请求、条件/预约、耗时、完成前重验、提交、通知和中断收敛到最小共通合同；复用共同时间和原领域成本，不建设万能行为规划器。
3. 对目标消失、容量或位置变化、预约冲突、取消及重复完成提供确定结果。进行中的事实只由原 owner 与在途记录保存；失败或中断不能提前生效、重复支付或复制。
4. 保留未来环境约定：同类相容的一堆作为一个普通来源，人物及携带物整体对外映射不在本包实现。这里不实现五行传播或冷热计算。

**验收与边界**：数量守恒、互斥预约、完成一次、取消和恢复等定向与跨域证据完整；不把单一物品的具体动作变成其他对象的专用逻辑。

## 包 D：世界装配、共同时间与保存恢复

**依赖**：包 A–C 的对象、空间和在途操作有明确原所有者。

1. 从真实内容定义和开局数据装配纯世界；将场景视图和调试投影接在其外侧。保留当前游戏入口可运行，不以孤立模拟器替代普通世界。
2. 内容/版本、引用、占地、容器和行动先在脱离活世界的候选中校验，再一次发布；损坏或不支持的输入明确拒绝，活世界保持原状。重建索引不恢复旧缓存为事实。
3. 世界时间和域时间的可见边界保持现有合同：分片推进、快进、预算积压及中断不丢失请求；对象动作完成按共同边界提交。未结算不可伪装成已到未来。
4. 覆盖当前明确支持的存档输入、在途动作、正常停止/重启和独立进程恢复。保留原 fixture；对被淘汰入口给出明确识别或迁移，而不是永久并行两套模型。

**验收与边界**：同一开局经历创建、变更、离开区域、回访、保存、完全退出、重开和再推进；比较原物、位置、数量、时间和在途结果。未建立无界远区全部人物行为的因果保证。

## 包 E：接入、诊断与性能出口

**依赖**：此前能力已有真实普通世界调用链，而非只存在数据单测。

1. 让普通世界和开发诊断使用相同引用/空间/生命周期接口。提供能定位对象所有者、位置、占地、进度、查询状态及待处理时间的最小诊断；玩家只看到自己能够认识的内容。
2. 对静态对象、动态身体和环境来源分别构造负载。检验静止时不全体逐帧执行，局部移动只影响相关范围；跨块、多格和新旧位置同时失效。
3. 按[验收口径](acceptance.md)和[全项目性能基线](../../engineering/architecture.md#全项目性能基线)在真实世界和合成数据中分别递增规模，记录实际硬件、CPU、进程内存、显存、查询、初始化、更新、帧时及存读；识别首次超限，不把局部结果包装为整世界容量。
4. 针对测得热点选择数据布局、批量、索引或异步方案；CPU 与可选 GPU 只有在同样输入和共同时间边界一致、端到端实测有益时才采用。GPU 对象场与完整环境接入为后续包，本阶段不承诺已有玩家设置。

**验收与边界**：各项联合条件和目标负载证据齐全才宣布第一阶段完成；否则按已完成包及未过项报告，不因表面 demo 或测试数量关账。

## 风险与后续事项

- 既有对象位置分布在多个原域；适配器只读时可先共存，后续生命周期写入必须证明原域和索引的同步协议，避免两套位置权威。
- 区域时间滞后、预算续算时的世界变化及索引候选过期需定义可观测的拒绝/重试；不能返回貌似完整的旧查询。
- 当前自然来源、单工地、多格身体均是有限样本，后续扩到真实植物/任意结构需要正式领域能力和迁入，不因为具有坐标而宣称它们已经是通用实体。
- 室内拓扑、冷热/五行场及人物携带物辐射后续接入；先保证空间变更和时钟接口能通知其调用者，不预先扩建定向/反射辐射。
