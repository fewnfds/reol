# 世界骨架模块接入检查

本页提供按需检查项，不保存施工顺序或独立任务。所属框架、改造范围、依赖及出口统一见[基础建设与改造计划](../foundation-priorities.md)，主要owner见[领域归属](../../engineering/architecture/05-framework-domains.md)，实际覆盖见[技术总表](../../status/technical-status.md)。先复用现有合同，再补本阶段真实使用点所需的接缝。

## 对象、能力与空间查询

- 沿[对象查询合同](../../engineering/object-query-contract.md)保留领域限定的引用、原owner、位置/包含关系、能力命名空间及时间状态。数量条目仍是原容器账，资源记录不冒充独立植物。
- `SimObjectSpatialSnapshot`只覆盖显式引用集合与捕获时刻。实时查询由原域提供局部候选、几何和变化/恢复失效接缝后组合，不将历史快照当作全世界实时索引。
- 检查多格去重、跨显示区块、容器锚点与地面障碍分离，以及缺失/未支持/滞后/预算未完成。查询不推进时间，不把开发全知写入玩家认识。

## 生命周期、数量与包含

- 沿[实物生命周期合同](../../engineering/object-lifecycle-contract.md)核对受管对象范围、原实例/位置/库存、幂等命令、失败原子性及提交后通知。局部revision只代表其原域。
- 新领域分别说明初始化、空间进入/离开、包含变化、销毁和候选恢复；必要派生索引随真实提交维护，恢复重建。多格指向同一原物。
- 数量拆合保持相容状态和原责任；独特实例保留身份。容器类型、容量、嵌套与跨账本支持范围按主计划实施，当前不支持的操作清楚拒绝。

## 行动过程与领域效果

- 以已有取放和施工的真实调用点核对意图、接近、条件/预约、占用、耗时、截止复核、结果和清理；共享有相同语义的步骤，领域继续提交原材料、结构或产物效果。
- 检查目标消失、途中空间改变、预约竞争、取消、控制丢失及同刻回调；已发生时间/成本按规则保留，终止后释放占用，重复完成不能重复结算。
- 玩家和NPC使用同一执行规则；观察、理解、意愿和权限不因进入共同接口而被跳过。身体控制通道和不同领域阶段沿原合同保留。

## 装配、共同时间与存读

- 沿[世界装配合同](../../specs/world-engine/program/01-topics.md)绑定定义、地图和开局；新局发行与恢复分开，候选不能借活世界人员/库存补事实。
- 沿共同整数毫秒和既有有序阶段结算，预算耗尽保留target及待处理过程。原状态与在途事实保存，空间/来源/参与索引恢复重建。
- 支持输入与格式变更遵循[兼容政策](../../engineering/compatibility.md)；完整候选通过后发布，失败不改原档或活世界，历史fixture只读。

## 普通入口与证据

每个框架用普通Main中的不同定义/布局验证相同机制，随能力补必要创作、观察及失败原因。规则用最小合法fixture；联合验收覆盖实际改造、离场/返回、进行中保存与完全停开后继续。

负载、硬件和测量沿[验收参考](acceptance.md)及[全项目基线](../../engineering/architecture.md)声明；静态索引或隔离计算的结果不外推完整世界容量。测试选择、原生审查和等待沿现有工作流，内部检查不成为自动停止或再次授权边界。

旧A–E分包原文可从Git追溯；现行框架进度只归技术总表和HANDOFF。
