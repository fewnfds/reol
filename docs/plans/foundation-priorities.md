# 当前实施计划

授权与停点在[HANDOFF](../status/handoff.md)，已实现能力在[FEATURES](../status/features.md)，性能事实在[BASELINE](../status/baseline.md)。本页只安排当前工作，不登记历轮完成过程。

## 当前方向

当前主题为**2D正交俯视ACT＋弹幕战斗改版**。用户已选择近远双路线：近战武器强调ACT，远程武器强调弹幕，各自形成完整玩法。目标不是在自动追击上补几个伤害按钮，而是重新建立直接操作、动作承诺/取消、空间判定、弹幕可读性与命中反馈。

已完成研究与实施规划，**当前进入P0响应链实验**：旧20Hz合成移动基线与测量入口已具备，尚未改变战斗频率或接入WASD/连招。具体玩法、参数起点、所有权/文件映射与验收候选统一见[改版规格](../../design/systems/combat_framework/act_and_barrage.md)；证据与成熟方案评估见[研究](../../design/research/act_barrage_references.md)。默认键位、闪身窗口、动作参数和技术频率仍由原型收敛。

现有生活/建筑/植物/感知/交往/装备背包与有限地图是接入基础，真实能力只维护在FEATURES。改版沿原World唯一状态owner进行；不能为手感复制第二套位置/HP，也不能把尚未验证的时间架构写成现状。

性能取舍按用户要求：**只有实测大世界拖慢目标战斗负载，才让次要世界过程的精度/频率为战斗让步**。允许远处降频、聚合与有条件的交战粗算，不预先缩小地图；详细次序与误差边界只维护在[规格9.3](../../design/systems/combat_framework/act_and_barrage.md#93-大世界为战斗让步的条件与次序)。

## P0的选择与反证

当前已完成旧链路测点、独立release以及最小后台/普通24人短窗，结果见[合成移动基线](../../design/research/act_barrage_references.md#12-p0旧链路的合成移动基线)。下一步核查运动dt、步内到达、索敌/植物分组与显示插值的50ms假设，制作60Hz统一心跳＋到期慢域候选，再复用同一测量。小型高频战斗视图、直接移动/瞄准、弹体相位及完整提交间隔仍待验证，不能把首项基线完成写成P0通过。

优先实验“一条高频权威心跳，动作/直接运动/弹体高频，低频世界按到期执行，轻战斗视图高频发布”。60Hz用整数tick/余数表示，不能简单每步加17ms造成世界漂移；100Hz的10ms与50ms整除方案可比较精度、显示节奏与CPU代价。没有测量前不定全世界120Hz，也不承诺某个弹数一定达到。

P0从1玩家、少量敌人/弹体和后台工作开始，先证因果/延迟，再上正常24人；P2/P3有真实玩法后复核同一前台切片，必要时选一个高人口档，按[后台对照](../../design/systems/combat_framework/act_and_barrage.md#114-怎样证明大世界确实拖慢战斗)取证，不重跑容量寻极限。主要反证：高频姿态仍被50ms插值拖慢；后台任务/join占用超过动作预算；身体重复写或用过去/未来位置命中；全量Frame复制吞掉余量。失标时先区分平均算不过来与周期长调用，再决定减负，不能用假躲避/提前扣血掩盖。

如果正常目标人数下全世界60Hz直接推进实测更简单且成本可接受，允许选择它；保留20Hz仅加预测也作为对照，但短避伤/取消窗口必须由权威时间正确解释。选型记录准备、计算、提交和发布成本，不能只比较FPS。

## 验证、工作量与扩展边界

验证方法遵守[开发循环](../engineering/workflow/testing.md)。每包只增相关短反例，图形/输入/声音实际试玩；不用完整长回归或headless通过数代替手感。指标、战斗负载阶梯和测试场在规格第11节，不在这里重复数值。性能放回一个适当历史点看增量，超过容量应报告，不自动重测精确极限。

粗估单名熟悉工程的开发者：P0约2–3人日，P1约2–4，P2约4–6，P3约3–5，P4约3–5，P5约3–5，P6约2–4，P7技术接入/调参约2–4，合计约21–36人日；正式美术/音效制作另计。按每周5天、计入往返试玩与返工，首轮完整切片预留约6–10周较合理。它是排产量级，不是承诺；先做P0/单剑切片后更新估算。若确需广泛调度重构、远战粗算或拓扑增量化，另按测到的瓶颈估量，不含在当前数值中。现有响应链、后台长批次与动画制作方式是主要不确定项。

首版范围与延后内容统一见规格第12节；多控/编队、自动物流、完整社会/修仙内容、无限世界和完整远区LOD没有因改版自动获得施工顺序。为目标战斗负载必需的局部降频/近似按测量单独选择。[产品层次](roadmap.md)保留长期愿景。

## 后续选题方式

- 按玩家遇到的体验缺口选择一个可观察出口，定位所属[顶层领域](../engineering/architecture/05-framework-domains.md)，沿[当前owner](../engineering/architecture.md)扩展。
- 新增密集计算时按[计算接入](../engineering/execution-batches.md)选适合的路径；小型低频功能直接实现即可。
- 性能按[开发循环](../engineering/workflow/testing.md)做相关档位的历史对照，以功能价值与成本决定保留/调整。

当前主题之外仍按试玩缺口选题；design中的详细候选不自动成为施工清单。
