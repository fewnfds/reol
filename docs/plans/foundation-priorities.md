## 当前阶段：主要模拟负载多核化

用户2026-11-11明确要求把多核优化作为开发主线，允许大范围重构。本轮已交付执行底座并测到复杂8192人，下面登记实际完成范围与剩余容量限制，不把“有线程入口”当作所有规则都已并行。线程划分、数据交换和失败处理统一见[执行方案](../specs/world-engine/execution.md)，成熟项目依据见[研究](../../design/research/large_simulation_optimization.md#多核执行2026-11-11)。

**总体状态：进行中。** 上一轮将底座与首轮压测的完成误当作整个goal完成，现已纠正。原生身体准备/判断/采用、显示交接尾部和受干扰的并发选型仍是本次任务的未完成部分，不因拆阶段就变成需要重新授权的另一个项目。

目标是让**主要计算**能分批并行，缩短模拟关键路径并解除显示线程阻塞。CPU总占用率、线程数和微小算子的倍数不作为交付结果。已有稀疏/分频、共同时间及CPU/GPU机制继续作为基础；本阶段不把零散单线程微优化列为独立开发项目。

| 顺序 / 顶层交付 | 内容与可观察结果 | 当前状态 |
|---|---|---|
| 1. 执行成本与共享读取底座 | 分清准备、排队、执行、等待、采用、发布；消除worker对活SceneTree及会隐式同步世界的getter的依赖，原owner提供可复用分块读取视图 | 已落地共享几何、身体成员复用、脱离原身体的身体显示发布、批量空间查询及Windows实际线程CPU采样。其他视图仍在完整边界读原世界 |
| 2. 模拟与显示分离 | 世界由一个模拟协调线程持有；主线程不阻塞推进或并发遍历活世界，统一时间和有序提交保留 | 已实现常驻协调者、单个邮箱请求、输入缓冲与Node信号递送。旧UI/画布在完整边界独占交接时读取，计算期间暂缓；身体/镜头插值及已捕获绘图继续。完整双缓冲留作后续取舍 |
| 3. 主要计算进入共用任务池 | 将实际主要计算族分批，争用与因果由原owner提交；不为增加线程数恢复无用工作 | 已接需求/路段数学、完整身体显示和交锋候选。普通路线请求与动作仲裁仍顺序运行；当前成本并非普通路径搜索，暂不另建异步规划平台 |
| 4. 环境与跨域计算接入 | 现有GPU场候选与可分块CPU受体/采样共用依赖和批执行；只等待真正需要的结果 | 已接16×16 CPU场及来源响应输入批，GPU原路径保留；所有响应锚点、领域争用及原子采用仍归原owner。后台等待实际任务依赖，不用固定毫秒轮询延后 |
| 5. 收敛任务粒度与规模 | 同算法串行/多worker短对照，按端到端收益选择并发数；小批可串行，负载可扩展且不积压快照 | 已测0/4/8及CPU/GPU同包对照、复杂300–8192容量；开放12/16/20与按硬件/批量选槽。高并发追加受外部GPU/内存负载干扰，不可靠排名，生产保持4；没有宣称已实现线性扩展。原始结果与限制统一见BASELINE |

首批已把**几何读取、路径缓存和变化订阅移回模拟层**，原生人物与服务不再借运行时Node导航；投射物同边界只捕获一次身体输入，查询使用共用批执行。输入不会为每个worker重建地图，效果仍由原交锋owner提交。实现边界见[批计算合同](../engineering/execution-batches.md#共享空间读取与批量查询)。

本轮范围已实现并完成相关短检查与真实容量测量：普通千人协调者+4worker相对同协调者串行约高15%，显示阻塞显著减少；复杂50房间/128物件/32携带来源在300附近满速，600以上过载。8192暴露的全世界衣物扫描已沿原索引消除，近9秒人物尖峰缩到一次约0.44秒，但仍远未满速。具体版本、条件及不确定性只见BASELINE。

当前继续完成两项架构工作：原生身体阶段的可复用热列/独立候选判断，以及其后的显示快照与有序采用。前者扩大真正可并行的工作，后者缩短主线程独占交接尾部；沿现有池/内核/owner实施，普通寻路不预设为主瓶颈。高并发复测须分清外部显卡和整机内存竞争；保留自动档可选，不用受干扰数据改生产默认。尚未决定引入原生扩展，不为覆盖模块名义另建执行平台。

完成依据为：主要热点已实施适合的并行/数据边界，相关顺序与状态隔离核对通过，端到端收益和容量曲线能够在已说明条件下复核，剩余串行依赖有明确成本与取舍。既不以线程数量或CPU总占用率验收，也不把“尚有主要执行管线未处理”包装成全部完成。

每个实现阶段只做有关的短顺序/取消检查与相同负载的release核对。保留同算法的串行执行供对照；实际运行窗口和装配计数分开。重构中间态在代码与HANDOFF标明，不把候选当运行事实，不恢复旧CI/长回归。

## 性能出口与边界

最新用户要求完成整个多核计划，并测到核心框架的性能上限。300人保留为普通负载对照；复杂负载扩展到玩家周围上千个持续行动身体、几十个真实围合房间、密集冷热与五行来源交替。逐级增加规模，报告满速容量、帧时/输入延迟、CPU执行/等待、内存与过载拐点，不以某个固定人数通过作为完成。允许重构数据和算法；当前已采用有界来源采样，业务采用时刻仍由逻辑时间决定。范围不等于所有领域可以漏算。

当前300人普通混合负载尚未稳定60FPS；多核阶段优先处理上面的执行管线，以下内容按实际关联纳入：

| 领域 | 范围与待核对的问题 |
|---|---|
| 环境与建筑 | 真实建造/拆毁的原子工作及密集强源；普通穿门已不产生拓扑重建 |
| 共同运行与行动 | 本阶段主动重构热数据与任务边界，沿原逻辑时间/规则顺序提交；优先复用原kernel和Godot线程池 |
| 呈现与可玩整合 | 当前尾帧仍含公共发布、视野和布局成本，优先结合真实试玩定位 |
| 整机范围 | 在相同负载和构建下核对目标硬件及长局，不能由单个kernel提速推断 |

已尝试路线及证据见[研究](../../design/research/large_simulation_optimization.md)与[历史实验](../archive/qa/20261111_performance_experiments.md)。多核实现结构见[执行方案](../specs/world-engine/execution.md)，其中未完成内容不是当前运行事实。完整战斗、超凡玩法与内容扩展见[产品层次](roadmap.md)，玩法扩展先让位于本阶段多核管线。
