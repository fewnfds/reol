# 模拟执行架构重构计划

这是唯一实施计划。当前授权和停点看[HANDOFF](../status/handoff.md)，逻辑领域看[职责](../engineering/architecture/05-framework-domains.md)，目标结构看[执行规格](../specs/world-engine/execution.md)。现有class、schema、测试和已投入工作都允许替换。

## 第一目标：游戏实际跑得动

在[目标PC](../engineering/constraints.md#产品与技术范围)上，300个持续行动人物与建筑、植物、环境、近远区共同运行，保持1×世界流速与稳定60FPS。允许大范围重写和暂时破坏旧功能；优先证明可扩展的运行路径，再恢复内容。计算不足可平滑降速，但不能静默丢时间或改因果。

实际进展、CPU/GPU采用范围和测量只查[BASELINE](../status/baseline.md)，本页不复制结果或声称目标已达到。

## 先解决哪些成本

| 范围 | 已知线索及要回答的问题 |
|---|---|
| 数据和共同运行 | 同步准备、状态发布、动态字典、重复扫描和全体补算分别花多少；原状态能否直接以热批数据运行，避免搬进worker又逐条搬回 |
| 空间和单位行动 | 已测旧寻路通行查询大量重复；地块数据、路径候选、局部避让和身体执行能否共用局部结果，避免每次调用穿过整条领域链 |
| 环境和自然过程 | 背景、房间、来源和受体是否需要相同粒度；哪些局部变化被放大成全局工作，哪些密集数学真正适合GPU且端到端有收益 |
| 呈现和生命周期 | 画面/UI是否触发模拟补算或重复复制；初始化、存读、取消和对象更替是否让热索引/任务长期增长 |

这些是调查范围，按实测最大成本选择，不逐项建设独立优化模块。CPU多核、Godot原生算法、GPU、数据布局和适当简化都可采用；不为了“使用GPU/多线程”增加比原计算更贵的准备和同步。

## 仍按顶层框架交付

| 包 | 能力与出口 |
|---|---|
| A：共同运行与热数据 | NPC移动/搬运链的数据、工作选择和批量采用重构；以实际主线程成本下降判断，现有接缝可替换 |
| B：空间、行动和自主执行 | 局部空间数据、导航、活动动作和必要决策协同；分散/拥挤和多目标下测增长。依赖共同数据接口，不等空平台全部建完才检查最大热点 |
| C：环境与自然过程 | 按实际影响范围组织计算，普通Main真实采用CPU/GPU结果，含设备回退；依据准备、传输、计算和发布总成本选择设备 |
| D：呈现、存读和可玩整合 | 视图读已提交结果，关键操作可用，整合达到300人目标；删除被替换的旧运行链，避免长期维护两套模型 |

已确认的身体/原物归属、共同时间、可中断行动和有限认识继续是游戏方向；内部表示和算法不冻结。大改引入的具体行为变化说清楚即可，不为旧功能永久保留复杂兼容链。

## 开发节奏与采用标准

### 参考资料驱动的实验清单（2026-11-11）

用户已授权长程实验和大范围重构。下表是同一计划内的候选，按主要成本调整先后；“尝试”包含隔离测量或小原型后决定不采用，不为不适用的技术强行接入。来源、版本和适用限制只在[研究](../../design/research/large_simulation_optimization.md)维护；结果只在[BASELINE](../status/baseline.md)维护。

| 包 / 思路 | 要验证的改变 | 当前状态 |
|---|---|---|
| A/D：隔离真实成本 | 普通Main中分别量规则、发布、画面；核对构建、限帧与诊断开销 | 已补真实Windows release入口及同负载开发版对照。最新同构建300/512人结果见BASELINE；巡行的剩余长帧有不同来源，不以开发版成本或旧探针漏计推断瓶颈 |
| D：合并呈现刷新 | 已提交通知统一发布人物投影，面板/画布只对相关变化工作 | 已统一人物投影，复用已受理路线和领域动作，只构造可见格布局；主线程工作下降。整批画面延后一帧使实际帧尾变差，已撤回，排队攻击及视野的提交顺序保持 |
| A：共享查询与索引 | 身份/控制/活动输入一次读取，多次使用；避免同边界反复穿过领域链 | 身份来源使用直接索引；当前全路证明供精确跨格/投影复用；局部几何变化只使相交/未知路线失效，消除山兽变化后的全区准备峰。到期索引typed原记录已试无整局收益并撤回，继续处理初始化/发布等剩余成本 |
| A/B：按到期工作 | 局部过格子只唤醒真实受影响工作，减少完整世界结算链重复进入 | 已分离局部几何与世界后果，并按来源/认识/空间索引的真实消费者保留跨格；库存观察不再物化全体身体，库存缓存先于截止点规划建立，release首个20秒样本最低流速1×；继续核对其余负载和帧尾 |
| A/B：认识分发与局部候选 | 同一事件一次准备各可知范围，保留各人的来源和确实看到的结果 | 密集重派中已减少取消后的分发成本；同刻事件共用格位采样，每事保存一份原文和紧凑的个人获取索引。持续巡行与联合存档有实测，下一步核对不同领域高频交互 |
| A/B：稳定区间积分 | 位移/需求按输入段求值，动作边界执行后果；保留移动来源及接触依赖 | 已从单格扩到有全路证明、无途中消费者的完整native路线，原行动仍拥有状态；native主线程实际减少，整局帧尾未改善，过渡反例通过 |
| A：紧凑原状态 | 以类型化列/活动分组直接运行，比较持续存储与反复打包的成本；不预建全量ECS | 原身体typed余额/Vector2迁移已接实际批输入和采用，普通整局无可信收益，已撤回；不能凭隔离循环继续扩大迁移 |
| A/B：扩大多核覆盖 | 足够大的隔离任务、重叠执行、确定顺序采用；包含准备/回收/发布总成本 | 大批只读导航有纯计算收益；在512人普通链路降低身体批门槛会增加准备、回收等待及缓行，已撤回。扩大覆盖优先找独立且足够大的实际工作 |
| C：GPU普通环境接入 | 复用已有compute，比较CPU小更新与GPU大批、传输和设备回退 | 普通来源候选/响应已实际采用常驻GPU，环境主线程成本下降；完整帧尾仍未改善，保留CPU回退，后续按真实密度复核策略 |
| C：来源/受体局部失效 | 空容器、不影响环境的移动、稳定房间不制造无效重建；共享重叠覆盖 | 已保留实际非零容器索引及来源续算；分钟人体采样共享地区背景，沿原轨迹求格，仅补齐实际改变消耗率的人物。房间范围仍按实际成本选择 |
| B：空间邻域与连通性 | 用已有索引验证密集/不可达查询；精确维护变化，比较局部格/块粒度 | 植物和兽身扫掠使用局部失效及共享净空查询，观察先筛候选。实际地形的混合目标中，弱连通分组可拒绝大量不可达；只在覆盖完整且通行规则匹配时适用，未进入普通链路。邻域密度仍按实际负载验证 |
| B：共享流场与路径缓存 | 多人同目标复用；不同目标、通行能力和结构变化下比较收益与行为 | 实际同目标、封路、紧凑几何及局部更新原型均已试。共享反向解有规模收益，冷建仍超预算；常规巡行未显示为主要成本，先保留有复用的密集导航候选 |
| B：分层/局部导航 | 远距离与不可达拒绝的适用性；不用房间ID冒充通行连通域 | 已试块内分组与跨块接点的不可达拒绝；更远距离路径需证明实际负载和路径质量，再扩到分层寻路 |
| D：原生/批量呈现 | 实际人物外观、可见性、排序与插值保持可用，比较共享shader、Server/MultiMesh等完整成本 | 已保留原生变换及共享shader选帧/合层。动画缓存、原生分层Sprite2D无净收益已撤回。MultiMesh隔离原型减少提交成本，原Sprite2D在同材质探针中也已合为一次绘制；未证明保留不同外观和遮挡后的整局收益，暂不切换 |
| D：视图复用与资源共享 | 可见性进出不反复创建/释放，定义/形状/外观共享，不缓存第二份世界 | 共享材质/图集已采用，近区人物视图隐藏后复用；远区访客当前进出时创建/释放。增量格布局缓存和循环合并已试无整局收益。访客复用用移动观察负载判断，固定镜头巡行不足以验证 |
| A/D：按需工作与精度 | 静态/离屏表现休眠、真实输入唤醒，不能因看不见更换战斗规则 | 已保留植物画布按真实依赖失效；512人静止镜头下移除逐帧迷雾扫描只省局部成本，帧尾几乎不变，未采用。其他画布和密集交互按实测选择 |
| D：分散初始化峰值 | 场景/资源按需准备，区分冷启动尖峰与持续吞吐 | 实测并拆开两地首次行动索引准备，不改下一逻辑时刻或省略工作；整体P99未变化。资源初建/地图预热仍独立测量 |
| A：原生热点后备 | 若合理布局仍受脚本解释限制，先做有界成本评估；新语言/依赖按基础边界处理 | 尚未引入原生扩展；已测剩余长帧未指向一个持续占主导的脚本算子。混合负载如出现这类热点，再做隔离替换并量数据准备与采用总成本 |
| A/D：长期数据与内存 | 只对发现的索引、任务、视图增长做短复现；核对退出/替换回收 | 已定位大量重复认识记录，原事件与各人获取索引分离；内存增长显著下降，档内不再展开重复直接观察。其余长期增长按实测推进 |

每项记录保留、放弃、已具备或负载不适用的原因；无端到端收益就停止该路线，不继续围绕旧接口叠加复杂度。清单不要求给每行新增模块、测试包或独立文档。

按[开发循环](../engineering/workflow/testing.md)做有界测量与相关短检查，以普通运行链路的整体改善决定是否采用。无可信收益就重新选择数据、粒度、算法或后端；本计划中的实现候选可以推翻，不因已有接口继续低收益小修。

完整战斗、超凡玩法和正式内容在可扩展底座上继续建设，产品方向见[roadmap](roadmap.md)。本页不再生成额外的小算法计划或重复的测试优化队列。
