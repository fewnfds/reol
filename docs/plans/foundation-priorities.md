# 世界运行基础：现状与实施优先级

核对时间：2026-11-05。本文根据游戏起点 `bbd4303eb2ae477015dd1d9a40b170562c40a4d8` 及下文明确列出的工作区 WIP 整理依赖，不代表这些建议已经实现或通过验收。此次只整理和报告优先级；P0a、P0b、P0c 及后续均为建议，由用户逐项排定后实施，不自动连做。每个包完成并验证后报告，再由用户决定下一包；排定后，包内普通技术细节自主处理。实际状态及未提交工作以最新状态文档和实际工作区为准。

目标是让物品、身体、动作、空间和环境接入同一持续世界。先建立能完成实际操作的窄接口，再沿真实需要扩展；保留已有原状态所有者，不为此预建万能实体类、全量 ECS 或另一套时钟。所有领域的开发者查询都必须经过观察与知识过滤后才能展示给玩家。

## 实际起点

表中“专用”表示实际有可运行路径，但仅覆盖列出的场景；“隔离”表示不属于普通 Main 的运行功能。无论状态名称，都不隐含大规模性能达标。

尤其要避免把新场继续绑在少数示例上：[artifacts](../../scripts/sim/artifacts.gd) 的 `_finish_thermal_switch`、`_finish_warming` 直接调用旧 `local_heat`，后者还读取旧 `pulse_energy`；[construction](../../scripts/sim/construction.gd) 的墙、门、顶变更也直接协调旧热拓扑。替换时必须明确这些既有真实操作和状态的去向，不能同时运行两份相互竞争的权威温度。

## P0：实物、能力与动作的分包建议

这不是一个一次性完成的“大框架”包。建议按下列三包建立最小闭环；每包需由用户单独排定，完成后停止并汇报。保留现有身体、独特器物、库存和共同时间的原所有者；定义是模板，实例/批次是事实，查询和显示是投影。

### P0a：引用与能力只读查询

**范围**：围绕现有 `SimEntityQuery`、`SimEmbodiment.capable` 和 `SimArtifacts.has_capability`，给一个人身和一个独特器物提供一致的最小只读查询结果；结果明确引用类型、原所有者、能力是否可判定，以及缺失、无支持、位置或时钟滞后等失败状态。不是通用实体注册、生成或属性系统，也不修改存档格式。

**可验出口**：以实际装配的一个人身和一件器物查询各自已有能力；不存在引用、错误类型、未知能力和世界时间积压都能明确区分，不把无法查询当作能力不存在。查询前后身体、物品、时钟和持久状态不变；开发者全知结果不直接暴露给玩家。核对实际来源和定向测试，再按项目规则完成相应回归。

**停止扩展**：不改玩家界面，不加入新物品玩法，不接环境、堆叠、动作执行或新自动加载器；不复制身体和器物状态。

### P0b：单件实物的受控生成与地面—容器闭环

**范围**：在 P0a 之后，沿用真实独特器物的定义及原所有者，受控创建或取得一件器物，支持在一个合法地面落点与一个原容器之间放置、拾回和转移，并定义合法移除；不同时处理数量批次或所有物品域。若生成与移除使本包过大，另拆为紧随 P0c 的独立小包，由用户排定。

**可验出口**：创建成功只形成一件原物并保持唯一 ID；同一 ID 和状态完成放下、拾起、存入/取出，合法移除后引用明确失效。无效创建或移除、位置切换失败、中断、重试、保存重启不能复制实物或重复提交。可见交互按工程规则实机核查；源场及人物携带辐射仍不接入。

### P0c：普通材料堆拆与最小动作合同

**范围**：在前两包可复用的引用和位置边界上，针对一种真实数量材料补合并、拆分及有限操作；提炼必要的请求、预约、耗时、完成前重验、一次提交与结果通知，具体领域仍负责自己的规则和原账。

**可验出口**：同类、状态相容的材料可合并和拆分，不同物品不能合成同一堆；总数量守恒，失败、中断、重试和在途存读不复制、不重复扣取或提前发布效果。相同堆的数量在未来普通辐射中只按一件强度投影；人物内部物品的对外辐射不在本包实现。

**共同停止边界**：不统一所有历史域，不引入完整背包容量、制作百科、自由文本、完整穿戴、NPC 工作规划或万能实体类；不为冷热石增加新玩法或收费机制。必要时使用清晰适配器保持唯一所有权，再在后续包淘汰重复运行分支。

## P1：将新环境接到真实世界

**输入和范围**：使用 P0 的真实地面物品变更、现有地理天气与共同时间；复用隔离的七通道场与温度响应候选。先接普通户外、少量真实物品及最小受体/调试观察链，冷热与五相规则按现行世界设计分别计算；不将可吸收灵气储量与不可消耗的环境影响混为一项。人物内部物品的对外辐射继续后置。

**出口**：真实放置、取走或改变来源可在同一世界影响环境；同类堆数量不扩大强度，冷热按各通道取最大后抵消，物品移走后的实际温度按时间逐渐回归。来源更改需先处理旧时段，再在可接受的共同时间边界发布新目标，不能因为 GPU 尚未算完就把待算当零或提交旧结果。

同一输入和时刻的 CPU/GPU 结果按声明精度一致；GPU 不可用、超预算、计算失败或结果过期时安全回退/重算，不能产生第二个世界。至少验证重叠冷热、跨块、移动/移除、最强源替换、共同时间整段与分段、进行中及完成后的存读、离场返回。普通 Main 只在确有后端接入并能正确处理失败后提供可选设置；不能放一个没有效果的开关。

**停止扩展**：先不一次实现所有受体、复杂遮挡、定向/反射能量、五行相生相克、吸纳修炼、海量物品生成或完整大型世界。必要的现有墙门拓扑兼容要明确，完整室内处理进入 P2。替换旧模型的有限旧档政策与拒绝方式须在本包定义，不永久维护两套运行热域。

## P2：可组合的空间与房间

**输入和范围**：从既有墙、门、顶和工地派生空间，逐步使地块、结构和实体占地通过明确接口查询；P1 同一环境域消费空间变化。工地只是样本，不能把它当所有房间的固有边界。

**出口**：一处由真实墙/门/顶围出的房间能承接多个真实来源，按面积汇总形成单一室温并随时间响应；验证开关门、拆墙、分房/合房与露天的温度连续、寻路和存读。占地只引用原实物，蓝图不提前变成实体，房间功能由人和家具的实际能力形成。完成自动墙形或跨块拓扑若是该次实现的必要部分，应分别验证。

**停止扩展**：不以房间命名强制生产，不预设完整家具百科、永久固定的组织形式或所有房间玩法；多格实体与任意区域的完整编辑能力另拆工作包。

## 后续依赖

- **通用实体创建与移除**：P0b 先验证单件器物的原定义、唯一 ID 和原所有者；其他领域按需要接入受控创建、存在性及合法移除，失败不部分改变世界。不要把个别物种的出生、死亡规则误称为通用创建合同。
- **导航与区域**：基础空间之后、自然响应扩展之前，补充动态障碍、多格占地、预算耗尽/不可达的明确结果、区域指定与地图编辑；行走位置持续、寻路可预算，跨块和存读使用同一事实。
- **自然单位与世界响应**：在上述空间、创建和环境查询边界上逐步接植物、动物、人物、材料与超凡过程；生长、死亡、破坏及可吸收灵气各自拥有真实状态，避免每种对象都强塞共同属性面板。
- **行动与创造**：按实际玩法逐步扩展动作、技能、战斗、制造与组织，并保留无 AI 时的结构化操作；不得让未来模型绕过权威规则。
- **远区和长期世界**：使用同一共同时间和已声明的近似合同，预算不足保留积压；出生、死亡、旅途、事件与有限转生另按真实状态逐步接入，不能以离开镜头后冻结代替。
- **编辑和内容**：由当前定义/场景入口逐步支持地图、对象、区域和环境的离线编辑、隔离预览与可保存装配；不要把开发者全知信息当玩家认知。

## 性能与 GPU 验收

先量端到端，再决定优化位置。代码上可能随规模增长的路径包括：普通 BFS 的逐次队列与字典、`SimInventory.available()` 对预约/保管记录的扫描、建造 `_reindex()` 对项目与工地空间的重算、共同时间边界里的领域与路由遍历；这些是待测风险，不是已证明的热点。

[已有隔离场基准](../qa/20261105_field_compute_acceleration.md) 在 RTX 3060 上对 512²、每格一来源的七通道场测得 GPU 整图端到端约 160–166 ms；该口径含打包、设备创建、计算、读回和发布，不是帧时。2048² 全图一次性尝试触及 1 GiB 守卫，后来只验证了局部窗口。普通 Main 的小规模 180 帧样本 p95/p99 为 13.473/24.764 ms，只有 12 人、8 器物、0 活热格；两者都不证明稠密物品和 GPU 场合并运行的帧率或大世界容量。

每个相关包分层记录：硬件/版本/场景、区域和实体/源数、分布及变化比例、初始化/更新/查询、CPU 与 GPU 端到端、上传读回和主线程发布、每帧 p95/p99、内存峰值、存读/快进及正确性。递增规模并设置时间和内存上限；覆盖每格一堆的 512²、1024²、2048² 隔离候选，分别改变每堆数量 1/4/16/10000，另测静止、局部移动和大量变化。大图仍只是候选压测，不能写成普通地图已经扩容。

GPU 优先承担可批量的场计算，原对象、时钟、环境历史及发布仍由权威 CPU 侧管理；只在实际负载证明端到端受益时启用，较小或不支持的任务保留 CPU。渲染与计算争用、内存及驱动故障都需实机验证。没有足够证据表明 Godot 无法满足需求，不把更换引擎当作当前前提。
