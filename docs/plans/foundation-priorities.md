## 已交付：可用的UI与交互

2026-11-13按用户确认方案实施。当前UI沿用#1操作者，采用常驻主角台、独立对象详情/情境命令、分类营造/种植/人物/地区抽屉、数量窗口与地形小地图。只用按钮名称、图标、高亮、禁用和真实数值表达，不加入备注、副标题或面板解释；未定人物属性用锁定入口占位，背包只接现有物资。

三个体验段已合并提供：基础观察/指挥/SL；真实数量取放、设施与单次营造/种植；现有社交/示例交换、协作/修行/旅行、小地图和DEV归位。实际键位/完整能力只维护在[FEATURES](../status/features.md)，实现职责只维护在[架构](../engineering/architecture.md#交互与小地图)，同包测量与失败范围只查[BASELINE](../status/baseline.md)。

实施时收敛了原候选范围：建造与种植均为单次放置并发起行动，不做连续放置蓝图/Shift队列，避免无物流/工作分配时产生假自动施工；已创建对象与行动受理分别反馈，原有扣料/资源规则保持。进度显示当前真实行动和剩余时间，不新增全局命令追踪平台。小地图采用已有瓦片/迷雾纹理、静物剪影缓存与可见单位点，而非第二相机重绘场景。

多控、征召、编队/群体避让、生产订单、区域任务、跨仓自动备料和完整人物/装备界面仍属未定/未做玩法。本轮不以这些大项阻塞可玩交互，也不将首版临时布局变成后续必须遵守的产品约束。出口是可操作试玩，不自动开启下一轮UI或性能工程。

本次试玩反馈已接入：固定地块探针、贴底/百分比缩放、人物中文事件与冷热耐受；随机压力场源与普通开局分离，地区无实体演示源删除。能力/容量以FEATURES为准，结算语义归simulation-pacing，不另开UI、事件或抗性路线图。两个不同模型使用同一份冻结材料并发咨询并收齐正文，客户端与说明已更新在忽略的本机目录；数值、缺陷和性能判断经源码/实测筛选，不以顾问一致意见作审批。

本机先并发布局/交互/交付三个隔离one-shot，再补充小地图与无说明文字交互两题，均收齐正文并结合源码核查。采纳双焦点、上下文操作和分层地图；拒绝未测性能保证、固定控件数量、把全部UI说成零后台改动、猜测闭源实现和提前增加新玩法。咨询方式已补入本机顾问说明，原问答/核查留忽略目录，不是第二份主计划。

## 已交付背景：在高速内核上恢复可玩功能

2026-11-12用户要求继续添加功能：体验可以接近旧版，后端可完全重构。基础运行框架重建已完成，成果与删减只看FEATURES、BASELINE；不再把继续优化或恢复旧代码当成开发主线。下表保留本轮交付顺序与边界，已实现范围以FEATURES为准。

每段按一个完整体验交付，内部算法归入相应[领域](../engineering/architecture/05-framework-domains.md)。旧版用于核对操作和体验，旧类、旧存档格式与样例数量不构成兼容目标。普通试玩与千人基准使用同一后端、不同开局配置，不维护一套试玩后端和一套性能后端。

2026-11-12已创建执行goal，用户授权按下表恢复功能。首要成功条件是可玩与性能同时成立：每段多次咨询顾问开拓方案并核查实际实现，保留最终决策；若新增能力造成真实倍率或画面大幅回退，先改算法、唤醒方式、精度或范围，不能作为完成品收尾。对照应固定工作内容，功能越丰富允许实际计算成本增长，但不接受重新回到千人无法正常1×/2×/4×运行的架构。六段均已提供集成可玩出口；细节、范围与最终同包证据只查FEATURES和BASELINE。

## 六段交付顺序

| 顺序 / 交付领域 | 玩家实际能体验的结果 | 本段边界与依赖 |
|---|---|---|
| **1. 实物交互与可接续会话** | 在小型普通开局中选中人物和物体，接近材料堆、拿取、携带、放入箱子；中途停止或保存退出，回来后继续 | 对象身份和生成/移除、定义与实例、真实物品与容器、最小行动过程、存读一起服务这个闭环。先交付少量内容，不预建所有对象能力 |
| **2. 建筑、设施与自主生活** | 用真实材料围房、摆放箱子/床/生活台；人物寻找已知设施，取用、休息、加工和搬运，玩家能介入或打断 | 墙门/家具成为可作用对象；组合占地、围合和设施操作位接现有空间。预约、消耗、工期、取消复用第一段行动，不另造施工任务体系；简单自主选择随生活闭环落地 |
| **3. 自然环境与植物** | 在不同生境种植、养护、采收或砍伐；温度、五行、季节和来源对人、房屋、植物产生可观察差异 | 复用现有冷热/五行，再按需要补历法、天气、照度；生境、容器栽培、生命周期、残株与产物进入共同对象/行动。先做能体现差异的少量植物，成精等能力按实际玩法再展开 |
| **4. 即时战斗与身体能力** | 攻击移动、驻守、追击、近远程攻击和受伤成立，战斗能打断生活作业，战后能继续处理真实物资与设施 | 已有近身攻击/治疗继续可用，本段扩展索敌、弹道和身体能力。移动和中断沿用共同行动；Godot承担适用的物理/显示能力，命中后果归世界事实，不开第二套战斗时间 |
| **5. 人物交往与修仙成长** | 通过交谈、请求、交换或协作获得信息与资源；在已有器物、设施和环境中学习、修行、使用一种可检验的能力 | 认识、权限、承诺与执行逐步扩展；不先造覆盖所有社会行为的评分平台。修仙由真实对象、环境、行动和经历组合，不只叠属性或换配方名称 |
| **6. 大世界与长期接续** | 前往另一个有差异的地方，回来时原地事务已继续，人与物仍能接续 | 局部循环成立后再扩展世界生成、区块装卸、远区近似和地方差异；按实际需要扩展生命与出身。不以无限地图、完整生态或多层世界阻塞前面的试玩 |

认识不是第五段才加的补丁：当首次需要找物、找人或选设施时，就区分客观事实、本人已知和开发诊断；先提供局部可用的观察与记忆，再扩展传播和社会判断。战争迷雾随这条观察链恢复，静态物体离开视野保留上次所见，移动人物不因此获得永久可追踪位置。

左选右移、停止、相机跟随、对象数值和可操作反馈随首段维护；攻击移动/驻守随战斗扩展。每完成一段就更新正式试玩包供用户反馈，不等全部功能完工。现有已验证的移动、倍率、环境和基础战斗不因排到后段而重新删除。

## 功能恢复出口与边界

六段共同接到同一世界、通用行动与当前会话存读。植物/环境、战斗/身体、交谈/真实交易/协作/修行、感知/冻结记忆与有限地区旅行已接回；未迁回完整内容没有包装成完成。最终review、release重建、真实千人1×/2×/4×及持续战斗/施工窗口、独立进程续接的结果归BASELINE。

第六段当前出口是有限连通地图内真实旅行和原地事务继续，不是无限地图、区块装卸或远区LOD。修仙与社会也只交付可验证的代表性过程，完整玩法范围见FEATURES。已完成段落不留另一份继续实现的旧待办；后续从实际试玩反馈选择主题，不自动延长为无限优化工程。

## 已完成试玩反馈：单位视野与迷雾

2026-11-12用户补充战斗单位需要视野属性，已完成共同感知、战斗接触和玩家格图接入。实际接口见[架构](../engineering/architecture.md)，参数/精度见[运行与精度](../engineering/simulation-pacing.md)，顾问取舍见[原研究页](../../design/research/large_simulation_optimization.md#全单位感知与战斗视野咨询)，容量与局限只查BASELINE。

- 每个对象有视距字段，当前移动人物默认可感知、普通静态物默认0；日常观察、战斗发现与玩家格图复用共同损耗。常用格线准备与长半径后备没有构成玩法视距上限。
- 新威胁发现分散，当前目标及时复核；丢视野追最后所见，盲区受击不暴露隐藏射手。守卫跳过射不到的目标；不可达接触记住失败位置，相关条件改变再自动尝试。
- 玩家格图、探索/地表和静态记忆接通，GPU仅柔化掩码。已有读档/缓存修复一并保留，临时纯圆与旧GPU逐像素判定已退出。
- 查询批复用现有CPU工作池，低量直接执行；短反例、实际移动画面与千人混合负载已核查。队伍视野共享、隐身、完整阵营和最佳开火点策略未因此预建，也不留下继续无限优化的待办。

## 已完成试玩反馈：地块环境、图块与柔和视野

2026-11-13按用户截图与反馈修复，范围沿既有Terrain/Nature/Facilities/感知和呈现职责落地，不创建另一套地块引擎或视野结算器。

- 地块分层、自然生境与清场：自然基底/装饰地被/可作用植物/人工地板分开，地板施工按植被等级准入，花盆和原有房间围合保留。详细语义只查[架构](../engineering/architecture.md#地块与实体分层)。
- 素材和排序：修正不等高切图、整树脚点、墙脚地板覆盖和跨人物/地物的前后排序，邻接墙自动选直线/角/分叉。重建入口与限制只查[assets](../../assets/README.md)。
- 视野：共同感知仍供NPC/战斗使用，预平滑损耗及连续余量提供弧形软边，保留最后所见静态物。精度只查[运行与精度](../engineering/simulation-pacing.md)，不复刻严格光学或给每NPC生成全图。
- 收尾：相关短反例、真实视觉反例、同最终release的千人混合负载与试玩重建，结果只登记BASELINE；顾问和成熟项目取舍归原研究页。没有扩大为持续生态、任意材质自动图块编辑器或另一轮无限优化。

第二轮截图反馈已继续修复：程序天气的采样相位、源图固定列宽裁边、轮廓影断层与中心接地分别处理；墙按完整一格覆盖，斜向家具替换为程序原创的轴对齐四向，建造占地同步旋转。实际方向运动、近景、同包性能与局限归BASELINE，素材参数只归assets；不扩展半格墙或新增一套物理世界。

## 开发取舍

沿[现有运行边界](../engineering/architecture.md)扩展即可，后端布局仍可重构；新功能按[计算接入](../engineering/execution-batches.md)选择直接执行、到期唤醒、CPU批或GPU显示，不要求全部对象成为每50ms更新的单位，也不强制低频业务进入并行管线。出现真实共同责任再提取，不预建万能ECS、事件总线或七套领域框架。

验证围绕新体验与最可能破坏的因果做短检查；改变热路径或规模成本时再用同负载release短窗对照。人口、活动内容与实际倍率一起报告，不能拿简化切片的万人结果保证未来完整玩法同速。旧CI和长回归不恢复，不把完整性能矩阵变成每个功能的前置。

顾问用于独立审视依赖、反例和成熟项目经验，不决定架构、不审批每次修改。采用或拒绝的研究依据归[原研究页](../../design/research/large_simulation_optimization.md)，原问答留本机；不再生成第二份路线图。长期产品方向仍见[产品层次](roadmap.md)。
