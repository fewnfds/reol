## 当前阶段：主要模拟负载多核化

用户2026-11-11明确要求把多核优化作为开发主线，允许大范围重构。方案与首轮核查之后，已开始落地共享空间读取及真实查询消费者；下面未实现的阶段继续是当前工作。线程划分、数据交换和失败处理统一见[执行方案](../specs/world-engine/execution.md)，成熟项目依据见[研究](../../design/research/large_simulation_optimization.md#多核执行2026-11-11)。

目标是让**主要计算**能分批并行，缩短模拟关键路径并解除显示线程阻塞。CPU总占用率、线程数和微小算子的倍数不作为交付结果。已有稀疏/分频、共同时间及CPU/GPU机制继续作为基础；本阶段不把零散单线程微优化列为独立开发项目。

| 顺序 / 顶层交付 | 内容与可观察结果 | 当前状态 |
|---|---|---|
| 1. 执行成本与共享读取底座 | 分清准备、排队、执行、等待、采用、发布；消除worker对活SceneTree及会隐式同步世界的getter的依赖，原owner提供可复用分块读取视图 | 已落地16×16几何读取块、保留旧块的只读输入、模拟层导航绑定、同边界身体列及批量空间查询。完整呈现发布、身体热列复用与线程CPU追踪待做 |
| 2. 模拟与显示分离 | 世界由一个模拟协调线程持有；主线程交换输入和完整呈现结果，不同步推进/遍历活世界。统一时间和有序提交保留 | 待实现。先替换实时导航、规则输入及视图中的跨线程调用，再移动owner；仅搬线程不能提高模拟内部吞吐 |
| 3. 主要计算进入共用任务池 | 身体/空间投影与感知查询、实际行动规划、战斗候选分批计算；共享库存/伤害等争用按原owner有序提交。先挑覆盖实测主要工作的一条完整链 | 首个真实消费者为投射物候选，按候选对数选择同算法串行/worker；普通混合负载并发飞行物少，仍走串行。主要运行负载的广泛并行尚待实现 |
| 4. 环境与跨域计算接入 | 现有GPU场候选与可分块CPU受体/采样共用依赖和批执行；只等待真正需要的结果，完整记录准备/读回/采用成本 | 原GPU路径在用；更多CPU任务及跨域重叠待接，不另建GPU系统 |
| 5. 收敛任务粒度与规模 | 同算法串行/多worker短对照，按端到端收益选择并发数；空闲负载可串行，较大负载能稳定扩展，不制造队列/快照积压 | 待主体管线落地后开展，避免先做线程参数矩阵 |

首批已把**几何读取、路径缓存和变化订阅移回模拟层**，原生人物与服务不再借运行时Node导航；投射物同边界只捕获一次身体输入，查询使用共用批执行。输入不会为每个worker重建地图，效果仍由原交锋owner提交。实现边界见[批计算合同](../engineering/execution-batches.md#共享空间读取与批量查询)。

下一小阶段继续**身体热数据与完整发布接口**，逐一替换显示/UI/手动运动对活世界的同步读写，再迁移模拟协调线程；线程CPU/等待分解同步补足。当前身体列仍每批由owner捕获，查询在交锋回调内收集结果，原生决定与公共发布仍在主线程。以身体—空间查询—服务/战斗消费链为接入对象，寻路作为同一底座的消费者，不另开纯寻路长期专项。

每个实现阶段只做有关的短顺序/取消检查与相同负载的release核对。保留同算法的串行执行供对照；实际运行窗口和装配计数分开。重构中间态在代码与HANDOFF标明，不把候选当运行事实，不恢复旧CI/长回归。

## 性能出口与边界

目标仍是[目标PC](../engineering/constraints.md#产品与技术范围)上300个持续行动人物与建筑、植物、环境共同运行，保持1×流速与稳定60FPS。允许重构数据和算法；当前已采用有界来源采样，业务采用时刻仍由逻辑时间决定。范围不等于所有领域可以漏算。

当前300人普通混合负载尚未稳定60FPS；多核阶段优先处理上面的执行管线，以下内容按实际关联纳入：

| 领域 | 范围与待核对的问题 |
|---|---|
| 环境与建筑 | 真实建造/拆毁的原子工作及密集强源；普通穿门已不产生拓扑重建 |
| 共同运行与行动 | 本阶段主动重构热数据与任务边界，沿原逻辑时间/规则顺序提交；优先复用原kernel和Godot线程池 |
| 呈现与可玩整合 | 当前尾帧仍含公共发布、视野和布局成本，优先结合真实试玩定位 |
| 整机范围 | 在相同负载和构建下核对目标硬件及长局，不能由单个kernel提速推断 |

已尝试路线及证据见[研究](../../design/research/large_simulation_optimization.md)与[历史实验](../archive/qa/20261111_performance_experiments.md)。多核实现结构见[执行方案](../specs/world-engine/execution.md)，其中未完成内容不是当前运行事实。完整战斗、超凡玩法与内容扩展见[产品层次](roadmap.md)，玩法扩展先让位于本阶段多核管线。
