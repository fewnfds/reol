官方目录及全部子篇已逐篇核对，适用性只维护在[研究矩阵](../../design/research/large_simulation_optimization.md#官方性能指南逐篇核查2026-11-12)。本轮完成主要减量、批量、GPU资源复用、review和最终release重建/核查，代码与文档一同交付main；实际测量只见[BASELINE](../status/baseline.md)。该优化阶段结束，后续先由用户体验与讨论决定功能范围。

已有轻量功能导览；启动方式见[功能试游](../engineering/tooling/usage.md#功能试游)，体验步骤只维护在游戏内。右键移动、A/S/H仍是下方保留的功能阶段，本轮没有提前启用。

### 运行效率取舍

目标是减少无用工作、缩短关键路径，并让已有CPU/GPU机制能被后续内容复用。世界事实、模型精度与调度延迟的唯一定义见[运行与精度](../engineering/simulation-pacing.md#世界事实与计算精度)。本轮没有改变共同时间、人物活动数量或既有来源采样频率，不靠停工、漏算或调快时钟提速。

| 方向 | 本轮最终取舍 |
|---|---|
| 同刻环境变化合并 | **采用**：同一时刻按key折叠移动/耗尽/过期，紧凑空间组合批；合并场求值、响应编译及设备派发，最后按并集刷新房间。单源外部事务继续复用原入口。协议只见[环境合同](../engineering/world-environment-contract.md#存读失败与性能) |
| GPU资源与派发 | **采用**：复用worker私有缓冲及绑定，在原访问预算内扩大派发片；稀疏远距变化走逐tile CPU，避免巨大空白矩形。上传、读回与依赖等待仍有成本；机制只见[计算接入](../engineering/execution-batches.md#gpu来源场与cpu后端) |
| 身体发布与节点应用 | **采用**：变化驱动的不可变衣着外观、发布时直接收集远区ID、复用未变朝向/外观，隐藏及插值完成节点停用空回调。真实位置和必要空间列继续发布，不把不可见人物退出模拟 |
| 身体owner元数据 | **采用**：下一截止判断输出连续整数列，复用单个读取对象；有序名册按原替换/恢复重建。保持原边界、取消/代次与回退语义 |
| 物品视图 | **采用**：保留上阶段外观捕获与携物平滑跟随分离；位置查询复用已受理路线，单次构建复用已读坐标，减少只为画图而积分身体。取放/暂停通知/迷雾/读档仍沿原owner |
| 目击者索引实验 | **撤回**：扩大适用范围及改扫已占格均无明确端到端收益；保留原局部索引与稳定结果，不积累两套试验分支 |
| 直接Server / MultiMesh / 全仓ECS | **不实施**：当前GPU绘制与原生提交计时不足以支持全面替换人物节点；透明顺序、独立外观、文字、选中及裁剪仍有适配成本。现有规则已经脱离SceneTree，纯视觉已有shader/atlas；3D LOD/GI/鱼群控制不直接适用 |
| 编译尖峰 | **保留现有预热与原生导入**：持续慢的主因不是已测GPU绘制或某次管线编译。headless导出不支持shader baker，不增加无效开关；以后新材质的首次尖峰按实际pipeline计数处理 |
| CPU更多worker / 寻路重写 | **保留已有批与选槽**：真实批已并行，准备/采用及串行owner仍限制扩展；普通导航提供者在该窗占比低。没有收益依据不固定扩大所有任务并发或重新造寻路 |
| 缩短安全输入交接 | **暂缓，保留体验缺口**：内部边界提前返回不足以让命令合法受理，还需同时处理时钟欠算、输入guard和发布成本。现有输入缓冲继续工作；本轮未声称解决所有命令等待 |
| 预算化NPC新决定 | **暂缓**：当前主负载持续在途，延后尚未开工的决定不能代表相同工作更快；等待真实决策尖峰再选择，不新增通用待办队列 |
| 慢环境跨步采用 / 区域所有权重构 | **暂缓**：联合候选已削减重复计算；余下等待与单owner串行仍是明确容量限制。跨步需要新生效时刻/陈旧范围，区域化需要真实独立依赖；本轮不以改时间戳或一域一线程假装完成，不把未来重构设成新功能门槛 |

release对照使用同硬件、渲染器、场景、窗口与诊断模式，装配/预热另计；CLI人数是每地人数。主要看实际世界流速、帧P95/P99、命令等待与实际行动量。临时callback/owner探针仅用于定位，已恢复原源码；不把带探针包的时长当纯吞吐收益。局部减量实测有收益才保留，负收益的协调者全衣着构建与无益索引实验均撤回。

本轮已完成review、最终包核查及主线交付。剩余容量与未测范围如实写BASELINE，不用“未来无限优化”掩盖它们；CI、长回归和8192人矩阵保持退役。下一项候选功能仍从下面的输入闭环开始，由后续用户讨论决定。

顾问用于独立审阅、提出反例和开阔路线；其结论经过源码及相关实机核查后才采用。没有采用固定收益、未埋点残差归因或所谓“32%捕获完全浪费”的推断。请求、原答和核查留本机忽略目录，不形成第二份主计划。成熟参考和逐篇官方来源统一见研究矩阵。

### 保留后续工作：输入、选择与指令

目标是形成一套可玩、可扩展的操作流程，让日常行走、交互和交锋共用命令入口。以下为待实施计划；当前可用键位仍只查[操作](../status/features/controls.md)，本轮没有提前启用右键移动、A/S/H。

默认采用鼠标指令控制当前化身。**观察目标**与**发令对象**分开：左键可以检查NPC、家具或草木，但不会因此接管它；移动命令默认交给当前化身。以后可指挥的同伴须先具有真实控制/合作权限，再扩展多选，不将全体居民变成RTS单位。

| 输入 | 计划行为 |
|---|---|
| 普通模式左键 | 只选择目标；空地取消选择。框选、Shift增减选择在确有可控小队时接入 |
| 普通模式右键地点 | 寻路前往；显示受理地点与到达/失败结果 |
| 右键单位 | 第一版走到可接近的位置；后续按已知关系和能力解析攻击、交互或跟随，不能将中立目标静默判作敌人 |
| A，再左键地点/敌人 | 地点为攻击移动：沿途搜索合法敌人、交战后继续原目的地；敌人为指定攻击。A不是范围伤害按钮 |
| S | 停止移动及当前可中断行动，清理尚未执行的后续命令；已发生消耗、已经飞出的效果沿原领域继续。停止后可按正常姿态应敌 |
| H | 驻守原位置，取消追击，只攻击自身射程内合法目标；不等同于格挡、无敌或自动追敌 |
| Esc / 预览时右键 | 先取消尚未提交的目标/技能预览，再按界面层次收起面板；不连带发出移动命令 |
| Q/W/E/R、D、F、I | 分别作为准备技能、身法、镜头跟随、物品入口的首选映射；具体技能仍需实际学会和装备 |
| Shift + 命令 | 后续加入有限队列；提交时反馈队列，执行时重新验证路径、目标与资源 |
| P、跟随/保护/撤退 | 基础流程稳定且有适用执行者后再补巡逻及小队命令，不先扩成全宗门调度器 |

键位重构与命令落地同时进行：现有WASD中的A/S和新命令冲突，默认鼠标模式会释放WASD；Shift闪身移到独立动作键，给队列修饰留位；F用于镜头，不兼任技能。雀身F落地/E啄食等身份动作迁入对应技能/交互槽，镜头键保持一致。数字编组与现有速度快捷键也有冲突，编组留待小队阶段统一处理，时间控制可继续使用HUD。若以后提供直接控制模式，应显式切换整套上下文，不让一次按键同时走路和发令。

按三个交付块推进：

1. **选择与移动闭环**：将Godot命名InputMap动作、UI/施工/普通地图上下文及命令路由收拢；复用现有输入缓冲、共同时间和路径执行器，完成左选、右移、停止、目标预览取消和明确的命令回执。UI点击、暂停下令、运行中下令、目标消失和不可达都能观察到结果。无需另建世界步进、人物位置或第二套寻路。
2. **战斗指令与姿态**：在原交锋/动作框架上实现指定攻击、攻击移动和驻守，定义遇敌、丢失视野、目标死亡、受阻、追击上限与恢复原移动的关系；目标搜索使用原空间候选/CPU批适配，动画只消费结果。日常工作被打断时交回原预约与资源所有者，S/H不直接清空原物。
3. **便利操作与扩展**：按实际体验加入Shift队列、快捷施法/普通施法选择、命令列表与少量重绑；有真实小队权限后才做框选、编组、跟随/保护/巡逻。先保证单一化身和生活交互能顺畅使用，再扩大操作范围。

参考的是成熟产品的操作语义，不声称拿到了其内部代码：[Warcraft III Unit Commands](https://classic.battle.net/war3/basics/unitcommands.shtml)区分Move、Attack、Stop和Hold；[StarCraft II Basic Unit Controls](https://news.blizzard.com/en-us/article/4552956/game-guide-basic-unit-controls)与[Special Control](https://news.blizzard.com/en-us/article/4552955/game-guide-special-control)提供选择、队列与编组参考。LoL的单一英雄/技能目标体验用于取舍，不照搬其经济或角色权限。

## 已交付基础：计算接入与项目记忆整顿

用户要求在已有CPU/GPU底座上提升代码质量与可接续性，不启动新一轮容量攻坚，也不建立每个新功能必须实现的万能接口。

| 交付 | 范围 |
|---|---|
| 清晰的接入选择 | 复用直接领域逻辑、事件/分频、CPU批与现有GPU场；适用范围和示例只维护在[计算接入](../engineering/execution-batches.md) |
| 减少扩展耦合 | 分开人物需求与运动读取；自定义需求保留原顺序计算，仍可利用无关的运动候选/边界批；诊断显示具体退化范围 |
| 收敛文档与证据 | 合并重复执行规格，删除过时的任务/候选关系；基线保留有效摘要，旧测量归档；参数以代码为准，命令只在usage解释 |
| 收尾 | 原规则和特殊回调的串并行状态对照、普通会话和短实机窗口已核对，证据归BASELINE；代码与文档一同提交main |

本轮不要求任何新领域先实现批执行、GPU后端或特定基类。发现真实公共责任时才提取机制，局部低频逻辑可以保持简单。

## 容量边界与暂不开展的工作

本轮完成官方指南核查与当前有证据的优化收尾，CPU批、GPU场和呈现减量已形成可复用路径；这不等于无限扩展或全玩法容量达标。此后先进入功能体验与开发，不自动恢复容量极限攻坚或重复增加worker；新的性能问题按真实热点处理。

保留的容量问题：下一边界选择/采用和有序空间通知成本、人物显示年龄、旧UI/画布的完整世界交接、压力驱动的真实动作/社会事件成本。千人以上负载仍有过载，最新证据见BASELINE；未覆盖完整战斗、长期运行和16GB目标整机。这些是已知边界，不是另一份必须逐项做完的队列。

本页之外的新功能范围由后续讨论决定。七个领域只查[职责表](../engineering/architecture/05-framework-domains.md)，长期游戏层次查[roadmap](roadmap.md)；研究和归档中的旧待办不自动恢复。
