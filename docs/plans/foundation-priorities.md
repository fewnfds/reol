# 世界基础架构建设与改造计划

基础建设唯一计划。职责见[领域归属](../engineering/architecture/05-framework-domains.md)，实际能力/缺口见[技术总表](../status/technical-status.md)，授权与停点见[HANDOFF](../status/handoff.md)，准确证据见[BASELINE](../status/baseline.md)。计划不代表已实现，也不自动授权开发。

## 计划层级与共同依赖

**顶层框架目标 → 模块职责/接口 → 内部实现与验证。** 内部算法、修复与优化归原模块，按普通入口、不同内容复用及跨域结果验收，不为每个小算法建立主计划。已授权框架内的小步不自动成为停止或重新确认边界。

参考[架构研究](../../design/research/colony_sim_architecture.md)及[自然地块研究](../../design/research/natural_world_workplace_sources.md)，复用定义/实例/能力、设施组合、可中断过程及变化通知；公开玩法不证明内部实现。保留原owner与共同时间，不预建全量ECS或全事件重放。

空间支撑建筑/植物，环境与生命反馈，行动/观察从首次可作用时参与。沿[共同结算合同](../engineering/settlement-contract.md)确定依赖、同刻顺序及完整发布；预算不足保留工作并主动降速，不冻结远区或丢时间。

### 扩域前与扩域时补齐的合同

| 归属 | 要交付的公共能力 | 依赖与验收 |
|---|---|---|
| 定义/装配＋存读 | 会话规则闭包、统一领域登记与安全保存 | 先把移动、值事房、约练规则绑定会话内容。载入A世界继续使用A规则，不混用当前磁盘B；新域接`SimWorldSaveDomains`及[通用存读管线](../engineering/architecture/04-persistence.md)，不重写中央恢复链；坏候选不改活世界 |
| 实体＋空间 | 唯一身份、受控生命周期及变化传播 | 随植物接生成、移栽、阶段变化、损毁与移除；空间、来源/受体、行动依赖更新或失效，恢复重建索引，不复制原物 |
| 行动＋原资源owner | 受理、接近、预约、复核、耗时、中断与一次提交 | 目标改变时释放或重评，已发生成本不抹去；第5阶段贯通过程投影、动态运动和搬运，效果仍归原域 |
| 认识＋原查询owner | 权威事实与本人所知分离 | 植物首次可见/可操作就接观察与理解边界；远区变化、隐藏药性、未察觉灵智不能从面板或自动工作泄露 |
| 共同运行＋各域 | 全局离散事件、有界工作与诊断 | 按[事件合同](../engineering/event-contract.md)交付可信规则、定时/条件唤醒、取消/期限、幂等与恢复；先接运输，再接植物。活动/到期/变脏执行，记录积压和历史增长；不能删除幂等回执、认识或在途依赖凑规模 |

顺序：**会话规则/事件 → 植物 → 环境组合 → 完整行动 → 共同认识**。横向合同随消费者补齐；授权/CI只看HANDOFF。

## 当前优先：共同运行与规模

先完成现有框架的规模出口，再扩大第6阶段。[人口与架构调查](../qa/20261110_performance_architecture_audit.md)支持以下顺序。共同运行与原身体执行在工作分支落实，准确状态看HANDOFF/BASELINE；后两包待实现。

| 框架交付 | 主要owner与改造范围 | 出口 |
|---|---|---|
| 共同运行与原身体执行 | `RegionalSimulation`、`SimSettlementKernel`、`VillageSimulation`、`SimActionExecutor`；按到期/变脏和依赖唤醒领域，动作/重试复用原索引；推进显式同步，读取不发业务通知 | 同一时间/阶段/积压；固定输入与游戏时长测有效工作，不再每人跨格重跑所有域/全员筛选；分片、中断、争用及存读同未来 |
| 空间与行动的导航接入 | `SimGridNavigation`、`SimMotionClearance`及原空间owner；比较原生搜索的几何复用、按移动能力/净空的局部失效；共同目标密集时比较共享flow field | 普通不同目标、动态墙门、多格身体仍成立，返回路径与实际执行均复核；以全游戏时间收益选择算法，不把插件独立跑分当收益 |
| 呈现与联合规模 | `WorldContinuityRuntime`、`VillageRuntime`及原视图；同次发布复用布局、局部可见/改变集合驱动投影，按draw calls/CPU/GPU证据选择池化或原生批绘 | 发布版原生100/300人持续真实移动，分别记录1×流速、帧P95/P99及积压；以60FPS、300人正常流速为本轮改造目标，联合拓扑变化/交互与停开。开发机结果和16GB/RTX3060目标分别声明 |

沿已有公共窗口组合多频率/到期任务与局部有序事件，优先保留精确顺序，退役隐式getter/旧轮询。动作量化、低频采样或环境近似须声明新精度/误差，不借卡顿改顺序、冻结远区或丢积压。

Godot负责原生搜索/几何/渲染，项目负责业务时间/仲裁；不先迁全量ECS或换引擎。插件按瓶颈/兼容选取，存读复用既有登记。

## 统一交付顺序

| 阶段 | 顶层交付 | 进入下一阶段的依据 |
|---|---|---|
| 1 | 世界地块与空间＋实体、物品、容器的共同接入 | 身体、地面物、建筑共享实时局部查询及变化接缝；取放/施工接最小行动；不同布局、取消与停开恢复一致 |
| 2 | 通用建筑与组合空间 | 定义/实例/能力、多格/朝向、材料、工地/用途、围合/屋面、家具操作位、原储藏/生产及耐久/损毁组合成立 |
| 3 | 植物实例与自然过程 | 生境、栽培承载、生长/物候、残株与产物、环境双向作用及最小植灵组合可复用；原资源账交接明确，离场/快进/停开连续 |
| 4 | 环境的跨领域组合 | 地表、建筑、植物、器物与身体组合来源/受体；包含、遮掩、房间温度及分合连续性成立，风水读取真实布局和环境 |
| 5 | 完整单位行动与交互整合 | 不同身体/移动能力共用空间执行、动态重评、搬运/容纳及跨账本提交；玩家/NPC同规则，进行中可恢复 |
| 6 | 共同观察、认识与自主选择 | 来源明确的认识驱动需求/职责/目标，复用行动入口，未知和权限不泄露，远区认识沿实际媒介传播 |

建筑/植被按2、3集中推进，环境/行动/观察贯穿。花盆/植灵只补实际接缝，不等于完成第4–6阶段。

## 各框架的模块职责与出口

### 世界地块与空间

`WorldMapData`持地表，`ReolWorld`呈现区块；原owner持位置/几何。沿共同空间组合地面、容器锚点、覆盖层和阻挡；`SimObjectSpatialSnapshot`只覆盖显式集合。

**出口：** 多格同一实例，局部接触/净空查询有预算；生命周期、离场和恢复后查询一致，能区分未知、未支持与预算未完成。规模按实测声明，高差/多层后置。

### 实体、物品与容器

`SimEntityQuery`、`SimStorageQuery`、`SimEmbodiment`负责原解析；`SimArtifacts`、`SimInventory`、`SimObjectLifecycle`分持独特器物、数量/预约及受管事务。新域适配引用、能力与生命周期，定义/开局/实例分开。

**出口：** 原物、数量、成本唯一，失败/重试/取消不复制或吞物；索引恢复重建。阶段1覆盖地面/本人容器，容量/负重、嵌套及跨账本随第5阶段扩展；包含、保管和处分权限分开。

### 建筑与组合空间

`SimConstruction`持工地/项目/过程与结构状态，材料归原库存；`SimEnclosedSpace`/`SimStructureQuery`推导空间，`SimWorkplaces`/`SimResting`读取实际设施条件。定义组合多格/朝向、材料、施工/拆除与耐久；通行、视线、围合、覆盖、支撑及环境屏障分别表达。

家具提供可达操作位、容量或工艺条件；`SimFacilityUse`等复用预约/复核/释放，原生产持配方、在制品及工时，环境持光热，行动/战斗持主动攻击。花盆新增的栽培承载能力随植物消费者接入，不另建一套植物状态。

**出口：** 不同材质/几何/能力定义及至少两种布局复用施工与恢复；Main可选择、朝向、建造与使用代表设施；材料守恒，取消/拆除/损伤有明确结果，围合与屋面随原变化成立。在途/完全停开后同未来。房温、全部工艺、维修与完整战斗按所属框架继续扩展。

### 植被与自然生命

目标是能持续存在、变化和被作用的植物框架；接缝与范围见[植物合同](../engineering/plants-contract.md)，已定方向见[生命规则](../../design/rules/lives-and-progression.md)。本节规定工程范围与验收。

#### 模块与数据归属

| 模块 | 本阶段交付与接缝 |
|---|---|
| 定义与实例 | 草本/木本、水生/旱生、一年生/多年生复用定义；`SimPlants`持唯一ID、年龄、存活结构与变化，按需接共同引用，不要求每株有心智/背包/Node |
| 生境与栽培承载 | 分别判断自然分布、植根、生存耐受与适宜生长。`WorldMapData`/`NaturalEnvironment`提供背景；花盆持基质/容量及承载关系，植物不另存花盆位置 |
| 生命周期与物候 | 年龄、结构生长、开花结果与存活分别表达；成熟、休眠、受损、终止及残根再萌发由物种能力决定，读取共同历法、实际温度/光照及可用水 |
| 采集、残株与移栽 | 采叶/花果、伐取地上部、带根移栽、清除残株分别成立；接`SimActionContract`及原执行器，库存唯一结算，活株移动保留ID |
| 环境双向作用 | 条件影响生长/损伤；植物按能力提供五行、冷热或遮挡，变化使依赖更新；`SimWorldEnvironmentFields`持环境响应，植物持自身后果 |
| 灵智与行动组合 | 明确事件后关联主体/感知/交互能力，原身体连续；接`SimEmbodiment`和`SimInteractionRequests`，首版固定树精可有限交流并接受/拒绝请求 |
| 观察、存读与规模 | 普通世界可见、可操作；定义进内容包，实例接`SimWorldSaveDomains`。候选校验承载/产物/主体/在途引用，恢复重建空间与参与索引；未知药性/灵智不泄露 |

#### 必须分清的框架条件

- 生境判断区分自然分布、植根、适宜生长与生存耐受。局部池塘/花盆可以提供条件，不能按地图名字禁种；不适地块上的原株不直接消失。花盆提供基质/容量/已支持供水，温度、光照和物候仍成立，拆盆后去向明确。
- 原株身份、年龄、损伤、灵智与产物分开；移栽不刷新，采叶果、伐取、带根移栽和残根再生分别表达。成熟不保证常有产物，一年生按生命周期终止，多年生跨季节不重开幼苗；不同物种可有不同适生窗口。
- 植物、移动、灵智、敌对与方法按能力组合，不用深继承；觉醒保留原身体且只创建一次主体，不补造过去记忆。首版原地有限交流，完整树妖行动/修行后接原框架。
- 旧环境区间先结清，再提交原株/来源变化，后续使用新条件；快进保留物候/环境边界。火行不自动发热，环境五行不被吸收耗空，可消耗灵气另有储量。

#### 联合验收

`SimLandResources`与`SimPlants`明确植物来源、生长及产物的唯一交接，泉矿仍归原域；背景flora不能在原株采空/伐倒后重复发行或呈现同一株。花盆/活株移动沿原承载定位。

普通Main以一年生药草、多年生木本、水生/旱生植物、花盆、火属性灵草和原地觉醒老树验证不同定义复用；能力与边界沿[植物合同](../engineering/plants-contract.md)。采空、移栽、损毁、觉醒中重评行动，不重复产物/主体或遗留占地/预约。

**出口：** 跨休眠/年界、分片/快进/预算续算及在途完全停开同未来；坏候选不改活世界，不按seed补回采空植物或重抽觉醒。声明株数、活动密度及联合帧时/积压/存读成本；按生命周期重建空间与参与索引，不全株枚举所有可选能力。

#### 修仙扩展方向

特殊物候、繁衍、共生、变异、条件药性和成精诱因仍为候选；由原领域复用现有接缝，不让标签自动产生玩法，不写死年龄必觉醒。完整生态、化形及树身开局后置。

### 环境

本阶段扩展原环境模型，复用共同结算、事件、参与索引、空间和存读，边界见[领域归属](../engineering/architecture/05-framework-domains.md)。`SimWorldEnvironmentFields`承接冷热/五行响应，建筑/空间提供拓扑；自然光/局部光保留独立语义，生命/材料提交自身后果。按实际能力接来源/受体、包含及遮掩；不重复原物或房温。当前实现合同见[环境合同](../engineering/world-environment-contract.md)，不另建环境计划。

**出口：** 覆顶、开口、材质、房间平均温度及分合/开敞连续性成立，同处不重复叠加室内外温度；来源启停/移动/移除、材质/容纳变化后，旧处残留与新处建立可接续。人物与植物读取同一适用温度，植物接自然/人工照明，快进中采样可用性明确。冷热、五行、照度及灵气各按原规则；风水读取真实布局/水路/环境。近似、负载及存读有证据。

### 单位行动与交互

`SimLocalMotion`/`SimRouteTravel`写原身体位置，`SimMotionClearance`查净空；`SimGridNavigation`复用Godot AStar2D，原执行器持过程。第5阶段贯通现有身体能力、接近/通行、动态重评、原容器搬运和跨账本提交；共同投影/中断沿`SimActionContract`，效果仍归施工、植物、库存、战斗等原owner。

工作与即时战斗共用身体、空间、控制、时间和取消；战斗另持起势/命中/收势、飞行物与身体后果。以搬运中进入有限交锋验证接缝，不等待完整致死战斗。Godot负责原生搜索、几何与呈现，离场规则不依赖当前场景的物理帧。

**出口：** 普通Main完成不同容器的取货—携带—交付，玩家/NPC同入口；绕行保留身份/预约，不可达则中断。战斗/控制改变保留货物、保管责任和已付代价；进行中完全停开同未来。固定证据行旅/规定步法保留原中断合同。现有箱体容量及单次数量受限；普遍质量/体积负重、任意嵌套、全部飞行/穿墙法术和完整战斗后续扩展。

### 认识与自主决策

保留`SimSocialMemory`、`SimStockInformation`、`SimInstitutionBook`的原事实，复用需求、`SimAutonomousLivelihood`和`SimStandingWork`。观察保留时刻、来源与未知，需求/职责/目标基于本人所知选择已支持意图，再经行动复核。

**出口：** 至少两类需求/职责组合共用选择与执行入口，拒绝/失败能反馈并重选；秘密、未观察属性和远区新事实不泄露。完整人格、策略编辑语言及制度玩法继续按产品层次建设。

## 各框架共同的交付要求

以不同定义/布局及普通入口验证复用；联合覆盖“装配→改变→空间/环境反馈→离场快进→在途保存→完整停开→继续”、争用、取消及坏候选。兼容见[政策](../engineering/compatibility.md)，性能见[架构](../engineering/architecture.md)，局部测试不代替16GB/RTX3060整机目标。

性能出口按上面的共同运行与规模组织，保留原参与索引和同一因果；内部重构不以加大6ms预算、删事件或停止远区凑指标。任何精度变更按显式新合同验收。开局不证明规模，规则步不限制画面插值频率。

验证沿[测试策略](../engineering/workflow/testing.md)：游戏包先定向，再一次完整check或同SHA CI，画面/规模另取证。内部参考[世界骨架](world-foundation/README.md)、[装配/创作](../specs/world-engine/program.md)及[效率审计](runtime-efficiency/README.md)，不恢复旧队列。

战斗、修行、组织治理、任务与正式内容在上述框架上实现规则，接口存在不等于玩法完成。高差、坡道、多层/3D、复杂农务及定向能量继续后置；长期目标见[roadmap](roadmap.md)。
