# 世界基础架构建设计划

本页是基础建设的唯一依赖与交付入口，按完整框架组织目标。职责和跨领域接口见[顶层框架与领域归属](../engineering/architecture/05-framework-domains.md)，当前能力/缺口见[技术落地总表](../status/technical-status.md)，实际授权和停点见[HANDOFF](../status/handoff.md)，验证证据见[BASELINE](../status/baseline.md)。这里不登记当前任务或重复实现状态。

## 计划层级与推进方式

**顶层框架交付目标 → 模块职责与接口 → 内部实现任务与验证。**

- 主计划以框架的可复用能力和完成标准组织；每项实现、修复或优化必须能指出所属框架、主要状态所有者及它补齐的框架出口。
- 用户确定建设范围后，开发者在该范围内安排模块、算法、提交和验证，持续推进到约定的框架出口。内部小步完成后记录进度，不自动变成重新请求授权或停止工作的边界。
- 完成某个算法、具名物品样本或局部性能优化，只代表所属模块取得进展。框架完成需覆盖约定的公共合同、不同内容复用、跨域接入和相应运行证据。
- 完成标准声明支持的能力、规模和扩展接口；完整框架不要求一次实现所有物种、全部天气或深层玩法。新机制按其领域补实现，已有能力组合应主要通过定义与装配扩展。
- 已有代码、原所有者、共同时间和存读继续复用。计划页及旧任务编号不授予额外实现范围，也不恢复已结束Goal。

## 顶层建设依赖与出口

| 建设层次 | 框架交付 | 可核验的框架出口 |
|---|---|---|
| **基础承载** | **世界地块与空间框架** | 平面地表/材质与稳定空间键、区块与稀疏改造、空间层和多格占地查询共用原世界；变更、离场和恢复后事实一致；明确支持地图规格及查询预算 |
| **基础承载** | **实体、物品与容器框架** | 多类原对象经共同引用、能力和生命周期接入；定义/开局独立装配，物品与数量不重复，位置/保管/包含及转移有明确合同；不同布局可创建、改造和恢复 |
| **并列世界领域** | **建筑与组合空间框架** | 在基础承载上组合真实结构、家具、施工/拆除、围合和用途区域；结构事实供空间、环境和行动读取；功能由人、器具和过程成立，不靠房间名称生成能力 |
| **并列世界领域** | **植被与自然生命框架** | 植物/自然对象具有原实例和生命周期、声明占地及来源/受体能力；已支持自然过程和采集/损毁能改变同一世界，离场及存读后连续 |
| **世界条件组合** | **环境框架** | 气候、天气、温度、光照、五行等按各自规则读取真实地形/建筑/植被/物品来源并向受体提供实际条件；支持约定的来源变化、空间变化、残留及房间接缝；风水读取真实布局和环境，具体利用规则按已确认范围实现 |
| **行为整合** | **单位行动与交互框架** | 不同身体、体型和已支持移动能力使用同一空间事实完成移动/通行/寻路/接近及动作；请求、权限、意愿、预约、耗时、中断、提交和结果衔接，玩家与NPC复用；变化后过程可重评并可存读接续 |
| **行为选择** | **认识与自主决策框架** | 实际观察与有来源的个人认识驱动需求/职责/目标和已支持策略，选择同一行动入口；认识、理解、承诺和执行结果分开，远区事实沿真实媒介传播 |

主要依赖为：**基础承载 → 建筑/植被等并列领域 → 环境组合 → 行动整合与自主选择**。单位的身份、身体、位置、占地、能力声明以及必要观察/权限接口在基础承载阶段即接入；前面各层继续用现有单位验证，完整运动与交互在后续整合。建筑与植被不互相成为前置，已有环境能力可以持续参与它们的验证。运行中的反馈由共同时间安排，不把这张建设图解释为单向数值流。

## 各框架共同的交付要求

1. **实际复用**：以不同定义/布局验证同一机制，普通入口可使用；有限样本和隔离计算分别声明范围。
2. **组合变更**：接齐原生命周期、空间/环境依赖及相关行动重评，提供明确拒绝和未完成结果；不以静默零值代替未知、不可达或预算耗尽。
3. **持续世界**：沿同一共同时间处理取消、快进、离场/返回、进行中保存与完全停开恢复；候选失败不改活世界，支持版本按[兼容政策](../engineering/compatibility.md)声明。
4. **创作与观察**：随框架提供必要定义校验、装配/编辑、原因查询和诊断入口；编辑器、视图和玩家操作都沿同一事实来源。
5. **运行规模**：新增/重构路径按实际能力及活动/到期/变脏工作执行，验证实际声明规模；完整世界的联合帧时、吞吐、积压、内存和存读成本按[全项目性能基线](../engineering/architecture.md)核对。

性能改进首先归入受影响框架和交付出口。只有测得的瓶颈需要跨域协调时才单列有界工程工作，不因一个可优化循环或小幅内存差异生成新的主计划。

例如“墙门变化后的路径失效与重规划”归入**单位行动与交互框架 → 运动与通行 → 路径规划与执行**，依赖建筑事实与空间更新。它作为内部算法和验收项推进，进度归回行动框架，不单独充当下一项世界建设目标。

## 后续游戏与当前边界

战斗、修行、组织治理、任务、复杂生态和正式内容使用上述框架继续实现各自规则；框架提供接入能力不等于这些玩法完成。高差、坡道、多层、完整三维、复杂农务和定向能量继续后置。产品层次见[roadmap](roadmap.md)。
