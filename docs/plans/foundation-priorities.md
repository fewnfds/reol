## 开发取舍

2026-11-19 性能集中整改已收尾。后续接入功能时，可从玩家能看到的后果、状态归属和访问范围选做小规模验证。跨域设计和成本判断分别见[模拟设计](../engineering/simulation-methods.md)和[计算接入](../engineering/execution-batches.md)。新的产品事项按用户需要启动。

### 系统组合成本审查

值得跟踪的扩展成本在[问题清单](../status/issues.md#系统组合成本)。普通场优先看实际观察、规划、供料和等待年龄。密集场优先看一个战场同一时刻的活跃攻击、接触对和裁决量。区域分担适合以相距较远且较少交互的负载验证。对同一片拥挤战场，可先比较数据列、空间筛选和窄原生内核。两类结果会回答不同的容量问题。

### 调度与计算依赖审查

当前可组合的接缝包括按到期取件、相关事实唤醒、后台提案、局部即时交接和可替换显示快照。世界规则按其真实读写关系推进，线程组织和发布频率可据实测调整。[计算接入](../engineering/execution-batches.md) · [调度证据](../status/baseline.md#跨步调度与后台规划)

### 公开参考

传送带分组、确定性接触、Godot API 线程边界和历史进程对照见[大型模拟研究](../../design/research/large_simulation_optimization.md)。后续原生内核、区域和跨进程试验，可沿同规则输入、结果与采用成本比较。
