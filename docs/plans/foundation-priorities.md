## 当前：运行效率路线规划，实施待后续安排

已有可单独启动的功能导览，集中现有能力与少量预置样本。入口及体验内容归[功能试游](../engineering/tooling/usage.md#功能试游)；具体玩法范围仍由FEATURES各领域说明，不新建另一份功能总表。

### 运行效率路线（待实施）

目标是让已有CPU/GPU能力与后续内容扩展形成良性循环：减少无用工作，缩短实际关键路径，再在需要的领域接受有界近似。正常试玩关注连贯画面、指令响应及实际世界流速；不以CPU占用率、线程数或更快的时钟代替这些结果。世界事实、采样精度和调度延迟的唯一概念正文见[运行与精度](../engineering/simulation-pacing.md#世界事实与计算精度)。

**先补一个可归因的短窗口，再只选择成本最大且能被当前方案减少的一项。** 旧千人窗口约0.901×，有混合等待及装配累计口径，不能作为当前热点排名；数据限制归BASELINE。复用现有release诊断，按需要开原kernel/native、导航或渲染计时；给人物CPU等待、环境等待分项，环境统计作采样起止差值。检查准备、计算、采用、发布的计时是否重叠，不建立新监控平台。工具语法只查[实际性能](../engineering/tooling/usage.md#实际性能)。

下面是同一条路线中的候选，不是全部必须依次实现的任务。已有按需潮汐、到期/变脏索引、解析响应、来源采样合并、CPU批与GPU场继续复用；解除长期同未来要求本身没有性能收益。

| 路线与触发证据 | 改动入口 / 减少什么 | 短验证与停止条件 |
|---|---|---|
| **缩短安全输入交接**：忙碌请求含多个内部边界，玩家指令等待明显 | `GameClock`、`ReolSimulationHost`、`SimWorldRunner`与命令受理检查；评估收到实际输入后在下一个完整内部边界交还。改善响应，不减少模拟总量；保留尚未完成的时间债务 | 观察真实输入受理/执行等待及发布次数；仅runner提前break还不够，当前时钟仍保留原pending/frame目标，输入guard会继续拒绝。须一并定义合法命令窗口；只有一个昂贵内部边界或发布反而增多时停止 |
| **减少无消费者的全量发布**：身体捕获、采用或Node应用占主要成本 | `SimBodyPublication`、`ReolBodyPresentation`、`PawnViewLayout`及原视图消费者；区分轻量位置/占格数据与按需衣着/姿态/诊断，评估兴趣集合和变化复用。收益来自少算少分配，不是仅把相同数据搬到别的线程 | 比较发布行数、各段wall、显示年龄和实际吞吐；覆盖视野进出、选中/死亡/换世界。不得将不可见人物退出模拟，也不能直接删掉仍被读取的`cells/points/sample_cells`；维护兴趣集更贵就停止 |
| **合并同截止的环境来源变化**：重复准备/提交、相交场窗口或设备调用明显 | `SimWorldEnvironmentFields._settle_work`、`SimEnvironmentSourceChange`、`SimEnvironmentFieldCache`及现有CPU/GPU后端；评估同一时刻的来源差量/受影响格合并，减少重复场求值、响应编译和派发 | 比较实际触及格、重复范围、派发/传输、响应编译与整局耗时；检查同刻移动、移除、耗尽和房间响应。当前是单来源候选，需设计联合提交，不能声称只改循环或天然逐位等价；稀疏远源不应合成巨型包围矩形，合并更贵则保留原路径 |
| **算法、数据布局与执行粒度**：原owner循环、准备/采用或小任务开销主导 | 原行动/导航/空间查询、`SimActorAdvance`、`SimBatchExecution`及`EnvironmentFieldGPU.compute`；按热点复用局部索引、减少中间Dictionary/重复读取，适合时改连续列或扩大独立块。GPU当前每job创建/释放缓冲、分段派发后同步读回，可独立评估容量复用与提交粒度；CPU/GPU选择看端到端成本 | 同包同负载比较串行与候选配置，保留必要输入校验；计入缓冲容量、job布局/几何变化、取消和退出。当前GPU已有compact局部输入，并非每次上传全地图；不因“2个块”就认定任务小，也不因有GPU就强制使用。没有收益不全仓迁移ECS或更换语言 |
| **预算化NPC新决定**：新决定/非紧迫寻路产生尖峰或持续占比高 | `VillageSimulation._settle_actor_work`、原行动owner及`autonomous_livelihood`；只延后尚未发起的新决定，记录待办年龄，避免后排ID饥饿。可先减少无效尝试，再评估跨边界预算；这主要平滑尖峰并改变发起时机，不自动减少总量 | 比较命令等待、额外空闲、最长决策年龄与任务产出；在途运动、已到期效果和资源争用沿原规则。不能靠居民不干活宣称吞吐提升，成本低时不新增队列 |
| **慢环境候选跨步采用**：减少重复工作后仍有显著可重叠等待 | 拆开环境纯目标计算与采用时响应段；保留统一时间坐标，在合法采用时刻向前建立新段，按领域声明陈旧上限及局部交互规则。缩短等待关键路径，不保证总算量下降 | 覆盖连续移动、销毁/传送、几何变化、设备耗尽/过期、旧候选及存读/退出；量旧值年龄、作废重算、队列和追赶成本。当前proof绑定旧时刻/revision，不能直接改时间提交；失败/负收益就退回同步或重新设计 |
| **区域所有权与更大重构**：上述局部方案仍被跨域交接和串行依赖限制 | `SimWorldRunner`、`SimWorldSettlement`、原区域owner及宿主读取；先找真正可独立推进的数据和跨区事务，再决定分区/消息边界。允许大改，但不把“一个领域一线程”当设计 | 先用一个区域/过程验证是否实质重叠，计入快照、边界消息、迁移和旧UI适配成本；没有可独立工作或证据不足则不开展全世界重写 |

选择顺序是：**有证据的工作量削减与批量化 → 仍存在的串行热点/批粒度 → 确有需求的局部调度弹性 → 必要时更大重构**。操作等待是主要体验问题时可先做安全输入交接；若新决定或设备等待已是主要成本，也可直接从对应候选开始，不为“先优化单核”拖延多核或语义改造。当前测量不足以在发布、环境和行动之间排出确定名次，也不支持承诺倍数收益。

每项用同构建类型、同场景/命令及短窗口对照，装配/预热另计；CLI的residents是每地人数，报告总人数才是场景规模。通常先做一个定位窗和一个局部前后对照，疑点消除后停止扩测。关键结果看世界实际流速、帧P95/P99、命令等待、显示/数据年龄与实际产出；局部毫秒下降而端到端无益时不继续堆复杂度。正确性只补本次改动相关的短接缝检查，不恢复旧CI/长回归、8192人矩阵或跨机器长期同未来门槛。

**顾问取舍（2026-11-12）**：以当前代码附件作一次中性长问，采用了发布减量、环境联合变更、GPU缓冲复用、安全输入交接和有界调度的候选思路。没有采用其“约六秒都是串行残差”“混合等待基本属于环境”“32%捕获完全浪费”、固定收益/行数/阈值等断言；统计范围、嵌套和消费者不足以支持这些归因。分区单写者不等于复制事实，大重构仍是可选路线；是否划算由实际依赖和端到端成本决定。完整提问、原答与核查留在本机顾问目录，公共仓库只维护本页最终取舍。

成熟参考用于选择方法：[RimWorld 1.6官方公告](https://ludeon.com/blog/2025/06/announcing-odyssey-and-update-1-6/)确认批量多线程寻路与照明并行；[Factorio FFF421](https://www.factorio.com/blog/post/fff-421)支持休眠、共享登记及只读批并行；[FFF415](https://www.factorio.com/blog/post/fff-415)把任务预算与查询算法优化分别处理。它们不证明Reol的热点或收益。Godot对[小工作使用线程池](https://docs.godotengine.org/en/4.7/classes/class_workerthreadpool.html)和[GPU同步等待](https://docs.godotengine.org/en/4.7/tutorials/shaders/compute_shaders.html)均有成本说明，仍须测本项目。顾问对RimWorld具体镜头降频、例外及乘dt行为的概括缺少足够一手支持，不作为本项目规则。本轮游戏代码未改、未新增性能结论。

### 保留后续工作：输入、选择与指令

目标是形成一套可玩、可扩展的操作流程，让日常行走、交互和交锋共用命令入口。以下为待实施计划；当前可用键位仍只查[操作](../status/features/controls.md)，本轮没有提前启用右键移动、A/S/H。

默认采用鼠标指令控制当前化身。**观察目标**与**发令对象**分开：左键可以检查NPC、家具或草木，但不会因此接管它；移动命令默认交给当前化身。以后可指挥的同伴须先具有真实控制/合作权限，再扩展多选，不将全体居民变成RTS单位。

| 输入 | 计划行为 |
|---|---|
| 普通模式左键 | 只选择目标；空地取消选择。框选、Shift增减选择在确有可控小队时接入 |
| 普通模式右键地点 | 寻路前往；显示受理地点与到达/失败结果 |
| 右键单位 | 第一版走到可接近的位置；后续按已知关系和能力解析攻击、交互或跟随，不能将中立目标静默判作敌人 |
| A，再左键地点/敌人 | 地点为攻击移动：沿途搜索合法敌人、交战后继续原目的地；敌人为指定攻击。A不是范围伤害按钮 |
| S | 停止移动及当前可中断行动，清理尚未执行的后续命令；已发生消耗、已经飞出的效果沿原领域继续。停止后可按正常姿态应敌 |
| H | 驻守原位置，取消追击，只攻击自身射程内合法目标；不等同于格挡、无敌或自动追敌 |
| Esc / 预览时右键 | 先取消尚未提交的目标/技能预览，再按界面层次收起面板；不连带发出移动命令 |
| Q/W/E/R、D、F、I | 分别作为准备技能、身法、镜头跟随、物品入口的首选映射；具体技能仍需实际学会和装备 |
| Shift + 命令 | 后续加入有限队列；提交时反馈队列，执行时重新验证路径、目标与资源 |
| P、跟随/保护/撤退 | 基础流程稳定且有适用执行者后再补巡逻及小队命令，不先扩成全宗门调度器 |

键位重构与命令落地同时进行：现有WASD中的A/S和新命令冲突，默认鼠标模式会释放WASD；Shift闪身移到独立动作键，给队列修饰留位；F用于镜头，不兼任技能。雀身F落地/E啄食等身份动作迁入对应技能/交互槽，镜头键保持一致。数字编组与现有速度快捷键也有冲突，编组留待小队阶段统一处理，时间控制可继续使用HUD。若以后提供直接控制模式，应显式切换整套上下文，不让一次按键同时走路和发令。

按三个交付块推进：

1. **选择与移动闭环**：将Godot命名InputMap动作、UI/施工/普通地图上下文及命令路由收拢；复用现有输入缓冲、共同时间和路径执行器，完成左选、右移、停止、目标预览取消和明确的命令回执。UI点击、暂停下令、运行中下令、目标消失和不可达都能观察到结果。无需另建世界步进、人物位置或第二套寻路。
2. **战斗指令与姿态**：在原交锋/动作框架上实现指定攻击、攻击移动和驻守，定义遇敌、丢失视野、目标死亡、受阻、追击上限与恢复原移动的关系；目标搜索使用原空间候选/CPU批适配，动画只消费结果。日常工作被打断时交回原预约与资源所有者，S/H不直接清空原物。
3. **便利操作与扩展**：按实际体验加入Shift队列、快捷施法/普通施法选择、命令列表与少量重绑；有真实小队权限后才做框选、编组、跟随/保护/巡逻。先保证单一化身和生活交互能顺畅使用，再扩大操作范围。

参考的是成熟产品的操作语义，不声称拿到了其内部代码：[Warcraft III Unit Commands](https://classic.battle.net/war3/basics/unitcommands.shtml)区分Move、Attack、Stop和Hold；[StarCraft II Basic Unit Controls](https://news.blizzard.com/en-us/article/4552956/game-guide-basic-unit-controls)与[Special Control](https://news.blizzard.com/en-us/article/4552955/game-guide-special-control)提供选择、队列与编组参考。LoL的单一英雄/技能目标体验用于取舍，不照搬其经济或角色权限。

## 已交付基础：计算接入与项目记忆整顿

用户要求在已有CPU/GPU底座上提升代码质量与可接续性，不启动新一轮容量攻坚，也不建立每个新功能必须实现的万能接口。

| 交付 | 范围 |
|---|---|
| 清晰的接入选择 | 复用直接领域逻辑、事件/分频、CPU批与现有GPU场；适用范围和示例只维护在[计算接入](../engineering/execution-batches.md) |
| 减少扩展耦合 | 分开人物需求与运动读取；自定义需求保留原顺序计算，仍可利用无关的运动候选/边界批；诊断显示具体退化范围 |
| 收敛文档与证据 | 合并重复执行规格，删除过时的任务/候选关系；基线保留有效摘要，旧测量归档；参数以代码为准，命令只在usage解释 |
| 收尾 | 原规则和特殊回调的串并行状态对照、普通会话和短实机窗口已核对，证据归BASELINE；代码与文档一同提交main |

本轮不要求任何新领域先实现批执行、GPU后端或特定基类。发现真实公共责任时才提取机制，局部低频逻辑可以保持简单。

## 容量边界与暂不开展的工作

上一轮执行底座和数百人短窗已有改善，不把整个多核目标标为完成。后续效率实施沿本页上方路线选择，不自动恢复容量极限攻坚或重复增加worker；没有新证据时保留当前足够快的实现。

保留的未完成问题：下一边界选择/采用和有序空间通知成本、人物显示年龄、旧UI/画布的完整世界交接、压力驱动的真实动作/社会事件成本。旧千人以上负载仍过载，具体证据见BASELINE；未覆盖完整战斗、长期运行和目标整机。这些是已知边界，不是另一份必须逐项做完的队列。

本页之外的新功能范围由后续讨论决定。七个领域只查[职责表](../engineering/architecture/05-framework-domains.md)，长期游戏层次查[roadmap](roadmap.md)；研究和归档中的旧待办不自动恢复。
