# 模拟执行架构重构计划

这是唯一实施计划。目标结构见[执行规格](../specs/world-engine/execution.md)，七个领域的逻辑职责见[领域划分](../engineering/architecture/05-framework-domains.md)，实际授权、工作区和停点见[HANDOFF](../status/handoff.md)。本页定义问题、范围与出口，不把候选架构写成已完成能力。

## 重构目标与边界

在[目标PC](../engineering/architecture.md#全项目性能基线)承载300个持续行动人物、建筑、植物、环境和近远区，保持1×流速及稳定60FPS。计算不足时主动平滑降速，保留已受理时间和因果；600/1000人物仅用于诊断增长拐点。

从游戏需求选择计算粒度、数据、算法及执行设备。允许重写运行内核、存储、装配、领域算法、呈现接缝和对应测试，必要时从最小可玩世界重建。现有class、文件、schema、调用顺序和已投入工作都不是必须保留的架构边界。领域的唯一状态所有者是逻辑职责，允许替换其实现。

保留已确认的[世界规则](../../design/rules/README.md)：原物/数量/身体/认识各有真实归属，玩家与NPC共用因果，远区持续，行动可中断，观察不能泄露全知。内部表示、采样或规则改变分别说明，不能把旧实现的偶然行为当成已确认规则。

Godot继续承担引擎能力；GDScript负责规则组合及适配，复用原生搜索/几何/渲染/线程池和compute shader。原生批量内核可作为技术候选，连同构建、接口和维护成本评估；不因本计划自动引入C#、收费依赖或其他引擎。

## 核心问题登记

“已测/已核查”只覆盖对应旧Demo样本；“待诊断”是重构必须检查的风险，不是假定已找到全部瓶颈。测量入口见[CPU调查](../qa/20261110_runtime_cpu_root_cause.md)和[当前证据](../status/baseline.md)。

| ID | 要解决的问题 | 证据与目标 |
|---|---|---|
| P01 | 主要模拟集中在一个同步执行链 | 已测旧样本最热线程约占进程CPU的99.8%；新结构从数据/任务层提供真实CPU并行，记录主线程关键路径 |
| P02 | 局部事件放大成全局阶段/对象工作 | 已核查局部边界仍遍历完整计划；调度成本应跟必要依赖/到期工作增长 |
| P03 | 普通查询触发全体身体补算 | 已核查布局/玩家查询和部分领域接缝；明确纯查询、局部消费屏障及完整捕获 |
| P04 | 动态字典、间接访问、分配和整图复制 | 成本构成待拆分；热/冷分离、紧凑批数据，不让并行准备和发布重做业务计算 |
| P05 | 几何/地形及邻边查询大量重复 | 已测同次搜索84.81%通行查询重复；重选空间数据/查询接口，不只给原回调套缓存 |
| P06 | 寻路、局部避让、实际移动纠缠 | 多目标/拥挤增长待诊断；分层路线、局部候选和活动执行分别组织 |
| P07 | AI反复找工作、检查全部目标或重新思考 | 待量各决策/执行成本；通过本人认识、需求阈值、目标变化和候选索引选工作 |
| P08 | 静态对象与能力无关对象承担持续更新 | 各域参与范围待量；按能力/过程组织数据，墙/植物/人物不承担相同运行成本 |
| P09 | GPU后端与普通世界脱节 | 已核查旧基础目标GPU服务未装配Main；新后端必须计算当前规则并实际采用结果 |
| P10 | 通知、失效、锁、等待和任务过细造成额外开销 | 待量传播范围/准备/排队/发布；批任务按真实依赖组织，避免全局失效和每属性一个任务 |
| P11 | 模拟模型的复杂度超过可观察玩法需求 | 逐域评估背景/房间/局部场和连续过程的合适粒度；任何近似先定义误差及阈值行为 |
| P12 | 世界提交、画面和UI刷新相互拖累 | 已测呈现CPU占用；视图读已提交投影，按可见/改变范围工作，输入延迟单独量 |
| P13 | 初始化、全量校验、存读、快照与长期历史成本 | 待量装配/捕获/恢复及历史增长；冷启动、稳态、停开分别核算，不删必要事实凑指标 |
| P14 | 脚本调用/解释执行可能成为吞吐上限 | 待量调用边界；改变数据批次并复用原生能力，必要时提出小范围GDExtension方案 |
| P15 | 诊断驱动改变被测成本，固定公共终点掩盖增长 | 已发现压测同步全体；采用相同命令流、不同分布/目标及完整端到端对照 |
| P16 | 文档、旧测试和完成声明把实现锁死 | 已核查旧队列/版本说明冲突；按当前合同选择测试，独立算法/后端通过不能代替普通世界交付 |

## 目标执行方式

静态事实按变化更新；连续量按稳定输入段积分；离散后果按精确截止点；AI按决定条件唤醒；渲染按显示帧工作。共同时间统一因果，执行频率、数据表示及设备各按任务选择。

```text
命令 / 到期事件 / 局部改变
            ↓
按领域与空间选择工作、准备紧凑输入
            ↓
CPU批任务 / GPU数值批计算 / 必要串行仲裁
            ↓
原领域批量发布 → 使真实依赖失效 → 必要后继工作
            ↓
完整世界时刻、可见投影及安全保存点
```

任务只等待实际依赖；共享资源和反向依赖显式处理。worker完成先后不决定游戏先后，主线程不重算其已完成的数学工作。成本主要跟活动过程、到期后果、变更覆盖、局部实际交互和可见内容增长；全局变化、全档读写及真实密集交互单列，不承诺所有负载都是O(N)。

## 必须覆盖的情况

| ID | 情况 | 验收要求 |
|---|---|---|
| S01 | 攻击与服药相邻/同刻生效 | 逻辑时刻及规则顺序决定结果；线程数、GPU/CPU速度和完成顺序不改生死 |
| S02 | 多人抢同一资源或操作位 | 原库存/预约只提交合法结果；失败、中断和重试不复制、吞物或重复付费 |
| S03 | 单位跨格、改变暴露或携带来源 | 结清旧输入段后采用新条件；占地/来源/阈值不漏报，无关身体不被迫补算 |
| S04 | 墙门开闭、拆改、房间分合 | 局部拓扑/传播/路线依赖更新；执行前复核，旧缓存/worker结果不穿墙 |
| S05 | 目标销毁、取消、读档和世界替换 | 旧任务失效并回收；不能迟到提交、复活对象或改到新世界 |
| S06 | 远区、快进、不同预算分片 | 同一因果和持续需求；不冻结远区，不丢积压，不借近似传送解围 |
| S07 | 串行、多worker及GPU不同完成顺序 | 离散未来一致，RNG不被线程争抢；连续数值误差及阈值按已定合同验证 |
| S08 | GPU不可用、错误、超预算或结果过期 | 同规则CPU后端，明确回退；未完成不当零，过期不冒充最新事实 |
| S09 | 进行中保存、完全停开、坏候选加载 | 保存原过程/时刻及必要事实；恢复同未来，坏候选不部分改活世界 |
| S10 | 隐藏/远区对象、NPC认识与开发诊断 | 规则持续但视图可休眠；纯查询不写认识，全知索引不能成为NPC已知事实 |
| S11 | 大量静物、多目标、拥挤、批量变化 | 分别测增长曲线，定位真交互与无关放大；不能只测开局一次出发/四个终点 |
| S12 | 长局、频繁生成/销毁、反复存读 | 索引/任务/缓冲有生命周期；保留幂等和认识所需事实，检测内存及历史增长 |

这些是框架联合验收情况，不拆成十二份独立开发计划。最小反例归主要owner，完整Main只保护实际整合出口。

## 四个交付包及依赖

| 包 | 框架能力与范围 | 出口 |
|---|---|---|
| A：共同运行与数据底座 | 重建工作选择、局部时间依赖、热数据批接口、CPU worker及批量发布；同步验证GPU数据/传输接缝，不先建设空平台 | 一条普通可玩因果链真实使用多核，能查任务/主线程时间线；覆盖S01/02/05/07/09，GPU真实路径不再是设计末尾事项 |
| B：空间、行动与自主执行，依赖A | 分块空间、静态/动态拓扑、分层导航、活动动作、本人所知与工作选择进入同一批接口 | 多目标/不同身体/拥挤/墙门和争用成立；覆盖S02/03/04/06/10/11，给出工作量和规模曲线 |
| C：环境与自然过程，依赖A及空间输入 | 按原规则组合背景、房间、来源和受体；复用GPU设备/缓冲及局部上传/回读。与B按接口分别推进 | 普通Main实际采用当前环境GPU结果，记录端到端收益/回退；覆盖S03/04/06/07/08/12 |
| D：呈现、存读与全域整合，依赖A–C | 可见投影、输入/镜头/UI、内容装配、领域存读、诊断和长期成本贯通普通Demo | 300人联合1×/60FPS、全部S01–S12、完全停开及完整回归；移除被替换的旧运行分支 |

每包交付普通入口和可操作结果；算法、缓存、独立GPU或任务类完成只算内部进展。已有补丁按目标结构取舍，允许直接被新实现取代。共同身份/能力不要求所有对象共享巨型类或一对象一Node。

## 测量与采用标准

- 固定内容、seed、逻辑命令时刻和分布，分别改变30/100/300人物、活动比例、静物密度、可见比例和变化范围；600/1000诊断拐点。分散/拥挤、多目标及移动来源都要覆盖。
- 发布版记录逻辑吞吐、实际流速、输入响应延迟、帧P95/P99、主线程关键路径、worker/GPU、准备/排队/等待/复制/分配/发布、RAM/显存和存读。冷启动/预热/稳态分列，重复同条件对照，目标PC和开发机分别声明。
- 60FPS帧预算约16.67ms，并行工作按关键路径分析。CPU/GPU使用率、kernel提速和PASS数量都不是性能出口；没有端到端收益就重新选择粒度、表示、算法或后端。
- 正确性来自已确认规则、最小反例和因果合同；旧实现只作对照。过时的结构测试/迁移链可按保护对象退役，不能删当前失败断言凑绿，也不永久复刻已知错误。
- 格式变化只维护一个当前模型及有限明确支持的输入，原fixture只读。替换实现后的对照模式仅用于验收，不长期维护新旧两套世界。
- 游戏包先定向，最终完整check或对应SHA CI一次；画面/性能/完全停开另取真实证据，按[测试与CI流程](../engineering/workflow/testing.md)执行。

完整战斗、超凡玩法和正式内容在基础框架上继续建设，见[产品层次](roadmap.md)。本计划不恢复旧六阶段、旧A–D迁入队列或按历史样本编号施工。
