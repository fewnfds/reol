# 当前实施计划

当前工作和停点见[HANDOFF](../status/handoff.md)；本页只维护阶段范围与后续取舍。七个领域见[职责表](../engineering/architecture/05-framework-domains.md)，实际能力和数值分别见[FEATURES](../status/features.md)与[BASELINE](../status/baseline.md)。

## 已完成阶段：分频结算与可穿行门

在整顿后的`70ea29f`上保留共同时间与现有CPU/GPU执行路径，完成按过程响应要求分频、错峰与合并工作。

已交付移动来源采样合并、植物慢采样错峰、有界离散输入缓冲，以及复用原存读管线的采样恢复。用户进一步确定门为可自由穿行墙体，已删除开关状态/操作，穿门不重建房间或场；锁门不在本轮范围。频率、直接事件和慢数据语义统一见[运行合同](../engineering/simulation-pacing.md#领域频率)。

研究依据与当日外部评审快照统一从[大型模拟研究](../../design/research/large_simulation_optimization.md#分频错峰与有界近似2026-11-11)进入；最终短实验、误差范围、未测负载及格式变更见[BASELINE](../status/baseline.md)。本轮减少了计算量，未宣称混合场景稳定60FPS。

未采用墙钟动态降频、驻留过滤和另建跨步场数据库。直接动作/库存后果仍按事件处理，普通过载政策保留后备；跨步场发布和更广泛异步重写只有新证据支持才扩大范围。本轮交付后停止扩展实验，先收集试玩反馈。

## 已完成：代码与项目记忆整顿

目的：减少重构遗留、重复路径和接手成本，为后续可玩Demo开发准备清楚的代码基础。

- 删除已退役的算法、验收适配器、迁移链和旧测试旁路；有效CPU/GPU路径保留。
- 将新局装配、实时推进、候选恢复分开；跨领域从实际owner定位，避免反向依赖呈现层。
- 当前事实留在现行文档；旧实验归档，去掉重复约束与无效测试要求。
- 只做相关短检查和真实运行核对，审阅后整合到main。

这轮不扩展玩法、不恢复长回归，也不以减少行数替代正确性。

## 性能出口与暂停范围

目标仍是[目标PC](../engineering/constraints.md#产品与技术范围)上300个持续行动人物与建筑、植物、环境共同运行，保持1×流速与稳定60FPS。允许重构数据和算法；当前已采用有界来源采样，业务采用时刻仍由逻辑时间决定。范围不等于所有领域可以漏算。

当前运行已有大幅改善，以下超出本轮的方向保留为候选：

| 领域 | 下次讨论要决定的问题 |
|---|---|
| 环境与建筑 | 真实建造/拆毁的原子工作及密集强源；普通穿门已不产生拓扑重建 |
| 共同运行与行动 | 若真实热点支持，再决定是否统一运动数据；不预设全面重写调度器 |
| 呈现与可玩整合 | 当前尾帧仍含公共发布、视野和布局成本，优先结合真实试玩定位 |
| 整机范围 | 在相同负载和构建下核对目标硬件及长局，不能由单个kernel提速推断 |

已尝试路线及证据见[研究](../../design/research/large_simulation_optimization.md)与[历史实验](../archive/qa/20261111_performance_experiments.md)。候选执行结构见[specs](../specs/world-engine/execution.md)，不是既定实现或另一份任务队列。完整战斗、超凡玩法与内容扩展见[产品层次](roadmap.md)，下一开发阶段待本轮交付后讨论。
