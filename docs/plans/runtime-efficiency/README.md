# 顶层运行效率改进方案

性质：2026-11-07用户要求的架构改进候选。不是新玩法设计，不恢复已结束Goal；实际授权/停点只见[HANDOFF](../../status/handoff.md)，本次选定的实施边界见[本包规格](implementation.md)。审计起点为`eff27a7dcf77031a4084258cc688bbb3616b64e4`，既有短时分项证据见[来源成本复核](../../qa/20261107_source_change_review.md)。

本方案替代“只修一件物品或单条来源函数”的窄范围建议：统一检查定义编译、能力参与、到期调度、空间候选、缓存失效和呈现路径，再逐包实施；不把整款游戏重写成新引擎。

## 要达到的执行方式

**系统处理拥有相关能力、且因变化/到期/当前活动需要处理的对象。** 不对每个实体枚举所有可能存在的属性，也不因游戏时间前进就让所有系统重查一遍所有实体。

这里的“能力”指物理/行为参与条件，如发光、发热、可移动、会受伤、可穿戴；不同于修炼技能熟练度，也不等于玩家已认识的属性。身体、植物、器物仍有各自原状态，不强制每个对象继承一个塞满可选字段的巨型类。

| 对象/状态 | 应参与的处理 | 不应产生的工作 |
|---|---|---|
| 普通石板：有土/金影响，没有冷热 | 落地/移除/位置或强度改变时更新相关五行格/通道 | 每帧扫描全部属性，或连带重做温度 |
| 火石：具有有限启停发热能力 | 启用时进入热源集合；开关/耗尽/变位产生环境变更 | 已关闭后每边界遍历全部器物找它 |
| 静止树木：持续影响环境 | 保持已注册来源；生长/损毁确实改变来源时失效 | 每帧重新注册整棵树及其不变影响 |
| 未受伤人物 | 正常需求/移动/自主时序 | 扫描全部历史伤口来证明他没伤 |
| 没有动作的鸟 | 按原需求变化和到期条件推进 | 因无动作就冻结饥饿，或每毫秒跑所有技能 |
| 窗口关闭/人物不可见 | 权威世界仍推进；视图休眠 | 反复重建面板历史、不可见图标和布局 |

“有能力”不等于“每帧活跃”，“静止”也不等于“没有时间依赖”。来源目标未变时环境仍建立/消散；伤口、潮湿、饥饿要按正确时刻推进。天气、潮汐、气候是独立依赖，不能只监听物品移动。

## 三个筛选层，两个执行边界

1. **定义层：** 装配内容时校验/编译能力清单、效果通道和依赖，静态定义共享，不在热循环反复猜字段、补默认或复制模板。
2. **成员层：** 各领域原所有者维护“哪些ID有此能力/状态”的派生索引，例如发光物、穿衣槽位、未愈伤口；不用世界全体对象作候选。
3. **工作层：** 从成员中只处理当前活动、已变脏或已到期的对象；失效范围落到实体、空间块/格、通道及观察者。

输入/外来存档做完整验证；内部受控阶段只核本次依赖和必要版本。执行按共同时间的既有因果阶段，先结旧区间，再提交真实变化，再使依赖失效。原物、数量、身体和知识不能被缓存复制成另一份真值。

通常的运行成本应跟**到期对象＋活跃过程＋变更覆盖＋局部候选＋可见投影**增长，而不是跟“全世界实体数×所有可选系统数×刷新次数”增长。这个式子是设计目标；全局天气变化、全档读写等确实覆盖广域的工作仍可能随世界规模增长，须声明预算。

## 文档路线与建议顺序

- [审计范围与证据](audit.md)：已测热点、静态增长风险、已有合理做法；不把全部for循环都称为瓶颈。
- [统一执行合同](contracts.md)：能力/成员/活跃/依赖、时间、索引及存读边界。
- [实施与验收](rollout.md)：四个可讨论的小包、停止点、必要验证与禁止轮询。

上述A→B→C→D是制定时建议依赖。当前通用核心及环境/健康的实际接入查[工程接口](../../engineering/sparse-execution.md)和[技术总表](../../status/technical-status.md)；其余范围并未自动实施，不重复执行A或把整个B–D当成本轮承诺。后续仍以多类真实内容验证，不增加物品名字判断来达成指标。

## 成熟项目参考与取舍

[Factorio FFF324](https://www.factorio.com/blog/post/fff-324)强调用依赖变化通知代替重复检查、集中热管更新；[FFF421](https://www.factorio.com/blog/post/fff-421)展示休眠/唤醒、重叠覆盖统一登记和多线程失败案例；[CDDA透明度缓存](https://github.com/CleverRaven/Cataclysm-DDA/blob/06be12f9884d82d387cb6b38dc549eca71c3835a/src/lightmap.cpp#L188-L291)使用脏子地图与依赖失效；[Mindustry路径场](https://github.com/Anuken/Mindustry/blob/3193fd81681476f3fa08bbcf3d7efb89e67229bd/core/src/mindustry/ai/Pathfinder.java#L188-L213)合并刷新并预算处理。分别借鉴稀疏参与/失效/批处理，不照搬其场公式、更新延迟或实体架构。

不新增全量ECS、万能事件总线、第二世界状态、数据库事务平台或每属性定时器；不先把所有领域套进一组空接口。沿已有原所有者/共同时间接缝改，至少两个真实使用点出现相同需求时才抽取小工具。GPU/线程由减少无效工作后的端到端结果决定。
