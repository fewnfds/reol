# 顶层稀疏执行框架：本包规格

## 交付边界

用户2026-11-07授权实施，进一步明确现有冷热、五行、伤口是规则接入样例，目标是可继续填入新能力的通用顶层执行结构。本包建立共同的参与索引与工作选择合同，接入普通环境和健康两个不同领域；不扩展任何演示玩法，不要求全部旧域一次迁完。实际进度与Goal只见[接续](../../status/handoff.md)。

## 执行链与所有者

```text
定义/原状态 → 原领域登记能力成员 → 当前参与 / 到期 / 依赖变脏
                                      ↓
共同时间原阶段 → 选取有工作候选 → 原领域验证/计算/提交
                                      ↓
                         更新成员、截止与局部依赖
```

共同工具放`scripts/sim/execution/`，没有五行、温度、伤口、物品名等内建含义。每个领域持有自己的索引；键是领域声明的工作种类与主体ID。核心仅保存参与元数据，不保存身体/数量/位置/伤势，不推进时钟，不自动调用领域，不写入存档。定义仍由内容装配校验；执行器不能从玩家认知反推真实能力。

## 实施步骤

1. **通用索引。** 登记/移除成员、当前参与集合、合并变脏原因和修订、可更新到期堆；查询稳定有序且不消费工作，成功后显式确认/重排。失败、预算耗尽、移除重建以及处理期间再次失效均不丢工作。休眠不等于冻结连续需求。
2. **效果执行接缝。** 场缓存输出本次真实改变的空间/通道掩码；缓存干净时新增来源影响比较最大值，旧最大减弱时局部求替代。缺失/脏数据有正确回退。响应只消费相关变化，数值未变不重开响应；现有五行通道在同格共享响应段，保留该耦合而不伪称逐通道独立。
3. **普通世界环境接入。** 有限设备按实际能力/启用状态登记；环境块按响应到期进入同一个通用索引，来源变更只登记本次触及块。背景、天气、潮汐和旧残留仍有自己的真实截止。复用原共同时间阶段，不建每对象Timer或另一世界调度器。
4. **第二领域接入。** 健康域从原伤口/诊疗记录构建未愈与活动集合，接齐创建、治疗完成、取消、自然恢复和读档重建；实时查询不再扫描全部历史。原连接检查、治疗/恢复先后和伤源解释保持。
5. **联合出口。** 通过真实普通装配验证两域都使用同一核心；新能力接入只需声明参与条件、生命周期和到期/失效规则，不在核心增加具体属性分支。记录已迁与未迁路径，后者不得冒充框架全部接通。

## 验收与停止点

- 核心独立验证同刻稳定顺序、预算保留、重复失效、旧确认拒绝、注销重入和清空恢复；增加无关成员不能增加到期/变脏查询的全量扫描。
- 接入验证多种材料/profile、源新增/删除/移动/并列与次强接替、无效通道、背景/残留连续性，以及不同主体的受伤/恢复/诊疗。只用合法原接口生成事实；候选失败保留活世界。
- 比较相同普通调用与环境访问格/通道数，报告测量配置；既有约0.22秒样本是起点，不预先承诺倍数。稀疏截止查询和历史增长分别用有界负载验证，不为每个属性建立专用基准平台。
- 不改变世界规则或要求存档重放；派生索引从原状态重建。读档失败不改活世界，进行中、整段/分段和继续后的未来保持明确精度。
- 主代理统一一次定向验证、必要集成完整check与一次主要审查。长验证由工具等待原进程终态，不扫描testlog、不数PASS、不定时查CI；新错误/修改才补受影响验证。
- 框架、两类普通接入、必要证据和新能力接入说明完成后停止。本包不是全款游戏、所有旧领域或全部A–D计划迁入的完成声明。
