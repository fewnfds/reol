# 分包实施与验收（候选）

本页不是执行授权。当前只交付[统一方案](README.md)，未改游戏代码、未新增Goal；后续一次选一个包实施、验证、报告。原世界规则与16GB整机/单RTX3060目标沿[工程基线](../../engineering/architecture.md)。

## A：能力参与与环境选择性执行（建议首先实施）

目的：让顶层“能力成员→实际参与→变更/到期工作”先在已有最重路径落地，同时改来源事件与时间刷新，覆盖所有声明profile而非石板特例。

1. 在已有定义加载阶段编译效果通道/非零掩码和必要依赖，保留内容错误与缺profile语义；不新增第二份物品/身体表。固定设备启用状态来自原器物。
2. 沿原生成/移除/取放/材料堆拆/设备启停接缝维护实际来源成员与本次改变信息；动态启用、耗尽与定义能力分开。复用既有零源/相同源no-op。
3. 来源缓存保持chunk存储，实际变化使用格/通道掩码。新增max增量，删除/变位旧赢家局部重求，脏块明确回退。冷热不变就不准备温度；五行目标未变就不重开响应。
4. 普通到期刷新从现有温度/五行earliest结构收集真正到期块/通道，不再任何小边界都重刷全部曾影响格。保持气候/天气/潮汐、旧残留、同刻顺序与数值精度合同。
5. 删重复投影和全量affected_chunks合入；必要局部候选仍在最后一次提交。此包先保持同步接口，优先降低总CPU，不同时重写分帧/异步协议。

验收不是“某个石头快了”：现有普通Main中的不同元素材料、纯冷热/零冷热、有限设备和已存在多来源组合共享同一路由；新增/删除强源/并列最大/次强接替/跨块/同类堆数量不放大，目标未变时不误动其他通道。共同时间分片/取消与当前存读后未来保持规定精度，不强求无意义的派生缓存字节相同，也不删真实事实断言。

复用现有两个普通调用比较总耗时、基础场耗时、实际访问格/通道与响应重开量，再加少量同结构不同profile/块内与块边界输入。短测一次结束后读结果，不建道具专用测试平台。0.22秒应显著下降；以60FPS总帧16.7ms为可感知阻塞参考，环境常态份额暂按2–4ms目标评估，不许把该模块独占整帧。数值未达即说明残余热点，不为追承诺倍数无限扩任务。

## B：人物与领域的活跃/到期调度

依赖A确立的参与/失效规则，但不强制共用相同数据结构。先改已确认全员×可选域的热点，采用健康与穿衣两个不同域验证通用方式，随后只在有收益时迁移其他域。

1. 在原owner建立actor→未愈伤口、active诊疗、actor→衣槽、湿衣等索引；已完成记录留存但退出实时求界。启动/结束/取消/穿脱/愈合和restore同样更新/重建。
2. 村落动作只投影/结算活跃者，自主判断只评估到期/被依赖变化唤醒者。原优先级与多人机会竞争不变。
3. 需求衰减先剖析，再按固定点carry/环境输入段/阈值决定是否惰性批算；无法证明等价先保留原路径，不把“无当前动作”当休眠条件。
4. 复用原region边界缓存并去掉重复求界。只有域数/频率确实占优时才考虑索引最早到期，不先新增全局堆、每属性timer和万能调度器。

验收：增加不相关定义或无此能力实体，不让健康/穿衣候选访问按其总数增长；伤口和湿衣从0→有→消失、技能/持有者/控制变化可正确唤醒，旧记录增加不会扩大活跃循环；近远区、整段/分段、同刻中断与保存继续保留原结果。测试角色按真实装配和合法变化生成，不直接注入绕索引状态。

## C：局部查询与可见投影

1. 复用原空间桶，补容器/持有者锚点候选与原属owner映射；查询先局部空间再能力/感知过滤。固定结构点集合用于寻路/墙邻接，不每查询节点全扫地区。
2. 静态器物候选/布局按局部revision刷新，与移动插值分离；跨原属区同格者仍共享正确布局。
3. 人物投影只处理可见/变化者，光照只在真实依赖变化或亮度截止时重建；保持雾/遮挡/动态光和无效候选失败语义。
4. 面板关闭停止历史重建；打开后先判本人知识/领域修订，再构建列表。计时文本与历史列表分离，不靠JSON签名掩盖前置全扫。

验收：远处增加静态物/容器，当前相同视野的候选/绘图成本不线性增长；可见携物连续跟随，隐藏实体/属性不泄露；移动锚点/多格扫掠/门墙变更/读档替换均失效。光的当前源数/格数预算如需调整单独明示，不能为性能默默少照明。涉及可见改动才启动一次普通画面验证。

## D：历史、复制与内部边界收口

只针对A–C量测剩余的真实成本，不再普遍改写全部域。

- 课程/交易/伤病历史按主体和相关类型派生查询索引，当前活动与历史证据分离。
- 静态定义用不可变共享描述；内部批处理复用已检查投影/数组，在没有外部别名和重入时按所有权交接，避免反复深拷贝。
- 原物与环境一致发布、版本失效、失败保留活世界仍保留；0.015ms显式检查不是优化主目标。存读完整校验不搬进每次动作，动作也不重演全部历史。
- 减少总工作后，若集中处理仍超帧预算，再单列既有step分帧、同刻dirty去重/后台纯计算或GPU候选。没有测出独立大批计算收益前不引并行复杂度。

## 跨包测量口径和停止规则

量测使用同一普通装配和代码版本，记录总调用、最大主线程连续耗时、处理延迟、访问对象/格/通道数、活跃比例、候选命中/空查/缓存复用、稳态分配和内存。调试计数按一次运行汇总，不在逐对象/逐帧热路径打印日志。

先复用原证据，必要时同负载前后短测；单次结果只叫样本，不报虚假的p99。静态复杂度风险先测，不自动安排512²满图或多年大历史压力测试。最终需要联合规模时按现有PC预算安排，不给每个子系统另设几百MB硬限制。

期望工作量近似随实际参与/变化增长；全局气候/全档读写等不可避免广域操作单列。不能为了过指标去掉实际效果、改变max/半径、冻结远区、丢时间或增加未授权运行时AI。每包预算内无明显收益就保留证据、回退无效改动并讨论，不演化成无期限“优化整款引擎”。

## 验证与等待：不让模型当轮询器

- 本次是文档与静态审计：只做结构/链接/差异检查，不启动Godot或完整测试。
- 实施时先跑受影响的必要定向验证；每代码包一次主要审查，集成出口一次最终完整check或准确SHA CI，不逐模块/逐文件反复全量运行。失败或新修改才补对应验证。
- 本机测试交工具层持有进程/会话handle和超时，结束后一次取得退出码/结果摘要；仅失败、超时、异常停滞或用户明确要求才读中间日志。**禁止定时读testlog、数PASS、报百分比、发无变化播报或派等待代理。** 等待原handle不等于扫描日志，不能因观察超时重启任务。
- CI只在真实提交检查点查一次；未终态留待下一真实提交，终态缓存复用，不按五分钟日程查询、不在push后开等待循环。
- 不添加常驻回调服务、第二Codex进程或自动修复链；没有宿主支持时不声称后台能唤醒已结束聊天。长期等待无可并行工作时保存准确handle/状态，不拿不停发工具调用充当开发。

停止出口：每包报告通用能力的变化、普通入口、量测收益及尚未迁入范围；本轮方案写完即停止，不自动实施A–D。统一框架方向是长期约束，包内只接真实已有系统，不能以文档/测试数量宣称整个游戏高效。
