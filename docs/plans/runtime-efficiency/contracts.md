# 统一执行合同（候选）

本页描述拟采用的框架约束，不表示当前代码已满足。范围/证据/分包见[目录](README.md)。[原状态所有权](../../engineering/architecture/02-owners.md)、[共同时间](../../engineering/architecture/03-time-space-presentation.md)与[玩家有限认识](../../../design/rules/README.md)保持。

## 1. 定义只编译一次，参与信息按需登记

定义仍放data/definitions，开局放data/scenarios。加载完整内容包时校验定义并得到不可变运行描述：声明的能力、非零效果通道、常量参数、启用条件、需要监听的依赖。实例引用共享描述；实例独有伤势/湿润/余量等仍放原所有者。不因增加一种可选能力而给每个实例新增几十个false或0字段。

- 字符串能力名保留为内容接口，热循环可使用编译后的小数组/掩码/索引；不规定所有玩法都塞进一个全局位集。
- 从定义缺省迁入的历史类型在装配边界处理。缺字段/未知来源不是“没有影响”，必须按当前定义合同明确拒绝或报告未配置；不能用优化静默吞掉坏内容。
- 来源可有多个效果；五行有非零通道不代表冷热也非零，火属性亲和不等于发热。定义能力只说明可能性，启停/穿戴/损伤/载体遮掩等实际状态决定是否有效。未来携物规则未实现前不伪造它。
- 不把开发全知能力清单投影成角色已知属性；能力索引用于执行，玩家显示仍经过原观察/知识规则。

## 2. 原所有者维护三个可重建集合

每域只为有实际收益的查询建立ID/引用索引，不复制原属性数值。例如器物域管理发光物/热设备成员，衣物域管理actor→slot，健康域管理actor→未愈伤口；环境域管理有效来源与受影响格。

| 集合 | 含义 | 示例 |
|---|---|---|
| 能力/状态成员 | 拥有相关可选能力或当前状态 | 可发光器物、可被穿戴衣物、未愈伤口 |
| 当前参与者 | 此刻需要该域处理的子集 | 已启用且未耗尽设备、湿衣、进行中诊疗 |
| 待工作集合 | 已到期、依赖改变或请求触发的参与者 | 到期引息、刚淋雨衣物、跨格移动的发光体 |

这三个集合可按需求合并存储，不要求每域机械创建三个类。永久静态来源注册后只保留空间影响，不每帧执行。需要连续需求变化的对象保留时间锚点/阈值时刻，不能因不在动作集就停算。

成员变动必须从原生命周期接缝更新：生成/移除、学习/遗忘、穿脱/持有者改变、启停/耗尽、受伤/愈合、移动/跨区和当前控制改变。开局装配、载入独立候选通过后使用同一构建规则重建；世界替换时整组旧索引失效。原属区映射与物理所在区不同，身体移动不擅自迁移保存所有权。

索引不成为新的权威锁。动作占用仍由原域确认，索引只缩小候选集；取消、冲突阶段或控制变化必须让候选失效。未接齐更新入口前不发布索引为唯一查询方式；有明确预算的正确回退须说明，不偷偷无限全扫。

## 3. 调度以活跃、到期与依赖变化为入口

复用共同整数毫秒与RegionalSimulation已有阶段；不再加世界时钟。边界按稳定次序处理，不能为了少调用改变原同毫秒的完成/受击/中断/观察优先序。

- 领域无参与者且无持续背景时返回“无到期工作”，直到相关变更唤醒；有背景的域仍有自身边界。
- 先缓存各域/地区最早边界摘要，只在该域实际状态变动后失效。当前二十余域常数遍历本身不是重写调度器的理由；先消除域内部全员扫描和重复求界。
- 原村落动作按活跃ID投影/结算，自主决策只取到期或依赖改变的人；可选健康/衣物/修炼建议只向相关候选评估。仍保留原需求/优先序、失败回退和机会竞争，不能把一次短路命中缓存成永久意图。
- 饥饿/精力/伤病/潮湿的连续变化可按时间锚点批算，但需先确定会改变决策的阈值边界、固定点carry和环境输入段。受控执行器在行为/后果所需时刻结算；纯查询只读投影，不借查询暗中改活世界。无法保证等价的域先保持原步进，不强行休眠。
- 户外天气/潮汐到期只使相应地区/块/通道失效。不是任一格到期就刷新全部曾影响区块；也不是只监听源变动而漏掉背景变化。

预算不足保留请求和积压，不能向后丢时间或假称未来已完成。采用现有step进行分帧时，最终真实提交仍只发生一次；显式“处理中”的呈现不能先改物品/温度真值。先减少总工作，确需调度变化时另包实施。

## 4. 失效范围必须携带足够信息

复用原signal/明确调用接缝；变更信息仅需原引用、已提交时刻、相关类别、原/新空间范围和所属revision。不是每次变更都生成持久审计事件，不把简单通知升级成事件溯源平台。

- 对象层：只失效该对象及实际依赖它的观察/行动。
- 空间层：原位置与新位置的有效覆盖并集；chunk用于存储，格/局部矩形/掩码用于计算，二者不强制一致。
- 通道层：只处理前后可能变化的值；新增源只对非零通道比较max，删除/减弱旧赢家时在该处重新求最大值，处理并列与次强接替。脏/缺缓存保留完整计算路径。
- 响应层：基础目标没变不重开响应段；确实改变时先求旧段在事件时刻的实际值，再接新目标。原量化/锚点可能影响字节级比较，先给出明确数值合同，不能删断言让新旧未来漂移。
- 观察层：以本人知识/视野/消息修订为依赖，不以全知世界变动直接让隐藏消息出现在UI。

同一因果阶段、同一游戏时刻的独立变更可以合并脏范围，避免掉落多件物品就重刷同一块多次；有中间观察/消费/触发/优先序差异的操作不能随意合并，不跨不同物理时刻抹掉驻留与旧残留。

## 5. 空间查询与呈现共享依赖，不共享真值副本

候选应来自所在空间的索引，再按能力、距离、遮挡/扫掠、权限过滤。索引只存ID与必要空间元数据，数值从原owner读取；不再“遍历全世界找有这个属性的对象”。

- 原地面占地桶、结构点索引和固有光源ID应复用。固定容器与移动持有者按各自锚点登记；跨格/容器迁移更新派生空间桶。多格单位查询覆盖与扫掠，不压成中心一点。
- 寻路查询读取本格已组合阻行事实，避免每扩一个节点遍历全部地区墙格；阻行、遮视、屋顶遮雨是不同依赖，不能为共享而混为一个blocked。
- 物品图标的静态布局/可见候选在实体、视野或容器锚点变化时重建；只有移动持有物的插值继续每渲染帧计算。不可见身体不重建视图，真实世界仍运转。
- 光照视图按实际光源/遮挡/视野/动态强度失效；时间确实改变亮度/太阳/耗尽时安排相应边界，不能一概删除time信号。保留当前128源/441格等上限或单独证明新局部上限合同，不以全局门禁失败当成无光。
- 面板关闭停止构建历史；打开后按相关revision重建条目，倒计时文字与长列表分开。不要先构建全部行并JSON.stringify再决定“没变”。定义展示需要列出未知技能时可以遍历UI目录；那不等于为全世界执行所有技能。

所有缓存须带世界装配代次和真正相关的revision；现有state_generation若仅代表批量替换，不能充当逐操作revision。不要给所有字段都加版本号，只在实际缓存依赖点设置。

## 6. 简化内部边界，保留低频完整验证

完整读档、外来定义/编辑输入与发布候选保留版本/引用/数量/时序验证。同步内部路径已校验的原对象，在无yield/回调/他写者的提交段内不重复做全世界扫描、序列化或还原；仅确认本次受影响对象和版本。断言仅用于内部不变量。

原物/库存与环境的最后一致提交要保留；既有短测显示其显式can_commit约0.015ms，不把删它当主要优化。全档捕获和恢复本就随世界当前事实增长，用户接受暂停，不能把它同每帧轮询一起删除，也不引入所有变化永久存日志的要求。

历史伤病/课程/交易记录用于世界事实和角色认识，当前执行器应查活跃/未愈/本人相关索引；不每tick重读全部历史。索引从原记录重建，不能为了省CPU删除游戏历史或把查询推测写成事实。
