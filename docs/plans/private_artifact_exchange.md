# U3-b2 私人器物交换：同一枚旧环的和平交接

2026-11-04。**下一包实施规格，主目录尚未实现或验收。** 核心规则已在忽略的隔离副本开始，不作为可用功能。此包接续[野外所得与引物计划](field_ring_use.md)：玩家晚到断碑台后，向眼前实际持有旧环的人商量，双方同意并当面花时间交割。实际功能和前包验证状态分别以[FEATURES](../FEATURES.md)和[BASELINE](../BASELINE.md)为准；U3-b1 的最终回归仍以该包证据为准。

目标是让同一枚环有一条可信的和平转手路径，同时保留拒绝与中途停手的结果。接受请求不等于成交；钱和环只有完成交割才转移。首包只处理具体唯一器物、具名买卖双方和现金，不构建通用市场、自由竞价、产权司法或胜利自动夺物。

## 玩家体验与参数

断碑台原处空了，只说明那里现在没有环，不能据此知道远处持有人。玩家实际见到持环的小满后，可从 C 请求选择本人、具体环和明确报价。双方须当面、能交流、同高无遮挡；对方忙、不能做或不愿意，分别给予解释。接受后双方留在原处交割，面板说明进行中、已完成或取消；玩家可以主动停手。小满取环后正在返程，首包对已有身体过程返回忙碌，不为了交易强行打断；玩家可按本人所知去河湾，实际找到她空闲时再询问，不能后台追踪或传送。

首个数据驱动报价建议 **4 钱**，交割过程建议 **5 秒共同游戏时间**。暂停不推进这段过程；价格、耗时、距离及意愿参数由开发按实际体验和测试调整，无需另请用户拍板。普通新局玩家行囊初始 6 钱，4 钱留出 2 钱；[预算劳动定义](../../data/definitions/budgeted_labor.json)虽有每趟 2 钱，但公库开局为空，必须先有实际现金和需求才可签约，不能假设工资必定补足报价。小满是否愿卖由本人处境、关系和真实目的决定，不能因玩家付得起就强迫接受；至少要验证一个无需补造钱货的普通和平成交路径。

## 状态归属与真实提案

- 新域 `SimPrivateExchange` 只持有提案身份、意愿及当次同意引用、双方过程、原钱预约引用与一次交割凭证；不拥有第二具身体、钱包、环或时间。钱仍在原区域 `SimInventory` 的 `actor:<id>` 行囊，同一枚环仍由原 `SimArtifacts.objects[id]` 的 `region/container` 指向持有人。
- `actor_home()` 表示身体和行囊的原登记区，实际相遇按连续位置判断。小满属于 `river`、玩家属于 `home`；即使在野外同处，付款仍从玩家原行囊到小满原行囊，环转到玩家原容器。相同原区与跨原区都使用同一规则，不能克隆实物或把机构 `records` 当私人钱包。
- 每个提案身份由**买方、卖方、具体器物、卖方本次取得它的真实来源事件、明确标价**组成。先核对来源与目前真实持有，角色、来源或价格伪造均不可产生有效提案。首包采用固定报价，不提供任意改价以洗选择。
- 当面可沟通且双方有条件时才判断意愿；首次社会判断的结果和随机依据按上述身份持久引用。同一提案反复点击、等待、读档或无关精力波动不重掷。`social_memory.gd::evaluate_request()` 的缓存还包含完整归一化上下文和政策，直接再调用会因条件变化生成新键；新域必须先按提案身份复用原判断，不能仅依赖那个缓存。
- **当次有效同意独立于旧判断。** 每次启动都须本人当面提出，核对双方身体、通信、处境与卖方当前明确同意；旧接受不是永久授权。卖方撤回、失控或其他真实条件使同意失效时取消；玩家取消后可再次当面商量，但不得自动成交或重掷原骰。首包同一来源、双方、标价的拒绝保持原判断；以后若支持有实质依据的重新评估，应明确新依据并沿用可追溯随机依据，不能通过无关变化刷骰。

## 过程、预约与原子交割

1. 开始前同步双方原区域，检查本人活着且能支配行动、移动和交流，未被原任务、职责或其他过程占用；核对可见、距离、同高、无遮挡、停稳、持环及其排他状态、买方可处分的钱和卖方钱包容量。忙碌、不理解、拒绝、资金不足或对象失效都不占身体、不转钱物，也不凭空补足条件。
2. 同意后在买方原行囊预约报价，钱仍在原处；记录双方原身体的连续位置、各自自主前态、提案和当次同意、开始及截止毫秒。双方和环全程独占，其他用环、引物、引息或寄魂操作不能同时占用。开始即占用身体并不产生实际转移。
3. 在共同截止时再检查同意、身体控制与位置、距离/同高/遮挡、原预约的 ID/拥有者/容器/金额、卖方仍持有同一环及目标钱包容量。通过后，在同一同步提交段完成买方扣钱、卖方加钱、释放预约、环移到买方原容器，并写成交凭证与器物来源事件；不能在中间回调、等待或存档。重复结算只认同一笔结果，不再转第二次。
4. 玩家停手、卖方撤回、任一方受击/失控/移动、物件或资金条件失效时，取消并释放预约及三方占用，恢复各自原自主安排；钱和环仍在原处。验收还需覆盖同一毫秒竞争和完成顺序，不将一次接受视为已经交付。

在私人交换域内抽取小型原子转移协作者，集中预检及提交原账本、器物和凭证；它不维护另一个钱包、对象表或通用银行。可参考 [avian_life.gd](../../scripts/sim/avian_life.gd) 的跨账本同步交换和 [budgeted_labor.gd](../../scripts/sim/budgeted_labor.gd) 的候选库存提交。若暂存候选，同区两人必须共用同一份候选账本，跨区使用各自原账本；全部预检后才一起提交，避免两个同区副本相互覆盖。受托或已预约的钱不能被擅用，溢出、缺预约、重复凭证和任一侧不合法时不得半扣。

[settlement_services.gd](../../scripts/sim/services/settlement_services.gd) 的 `transfer()` 没有预约参数，且其操作受 [service_schema.gd](../../scripts/sim/services/service_schema.gd) 的工作单归属检查；[local_trade.gd](../../scripts/sim/services/local_trade.gd) 又是机构常备报价和公库交易。私人交割不能冒充它们的操作，也不能预约后直接用不识别该预约的转账。若新方案在原账本保留操作，必须给恢复校验声明并核对其真实归属；钱转移凭证无论存放何处，都须与本次完成记录双向一致。

## 时间、原物与来源证据

`SimPrivateExchange` 接入 [regional_simulation.gd](../../scripts/sim/regional_simulation.gd) 的活动占用、共同毫秒边界、结算和 `interrupt_occupation()`；参考 [health.gd](../../scripts/sim/health.gd) 的双人身体过程与原自主前态。检查 [world_continuity_runtime.gd](../../scripts/runtime/world_continuity_runtime.gd) 的玩家推进外循环、停稳、WASD 和停止入口，使短过程截止不会被手动投影跨过；取消保持真实连续位置，不吸附格心。

[artifacts.gd](../../scripts/sim/artifacts.gd) 的 `target_in_use()` 是原器物、寄魂与引息共享的接缝：交割须在此对外可见，并在启动时反向核查现有占用。两个买家不能同时拿同一环，交割期间也不能启动对该环的其他动作。

完成时保留原器物域的**真实转移来源事件**，记载唯一环、原持有人/容器、新持有人/容器、完成时刻和私人交割引用；私人完成凭证反向指向该事件。两侧必须互相核对双方、对象、时刻与一次交割，且凭证同时核对实际钱款转移、报价和当次同意。事件不能伪装成原 `taken`，也不能只改当前 `objects` 位置。

[field_opportunity_schema.gd](../../scripts/sim/field_opportunity_schema.gd) 的 `_custody_valid()`、`_custody_at()` 和 [artifact_schema.gd](../../scripts/sim/artifact_schema.gd) 的 `_held_before()`、`_transfer()` 等须识别这一真实交接，使原现场观察、前后持有链及买方后续本人研究/引物有可核来源。扩展原器物动作的统一序号或等价的明确统一顺序，让同一毫秒的取放、交割和研究有可验证先后；不能依赖字典遍历顺序或只比较粗略时间。实际历史按当时证据验证，不用当前墙或当前位置倒推过去。

## 意图、存档与候选

[interaction_requests.gd](../../scripts/sim/interaction_requests.gd) 增加窄的私人交易意图和对象校验；[interaction_requests_runtime.gd](../../scripts/runtime/interaction_requests_runtime.gd) 的 `receivers()`、`objects_for()` 和 `submit()` 只列本人眼前可辨认的人与其可见的具体环。`pending()`、`observe()` 从实际过程及本人接收的结果投影等待、完成或取消，读档可恢复进行中引用；不公开远处交易或将 UI 文案当状态。

旧档显式迁空私人交换域，不创造提案、意愿、钱、环、转移或改变原自主；根、区域与器物版本及必要的事件格式在实施时明确升级，现代缺字段或混版不能通过旧迁移绕过校验。区域恢复时，私人域预约及必要的原账操作须进入 [regional_simulation.gd](../../scripts/sim/regional_simulation.gd) 的 `inventory_scope`；[village_simulation.gd](../../scripts/sim/village_simulation.gd) 会拒绝没有过程归属的预约。

先构造独立候选，在原区域、器物、个人社会决定和私人域都就绪后联合校验，再替换活世界。候选必须拒绝伪造或缺失的同意、来源、钱款或器物半边，错价/错人/错容器、孤儿预约、双重占用、越界时间与重复转移；失败不得改活状态。旧真档保持只读，不为迁移测试覆盖原文件。

## 分步实施与验收

1. **定义和纯规则。** 写固定报价/交割时间及窄意图，建立具名提案、稳定判断与当次同意；验证同一提案重复点击及读档不重掷，拒绝、忙碌和不理解不会启动过程。明确何种条件取消，数值由开发调整。
2. **原身体和一次交割。** 接双人过程、原钱预约、环的共享排他与小型原子协作者；覆盖同区/跨区、余额不足、受托/竞争预约、满钱包、物件忙碌和两个买家。接受时钱环均未移动；完成只转一次；任一方中断后原钱原环均在且双方恢复。
3. **来源和存读。** 接原器物转移事件及双方/钱款/同意的双向因果，覆盖原现场保管链、同毫秒顺序和之后研究/引物；完成独立候选、旧档空迁移和坏候选原子拒绝。对进行中、完成后和取消后的真实档做完整停开同未来；不得用修改 fixture 来制造普通路线。
4. **普通产品路径与拒绝边界。** 从正常新局让小满真实先取环，玩家晚到看到空台，再按可知路线见到她；回程忙碌时应拒绝打断，在河湾真实空闲后当面商量。实际记录可负担报价被接受、经过配置的交割时间后同一环与实际报价完成交割，并可继续本人研究/引物；另由接受后玩家实际停手验证钱环不动、预约释放、双方继续原生活。不得传送、硬改 NPC 或强造档来伪装普通路线。拒绝、重复请求/读档不刷骰及卖方撤回另用明确标注的受控规则场景覆盖；若在正常世界自然遇到拒绝，也应保留证据，但不强求同一固定开局和提案既接受又拒绝。记录验收时实际使用的价格和时长，初值为4钱/5秒；找不到普通可成交窗口时继续修实现/调参数，不把本包算作通过。
5. **实际运行与回归。** 验证 C 选择、提示、进行中读档与停手，检查 1280×720 可见画面和日志；执行适当定向测试及项目要求的完整 `python tools/godot.py check`，按当时工具与 CI 状态保留命令输出和证据。通过后更新相关功能、基线和 QA 文档；本计划本身不是完成或测试证明。
