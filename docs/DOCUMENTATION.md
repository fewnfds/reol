# 文档职责与长期记忆

## 什么会进入agent上下文

| 信息 | 载入方式 | 本项目的放置原则 |
|---|---|---|
| 系统/开发者/本轮用户指令、宿主提供的工具目录 | 由宿主注入 | 仓库不能改写其权限或优先级 |
| `AGENTS.md`、可选的`AGENTS.override.md`及已配置fallback | Codex启动时发现并组合；全局与项目目录链可能同时适用 | 本仓库使用根AGENTS短指引，领域知识放普通文件 |
| skill名称、description、路径 | 技能发现时提供，受宿主预算影响 | 描述准确触发范围，不在description塞规则和当前任务 |
| `SKILL.md`正文及references/scripts | 选中技能后才读取/执行 | 放可复用方法，详细参考再按需打开 |
| README、HANDOFF、设计、工程、计划、归档 | 普通文件，需主动查询 | 文件名或AGENTS里的链接不会自动加载正文 |
| `.codex/config.toml` | 宿主配置，不是普通项目记忆 | 指令相关设置可能改变载入行为；不把含凭据的本机配置复制到文档 |

这是Codex官方发现模型，不保证所有客户端完全相同。2026-11-11静态核对：仓库仅根AGENTS；可见项目/用户配置未设置额外文档fallback或自定义指令文件。未启动第二agent测载入，也不宣称已编辑的规则一定热更新旧聊天；新会话应以实际注入为准。

## 四种文档角色

- **稳定约束**：[基础边界](engineering/constraints.md)与[已定游戏规则](../design/rules/README.md)。只有影响跨任务行为且已确认的边界进入这里；AGENTS只指路。
- **项目记忆**：HANDOFF维护当前工作；BASELINE维护核实数值/版本；FEATURES维护可用能力；领域工程页维护接口与原因。它们是可查询事实，不是全部常驻指令。
- **当前计划与候选**：唯一主计划安排框架，specs/design候选讨论做法。计划不授予额外行动范围；未实现方案不算代码能力，也不约束以后必须沿用旧类。
- **历史资料**：已结束的报告、旧参数/流程/计划和素材生产方案进入archive或固定Git版本。正文中的“下一步/必须/当前”只在原日期成立。

每类正文的位置由[项目记忆地图](README.md)指定；不再另立同义MEMORY、总进度或全文件CATALOG。

## 写入、更新和去重

1. 先判断这是临时要求、确定事实、候选还是稳定边界，再从地图选归属；用概念和实际代码标识搜索那里。已有内容就改原页，其他页面只链接。
2. 新正文只在没有合适owner且内容确实独立时创建，并在地图的相关领域入口登记。不要求每个任务都有计划、ADR、QA、总结各一份。
3. 当前状态覆盖旧状态；旧过程需要追溯时交给Git或归档。更新只触及本次改变的事实、接口及其链接，不机械维护所有状态页。
4. 冲突按性质处理：用户最新决定更新规则owner；代码说明实际行为，不自动推翻已确认规则；文档落后就纠正，尚未实现就标候选。修改日期或目录深度不产生授权。

用“用户随口建议”推导的假设标为待定，不写成“用户已确认”。一次调试故障可以修代码或加局部说明，不自动形成永久全局禁令。

## 过期与归档

已被替代的工作流、过时实现快照、结束阶段报告和后置资源方案退出日常入口；仍有效的信息先归并到现行owner。移动时保留来源、日期、证据和相对链接，避免活动页与归档同时竞争权威。

archive通过`.ignore`退出默认rg检索；追溯从[归档入口](archive/README.md)显式进入。原报告和原fixture不改写为“通过当前版本”，归档不会自动退役运行代码。已确认规则除非被用户改变，不因时间久而过期。

## 如何积累经验而不膨胀规则

完成工作时只保存会改变下次决策的结论：临时停点写HANDOFF；可核实事实写原领域/BASELINE并给来源；有效设计取舍写其接口页；跨任务复用方法改已有skill。若需要新增skill，其触发应窄，正文不复制规则和计划。

只有明确、长期且跨任务的边界才上升为稳定约束；不自动把更多工具、更强审查或更长测试当作改进。失效经验与旧规则一并删减。这个维护动作随实际工作顺手完成，不创建自我反思后台、每轮总结模板或新的审批循环。
