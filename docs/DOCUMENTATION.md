## 权威分工

| 问题 | 负责文件 | 其他文档怎样引用 |
|---|---|---|
| 现在的任务/授权/暂停/未提交接续 | HANDOFF | 链接，不复制多代“当前active/下一包” |
| 用户确定的游戏概念 | GAME-BRIEF；领域细则在design对应页 | 例子不是强制剧情，开发候选不升级成用户决定 |
| 当前实际可操作范围/入口 | FEATURES | 按领域引用，不在各入口再抄一份功能清单 |
| 版本、SHA、测试/画面/性能证据与未验范围 | BASELINE；具体历史证据在qa | 测试成功只能覆盖受检版本/路径 |
| 代码状态所有者、接口和限制 | ARCHITECTURE | 目标架构留plans，领域细节指源码/规格 |
| 当前实施包/联合出口/工作量预算 | world_engine_execution；总依赖在ROADMAP | 旧样本路线不构成并行执行队列 |
| 设计依据/竞品/理论/许可候选 | design/research、工具研究 | 来源事实与我们的建议分开，候选不等于采用 |
| 工具实际配置/命令/维护/审查 | SETUP / TOOLCHAIN / MAINTENANCE / CODE-REVIEW-WORKFLOW | 分别管已装、怎么用、怎么升、怎么审；不各复制整套状态 |
| 历史理由与原文 | DECISIONS索引、archive | 追溯时读，不作为新任务或永久实现约束 |

发生矛盾时先确认描述的是**目标、代码还是证据**：概念按最新用户决定，行为按真实代码及运行，完成结论按具体SHA证据。代码存在而未验证要标待验，代码偏离概念要登记缺口，不能用一个“较新文档”抹掉另一个层次。

## 状态词与边界

- **已定概念**：用户明确选择/持续方向；不意味着已实现。
- **设计/候选**：开发提出的结构、公式、参数与场景；未经验证不可当成唯一世界法则。
- **有限样本已验**：有对应行为和证据，只在写明范围内成立。
- **在制/待验**：有代码或文档落地，缺规定验收；不列为完整功能。
- **暂缓**：不是当前前置，不为它扩架构；恢复需要实际依赖或新指令。
- **历史记录**：保留当时证据/方案；其中版本、下一步和授权均不延续。

同一系统可同时拥有“概念已定/有限样本已验/完整系统待实现”三种状态。不要用一个勾选把三者合并；不在所有页面贴重复状态长前言。

## 维护方式

1. 新内容先找现有负责页，独有规则才新建文件；按定义/实例、事实/认识、目标/实现/证据分类。
2. 稳定工程约束放AGENTS/相关技能；当前进度只更新HANDOFF/BASELINE/FEATURES各自负责部分。新会话不必整读所有长文。
3. 完成包保留最小规格和QA引用。旧完整报告可归档，在原路径留短链接，避免破坏已有引用；不得覆盖fixture或修改历史证据来匹配新说法。
4. 大幅重写先保留原文。此次快照在`archive/documentation_consolidation_20261104/`，更早档案保持原样；原始相对链接可能不再相对新位置有效，所以archive不是当前可执行指南。
5. 结束运行结构/链接/差异及目录覆盖检查；文档任务不启动Godot、不把结构检查当语义或游戏验收。后续新增/移动文档同步更新目录索引；不让目录重新积累“最新”段落。
