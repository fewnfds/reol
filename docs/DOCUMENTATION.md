# 文档与项目记忆

目标是让无上下文的AI找到当前事实，也让已有上下文的AI只读本次所需资料。

## 怎样进入上下文

| 来源 | 载入方式 |
|---|---|
| 当前对话、宿主指令 | 宿主注入，最新用户意图优先 |
| 根AGENTS.md | 宿主按目录发现载入，只放短入口和基础边界链接 |
| 技能名称/描述 | 宿主提供目录，相关时才读取正文；技能提供方法 |
| HANDOFF、工程、设计、计划等文件 | 按需主动读取；链接不会递归载入 |

本机配置、凭据与顾问程序不属于公共项目记忆。具体宿主载入行为以实际注入为准。

## 每类信息一处正文

| 信息 | 归属 / 维护方式 |
|---|---|
| 长期边界、已确认玩法 | constraints、design/rules；只收跨任务有效的已定要求 |
| 当前停点、未完成事项和必要路径 | HANDOFF；覆盖旧状态，不追加历轮总结 |
| 当前能力、实现职责与参数含义 | FEATURES、对应工程页；接口变了改原页，默认参数以代码为准 |
| 已接受的构建与测量 | BASELINE；具体机器数值由performance.json维护，正文不再复制数字表 |
| 当前实施顺序 | 主计划；完成项退出活动队列，功能详情回原页 |
| 未采用思路、参考资料 | design候选/研究；标明来源、日期和适用限制，不产生实施任务 |
| 日志、临时脚本、顾问问答、实验草稿 | 忽略的logs或.local任务目录；需要长期保留的结论才提升到原页 |
| 已失效的实现和过程 | Git历史或archive；不从旧“当前/必须/下一步”恢复任务 |

## 防止过载记录

过载记录是把一次任务的全局上下文拆写到许多页，靠当时记忆维持它们之间的关系；上下文丢失后，候选、进度和事实无法辨别，文件永久停在中间态。

写入前先搜索概念或代码标识，找到原页。只留下能独立理解、未来会用到的事实或理由；一次性建议和排错过程留在本机工作目录。没有独立用途就不新建计划、QA、ADR、记忆或总结。

暂停或交接时，把未完成事项的下一动作和必要代码/证据路径放在HANDOFF的一处；已完成事项更新归属页后从接续页删去。持久文件能从文档地图或所属主题入口找到，临时工作不另造长期索引。无需每轮生成文档清理报告。

旧过程可以由Git恢复就不再复制一份归档；确有独立研究价值时才归档。文档数量和长度本身不是门槛，关键是职责清楚、状态明确、没有多处维护同一结论。

发现矛盾时核对用户决定、实际代码和测量。可以删除失效要求，也可以不用不适用的方法；不因一次教训给AGENTS、skill或工作流增加一条全局禁令。开发步骤见[开发循环](engineering/workflow/testing.md)。

组织方式的参考与适用限制保留在[文件组织研究](../design/research/project_structure_references.md)，参考不是工作门禁。
