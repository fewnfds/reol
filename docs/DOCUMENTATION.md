# 文档与项目记忆

目标是让新AI从短入口找到事实，避免把整个仓库当成一份长指令。

## 哪些内容会自动进入上下文

| 来源 | 载入方式 |
|---|---|
| 当前对话、宿主指令 | 宿主注入，最新用户意图优先 |
| AGENTS.md | 按宿主的目录发现机制载入；本仓库只保留根入口 |
| 技能名称/描述 | 宿主提供目录，相关时才读取SKILL.md及参考文件 |
| HANDOFF、README、工程/设计/计划等Markdown | 普通按需资料；链接不会递归自动载入 |

本机Codex配置不是公共项目记忆，含凭据的配置不复制入库。具体宿主行为以实际注入为准，仓库文件不能改变权限。

## 每类信息一处正文

- **边界**：[constraints](engineering/constraints.md)和[已定游戏规则](../design/rules/README.md)。只收已确认、跨任务有效的要求。
- **当前事实**：HANDOFF为停点；BASELINE为版本/测量；FEATURES为可玩能力；工程页为当前接口。入口见[记忆地图](README.md)。
- **意图**：唯一主计划安排当前阶段，specs与design候选讨论做法；计划和参考示例不等于实现或执行授权。
- **历史**：已结束实验、旧流程与过期快照放archive或由Git追溯，默认不检索，不继续其中的待办。

记录前先选归属，再搜索已有概念/类名并修改原页，其他入口只链接。用户一次性建议不自动升级为基础约束；不为每轮任务新增计划、ADR、QA、记忆和总结各一份。

当前状态覆盖旧状态；需要保留的证据移到历史，链接随之修正。代码接口变了就更新原接口页，候选未实现就明确标注。不同页面出现矛盾时核对用户决定、代码和实测，不靠重复数量或修改日期定真伪。

项目技能只提供可复用方法，不能新增提交门禁、强制文档模板或与当前任务无关的验证。重复规则和失效方法可以删除；是否新增文档或技能取决于有没有独立、长期用途。
