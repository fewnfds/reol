# 文档权威与维护合同

文档按所回答的问题组织。最新用户指令优先；历史代码、class、schema、测试数量和旧阶段不会自动约束新架构。

## 唯一职责

| 内容 | 唯一位置 |
|---|---|
| 游戏方向与已确认世界规则 | design/vision.md、design/rules |
| 机制/参数候选与来源 | design/systems、proposals、research；须说明候选与证据边界 |
| 核心问题、范围、交付依赖和验收情况 | docs/plans/foundation-priorities.md |
| 独立的详细工程合同 | docs/specs；不另排施工队列 |
| 领域逻辑职责 | docs/engineering/architecture/05-framework-domains.md |
| 现有实现接口、工具和稳定工程约束 | docs/engineering；明确当前实现与目标结构 |
| 授权、执行状态、未提交工作与handle | docs/status/handoff.md |

## 目标、实现和证据

逻辑所有权不绑定历史class、单线程或同一字典。现有API合同只说明对应运行代码；目标规格可以替换实现，已确认游戏规则和必要失败语义继续成立。代码完成、普通Main采用、性能达标和整包验证是不同结论。

研究、候选机制和历史QA中的下一步不产生授权。状态只在status维护；基础问题和交付只在主计划维护。算法属于明确领域及其内部模块，不因一次修复再生一份独立计划。

正确性由当前规则及可观察后果决定；旧测试可按保护合同重建/退役，不能通过删除当前失败断言凑绿。历史来源保持版本与日期；需要引用已删除资料时使用固定Git SHA链接，不伪装为当前说明。

## 术语原名与唯一标记

- Godot、GDScript、SceneTree、WorkerThreadPool、RenderingDevice及已命名API/算法保留原名，不另造翻译或同义class。
- 中文世界概念保留中文，实际English代码标识符按[术语映射](engineering/terminology.md)定位；映射用于找现有代码，不冻结实现。更名同步调用、反射、工具、存档边界和文档。
- 普通解释使用自然中文，产品不展示无助于玩家决策的内部技术细节。

## 增删与检查

1. 新会话按HANDOFF和主计划/领域读最少材料，每次1–3技能；不默认加载历史或全库。
2. 活跃页以4–12KiB为宜，超过16KiB按独立主题拆分；不把一个主题机械切成多个同义总纲。
3. 新文件必须有独立职责。重复、失效或有歧义的内容直接合并/删除，不靠追加长免责声明继续保留。
4. 文档删除/迁移同步入口、链接、技能和分类目录；Git保留来源，原fixture/证据数据和隔离用户工作不改写。
5. 链接优先相对路径。历史原文使用固定Git版本，当前入口指向当前合同；不要把旧标题链接到内容不相干的新页。
6. 游戏包完成核对功能、工程合同、证据和HANDOFF；纯文档只查结构、链接、大小和差异，不启动引擎或模型审查。
7. `python tools/check_structure.py`不证明行为/性能。数据静态解析及引用也不等于完整装配验证；结论须说明实际范围。

[分类目录](CATALOG.md)只列真实文件与分类，不维护状态、重复内容清单或额外任务。
