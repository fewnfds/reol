# 原身体CPU批计算：首条运行接缝

日期：2026-11-11。代码起点`3e32b7048e0622de87bc1fa6823ed661c36b8369`，分支`codex/execution-foundation`。属于[主计划](../plans/foundation-priorities.md)A的第一部分，不是A整包或300人规模出口。当前实现合同见[批执行](../engineering/execution-batches.md)。

## 实际改动与范围

- `SimBatchExecution`复用Godot WorkerThreadPool，处理scratch-only任务、非阻塞完成检查、撤销采用及最终回收；不新增autoload、世界状态或时钟。
- `SimActorAdvance`按到期人物准备Packed需求/体力/既有路段数据，worker计算候选，原VillageSimulation按序采用并发出真实空间变化；原动作、预约、搬运及资源提交继续由原owner处理。
- `native_interval/native_actors`接入同一个SimSettlementKernel，用BUDGETED回执区分正常等待和真实错误；手动接管在begin前受理，位移不因线程续算重放。既有呈现和存读pending保护覆盖这一步。
- 普通WorldContinuityRuntime绑定本接口；少于64个到期人物走原直接路径，32人一chunk，默认最多4个worker。工具可用`--actor-workers 0`运行同一Packed计算，诊断记录实际线程、采用及分项成本。
- 当前保存格式不变，线程、候选和计时不入档；取消/依赖失效/原身体同步/成功restore撤销候选，失败restore保留活世界。

GPU接入位置已经明确：设备批次用紧凑输入、时刻/代次/依赖及输出候选，沿原owner采用。当前需求的64位整数布局不能直接当作GPU浮点合同；本包没有新增GPU dispatch，也不声称普通环境已使用GPU。

当前native_actors步骤累计约2.54/2.58秒，包含大量仍走原直接路径的工作与同步通知；只占少部分的worker数学不是主要成本。接下来的A实现应从热数据实际所有权、输入准备及批量发布减少主线程重复工作，批调度本身不是性能完成声明；完整框架出口仍以主计划为准。
