# 真实地面来源 CPU/GPU 接入验证

2026-11-05。范围为[真实缓存合同](../engineering/environment-ground-cache-contract.md)的计算后端：由同一真实原物投影计算基础目标，不包括实际温度/五行残留、普通Main、移动携物、房间或新存档域。GPU结果不能作为另一份世界事实。

## 版本与方法

首代码`3e91b28ed27a082fd341ff47c5fbc68d14718357`，审查窄修到`9b3e724ce7e405d01b885e9b3e477b8afa09b226`，主代理统一验证；四份原环境WIP按`logs/world_lifecycle/protected.json`保持4/4未变，不混入提交。准确SHA另建独立检出`logs/environment_ground_gpu/validation`，导入后只由本代理串行启动验证进程，独立日志和源码哈希保留。运行层与原物分工由弱引用租约连接，模拟层不依赖渲染层。

采用Godot4.7.2 stable、Windows、i5-13600KF、约32GiB开发机、单RTX3060、Forward+/D3D12。目标仍是[16GB/3060整机基线](../engineering/architecture.md#全项目性能基线)；本机不是16GB整机验收。测试使用官方引擎程序而非独立发布包，不把离线场计算称为游戏FPS。

## 功能证据

准确SHA独立检出定向**9498断言、0失败**，12.831秒，峰工作集约258MiB；覆盖原A2a、库存epoch、原计算服务与新真实来源接入。主工作区前测9504断言0失败仅作开发证据，不能替代此干净版本。

同检出真实RTX3060原生验证11.826秒退出0，无ERROR/SCRIPT ERROR：10个案例全部达到预期，**6144格/43008通道**与真实原物A1 oracle逐格一致。包含半径2/4/8/16、冷热与五行、多格来源、同类1→10000份同强；来源未同步先preparing再实际GPU完成；运行中move拒旧后CPU计算新值；取消后回收/复用；直接库存旁路、同owner恢复与换世界均拒旧，新绑定可再次GPU完成。故意失败案例的status=failed是被验证的拒绝结果，整份QA结果passed。

来源变更先更新外层代次和可读性，GPU发布前再次核原所有者、库存epoch、定义、绑定、来源同步队列和代次；仅查底层revision不足以覆盖变动已登记而投影未同步的间隙。取消不清空原待算块，关闭不在主线程join活线程。CPU和GPU均不推进共同时间。

原日志为`validation/logs/environment_ground_gpu/targeted-clean.{json,log}`、`gpu-clean.{json,log}`；真实GPU路径与无设备CPU回退分别测试，不能互相冒充。

修复后的准确SHA再次定向**9513断言、0失败**，12.621秒；原生RTX3060仍10案例/6144格/43008通道通过，11.818秒，无ERROR/SCRIPT ERROR。日志`targeted-final-sha.*`、`gpu-final-sha.*`。新增回归以真实物资在普通容器间连续往返，逐块请求仍能完成；保持正数的同类堆不改变来源代次。断言数随预算循环次数有少量差异，不作为性能或功能完成度指标。

## 首错与限制

主工作区首轮原生脚本在autoload初始化前preload复合fixture，导致GameClock编译错误；已改为延后到SceneTree初始化后的load，再进入上述准确SHA。首轮最后一次local device初始化还出现D3D12 CreateDescriptorHeap/设备拒绝，未确证根因；原失败日志`gpu-initial.*`保留，不算通过。修正测试入口后的主工作区与独立检出均通过完整原生案例；后续密度基准另记录是否再现，不能据一次重跑声称所有驱动均稳定。

## 真实负载性能

基准`tools/benchmarks/environment_ground_compute_guard.py`：相同原物布置、定义digest、半径和变更序列，CPU/GPU各用独立进程；75%独特实物、25%真实材料堆，每格一个来源。初始装配、目标重建、同步变更及恢复分别计时；主线程每次poll约2ms目标、每呈现帧至多8次CPU poll，GPU忙时每帧一次。延迟含帧调度，快照/传输/设备建立/回读/发布均非免费。外部900秒/6GiB等守卫只保护该次子进程，不是游戏模块内存限制。

64²/半径16的初次目标：CPU322.831ms、GPU114.868ms；GPU设备建立71.985ms、主线程请求1.520ms/发布0.089ms。两份基准全4096格独立oracle校验通过且digest相同，范围仅为这个负载，不沿用旧合成来源160ms推算提速。

首代码同负载测量：128²混合半径CPU6209.091ms、GPU289.531ms；512²/半径16两轮CPU19754.178/20153.249ms，GPU569.241/492.764ms。512²的1%分散变动，在原物提交后至新结果可读CPU19706.727/20126.346ms、GPU558.988/608.890ms；原物提交本身另计约0.48秒，不能从链路中藏掉。大图各24个分布样本，CPU/GPU初值digest相同；不称大图全部262144格逐格oracle核对。

512²原物来源装配仍约7.36–7.46秒，不因GPU消失；CPU峰工作集约2.34GiB、GPU约2.53GiB。CPU初建poll p99约2.02–2.07ms，GPU约2.40–2.56ms；GPU主线程request约5.6–6.0ms（含约3.7ms快照和线程启动），并非所有同步步骤都低于4ms。实际显存未单独取得可靠进程峰值；静态内存、进程工作集与GPU工作缓冲分别解读，不互相替代。

初次创建GPU设备/管线每job仍需约70–105ms。自动4096格阈值在512²选择GPU，局部48²选择CPU；此保守策略未必是稀疏、小窗口的最佳交点，不承诺任意请求都加速。以本包密集大范围场计算为依据保留可选GPU；不扩常驻设备、通用GPU框架或玩家设置。

## 审查与完整回归
