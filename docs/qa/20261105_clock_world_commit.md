# 共同时间：先完成世界，再发布时钟

2026-11-05。本包接入普通 Main，修复预算或环境预检不足时，GameClock 先公布未来、世界和身体还未完成的顺序问题；为新环境场的分帧准备提供必要接缝。**普通冷热仍为旧 Q，新来源场未因本包接管 Main。**

## 实现与边界

- `ReolGameClock` 只允许一个 interval executor；其返回原世界实际完成的整数毫秒后，才发布 `time_advanced`，分钟通知随后发出。回调必须在请求范围内，零进度不发虚假通知；绑定失效不自行绕过世界推进。
- `VillageRuntime` 绑定真实执行器，原通知监听只同步呈现。原身体的手动/自动移动仍由原区域边界调用一次；在每个实际子边界，先处理已采样的手动意图，再投影尚存在的自动行程，最后执行手动身体积分，避免 WASD 接管前先朝旧目的地移动。
- 普通帧只扣实际提交毫秒；部分或零完成保留原区间与帧债，下帧续算。等待保留目标，取消等待只取消尚未请求的后续等待；显式推进每次最多4096个分钟区间，其余继续保留。显式命令是新增请求，排在旧的已请求边界之后，不将原帧剩余债务同时算成已完成。
- `RegionalSimulation` 保留更大 `target_ms` 作为积压，但单次实际推进不越过本次 `requested_ms`。有事件预算积压时运行适配不忙循环、不以正常 pending 发引擎错误，也不伪造原自动路段的未来位置。
- 回调/通知中拒绝重入推进、绑定更换和恢复。会话加载在替换世界之前检查正在提交状态，避免时钟拒绝恢复时活世界却已被替换。原生无树测试释放也解绑，不能留下已销毁实例的执行器。
- 当前七字段时钟、根50与区域41写档格式保持；不声称支持保存临时候选。pending、正在提交、clock/world不一致或world仍有目标积压时，普通保存先返回 `ERR_BUSY`，不动主档、备份或临时文件。已验证的完整加载可以放弃旧活局的未完成请求并恢复保存边界。

本包没有使所有世界规则具备回滚事务；新源目标自动续段、原物三方事务、付费脉冲、有限旧热导入及房温仍见[F2接管合同](../plans/field_environment_integration.md)。真实规则错误仍需暂停定位，不能把任意中途错误当安全预算续算。
