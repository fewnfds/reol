# 运行、精度与过载

## 世界事实与计算精度

唯一事实、直接因果和资源守恒是正确性边界。全球严格“同操作必然同未来”不是产品要求；也不因为随机性允许重复扣款、死者被陈旧治疗复活或画面补造模拟进展。物理连续信号可以用适合玩法的离散近似，近似和延后要说明改变了什么。

当前运动为50ms世界时间一跳，速度5格/秒，沿Godot原生路径连续走，不能穿墙；允许角色互相穿行，尚未恢复人群避让和大体型占地。需求/环境采样每1000ms世界时间一次。五行地块值直接按基线+来源max与百分比潮汐读取，不做持续趋近；五种潮汐各自每60000ms抽取95..105整数百分比。稳定来源下不会每秒累计添加潮汐。

温度用距离衰减场及墙体衰减，人物和房间保留指数响应；无人空地没有残余热历史。静态来源变更/施工可触发冷路径重建，当前不承诺无限地图和频繁大面积施工的耗时。具体参数以代码为准，不在多处复制维护。

## 倍率和显示

Runner自身使用单调墙钟积累倍率时间需求，1×/2×/4×以完成更多相同50ms步实现，不放大运动dt，也不仅放大时钟。画面以独立30/60/120FPS取最新已提交快照，模拟不等它收取或再次派发。

显示只在两个已提交位置间插值，动画与镜头使用相同显示时刻。低显示帧率会降低视觉采样密度；它不应再成为模拟每秒只能交接若干步的硬上限。实际倍率由世界毫秒增量/墙钟秒测量，不能用请求倍率或FPS代替。

## 算不过来时

模拟完成一步后可以连续赶算后续步，仍逐步提交完整效果。积压的时间需求有上限；超过上限只放弃额外追赶需求，不跳过资源、伤害或已经提交的结果。达到计算容量时实际世界速度会低于玩家选择，并在HUD/日志显示；帧率高不代表模拟满速，低总CPU也不能证明没有串行关键路径。

当前没有“强行保墙钟速度、漏掉业务计算”的模式。也没有将所有领域强制保持同频率：普通走路不唤醒慢环境，静态物不每步刷新。下一步新机制优先削减无用工作，再按实际依赖选择批并行或其他设备。
