# 运行、精度与过载

## 世界事实与计算精度

唯一事实、直接因果和资源守恒是正确性边界。全局严格“同操作必然同未来”不是产品要求；随机性不允许重复扣款、死者被陈旧治疗复活或画面补造进展。连续过程可用适合玩法的离散近似，说明漏掉了什么，比承诺完整物理模拟更有用。

### 领域频率

| 当前工作 | 世界时间节奏 / 语义 |
|---|---|
| 身体运动与共同提交 | 50ms，速度与路径按实际dt推进；到达/到期记录保留步内时间，动作下一段从下步开始 |
| 战斗/警戒 | 当前目标、在飞物与攻击每步处理；新目标发现按200ms分散，追击重规划约300ms。先收集同边界攻击再提交，允许互杀；失联追最后所见，至到达或5000ms超时，路径失败后自动警戒延后2000ms，并按地形/能力版本记住失败位置，目标移动后可重新发现 |
| 人物需求、身体环境与房间温度 | 每1000ms；先处理本步更早的到达/行动，再提交期末热伤害 |
| 五行潮汐 | 五通道各自每60000ms抽95..105整数百分比，乘读取值，不累计添加 |
| 植物 | 5000ms分成100组，每步一组；按上次采样rate积分，不为每株分配移动页 |
| 玩家感知 / NPC观察 | 玩家约200ms并在布局变化时更新，NPC按决策到期、约5000ms观察与行动反馈局部刷新；人物与镜头显示继续连续插值 |
| 静态拓扑/来源/外观 | 实际变化触发，结构改动合并后刷新；不每步扫描所有静态物 |

上述是当前实现，不是所有新功能必须采用的固定档位；参数以代码为准。没有全域亚步屏障，也没有按墙钟压力自动跳过已到期动作的通用低优先级池。

五行直接读基线、来源max和潮汐，不持续趋近；输入不变就不跳动。移动来源、天气/身体热惯性和植物是各自过程，不能把温度或来源改变解释为潮汐每秒叠加。温度使用距离/墙体衰减场，人物与房间有指数响应，空地没有残余热历史。

植物采样允许环境输入已更新后到下一组轮次才响应，先前区间仍用旧rate近似；天气等输入本身还有自己的更新周期。快速经过的热源可能漏采，不能宣称5秒抽样必定捕捉4秒事件。采收/消耗/毁坏/修行完成等直接效果仍在owner原子提交；目标读条期间改变，完成时复核，不能因慢采样凭空发奖励。

地面身体当前半尺寸0.35/0.9格，以保守轴对齐方形检查站立/线段净空，允许飞行越墙；不是精确圆体、任意形状物理或全局欧氏最短路线，当前无角色间避让/推挤/编队。目标不合法时只在附近2格内投影并逐一验证，无解则拒绝；合法的格内小数落点保持，停止不回格心。追击约300ms复核，目标位移至少0.25格或本次移动已结束才重下路线。

路径仅在新目标或失效时准备。当前每lane每步最多32次准备（含直达和缓存命中后的几何）、其中最多8次原生新搜索；未轮到的请求保留等待，已有合法路线照常走，玩家所在页的首行先执行。平滑最多前探32个通路节点，再折半寻找可走段，DDA访问线段窄走廊而非对角包围盒面积；这些是当前参数，不是单次调用的硬耗时保证。失败后只给完整遍历且不超过128节点的小封闭区打标签，超限不发布；相关拓扑变化全部失效。统计分别暴露原生搜索、几何准备、等待次数，具体突发延迟/尖峰见BASELINE。

转角/提前停步保留可变长度时间节点，显示和箭矢不再用起末弦线代替整个折线；普通直线步无需这份稀疏数据。到达与投射物结果的共同提交节奏仍如上表，未变成连续物理求解器。

感知按距离加沿线环境损耗判定，墙/家具/成熟大树降低范围，物理弹道仍独立检查阻挡。布局损耗实际改变时预先做一次3×3加权扩散，查询仍只读一条准备路径，避免单格射线形成细碎缺口；不在每次查询中重复邻域滤波。常用局部格线/距离预先准备，大视距用同公式后备；NPC只查局部候选，不各建全图。

玩家逻辑地图按格心距离余量与共同损耗计算，阈值控制实物观察/动态显隐，约±1.25格边缘支持带只写地表显示值。换格、视距或损耗改变时重建局部图，同一格内不连续重算，观察仍约200ms。0视距表示失明，多格静态物按任一可见占格判定。

屏幕柔边现在使用与人物相同的已提交轨迹/显示时间，直接读取连续浮点位置，不把圆心吸附整数格或0.1格。GPU沿该位置到片元方向，用24次有界采样近似积分原有`Sight.smooth_loss`；只为玩家绘制一张遮罩，损耗纹理仅随实际版本变化上传，不平移世界固定阴影、不按走动重建全图。CPU观察、战斗判定、静态记忆和地表缓存仍为原所有者；Shader不写探索、不读取隐藏人物或最新地表，也不为NPC建立高分辨率地图。视觉衰减与格心射线并非数值完全相同，长视距下24样本更粗；边缘单位/静物仍可能体现原观察周期，不宣称所有感知已精确到0.1格或复制商业RTS闭源算法。

屋顶尚无完整遮雨/照度后果。地区始终在同一有限世界推进，当前不存在远区跳时或LOD补算。

### 冷热暴露与耐受

身体的`body_heat`是游戏暴露指标，沿用初始22°C与30秒指数响应，不是人体核心体温；指标低于0°C或高于80°C时，每世界秒产生1点冷热伤害。先消耗最多100点浮点耐受，余额耗尽才累计HP伤害；不足整点的剩余伤害保留在`thermal_carry`，不会因每次取整凭空消失。冷热仍按上表整秒采样，不能将探针刷新频率当成伤害结算频率。

身体指标回到5～75°C且所在环境在0～80°C时，耐受按每世界秒1点恢复，不恢复HP；仍在危险环境或身体尚未脱离危险时不回充。战斗伤害直接扣HP，暂不进入耐受；死亡清零耐受及余数，不再恢复。数值是当前试玩平衡，并非未来抗性系统的固定设计。

worker只改独占身体页并生成本页事实，join后由World发出冷热损耗、耐受耗尽/回满和死因记录。显示中的连续损耗合并不改变真实伤害。普通开局与混合压力开局共用算法，随机测试场源仅由压力配置启用；地区背景温度和真实实体排放各自保留。

## 倍率和显示

Runner自身按单调墙钟累积所选倍率需求，1×/2×/4×完成更多相同50ms步，不放大运动dt、不仅放大时钟。画面独立收最新已提交快照，不再负责派发下一步。

显示在相邻已提交姿态间插值，动画、镜头与选择用同一显示时刻；低FPS降低视觉采样密度，不应成为模拟步数硬上限。实际倍率按已完成世界毫秒/墙钟秒测量，不用请求倍率或FPS代替。

## 算不过来时

模拟可连续赶算后续步，仍逐步提交完整效果。积压需求有上限，超过上限只放弃额外追赶需求，不丢资源/伤害结果。达到计算容量后实速低于选择倍率，并在HUD/日志暴露；帧率高不代表模拟满速，低总CPU也不证明没有串行关键路径。

当前不强行保墙钟速度而漏业务计算，也不自动延长所有领域的dt。减负首先靠休眠/到期、局部工作、缓存、分散慢周期与合适的并行；需要进一步延后时先确定该领域可接受旧值与最长延迟，再局部实现，接入选择见[计算接入](execution-batches.md)。
