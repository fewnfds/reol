# 模拟系统的复杂度与扩展范式

接入功能时，可以先画出一条实际调用链。从谁触发、调用多频繁开始，沿途数一数读取的对象、写入的事实和收到通知的人。需要按事务选择节奏、线程或呈现方式时，可对照[新计算的接入选择](execution-batches.md)。真实规模、观察等待和试验取舍见[验证基线](../status/baseline.md#性能收尾对照)。

## 成本为何会随系统装配放大

同一个函数的代价还取决于调用它的地方。例如站位请求检查多个候选落点，每个落点再扫描全世界身体，成本随 `请求次数 × 落点数 × 身体数` 增长。密集战斗同样会增加局部接触对和时间子区间，影响每段都访问的身体数据。相关人数、局部密度、实际复制大小和写入次数往往比总人口更能定位问题。

排查一个热点时，可以把查找、准备输入、计算、合并、采用、通知和显示分开计时。CPU 累计时间适合描述各线程做了多少工作，墙钟时间更适合观察世界等了多久。父子计时可能重叠，可以在比较时把子项扣出来。

## 新能力怎样接入

| 情形 | 可试的做法 | 可以一起看什么 |
|---|---|---|
| 大量身体每次都要移动或代谢 | 用连续身体页批处理，按需要将几个读者共用的计算合并 | 访问的页数、实际活动者、页批等待，以及局部战斗是否带动远处全页重复更新 |
| 少量变更、已知到期或自然休眠 | 用活动集合、相关变化或到期索引派发 | 触发次数和订阅者数、同时到期的峰值、取消后的清理及重试机会 |
| 查询某人、设施或附近有多少相关对象 | 按主体、目标、组织关系或空间建立派生索引 | 多放远处对象或无关任命后，本地访问是否增加。写入维护、停用、删除与读档后重建也计入成本 |
| 同一描述反复读取，只有少量内容变化 | 对稳定版本按需编成窄视图，给合适的读者复用 | 各项写入是否触发相应失效，旧发布是否仍可用。玩家或 NPC 首次观察仍按各自能获知的内容处理 |
| 计算相对独立，结果晚到仍有用 | 比较直接处理、成批处理和后台提案 | 输入准备、复制、工作线程空等及采用复核。候选变旧时原行动能否继续 |
| 结果影响当场的下一步 | 按实际交互对象和时间范围裁决，试将候选判定并行 | 谁会竞争最后一份资源或站位。较早的事件变更时，后续行为和即时反馈是否仍解释得通 |

当前的 `StationSpace` 按身体位置与已受理目的地提供邻近候选，设施预约由相关作业核对。`Knowledge` 和战斗都使用身体空间查询，观察还可能读取尸体。改一个索引前可按读者分别核候选范围、时间和过滤条件。站位、地图变更及跨角色状态的实际先后可以从[架构](architecture.md)追到源码。

当前 `DeferredWork` 以未来到期和可服务项组织工作，普通观察另有按主体的到期索引。扩展时可观察合并前后的等待年龄、跨域完成量、已取消任务的回收，以及持久凭证如何恢复。这些结构也有服务成本，多分线程或加大分片之后仍可用相同工作量比较。

## 怎样说明访问成本

较大的改动可以在原主题或 review 里简要记录触发、读写范围、和现有调用相乘的规模，以及最能区分方案的反例。小功能适合用与影响相称的验证。例如检查调度时可比较一个晚来的急事和一个已经等了很久的普通事项，有缓存时可检查撤权、死亡、移动、重新加载或发布过的旧视图。原实现的职责和执行设备可以随真实依赖重划。

## 怎样验证而不追逐人数极限

局部成本可用受控输入或访问计数定位。玩家体验更适合同场景、同成熟度、同图形设置和倍率的 Release 对照。关心自治时，可以同时记录真实完成、行动类型、待办数量、最老等待和输入响应。短窗之后接一段相同世界能帮助区分开局集中到期和持续服务不足。改计时时可以另跑一次无插桩版本检查观测本身的开销。

### 可观察计数的最小闭环

| 疑点 | 可以记录的证据 |
|---|---|
| 每次选工作时又翻了多少表 | 新请求、合并、拒绝、未来和就绪项数，实际访问项和有效服务片 |
| 画面正常时，人物是否还在等 | 各类完整任务的完成量、全体待办和最老等待。仅统计已取出的工作会漏掉尚未获服务的主体 |
| 线程有活干时，世界为什么在等 | 从准备输入到收到候选的时间，从候选到采用的时间，弃用原因和数据复制量 |
| 速度上升后，活动是否变少 | 同输入的实际接触、交付、观察、移动及完成反馈。一起记录可用材料和活动参与人数 |
