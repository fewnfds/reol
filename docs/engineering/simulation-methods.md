# 模拟设计与实验方法

本页用于新增或评估相互影响的玩法规则，不规定每次改动都走一套研究流程。既有事实查对应领域正文，访问范围与计算接入分别归[复杂度](simulation-costs.md)和[执行方式](execution-batches.md)。外部来源、阅读深度与采用理由见[研究取舍](../../design/research/development-paradigms.md)。

## 先确定要产生什么体验

深度来自处境改变时仍有值得权衡的办法，不以属性、配方或隐藏变量的数量计。设计时从“玩家/NPC为什么在这里作出这个选择”倒推最小规则。例如护田、求学与补充灵气争用一个人的时间，比无消费者的二十项性格条更可能形成取舍；这只是分析例子，不授权新增玩法。

对本次不确定的部分说明：期望玩家能判断什么，哪些角色/物资/权限互相影响，影响经过哪些延迟，玩家通过什么行动改变结果。可以是一段话或一张小图，不要求另写spec。科学模型的现实预测准确度与游戏的体验目标不同；参考现实帮助找结构，是否保留细节取决于本项目要呈现的体验和代价。

将有关状态分为存量、流量和占用：粮食库存不是产粮速率，承诺配送不是已经入库，人力/灶台/教习时间也是容量。查看来源、转换、消耗、再生、在途及谁有使用权。平均产出大于消耗仍可能因为生产周期、步行、权限或同一人兼任而断供；初始储备也可能掩盖赤字。资源短缺不是语法错误，能否生存也不是唯一合法开局；区分定义错误、理论容量提醒与刻意的挑战配置。

沿关键反馈检查增强、抑制、阈值和延迟：优势是否无代价累积，失败后是否失去一切恢复办法，补偿是否让选择失去意义。稳定生活可以是有价值的成果；不把同构院落、稳定产出或偶尔闲暇直接诊断成无聊，也不为“涌现”强行制造冲突。需要研究的是玩家能否理解和影响下一步处境。

低美术成本优先保证一致的空间/动作语法、明确目标、阶段、进度和少量关键转折反馈。正常界面表达玩家可知的事实与角色明确表达的理由；私密目的、开发者评分与真实全局库存仍受原`SubjectView`边界约束。文学化描述可以增添风味，但不能反向成为模拟事实。

## 社会行动接入已有自治框架

现有`Knowledge → Livelihood/agency_selection → Decisions/host`区分本人所知、个人选择与真实执行；`Society`承接交互，`Institutions`承接职责、事项与份额。借鉴Versu的是“可复用情境提供可选行动，参加者自行判断”的编写方法，不新增统一Practice账本、通用逻辑求解器或另一套AI执行器。

社会情境按本次需要说明参与者角色、如何得知机会、可提出的行动、双方接受/拒绝/延期、进入共同过程的时机、退出与已发生后果。同一情境换参与人或由玩家扮演其中一方，仍用原操作和owner；若处境只涉及单人操作，不硬套多人协议。双人过程还要看双方机会的时间交集：暂忙后如何延期、有关变化怎样唤醒/退避，已进入共同过程的一方退出怎样通知伙伴，避免只按各自周期反复错峰。

- **能做、愿做、应做、承诺过分别判断。** 物理/能力/访问规则可硬拒绝，社会期望和个人偏好通常影响选择与后果；是否允许违约或违规属于具体规则，不能把道德规范一概编成能力限制，也不擅自增加偷盗等操作。
- **常驻职责不等于时时忙碌。** 看本人已知缺口、当前现场阶段、估计投入与替代机会。余量可用于评价已知期限，不能用全知库存、未公布截止时间或过度精确的未来预测评分。高余量也不保证接受任何请求，仍可能因资格、个人意愿、关系或其他承诺拒绝。
- **人格要有实际消费者。** 同一处境只改一个有关倾向或一条认识，预测选择/坚持/受阻应对如何改变；不要求每次都选出不同动作。测试到真正竞争的阈值附近；远离阈值的无差异不能证明人格无效。
- **经历与情绪从本人证据解释。** 若扩展情绪，先确定事件如何影响本人目的、本人怎样归因、有哪些应对动作，再决定需要哪些持久量。归因可能错误，不能直接读真实动机；有界经历不是完整事件溯源账本，也不能作为已淘汰义务的唯一事实。
- **信息沿真实渠道流动。** 打听/转介等尚未实现的候选应复用认识来源、时刻和跳数；不能在拒绝时顺手扫World替人找最优老师。相关性筛选同样只读双方允许得知的线索，控制联系人/话题集合、通知扇出与记忆维护成本。

生动性既看长期一致，也看处境改变后的变通。稳定履职、拒绝不合理请求、暂时等待都可以合理；把某个结果当bug前先分开资格、意愿、可知性、可到达性、现场占用和调度欠办。测操作通路的夹具明确给出可满足的动机/条件，测自主选择的夹具才保留目标冲突；不为让旧断言变绿而提高玩家指令到无限优先级。

## 用不同证据回答不同问题

借鉴ODD的目的/状态/过程顺序/感知/观察与POM的多种行为模式校核，不采用完整学术模板。只展开本次有风险的部分，不能要求普通实例或改字附全套实验。

| 问题 | 适用证据 | 不能由此推断 |
|---|---|---|
| 规则是否正确 | 原owner短反例：来源与消耗、争用、中断、恢复；必要时以慢扫描对拍派生查询 | 好玩、规模达标、任意长局稳定 |
| 这条规则是否影响行为 | 在同一受控处境只改变一个相关条件，比较选择、采用、实际执行及原因；必要时消融一个机制 | 一个无差异样本证明机制永远无用；全员必须接受请求 |
| 共同体能否持续运转 | 现有正常开局跨相关生产周期，看库存谷底/净变化、实际完成、各院与个人尾部、受阻后的恢复 | 每个人都公平、全年平衡、陌生人冷启动容量达标 |
| 玩家能否理解与干预 | 实际试玩中先让玩家预测、行动、解释结果，再核实际因果；区分困惑与有意犹豫 | 自动检查通过就有活人感；必须永远显示私密数字 |

先预测哪种变化会支持或推翻模型，保留失败模式，避免看到结果再倒写目标。规则夹具可显式设初态；声称正常百人自治时则不能暗中补物、强制派工或注入认识。比较个体行为时看合法、可知、可用的机会集合；动作次数受工时/批产量影响，不能直接当工时占比、效率或“聪明程度”。

同因果对照先固定开局/存档、数据签名、种子、步进/worker方式与刺激时刻，记录唯一改变的条件。随机或异步影响结论时才做必要重复与多个种子，先用短小确定性机制检查定位；不能同时抹平性格和关闭信息后把差异归因于其中一项。相同seed也不保证不同调度策略的逐次随机调用一致；描述能复现的范围，不能默认逐帧轨迹相同。

现有`agency_boundaries_smoke.gd`已有有关倾向影响真实选择的短夹具（组合改变倾向，不等于隔离了每项的因果效应），`subject_view_smoke.gd`已有玩家视图隔离检查；新问题沿相关专题增加受控条件，不必扩成百人长测。当前`settlement_cycle_smoke.gd`固定青禾宗与中途恢复点，不提供任意开局/种子/消融或“不恢复直跑”CLI；下述分支/规模实验是按改动编写专题检查的方法，**不是现成通用实验开关**。访问计数和队内年龄仍随C01等实际施工接入，现有离线报告不能填补。

存读检查按合同选比较层：规范事实与守恒可精确对照，派生队列/后台未完提案按原恢复合同重建，不要求原线程完成顺序、计时器诊断或动作轨迹逐位一致。需要时从同一快照做直跑与恢复分支，比较受影响状态/结果；不默认开启每步存读的Heavy Mode。

## 成本与作者能力也参与取舍

行为模式正确而每人每候选全扫世界，仍不是合格接入。继续沿[访问成本示例](simulation-costs.md#怎样说明访问成本)核触发、读集合、写维护、输入与采用；“有事件/后台”不免查。必要的全员连续热批可以保留，事件定向也要看实际订阅者数量，批量同时到期也有突发代价。

声称局部化时固定相关人/目标/结果量，只扩大不相关人口、任命、状态或未来事务，查看实际访问数及写维护。树/堆允许合理的对数增长，不强求所有查询计数恒为0增量；索引还需在同批准入、移动、取消/退役、读档后与正确参考结果一致。队列要同时看需求、完成、积压与仍未出队/未准入的年龄；只测已经服务的人会隐藏饥饿。相关测量随C01等实际施工加入原owner，不预建通用探针平台。

内容作者继续使用原Resource定义、`compile/errors/values`及开局独立候选装配。新内容区分缺少原语与缺少实例：同机制先改定义，特殊机制才在正确领域增加可复用能力和专用脚本。核跨引用、错误组合与真实执行一例；不要另写Python解析器猜`.tres`业务语义。现有编译/装配及坏开局反例已覆盖多类引用/空间错误，不将其误写为“只有路径检查”。两级验证不能互替：`Opening.compile`通过不保证实际作业位/路线可用，改开局空间仍需`Opening.assemble(candidate, spec)`沿原空间/领域检查。容量算术只在假设适用时提示上界，不能静态证明自治、无死锁或学习必达；尚未使用的新编辑器/MCP须先说明现有Inspector/CLI解决不了什么。

## 现有宗门日志的离线分窗

`tools/settlement_report.py`只读取`tests/settlement_cycle_smoke.gd`已输出的`NORMAL_SETTLEMENT`，逐相邻样本计算真实模拟时间、累计完成/拒绝/生成量的差值、库存变化、各院完成和已采样低点。命令归[usage](tooling/usage.md#宗门周期日志分析)。不重新启动游戏、不新增运行期轮询、不重建第二份世界。

`actions/refusals`来自`activity_results`的完成/非完成结果，**不包含所有规划候选的落选原因**；调查“为什么没人求学”还要核受控决策输出。各院`resident_actions_delta`和生命截面按编制居民归组，`spatial_items_delta`按对象当前坐标就近归院，含行人随身物；二者不能拼成院落封闭权属账本。顶层库存总量也不提供消费/转移路径，守恒仍由原运行审计证明。

第一条快照是基点，不能默认从0开始；部分运行、计数回退、缺字段、终止错误和没有进程退出码分别处理。报告保留原始终止标记，不把“解析成功”当烟测通过；现有日志没有逐人完整轨迹、逐项队列年龄或帧样本，不能生成公平性、等待p99或FPS结论。`*_usec`是已记工作量，可能嵌套/跨线程，不能相加成CPU利用率或当GUI帧时。历史日志分析只验证分析工具和当时记录，不重新验收当前游戏。

工具支持当前固定的粮/餐/水字段及11项累计metrics；新增诊断字段先区分累计计数与当前量，再更新消费者，不能把队列当前年龄相减当完成量。终止行的`final`字典不解析，最后一条打印快照也可能早于实际停止；中途恢复窗口的墙钟包含恢复检查成本，不能将其比率当正常GUI世界流速。不同进程分别分析，保各自来源与覆盖区间，不自动拼接续跑或输出加速百分比。
