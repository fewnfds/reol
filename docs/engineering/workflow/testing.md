# 测试选择与成本

测试保护现行行为，不以数量证明完成度。运行结果对应受检代码、平台和实际路径；命令入口在[tests](../../../tests/README.md)，结果在[BASELINE](../../status/baseline.md)，CI查询纪律见[code-review](code-review.md)。

## 按风险选择

| 改动 | 首选验证 | 不能据此宣称 |
|---|---|---|
| 文档 | 结构、链接、差异 | 游戏已运行 |
| Python工具 | 对应Python owner | 全游戏回归通过 |
| 测试运行器 | Python参数/错误门禁，Godot列举、选组、无效名称退出及报告smoke | 全部规则通过 |
| 领域规则/状态 | 直接owner与受影响联合测试；游戏包最终完整check或同SHA CI一次 | 用少数定向组替代完整回归 |
| 实际存读/场景 | 支持范围、失败原子性、在途和必要的进程停开 | 无头证明画面/手感 |
| 渲染/GPU/性能 | 真实渲染器及声明硬件/负载的有界测量 | 普通CI证明RTX3060性能 |

同一包不默认重复本机与CI全套。计时、超时诊断先选疑似热点，不再跑几十分钟只为数PASS。保持断言、SCRIPT ERROR/ERROR、退出码和超时门禁；超时未完成是待定位，不能算成功。

长验证有独立工作就继续做，只剩测试就等待。完成事件优先；session续等在一次工具编排内部持有同一handle，模型不每60秒重新调用、不用delay/sleep循环查询、不为无变化发进度。完成/失败/超时/真实异常或用户主动询问时才处理；具体接续见[等待策略](code-review.md#采用的流程)。

## 永久测试准入

新增或扩展前说明：保护哪条当前契约、失败伤害什么、主要owner在哪里、什么可观察反例会使它失败、fixture及运行成本多少。没有必要新增永久测试是正常结论。

- 同一规则一个主要owner；跨层只保留接口/联合行为的证据，不每层再装全世界重复证明全部规则。
- 使用最小合法fixture；完整Main用于真实集成出口，纯规则不为方便加载Main或所有内容。可变fixture不可跨组共享，避免污染。
- 逐格/逐通道对照可以保留，错误标签与详细诊断尽量失败时才生成；合并断言不等于减少实际运算。
- 大规模穷举、兼容退役调查及压力测试按需运行，不自动并入每次提交。现行契约和来源消失后可有依据合并/退役测试，不能删断言凑绿。
- 优化先看每组耗时，再区分装配、模拟推进、快照/存读、参考计算和断言成本；先改最大项并同负载复测，不以断言数量推断热点。

## 选择与耗时证据

`test --list-suites`只列已注册组；`test --suite test_<完整名称>`可重复，按注册表排序执行并去重。未知名称/参数和报告打开失败必须非零退出。默认`check`运行完整注册表，不接受`--suite`。

`test`和`check`可用`--shard INDEX/TOTAL`按排序后的完整注册表取互不重叠的分片（从1计数，注册表下标对TOTAL取模）。它不能和`--suite`混用；单片通过只证明该片。`--list-suites --shard INDEX/TOTAL`可核选中范围。CI使用12个独立runner执行各片，避免共享可变fixture、`user://`和时钟；实际同时运行数受仓库配额及排队影响。本机不要为模拟CI同时启动多套引擎。

CI只有各worker的导入、日志错误、超时及退出码门禁均通过后，才由`tools/check_test_reports.py DIRECTORY --shards 12`核对各片相同的完整注册表、确定分片、逐组开始/完成、断言总数与完整终态。缺片、重复组、遗漏或失败均不能通过。覆盖报告不能代替worker退出码；手动本机分片验证也须同时保留每片包装器的成功结果。workflow的`GODOT_TEST_SHARDS`同时传给执行器和覆盖检查，改变分片数时须同步matrix中的片号。

每组输出耗时与断言增量，终态列最慢十组。Python入口默认生成唯一的`logs/*-timings-*.jsonl`，也可用`--timing-report PATH`指定。JSONL逐组开始/完成即flush；超时后一次读取已完成记录及最后开始的组，不轮询文件。计时是墙钟时间，包含fixture与断言，不是函数级性能分析。

报告中的`assertion_failures`只记录断言失败；脚本运行错误可能中止单个方法，最终仍须核Python包装器的日志错误门禁与退出码。缺`run_finished`不能算整轮完成；选组报告也不能算全套通过。

墙钟预算循环可能在每次续算时记断言，跨次调用数不一定相等。前后数量差异须定位到实际路径；完整覆盖看注册表、必达结果和错误门禁，不能把循环次数误当固定案例数，也不能用这一点掩盖漏跑分支。

## GitHub与本机边界

当前workflow使用标准`ubuntu-24.04`托管runner，12片运行Godot导入与headless CPU回归，Python工具测试在第1片运行，上传独立输出及计时文件，最后聚合完整覆盖。GPU测试无RenderingDevice时验证CPU回退。自动测试适合确定性规则、所有权、存读和错误退出；总工作量与各片耗时均由逐组证据定位。

普通runner不提供本项目所需显卡保证，无法验收真实GPU加速、画面、输入手感或目标PC帧时。GPU证据在本机真实显卡取得；需要时可单独记录Windows独立包和硬件性能。软件渲染不是目标显卡替代品。GitHub另有GPU larger runner，但不是当前配置；不为普通回归新增付费或自托管基础设施。

CI的CPU超时不能归因于缺显卡。要拆分并行或分层，先量出热点并说明完整覆盖；不能静默跳过慢组或只增加超时上限。
