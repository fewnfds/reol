# 开发循环

通用开发循环在[项目约定](../../../AGENTS.md)。本页用于选择具体的验证和测量方法。

按本次风险选择相关领域技能，名称/描述用于发现，正文和reference按需读，不设每轮全读清单。架构页描述现状，不能自动替代Resource隔离、输入焦点、存档失败等专门检查；技能覆盖与维护见[工具配置](../tooling/setup.md#skills怎样维护)。

新增相互影响的经济/社会/生态规则时，先把体验目标连到具体选择、可见后果和能推翻设计的证据，按需使用[模拟设计与实验方法](../simulation-methods.md)。规则短检查、因果对照、正常周期、实际试玩与容量测量回答不同问题；不以“都动了/没饿死/帧率正常”互相代替。普通bug、实例微调或纯性能整改不自动增加设计报告与长窗实验。

## 写前设计与代码review

访问规模是功能设计的一部分，不等到卡顿后才检查。新增领域或改变访问范围、调用次数/时机时（包括在新循环或高频路径复用既有查询/视图），在原主题说明或review中简要回答[成本说明](../simulation-costs.md#怎样说明访问成本)，据此选择已有局部查询、活跃集、到期服务或全员顺序批；明显的全局放大先修正设计，不以“功能已通过”留待返工。至少写出实际调用链、每次访问的集合及上层倍率、选择的做法与依据；只写“已考虑性能”不能完成审查。

小而有界的查表、必要的全员批和冷路径全量校验可以保留；边界须由规则、实际数据范围或负载证据支持，“目前样本少”不能代替规模判断。全局容量上限也不等于小常数：任命/服务等仍随人口、设施或历史增长，不能据此豁免高频全表读。成本包含结果项数，索引不能消除本就需要的全量输出。不要为消除所有线性操作预建万能索引。

review不能止于改动函数：向上查到触发/倍率，向下查到实际容器，核查helper是否暗含全表遍历、`values/keys`物化、深浅拷贝（`duplicate`、`State.copy`）、排序或大视图拼装，以及输出本身需要多少项。已有接口也需核实，不因其名字是“个人查询”“局部查询”就认为成本局部。再看写入/通知/缓存失效、批出口集中唤醒、输入准备与提交、显示/诊断消费，以及拒入/退让造成的重试是否将省下的工作加回别处；这些操作不是语法禁用表。

按风险选择能推翻设计判断的短反例：只增加无关人物/服务时单次相关查询是否变贵；索引在同批准入、取消或读档后是否仍返回完整结果；持续需求下完成量与等待是否合理。只做与本次改变有关的项，不为单个Resource实例、文案或普通局部UI改动另建报告或性能矩阵。代码与观测冲突时修实现或更正结论，不能靠放宽阈值、降低活动或丢结果取得通过。

## 性能回归

目的是回答“本次功能增加多少成本、还能否接受”，不是每次重测精确人口极限。局部查询优先用相关访问计数/规模反例；涉及高频调度、全员批、渲染或短检查不足以判断端到端余量时，再用真实性能短窗，不因改了一个查询就自动重跑历史矩阵。

验证由写前/review确定的增长维度：算法归因按需做无关规模对照，例如保持本人数据不变、只增加他人任命；帧时与产品余量再用同条件真实窗口。计时与有效活动/等待一起核，不能仅凭帧率或预算截断后的步均判断扩展能力。下面的历史人数样本不能代替设施、房间格、状态或队列规模等相关维度的检查。

从[已接受历史样本](../../status/performance.json)的同人数、同场景开始；每个倍率最多3个真实窗口，正常只测1次，有异常才同负载复核或粗略降档。只测与改动有关的倍率，不强制每个改动覆盖五档。时长沿历史样本，避免把不同时段的工作量直接当纯算法差异。

同时看实际世界流速、帧时、步均、主线程/GPU耗时与有效活动量。用同条件成本差和可玩余量权衡收益；工具的退化提示是审查线索，不是自动否决规则。负载或硬件/窗口不同就标注不可直接比较，不输出伪精确百分比。新结果不自动覆盖已接受基线。

## 验证与等待

检查组成见[tests](../../../tests/README.md)，命令见[usage](../tooling/usage.md)。规则短检查约十秒；Python工具用对应短检查。旧CI和全玩法长回归已退役。

真实图形测量串行，避免互相争用设备；运行期间做独立工作，只剩等待就等待同一进程完成。仅有结果、错误或需要用户介入时再汇报测量进展。
