# 当前开发与验证方式

按当前任务完成实现、检查相关风险、审阅差异并提交。验证服务实际问题，不按通过数量评价进展。

旧GitHub CI、长回归套件、12片聚合与自动模型审查已退役；目前没有远端测试门禁。历史说明见[流程记录](../../archive/qa/20261111_workflow_retirement.md)。

## 选择最短的有效检查

- `python tools/godot.py test`只跑结算续算、CPU批一致、库存守恒、忙碌输入与呈现延后；默认进程上限15秒。`--suite NAME`选择相关项，语法见[usage](../tooling/usage.md)。
- 新class、资源或路径改变后按需import。规则、存读与场景改动核对本次受影响的具体流程；文档只查差异和链接。
- `python tools/check_structure.py --audit-code`可辅助定位路径、UID和层依赖疑点；动态调用需要人工判断。`tests/tool_smoke.py`用于启动器改动。

不要求每个任务新增测试、QA或自动审查，也不恢复与本次问题无关的全量矩阵。失败和未测范围如实记录，短smoke不能证明所有玩法或规模性能。

## 性能与等待

性能任务先找主要成本，再用相同人数、命令、构建和短窗口比较端到端结果；通常20–30秒已能回答局部问题，确有需要再延长。headless用于CPU/工具诊断，画面性能用实际渲染器。命令见[实际性能](../tooling/usage.md#实际性能)。

验证运行时继续独立工作；只剩等待就等待同一进程完成，不循环查日志或报告无变化。停点写HANDOFF，有效结果写BASELINE，长实验过程归档。
