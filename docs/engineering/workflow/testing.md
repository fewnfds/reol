# 当前开发与验证方式

类型：当前方法。2026-11-11起，旧GitHub CI、260组回归、12片执行/聚合与每包自动模型审查已退役；不再设置全量check、完整迁移矩阵或旧绿色结果的提交门禁。恢复或改变策略需要当前用户方向，不由旧skill/报告自动决定。

开发围绕实际性能：从普通Demo选主要成本，改变数据/算法/执行结构，用相同人数、命令和短窗口比较实际流速、帧时和主线程工作。一般用20–30秒样本；负载、长局或GPU专项只按当前问题追加，不自动成为永久矩阵。

## 必要的短检查

`python tools/godot.py test`只跑结算续算、CPU批一致、库存守恒三个最小smoke，没有完整Main、全内容库或长时间世界推进。默认进程上限15秒；`--suite NAME`选相关项，`--list-suites`列范围。参数语法以[usage](../tooling/usage.md)和工具帮助为准。

新检出、新class或资源不可见时按需单独import，不在每次test前重复导入。`tests/tool_smoke.py`只在启动器改变时有用。规则、存读、场景按本次会影响的具体路径检查；文档看差异和链接，不启动引擎。

测试范围由实际风险决定，不要求每包新增用例、QA或自动review。错误/超时如实处理，smoke不能证明全部规则或规模性能。

## 测量与等待

普通人口和开局采样命令在[usage](../tooling/usage.md#实际性能)。JSON/JSONL保留实际代码与负载；headless只用于CPU/工具诊断，画面性能使用真实渲染器。worker活动或独立kernel提速不代表整个游戏加速。

有独立工作就继续做；只剩有界验证时等待同一进程，不由模型定时读日志/查CI、报百分比或派等待代理。当前停点只写HANDOFF，有效数值只写BASELINE；旧结果归档，不因推送新建等待任务。
