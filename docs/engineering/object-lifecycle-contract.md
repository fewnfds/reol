# 实物生命周期与共同动作

本页解释当前代码合同，不记录进度或性能成绩。结果看[接续](../status/handoff.md)和 QA；查询语义见[对象查询](object-query-contract.md)。

## 原状态与适用范围

- `RegionalSimulation.object_lifecycle` 是共同事务入口，`SimArtifacts.objects` 继续持有独特器物实例。新物通过定义的 `physical` 能力和 `placement.footprint` 显式接入，不能按名称增分支；旧储热、引物、灵源、魂器等特殊对象仍由原域执行，不自动获得新的移除权限。
- `SimGroundPlacements.slots` 仅持有地面位置、尺寸、原引用和是否在地面；不保存数量、温度、身体或第二份器物。它的格索引、16×16 桶和引用索引可重建。地面坐标是同一张全局地图，账务 `region` 不是另一层空间。
- 材料数量始终在原 `VillageSimulation.inventory`。一堆对应一个 `ground:<command>` 容器和一个物品类型，数量为零后不再是活跃地面实体。为保留旧转移回执、重试和引用，空容器及旧位置元数据暂留；ID 不复用。
- 地面器物占地以左上角和正整数尺寸描述，可为偶数宽高；身体仍遵循自身原有的中心占地合同。多格都指向同一对象，不复制物品。地面堆互斥不等于人、植物、区域和全部实体都互斥。

`ground.query_cell(cell)`只读原逐格占用索引，返回与矩形查询相同的ids/complete/scope/revision语义，合法单格查询`work_used=1`；无占地为空，越界明确拒绝。它覆盖多格实物的任一占地格，不再扫描16²桶。材料落地/合并复用此接口，仍执行原can_place及库存/回执事务；批量世界装配不因此获得绕过成本/来源历史的权限。

## 同步事务入口

`execute(request)` 是开发/权威接口，不代表玩家、NPC 或未来 AI 已获得执行权限。玩家距离、观察、所有权和同意需由各自交互适配器审查，不能将此接口直接当自由文本工具暴露。

所有请求包含唯一 `command`，使用以下 `op`：

| 操作 | 字段 |
|---|---|
| `spawn` | `id`、`definition`、`to`；只允许显式接入的普通实物定义 |
| `move` | `id`、`from`、`to`；核对原物当前源位置 |
| `remove` | `id`、`from`；只终止本域创建且没有旧域在途/历史依赖的实物 |
| `stock_transfer` | `from`、`to`、`item`、正整数 `amount`；原库存预检、扣加和操作回执一次提交 |

`from` 为 `{region,container}`；`to` 为同一结构或 `{region,cell:[x,y]}`。同一命令与内容重试返回原结果，换内容返回冲突。失败不留下新器物、数量或半个位置登记。当前材料和独特物转移限定同一区域记录，跨账本明确拒绝；跨 64 格区块不是跨账本。

同类型、没有独特实例状态的可处分材料可以拆开或合堆；异类不能混堆，保管限制和预约仍由原账本决定，不按总数绕过。独特物保留 ID，不因外形相同自动合并。

提交后 `committed` 发出冻结的通知，包含命令、共同时刻、原结果、旧/新地面占格和本域地面 revision。调用者不能修改通知回写状态。这个 revision只覆盖本域位置；`SimWorldSpace`组合身体、原物和结构的格投影变化，具体范围见[实时空间合同](object-query-contract.md#实时局部空间)。显式集合快照仍为历史快照。

## 最小耗时动作

`schedule(request, actor, duration_ms)` 接 `move` 与 `stock_transfer`。它暂占原身体的行动通道，记录原自主权、源位置请求、起止时刻；材料在原账本预约，目标多格按全部占格互斥。没有第二个世界时钟或逐静态物品 tick。

共同世界在 deadline 结算：重新核对身体、源位置、目的地、可用数量与预约，通过后提交一次。取消或失败释放预约和行动通道，不提前产生实物效果。进行中、完成、失败和取消均保存；重复完成不重复支付。调度预算用尽仍保留共同 `target_ms`，内部在截止边界结算不因还有未来积压而错当失败。

动作接口同样是权威基础，不包含寻路接近、玩家输入、社交接受、任务规划或任意高级工艺。耗时动作不把常规 NPC 变成了玩家无条件操控的执行器。

普通物品面板已接受管 `physical` 实物的取起与脚边放置，调用 `schedule(request, actor, duration_ms, true)`；定义提供耗时。第四参要求原动作保存可选 `contact:true`，启动和截止均检查同区域、地面到本人容器（或反向）、交互半径、同高及无遮挡；旧权威调用缺省不附加此约束。读取候选接受原先不带contact的动作及严格布尔true的新动作，不改变旧fixture。过程中失去接触会失败而不是穿墙完成；手动移动/停止释放原动作，远行不能并行占用身体。

该入口不授予他人/场所物品的处分权，也不提供材料选堆、任意NPC命令或所有对象的共同探查。当前法律产权尚未实现，地面可取不代表已证明“无主”。新建实物可由 `--world-editor` 的F8开发编辑按定义放置/移除，经同一生命周期和普通存档进入游戏；生成不扣材料，只是开发权限，不是玩家制造技能。

## 与施工共用的最小行动合同

[SimActionContract](../../scripts/sim/action_contract.gd)属于单位行动与交互框架，由耗时取放和`SimConstruction`两处实际调用。共同部分是原身体存活与action/motion控制、原活动占用冲突、启动后暂停原自主权、执行时复核以及释放原预约/恢复原自主权。没有新增任务状态库、计划器、时间或保存结构。

- `can_begin/can_act/can_continue`核对原状态；两者均不能绕过另一个过程占用。取放按原动作位置和可选contact复核，施工行路沿原路线检查，取料/作业阶段要求仍处于原目的位置；条件改变在下一有效边界中断。
- `occupy/release`操作原身体与原库存，领域在预约和路线预检成功后才登记。中断施工仍保留原工时、已取材料及真实落点，未完成取放仍保留原物源位置。
- `RegionalSimulation.describe_actor_action(actor)`提供这两个原过程的共同只读投影：原domain/id/意图、领域phase、起止时刻、remaining_ms、status和目标id。普通实物面板读此deadline；领域仍自行解释施工/取放阶段，未接领域返回`no_supported_action`，不生成假的通用空闲任务。
- 原owner完成效果、移除活跃成员并释放占用后，`RegionalSimulation.action_finished`发出冻结的终态投影，status为`completed/failed/cancelled`。这是当前世界瞬时通知，不是持久事件账；取放完整状态仍在原actions，施工结果仍在原项目/库存与line中。

启动、接近、材料预约、阶段推进、领域效果和恢复校验继续沿原执行器；本阶段未把所有旧动作、观察权限、跨账本搬运或全局绕路迁入此合同。两者的原存档schema不变，恢复后重新读取原过程。

## 存读与容量

当前收尾工作树使用根格式52、区域43、生命周期域1；普通旧根及旧区域明确拒绝，不再把根50/区域41的历史转换称为当前入口。加载独立重建候选，交叉核对位置、占格、实例、原库存回执和预约，全部成功才替换活世界；失败不能部分发布。兼容范围见[兼容性](compatibility.md)。

生成和材料转移回执使用固定的紧凑数组编码，重复请求/结果由 `object_receipts.gd` 临时重建；实物搬运和终止回执保留明确记录。材料请求格子与实际合并目标、库存操作和预约均保留，已有完整字典回执仍可读，未知新增字段沿完整记录保存。解码前校验数量和坐标，再规范整数；不减少原物、命令去重、成本或交叉验证。查询方通过 `_receipt()` 读取，不依赖内部布局；恢复输入不共享可变数组。

历史位置上限 524288，成功回执/动作历史各有有限上限；到限明确拒绝，不丢历史来继续写。它们是可观测容量边界，尚无长期历史压缩或安全回收。附近候选结合地面索引、有限旧物列表和按容器分组的派生 ID；容器组仍有预算遍历，不能据静态密度宣称大量动态 NPC 已获支持。

`diagnostics()` 只供开发，显示原身份数、位置活跃/历史数量、动作与回执量、共同时间和积压。玩家视图继续走观察和迷雾过滤。自然资源记录仍不是完整植物实体；普通来源变更与新冷热/五行响应的接线及限制见[世界环境合同](world-environment-contract.md)。

建筑家具的操作位、储藏回执、工作台与损毁沿[建筑合同](construction-contract.md)接入；内容仍在原库存，领域效果不迁到第二套执行器。
