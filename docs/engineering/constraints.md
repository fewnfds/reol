# 基础边界

类型：稳定约束。这里维护跨任务仍成立、改变后会影响产品方向或数据安全的边界；用户可以明确修改。当前性能目标、任务步骤和实现参数分别查[主计划](../plans/foundation-priorities.md)、[HANDOFF](../status/handoff.md)与代码。

## 产品与技术范围

- GDScript、单机、2D正交俯视、正方形格；当前先平面地块。Godot使用项目已采用的稳定版，实际版本只在[BASELINE](../status/baseline.md)记录。引入C#、联机/账号、运行时模型或付费依赖需有对应用户授权；无LLM也可玩。
- 目标PC为16GB整机RAM、单张RTX3060级显卡；允许CPU多核、GPU计算和合理缓存。开发机不替代目标机，模块估算也不替代整机预算。当前人数/帧率出口属于主计划。
- 已确认的游戏规则唯一在[design/rules](../../design/rules/README.md)。详细机制、研究示例、历史样本不能自行升级成产品限制。

## 模拟完整性

- 身体、位置、实物、数量、账本、知识和共同时间各有一个事实来源。派生索引、候选结果与视图不成为第二份世界；定义与实例分离。
- 逻辑时刻和明确因果决定生效顺序，CPU/GPU完成快慢不决定游戏先后。算不过来可以主动降速，已受理时间与后果须继续处理；不能静默丢弃、重复提交或冻结远区。
- 玩家/NPC行为沿相同规则；客观事实、个人所知和开发诊断分开。普通查询与画面不能凭全知索引生成角色认识。
- 保存必要的不可重建事实与在途状态；加载先构造独立候选，失败不部分替换活世界、不改原档。只维护一套当前运行模型，旧版支持范围见[兼容接口](compatibility.md)。

## 工作区与外部操作

- 保护用户工作、原始fixture/存档和明确隔离的分支/stash；不强推、不擅自清理它们。凭据、本机配置、缓存、日志和构建产物不入库。新依赖核对用途、许可与兼容；超过50MB的新入库资源先征得用户同意。
- 不因项目维护改全局模型、权限、账号或无关连接器；不手改第三方addon。实时编辑器连接使用官方认证方式并核对项目。
- 测量和结论须对应实际代码、负载与路径。未测、失败或未达标如实标明。当前验证强度和CI状态只由[开发循环](workflow/testing.md)定义，技能和旧报告不能另设门禁。

这些约束限制结果和授权边界，不冻结class、目录、数据布局、调度器或算法；常规技术选择在当前授权内推进。
