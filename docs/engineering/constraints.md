# 基础边界

这里只保留长期有效的产品方向与数据正确性边界。最新用户决定优先；实现、目录、算法和工作方法可以重构，不因旧代码或测试冻结。

## 产品与技术范围

- 单机、固定斜俯视的纯2D显示、正方形逻辑地块，当前先平面世界。目标PC为16GB RAM、RTX3060级显卡。CPU多核、GPU与合理缓存均可使用。
- GDScript 是当前主要实现。实现语言、引擎扩展、模拟内核、调度和数据布局按实际性能与维护成本选择。
- 素材制作采用二维精灵/图集，不引入运行时三维场景或建模流程。当前不做整幅画面的透视形变；斜俯视由二维素材与前后遮挡表现，不改变模拟坐标。
- 玩法已定部分查[游戏规则](../../design/rules/README.md)，未定内容仍可讨论。联机、账号、运行时模型或付费依赖属于产品范围变化，由用户决定；无LLM也可玩。

## 模拟完整性

- 每项世界事实有明确的权威版本。独立记录可以并行推进，相互影响的变更按实际依赖协调。定义、实例和可重建视图分开，玩家与 NPC 使用相同规则。
- 已确定的直接因果与效果先后成立，资源转移和动作后果不能丢失、重复或被陈旧结果覆盖。次要过程可按领域语义近似或有界延后，不要求全局长期同未来；取舍见[运行与精度](simulation-pacing.md#世界事实与计算精度)。
- 客观世界、个人所知与开发诊断分开；画面和普通查询不补造角色认识。
- 加载先验证独立候选，成功后替换；失败保留活会话和原档。支持格式查[compatibility](compatibility.md)，不维持第二套旧世界。

## 工作区与外部操作

- 保护用户改动、凭据、当前有效存档和明确保留的分支/stash；不强推。开发存档支持与清理见[兼容政策](compatibility.md)。缓存、日志、本机配置和构建产物不入库。
- 第三方组件保留来源与许可，不在日常重构中手改；新增依赖核对许可和兼容性，超过50MB的新资源先征得用户同意。
- 如实报告测量负载、失败和未验证范围；实际开发与验证强度只查[开发循环](workflow/testing.md)。
