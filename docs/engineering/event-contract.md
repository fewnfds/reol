# 离散事件执行合同

`SimEventQueue` 是共同结算之上的通用离散工作队列；`SimWorldEvents` 登记可信领域规则。连续过程、命令受理、Godot signal 和玩家消息仍保留各自责任。资料与取舍见[研究](../../design/research/simulation_events.md)，阶段顺序见[结算合同](settlement-contract.md)。

## 所有权与顺序

- `GameClock` 与 `RegionalSimulation` 保留唯一整数毫秒；队列的 `clock_ms` 是已调度边界的检查点，不是第二个独立时钟。
- 队列只保存请求、下一到期、状态、成功次数和终态原因。规则代码持有真实效果，库存/身体/植物等事实不在队列里复制。
- `SimWorldSettlement` 在 messages 后、transport 前执行 events。旧区间和现有过程先完成；事件不能回头改变已结算区间。
- 到期按 `(next_ms, operation_id)` 排序；预算不足保留队列和内核游标，相同瞬间恢复不重放前项。性能与渲染帧数不参与排序。
- handler 不能递归派发；其中新建的请求必须晚于当前派发时刻，通知至早在下一毫秒唤醒。原步骤的同步 signal 不成为无限事件链。

## 请求与效果

可信代码用 `register_rule` 登记规则 ID、载荷校验、条件和效果；存档只含 ID 与 JSON 数据，不能指定脚本路径或 Callable。相同 operation ID 和完全相同请求可重试；不同请求复用 ID 被拒绝。

| 状态/结果 | 合同 |
|---|---|
| pending | 到期后重查原领域条件 |
| READY / WAIT / INVALID | 条件满足、等待相关变化、目标/条件已无效；WAIT 不产生效果 |
| waiting | 从到期堆移除，保留明确期限；仅精确 topic 通知或期限唤醒 |
| APPLIED / RETRY | 一次效果已提交，或明确未来重试；RETRY 不增加成功次数 |
| completed / cancelled / invalid / expired / failed | 保留终态回执，不再次施加效果；取消不撤销过去已发生的效果 |

周期请求复用一个持久记录，`occurrence` 区分成功次数，不为每个周期无限追加队列历史。原领域如需跨库存/身体提交，应先预检再一次提交；队列不提供全世界事务回滚。业务拒绝应明确返回 INVALID/WAIT，不能借异常或 assert 实现控制流。

`SimParticipationIndex` 维护可重建的到期堆；精确 topic 表只索引相关等待者。历史回执和实际在途依赖不能为省内存随意删除；若未来需要压缩，必须先确定仍可能重试的来源和保留边界。

## 当前消费者

运输路线周期评估的下一到期完全归队列，`routes` 不再保存 `next_assessment`。效果仍调用原 `request_delivery`，保留库存报告、传信时延和实际运输分工；dispatch 仍归运输阶段。

植物觉醒由显式情境请求产生，等待成长等条件。原植物变化只通知它自己的 topic；满足后给同一身体建立主体与通信能力，不产生第二株植物或觉醒前记忆。生长、供水、年生寿命和环境响应仍由植物/环境原领域处理。

本阶段不包含任意脚本 DSL、故事导演、随机灾难内容库或全事件重放。今后天气、任务或工艺等领域可登记新的可信规则与真实通知源，沿同一顺序、预算、取消和存读合同接入。

## 存读边界

事件作为 `SimWorldSaveDomains` 的参与者保存。规则先由可信装配登记，独立候选验证请求/回执并重建索引；不执行 handler，不重新登记开局请求。全部领域和交叉引用通过后才安装，失败不改活世界。

当前根54/区域45/内容包3记录完整事件、植物和会话规则；旧根缺少这些因果事实，普通入口明确拒绝，不从当前磁盘补造。旧内容包仅在原清单下可独立解析，不因此成为当前运行模型可加载的世界。
