# 当前版本与历史退役

状态：2026-11-04用户已定工程方向；本页规定后续兼容边界，不表示现有历史分支已经清理。实际受检格式/提交见[BASELINE](../status/baseline.md)，代码现状见[ARCHITECTURE](architecture.md)。

## 一套当前实现

项目只维护一套当前世界运行模型、领域规则和写档格式，不长期并行维护“旧世界引擎/新世界引擎”、旧UI或每代数据解释器。新局与已有存档是不同世界实例，不是两款游戏；读入支持范围内的旧数据后，都进入当前运行模型。

仍需保留格式、生成器和内容的版本标识，用于校验、迁移和明确拒绝不支持的输入；不能仅修改版本标签便假装转换完成。不同世界的种子、布局、实例状态、已发生历史或合法内容快照可以不同，这种数据差异不等于维护多套旧代码。内容快照本身也须符合当前能解释的格式与规则。

默认只写当前格式。确有保存价值的旧进度，可临时提供范围明确的导入器；每次引入时列出接受的源版本/数据条件、转换结果、测试依据和退役节点。迁移内部可以分步骤，但不要求永久保留从最初版本到现在的完整链，更不为了测试样本不断扩展历史支持。

不支持的旧版、新于当前的格式、未知生成器或缺失必要事实，清楚返回不兼容原因；不静默开新局、不补造库存/经历、不用当前种子生成另一张图冒充原世界。不改变原档文件或活会话。备份及独立候选验证仍是当前版可靠性的要求。

## 按包退役

1. 核查调用者、真实存档、fixture和CI依赖，列出当前实际支持范围与拟删除范围；不要只凭schema数字推断某历史玩法仍可运行。
2. 将有价值的回归场景迁移为当前格式fixture，或按同一语义重新建立当前样本。保留来源/版本/转换方式，并验证关键实物、时间、在途过程和失败隔离；旧文件不原地改写。
3. 需要保留的进度先由经过验证的转换生成新文件。不能可靠转换的版本明确停止支持；不能以默认值抹掉无法证明的历史事实。用户存档不擅自清除。
4. 同包删除已退役的运行分支、旧入口、专用生成器/模板及无效主CI路径，更新支持清单和文档。历史源码与证据可由Git追溯；无需主分支永远承载全部旧资料或让主CI永远执行旧解释器。
5. 验证当前新局、当前存读/完整停开、仍承诺的导入及不支持格式的明确拒绝。退役产生新修改，按范围检查并核对相应SHA结果。

单一当前版本不要求删除Git历史、旧提交或用户工作。原历史证据不追改为“曾通过当前格式”，长期档案可按文档治理归档/精简。保留证据也不等于必须永远保留它依赖的运行代码。

## 当前实现的有限边界

当前开发分支的[SessionSaveSchema](../../scripts/persistence/session_save_schema.gd)只接受根`56`；根`55`返回`legacy_actions`，根`53`返回`legacy_events`，根`52`返回`legacy_buildings`，根`1–51/54`返回`legacy_environment`，未来或非法版本返回`unsupported_version`。根55没有当前搬运规则闭包/库存预约scope；不从磁盘补造历史，明确提示旧行动格式，原文件与活世界不变。更早的环境/建筑/事件格式也不自动迁入；验证证据见[BASELINE](../status/baseline.md)。

普通联合区域为`47`，`RegionalSimulation.restore`明确拒绝其他区域版本与旧热导入标志。当前内容包为`3`，绑定44份定义/开局，搬运参数随`local_actions`绑定；旧`1/2`版内容包可按原清单解析，但不足以装配当前世界，不从磁盘补历史能力。不要把低层旧版校验器或历史导入源码误写成旧存档已支持。

[WorldSessionSnapshot](../../scripts/runtime/world_session_snapshot.gd)在独立候选通过校验后才替换活世界；地图按档内生成描述重建。当前环境保存版本`5`、模型`composed_fields_v1`，保存背景及已受影响格的响应锚点、必要来源与采样；派生来源/块缓存从已验证原物重建，细节见[环境合同](world-environment-contract.md)。存在未完成共同时间/环境事务时不能当成已完成快照。历史各阶段的导入边界保留在[归档](https://github.com/fewnfds/reol/blob/8c3deaa972f932e999167b61ea6b166b928cfe5f/docs/archive/engineering-context-20261105/compatibility.md)，不能作为永久兼容承诺。
