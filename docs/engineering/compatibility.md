# 存档支持现状

当前仅支持`reol-world-7`开发布局：新增规范品质物品堆、人物穿戴位置及可选基础属性，派生热列不入档。原身体耐受/冷热伤害余数、个人事件、连续目的地/路线和战斗目的地保留。地块基底、装饰地被与人工地板独立保存，兼有植被清场等级、最后所见地表、单位视距与战斗接触；不读取之前的开发格式，不维护旧档迁移链。F5/F9默认使用`user://quicksave.reol`，不自动加载；关闭重开后可主动读取。用户已有旧档保留，但本版需新开局。

`World.state_owners()`是实际领域入口，各owner的`STATE_FIELDS`显式选择原状态，`persistence.gd`通用遍历，不序列化任意引擎对象。身体页另按热列导出；缓存、Frame、Thread、Callable和锁不入档。新能力只在实际owner扩展状态与语义校验，不需要为每个功能重写文件I/O。

保存从完整模拟边界取得脱离值，独立冷I/O线程写二进制或重建候选。覆盖实物/材料、路径/通用行动/预约、植物/宿主/来源、战斗订单/在飞物、个人线索/承诺/成长、探索/静态记忆、地区、历法/天气与随机状态。校验域类型、数组长度、库存/引用和过程，重建空间/场/导航缓存后才由owner替换会话；失败保留原世界，成功提升epoch。恢复不通过推进世界来重建缓存，不偷刷离场静态记忆。

耐受与小数伤害余数要求有限值及合法范围；个人事件只保存事实环和序号，恢复时校验预算、时间/载荷并重建人物索引及视图。读档使人物列表回到存档时状态，UI不保留后一段未来。界面缩放属于本机`interface.cfg`，不随世界档回退。

库存和穿戴统一验证规范物品键，穿戴必须匹配实际槽位；实物审计包含已穿物。恢复先校验源记录，再重建所有身体的派生属性，最后校验现血上限；不以默认裸身上限截掉合法装备血量，非法槽位/未知品质/越界基础值拒绝整个候选。重用身体槽位重新计算新身份属性，不继承上一个人物的装备缓存。

写入先到`.tmp`，保留上份`.bak`后替换；主文件缺失时可尝试备份，主文件存在但无效则明确失败，不悄悄切换历史。Windows替换不是断电持久性承诺，错误通过回执返回。四次覆盖同一路径与全新进程续接已做短验证，证据归BASELINE；没有旧档兼容、任意恶意文件沙箱或跨Godot版本二进制兼容保证。
