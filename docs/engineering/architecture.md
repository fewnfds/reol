# 当前运行架构

运行链：Godot输入/画面 → 命令邮箱 → 自主模拟线程 → 独占页CPU批 → owner共享效果 → 不可变显示快照。正式场景只有`scenes/main.tscn`，没有旧慢后端回退。当前能力与测量分别查[FEATURES](../status/features.md)、[BASELINE](../status/baseline.md)。

## 状态和职责

| 入口 | 唯一负责的内容 |
|---|---|
| `scripts/sim/kernel/terrain.gd` | 有限地块的自然基底/装饰地被/人工地板、生境准入、结构/围合、连续身体与线段净空、目标投影 |
| `scripts/sim/kernel/navigation.gd` | lane私有的原生AStarGrid通路、连续起终点连接与拉直、版本缓存和请求分批 |
| `scripts/sim/kernel/units.gd` | 每页256行身体热列、沿路运动、到达/到期、需求与环境接收；一页只由一个lane写入 |
| `scripts/sim/kernel/motion.gd` | 本步带时间折线的采样与分段相对扫掠，供显示和投射物共用 |
| `scripts/sim/kernel/world.gd` | 世界组合根、命令/通用行动、预约、共享效果顺序、生命周期与结构提交 |
| `scripts/sim/kernel/objects.gd` | 单调身份、静态位置索引、定义/分类库存、转移与原子交换；不逐步空转所有对象 |
| `facilities.gd`、`livelihood.gd` | 组合占地/蓝图/设施效果与个人线索驱动的稀疏生活决策，复用身体到期/到达 |
| `environment.gd`、`nature.gd` | 历法/天气、静态max场/移动来源索引、房间响应；分组植物采样/生长/产物/宿主与来源 |
| `combat.gd` | 活跃战斗订单、最后所见、投射物扫掠与步末伤害；感知与攻击通路分别校验 |
| `combat_scan.gd` | 脱离的身体空间索引、分散威胁发现与目标复核；查询按观察者批交现有CPU池，owner采用 |
| `society.gd` | 接触结果、线索传播、真实交易、临时承诺、方法/修行/能力；状态留在原人物/植物记录 |
| `sight.gd` | 全单位共用的距离/平滑环境损耗查询；只读常用格线表与长半径后备，无共享写缓存 |
| `perception.gd` | 玩家当前格图、探索/最后所见地表、静态记忆与人物显隐；NPC不读取这张玩家地图 |
| `regions.gd`、`scenarios.gd` | 同一世界的有限地区冷装配/旅行落点；可选混合压力开局，不提供另一套模拟算法 |
| `persistence.gd`、`state.gd`、`session_io.gd` | 领域显式状态捕获、候选校验/缓存重建和冷I/O；存档不是显示Frame或任意对象反射 |
| `runner.gd`、`frame.gd` | 一个自主Thread、倍率/暂停、可靠命令/回执、只读Frame及姿态历史、采用候选与关停 |
| `scripts/sim/execution/batch_execution.gd` | Godot WorkerThreadPool group任务与join，不建每域线程池 |
| `scripts/presentation/` | 主线程UI/输入/相机/选择、静态画布、GPU迷雾与MultiMesh显示，只读Frame |
| `scripts/presentation/art.gd` | 当前临时视觉包的图集、图标与八向读取；覆盖/来源唯一查[assets](../../assets/README.md) |

表中省略目录的脚本均在`scripts/sim/kernel/`。外部身份不复用，身体槽位可以回收；`actor_slots`只在owner映射到页行。worker不查询库存/对象字典，cargo/potions是变化时同步的工作摘要。植物、箱、家具和墙没有移动页；活的植物增加能力仍保留原身份。对象视距由共用字段承载，移动人物默认有感知，普通静态物默认0；静态感知查询不要求占身体页，目前自动战斗仍只调度移动人物。定义/开局/实例分开，不因保留旧JSON就启用其旧后端。

## 地块与实体分层

Terrain持有自然基底`base`（土/砂/水）、装饰`cover`（无/草地）和人工覆盖`flooring`。三者是紧凑字节列；装饰地被不可选择，不生成逐株对象或定时生长任务。地板对象保留身份、施工投入与拆除材料，Terrain覆盖列是地板对地面的实际效果，不另存一份地板材料。

`Nature.can_plant`负责定义的基底准入及宿主，`Terrain.wild_site`额外拒绝已有围合/房间、地板和阻碍。开局与地区自然撒布统一用wild入口；人工种植可在适合的裸土室内进行，花盆以自己的栽培基底容纳小植物。没有持续扫描并清除被玩家后来围进房间的植物，也尚无持续野生扩散。

`Facilities.placement`区分ground/floor/roof，不再把所有非屋顶物体互斥。低草可铺地板，灌木、树和残桩先清除；蓝图不立即清草，完工再次校验并释放草的来源/宿主/库存，不能装进背包的产物留实物堆。取消蓝图不毁草。地板可在墙/家具下方，不改变通行/围合；铺完去掉地被，拆除露土。已有家具、屋面和盆栽不因拆地板消失。

压力开局的`resource/wood`仍是有限木料点，不冒充完整经济树生命周期；其清场等级从树到桩到散木料变化，保留原库存和来源下标，不砍一次另生一份1000木材。真正生长植物仍归Nature，不能把全部资源点重新纳入高频生长循环。

## 连续移动与共同导航

地块/墙/家具保持方格占地，身体`positions`、`targets`与`routes`使用连续坐标。鼠标移动/攻移传`position: Vector2`，回执给出经过合法投影的实际落点；内部按格旅行仍可传tile取格心。停止保留当前身体位置，换令从当前位置重新规划，均不先吸附格心。八向仅量化素材朝向。

每个lane独占一个Navigation上下文：小体型图节点在格心，大体型图按需建立、节点在整数交点，邻接四格有阻挡则不可用。这保留两格宽通路的中线，不使用旧的3×3整格膨胀。原生无切角八邻接搜索提供格通路，缓存只保存通路节点；起终点各自连接，带净空的有限前探生成连续线段。具体近似和分批只查[运行与精度](simulation-pacing.md)，选型及NavServer对照只查[研究](../../design/research/large_simulation_optimization.md#任意角度移动方案核查与实施)。

玩家、追击、攻移、探索与设施接近共用这条链。设施按真实位置、身体尺寸与目标占格选择操作点，已在范围内就留在原位；完成时再次检查实际范围/物理通路。追击依据最后所见连续位置节流重规划，不只等待目标跨格。新墙检查当前点到全部剩余路点的线段，受影响者清路线后再求路；建墙/完工也检查邻格延伸过来的身体，飞行不占地面墙。拓扑变化清通路缓存和已知封闭小区标签。

Units按弧长消耗一步可行距离，输出确切到达毫秒；只有本步转角或提前停步者生成稀疏的`(x,y,alpha)`轨迹，不假定最多一个转角。World提交效果后发布不可变Pose，GPU、镜头/拾取与投射物使用相同分段时间。没有引入逐人物Node、第二物理时钟或第二生产导航后端。

## 一步怎样结算

Runner按单调墙钟累积所选倍率的时间需求，不等主线程派发下一步。每个50ms步之前按受理序处理邮箱命令；暂停中也可受理命令，但不推进世界时间。

1. 重置lane的路径准备额度；仅在有在飞物时保存扫掠所需的步首位置，把互不重叠身体页交给lanes。上下文不同时由owner和worker调用。
2. join后合并到达/到期记录，按步内毫秒、稳定身体槽位处理资源与行动。动作新段从下步开始，不宣称逐毫秒连续模拟。
3. 感知损耗按布局版本在读取前同步。空间索引按阵营分组，和平自主者分散发现附近新威胁，已有目标复核；量少同算法直接执行，量大按观察者分块交CPU池、join后owner采用。活跃战斗处理在飞物和订单；命中/挥击统一量化到步末，先收集同边界攻击再提交，可互杀。Godot Geometry2D提供扫掠几何，owner提交伤害，不从后台线程读取主线程物理空间。即时近战与持续攻击共用身体槽位冷却。
4. 处理本步植物分组，合并结构改动，更新导航、受影响路线、围合与必要静态场。来源删除局部回填重叠max来源，不保留旧最大值。
5. 整秒到期再更新天气/潮汐条件、移动来源桶、房间与身体接收；热伤害在本步更早的行动之后。提交步时钟，再按到期/布局变化更新玩家观察。

战斗接触只在看见目标时刷新位置/时间；失联后追最后所见，到达或超时放弃，隐藏死亡不直接清空接触。盲区受击可沿真实弹道来向搜索，不取得隐藏射手位置。驻守只锁定射程/物理通路可用的目标；不可达自动追击记住目标失败位置，地形、目标位置或自身通行能力变化后再尝试，避免长工作反复被同一失败接触打断。警戒范围、个人视距、武器射程和物理命中是不同概念。当前敌我仍按side区分，未实现完整阵营关系。

静态物不每步空转，普通跨格不触发全域屏障或全村目击。个人观察仅复制可见局部事实，库存版本未变不重复构造；交谈传播历史线索，不查询全局最新值。社交邀约、施工协作和生活恢复仍走通用接近/预约/耗时合同；取消先移除行动记录再回调，不能覆盖后来收到的停止命令。具体精度与近似只查[运行与精度](simulation-pacing.md)。

## 显示、通知和存读

`scripts/presentation/debug_console.gd`是独立调试autoload，`runtime_log.gd`用原生Logger收取线程安全的有界记录。控制台只通过main提供的诊断回调读取不可变Frame、邮箱状态和UI焦点；不读取活World，不执行游戏脚本。命令、导出位置与捕获限制只维护在[运行与测量](tooling/usage.md)。

Frame包含必要身体列、静态外观版本、玩家格图/记忆、选中详情和统计，全部与活世界脱离。短Mutex只交换latest引用和通知队列；发布后不写已发布容器，也不复用消费者仍持有的槽位。外观/身份索引按布局版本发布，不每步复制所有库存。

画面可跳过中间Frame，可靠命令回执/到达/失败/死亡走独立队列。命令在途上限包含未收回执。Pose随位置保留身份；槽位换人不串插值，读档提升epoch并重置显示历史、拒绝旧会话命令。

### 交互与小地图

`presentation/game.gd`协调原会话/渲染；`presentation/ui/hud.gd`持有原生Control布局、窗口与脱离数值视图；`interaction.gd`统一InputMap、拾取、相机/当前工具和命令分派；`actions.gd`只提供已有命令的名称/适用按钮，不取代领域判定。按钮和热键共用一条入口，世界输入在GUI未处理事件中执行；模态焦点另阻止Input持续轮询。地面命令走既有脚点逆转换，小地图地理坐标直接使用逻辑位置；建造才按格取整。读档epoch重置工具、菜单与数量窗口。

普通详情先检查当下可见性，离场静物只读`perception.memories`，不展示`inspected`中的隐藏库存；动作结果与完整诊断仍沿独立通知/F12。当前行动用`started_ms/due_ms`展示真实进度，命令受理不等于完成。`construct/plant`回执携带已创建目标与`placed`，后续接近失败不隐去已扣料事实；没有第二套施工/行动队列。

`ui/minimap.gd`只在静物描述符更换时生成一张512² R8类别图；片元shader复用现有地表R8、瓦片图集和可见/探索纹理，合成地形、墙屋/树冠剪影和记忆明暗。原生绘制少量彩色可见单位点与相机框，人物side列按布局版本发布。动态点在HUD更新时降频整理，地图支持局部到全图缩放；不做第二场景渲染、全图每帧烘焙或GPU读回。具体周期以代码为准，测量见BASELINE。UI不新增世界事实或为每NPC创建控件。

### 世界呈现与恢复

`Frame.Visual`发布行动显示代码，受击缓存随会话/身份重置；美术不改变身体事实。设施建造的facing与旋转占地保存于原对象记录，外观/冻结记忆携带同一方向，不由UI另存一套布局。`atmosphere.gd`用Godot CanvasModulate和单屏shader呈现共同时钟的天光/天气，屋顶与当前格图限制粒子；接触影与动作在原批次内完成，不建逐人物灯或计时器。坐标/锚点、素材清单与重建只查[assets](../../assets/README.md)。

人物和静态物合入一个MultiMesh：静态描述符变化时准备完整精灵与脚点顺序，新人物姿态采用时用原生数字排序并线性归并，解决两个独立批次不能互相穿插的问题。直线步保留GPU两姿态插值，转角/提前停止的稀疏轨迹打包进RGBAF纹理，由同一shader按时间采样；动画、选择和镜头使用相同显示时刻，飞行显示偏移另作拾取修正。排序按采用姿态的脚点近似，不每显示帧重排全部物体；屋顶仍最后绘制。图集和锚点细节只查素材入口。

玩家观察使用共同感知的连续距离余量：逻辑阈值控制人物与实物刷新，羽化权重仅给显示，采样周期与近似见simulation-pacing。地表外观另存R8观察缓存；静态对象用最后所见descriptor，按根部可见状态整体明暗显示，不让地面迷雾切掉跨格树冠。视野外变化不刷新缓存，动态人物/选中圈/在飞物按当前逻辑可见格过滤。GPU只滤波可见/探索纹理，不另投射视线。开发全图视图只改变显示，不减掉远处模拟；开发HUD保留真实后台数据，包括鼠标格的基底、地被与地板。

`World.state_owners()`列出实际领域，每个owner维护自己的`STATE_FIELDS`，通用捕获/恢复循环不随每个玩法重写。对象状态、在途过程和随机流保存；索引、导航、场缓存、锁和Frame重建。候选只重建观察缓存，不刷新保存的离场记忆。完整格式与支持范围查[存档现状](compatibility.md)。

低频新功能可以用普通局部记录/函数，密集独立计算再选页批；kernel不是万能ECS。地区当前共用一个有限世界，一直真实推进，不把旅行入口称为已具备无限地图或分块LOD。
