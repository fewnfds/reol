# 当前运行架构

运行链：Godot输入/画面 → 命令邮箱 → 自主模拟线程 → 独占页CPU批 → owner共享效果 → 不可变显示快照。正式场景只有`scenes/main.tscn`，没有旧慢后端回退。当前能力与测量分别查[FEATURES](../status/features.md)、[BASELINE](../status/baseline.md)。

## 状态和职责

| 入口 | 唯一负责的内容 |
|---|---|
| `scripts/sim/kernel/terrain.gd` | 有限地块、生境、结构/围合、路径净空和Godot原生AStarGrid装配 |
| `scripts/sim/kernel/units.gd` | 每页256行身体热列、沿路运动、到达/到期、需求与环境接收；一页只由一个lane写入 |
| `scripts/sim/kernel/world.gd` | 世界组合根、命令/通用行动、预约、共享效果顺序、生命周期与结构提交 |
| `scripts/sim/kernel/objects.gd` | 单调身份、静态位置索引、定义/分类库存、转移与原子交换；不逐步空转所有对象 |
| `facilities.gd`、`livelihood.gd` | 组合占地/蓝图/设施效果与个人线索驱动的稀疏生活决策，复用身体到期/到达 |
| `environment.gd`、`nature.gd` | 历法/天气、静态max场/移动来源索引、房间响应；分组植物采样/生长/产物/宿主与来源 |
| `combat.gd` | 活跃战斗订单、局部索敌、投射物扫掠与步末伤害；不为每个和平对象运行战斗循环 |
| `society.gd` | 接触结果、线索传播、真实交易、临时承诺、方法/修行/能力；状态留在原人物/植物记录 |
| `perception.gd` | 共用静态损耗、局部射线缓存、玩家探索/静态记忆与当前人物可见性；不建立全NPC视野位图 |
| `regions.gd`、`scenarios.gd` | 同一世界的有限地区冷装配/旅行落点；可选混合压力开局，不提供另一套模拟算法 |
| `persistence.gd`、`state.gd`、`session_io.gd` | 领域显式状态捕获、候选校验/缓存重建和冷I/O；存档不是显示Frame或任意对象反射 |
| `runner.gd`、`frame.gd` | 一个自主Thread、倍率/暂停、可靠命令/回执、只读Frame及姿态历史、采用候选与关停 |
| `scripts/sim/execution/batch_execution.gd` | Godot WorkerThreadPool group任务与join，不建每域线程池 |
| `scripts/presentation/` | 主线程UI/输入/相机/选择、静态画布、GPU迷雾与MultiMesh显示，只读Frame |
| `scripts/entities/humanoid_appearance.gd` | 八方向人物资源清单与只读外观解释 |

表中省略目录的脚本均在`scripts/sim/kernel/`。外部身份不复用，身体槽位可以回收；`actor_slots`只在owner映射到页行。worker不查询库存/对象字典，cargo/potions是变化时同步的工作摘要。植物、箱、家具和墙没有移动页；活的植物增加能力仍保留原身份。定义/开局/实例分开，不因保留旧JSON就启用其旧后端。

## 一步怎样结算

Runner按单调墙钟累积所选倍率的时间需求，不等主线程派发下一步。每个50ms步之前按受理序处理邮箱命令；暂停中也可受理命令，但不推进世界时间。

1. 仅在有在飞物时保存扫掠所需的步首位置；把互不重叠身体页交给lanes。lane拥有私有AStarGrid、路径缓存及按需建立的大体型净空图。
2. join后合并到达/到期记录，按步内毫秒、稳定身体槽位处理资源与行动。动作新段从下步开始，不宣称逐毫秒连续模拟。
3. 活跃战斗处理在飞物和订单；命中/挥击统一量化到步末，先收集同边界攻击再提交，可互杀。Godot Geometry2D提供扫掠几何，owner提交伤害，不从后台线程读取主线程物理空间。即时近战与持续攻击共用身体槽位冷却。
4. 处理本步植物分组，合并结构改动，更新导航、受影响路线、围合与必要静态场。来源删除局部回填重叠max来源，不保留旧最大值。
5. 整秒到期再更新天气/潮汐条件、移动来源桶、房间与身体接收；热伤害在本步更早的行动之后。提交步时钟，再按到期/布局变化更新玩家观察。

静态物不每步空转，普通跨格不触发全域屏障或全村目击。个人观察仅复制可见局部事实，库存版本未变不重复构造；交谈传播历史线索，不查询全局最新值。社交邀约、施工协作和生活恢复仍走通用接近/预约/耗时合同；取消先移除行动记录再回调，不能覆盖后来收到的停止命令。具体精度与近似只查[运行与精度](simulation-pacing.md)。

## 显示、通知和存读

Frame包含必要身体列、静态外观版本、玩家记忆/损耗、选中详情和统计，全部与活世界脱离。短Mutex只交换latest引用和通知队列；发布后不写已发布容器，也不复用消费者仍持有的槽位。外观/身份索引按布局版本发布，不每步复制所有库存。

画面可跳过中间Frame，可靠命令回执/到达/失败/死亡走独立队列。命令在途上限包含未收回执。Pose随位置保留身份；槽位换人不串插值，读档提升epoch并重置显示历史、拒绝旧会话命令。

MultiMesh只在采用新姿态时上传，GPU在相邻已提交姿态间插值；动画、选择和镜头使用相同显示时刻，飞行显示偏移另作拾取修正。迷雾圆心使用连续显示坐标，GPU读取损耗/探索纹理；静态物使用最后所见外观，动态人物用当前可见性。开发全图视图只改变显示，不减掉远处模拟。

`World.state_owners()`列出实际领域，每个owner维护自己的`STATE_FIELDS`，通用捕获/恢复循环不随每个玩法重写。对象状态、在途过程和随机流保存；索引、导航、场缓存、锁和Frame重建。候选只重建观察缓存，不刷新保存的离场记忆。完整格式与支持范围查[存档现状](compatibility.md)。

低频新功能可以用普通局部记录/函数，密集独立计算再选页批；kernel不是万能ECS。地区当前共用一个有限世界，一直真实推进，不把旅行入口称为已具备无限地图或分块LOD。
