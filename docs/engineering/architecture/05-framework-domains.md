# 顶层框架与领域归属

本页是Reol基础架构的职责入口。七个框架规定代码和后续建设的归属；现有入口用于定位原所有者，**不表示目标能力已全部实现**。接入和缺口只在[技术落地总表](../../status/technical-status.md)维护，建设依赖和完成标准只在[基础建设计划](../../plans/foundation-priorities.md)维护，具体原状态见[状态所有权](02-owners.md)。

## 框架关系

```text
世界地块与空间框架 ＋ 实体、物品与容器框架
       ├─ 建筑与组合空间框架 ─┐
       └─ 植被与自然生命框架 ─┴─↔ 环境框架
       ↑              ↑                 ↑
       └──── 单位行动与交互框架 ────────┘
                ↑ 意图       ↓ 可知结果
                认识与自主决策框架

定义与装配、共同时间、生命周期与事务、存读、呈现/诊断贯穿上述领域。
原对象提供几何、材质、能力及来源；行动按实际条件请求领域效果。
各领域的真实变化更新相关空间事实、环境来源和受体条件。
```

这是职责与接入关系，建设顺序由[基础建设计划](../../plans/foundation-priorities.md)规定。建筑和植被是并列领域；单位身体和最小行动从基础阶段参与放置、改造与过程验证，环境提供已有条件并随领域扩展。反馈沿共同时间和原所有者接缝处理；查询与视图不推进世界。框架不要求各对应一个class、Autoload或独立存储库。公开作品和教程的对照依据见[基础架构研究](../../../design/research/colony_sim_architecture.md)。

## 七个领域

| 顶层框架 | 领域负责的事实与行为 | 向其他领域提供什么 | 现有代码入口 |
|---|---|---|---|
| **世界地块与空间框架** | 地图生成描述、地表与材质、空间键和层；组合原对象的占地/位置投影与派生查询 | 地形/材质、覆盖/邻近、净空/接触几何及相关变更范围 | `WorldMapData`、`SimWorldSpace`、`SimObjectSpatialSnapshot`、`SimGroundPlacements`、`SimStructureQuery`；`ReolWorld`负责区块呈现适配 |
| **实体、物品与容器框架** | 共同引用、定义与实例边界、能力声明、受控生命周期；原物与数量、保管、容器和转移 | 对象解析、原所有者、位置/包含链、能力与合法物资事务 | `SimWorldObjectQuery`、`SimEntityQuery`、`SimStorageQuery`、`SimObjectLifecycle`、`SimInventory`、`SimArtifacts`、`SimClothing`、`SimEmbodiment` |
| **建筑与组合空间框架** | 结构/家具实例、施工/拆除、耐久与损毁、门状态、围合与屋面；用途区域及工作空间组合 | 真实几何、材质、开口、覆盖、结构连接及推导房间；设施所需的器具/空间条件 | `SimConstruction`、`SimConstructionGeometry`、`SimStructureQuery`、`SimEnclosedSpace`、`SimFacilityUse`、`SimWorkplaces`、`SimResting` |
| **植被与自然生命框架** | 植物与非人生命的专属状态、自然过程、环境响应及产物条件 | 可作用的自然对象、实际占地、来源/受体能力，以及采集等领域作用接口 | `SimLandResources`是有限资源/草木接缝，`SimAvianLife`、`SimLargeBodies`是非人生命入口；地表植被覆盖由`NaturalEnvironment`派生，完整植物实例框架待接 |
| **环境框架** | 历法/气候/天气条件；温度、光照、五行等各自规则与必要实际响应；风水所需环境组合 | 有时刻与来源的环境查询、响应变化和受体输入 | `SimWorldCalendar`、`SimGeographicClimate`、`SimWeather`、`SimWorldEnvironmentFields`、`SimNaturalLight`、`SimLocalLight`；`SimEnvironment`适配人体暴露 |
| **单位行动与交互框架** | 按身体能力执行移动、通行、寻路与接近；意图受理、表达/理解、权限/意愿复核、过程占用、资源预约、耗时、中断和结果 | 同一套可由玩家/NPC使用的行动入口、过程状态、失败原因和领域结果引用 | `SimLocalMotion`、`SimRouteTravel`、`SimMotionClearance`、`SimActionContract`、`SimActionExecutor`、[object_actions.gd](../../../scripts/sim/object_actions.gd)、`SimInteractionRequests`及现有各领域执行器 |
| **认识与自主决策框架** | 感知、个人所知与来源、目标/职责/策略和选择；组织任职/授权依据的有限记录 | 观察者可知的投影、基于自身认识的意图、请求接受与否所需依据 | `SimSocialMemory`、`SimStockInformation`、`SimInstitutionBook`、`SimAutonomousLivelihood`、`SimStandingWork`及原需求决策；Fog与runtime负责观察适配 |

这些名称用于统一文档归属；实际class/字段按[术语映射](../terminology.md)引用。完整植物、通用风水、任意策略编排等尚未接入的能力不据此获得虚构的class或完成状态。

## 原状态与组合接口

1. **地块承载实体。** 地图持有地表；身体、墙、植物、器物仍归各自原领域。多格占地指向同一实例，空间索引只保存可重建引用和投影；容器内物品不因锚点相同就成为地面障碍。
2. **能力声明与能否执行分开。** 身体/器物定义声明已有能力，实际动作按当前控制、空间、认识、权限、资源和过程状态复核。新内容复用已有能力；新机制由所属领域实现。
3. **阻碍的事实与通行判定分开。** 建筑/植物等提供几何、材质、开口和作用条件；世界空间组合相关事实；单位行动根据体型、移动方式和实际能力判断可通行、代价与路径。特殊穿行是否成立及成本由相应规则决定，不由建筑脚本写死人类专用结论。
4. **环境来源与受体分开。** 建筑、植物、物品和身体提供原位置及已支持来源/受体能力；环境维护自身不可重建的响应。受体后果由原身体、植物或材料领域提交。温度、光照、五行和可消耗灵气保留各自语义；风水查询真实布局/水路/环境，详细利用规则仍按[环境规则](../../../design/rules/environment.md)收敛。
5. **行动协调与领域效果分开。** 行动框架组织接近、占用、时序和取消；施工、采集、交换等实际效果仍通过对应领域接口结算，不复制其材料、伤势或来源状态。
6. **决策与执行分开。** 玩家、NPC和未来AI提出已支持意图；执行器使用同一世界规则。客观查询不能自动写成角色知识，NPC也不能借开发全知绕过通信、认识和权限。
7. **共同接入与原状态分开。** 新领域按实际能力接定义、引用、空间候选及生命周期；初始化、进入/离开空间、包含关系变化和销毁分别明确。索引随原提交更新或失效，恢复后重建。共同协议可以适配不同owner，无需把全部状态迁到统一对象库；本项是扩展合同，具体已接范围以技术总表为准。

## 跨领域变更示例

### 墙门变化与路线

归属为：**单位行动与交互框架 → 运动与通行 → 路径规划与执行 → 障碍变化后的失效与重规划**。

- 建筑领域负责合法结构变化、原材料/工时及结构事实。
- 世界空间负责相关占地、净空和查询投影的更新或失效。
- 单位行动负责哪些路线受影响、重新查询、绕行/等待/不可达，以及按已支持规则尝试开门等交互。
- 环境负责相关房间、遮挡或来源条件的变化；当前已接效果和未实现边界以技术总表为准。
- 共同时间与存读保证各领域按同一提交边界发布，预算不足保留过程与积压。

重规划是行动框架的内部能力，单项算法通过不能代表该框架完成。上述职责归属也不声称当前所有失效通知和重规划已贯通。

### 植物变化与环境

植物领域提交实际生长/损毁及产物变化；实体生命周期处理相应对象关系；世界空间更新原占地投影；环境只更新确实改变的来源/受体依赖；行动框架重新评估受影响的接触和通行；认识框架只让实际观察者获知可感知结果。没有相应能力的对象不产生该领域持续工作。

## 公共运行与工具合同

| 公共合同 | 原职责与接入要求 |
|---|---|
| 共同时间、跨区和因果阶段 | `GameClock`与`RegionalSimulation`保留原推进合同；领域反馈在明确阶段生效，预算不足保留待处理时间和事件 |
| 定义、装配和生命周期 | 定义/开局与实例分离，绑定会话的实际依赖；生成/移除由原领域验证，派生索引沿真实提交维护 |
| 物资与提交 | 原库存、器物和身体各有唯一所有者；跨领域通过预检与明确提交接缝协调，失败语义与已发生成本由原过程定义 |
| 存读与长期持续性 | 保存不可重建事实、必要在途状态和版本；完整候选通过后替换活世界，恢复重建派生索引；历史增长按实际规模验证 |
| 稀疏执行与性能 | 各领域按实际能力、活动/到期/变脏工作选择候选，复用`SimParticipationIndex`等现有工具；性能工作归所属框架，跨域热点统一协调 |
| 创作、呈现和诊断 | 工具编辑同一内容或提交同一规则；视图只投影。各框架同步提供必要编辑/观察入口、错误原因和验证证据 |

具体公共合同沿[依赖方向](01-dependencies.md)、[时间与行动](03-time-space-presentation.md)、[存读](04-persistence.md)和[稀疏执行](../sparse-execution.md)维护，不再创建第二套时钟、实体状态或无实际使用者的通用平台。
