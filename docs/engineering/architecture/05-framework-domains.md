# 顶层领域职责

本页唯一维护逻辑职责。领域不等于某个class、Autoload、Node、线程或数据库；状态有唯一可写所有者，也可以通过私有批结果、分区和并行任务计算。重构允许替换现有实现，名称/文件定位通过[术语](../terminology.md)与[当前owner索引](02-owners.md)按需查询。

## 七个领域

| 领域 | 负责的事实与过程 | 提供的接缝 |
|---|---|---|
| 世界地块与空间 | 地形/材质、坐标与真实占地；从原对象派生分块候选、净空、接触和可见几何 | 带适用范围/版本的局部查询与变化范围；视图瓦片不作权威碰撞 |
| 实体、物品与容器 | 唯一身份、定义/实例、实际能力、原物/数量、包含与保管/处分；受控生命周期 | 稳定引用、合法转移和变化；原物不因跨格、视图或任务复制 |
| 建筑与组合空间 | 结构/家具、施工/拆改、材料过程、门/屋面、操作位、设施及推导围合 | 真实拓扑/材质/开口与设施条件；房间不是另一份建筑/库存 |
| 植被与自然生命 | 原株/其他生命的专属状态、物候/生境/响应、残株与产物、条件能力 | 实际占地、来源/受体与领域作用；不要求每株完整心智/背包/Node |
| 环境 | 历法/气候/天气、温度/五行/照度的各自规则、必要响应与可定位来源 | 带时刻/空间/输入依据的查询及受体条件；不复制原物或生命后果 |
| 单位行动与交互 | 身体能力、移动/路线/避让、受理/接近/预约/耗时/中断，通信/回应和执行 | 玩家/NPC共用意图/过程/失败接缝；施工、产物、伤势等效果归实际领域 |
| 认识与自主选择 | 来源明确的观察/记忆/传播、理解、需求/目标/职责和本人决策 | 基于本人认识的意图、反馈与重选；全知索引不能写成个人知识 |

建筑和植物共同改变空间，环境与生命双向作用，行动与认识从首次可作用时参与。建设依赖与出口只看[主计划](../../plans/foundation-priorities.md)，具体计算/数据/并行合同只看[执行规格](../../specs/world-engine/execution.md)。

## 贯穿领域的边界

唯一事实、共同因果、认识与恢复完整性只由[constraints](../constraints.md)及[已确认规则](../../../design/rules/README.md)定义；这里仅解释各域交接，不复制另一组全局要求。批计算/输入段的当前细节分别在对应工程接口页，目标做法属于候选规格。

## 跨域变化应怎样归属

墙门变化：建筑提交真实结构；空间更新局部几何/连接；行动使受影响路线失效并在执行时复核；环境更新对应传播/房间；认识只向实际观察者提供可知结果。动态重规划是行动内部能力，不能独立充当顶层计划。

植物变化：自然生命提交原株/产物；原资源owner处理物资，空间更新占地，环境更新真实来源/受体，行动重评实际目标，认识按观察传播。无能力的对象不产生该域持续工作。

跨区和跨线程：按实际读写依赖选择任务/屏障，计算结果由相应owner采用；不能仅因同处一块就认定全部相互独立，也不能把一人跨格变成所有域全量运行。

## 新能力接入需回答

事实归谁、输入适用哪个逻辑时段、什么触发/到期、变化影响哪些消费者、失败/取消有什么后果、资源怎样唯一提交、哪些内容保存/恢复、玩家何时如何知晓，以及实际工作量怎样随规模增长。

这些是设计/评审问题，不要求先建立一组空基类或注册平台。不同能力只有出现真实公共责任才提取机制，不能为样例逐个新增顶层系统。
