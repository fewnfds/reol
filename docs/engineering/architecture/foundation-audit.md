# 宗门自主模拟所需的共享框架审查

审查基线：`main`的`edb08712109b684447e3f55366707c12d986a9d5`，始于2026-11-16。依据现有运行链、领域源码、作者定义、界面和恢复入口作静态审查，并参考公开开发资料与顾问反例。**本轮只审查和修订设计，没有修改运行时代码，没有新增场景，也未验证未来百人宗门的运行或性能。**

本文维护能力缺口、源码依据与演进理由；逻辑职责归[领域职责](05-framework-domains.md)，建设顺序与出口只归[主计划](../../plans/foundation-priorities.md#下一阶段候选)。人物、社会、宗门的玩法语义分别沿[角色基础](../../../design/systems/beings_and_lifeways/character_state.md)、[社会系统](../../../design/systems/social_system.md)、[宗门生活](../../../design/systems/sect_life.md)，不在此复制功能表。

## 结论与应保留的基座

项目已有共同世界和行动执行核，缺口主要在**个体、社会与实际活动之间的共享领域机制**。继续直接添加工种、功法和职务，会把规则继续写入`World`、`Livelihood`和`Society`的具体内容分支；单独做一个会种田或求学的NPC不能补齐这些责任。

以下现有能力继续作为基础，不重造另一套模拟后端：

| 已有能力 | 当前可复用的内容与实际边界 |
|---|---|
| 共同时间、状态与计算 | 一个World/Runner、稳定对象身份、身体页批、精确边界提交、变化时重建与稀疏到期；不因新增领域再建线程池或逐NPC节点 |
| P4公共准入与作用 | ActionGate、ActionCosts、领域操作、效果/资源/防御/反应/召唤/器物；已经有共同资源访问，领域操作目前仅接`tend`，不代表所有生活能力已通用 |
| P5协调与执行关联 | 当前任务、原host/run、合法交接、战术规则/有限序列、唤醒、失败依据与退避；不等于已有持久人生目的 |
| 空间与实际劳动 | 连续移动、可达操作位、完整占地、施工进度/半成品、预约、设施/植物owner；不能再为授业、医护或炼丹各造一套寻路和计时 |
| 定义、表现与恢复 | Resource/Inspector及已有JSON定义、校验/冻结/签名、不可变Frame、显式STATE_FIELDS和独立候选恢复；新增领域扩其合同，不新建存档系统 |

现有“七个领域”对物理世界的分工较清楚，对**生命状态与能力成长、社会联系与组织**的归属不够显式。领域地图补清这两类职责，原“认识与自主选择”补上持久目的；这只明确谁负责什么，不表示新增若干Manager、所有原数据立即搬家或九套运行框架已经实现。

## 七项共享能力

分类中的“新增责任”指目前没有贯通的状态归属与消费规则；“扩已有”指原身份、执行或实际物资机制可以沿用。每项都应进入正常游戏路径，具体内容只是共同机制的消费者。

### 1. 主体能力组成与共用行动查询：扩已有

**源码依据：** [Equipment](../../../scripts/sim/kernel/equipment.gd)第18、39行将身体分为`human/companion`，后者直接关闭需求；[World](../../../scripts/sim/kernel/world.gd)第929行交互入口只接受人形；[Decisions](../../../scripts/sim/kernel/decisions.gd)的`bind/wake`要求身体槽。[Society](../../../scripts/sim/kernel/society.gd)已允许与灵智植物接触，但未贯通静止主体自主。身份、感知与身体热列已有，缺的是按实际能力装配和查询的共同边界。

主体是否有移动身体、需要进食、可以操作/表达、能够学习，应分别成立。形态、装备、掌握和当前身体条件共同提供能力；物种、临时召唤身份、智力与社会权限不能互相代替。不为静止的有智主体伪造步行身体，也不让普通植物强制拥有完整心智。

**状态与接缝：** Objects保留身份和实际载体，身体/掌握/装备等原owner保存各自源状态。有效能力从这些来源查询或派生，不再维护一份会独立漂移的“角色全能力真值”。共同操作定义描述输入、施动者/目标要求和处理器，玩家操作菜单、NPC方法与执行准入引用相同语义；操作候选的发现仍受本人认识约束，执行时由owner复核真实条件。界面不能通过禁用理由泄露对方隐藏本领、资产或意愿。

查询应分清本人已掌握/固有手段、当前操作装配、自身就绪、本人所知机会与最终领域准入，不能让一个带“查真值模式”开关的全World入口同时供UI和NPC自由调用。只读候选查询接脱离的可知输入，权威复核留owner；标签缓存不代替实际费用/目标校验。[ActionGate.check](../../../scripts/sim/kernel/action_gate.gd)及[ActionCosts.available](../../../scripts/sim/kernel/action_costs.gd)目前也依赖身体槽，静止主体接入须贯通所需载体/资源适配，不能只删人形判断。

**消费者与验证：** 工作/战斗、普通动物/人形/灵智静物、玩家/NPC交互均消费该接缝。验证要能改变能力来源而不追加物种特判，同机制新操作不再分别修改UI、NPC与执行三份规则。定义改变、掌握/装备/身体条件改变时更新派生值，保存源状态，恢复重建查询；不建立每帧重算能力的全实体循环。

### 2. 生命条件与掌握成长：补明确责任，扩原资源与派生

**源码依据：** [Equipment](../../../scripts/sim/kernel/equipment.gd)已有基础值/穿戴/状态到身体热列的变更时重建。[Society](../../../scripts/sim/kernel/society.gd)第129～173行把学习、修持、解锁与木愈施展绑定在`wood_breath/old_tree/wood_mend`上，`methods/practice/abilities`尚未形成通用掌握合同。木愈的直接命令路径与P4技能配置也是两套能力入口。

共同能力需要区分本源素质、当前资源、持续身体状况、已掌握的方法与进展、当前可用方式，以及快捷配置。听说过一门术法不等于掌握；换武器或换快捷栏也不应忘掉已学技艺。生活技艺、修持和战斗本领可共用掌握/前置/学习来源的机制，但不强迫它们使用同一种经验数值或成长公式。

**状态与接缝：** 素质/持续条件与掌握进展有明确的领域写入者和schema，可先存规范子记录或按实际复杂度拆稀疏owner；字典所在文件不自动决定业务归属。原HP、精力、饱足、qi及可选资源池继续各有唯一真值，沿ActionCosts等访问适配演进。派生属性消费有关素质、装备、伤病及掌握，仍在变化时重建；治疗HP不自动删除持续伤病。持续身体过程能复用状态贡献，但不把所有疾病、修为与人格都塞进Effects。

**消费者与验证：** 学习/授业/实践、劳动/战斗/休养至少共用有关能力；具体成长必须改变一次真实选择或执行结果。已解锁的生活能力和战斗能力沿共同准入/作用使用，保留各自即时、耗时与并行政策，不能为“统一”擅改木愈的作用范围或把即时治疗强制变成站桩。源条件和掌握跨中断/存读持续，投入时间与消耗由真实过程提交；不以新增一页属性条算完成。

### 3. 个人认识、评价与持久目的：补P5上层，迁移固定生活选择

**源码依据：** [Livelihood](../../../scripts/sim/kernel/livelihood.gd)第31行起已有可见观察和个人`known`；第92行起的选择仍按进食、休息、施工、烹饪等固定优先级与距离挑单步行为。烹饪要求原料已经在身上。[Decisions](../../../scripts/sim/kernel/decisions.gd)的`_sequence`是最多8步/6000ms的战斗槽位序列，不能通过放宽上限承担人生计划。[PersonEvents](../../../scripts/sim/kernel/person_events.gd)是有界标量历史，不是语义认识或责任记录。

需要抽开“获知了什么”“为何在意”“希望什么成立”“眼下采用什么方法”。本人认识保留来源、时刻与有关证据；评价形成有原因的情绪、期待与方法偏好；持久目标保留来源、达成条件及当前受阻原因。有限方法根据已知条件与实际掌握产生下一步，P5继续承接原任务、唤醒、交接与失败反馈。

**状态与接缝：** 认识/评价/目标/方法属于按需装配的个体自主记录，原身体和社会事实不复制进个人黑板。方法定义可作纯计算；活跃意向只保留选用手段、有关依赖与必要展开/重试预算，每次依据原owner的实际物资/进度、已提交结果和现有条件重入。可以有必要子目标，但不保存盲目重播的脚本调用栈，也不与P5再各存一份生活步骤游标；不制作任意状态空间搜索平台。失败沿P5已有证据和退避语义处理，不另造全局黑名单。重大经历的语义摘要按类别和用途有界，不无限积累事件全文。

**消费者与验证：** 维持生活、求学修持、履职/求助和自卫共享该层。吃饱后仍可推进个人目的；相同处境改变有关认识或倾向，会形成可解释差异。手动接管/战斗打断当前执行后，持久目的仍在；已拿的材料不重复领取。暂缓目标保留下次有关事件或有界复查机会，既不逐帧思考，也不等待一个永远不会来的事件。细节沿[自主生命](../../../design/systems/beings_and_lifeways/agency.md)。

### 4. 可定义行动与持续活动合同：扩P4/P5和原宿主

**源码依据：** [World](../../../scripts/sim/kernel/world.gd)的`begin_interaction/settle_action`同时判断动作名单、具体耗时和领域分派；[DomainEffects](../../../scripts/sim/kernel/domain_effects.gd)已经示范手工与术法共用`tend`作用。[Society.waits](../../../scripts/sim/kernel/society.gd)已有伙伴等待与退出清理，[Facilities](../../../scripts/sim/kernel/facilities.gd)已有施工中断保留，不能说完全缺少活动生命周期。

共同操作需要可校验的输入/目标要求、能力/领域准入、接近或参与方式、过程处理器、费用/阶段和实际结果解释。原宿主继续负责run、时刻、已付款及中断；特有算法放领域脚本，同机制内容通过定义复用。战斗交付继续用Combat，不把所有行动塞进它；植物生长、代谢与环境变化也不因此变成cast。

**状态与接缝：** 当下执行归原宿主和Gate，多方活动保存实际受理者、各自参与run和已共同投入的阶段；需要同步的部分按真实到场/参与推进。未来约期、社会份额、现场操作位和库存预留分别表达；异地接力协作不绑多人身体锁。活动结束返回关联原run/阶段、实际数量或变化引用的领域结果，供方法和有关事项直接采用。只保留恢复/履责所需的完成依据与去重状态，不把所有结果变成永久全世界日志。

多方共同过程可以由原交互宿主保存一条活动记录，不必有物理在制物；参与者run只表示这次实际参与。一次性作用可用原run与作用序号关联结果，跨run的共时活动/在制阶段则以原活动/过程及其提交序号或已结算区间为依据。不能分别拿老师和学生的run计两次同一履职，也不能重连一次便把已学时间再算一遍。具体幂等依据由实际后果owner确定，不引入全世界回执数据库。

**消费者与验证：** 施工/制作、教学/诊治/交换、手工/术法作用共用生命周期的适用部分。取消只结束尚未完成的执行，不回滚已投入材料、已学进度或已经交付的结果；教师离开可以结束当前授业段，双方目的和后续约定按自身规则保留。新增同类配方/法门不要求在World写具体名称分支，新增真正宿主仍须显式组合与恢复校验；“World里零match”不是交付指标。

### 5. 社会联系、组织、事项与授权：补明确责任，拆清Society

**源码依据：** [Society](../../../scripts/sim/kernel/society.gd)的独立`STATE_FIELDS`只有`waits`；施工`commitment`是单人物临时记录，未形成成员、任职范围、共同事项或物资授权。不能靠给人物添加“执事”“师父”标签完成这些关系。

需要维护已成立的联系及其认可范围、组织/成员、职位与任职/职责范围、住所与服务安排、已受理事项的版本/份额、真实办理依据及有限消息。职责与任职者分开，个人感情与已成立约定分开；制度记录表达谁认可、谁有权办理什么，不充当全世界统一法律或道德裁判。

**状态与接缝：** 社会领域owner保存共同记录和许可，物品owner保存实际位置/数量与必要关联，个人认识保存自己知道什么。接单、变更、部分交付、签收/结清由有权办理的入口按版本与份额采用，消息只传实际提交且已送达的内容。任务结束不自动结清责任；同一教学结果可以支持师生个人目的和已约定的教学职责，但同一份支付或同一责任份额不能重复兑现。未知损失和逾期本身不证明侵吞或恶意。

**消费者与验证：** 宗门任职/公库、师徒教学/私人委托、住所/公共服务使用共享该责任。换人或缺席后，例行授权仍可办理，需额外受理的事项可以受阻；未获知者不立刻知道远处死亡或卸任。保存仍影响后续的关系、未结事项和办理依据；死亡使部分资格不可用，不等于删除全部历史联系或让所有主体瞬间更新认识。权限限制正常办理方式，不凭一个标记制造物理不可触碰。

### 6. 物品批次、必要实例与容器访问：扩Objects

**源码依据：** [Objects](../../../scripts/sim/kernel/objects.gd)第23～84行已有稳定身份、`item_key→count`库存、容量与真实转移；换装/交换也有共同规则。当前计数尚不能表达同一物品在同一背包中的公产、私产与受托用途，装备尚无独立单件状态，移动有内容容器也未接通。

必要同质批次保存能影响合法使用/交付的归属或受托约束关联；普通无差异物资仍聚合。需要耐久、绑定或个别修持的单件才获得实例身份。物理所在、保管人、所有权与可处分用途分别成立，不能只在库存合计旁添加一份会漂移的“公物扣除量”。同质合并、拆分和加工延续约束沿[物资批次合同](../../../design/systems/appearance_and_possessions/objects.md#52-堆叠物的公私与受托用途)。

**状态与接缝：** 实物/数量/包含关系继续由Objects唯一提交，社会owner负责权属/授权与未结责任，双方用稳定引用关联；容量、索引和可用汇总可重建。移动有内容容器按实际用例补包含/容量/访问校验，取物完成时复核容器还可接触，包含关系拒绝循环；不先制作完整递归背包和液体物理。所有原料、在制和成品不得各自再存一份同一实物。

**消费者与验证：** 公私取用/代领交付、受托加工/跨人接手、装备/法宝和随身储物共同使用。中断或转托不自动把公料变成私产，不瞬移余料；部分转移返回实际批次和数量。恢复核物资守恒及约束引用，未知或过时的账目仍只是记录。当前owner顺序提交已经避免同刻两次无条件扣同一份库存；按量预留是否必要，要按保证供货/减少扑空等实际语义选择，不能把所有拿取都升级为独占锁。

### 7. 可定义生产、转化与设施服务：扩原过程能力

**源码依据：** [Facilities](../../../scripts/sim/kernel/facilities.gd)已有工位、施工工期与设施效果，`finish`中的做饭仍是固定`2 grain + 1 water → 3 meal`；[Society](../../../scripts/sim/kernel/society.gd)中的学习修行也绑定单个示例。Nature的生长/养护已经有自己的过程，不应再复制一套植物计时器。

共同制作需要可定义的投入/可用工具与场所、操作投入或自动阶段、真实进度/阶段后果、产物/副产物/损耗和能力消费者。烹饪、炼制、加工的相同机制共用，特殊火候/品质等仍可在受约束的领域脚本实现；只换一个配方不重写AI或执行器。设施服务可复用参与、耗时和结果合同，不把教学、植物物候与全部生命过程一律改成配方生产。

**状态与接缝：** 设施、工地或可移动在制物承载实际在制状态；操作者当前任务只引用它。已投入、尚可原样取回、已转化、实际产出和损失分别表达，不用成品数量倒算全部耗料。人工阶段按实际参与推进；无人值守阶段按定义的到期/环境条件推进。学习进度仍归掌握owner，作物物候仍归Nature。

本项增加的是转化/产消规则及其真实状态，生命周期复用第4项原活动合同，不另建生产调度器。不同领域仍可有明确的专用阶段规则，不能因都有“开始/结束”就把炼制、讲学和植物生长强行做成同一个算法。

**消费者与验证：** 原烹饪/施工与同类新增加工共享定义和过程机制，个人自制与受托制作共用真实投入和产出。工人避险、交班、目标损坏与存读后，进度和余料有明确去向；由别人接手不重新生成一份原料或成品。真实来源与代谢/生产消耗接起来以后，再谈宗门经济是否能够持续，不能以开局发满材料代替循环。

## 跨域交接还要补什么

以上七项不要求七个新增服务。共同制作、依赖失效、恢复、观察和诊断沿现有管线接入：

| 边界 | 需要随共享能力扩展的合同 |
|---|---|
| 定义与开局 | 定义→校验/冻结/签名；状态与初始装配分开。迁出World/Society/Livelihood里的演示赠物、固定老师和具体功法装配，让正常开局引用共同机制；Resource不是运行态黑板，也不必把已有JSON全部换格式 |
| 生命周期与有关变化 | 复用受控创建/移除、原run/目标清理和唤醒；只使有关缓存/候选失效。按实际规模补依赖索引，不先造全世界事件总线。技术上不可用与角色获知原因分别交接 |
| 结果与履责 | 真实领域结果直接关联有关活动/事项/份额；完成依据仅保存必要寿命。重试和读档不重复扣费/产出/记功，一次合法结果可以被多个不同目的使用，不做“全世界每个结果只能消费一次”的错误去重 |
| 恢复 | 扩Persistence候选验证：主体能力来源、掌握、目标→方法→P5任务→原run、参与者、在制物、事项份额与批次关联。活动可用引用和历史来源引用区别校验；不因旧老师已死亡就拒绝一个合法学习历史 |
| 可知表现与诊断 | 普通Frame只投影玩家可知内容、实际回报与有依据的失败；开发诊断可显示目标/方法/任务/事项和主要选择原因。表现历史与日志不驱动结算，不向UI开放活World |
| 算量 | 原共同时间、事件/到期唤醒和页计算保留；较重的候选评价/方法展开从接入时就有预算、去重和可续算状态。分别看思考等待、重复失败、服务/寻路竞争与帧时，不以每个NPC每帧扫一遍全部定义证明通用 |

必须区分以下状态的寿命，字段名称在实施时确定，不预建抽象基类：

| 状态 | 为什么不能与旁边状态合并 |
|---|---|
| 本人认识与评价 | 可以过时、误判或与别人不同，不改变世界事实 |
| 持久目的与所采用方法 | 目的可以跨多次行动；方法保留选用手段、必要依赖与预算，已取物资和进度查询原owner，不能每次从头重播 |
| P5当前任务与实际run | 任务关联当前步骤；run是原宿主的一次执行，拥有其准入/费用/阶段，结束不等于达成目的 |
| 社会事项与份额责任 | 另一方仍有期待和权利，不能因执行者去睡觉或玩家接管就消失 |
| 原物、在制与实际进度 | 人换目标或换人继续，世界中已经发生的材料转移与劳动仍在 |

例如：弟子领公料后被袭击，P5切到自卫，公料仍在身上，原社会责任仍未完成。之后本人继续或有权方安排接手时，方法检查实际保管/已交部分，再把原物交接给下一人；不会靠重建任务再领一份，也不会靠取消run退款。这里需要的是几个明确owner之间的合法交接，不是再建覆盖全部领域的事务机。

## 最容易继续积债的入口

1. **World的具体内容分派及多入口准入。** 收口共同操作描述与领域适配，迁移UI/AI/命令的语义差异；保留组合根、共同时间和不同宿主的显式清理。仅把分支搬到另一个万能Registry不算改善。
2. **Livelihood的观察与固定单步优先梯。** 把可知候选、目标来源、评价和方法分责，接回P5原反馈/唤醒。只把`cook_stove`换成标签、再给新职业加一条优先级，仍没有持久自主模型。
3. **Society承载交互、学习、临时承诺并写人物杂项。** 按行动参与、掌握/成长、社会事实和个人认识划清写入责任。存放在Objects规范子记录还是新owner由实际状态规模决定，不能用文件搬迁代替schema、准入和恢复规则。

公开资料读取于本轮审查；以下是实际读取的机制范围，不是要求照搬实现或引入依赖。

| [CDDA Proficiency](https://docs.cataclysmdda.org/JSON/PROFICIENCY.html)、[Practice Recipes](https://docs.cataclysmdda.org/JSON/PRACTICE_RECIPES.html)，定义文档 | 掌握知识有具体消费者，实践可沿同类活动接入；不表示本项目必须照搬技能分层、学习倍率或上限 |
| [CDDA Items的Containers段](https://docs.cataclysmdda.org/JSON/ITEM.html#containers)，定义文档 | 盛装能力、容量与访问条件可以组成物品；不因此预造其全部口袋、嵌套或液体模型 |
| [OpenRA Traits](https://docs.openra.net/en/release/traits/)、[Lua actor接口](https://docs.openra.net/en/release/lua/)，官方生成文档 | 组件能力有依赖，公开操作随能力组成；不改为逐单位Node，不引入Lua，也不把项目受信GDScript当沙盒 |
| [OpenRA Activity.cs](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Game/Activities/Activity.cs)，公开源码 | 实际读到排队/运行/取消/完成、首次执行复核动态条件、子活动及清理边界；不由旧issue推出当前OpenRA无法存读，不复制其对象链实现 |
| [Factorio FFF324的Targeter段](https://www.factorio.com/blog/post/fff-324)，官方开发日志 | 少见的目标变化通知有关依赖，避免所有消费者每tick询问；不等于NPC共享全知消息，也不证明现在必须建通用依赖图 |
| [RimWorld修补工作教程](https://rimworldwiki.com/wiki/Modding_Tutorials/Code_MendingJob)，社区Mod资料 | Job定义、通用执行步骤与专用代码配合可扩内容；仅作公开Mod接口参考，没有审计商业游戏源码或采用其实现 |

| 意见 | 独立判断 |
|---|---|
| 社会事实与个人认识分开，掌握与施展共用接入，在制进度不能只留在工人task | 采用职责划分，沿上述原owner逐步演进；不一项一个Manager |
| 活动/生产可能重复生命周期，个人run不足以核销跨run共同结果 | 采用反例：生产消费原活动生命周期，非物理的共同活动由交互宿主保存；跨run结果按原过程/阶段的实际提交去重，各参与run只关联本次执行 |
| 个人方法栈会与P5步骤重复，应删掉一切持久方法状态 | 采用前半：不存两份生活游标、不盲播调用栈；仍保留有效意向的选用手段、依赖与预算，实际物资/劳动查原owner，避免每次重选绕过限制或遗忘等待 |
| 当前执行与历史/认知引用要分开；有答复又建议死亡自动释放托管承接 | 采用引用分责；清技术占用不删除旧认识或历史来源，不把未交公料/未结责任自动清掉 |
| 复用名叫entities的owner存所有生命成长 | 未采用：[combat_entities.gd](../../../scripts/sim/kernel/combat_entities.gd)是临时召唤/生产者的归属、寿命与成员owner，不能按名字泛化为永久角色档案 |
| 仅凭OWNER_TRUTH拒绝原因直接证伪本人认识 | 未采用：技术准入可以知道不可用，人物认识仍只接实际能获知的原因；失约/人不在不能自动推断死亡 |
| 八域并扩实体/自然生命、九域分责、掌握并入心智等不同建议 | 逻辑地图显式补生命成长和社会责任；身体与掌握分开实现，实际掌握也不同于本人信念，不以表格数字决定代码结构 |
| take/put/eat无独占锁就是并发错误，百人必活锁，所有存取先加按量预留 | 未采用：当前由owner顺序提交，锁/预留是服务语义和吞吐取舍，应基于具体争用测量 |
| suspend清施工commitment就是人生目标被删的现存bug | 未采用：当前临时施工约定符合旧合同；新持久目标/责任接入后才扩控制交接 |
| World零具体动作分支、全部心智/成长字段迁出Objects、身体病理复用Effects等建议 | 选择性采用职责与输入收口；不以零分支或文件搬家为指标，专门病理规则不强塞Effects，资源访问统一也不要求同表存储 |
| 一层前置或固定1～4步足以解决全部人生工作流，固定24小时/帧率为门槛 | 未采用：按真实方法的必要依赖和预算限制，按实际源耗/职责周期选择验证，不能用未测常数替代设计 |
| 木愈顺便扩为医治他人/持续旧伤，立即加惩罚配给或所有工位排队 | 未采用：已有内容作用范围不擅扩，特殊制度和新作用要有真实用例再设计 |

同类机制的新内容应配置已有能力，新的特有机制仍需写领域实现并接共同合同；不存在填表就能实现任意玩法的承诺。百人宗门是这些能力在同一持续世界里的组合验证，不是制作若干小demo后把人数乘起来。远区代算、完整经济/工艺树、婚育轮回、外交战争、可视化编程平台与战斗打磨继续后置。
