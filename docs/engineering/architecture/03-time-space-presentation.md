# 当前代码架构与边界：时间、空间、行动与呈现

本页定位当前实现；逻辑职责见领域划分，代码结构可随需求重构。

## 时间、空间与行动

领域分工按[顶层框架](05-framework-domains.md)：地块/结构提供真实空间事实，单位行动根据身体能力判断通行、维护路径和执行移动；认识与自主决策提交意图，领域执行器提交实际效果。动态路径失效、重规划、多格净空等属于行动框架的内部能力，不能单独充当顶层建设目标。

- 模拟依共同整数毫秒和有名边界推进，分钟需求用保存的固定点余数。预算耗尽保留已准入target/欠算；主时钟按[运行流速](../simulation-pacing.md)统一降速与限制未来准入，不把未准入现实时间变成追赶债务。宿主由`GameClock`调度，领域视图只呈现。
- 跨区写入前同步有关区域，近远区共享原事实与规则。安静区间可批算，战斗/环境等已接细步不能冒称全部事件化远区完成。
- 同刻先结旧区间和既有过程，再形成未来决定；冲突先收集线索/命中再提交，后处理者不提前看见别人刚决定的起势。
- `SimSettlementKernel`在装配时编译阶段/依赖并注册边界，`SimWorldSettlement`把原领域按原同刻顺序接入；运行中保留工作游标，完整阶段后才发布时刻。`settlement.contract()`是实际调用图，`schedule_contract()`仍是公共分类目录。地区生活决定保留其内部顺序；原资源争用和同时命中由相应owner处理。完整合同见[共同结算](../settlement-contract.md)。
- `native_interval/native_actors`是同一个kernel的首阶段：相关人物的连续量和已受理路段可交给CPU worker，原身体按序采用；待计算与其余阶段沿同一pending/发布/存读保护，不建立第二套时钟或调度游标。实现见[批执行](../execution-batches.md)。
- 身体有唯一连续位置，格路/地块用于通行和放置。多格身体检完整覆盖及扫掠；动态通行组合静态地图、真实墙门和兽身，不把视图瓦片当碰撞真值。
- `SimGridNavigation`复用Godot AStar2D，`SimRouteTravel`在受阻的共同边界重评原路段；原owner保留ID、预约和效果。工作、交互、战斗沿同一原身体/时间/中断接缝，战斗另持起势、飞行物和命中；完整接口与容器搬运见[行动合同](../object-lifecycle-contract.md#共同执行合同与领域过程)。

**选型边界：** 用户已撤回“全对象格位置权威、移动动画纯视觉”的临时结论，要求先研究成熟项目。当前 `SimLocalMotion.position` 与 `SimRouteTravel.project` 的连续位置仍是原身体真值并参与碰撞/行动，代码保持原状；不能因未定方案把它定性为应立即迁入的错误。整格/子格、占地、碰撞和插值分别评估，最新概念边界见[空间规则](../../../design/rules/objects-and-interaction.md)。
- `owns_for_scope`只读各域原占用，不是新增锁镜像；动作可占不同控制/执行通道，不能强行把所有生命压成一条全局动作轨。
- 当前基础先使用平面地块，本轮没有新增高差系统；旧档不因包含高度/飞行记录而获得迁入例外，普通入口的版本拒绝范围见[兼容性](../compatibility.md)。

## 输入、认识与呈现

输入提交意图，领域在实际开工/完成前复核原条件。界面只显示本人已知/眼前可见投影，诊断可全知但不写入角色记忆。接收者理解、意愿、能力、资源、控制与真实结果各自成立；未来AI只是表达/计划入口，不能绕过规则。

`HumanoidPose`读取原身体和过程；共享外观采样与分层不拥有物品或业务状态。八方向合同保持解剖左右，当前像素技术样本不代表所有体型/服装/动作已完成。绘图持有同一次观察的会话引用，调试器重入读档时不能混用两代世界。`WorldContinuityRuntime`管理的`CommittedWorldCanvas`在时钟推进期间合并普通刷新请求，在最后的完整发布入口同步捕获一次；渲染只回放参数。暂停操作、可见性变化及读档仍立即捕获，不按游戏毫秒去重，也不在延后绘图时读取下一次未完成的世界。

人物视图只求值已受理路段；格和可见性与该次已提交位置一致，不能读较早的积分锚点格；身份解析和绘制不调用全体人物同步。同格人物不做画面挪位：已删除拥挤环形偏移及其CPU批，重叠者可在开发检查列表分别选中；这不是新增人群碰撞/避让规则。玩家与被选人物的需求通过`projected_actor_needs()`按相同原输入公式只读求值，未选身体不为HUD复制需求。NPC节点以Godot原生变换显示插值位置，移动不重新执行衣层/文字绘制；`Pawn.project_position()`接收已提交目标，`publish_motion()`接入原呈现段。玩家节点保留已提交坐标，绘制时将插值偏移加入身体、阴影与文字的局部坐标；外层`draw_set_transform()`会被分层绘图覆盖，不能用它承载整个玩家的位移。相机读取同一`presentation_position()`；身体真值仍在模拟owner。

物品的地面外观、重叠偏移与可见性由`WorldObjectsRuntime`在完整边界捕获；暂停事务由原`object_lifecycle.committed`及`artifacts.space_reset`通知，换世界重绑，视野变化沿原fog通知。携带物用`object_marker_view.gd`保留外观，只在每帧读取holder的`presentation_position()`更新Node2D显示变换；外观与地面图标共用绘制函数。它不访问物品owner或决定保管/可见性，holder失效即隐藏；物品放下、移除、失去视野或换世界时清理旧节点。玩家主动引物的连线仅读取已捕获端点和显示节点，进度仍来自完整边界。该做法复用Godot的[保留绘制命令](https://docs.godotengine.org/en/4.7/tutorials/2d/custom_drawing_in_2d.html#updating)，不为平滑跟随重新查询整片世界。

携物位置查询复用原身体`rule_actor_position()`取得当前已受理位置，不为一次位置读取积分全部需求；未知路线仍由原查询处理必要修复。一次视图构建复用已经读取的cell。衣着派生值、身体发布和人物回调的减量方式只维护在[计算接入](../execution-batches.md#宿主交接与呈现)，不建立第二套人物或物品坐标。

当前开发HUD由`DevelopmentInspectionRuntime`在完整边界读取原环境和选中单位，向`GameHUD`及`DevelopmentInspectorPanel`发布脱离owner的数值。静止指针/单位最多4Hz刷新；鼠标切格只读单格地形与环境，悬浮信息不用空间对象扫描；每帧只更新提示的屏幕位置。所有提示Control忽略鼠标，UI上收起悬浮。数据包含采样时刻，后台忙碌时保留最后快照，不补造角色认识。

普通世界左键由`Main`路由给`WorldUnitPicker`，复用[空间显示候选](../object-query-contract.md#实时局部空间)、`describe_object`和原可见图标命中方法；身体按显示位置命中，墙/家具按高程投影后的占格命中，屋面和蓝图次序靠后。命中半径按缩放换算，候选窗口包含身体/高差抬升。固定场所仍是原记录，地块不放入单位候选。候选失败保留原选择，不当作空地；成功后按单位引用保持选择与重叠切换。失去视野时收起对应实时单位数据，记忆影像不提供隐藏真值。点击只选择；显式打开操作才交回原领域复核，动作权限、耗时和消耗不在检查器实现。

`ReolSimulationHost`在worker忙碌或主时钟尚待发布时保留输入，只在完整交回且主时钟不再pending时重放。缓冲鼠标同时保留收件时的世界坐标，GUI继续使用原屏幕坐标，镜头移动不改变已经点下的地点。各领域不再自行监听普通左键，显式施工/画笔模式保留；后续命令整合见主计划。

`FogOfWar`区分未探索、当前可见和已探索未见。`FogVisualMemory`仅保存曾见格的固定外观元组：建筑/家具/屋面、植物、地面physical实物与两聚落场所组件；包括位置、轮廓/阶段等绘图参数，不含健康、库存、命令或世界对象副本。可见格更新或清空该层记忆，未见格保持；所有固定影像在fog下方绘制。人物、动物、运粮者及飞行效果仍须当前可见，不冻结成留影。各视图复用原完整边界画布，重放缓存不访问隐藏owner。探索存档同时保存这些外观，并在候选阶段验证格式、范围和已探索归属；读档不会从隐藏的最新实体倒推旧影像。
