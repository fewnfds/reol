# 普通世界环境与调度合同

本文记录普通世界的环境接线。当前工作状态和验证证据以[接续](../status/handoff.md)为准；已定玩法规则见[环境规则](../../design/rules/environment.md)。

## 所有权与范围

[RegionalSimulation](../../scripts/sim/regional_simulation.gd) 装配一个 [SimWorldEnvironmentFields](../../scripts/sim/world_environment_fields.gd)，通过运行字段 `environment_fields` 提供给普通世界消费者。它是当前普通世界室外实际温度和五行环境响应的唯一环境域；气候、天气、身体、植物、器物、库存和共同时间继续由原领域持有。

当前存档的 `local_heat` 是保存数据键，由 snapshot codec 映射到运行时 `environment_fields`。`ReolContentDB.local_heat` 和 `data/definitions/local_heat.json` 则保存热设备参数定义，不能把它们当成运行环境域或自动重命名存档数据。

- `SimEnvironmentTemperatureState` 保存已受来源影响格的实际温度及响应锚点；`SimEnvironmentPhaseState`保存这些格的五行响应。来源离开后，已产生的残留属于环境状态，不能根据当前物品倒算历史。
- [SimWorldEnvironmentBackground](../../scripts/sim/world_environment_background.gd) 保存气候区共享背景的响应段，供尚未受来源影响的格查询；它随世界环境共同时间推进，不拥有另一套独立时钟。
- `SimEnvironmentGroundField`/底层缓存保存从原对象派生的来源槽和基础目标；变化后相关块更新，来源索引及缓存可从经校验的原物重建，不是实物、温度历史或另一套存档权威。
- `SimEnvironment`负责人体暴露的有限采样，草木资源沿原采样入口读取同一环境域的温度投影；人物身体与植物状态仍归各自原所有者。`elements_at`提供当前五行影响查询，不代表所有修炼或生态玩法已经消费五行。

普通新局在内容、地图和原物装配后激活来源。来源定义随内容包绑定；活跃地面独特器物、同类材料堆和代码支持的非人物固定位置器物可投影为源。一个多格物仍只是一份原对象；同类材料同堆的数量不会乘大源强。人物及其随身物整体对外发源、遮掩或容器透过率尚未实现；没有发源不代表已经模拟遮蔽。植物通过原`SimPlants`和共享来源profile接入；鸟类和墙材的普遍发源尚未接入。

## 场与响应

每个已定义来源按圆形欧氏距离衰减；五行逐通道取最大，热侧与冷侧各取最大再按等级相抵，转换为相对当地气候的温度目标。实际温度/五行沿共同时间从保存的锚点逐渐趋向目标；移动、移除或关闭后旧处残留继续响应，不会立即清零。共享的接收端潮汐来自世界种子、位置及时间，不逐件创建独立计时器。具体曲线和量化参数是可调实现，不是严格热力学或总能量守恒模型。

`next_boundary_ms()`收集背景、响应段、临时来源到期及固定热设备剩余容量边界。已存在的固定设备仍由原器物持有储热量 `stored_q` 和开关 `enabled`，实际出入与开关在原世界时间结算；旧有暖身动作的临时来源有明确时限和回执，不将携带物整个登记为持续源。

领域持有[通用参与索引](sparse-execution.md)：设备处理当前参与者，响应刷新到期块与域，来源提交使触及范围的截止摘要失效。干净基础场按实际变化格/通道准备响应，冷块先证明旧值，无法证明则回退。索引从原响应锚点和器物重建，不进入存档；集成与证据见[技术总表](../status/technical-status.md)。

`actual_at(cell, at_ms)`、`project_tenths`及`elements_at`依各自合同查询已提交范围；忙碌、缺失、时刻不受支持等必须区别于真实零值。采样是实际环境对受体的投影，不授权玩家知晓隐藏来源或属性。

当前模式为`outdoor_fields_v1`：墙、门、屋顶仍用于原有围合、碰撞、遮挡和其他相应规则，但**不阻隔或衰减此冷热/五行场**，也没有按房间求平均的一房一温。热墙、冰墙、开门换气、家具材料和房间继承温度不是本实现已完成的规则；不可把施工时的热时刻预检当成隔热效果。

## 原物变更与同步提交

[SimWorldEnvironmentSourceParticipant](../../scripts/sim/world_environment_source_participant.gd) 使用档内来源定义和原实物/库存/位置构造派生引用与来源候选。普通生命周期支持的`spawn/move/remove/stock_transfer`及旧器物转移使用对应候选；具体合法性、预约、耗时、权限和原物状态仍由[实物生命周期](object-lifecycle-contract.md)及相应原领域负责。

典型路径是：同步相关区域到已提交时刻 → 结算旧环境区间 → 按旧/新原位置和定义准备来源与温度/五行候选 → 检查原世界、时刻及候选仍有效 → 同步写原物并发布环境候选 → 写原动作结果/回执，最后通知外部观察者。准备或原物变更失败时取消候选；已发生的时间或既有动作成本按原领域规则处理，不擅自退回。原器物设备启停也先准备来源变更，再在同一无观察者的提交段切换状态并发布。

该协议只覆盖接入的受控路径，不是对公开Dictionary任意直接写入的通用隔离或安全沙箱。来源事务当前在调用中同步准备局部候选，受显式工作/容量边界约束；不能据此承诺每帧无卡顿、任意密度可实时运行或 GPU 已加速此事务。

## 共同时间与调度目录

`SimWorldSettlement`将环境及现有领域接入[共同结算内核](settlement-contract.md)。环境场在previous_interval先结清旧区间，来源/动作随后按原依赖提交；中途续算不重复旧区间。`settlement.contract()`给出实际编译图，`schedule_contract()`保留公共分类目录；区域、路线、消息和草木仍提供相应额外边界。

推进以共同整数毫秒和既有阶段顺序为准：处理手动移动与相关区域推进；结算上一段环境及已有过程；处理途中进度/抵达；结算物品与其他当前过程；采样草木、考虑未来行动并处理消息和运输。旧封闭开发会话不能再向普通新环境世界绑定 guard；普通事务通过当前环境参与者提交，目录不是允许随意跨阶段提交的事务保证。预算不足保留`target_ms`所表示的时间积压，不能把未完成的目标当成已发生的世界事实。

## 普通存读和失败

[WorldEnvironmentFieldsState](../../scripts/persistence/world_environment_fields_state.gd) 捕获模型标识、定义和设置digest、响应时间/锚点、背景、临时来源、设备切换回执及必要采样。恢复在独立世界候选内校验原对象、来源、响应目标及时间，重建派生场后才能让联合候选替换活世界；失败丢弃候选，不改活会话或原档。

当前环境状态4，普通根/区域/内容包版本和拒绝原因由兼容政策统一维护。缺完整事件/植物因果、旧建筑或旧环境的根档明确拒绝，不补造或自动回滚世界；低层保留的旧格式校验/历史代码不构成普通迁移支持。[兼容性](compatibility.md)给出具体边界。世界时间有未结算积压、环境候选未完成或处于不允许捕获的提交阶段时，普通保存不能将它伪装为完整完成点；允许的原进行中动作依现有格式保存并在恢复时核验。

普通运行的来源变更与目标刷新目前为同步 CPU 路径。此前的[地面缓存计算服务](environment-ground-cache-contract.md)有单独 CPU/GPU/auto 接口，不能把隔离样本加速当作普通Main已经启用GPU选项。端到端帧时、恢复、内存和不同规模来源变化须以实际工作树、硬件及测试结果核对，未验证前不承诺性能。
