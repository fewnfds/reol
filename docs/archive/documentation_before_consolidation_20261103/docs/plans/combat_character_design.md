# 战斗、修行与纸娃娃：详细设计与实施拆分

> 2026-11-03用户已授权持续Goal实现游戏，覆盖此前仅设计限制。当前实际进度以[BASELINE](../BASELINE.md)为准；下列未实施的动作/穿戴/学习细节依然需要逐包验证。

> 同日最新[世界总纲](../../design/systems/self_consistent_world.md)与[世界先行W0–W7](world_first_sandbox.md)修订优先级：本页仍是适用领域的人形动作/穿戴/学习设计，不把六衣位、四快捷招式、心神4、40节点当世界本质。先在可靠基础上验证不同生命、有限认知、器物与跨域创造，不以完成C0–C7为其前提。

日期：2026-11-02。状态：**详细设计与交叉评审已完成，待原型验证；游戏功能未实现**。用户本轮明确选择“先完成详细设计，暂不改游戏代码”。后续实施仍按独立工作包推进，不把这份文档当批量开写全部系统的指令。

## 1. 新的方向约束

用户明确：现场战斗可借鉴Hades、DNF、英雄联盟、魔兽争霸；装备重点在纸娃娃换装与社交表达；非战斗者、非战斗型修士有完整生活；成长借鉴PoE大型天赋网络，但没有预先锁死的职业，人物由学习、选择和经历形成。

据此形成三条分工：

- **人物的本领**：身体/境界、功法、招式、知识、熟练和经历分别表达。
- **穿在身上的东西**：实际物品、用途、防护、审美和身份线索分别表达。
- **具体交战**：距离/时机/地形、准备、资源、目标与协作，决定某次行为的结果。

装备可以有真实功能和强力特殊器物；不能让所有服饰都成为攻击力、暴击和伤害加成载体。成长图可以广阔；不能把所有人生路线变成同一套杀怪经验购点和职业转职。

## 3. 当前代码能接什么

现状依据 `scripts/entities/player.gd`、`pawn_visuals.gd`、`data/pawn_state.gd`、`sim/village_simulation.gd`、`inventory_ledger.gd`、`autoload/game_clock.gd` 与现有runtime快照边界。

| 现状 | 接入时必须解决 |
|---|---|
| 玩家连续手动移动，NPC/日常由分钟tick与格子动作推进 | 共同时间与格内位置；不能主角物理帧掉血、分钟模拟再覆盖状态 |
| Actor记录和PawnState显示已有qi/stamina/energy等字段 | 明确唯一持久负责人；不能往双方各加HP并靠每帧互抄修补 |
| 物品是容器内按字符串计数，含预约和转移 | 保留堆叠账本，增加独立实例及唯一位置；穿戴表只引用，不能再持有第二份物品 |
| 人物只有共用几何衣色/发髻 | 外观根据真实穿戴组合；先代码分层占位，不同时制作完整动画库 |
| 已有个人认知/来源、机构账本与权限 | 服饰观察输出有限线索，原授权仍在办理时核验，不能服装标签直接改任职 |
| 双聚落共同时间/远区边界/联合快照已工作 | 战斗第一版即离场无头接续、完整快照；高效粗算后置，不冻结 |
| 尚无完整战斗/学习/穿戴或独立装备状态 | 不把已有qi/stamina字段、身体剪影和继任原型算作这些功能已实现 |

## 4. 状态、规则和显示怎样合作

```text
玩家意图 / NPC已知目标
             ↓
     行动选择与唯一执行权
       ↙       ↓        ↘
    战斗阶段  穿脱/持物  学习/练习
       ↘       ↓        ↙
   原人物身体 + 实际物品 + 已学本领
             ↓
   世界事实 / 有限观察 / 正式凭据
             ↓
   纸娃娃、前摇/效果、人物卡与修行图
```

### 4.1 唯一持久状态

| 数据负责人 | 持有 | 只读/引用 |
|---|---|---|
| 人物身体状态 | 所在地、格内位置、健康伤势、短时体力、灵力、长期精力 | 定义、本领和物品，派生能力按需计算 |
| 行动执行/战斗上下文 | 主动作阶段、目标/方向、时间、位移约束、持续效果/命中去重 | 原身体和容器；不复制第二套HP/库存 |
| 物品/位置与权利关系 | 堆叠或独立实例、状态、唯一容器/附件位置、合法权利依据 | 穿戴/手持视图只引用实例ID；背包“全部随身”是查询 |
| 本领与准备状态 | 已知线索、已学内容、进度、准备招式、运转方案/心神占用 | 功法/图节点定义、师承证据、原qi/stamina |
| 社会与机构 | 个人观察/记忆/认知、请求、任命、正式许可和公账 | 不从物品价格直接推全体好感 |
| 纸娃娃/战斗视图 | 可重建的图层、锚点、缓存、插值和提示 | 读取上述事实；不拥有命中、物品或权限 |

动作可以声明移动兼容性，例如边移动边护持；仍由同一执行器协调身体，不开两个互不知情的控制器。持续术法可与主动作并行，但必须显式占用资源/心神并有中断规则。

### 4.2 三系统互相查询的契约

- 用某招前查询已学/准备、当前身体、实际持物与占用。失去兵器后不能继续用该媒介的招式；若学过徒手变化，可明确改用，不偷偷保留原兵器射程。
- 换衣只改变实际穿戴与相关派生用途，不改学会数、功法、健康、当前冷却、正式身份。最大资源真有变化时保留当前绝对数量并钳制到合法上限，不按比例回满。
- 重配需安全准备时间与兼容条件，冷却按人物/冷却组保存；法器自身的消耗/冷却按实例保存。切出再切回、丢下再拾起都不归零重置。
- 主功法和兼修、护持、御器等统一从一个心神预算查询。普通手艺已学会就可在适用条件下使用，不为做饭、认路都要求挤掉战斗槽。
- 观察服饰/出手只产生观察者能推断的部分；调试字段、隐藏防具、未展示招式与全部修行图不会自动成为对方已知。
- 私人物权、借用用途、钥匙、制服、腰牌与机构任命互相可关联，但没有自动等号。成功穿上执事袍不能令公仓查询返回有权。

## 5. 实施次序：与长期路线对齐

这不是要求先做完整P1/P2才允许测试一剑。可以先做隔离动作/纸娃娃试验回答风险；正式接世界时仍补齐依赖，不用临时状态成为新的权威系统。

| 包 | 目标/最小范围 | 依赖与文件边界 | 出口证据 |
|---|---|---|---|
| C0 共同时空试验 | 短动作、分钟消息、连续位置、暂停与1/2/4倍；原日常同一时间 | 长期P0，时钟/区域调度/运动适配；先小试验再定单位 | 旧双聚落回归、跨分钟存读与同刻顺序；记录ADR |
| C1 实例与换装骨架 | 堆叠＋实例，6个衣位先接其中3个，基础服/工作服/礼服与一件手持物 | P1实例与现有库存；sim规则、原图层表现、候选快照 | 唯一保管/穿脱中断；三套外观可辨，换衣无战力词条/资源刷新 |
| C2 基础动作决斗 | 4动作、两种简单敌方反应、健康/体力，约3–5名参与者 | C0，P3纯规则战斗，原地形和身体持有者 | 走位/格挡/停手可读；命中扫掠、取消、暂停和离场无头继续 |
| C3 学习网络小片 | 8–12节点，两个跨域连接，一名老师/一本入门资料，练习与安全准备 | C1/C2，P4学习，已有知识/请求/真实时间 | 拿到书未自动学会；学剑与护持可组合；非战斗练习有效且不需杀怪 |
| C4 技能与伙伴 | 扩投射/控制/护持/急救，4快捷招式、1伙伴，心神/资源协作 | C2/C3、P3小队与医疗供给 | 撤退/护送/救助，与角色各自本领/物资相称；不能永久连控 |
| C5 外观与社会 | 扩到6衣位/13样本，有限识别/核验/洗护 | C1，已有社会与机构；P4交涉，P6复杂核验后续 | 礼遇与实际权限不同；换制服可影响判断但不能打印许可 |
| C6 开放修行内容 | 扩8域40节点、少量功法/器物和混合路线 | C3/C4/C5通过，小型数据内容校验 | 至少3条非战斗路线和3条混合路线各有成立行动/代价 |
| C7 世界闭环与规模 | 供给/责任、完整接续、远区粗战及20–30人目标 | P5–P7，已有生计/消息/组织与动态地区 | 真实断供/死亡/借物/继任有后果，精度切换不复制和重抽 |

C0–C6是跨长期阶段的主题拆包，不取代P0–P10，也不提前承诺新工期。C1和C2可在接口明确后分别做原型；先每包跑通再合并。正式美术继续在P9，前期用代码轮廓/图层/有限声音验证动作和换装。

### 5.1 首次可玩原型应该能做什么

在既有世界边缘的安全校场/独立测试fixture中，用真实人物状态和明确起始物品验证：穿三套不同常服，练一次招架，学习一个护持动作，主角与伙伴应对两名风格不同的对手，主动撤退，途中保存读回。

正常世界的校场需要比试同意、非致命动作与停止规则；测试fixture可以独立重建用于重复测试，但不能把“重置测试”按钮当世界中的免费回血/复制装备。原型还没有完整供给/社会后续时明确标记其范围，不假装一场校场已经完成开放世界战斗。

## 6. 未来定义和持久化的必要字段

只列规则需要，不在本轮预建JSON、脚本或空场景：

| 定义 | 必需语义 | 运行实例需保存 |
|---|---|---|
| 动作/招式 | 获取条件、可用媒介、阶段、形状/高度、成本时点、取消/中断、冷却组、目标/友伤规则 | action_id、参与者、锁定意图、阶段/时刻、已付成本、已命中对象 |
| 功法/持续效果 | 运转条件、资源流、兼容、心神、停止和代价 | 来源实例/人物、开始/结束、占用、剩余和已提交脉冲 |
| 物品/穿戴 | 堆叠规则、用途、占用/覆盖、形态资源/锚点、质量的实际意义 | 稳定实例、唯一位置、损坏/染色、必要来源与权利引用 |
| 修行节点/教学内容 | 所属领域、可见线索、路径、前提、学习机会、规则效果和取舍 | 人物所知、来源、学会/练习进度、证据引用、准备方案 |
| 观察/身份主张 | 线索/距离/光照、所需知识、核验渠道、失效/更新条件 | 谁看见/认出、何时、来源、判断上下文版本 |

堆叠材料不为每份生一实例。模板定义只读，保存资料的内容版本；人物持有书卷/秘本和脑中所学分别存。缓存、描边、粒子、UI排序不是权威状态。

新字段引入同包就有schema、合法范围/引用检查、旧格式迁移或明确拒绝策略。必须支持进行中的挥击/符术、半完成穿脱、借物、已学/准备/冷却、飞行物、观察与未结世界责任共同恢复。坏档在独立候选拒绝，不能只恢复衣服丢掉借用债务。

## 7. 整体验收：不是三个菜单各自能开

全部为未来验收。领域细节分别见三个设计文件，本表验证相互配合。

| ID | 场景 | 通过标准 |
|---|---|---|
| CC1 | 同人同招同兵器，分别穿素袍、工服、礼服 | 衣色/价格不凭空改攻击；用途、防护/负担和社会线索各自可解释 |
| CC2 | 不会剑术的人借到名剑，学过剑术的人拿普通剑 | 器物有实际长短锋刃/功能，熟练与招式不同；不自动授整套技能，也不保证普通剑必胜 |
| CC3 | 药师、工匠、商旅各完成一次自己的局势 | 有生计/成长/求助/避险，未点攻击盘仍能生活；守卫和物资真有来源 |
| CC4 | 看见剑术节点但没有教学；读书、观察、练习和实战后再学 | 图连接不是付点解锁；每阶段学到什么/缺什么可查，木桩/杀人不能刷所有领域 |
| CC5 | 学会多招，准备4招并运转功法/护持/器物 | 学习数与同时运转分开；超预算/不兼容有解释；非战斗手艺不挤战斗栏 |
| CC6 | 衣物被借走/武器被缴械，中途读档 | 同一物品唯一位置；外观/可用动作更新；借物责任/冷却不丢失 |
| CC7 | 乔装守门→进入接待处→申请支取 | 不同观察者可先信或核验；公仓仍查真实许可；熟人不因换衣失忆 |
| CC8 | 受伤、穿脱、修补、切换功法、投掷后丢拾法器 | 没有回血、回灵、刷新冷却/符纸或失物责任漏洞 |
| CC9 | 重击前摇、短缓冲、招架、连续控制、救助 | 前摇/范围可读；正确回应有效；无无限连控；救治有资源与中断 |
| CC10 | 调整服饰图层/帽高/LOD/缺帧回退 | 只改表现；碰撞、射程、人物身份、隐藏信息与装备事实不变 |
| CC11 | 暂停下令→等待快进→受袭→切区/重启 | 一个世界时间；世界事务连续、危险在边界打断；已提交结果不重抽 |
| CC12 | NPC在玩家缺席时学习、换衣、护送、战败 | 依自身所知/资源行动，有因果可追踪；不因入场重新装备/治疗/生成资产 |
| CC13 | 宗门管事在冲突中失能，仓库有旧账与借物 | 预约/职位清理或代办，基本生活可接续；机构和私人物权没有随身体删除 |
| CC14 | 导出测试包下多套衣服/技能/中文说明 | 资源族匹配、动作关键提示不被遮挡，无开发机器字体或节点路径依赖 |

首原型C0–C3先选对应子集，完整C7才要求全表；每包增量证明其承诺，不用“未来还要做”免除已开放行为的失败/存读边界。

## 8. 怎样判定这套设计是否有趣

作者自测先回答：能否靠看招与行动改善结果；停手/退让是不是有价值；伙伴不是纯增加血条；换衣是否表达生活又不过度强迫；修行图是否让人想到下一步去学什么而非只找最短加伤路径。

之后让未读方案的人完成三个短任务：赴会交涉、护送受袭、为一个实际问题学习新本领。记录他是否知道为何遭拒/受伤、如何换装/改准备、是否觉得非战斗路线被迫补攻击装。人玩不明白时先改信息与规则，不先添100个节点。

## 9. 设计风险与最小处理

| 风险 | 最小处理 |
|---|---|
| 五个参考作品互相拉扯 | 只取动作衔接/可读性/指令/网络结构各一层；统一正交俯视和共同世界 |
| 无职业最后变成万能全学全开 | 学习渠道/时间机会、训练与准备/运转取舍共同作用，不用出身锁定；普通手艺无需遗忘 |
| 社交穿衣变成全世界魅力评分 | 只给观察线索、场合判断和实际核验，不把衣价自动折成人情/权限 |
| 外观为主被误解成防具毫无作用 | 有真实覆盖/材质/负担，特殊法器有功能；普通衣饰无通用攻击词条 |
| 持久伤亡破坏动作游戏试错 | 先受控切磋与倒地/撤退；危险有预警，普通模式可存读，不靠无原因满血重生 |
| 图很大但内容空 | 第一包8–12节点验证学习/生活，40节点是首内容集预算，完整大图按实际选择增补 |
| 秒级战斗与分钟模拟各走各的 | C0先做共同整数时间/格内位置/旧档迁移试验；正式数值在结果后确定 |
| 多套战斗/物品/社会真值失步 | 各领域明确负责人，runtime与UI只意图/查询；穿戴引用不存第二套实例 |
