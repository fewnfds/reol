## 1. 要做成什么游戏

一个能独自生活、加入组织、经营聚落、组织远行和卷入争端的修仙沙盒。玩家与 NPC 处在同一套世界规则里：需要生活资料，有自己的认识和目的，占用真实时间与物资；组织依靠成员、资产、制度和外部关系存在。玩家离开、失败或换身份，世界仍能接着运行。

完整游戏应支持三种相互连通的重心，而不是三个割裂的模式：

- **亲历**：一个人的生活、修炼、冒险、交往、受伤、谋生与选择。
- **经营**：有权限地安排劳动、设施、生产和分配；经营洞府、农庄、商队或宗门。
- **局势**：生产与贸易形成依赖，竞争与争端改变道路、人口、权力和机会；玩家可介入，也可离开。

这些体验通过资源、人物、信息、权利、时间互相连接。例如：宗门缺药→药师求购→商人组织采药→道路遇匪→护卫受伤→供给变少→弟子争夺分配→管事需要处理。每一步有原因、行动者和可改变的条件，不用一条“势力发展度”同时决定所有结果。

**完成目标是可持续游玩的有限世界，不承诺把所有参考游戏的内容总量相加。** 第一版完整游戏先让一套地区生活成立，再扩地貌、境界与生活方式。人类、鸟妖、寄魂者和古兽等应以不同处境检验共同规则，不能因旧预算默认三种人类出身而永久排除；逐步实现的具体范围按W包原型与试玩确定。切片中的“暂不做战争、建造、多出身”是旧阶段范围，不是永久禁止。

## 3. 用什么标准取舍

1. **先解释过程，再使用数值。** 内部允许需求、价格、关系估计与成功率；必须能追溯来源、作用对象、适用范围与实际执行者。
2. **玩家与 NPC 共用成本与后果。** 玩家可以更会规划，不能靠切换视角复制粮食、免除受伤或赋予组织全知。不同 AI 可以简化推理，规则权利不能凭空改变。
3. **命令需要权限，承诺需要履行。** 熟人可拒绝，雇工可辞职，掌门也不能让空仓发粮；制度的承认和实际强制力分别表达。
4. **有限认知。** 事实、亲历、转述、机构记录和玩家笔记分开；远方变化通过人、信件或渠道被知道。
5. **失败继续产生选择。** 缺粮、败战、受伤、失职、流亡都要有后续路径；避免每个失败都迫使读档。
6. **精度改变，责任不断。** 近处行动，远处批算；同一人物、同批货物、同份合同和同个时间线不能有两套真值。
7. **新机制必须产生选择。** 无法改变行动成本、风险、机会或关系的复杂度先删去。
8. **先玩法后正式资源。** 玩法开发仍需清楚的按钮、轮廓、预警和战斗反馈；整套美术、音乐、装饰与宣传资源放在玩法闭环后制作。
9. **本领与穿搭各有价值。** 修行网涵盖战斗、生活与协作，出身不锁职业；衣物的外观、用途、防护和社会识别分别成立，不能把非战斗人生变成刷满攻击装备的前置任务。
10. **先让众生生活，再调平衡。** 身体/载体、所知、目的与关系产生可行办法；同一作用能跨场合使用。允许强弱悬殊，优先修复复制、全知、离场重置和因果矛盾；固定面板与人形槽位不决定全部世界存在。

## 4. 推荐的完整1.0边界

以下是执行规划的**推荐默认值，尚非用户逐项拍板**。容量是测试档和内容预算，不是当前性能承诺。发生瓶颈先减少密度和无价值更新，再讨论扩大。

| 维度 | 1.0推荐范围 | 后续扩展 |
|---|---|---|
| 世界 | 有边界、可重复种子的地区世界；12–24个模拟区、约12个聚落/据点；道路、野地、资源点和少量秘境 | 更大地图、新气候、跨海与地下世界 |
| 社会 | 3–5个主要组织，组织内有职位、利益差异和对外依赖；个人可多重隶属 | 大型国家行政、多层法域、复杂宗族谱系 |
| 人口 | 300–600个持久人物目标；本地最多约60名，战斗先20–30名；大队伍以有名单的群组处理 | 千人以上目标须独立验证，不作为1.0前提 |
| 出身 | 宗门杂役、自由散修、小聚落经营者3个开局；共享同一个世界 | 更多遭遇式开局和职业专属篇章 |
| 生计 | 工作报酬、采集、农业、少量加工、交易与运输；组织不能无限发钱或发粮 | 完整金融、期货、复杂税制 |
| 建造 | 土地/使用权、蓝图、材料、劳动、通行、储物与简单房间用途；一个自营据点 | 城市美学、复杂水利/温度/结构力学 |
| 修炼 | 炼气、筑基、金丹三个可玩层次；无职业学习网络、功法/招式/生活本领组合、准备/运转、突破与师承 | 更多境界、完整飞升、极多秘传与大型图内容 |
| 战斗 | 实时可暂停；小队、撤退、士气、伤势、救治、俘虏与简单据点攻防 | 全面战争级千人实时会战、复杂攻城机械 |
| 穿戴 | 分层纸娃娃、真实物品/衣着/持物、用途/防护/借用、有限外观观察与身份核验 | 海量动作服饰、复杂隐形/幻化、无限嵌套容器 |
| 工艺 | 种植→食物、药材→基础丹药、矿料→基础装备；每条少量有差别的配方 | 百种材料、复杂炼器/风水/阵法组合 |
| 政治 | 任免、分配、利益冲突、继任、旧账处理、谈判/制裁/冲突 | 全套诉讼、自动阴谋策划、议会模拟 |
| 长线 | 生计→自立→掌握一项生产或武力优势→对组织/地区产生影响；角色可死亡，世界可用新身份接续 | 完整血缘遗传、育儿、跨世修行 |
| 内容 | 每种起点有成立的前30分钟；至少一轮约5–10小时具有不同选择的完整历程，再以长局测试证明循环可持续 | 这个时长是试玩校准目标，不用重复劳动强行填满 |
| 发布 | Windows独立包，离线运行，常规存读、多槽/自动备份、可理解的新手引导 | 联机、云账号、模组API、跨平台同时首发 |

高境界人物若出现在背景，仍须有行程、立场和可理解的行动边界；不得把“世界强者”写成堵住全部出路的无敌脚本。正邪是教义、行为、利益和组织立场的差异，不是全世界统一的道德分。

## 6. 里程碑与依赖

阶段编号用于长期方案，保留旧 M0–M5 作为历史切片术语，避免把已完成重标为待做。每一阶段内部按工作包串行收敛；独立研究、内容和评审可并行，涉及同一状态所有者的改动不可竞相写入。

| 阶段 | 达成的玩家体验 | 核心工作包 | 依赖和出口 |
|---|---|---|---|
| P0 基础可靠性 | 当前生活能可靠保存、恢复；扩大前知道哪里慢 | 测量基线、动态世界存档、版本迁移、战斗时间原型 | 不重写已有模拟；出口F0 |
| P1 生计与生产 | 不靠初始赠币，能谋生、吃住和应对短缺 | 资源来源、有限生产、工资与本地交易、需求耗尽后果 | P0存档约定；出口F1 |
| P2 建造与经营 | 有权获得土地、安排劳动，建成一个有用的据点 | 蓝图/材料/通行、储物/生产、岗位和分配 | P1真实资源；出口F2 |
| P3 冲突与小队 | 能战斗、逃跑、受伤、救人并承担损失 | 战斗时基、伤势/医疗、武器技能、小队/俘虏 | P0时间试验、P1供给；出口F3 |
| P4 修炼与一小时切片 | 一个人从杂役取得修炼和身份上的实质进展 | 功法/修炼/突破、冒险据点、动态委托、引导 | P1/P3；重验P2经营入口；出口F4 |
| P5 多区经济与人口流动 | 商旅、迁居、远行有意义，留下的地方继续生活 | 动态地区装配、价格/贸易、旅行/定居、资源再生 | P0/P1/P2/P4；出口F5 |
| P6 组织与权力 | 管事/掌门通过人和制度办事，换人会改变实利 | 任免/授权、派别目标、争端处理、继任与旧账 | P5资源与信息渠道；出口F6 |
| P7 战争与长期人生 | 多身份进入同一局势，战争、死亡与历史可以继续 | 远区冲突/补给、据点变化、人口接续、3种出身与换角 | P3/P5/P6；出口F7 |
| P8 玩法Alpha | 主要玩法已接通，持续长局能产生可理解的变化 | 内容补齐、长期稳定、平衡、信息可读与陌生人试玩 | P1–P7出口全过；出口F8 |
| P9 正式视听 | 玩法含义清楚，画面、声音和操作语言统一 | 风格样板、模块角色/建筑/地形、VFX、音效/音乐、无障碍 | F8后正式批量制作；出口F9 |
| P10 Beta与1.0 | 新电脑可安装、开始、保存、继续、完成一轮 | 缺陷清理、优化、导出、发布资料/许可/备份恢复 | P9与目标机器验收；出口F10 |

没有按日历承诺工期。一个阶段可包含很多实施轮次；完成一个工作包交出可运行构建、测试与进度记录。新发现可调整后续顺序，但不得跳过既定出口并把未解决问题埋到美术阶段。

### P0：可靠基础，先解除真实风险

- **P0.1 测量与回归固化**：独立运行当前场景，区分主线程、模拟、寻路、视野和渲染；重跑真实办事闭环。保存固定种子、硬件和测量条件。
- **P0.2 会话/世界存档边界**：给生成种子/生成器版本、探索信息、可变地形与未来建筑预留明确分区；已有持久事实仍由原模块拥有。实现当前有内容的区块，后续领域随其工作包接入。
- **P0.3 迁移与恢复**：版本化快照、最小迁移链、候选验证、坏档保留原世界、备份恢复；旧格式能迁移的显式迁移，无法可靠迁移的解释原因，禁止猜字段静默修补。
- **P0.4 时间语义试验**：在隔离最小战斗中验证细步进/分钟边界/暂停/倍速/远区消息同刻顺序。确定时间与空间单位后再写战斗正式规则；不在纯研究阶段重写所有分钟字段。

### P1：从“能花初始钱”到“能持续生活”

- **P1.1 生存后果**：饥饿、疲劳、休息和健康的有限状态；缺食有预警与救济/求助/离开路径，不用心情条替代全部行为。
- **P1.2 资源与生产**：有数量/产出周期的采集点、田地和至少两条加工链；输入→劳动/工具→产物，库存预约与失败释放复用现有账本。可堆叠耗材继续按数量记；需追踪使用/损坏的工具采用实例ID，装备/携带/出售不能重复占有。
- **P1.3 劳动收入**：雇主有预算、真实需求、验收和工资；贡献奖励与现金工资分别记录，重复交付不能重复领奖。
- **P1.4 本地交易与救济**：真实卖方库存、钱包和需求；卖出资源→支付食宿/购买工具→继续生产。商人无钱时能拒收/换物，不能无限收垃圾。
- **P1.5 有限自主计划**：短缺→选择生产/采购/雇工→执行/验收的两三步计划及有预算的需求发单。玩家不介入也有人尝试解决；按事件和失败重评，不引入无限规划器。P4再扩到寻材、修炼与冒险。

### P2：建造确实改变生活

- **P2.1 土地与施工**：使用权/侵占、占地预览、蓝图、材料预约、运送、施工与取消；落地时再查地形和通行，不在点击时凭空完工。
- **P2.2 据点闭环**：住处、仓储、田地/药圃、灶/工位；简单封闭房间与用途判定，设施受损/不可达有后果。
- **P2.3 劳动组织**：工作优先级、排班/工单、岗位能力与允许区域；自有/雇用/同门的指挥权限不同，人员过劳、缺薪或职责冲突可拒绝/离职。
- **P2.4 经营分配**：公私库存、口粮/工钱/贡献、维护与补给。代理人可负责常务，玩家出门不需要每分钟远程点按钮。

### P3：冲突产生损失和后续

- **P3.1 最小战斗**：目标选择、走位/招架/身法、前摇/作用/后摇与取消、近战/远程、施法/打断、伤害与战斗结束；按[动作设计](../../design/systems/combat_framework.md)先小场景验证，规则与表现分开。离场后原纯规则战斗上下文继续无头细算、可重入/存读，P7才增加高效粗算；不能中间冻结。
- **P3.2 人员后果**：伤势、倒地/死亡、治疗材料与照护、负重/战利品保管；同样适用于 NPC。武器/穿戴沿用工具实例与唯一保管规则；死亡当包交付动作/预约/背包/承诺/职位空缺清理，并提供最小临时代办或空缺冻结及基本生活替代路径；公账债务不能随人删除，复杂争议继任留P6。
- **P3.3 小队意图**：跟随、保持距离、集火/护送/撤退；战斗快进回1倍，暂停可下令，危险有预警。
- **P3.4 败而不灭**：求饶、缴械、俘虏或逃脱至少形成一种可继续的败战；世界不得为惩罚玩家额外生成无来源追兵。

### P4：修仙成为改变策略的成长

- **P4.1 功法与训练**：资质作为倾向、功法作为选择、修炼消耗时间和供给，师承/秘本有实际获得渠道；按[修行网络](../../design/systems/cultivation_and_learning.md)先12节点再扩候选40节点，生活与战斗本领都可成长；不能用职业锁定、杀怪通用点数或装备孔自动授技替代学习。
- **P4.2 突破与修养**：材料、环境、认知/准备、风险和伤后恢复；NPC同样可以寻材、错过机会、突破或失败。具体概率通过场景校准。
- **P4.3 冒险与委托**：一个后山资源/秘境、一个敌对据点、至少两种解决途径；委托来自欠缺/冲突，也保留少量精写入门剧情。
- **P4.4 一小时切片**：工作谋生→认识人物→争取资源/授权→修炼/突破→冒险或经营解决短缺→得到身份变化；完整存读，离场后两聚落继续变化。独立Windows试验包验证中文界面/字体分发与正常操作；正式大规模资源尚不投入。
- **P4.5 可操作的交涉**：人物会话中用模板选工作/物品、报酬、期限、风险与担保等适用条件；附条件回应后能实际修改提议并履约。提议按当事人所知形成，只有结构合法性/已确知硬条件可提前拒绝，秘密真值留执行时复核；P6复用此入口办旧账，而非只增加调试API。

### P5：走出去仍是同一个世界

- **P5.1 动态地区装配与生成**：消除仅home/river才能运行的装配假设；地区ID与全局格/路径层级明确，首区512×512不变成整个宇宙硬上限。按资源/道路/聚落/秘境约束生成并校验种子，确保三种起点可达基本食宿、生计和核心材料链；失败有限重试/可诊断回退，不生成不可玩的随机空地。
- **P5.2 区域贸易**：地区生产优势、有限需求、价格报价、路线时间/损失/补给；至少能靠一次有风险的商旅取得净收益，也可能亏损。
- **P5.3 人物旅行与迁居**：出发/在途/抵达/住址/工作转移；带走原身体、背包、知识与未结责任；迁居不在两地各生一人。
- **P5.4 人口与资源容量**：资源再生、就业/食宿容量、迁入迁出和新人来源；新增者有来历，招募/迁入不凭空附赠无限物资。

### P6：组织是可行动的人与制度

- **P6.1 职位与办事**：职责、任期/任免、授权委托、代签范围、分配和审计；制度记录的存在、承认和执行各有条件。
- **P6.2 内部差异**：少量有实际资源基础的利益团体与议题；行动由成员、预算和消息触发，不能只有抽象派系支持分。
- **P6.3 争端与继任**：调解/查账/裁决/私下交易/暴力升级；候选人有资格、支持、能力和控制条件。原继任算法仅作候选实现，先让场景结果正确。
- **P6.4 旧账与新局**：公账/私情、任职更替、履行成本、证据、担保与反制；实现“礼数仍在，收益可能拿不到”，同时给玩家申诉、找见证、谈判或离开的动作。

### P7：战争、时间和不同人生

- **P7.1 有目的的冲突**：目标、动员、成员、粮饷、行军、交战、撤退和谈和；有补给约束与事后恢复，不让所有组织永远打到灭亡。
- **P7.2 远区战斗**：同一参战名单、装备/健康/补给/地形条件和随机上下文；交接只改变算法精度，不重掷既成结果。近远不承诺逐位同轨，但战略倾向与资源/伤亡约束必须一致。
- **P7.3 人口与历史接续**：NPC寿命、死亡、接班、招聘/成年迁入的有限来源；重要事实归档，未结权利和义务保留，私人秘密不因死者消失变公共。
- **P7.4 多出身与有限转生**：多起点验证不同生活；同局主角通过有限次数的新生候选转生，范围不限人类、世界不回滚，机会耗尽结束本局。主角记忆连续与新身体成长分开，财产/贡献/权利不自动继承；加入出生来源、候选域/档位、有限刷新与防筛选测试。普通存读另行保留，不用退隐或免费新人绕过预算。详细规则以rebirth_and_new_lives为准。

### P8：玩法冻结前的系统验收

- **P8.1 完整内容通路**：三起点、三可玩境界、生活/经营/冒险的转向均可用；没有“菜单能点但规则未接”的假功能。
- **P8.2 长局与经济调参**：多种子30/365游戏日、多次切区/存读；增加临界寿命、任期/债务到期、待压缩证据的短fixture，并至少一个小人口10年以上推进案例。更长时间作降密度压力测试，检查饥荒、人口崩溃、钱粮膨胀、垄断死局、永战；不把未跨寿命边界的365日测试当世代已验。
- **P8.3 解释与恢复**：每种关键拒绝/失败/停工都有可查原因与下一步；历史能解释地区变化，开发者全知不进入玩家UI。
- **P8.4 玩法Alpha出口**：先完成作者自测，再做至少3轮陌生人任务试玩；问题形成工作包。没有用户在场也能完成自动和作者验收，但不能把作者自测冒称陌生人试玩。

### P9：正式美术与声音

- **P9.1 风格样板**：同一小场景验证草地/水/山、一个建筑、三人物、战斗效果和界面；色盘、像素密度、方向、光照和缩放一致后扩量。
- **P9.2 模块资源**：角色按身体/衣物/装备组合，设施按用途/等级/损坏组合；代码绘制、图集和可商用许可素材混用，以可读性和一致性取舍。
- **P9.3 反馈与音频**：命中/施法/受伤/施工/交付、环境音、音乐分层、音量总线和静音；反馈不改变真值，快进和批算不会播放成百上千个过时音效。
- **P9.4 素材交付**：每包有原许可、来源/版本/哈希、修改与署名；正式字体、音效、音乐同样核对，打包验证缺图/乱码/漏许可。

### P10：可发布构建

- **P10.1 性能与容量**：在记录的目标Windows机器、独立窗口/导出包测量；优化实测热点，保持规则不变量。失败先缩规模，不更换技术栈碰运气。
- **P10.2 存档与长稳**：更新前后迁移、断写/备份恢复、长局、损坏输入、异常退出后的恢复体验；固定支持版本，退出支持要明确说明。
- **P10.3 发布**：导出预设、版本号、说明、操作/新手教程、资源许可清单、已知限制；项目自身许可证及商业发行主体需用户在发布前决定，不阻塞玩法开发。
- **P10.4 1.0出口**：F0–F10验收通过，已知严重缺陷清零；可用正常操作从新档完成三种起点的核心通路，无开发工具依赖。

## 7. 工程实现方式

继续遵守 [文件职责](../PROJECT-STRUCTURE.md) 与 [当前架构](../ARCHITECTURE.md)。这里的模块名只表示未来职责，不预建空文件、空Autoload或第二套事件框架。

| 领域 | 持久状态与规则建议归属 | 场景/UI职责 | 必须接入存档的时点 |
|---|---|---|---|
| 行动/劳动 | sim行动、工作/预约 | 命令、路径查询、动画 | 引入新动作或承诺时 |
| 建筑/土地/资源 | sim持久建筑/使用权/资源状态，world只读空间表现 | 放置预览、可达/房间缓存 | 能建/拆/采的同一个工作包 |
| 经济/合同 | sim库存、所有权、支付、报价 | 交易意图与可见报价 | 首次真实交换时 |
| 战斗/健康 | sim战斗上下文、状态、结算 | 输入、插值、碰撞查询、效果 | 第一次持久伤势/物资损失时 |
| 修炼 | sim功法、训练、突破事务 | 计划和风险提示 | 首次训练/突破时 |
| 组织/信息 | 现有账本/记忆协作的专属领域 | 人物所知与合法办事入口 | 任免/传播规则启用时 |
| 世界/历史 | regional调度，领域自己的事件和快照 | 地图、聚落远景、见闻 | 新跨区事件类型上线时 |

每包遵循：设计/失败场景→数据定义与纯规则→有效整合测试→运行适配/最小UI→存档回归→实际操作与证据。**UI、存档和边界处理不能挪到整阶段最后补。** 不为了“完整游戏”引入全ECS、全事件溯源或几十个单例。

重要工程约束：

- 为行动、人物、容器、建筑、事务、事件分配稳定ID，引用关系需校验；定义只读，状态不回写JSON定义。
- 共用动作语义，按领域扩展，避免为“请求”“命令”“剧情动作”复制三份执行器。
- 随机按上下文和领域隔离；拒绝理由可解释，重复无变化请求不重掷。更改seed和内容版本需保存。
- 所有异步/长期事务都定义完成、失败、取消、死亡/撤权、离场、读档与退款/资源归属。
- 每个新增模拟领域实现`next_boundary/advance/snapshot/validate`等实际需要的协作能力；先以现有接口模式接入，不先造通用框架。
- 场景引用、缓存和局部寻路可重建；世界事实、知识来源、权利义务和随机上下文不能靠重建猜回。
- 领域定义与调参进入`data/definitions/`；开局在`data/scenarios/`；自动测试在`tests/sim/`与`tests/runtime/`，不加无用途的大目录。

## 8. 规模、性能与质量预算

这些是**待验证门槛**。先记录开发机器，再在最低目标机器定稿；未知硬件时不得宣称已达性能标准。

| 档位 | 代表负载 | 通过后才能做什么 |
|---|---|---|
| S0 现有Demo | 双聚落、现有真实事务与UI | 比较回归、找热点，不外推世界规模 |
| S1 可玩切片 | 2–3聚落、12–30持久人物、本地小规模战斗 | 完成45–60分钟通路 |
| S2 系统Alpha | 4–8模拟区、60–150人物、本地约40 | 验经济/迁居/组织连续性 |
| S3 完整候选 | 12–24模拟区、300–600人物、本地约60、战斗20–30 | 决定1.0出厂密度 |

渲染初定1080p、1倍、S3典型场景60FPS，1%低帧不低于45；这是目标而非当前结论。主线程单帧16.7ms中模拟/调度建议常态不超过4ms，局部路径/流式按预算分摊；按P0实测与目标硬件再细化。快进达不到目标时降低有效推进速度并显示原因，不能跳过事实或把远区冻结。

长时快进和入场同步要可分片、显示进度、可取消到安全提交点；世界总时间不能宣称追到了目标而相关地区仍欠账。内存、存档体积、加载耗时以S0实测建立预算，再记录S1/S2/S3曲线；不凭空填写“百年只需一秒”。精度切换、历史压缩与规模压力测试详见[世界目标](../../design/systems/world_simulation_target.md)和[验收矩阵](full_game_acceptance.md)。

## 9. 工作包的完成和长期接续

每次实现只选择第一个依赖满足且未完成的工作包，并在`docs/plans/`建立有内容的专用计划。单个包以一个可观察通路为界，过大就拆成几个可验证包；研究可以继续，但不能堆多个半接入领域。

每包记录：目标与非目标、依据的代码、持有状态、命令/失败、触及文件、定义参数、时间与存档影响、自动验收、可见证据、当前风险。完成后：

1. `python tools/godot.py check`通过；工具变动另跑Python工具测试，可见变化实际运行并读日志/截图。
2. 对照本方案相应F场景验证，不凭测试条数宣称完成玩法。
3. 在BASELINE更新当前事实，在专用工作包保存证据；路线只更新进度，不复制测试数字。
4. 交接写清已完成、剩余、最新通过构建、已知阻塞和下一小步，避免新会话重做基础。
5. 保留用户未提交修改；未明确授权不提交/推送、发布或安装依赖。已授权实施范围内的可逆小步无需反复确认。

自动检查失败先修第一个错误；可重现的严重规则漏洞优先于新内容。没有可玩新通路的重构必须有具体缺陷或测量依据。某阶段核心乐趣未验证时，先缩内容、改善选择和反馈，不用新职业/新境界掩盖。

## 10. 最大风险和预设处理

| 风险 | 早期证据 | 处理 |
|---|---|---|
| 当前分钟tick与战斗错位 | 攻击时机、暂停/快进、日常消耗互相矛盾 | P0隔离试验；统一时间语义，迁移有旧档与时序回归 |
| 完整存档落后于玩法 | 重启丢建筑/探索/伤势，格式靠当前布局猜 | 按领域同时交付快照与迁移；候选全验后提交 |
| 经营变成按钮印物资 | 同材料多人用、空仓付钱、取消返利 | 单一保管/预约/事务ID；守恒与失败测试 |
| “智能社会”成本失控 | 每人评估每人、无限记忆、永不结束的计划 | 有界候选/目标/记忆，按事件触发，只有有用证据常驻 |
| 世界自我灭绝或永远静止 | 多种子普遍饥荒/永战/垄断，或变化不可感知 | 容量和源汇调参、撤退/谈和/迁居/新人来源；不秘密重置已有事实 |
| 角色自由却没有玩法 | 出身只换名字，所有人刷相同贡献 | 三起点分别验证生计、依赖、风险、机会、转向 |
| 数值模拟不可读 | 不知道为什么拒绝、缺什么、远处发生什么 | 提供可知理由、凭据与渠道；重要事件有现场后果 |
| 美术吞掉玩法开发 | 规则未定就做大量变体，反复返工 | F8后正式批量；前期用已有代码表现和可读占位 |
| 参考过多导致无限扩张 | 一个阶段同时开五种新玩法 | 以1.0表和F出口砍范围，扩展明确后置 |

## 11. 当前暂定项与真正需要用户决定的时点

原方案中的三种出身、三层可玩境界、容量、目标时长和性能预算仍不冒充已拍板；转生概念已于2026-11-03确定，具体数量/成本/时间窗由开发测试。实施到对应工作包时给可玩结果让用户修正，不为名词与细数值逐项打断开发。

真正改变工程或发行边界的事项再问：收费/付费依赖与素材采购、技术栈或联网方向改变、会丢失现有存档的不可逆迁移、正式对外发布及项目许可证。当前无须安装新依赖或采购素材。

下一次实施从[P0首工作包](world_foundation.md)开始；先让当前世界可靠、可测、可接新规则，再让它越来越大。
