# Demo重构与实际功能核对

日期：2026-11-02。依据是本轮结束时的脚本、配置和测试，设计愿景不作为已完成功能。当前构建数字以 [BASELINE](BASELINE.md) 为准，本轮范围见 [工作包](plans/demo_refactor.md)。

## 本轮实际修改

| 原有问题 | 已落地的处理 | 代码归属 |
|---|---|---|
| 场景适配脚本混有整套联合快照验证 | 提取WorldSessionSnapshot，先同步统一提交点，再构造/验证独立候选；运行适配只负责成功后的场景替换 | scripts/runtime/world_session_snapshot.gd、world_continuity_runtime.gd |
| 服务面板穿透本地适配器的私有状态 | 提供准备命令、取消、背包、活动和求助的明确入口；ServiceRuntime专注意图路由与观察结果 | scripts/runtime/settlement_services_runtime.gd、village_runtime.gd |
| 隐藏旧面板使同门求助不可见；河湾选择未接人物卡 | 人物卡恢复已有送柴求助；河湾选中信号接入HUD，使用实例名字和原人物状态；选择清除与失效引用检查 | scripts/main.gd 与两个runtime |
| UI每帧重构长串调试/人物文字，底部全操作平铺 | 共用主题、时钟事件合并刷新与数值缓存；需求条、可展开档案；生活/差事/互助页签；F3诊断低频采样，封路工具折叠 | scripts/ui/ |
| 开始提示不变，遮掉真正结束/封路结果 | 服务状态返回阶段、阻塞/完成结果和下一边界时间；通知按当前事务更新，新拒绝不被旧成功覆盖；读档重置本地观察缓存 | scripts/sim/services/settlement_services.gd、runtime适配 |
| 三处补给缺口算法重复；旧需求信可能重复派货 | 统一delivery_need；承接与真实出库都占用已知/未达报告的份额，取消通过原有延迟报告恢复；不让发货方偷看未知库存 | scripts/sim/regional_simulation.gd、services/ |
| 读档后原地办事误报路不通 | JSON数值与场景整数坐标用格子语义比较，避免不同数字类型的数组被判为异地 | scripts/sim/services/visitor_jobs.gd |
| 设施只有方框、地形深粗边、人物重复绘制 | 小型共享地形图集、克制网格、井/药圃/门/仓库等剪影；共用人物衣襟、发髻、影子与名牌 | terrain_visuals.gd、facility_visuals.gd、pawn_visuals.gd |
| 多人使用同一设施时角色和姓名完全覆盖 | 按稳定ID确定小范围绘制偏移，拥挤时只给选中人物显示姓名，点击选最近目标；不修改模拟格、实际位置或行程 | pawn_view_layout.gd、pawn.gd 与两个runtime |
| 悬崖局部几何缺少区块位置；黎明突然跳色 | 悬崖放到所属区块；7点至9点持续过渡到日色，夜色兼顾辨识 | world.gd、cliff_chunk.gd、day_night.gd |
| 静止时迷雾仍反复投射视线/上传纹理 | 焦点变化或遮挡明确失效时才重算；强制刷新仍可用于读档 | fog_of_war.gd |

没有引入新依赖、ECS或额外autoload，没有改addons，也没有把本轮扩成新经济、政治或战斗系统。脚本与UID保留；联合存档格式未更换，已有正常服务存档实际读回成功。重复可达区域搜索也收敛到既有公共实现。

## 当前Demo实际有什么

| 领域 | 代码中的现状 | 适用边界 |
|---|---|---|
| 世界与移动 | 512×512正方格、64×64区块、噪声地形、高度、地面通行/高差/斜角判定、玩家行走、相机平移缩放、迷雾、昼夜 | 单一生成首区；不是完整多地区大世界 |
| 时间 | GameClock统一分钟、暂停与1/2/4倍速；模拟固定世界tick、表现单独插值 | 没有完整世代/历史压缩 |
| 人物 | JSON定义玩家、五名山门NPC；河湾六个复用定义但有稳定实例ID/当地名字的常驻人物；另有运粮人 | 不是十二套独立剧情人物，也未实现普通居民跨区迁居 |
| 日常生产 | 饱食/精力衰减、自主吃住、送柴/挑水/运粮/做饭/巡视；行动有路径、耗时、预约、真实取物与交付 | 有有限日常策略，不是通用智能、人生规划或LLM代理 |
| 物资 | SimInventory管理容器、预约、消费、生产与幂等操作；人物包、仓库、在途货物、托管和钱包分别保管 | 没有完整市场、劳动工资或所有人物消费货币循环 |
| 个人认知与关系 | SimSocialMemory记录事实、所知、来源、有向关系；请求按处境和有种子判定，承诺结果留痕 | 有界事件/请求模型，不是完整谣言政治模拟或任意对话系统 |
| 机构 | SimInstitutionBook记录机构、职位任职、签署权限、贡献发放/扣账及依据 | 没有通用所有权/判例/审判平台；职位换人不等于已接完整继任剧情 |
| 跨聚落连续性 | RegionalSimulation共同时间、远区稳定区间批算、关键边界推进、运粮人在途、封路续行、消息延迟；归来展示原持久人物 | 双聚落场景已验，不可外推为百万平方公里或大人口性能已验 |
| 玩家办事 | 异地食宿、6粮运输、凭据报工3贡献、用1贡献兑饭、满足2贡献申请药圃许可、凭据取药 | 费用/门槛是当前数据；许可仍依赖原签发者在世且有权 |
| 互助 | 山门选中同门请求送柴；河湾仓库附近请求运粮人合作，考虑距离/体力/旧承诺/路况/需求/报酬；报酬先托管，指定批次送达才付款 | 河湾普通居民跨机构私人委托未接；不能把礼貌当无条件帮忙 |
| 存读 | 原子文件写入/备份，联合恢复身体、物资、机构、关系/知识、随机状态、行程、消息和未结服务；坏数据拒绝后保持原世界 | 地形变化、迷雾探索与建筑未纳入完整世界存档；旧无服务格式无自动迁移 |
| 隔离原型 | succession_resolver.gd及测试仍存在 | 继任算法未接到本Demo，权重不是用户最终认可的完整政治系统 |

## 验证记录

自动检查覆盖原有行为，并增加旧需求信/多人物承诺取消、失效入参、服务结果、同地点读档后新办理、快照抽取的近远区因果一致、真实选中求助、名牌选择、迷雾重复工作、悬崖位置和黎明连续性。最终测试数和日志见 [BASELINE](BASELINE.md)。

最终 `python tools/godot.py check`：41组、1,358断言、0失败；`logs/check-test-20261102-205244.log`。Python工具测试15条通过；场景/资源检查432文件、0错误/0警告，结构检查通过；最终新启动主场景的编辑器与游戏日志无项目脚本错误或警告。`git diff --check`通过，addons与project.godot无本轮改动。

新增快照测试首轮构造了错误的河湾自治标记，触发合法拒档；修正fixture保留控制不变量，没有放宽验证。实际试玩随后发现原地服务坐标类型问题，已修复并保留独立回归。一次临时调试命令混用了缩进，编辑器暂停后已重启；不属于项目脚本错误，最终运行重新检查。

真实主场景已通过UI操作运输、报工、兑换，重启读回同一份2贡献/1饭的状态，再申请通行、取到1药、前往河湾；吃随身饭不收费，休息和另买一餐各1钱，盘缠6→4，河湾记录收款2。后半段验收用GameClock推进确定分钟，不改库存或伪造奖励。专用QA存档使用 `user://demo_refactor_qa.json`、`user://demo_refactor_river_qa.json`，没有覆盖默认玩家存档。
