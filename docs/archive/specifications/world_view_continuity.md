# 读档首屏的地形呈现连续性

2026-11-04；首屏修复已通过对应提交的CI，证据见[QA](../../qa/20261104_world_view_continuity.md)和[BASELINE](../../status/baseline.md)。此包只调整可替换视图，不改变地图、共同时间或保存格式；下文保留原实现合同。

真实 v42 在途档在暂停状态下读入时，独立候选地图被正确接回，相机与迷雾位置也正确；但旧视图先清空，再按 64×64 区块行序每帧绘 256 格。玩家格位于区块行序第 2304 格，刚读完就截图会得到黑背景。等候两秒的原生探针可见正常世界，这不能证明第一帧已经就绪。

本包采用屏幕内地形优先队列：main 只提交相机/缩放推得的可见格范围，世界视图以屏幕中心为先绘制；每帧总预算仍为 256 格，剩余预算继续普通区块扫描。优先范围裁剪到有限世界与当前关注的加载范围，不引发远处模拟或授予视野。地形预绘和真实可见性分别成立，迷雾继续由原感知系统决定。

预绘格按未完成区块保管，普通扫描接续后交回完整区块索引。远跳、取消、卸载和重新绑定必须清理预绘的地面、植被与崖面；不能留下线性扫描游标不知道的残片。未完成区块的崖面只绘已写入的地格。`is_view_ready` 只读检查世界内请求范围是否全部写入；请求超过当前加载范围时返回 false，不把局部就绪冒充整屏。它不代表 GPU 已提交，原生截图还须等实际绘制帧。256 格为地面写入预算，视口排序、删除与崖面绘制仍有额外 CPU 工作，须按目标窗口实测，不宣称每帧总耗时有硬上限。

验收包含跨区块首屏、世界边界与加载范围裁剪、每帧预算、重复提交、普通扫描完整接续、远跳/重绑清理，以及暂停下首屏绘制前后完整会话事实相等。原生复核新局、真实在途档、再次读档和换区。正式美术、全地图渲染、全局设备设置与超大规模性能不在本包内。
