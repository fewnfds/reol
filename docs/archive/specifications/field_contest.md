# U3-c 建议：断碑台的一次现场争环

2026-11-04。**暂缓的事件规格**：旧争环实验仅保存在本地`codex/field-contest`的未验收WIP，不属于当前`codex/world-engine`基线；用户已要求先建设通用世界引擎，不继续磨合此事件。当前功能与构建以[FEATURES](../../status/features.md)/[BASELINE](../../status/baseline.md)为准。

## 1. 可玩的结果

在原断碑台，河湾小满 `river_shi_tou` 依自己的旧闻和寻物目的赶来。如果她本人看到另一个人正在取台上那枚灰纹环，可以说自己也想取，并短暂等待答复。她不是守卫，也没有证据证明环属于自己；这是两个真实目的相遇，不是系统认定偷窃。

玩家可在本人实际听到警告后：

1. **明确让路**：选择“停手，让你先取”，先真实取消自己的原取环动作并当面表达，小满仍须自己在原台边完成原一分钟取物。她实际取到后才记得这次帮助，随后可以沿原行旅回河湾；玩家另日找到实际持环、空闲且愿意的她时，使用现有 C 私人交割，4 钱与同一枚环在原五秒过程结束时交换。她可能忙、拒绝或玩家钱不足；帮助不保证成交。普通 I 的“停止操作”也能停手，但没有说过让路就不写帮助记忆。
2. **继续争取**：对方没有停手，短暂等待到期后，小满只有在仍看得见、仍能沟通、愿意且实际有手段时，才能以自己的原身体发起原有限驱离。玩家可用已有交锋、移动和退让应对；双方的气力、原武器、挫伤和实际退开沿旧规则。胜负不转移环：台上若仍有环，接近它的人仍须完成自己的原取物；环已在他人手中时，不能从行囊凭胜负自动夺走。

玩家先拿走并离开、小满到达空台、双方隔墙或不同高度、她忙于需求或受伤时，可以根本不发生这次对峙。她只从空台知道“此处已空”，不追踪不可见的持有人。物理在场、认识、意愿、是否开战、实际取得是不同事实；让路不授予任何人正式产权。

## 3. 触发、沟通和让路

### 3.1 小满到场后才能知道

- 小满按原 `wants_decision` / `note_decision` / `consider`、原路线和共同时间行动；饥饿、疲劳、原事务、受托职责、健康和控制通道优先。她不因玩家接事、开面板或靠近而被提前传送、补状态或强制出发。
- 仅在她实际抵达、原旅途已结束且身体可作下一步时，若环仍在固定台槽，而**另一具真实身体的原 `take` 活动正占用这枚环**，把该活动作为待观察候选。须同时亲见动作参与者与台槽：实际连续位置在允许距离、同高、真实墙门/地形视线可达；再检查双方具备通信通道并在当面沟通距离内。读取活 `active` 用于找到可能的实际动作，不等于隔墙认知。对她可观察的是“眼前有人在取环”，不是背包、隐藏动机或远方位置。
- 说话时保存一条本人观察和具名警告事件，只向实际发言者/接收者写认识。相同原 `artifact action` 对同一寻物目的最多一条警告，重复刷新、重进面板或存读不重新发出、续时或刷社会判断。
- 如果环已经完成取走，或在本人到场时只见到空台，继续现有空台/返程行为；不从 `artifacts.objects` 的远方容器推断谁拿了它。单纯路过、查看、对方已经持环或没有可确认的活取物，不产生本包驱离。

### 3.2 有限等待是她自己的动作

警告后的短等待是小满本人选择继续这次寻物的有限身体活动，不是 UI 锁、第二具身体或对所有 NPC 的后台干预。可扩展原 field 目的阶段并让 `owns_actor()` / `previous_autonomy()` 投影这个等待：只在原行程到达并释放后开始，捕获原自主前态，使用原身体，不取消任何既有事务。活动结束恢复真实前态，不覆盖新的控制归属。

等待期间按共同毫秒重核本人位置、视线、通信、需求、健康、原责任、控制及被争的原动作。需要吃饭/休息、受伤、被控制、被其他真实活动占用、离开、失去视线、原动作结束或对象失效时关闭等待；未得到同意不拿走环。用现有需求边界、警告截止和有限观察推进，不依场景帧或打开 C 面板。必要时仅释放此等待本身，不能取消其他域正在做的事。

建议 `contest_grace_ms = 15000`，放在野外目的定义并以实测调整；一次最多短暂等待，不延长原 take 截止。警告开始不取消玩家取环、不扣费、不改变容器。到期重核未通过则诚实结束这次介入，不以警告代替本人一直看见。

### 3.3 明确让路与实际帮助

本人收到的警告在已有 C 上下文提供“停手，让你先取”，并显示其具体对象和对方；也可从 I 直接停止。新增意图须只允许对此警告所引用的**本人正在进行的那一次**取环动作使用，不把其他身体活动的忙碌限制全局放开。先核实时沟通、当前主体、双方、警告、原动作和对象；再在同一同步提交段调用原 `artifacts.cancel()`，记录实际收到的让路说法，释放小满自己的等待，并在原条件允许时由小满通过原 `take` 开始取得环。不能先发帮助奖励或预改环的容器。若条件变了或原取物无法开始，说明实际停手/说话结果，回原自主流程；不虚报取得或抹掉已发生的取消。

让路说话使用原 `SimSocialMemory.record()`，`actor` 是发言者、`target` 是小满，因真实通信才让两人拥有这条记忆。将该说话事件和小满随后那条具体原取物 action 关联；只有它实际以 `taken` 完成并取得同一环，才调用 `remember_outcome(小满, 发言者, "helped", 让路事件)` 一次。途中受击、缺控制、取消、第三人取走或说话没传到，不形成已完成帮助。该私人关系会在小满**首次**评价之后的新私人交易提案时作为现有 `affinity/reliability` 输入；已有同一身份的提案继续复用原判断，不借新记忆重掷、撤销已成交或把当次同意变永久同意。

## 4. 截止、同刻和玩家主动等候

### 4.1 冲突只在到期且仍可成立时创建

到期时同步双方原所属区，核警告仍活、同一原 `take` 尚活、环仍在台槽、双方本人当前可见/可通信、小满身体可控制且需求/责任/意愿仍允许。她还须有实际会用的 `sword` 或 `qi_bolt`、原武器/qi/stamina 和 `SimHealth.can_fight()` 等条件；会一项方法的定义不等于有足够费用或持剑。无力、忙碌、遮挡、环已完成转移或对方已停手都不创建交锋。

建议新增仅接收本域真实到期警告 ID 的 `begin_field_contest()` 类受信入口，名字以实现为准。它像已有 `begin_source_care()` 一样由本域给出复核后的双方，再走 `SimConflicts` 的共同提交；不能由外部传任意 `internal=true` 或伪造警告。预先捕获双方的原自主前态；只有真正开场时才通过 `RegionalSimulation.interrupt_occupation()` 中断各自当前占用和这次原取环。对峙域需有类似看护的提交保护，防止中断回调先把警告错误关闭或重复开场：成功时记录一个 `cause={domain: field_opportunities, id: 原警告}` 和对应 encounter，失败时不留下单边因果。原玩家 `begin()` 仍保留公共时间保护。

小满胜出后依实际身体、退让过程、生活需要和原目的再决定是否到台边取环；她受挫则真正退开并保留伤势，之后沿现有寻物重试及需要处理，不无限原地复活。玩家胜出也要回到台边重新取环。没有胜利掉落、自动从他人行囊夺环、全体敌对或凭一次争夺认定违约。

### 4.2 原取物完成先于同毫秒警告升级

当前 `RegionalSimulation._settle_current_processes()` 先结算 `artifacts`、再结算 `conflicts`，之后才结算 `private_exchange` 和 `field_opportunities`。本包保持该顺序：若取环完成与警告截止同为 `t`，先由原器物提交 `taken` 和真实容器，警告在同刻见到原动作已结束后关闭，不中断已完成动作、不倒拿环，也不凭旧警告开战。已有击中、失控或明确取消也先按原阶段结算；新警告在本域阶段检查当前事实，不重放之前的隐藏动作。

原 `take` 为 60 秒，宽限不能照搬公源的 90 秒：对仍在进行的取物，90 秒后动作必已结束。15 秒可使较早发现时真实开场；若小满首次看见时距完成不超过宽限，则取物可以先完成，这是合理的错过，不延长或暂停原动作以强造战斗。

### 4.3 主动等候不能吞掉玩家可回应的警告

现有 [GameClock](../../../scripts/autoload/game_clock.gd) 的主动等候一次 `_commit_interval()` 可能到下一分钟；UI 通过 `time_advanced` 回调在该次提交后才读警告。简单套用看护的“收到后暂停”无法保证短于一分钟的警告尚未到期，甚至可能先完成整场交锋。不得倒拨钟或停止无关 NPC 来补画面。

建议增加一个**主动等候提交上限的只读 provider**：仅当当前玩家真实控制的人身正在对本环执行原 `take` 时，将主动等候的单次提交上限设为 **1000 毫秒**；其他主体、远处 NPC 和无该动作时继续原等候行为。普通 1–4 倍速本来以固定短步提交。每次提交后运行现有本人接收检查：收到本人活警告即取消后续等候、恢复 1 倍并暂停，显示当时剩余时间和可操作项。暂停后世界毫秒不再推进；魂/鸟人生中自主的人身或 NPC 对 NPC 的警告不代玩家暂停。

这不是第二个模拟时钟，也不是改变 NPC 意图；已有同步 `advance_msec()`、无关等候及原域结算语义不因 UI 而被全局改写。现有 `_wait_guard` 只有布尔许可，不能假称已有上限接口；需处理读取期间已经在等候、读档恢复的等候、解除 provider 和原分钟边界。1 秒上限意味着通常至少剩 14 秒宽限；若警告发生在取物最后不足一次提交的时间内，原完成可能先于界面显示，须显示真实结果，不制造已失效的活警告。分片推进相同世界时间的结果应一致；因玩家主动响应而产生的分支除外。

## 5. 数据所有者、存档与可证明性

最小新增记录建议放在原 `SimFieldOpportunities`，例如有界 `contests` 和稳定递增 ID；具体字段名由实现决定。每条只保存：原 purpose/site/环/两人/取物 action 引用、观察与实际通信时间及双方当时位置高度、警告开始/截止与状态、说话事件、可选让路后的原 NPC take action/结果事件、可选原 conflict 引用及结束原因。等待的原自主前态只服务活动交接；不复制身体、环的位置、个人关系、钱包、健康或时钟。历史量需有限上限；满时不覆盖旧因果、不再新开警告，并按原寻物/生活规则继续。

| 事实 | 唯一所有者 |
|---|---|
| 地点、原目的/行程、这次警告与引用 | `SimFieldOpportunities`；无通用任务或产权 |
| 位置/控制、需求与原日常 | 各人原 `VillageSimulation` / embodiment；归属区不等于当前位置 |
| 环、取放与已完成来源 | `SimArtifacts`；前后只存在一个容器 |
| 说话、本人所知及 directed 帮助关系 | 共享 `SimSocialMemory`；不是机构公账或全局声望 |
| 交锋、成本、伤势和退开 | `SimConflicts`、`SimHealth` 和原身体/器物 |
| 买卖中的钱、同意与交割 | `SimPrivateExchange` 和双方原 `SimInventory` |
| 所有过程的截止和顺序 | `RegionalSimulation` 与 `GameClock` 的同一整数毫秒 |

当前根 42 / 区域 38 / 野外地点 1 / 交锋 3 是本规格核对时的格式。建议根与区域各升一版，地点域由 1 升 2 并增加空争议集合；交锋 cause 接受新域需显式升级并保留所有旧 `source_care` 与无 cause 交锋。器物 6 / 私人交换 1 在仅引用原事件时无需为新玩法复制或重建。实施前以实际合入版本核对，不能仅改数字让混版通过。

旧地点域非空时完整保留其地点、目的、在途路线、原环和既有记忆，只迁入**空争议**；旧地点域为空也不补地点、环、人物或过去的争执。旧局以后若自然发生有效接触，可以按新规则形成新事；不为历史提前编警告、帮助、对手或战果。真实历史 fixture 原样保留。

独立候选先验证形状再在所有原域就绪后联合核验：

- 警告引用已存在的相同环和对方原 `take`，观察时间处于其真实进行期间，双方及静态高度/记录距离符合；事件包含的身份、观察/沟通和截止与该行一致。只验证可保存的历史证据，不能用今日墙门反推过去无遮挡，升级当刻则必须重核候选当前视线。
- 同毫秒玩家收到警告并立即停手是合法情况，不能只用严格 `observed_ms < cancelled_ms` 拒绝。警告创建时可像私人交换保存原 `artifacts.next_id` 的 `artifact_floor`，不额外消费序号；用现有 `SimArtifacts.Schema.serial_floor_valid()` 和原 action/result 序号核对 action 已开始、终止事件在警告快照之后。只凭毫秒相等无法证明跨域所有动作的先后，也不宣称完整历史重演。
- 明确让路必须有实际接收的原说话事件与被取消的那个 action；成功帮助须关联让路后的**同一** NPC take 的 `taken` 结果和唯一关系历史。失败或无说话不能伪造 `helped`；重复事件不能重复记功。
- 升级警告恰有一个同时互指的原 encounter、正确发起/接收者与因争执中断的原 action；未升级者不能挂 encounter。原交锋也反向核对其 cause；孤儿引用、替换人物、未来时间、重叠占用、虚假结果和混旧格式均拒绝。跨原区读取各自身体/记忆，不用当前归属推断现场位置。
- 进行中候选保留等待及原自主前态、玩家原取物占用、剩余毫秒、当事人所知及原交锋状态；全部通过后才替换活会话。坏档不得改活时钟、地图、身体、原物、原账或既有决定。

## 6. 接口改动地图与实施顺序

1. **原目的与有界警告**：扩 `field_opportunities.gd` / `field_opportunity_schema.gd` 的到场判断、等待占用、deadline/失效与旧格式空迁移；配置只增加必要的宽限和历史上限。先覆盖 NPC 原需求/寻物未被劫持、直接目击与空台盲区。不要从 `source_care` 搬来一份不相干的看护安排。
2. **原交锋与真实让路**：扩 `conflicts.gd` / `conflict_schema.gd` 的受信 field cause、提交保护和双向因果；沿原中断/动作/健康。扩原 C 意图、`SimSocialMemory` 说话引用及原 NPC `take` 完成后的 `helped`；复用原私人交换，不改已有提案的缓存语义。先定向验证两个出口、取消和同刻完成。
3. **玩家接收与连续性**：扩 `GameClock` 主动等候上限的只读绑定及 `WorldContinuityRuntime` / C 适配的当前主体接收、读档重投影和精确取消；接根/区域明确迁移及完整候选交叉检查。做正常主局、真实在途保存/完整停开、UI画面和要求的完整验证，再更新 FEATURES/BASELINE/QA。当前文件只是规格，不冒称这些步骤已经完成。

## 7. 验收与普通新局复现
