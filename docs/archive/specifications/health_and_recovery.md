# P3-a — 身体后果与实际救护

2026-11-03，**P3-a有限首包已实现并实机验收**；具体交付/精度和真实档证据见[QA](../../qa/20261103_health_and_recovery.md)，不是完整医疗/伤亡。接[众生](../../../design/systems/beings_and_lifeways.md)、[动作设计](../../../design/systems/combat_framework.md)与[有限转生](../../../design/systems/rebirth_and_new_lives.md)。实物衣着和本包保留原状态所有者，当前功能/证据仍只看[FEATURES](../../status/features.md)/[BASELINE](../../status/baseline.md)。

目标：危险能改变后续可行行动，药材、医者和休养有真实用途；不把所有生命再压成一条万能血量。
体验：强行催动温石造成可定位的身体不适，可停手、带药求助、由懂行者实际查看/处理，再靠原身体休养恢复；身体状况影响继续冒险或谋生的选择。
约束：共同时间、原身体/精力/灵力/库存、本人所知与社会判断保持原所有者。离场/暂停/读档不能洗掉伤势或重复药物。
首包不开放致死行为；其后开放致死来源时，同包交付死亡清理/遗物/职位空缺与人生终局/有限接续，不靠无原因留一滴血或免费换身份兜底。
验收：至少一条原有风险→身体后果→有条件诊治/真实药物→休养恢复的完整因果链，包括NPC同规则、离场与进行中真实档重启。

## 1. 沿已有因果做第一条链

原温石强灌/不懂操纵的反噬已有实际判定、原灵力/体力成本和石芯裂损。先从该判定接入有限的人身经脉灼涩，不另造每日随机事故或无来源敌人。常规温养、只看外观、普通劳作不凭空受伤；旧反噬记录不补成新历史伤势。

首伤不是累计总伤害积分：只记录身体来源、伤势类型/部位范围、发生时刻/实际来源、当前恢复进程与已处理条件。强弱由实际作用/身体适配和材料条件决定；起步只实现有明确行为后果的少量类型，不预建全解剖/疾病模拟。具体恢复时长、材料份数和不适阈值放定义，通过测试调配。

经脉灼涩先限制继续引流/强灌，不剥夺普通行走、吃饭、交谈和求助；精力/灵力仍归原actor，不新增同义资源。自然休养可慢慢改善，合适处理能改善条件；吃饭不直接抹掉损伤。天气/湿衣继续影响原精力，换衣、换修行版本、取放器物不清伤。

## 2. 看见、理解、愿意帮、实际完成分别成立

| 层次 | 首包行为 | 不能代替什么 |
|---|---|---|
| 本人感受 | 发生后感到灼痛/引流不顺，知道哪些动作暂时不宜 | 不自动知道精确医学原因或全部治疗步骤 |
| 近旁观察 | 严重到可见时呈现表情/停手等线索 | 不远读别人的身体真值/包内药物 |
| 查看/诊断 | C向近旁具备相关经历者提出查看，实际在场耗时 | 身份标签或自述不是诊断能力，也不立即治愈 |
| 商量处理 | 根据本人所知、本领/当下事务/关系和真实约定决定 | 不把NPC变成随叫随到的无偿按钮 |
| 处理 | 合适的可处分材料和双方身体可用，实际接触/耗时完成 | 点击同意不扣空库、不复制药、不提前获益 |
| 休养 | 与原睡眠/日常、共同时间连接，原身体逐步恢复 | 离场、读档或新窗口不能立即康复 |

具体用药从现有herb/dried_herb及材料定义判断，不能自动把所有“药”都设为万能回血。受托公物继续受原available/custody保护，不可因急救入口就侵占；若需紧急取用，另有明确授权与后续责任。医者自用材料/患者供料的交易条件分别成立，首包只开放可核验的一种。

## 3. 状态与执行接缝

- 身体后果可作为原身体旁的专属领域，稳定引用原人身载体；由RegionalSimulation组合，不能给PawnVisuals或HUD持有真值。雀身/山兽/旧戒不硬套人类经脉，缺适配规则时拒绝对应处理。
- 原SimArtifacts的真正作用提交提供来源，身体后果由明确API落地；原同刻失败/取消/重复settle不重复损伤。不从渲染、提示文案或任意外部ID生成伤势。
- 恢复用原固定时间与有界事件/边界，先同步受影响身体再改后续可行条件；不开第二时钟。风险已发生和对外消息分别存，远处不因玩家不在而冻结，也不全世界瞬间知道。
- 诊治复用原结构化请求/社会决定与单身体排他约束。事务明确双方、材料来源、接触/持续条件、投入点、完成点与取消；中断后材料/已处理与恢复各有实际归处。不能让医者边远行边给人处理。
- 新候选独立核对来源、时序、作用只提交一次、原材料/社会决定、身体互斥和恢复边界；旧档显式迁空，不把过去反噬倒写成新伤或给旧死者复活。

实施先检查`artifacts.gd`/`artifact_understanding.gd`、`embodiment.gd`、`regional_simulation.gd`和原请求/服务及候选接口，再决定最少文件。仍按规则/定义→测试→运行/交互→存档→实机与文档收尾，不先堆医生面板。

## 4. 开放致死来源前的必须项

普通肉身死亡通常魂散；保魂需真实方法，主角仅按已定有限转生例外。致死不是单独把alive置false：原动作/控制/预约与协作者需结清，随身物留在原身体/遗物来源，未结公物/工资/债务保留责任，任职空缺与基本生活代办或冻结要可运行。旁人认识须经见闻/消息形成，不能借死亡广播泄密。

玩家死亡无剩余机会时终局；有机会时使用真实出生/成长来源及有限抽选/前向时间，防人口筛选，不能直接拿现有三个开局按钮免费替换。尚未交付这些条件时，不开放会致死的攻击/饥荒/反噬入口，也不声称已完成完整伤亡。

## 5. 首包验收场景

1. 具备/缺少操纵认识的不同原身体对同一温石实际尝试；只有真正反噬来源留下对应新后果，原石芯裂损/灵力成本不重算。
2. 受影响者仍能通过普通生活/求助继续游戏；强行重复催动因真实身体/器物条件被拒或产生定义后果，换装/存读不恢复。
3. 对同一救护请求，普通同门与具相关经历者有不同理解；能力自述不授本领，远处/忙碌/无药/无权用料有合理结果。
4. 实际耗材/两人耗时后改善处理条件，再经休养逐步恢复；取消/材料不足/离开/控制丢失不得提前治好、复制药或吞掉他人未同意财物。
5. 玩家离场，原NPC仍处理自己的身体处境；粗细推进、进行中联合存读和完整进程重启到同一可核验未来。
6. 原双聚落、工资/自主备粮、施工/床/天气、衣物、寄魂与历史档保持回归；坏候选原子拒绝。范围只写实际完成的类型，不把此规格算成医疗/死亡已完成。
