# 温火石的第二用途与有限办法选择

2026-11-03，接续已验证的共同执行/对练包。已完成有限样本并通过自动/实机/完整重启验证，见[证据与边界](../../qa/20261103_heat_methods.md)；完成度以BASELINE为准。

同一块石头的有限余热既能替柴做饭，也能在药圃烘药。两种用途通过同一个热工艺执行函数检查：本人会不会导热、实际位置、材料、输出空间和余热，再单次消耗材料/储能并保留真实产物；不设置两个独立完成flag。干药留在原药圃库存，不直接变钱/经验/贡献。烘药是小样本，不声称有通用热力学、药性/保质期或医疗系统。

保留现有烹饪定义和真实存档验证，新增用途使用同样的数据字段和进行中阶段。独立实例仍唯一，背包不复制石头。操作可中断、对象竞争、失控、缺热/缺料/满容器失败都不半扣材料。新用途是附加动作定义，现有快照字段不变；若实际需要变字段，再显式升级，不能改旧fixture。

NPC最小样本：当已有做饭职责确有需要、本人所知缺柴、附近有可接触的异石时，可以先亲自端详，再付本人灵气探查，获得本人的导热方法；之后可选择以石代柴。旧木柴办法继续存在，有柴时优先普通办法。选择只读自己的库存认识/器物经历；执行再查实物，不读后台储能来替NPC预知成功。不新增职业、不让NPC自动继承玩家的学习，也不直接强拉忙碌人物。

RegionalSimulation在共同时间提交后检查本次刚选择/完成行动的空闲NPC，器物领域根据其职责和本人认识接续一个有限方法；不会从正在超前推进的VillageSimulation内递归调用尚未提交的世界时刻。NPC可以在稀疏推进中受理下一步，玩家外部命令仍须等当前目标结算完。没有为此新建通用GOAP、无限行动规划或第二套库存。

验收：两用途真正争用同一余热/实例；烘药消耗真实原草药，缺料/低热/预约/容量失败原子；开始/中途/重启接续相同；NPC本人观察→探查→替代生产成立，他人未学习、假库存说法可改变方法选择、实际执行不能造物；已有v1–v7和生活/对练回归通过；实际器物面板/路线/产物和日志截图。后续已接有限医疗与本地交易样本；被动工艺、完整医疗/市场仍未完成。
