## 1. 已核对的真实状态归属

| 状态 | 当前代码中的负责人/流向 | 当前边界与后续风险 |
|---|---|---|
| 世界时间与玩家倍速 | [GameClock](../../../scripts/autoload/game_clock.gd)：tick_index、total_minutes、speed、paused | 10Hz、一tick一游戏分钟，初始历法偏移480分钟；tick与日历数值不是同一个字段 |
| 已提交/目标世界时刻 | [RegionalSimulation](../../../scripts/sim/regional_simulation.gd)：current_time、target_time、地区边界 | 地区可惰性滞后；跨区读写前同步；目标时间不等于已经发生 |
| 本地行动/身体数值 | [VillageSimulation](../../../scripts/sim/village_simulation.gd)：actors、tick_index与执行装配 | 目前主体/身体/定义/单格与actor容器绑定；主要为固定人形生活 |
| 手动玩家位置 | [PlayerCharacter](../../../scripts/entities/player.gd)的连续位置/cell，经[VillageRuntime._sync_player_cell](../../../scripts/runtime/village_runtime.gd)同步回sim | 当前确有节点到模拟的写入；不能仅依据目标架构声称所有空间状态已归纯模拟 |
| NPC与行程位置 | 本地executor修改actor.cell；[WorldContinuityRuntime](../../../scripts/runtime/world_continuity_runtime.gd)推进玩家行程与远地视图 | 视图插值/拥挤偏移不回写真实格；新移动方式需明确交接执行权 |
| 人物显示状态 | [PawnState](../../../scripts/data/pawn_state.gd)由runtime按actor刷新，远区安静间隔可能做需求显示投影 | 不能让HUD值/投影又作为另一套健康、消耗或资源结算真值 |
| 动作阶段与预约 | [SimActionExecutor](../../../scripts/sim/action_executor.gd)：actor.active；库存保管预约 | 当前单人物/单active；合作与持续作用尚无通用状态 |
| 数量库存/转移 | [SimInventory](../../../scripts/sim/inventory_ledger.gd)：containers、reservations、operations | 只有可堆叠数量；不是实例物品、物权或物理容积/负重模型 |
| 机构记录/权限 | [SimInstitutionBook](../../../scripts/sim/institution_book.gd)：任职、entries、operations；余额由账目派生 | 不归PawnState；任职/记录与执行能力分开，完整争议/政治未接 |
| 事件/转述/私人关系 | [SimSocialMemory](../../../scripts/sim/social_memory.gd)：events、knowledge、relationships、requests | 现有转述复制受限快照；新错误认识/矛盾命题不能直接冒充既有事件结构 |
| 路线/在途/消息 | regional：routes、shipments、couriers、messages、local_news与in_transit库存 | 路线快照和迟到信息继续有意义；不是任意人口迁移/消息网络 |
| 地形/像素格换算 | [ReolWorld](../../../scripts/world/world.gd)、[TileGrid](../../../scripts/core/tile_grid.gd) | 首区512×512、64格区块、64像素tile；像素不是米；无完整可变地形/建筑存档 |
| 内容/开局 | [ContentDB](../../../scripts/data/content_db.gd)、data定义与scenario | 定义只读；village现仍混合规则与初态，不为整齐一次拆碎；动态学习/创造不能回写定义当存档 |
| 一致快照/恢复 | [WorldSessionSnapshot](../../../scripts/runtime/world_session_snapshot.gd)构造候选，runtime验证后替换 | 按当前home/river/player装配核验；动态实例需合法重建清单，不直接放松旧校验 |
| JSON文件边界 | [SimSaveStore](../../../scripts/persistence/save_store.gd)临时文件校验、备份、替换 | 只管文件；领域版本、有效引用、真实因果不能交给文件读写器猜补 |

固定装配和人形假设是当前Demo边界，不据此将其既有可玩闭环判为错误。新增系统优先接小适配与明确所有者，不把以上所有字段一次换成大框架。

## 2. 单位与身份的最小约定

| 项 | 当前含义 | 新规则进入前必须声明 |
|---|---|---|
| tick_index | 当前每tick一游戏分钟的模拟步数 | 新时刻的单位、纪元/历法换算、速率和旧档迁移；不悄悄改成秒 |
| total_minutes | GameClock显示历法，含初始偏移 | 与已提交时间保持何种关系，恢复怎样校验；不存第二条独立世界时间 |
| cell / global_position | 整格与像素连续位置，tile为64像素 | 使用何种空间单位、载体锚点/占地/触达与表现投影；不能把64像素解释为64米 |
| altitude / elevation | 当前高度层规则与显示偏移 | 可达、遮挡、落点与接触条件；不等于自由三维坐标 |
| 库存count | 非负整数份数 | 一份代表什么；实例或批次如何拆分合并；质量/体积另声明 |
| MAX_COUNT | 当前JSON可精确表示的最大整数边界 | 不是身体负重、容器容量或经济预算；单位与允许范围按字段定义 |
| definition_id | 内容模板引用 | 不用作所有实际实例的唯一身份；修改定义需说明版本兼容 |
| actor_id及事件/行动ID | actor跨当前地区检查不重复；若干事件/行动序列由本地实例分配 | 跨域引用保留命名空间，不拿裸event_1当全世界唯一标识 |

新字段须区分“未知/尚未观测”“不存在/不适用”“已知数值为零”“引用失效”。不统一以0或空字符串塞过校验，业务上再猜含义。

### 2.1 跨地区引用不能假定本地编号全局唯一

当前各SimSocialMemory可分别产生event_1；regional也有自己的事件分配器。现有状态分别保存在领域内，不能仅据此声称当前出现冲突；但新命题/证据跨域引用若只存裸编号，会失去出处。

建议先用“持久分配命名空间＋本地ID”的有类型引用，或等价稳定方案。命名空间属于ID来源，不是主体当前所在地区；迁居或转交不改变已有ID。实现前选择一种最小表示并为旧档写显式迁移，不能先在文案里拼前缀再假装引用已升级。

身体/载体、主体、物品、过程和定义引用要能区分类型，避免一个同名字符串在几张表中误指。历史所指人物死亡/离开后保留必要的历史身份和来源摘要，不强求其仍是本地活跃actor，也不把未结证据一并删除。

## 3. 六条接入契约：先定责任，再添能力

### C1：只有一个权威提交路径

每项真实变化说明由谁提交：位置、身体状态、物资、设备、信念或机构记录。UI/文本/观察者投影没有直接改真值的权限；输入可提出动作，执行复查真实条件。现有玩家移动接缝要保留并明确交接，再按P0结果迁移，不让旧输入与新战斗移动同时拥有写权。

共同过程可以有多个参与者，但只有一个事务提交负责人。各参与者保存自己的占用/阶段与实际后果，不能多人各自生产一份成果。长期效果不必占满单一active槽，首次需要时定义可并行通道与冲突。

### C2：查询分为实际可行、主体预期与界面表达

实际可行性回答“世界条件是否允许”；主体预期回答“他据所知认为怎样”；界面表达回答“玩家此刻可看到什么”。它们可以复用底层结构，但不得串用权限。

计划器不能用后台真实材质提前识破尚未被识破的伪器。拒绝结果先有内部诊断，再根据已知现象生成对外理由；不能把隐藏条件直接拼成错误提示。具体规则见[所见/所知/所在意](../../../design/systems/perception_and_understanding.md)。

### C3：引用、版本与依赖可校验

新状态列出引用类型/来源、单位、schema、所依赖内容版本、生成条件及失效处理。当前只有world_seed和既有v1约定不等于已具完整内容/生成器版本迁移；按第一次实际变更接入，不预造所有未来字段。

动态恢复应从合法定义与保存的实例/过程清单构造独立候选，而不是以“当前活场景里正好有谁”为全部历史事实。验证失败不覆盖存活世界，不用默认值静默修补不一致的引用和知识。

### C4：时间与进行中过程可打断、可恢复

过程声明开始、边界、中止、投入、已提交结果、剩余工作与随机上下文。目标推进时间与已提交时间分开。快进、离场、保存和恢复不能退还已消耗材料、重掷已定结果或把未来产物提前交付。

预算不足保留待处理工作并在一致点降速/返回；不在某些领域丢掉事件又宣称所有世界追到目标。感知/消息打断遵循角色渠道，具体秒/分钟方案由P0原型决定。

### C5：描述不改变状态，学习需要来源

同一主体展开/收起面板不新增观察、知识、经验或随机调用。真正调查、传授与试验才提交相应记录；学习改变对旧线索的解释，不修改过去发生过的观察。

表现缓存可丢弃重建，角色所知、经历摘要、重要命题/矛盾来源与正在进行的调查应保存。记账权利、私人说法、感知信号与事实各有负责人，不能全放进Claim或一个字符串description。

### C6：允许新存在，不隐性扩张实现边界

新形态/器物/方法声明已支持的条件与作用。多种生命可以复用接口而不具同一字段集；方法可以很强，但代价/来源/例外要能执行与保存。未支持的效果明确报告，不靠描述事后编造结果。

造物/分魂可生成新实例或主体，有来源和条件；重复提交同一动作不得再造一次。规则中的复制、分化、绑定与消散并不等于引擎失误造成的重复ID或双重记账。

2026-11-03转生补充：本局连续性、世次、死亡事务、剩余/预留次数、候选随机与出生来源另有负责人，不能只绑在会被换掉的Pawn或显示面板。新世与原人物的记忆/身体/身份引用分开；候选随机根不使用可被当前世界动作序号洗动的种子。[有限转生](../../../design/systems/rebirth_and_new_lives.md)中的L场景在对应领域实现时加入，当前没有这些运行状态。

## 4. 最小反例目录（未来执行）

| 编号 | 反例 | 应拦住或保持的条件 |
|---|---|---|
| K1 | home与river都生成event_1并被跨区引用 | 出处可区分，不串到另一事件；迁居不改已有引用 |
| K2 | 玩家手动移动同时新战斗动作位移 | 一个明确提交/交接顺序，不能两个模块互相覆盖制造穿越 |
| K3 | HUD展示需求投影后保存/恢复 | 不把显示预估再次扣进真实身体，不重复消耗时间 |
| K4 | 两人共同过程、一人退出再恢复 | 单次结果，预约/占用与阶段损失一致 |
| K5 | 空值、未知功能和零储能混入同一字段 | 明确区分状态；未知不能按零推断“安全/无功能” |
| K6 | 主体误信神器性质，计划器与UI作选择 | 不读后台真值替角色纠错，不由排序/提示泄密 |
| K7 | 被引作证人的人死亡/离场 | 事件来源与未结权利保留必要历史信息，不因无活节点而失效 |
| K8 | 当前布局与保存的动态人物清单不同 | 依兼容定义构造候选；缺依赖/坏引用明确拒绝，不丢人或填假人 |
| K9 | 单位换算后载荷或时长误差60倍 | 字段单位/转换fixture可检验，不靠视觉看起来正常判通过 |
| K10 | 只展开详细说明或换观察重点 | 真值/知识/随机不变，解释只使用已获准内容 |

现有测试继续保护当前双聚落/运输/办事；K1–K10与U/R场景分别保护新契约，尚未执行。没有改代码，因此本轮不为这些未来场景新增空测试或重复原有测试。

## 5. 首轮梳理的结论与下一步

已核对当前关键脚本，明确现有人形假设、双向位置接缝、显示投影、本地ID作用域、知识结构与动态存档限制；上表是W0-a的首轮静态交付。它没有证明现有程序已符合所有目标契约。

原调查时推荐P0时间/位置、W0-b引用或错误认识闭环；这些后来已有有限交付，不再作为当前待办。恢复后的具体顺序见[ROADMAP](../../plans/roadmap.md)。每项实施前缩到必要文件与可运行样本；不能在一轮里同时重写时间、身份、物品、认识和保存。

用户负责世界概念与全局取舍；字段表示、算法、阈值、UI密度和测试定参由开发负责。需要用户决定的概念若尚无回答，保持明确未定，不以暂用值把它悄悄固化为世界法则。
