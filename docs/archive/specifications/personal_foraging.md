# P1-c1：自留采集与原公差分开

状态：已实现并自动/实机/完整重启验证，2026-11-03。承接[有限交易](local_trade.md)。先给自营生产者正常入口；受托公物的完整保管/追偿另包，不把本包当全部产权完成。实际证据见[QA](../../qa/20261103_personal_foraging.md)，当前完整验证/格式只看[BASELINE](../../status/baseline.md)。

## 玩家闭环

采集页选择“自留采集”→原身体实际到同一有限野外来源、预约/劳动→产物留在本人行囊、不送公库、不产生公差贡献→按当地需要出售或自行使用。原送库工作保持原方式，交付后才可能形成公差凭据。两种用途共用同一来源，不新增一套无限个人资源。

## 规则

- 个人采集是原日常执行器的新forage动作种类，定义在data；正数劳动/数量与原来源一致，贡献必须0，没有公共目标库存/职责支持字段。已有同类物品不代替本次采出，也不触发“把已有物送库”的旧续运快捷分支。
- 只有实际劳动完成才由原来源扣除/原actor行囊收到；预约、通路、容量、停止/控制丢失与原来源有限生长仍生效。未完成无物，完成后自然停在来源处。没有额外的个人库存/身体/世界时间。
- 原公共gather/haul不改成个人模式，取消仍保存既有真实物资；公共委托/保管责任及任意物品产权不在此处伪造。后续P1-c2须接受托货物处置权限，不能以“在包里”替代归属。
- 原采集页以模式选择复用按钮，显示是自留还是送库；新旧存档/人身/鸟身/残识边界不变。NPC也能调用相同forage规则；本包不强制所有NPC转行经商。

## 持久化

根19→20、区域16→17；村落字段不变。旧档有原自然来源时，仅迁入相应个人采集动作定义，不补物品/采出/贡献或过去劳动；早于来源的旧世界保持无自然来源，不倒造野地。旧正在执行的公共动作不变，不免费转换已付劳动。真实v1～v19及overload_v10不改写，新真实采集中途档用于完整停开接续。

## 验收

同源竞争/实际耗时/有限产物、已有物不跳劳动、容量与预约失败、中途停手/存读、原公共送库/记功不变、自留不生凭据、粗细/近远一致、旧档显式迁移/坏候选原子拒绝。实机从采集到携物/商量出售/取食有正常入口，1280×720、日志、完整停开未来一致及全量check通过后交付。
