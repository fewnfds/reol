## 1. 具体出口与范围

普通人身新局，玩家实际接触原温石、学会原循纹手法，从当面说明得知本地公源安排，向现任有权人申请一次具体借用；获签后去原地火隙完成原引息，再将同一块温石实际放回。玩家当面申请核验，有权人同意后用原身体沿真实路径去灶旁查看，再回原值事房桌前登记。最后得到的是有来源的履约记录，以及原身体或原温石的实际恢复。

本包不赠送灵气、钱、贡献或第二块温石，不要求先刷贡献，不以战斗解锁使用。本包也不禁止无许可的物理取用：许可决定是否获得当地认可，实际身体/手法/实物/源量决定能否做成；U1-b2才接有人看见后的警告和干预。

第一版仅山门既有`hearth_seam`、既有`hearth_stone`及原机构。新局内容指定原`steward`职位和`authorize`权限的组合，不能仅凭全世界任意一个`authorize`就有权办理此处公源。人物名字不写成永久掌权者；每次当面办理从原职位查现任。

## 3. 唯一归属与最小数据

拟新增`SimSiteAffairs`与`site_affair_schema.gd`，只保存地方安排、具名许可及办理/核验依据。原源、器物、身体、健康、职位、社会记忆和服务job仍各自唯一拥有事实。

建议内容文件：`data/definitions/site_affairs.json`保存有限规则，`data/scenarios/source_loan.json`保存仅新局的装配。以下为拟议字段，实际严格形状在实现时确定：

| 记录 | 最小内容 | 不保存的副本 |
|---|---|---|
| case | 稳定ID、规则版本、启用时刻、region/institution、指定office/permission、source/object、原登记载体、原归还place、固定可选target | 源量、器物储热、独立职权矩阵 |
| 已知安排 | 实际说明者/接收者、原社会事件引用、case和固定条款版本 | 全图源列表或后台库存 |
| note | 稳定ID、case、受益人、签发者/office/载体、具体source/object/target、issued_ms、start_until_ms、原办理job/决定/事件 | 身体、可花费qi、通用永久权限 |
| 用源尝试 | note引用与原`spirit:N`；至多一笔未结束绑定，成功使用的稳定引用 | 第二份源job、第二预约、重复before/after/output |
| 归还核验 | 申请者具名归还说法/所用原社会事件、个人采信决定、执行者、原核验job、现场观察时刻和位置/所见归处、回桌登记事件 | 第二个温石、实时远处位置、完整人物轨迹、未经见证的“本人亲放”证明 |

source/object/target签发后固定。每人对此case至多有一笔尚待使用或归还的认可借用；重复同条件申请返回原进行中或原答复，不重签、不延长期限、不重掷意愿。这个限制约束case内许可，不代替原器物/源的真实竞争。

本包归还条款是**同一公器确已复位到约定处，可以重新供用**，不要求机构客观证明究竟谁亲手放下。客观取放者仍由原器物事实记录；申请者说了什么、核验者相信什么、机构依据何事结清分别保存。正式内容应为“已核公器复位，某人声称归还”，不能写成“已客观证明某人亲放”。

原职位记录没有完整任免时间线。签发/最终登记当刻查现任与指定权限，历史候选查保存的签发快照、case范围和原登记事件，不能拿今天holder否定过去签字，也不能声称已重演全部任职历史。新任如何推翻旧账留U4；本包旧的合法一次使用不因换人自动改名或倒扣。

## 5. 玩家怎样知道在借什么

当前源域`describe().remembered`仅来自本人原用源active/records；`SpiritSourceRuntime._seen_sources`是临时UI缓存。不能从全部source定义生成C对象后声称本人早已知道，更不能让新请求依赖读档就丢失的UI缓存。

首包采用**当面公布的地方安排**作为稳定入口：实际值事房里原登记载体可用、本人在场、现任管事能交流时，C提供“询问公源借用安排”。回答只给此case的地点、具体公器、办理方式和一次用途，不透露源量、别人当前预约或未见活动。原社会事件保存具名说明，后续C的借用对象由本人这条知识或自己的原实际用源经历列出。

若想实际看到源，按说明沿原路去看；听说地点不等于学会方法或知道当前余量。申请者须持有同一公用温石并已亲自学会原手法，方可申请本首包路径；原take/study须实际完成。这样值事房能指认眼前实物，无须为源的首次亲见另造通用发现平台。未来可以支持未先取公器的申请，但不作为首包验收。

拟新增的有限动词为“询问公源安排”“申请一次借源”“请求验还”；它们进入既有动作/对象补全，不长期增加三排专用按钮。对象使用case/固定offer/note稳定ID，`conditions`首包保持空；本人/温石由固定offer表达，不放开任意条款。鸟兽听不懂或无任职的人不能替机构签字；正常脚本请求经过同一domain条件。

## 6. 签发、绑定与消耗

### 6.1 正式签发

当面申请只说明意图。有权人按已知地方安排、本人精力/忙碌、已有事项及原具名履约记忆作有限判断；复用原社会决定缓存。无真实当面沟通、无指定现任、原身体忙碌、原温石不在申请人手里、方法未知、已有未结借用时给出具体原因，不改原工作或赠予物资。

答应后复用原visitor job执行一次值事房办理。建议服务kind`site_loan`，job.actor仍为申请者，options只引用case/固定offer/具名签发者与office；完成时再核指定现任、实际桌案/登记载体和双方通信/行动条件，才写note与签发事件。此处不签source库存保证，管事不能用后台源amount判断“库存一定够”。

原服务只占申请者身体，不假装已把管事固定在桌前；管事离岗、受伤或忙于别事时，完成检查失败，申请无许可且不丢实物。用户可等其实际回岗再申请；重复同条件不洗掉个人拒绝。

### 6.2 最迟开始与原用源

`start_until_ms`表示**最迟开始一次引息**，不是许诺结束时刻。开始必须满足`issued_ms <= job.started_ms < start_until_ms`。在期限前已经合法绑定的原过程可以完成，期限到达不神秘取消原预约；若中断释放时已过期，则不能凭该note重开。

原`SpiritSources.begin`先完成原方法/身体/原石/源量/预约检查；成功分配原job后，同步关联至多一份有效note。准备绑定只读，失败不留下半个许可锁；提交无await，不重入另一个世界时钟。所有UI/脚本/NPC都经此原入口，不由源面板另开一次许可消费。

许可绑定不另占源量；竞争仍由原`available/reserved`与物件排他处理。无许可时不拒绝原物理begin，只保持“这次没有获得此case认可”；U1-b2再从实际可知事实决定是否干预。源量不足、石头有人操作或本人qi已满等原失败不能消耗许可。

原统一`_finish`建立record后再同步事项结果：`success`且actor/source/object/target/时序全部匹配，才把一次权利记为使用；`cancelled/failed`只结束本次绑定，未来仍可在期限内重试。相同record重复通知幂等，不重复结清。具体output、loss和支出仍只读原source record，不复制奖励。

## 7. 归还不是后台自动验收

正常QA路线由申请者本人原`take`、用源及其后`place`完成，但这条路径不是NPC核验作者的全知门槛。申请者可以当面说“我已交回，请核验”，即使原后台没有本人placed；其真实性不能由核验者直接读原私下日志判定。有人代还、申请者虚报亲手作者、本人是否被相信和公器归位义务是否结清是不同事实。

核验者按已听到的具名说法与自己已有的有限记忆作决定；没有新建万能骗术系统，也不新增全局诚实值。若别人实际代还，同一公器已经回到约定处可用，本条款允许核验者登记归位义务完成；若申请者另声称亲手归还，记录保留这只是其说法。个别人实际见过另一位归还者，可据本人记忆有不同看法，但不把后台作者广播给全世界。

原placed事件并不会让桌前管事自动知道。玩家回到管事面前提出验还，管事同意后进行一次**有限实际核验行程**：

1. 当面接受、记录具体note与申请依据。此时只知道申请者说自己已放回，不提前登记履约。
2. 核验visitor job以有权人作为`job.actor`，沿原真实路去灶旁；申请者明确保存在`options.requester`及note中。原服务拥有核验者身体，申请者可继续活动，不能借申请遥控核验者或强清其原事务。对同一核验者重复催问返回已有受理/忙碌结果，不能给他并行创建几条申请者的路线或核验身体。
3. `inspect`阶段到场，按自身位置、同高度、实际遮挡与原公器引用查看。只有同一原石实际在约定place、按实际可检查条件可重新供用，才形成具名现场观察。这里亲见证明的是“此刻公器归位”，不能证明谁亲手放回；申请者的作者说法仍只来自其当面声明。另一块同定义温石、原石仍被携带、地点错误或不能亲见时，不能登记公器已复位。
4. 复用原导航回值事房，以`register`阶段在原桌前核对现任/载体，才把现场证据及原具名说法写入事项账，形成“已核公器复位，某人声称归还”的登记事件，并按本条款结清归位义务。即使核验者相信本人亲放，也不能把个人采信写成已客观证实的作者事实。
5. 原service finish恢复核验者的先前自主，申请者按其后实际收到的回话/可查登记得知结果；核验者在远处的具体坐标、路障、当时看到的一切不会自动进玩家面板。

这是原`travel/work`之上的两段有限stage，原运粮已有多段路径实践；但**现有服务没有这条核验流程**，须明确修改kind/stage/spec与schema。不能声称原接口原封不动即可完成。也不新建通用工作流、第二移动器或第三级身体锁。

现有`SimWorkplaces.assessment`的`workspace_action_available`会把任何服务占用视为忙碌；核验者回桌登记时恰被自己的job合法占用。新增检查只允许该已验证job作为当前所有者，仍核控制、原actor.active、位置/桌柜和其余域占用；不能临时关掉全局action guard或先释放再补记。这条接缝须单独测试。

现场原石不在约定处、在核验者到场之前又被拿走或仍有人携带时，亲见不能确认复位，核验失败、无结清记录。有人代还而原石已在约定处时，不因后台作者不是申请者而强制失败。现场已经真实核验且持久保存后，第三人再取走不倒写当时的归位事实；回桌登记使用原现场证据，不再用当前远处真值拒绝或确认。之后的新保管或违约是另一件事实，非本包通用物权。

任一路被阻、核验人被击中/控制丢失/中断/离任或桌柜失效时，原job和真实证据保留其终态。现场观察已发生但未登记，状态就是“已查验、尚未入账”，不能退款式删除过去，也不能当成已经结清；后续可当面重请有限登记，须复用既有现场证据且不得重复签收。过期未用的借用仍可实际归还公器并核验为“归还、未用”，不恢复已经过期的使用权。

## 8. 候选与因果检查

严格shape、整数时刻/精度上界、稳定序号与最大记录预算进入原数据规则。候选须独立恢复case、职位、源、器物、服务和社会记录，随后交叉核验，最后一次替换活世界。恢复次序不足以互查时分为本域形状检查与全域`cross_valid`，不能读取活会话来补证。

至少验证：

- case只引用保存世界确实存在的原机构、指定office/permission、原source/object/return_place及登记载体；空case旧档不能带该case的许可或服务job。
- 具名说明、个人决定、签发事件、note及完成的`site_loan`必须双向对应，当前历史签名不由现任者名称覆盖。不能加一个孤立note绕过办理时间。
- 同一note最多一条活绑定、至多一次原成功record；同一source job不能给两份note消费，不能引用他人或其他source/object/target，不能在签发前或最迟开始后绑定。
- 每个失败/取消attempt对应原record，每个活绑定对应原active；不能从事项表删除已消费成功引用后重复使用。原源量/qi/charge仍由原账核验，许可不让坏余额过关。
- 归还说法必须有实际当面发言者、接收者和正确case/note，个人采信须引用他实际听到的说法与原已知依据；不要求说法作者等于原真实placed作者，也不因缺本人placed拒绝声明。原取放记录仍独立校验其自身事实，不能改成声称者名字去迎合机构记录。
- 核验job的申请人、执行者、note、两段路线/阶段和现场观察事件一一对应；观察须是本次受理后的同一原公器、约定place和正确时序。不能拿旧观察、错物或未来观察结清新借用。第三人代还可以满足归位义务，作者说法的真假与机构是否依据复位结清分别成立。
- 现场观察只验证记录内部的有限距离、同高度、时刻与原物件/所见归处，不用今天的墙门、人物坐标或后台私下placed作者冒充核验者知识；不声称完整重演全部历史遮挡。当前in-flight阶段的身体/路线/物件条件另按原候选查自己的地图。
- `register`成功必须有本次先前真实现场证据、完成的原job及匹配的登记事件；同一依据不重复结清。登记准确引用“谁说归还、谁见到公器复位”，不得把声称、采信和客观亲手作者合并。原社会知识受众和个人回想依原事件，不因后台note终态向缺席者泄漏信息。
- 受击/取消/到期/换任/新旧会话切换正确释放原身体与许可绑定；不保留上个会话的临时选项、排队命令或新局安排。任何坏候选拒绝时原世界、地图、钟、身体、物资与全部记录不变。

## 9. 非战斗真实验收流程

纯规则和有限运行适配通过后，必须用主局普通命令跑以下流程，不能注料/改坐标/教会本领/关闭NPC自主：

1. 正常人身开局，真实取同一温石并学习循纹；到原值事房与现任交流，保存具名公源说明。
2. 选择具体一次用途，原办理时间结束才得到签发记录。`body`目标须先有原温养等真实消耗，或选择确有容量的`stone`目标，不改余额制造需要。
3. 沿真实路径去原地隙，在原有限源量和物件竞争下开始引息；在进行中普通保存。未完成时无新增qi/charge。
4. 完成后原源实际少一批，原目标只增加接受的产出，note引用同一成功record。取消/源不足/他人先用分别保留尚未消费权利。
5. 本人实际place放回原石，再回现任面前具名说明并请求验还。观察核验者用原身体出门、到灶旁看到原石、回真实桌前登记；无需等他偶然路过现场，也不代替他瞬移或手填成功。
6. 正常路线保留原take/study/source success/place供联合事实与QA核对；NPC据实际听到的说法和现场观察办理，正式登记只证明“已核公器复位，某人声称归还”。人物和源的其他生活继续，不开战、不重建农场也能完成。

分别保存已签未用、引息中途、核验去程、现场已见回程与回桌登记前的正常档；完整停开后从同源到固定共同未来，比较完整联合状态。至少另测：原石仍在包中却声称已还，核验亲见拒；第三人已实际代还而本人声称亲放，允许按公器复位义务结清，声明仍只是声明；核验前被拿走则不能确认，核验后第三人取走不倒写旧观察；两位实际见闻不同的人不自动获得相同作者判断。还须覆盖核验人在路上受击、门墙阻路、期限中途、两人竞争及旧局新局替换。

**可达性是交付门槛。** 必须实测新局值事房/厨房路线、核验者身体占用、原柜台行动guard与阶段切换，确保无AI辅助的普通玩家能完成全程；“规则允许，但只有官员偶然站在灶旁才能交任务”不算完成。画面入口/文字须实际运行检查，最终完整回归和证据只维护BASELINE。
