# U1-b2：公源看护、当面警告与有限驱离

2026-11-04。**状态：已按本规格实现，定向、普通主局路线及完整停开一致性已验证；最终完整检查以 [BASELINE](../../status/baseline.md) 为准。** 接在[一次公源借用](source_loan.md)与[有限交锋感知](conflict_perception.md)之后；实际证据与首轮修复见 [U1-b2 QA](../../qa/20261104_source_care.md)。本规格保留设计推导，“拟补”段落用于说明实现接缝，不是第二份完成度清单。

## 1. 本包要形成的玩法

新局中的原管事安排原人物石头，在一段有限时间内照看原地火隙及原公用温石。石头仍吃饭、休息、交接已经承担的实活；有空才沿原路线去灶旁。玩家照常可以学习、签借用、引息与归还，也可以在没有认可的情况下实际使用。只有看护本人确实看到有人引息，并且尚未采信本次借用依据时，才当面提出警告。玩家能停手、说明依据、离开或继续；宽限后仍在眼前强行取用、看护仍愿意且有能力时，才可能用原身体发起原有限驱离。

本包交付的是一个有生活、有盲区、能被说服或击退的具名看护人。不是地图上的许可空气墙，不是全门派同步敌对，也不是替任意土地、器物与组织建立通用执法系统。胜负保留原消耗与挫伤，不赠送源、温石、贡献、永久通行权或所有权。

本包不需要新源、新人物、新武器或新材料。全部利害仍来自唯一的 `hearth_seam`、`hearth_stone`、原身体、原机构和原源预约。

### 2.1 两个实施前置问题

**自动方目前是写死的。** `SimConflicts._ai_motion`、`_ai_action` 和 `ConflictPerception.cues` 都以 `row.defender` 为自动方。让石头作为 initiator 开场，会导致石头自己不出招、玩家作为 defender 反而被 AI 接管。不能用交换参数掩盖：发起人、被警告人、退让方与社会事实必须保留真实身份。

拟改为逐参与者判断是否由原自主策略控制，并给该人采样对应对手的提示。开场前从原身体与 `activity_previous_autonomy` 捕获原自主意图；`previous_autonomous` 只证明原自主前态，**不等于身体控制权**。每次行动仍查真实 `embodiment` 的 action/motion 等通道与实际玩家主体政策；控制丢失或附身冲突走原停止路径，不能凭旧布尔值继续驱动身体。也不能把战斗期间统一设为 false 的当前字段当作“双方都应手动”。人身玩家、非人开局后自主生活的原人身、NPC 对 NPC、控制丢失和完整存读必须分别验证。两个 NPC 同时动作时仍先采样同边界全部提示，再提交新起势，避免字典遍历顺序给予后手全知。

**内部开场时间目前不允许。** `conflicts.begin` 要求 `world.elapsed_ms == world.target_ms`；看护宽限到期发生在世界推进内部，通常还没到最终 target。拟拆出共同的受限开场提交，普通玩家入口保留原要求；看护入口只接收本域已验证、确实到期、尚无交锋绑定的 warning ID，并在当前毫秒复核本规格全部条件。不能临时修改 target、补写未来时刻、从公开请求传 `internal=true` 或仅凭一个字符串理由绕过保护。

## 3. 唯一状态所有者与最小记录

建议新增一个很窄的 `SimSourceCare` 及独立 schema，只保存看护安排、本人观察、沟通依据、警告和与原交锋的关联；新规则放 `data/definitions/source_care.json`，新局安排放 `data/scenarios/source_care.json`。这些名称是实施建议。它不注册为第二身体活动，不保存位置、路径、源量、qi、stamina、伤势或器物容器的副本，不创建新 autoload。

| 拟议记录 | 最小持久内容 |
|---|---|
| 看护安排 | 稳定 ID、原 case/region、委托职位与当时具名委托者、原看护人、明确范围、起止毫秒、来源/接受依据、状态/结束依据；当前由其发起的原查看 action 引用 |
| 本人观察 | 看护人、原 source job ID、case、观察毫秒、双方当时位置/高度、所见源与原器物；只记足够支持本次判断的有限事实 |
| 已收到的借用说明 | 发言者/接收者、具体 case/note 或“未能说明”、原个人记忆/具名发言事件、收到时刻、来源、采信决定；不复制整本 notes |
| 警告 | 安排、被警告人、具体原 source job、首次有效目击、实际警告/接收事件、开始与宽限截止、采信依据、终态原因/毫秒、原 conflict ID（如已开场） |

“尚未采信依据”“借用已经获得机构认可”“这次引息物理成功”分开成立。警告不改原 note 的 `bound/used/attempts`，原 note 也不能给看护增加未收到的知识。

每项安排对同一原 source job 至多一次活警告、至多一次驱离关联；同条件刷新面板、反复询问、重复通知不能延长宽限或重掷意愿。记录、观察频率、同刻扫描次数均有有限预算；达到预算给出可解释的暂不处理，不删除旧因果后重新给奖励或开始新的袭击。

## 4. 看护安排、意愿与原生活

### 4.1 新局与授权

只在主局明确装配完原 case、机构、源、温石与人物之后，显式装配一项有期限的开局安排。开局内容可明确写“石头在开局前已经接受本时段看护”，并标为开局初始社会事实；不能伪造一次当前身体并未当面发生的对话、随机接受或调岗事件。人物不瞬移到灶旁，原 profile 仍为当前代码中的 `deliver_water`，不改成永远站岗。

委托范围是本 case 的“询问依据、先劝停、必要时有限驱离”，不是任意封路、搜身、扣押、没收或签发公源许可。开局安排不能由一条温石定义、某人会御气或 `workplaces_version` 自动推导。后续普通任命若本包实现，必须真实当面、现任有指定权限、看护人自主且没有冲突承诺，复用原具名社会意愿；同条件不反复抽签。首版无需做通用任命系统。

初始建议为有限两小时看护，具体参数进入数据并在实测后定；期限不是“玩家回来之前”。到期不延长，重复请求不刷新。现任撤回本机构授权会使未来执法资格失效；看护人实际听到撤回之前可保留旧认识，但本首包不继续允许靠已经失效的委托升级新驱离，界面表述是“本包不再执行”，不是所有人瞬间知道任免缘由。详细命令传递与违令留组织包。

### 4.2 不能拥有第二具身体

安排只提供下一项打算。原吃饭、休息、报工、已经接受的常备任务、原值事职责、医疗、运送、建造、个人制作、学习、器物操作、对练、交锋和控制权全部仍有效。不能因为接了安排就清空 `actor.active`、强关 autonomous、扣走他人 job 或把原预约释放再补回。

建议在原自主选择的有名接缝中决定是否前往照看：只有原需求已满足、原身体允许、无更早承诺且本人仍愿意，才通过原 `submit_action("check_kitchen")` 真实出发；记录刚分配的 action ID。路被墙门阻挡就按原执行器失败并退避重试，不瞬移、不另开服务 actor 去代站岗。

到达后的原 `work` 是有限查看时段。看护可在本人空闲或本安排自己的 `check_kitchen/work` 中观察并讲话；途中、吃饭、休息、其他人的受托工作或另一域占用时，本包不额外抢出执法动作。原查看结束仍按原流程释放 `actor.active`；需要再次查看时由安排的有限再评估边界触发下一次原决策，不能只依赖原十二分钟重试，也不直接让另一个执行器写位置。

吃饭/歇息阈值达到、伤势需要优先处理、控制丢失、赴另一聚落、原承诺开始、看护撤回、委托到期或现任资格失效，均使当前警告关闭或停止升级。只允许中断本安排自己发起的那条查看去满足紧急原需求；其他活动仍由自己的原取消规则收尾。看护离岗不恢复别人已经完成的源量、不消灭自己的旧记忆；回来须对当前真实活动重新观察。

本包不重做通用 needs 抢占器。若原查看时段不能在需求临界点让人吃饭，给这个有限查看增加明确的需求边界即可，不能由“以后自主会处理”掩盖本包全天不离岗。

## 5. 看见与知道，不能跳过中间一层

### 5.1 可见引息才是介入起点

调度器可以知道有一条原源 job，以便只唤醒相关有限观察；这是后台物理调度，不等于 NPC 已经知道。产生目击前，必须结算本人原地区至该毫秒，并检查活身体、同高度、观察半径、真实墙门/柜体/地形视线，以及本人现在确实处于允许观察的看护时段。远处源开始、迷雾显示、UI 选中、后台 note 未绑定、只听说附近有玩家，都不能当作目击。

所见是“此人正借眼前这处源与这块原器物引息”。没有被告知时，不擅自读出人物心里选择的 `body/stone` 用途、当前 qi、隐藏技法、背包清单或后台 source amount。具体用途可在当面说明时由对方宣称，判断仍保留来源。看护到场太晚，不会自动知道对方何时开始、此前用了几次或最初是否在许可期限内。

首包不追索不可见期间已经结束的私下使用，不从原 `records` 全量回放“发现犯罪”；过去真发生与现在有人知道是两回事。

### 5.2 原签注目前不能随身展示

当前 `site.note` 是固定值事簿附页，记录尚不是可携带的纸证物件。不能在地火隙旁凭 note ID 远程翻整本账，然后把结果写成“看护亲眼验过文书”。首包采用有限的当面**说明借用依据**：

1. 发言者只能转述自己实际已知的该条签发记忆，或明确提出一条未经证实的口头说法；不能引用别人私有记忆来生成选项。
2. 通过原 `social.learn` 转述时，保留来源和 `direct=false`。看护收到的是“某人告诉我管事曾签下这一条”，不是自动验证的官方真值。
3. 看护按已知范围、时间、对象、本人既有具名履约记忆和发言者可信度有限采信；正常首次合法借用应有可重复到达的和平通路，不要求先打架刷信任。具体参数由开发测试定。
4. 本人原本就在签发现场，或现任管事亲自在场确认，则可保存更强的具名来源；若以后实现本人走到原簿前核查，必须真实到场、原载体可读且只查被提出的具体一条。后两种不必都扩成首包新行程。

本首包的必要路径是当面说明与带来源的采信，不扩便携文书/伪造印章/万能审计。只有收到的具体依据才能决定免警告或解除警告；不能扫描 `notes_for` 以外全部 notes，不能用后台 `note.used/bound` 偷偷揭穿本人从未见过的重复使用。一个已用过但看护不知的旧许可仍可能骗过他；这不是存档失真，原客观使用和个人认识各自保持准确。

看护只知“没有得到足够解释”时，警告用“我还没核到这次的借用依据，请先停手或说明”。不能写“系统已证明你偷取”，也不产生全局犯罪/恶名标记。

## 6. 警告、合理宽限与驱离门槛

### 6.1 警告不等于已经开战

发出警告还须双方实际能通信、在有效听说距离与视线内；不能给听不到的人启动惩罚倒计时。保存实际接收者与毫秒。警告只产生具名沟通、一个有限宽限和可理解的人话，不调用 `interrupt_occupation`、不取消源 job、不锁玩家移动、不扣源、不消费 note，也不提前把双方 `autonomous=false`。

建议初始 `grace_ms=90000`，观察步长与宽限数据化。原源过程为 `120000` 毫秒，原常规决策间隔为十二分钟，故不能靠普通闲逛偶遇与下一次十二分钟决策实现此包；同样不能在警告后一毫秒自动攻击。

当前 [GameClock](../../../scripts/autoload/game_clock.gd) 的等候推进一次可提交到下一分钟，[ConflictRuntime](../../../scripts/runtime/conflict_runtime.gd) 直到回调才取消等候。若宽限只有十五秒，第一次看见提示时可能已经开打。首包采用宽于一分钟的初始宽限；**当前玩家实际扮演的主体收到这次具名通信**后，运行适配必须立即停止后续等候、恢复一倍速度并暂停以供选择。不能写成 `actor_id == "player"`：鸟/魂开局时原同名人身可能是自主 NPC，其收到警告不代表玩家收到。暂停期间世界毫秒不走，远处源告警和 NPC 对 NPC 的警告不打断无关玩家。不得先把世界跑过截止再回拨时钟补提示。九十秒是本包初始可调参数，不是世界概念承诺；任意毫秒精确打断整次主动快进若需要更大的钟契约，应另包实施，不伪称已有。

### 6.2 宽限内的真实选择

- **停手**：原引息取消生成原取消 record、释放唯一预约，不提前得到 qi/储热；警告结束，不再为这次已经停掉的 job 开战。
- **说明**：使用上节当面说法与来源，足够采信则解除警告；收到新信息不会重置原借用期限或把一次变多次。
- **离开或遮挡**：按原活动条件结束/失效；本包不隔墙追踪未知坐标，失去有效当前观察则关闭本次升级资格。重新见到新的持续活动，另有明确新观察依据，不把旧倒计时暗中续用。
- **继续**：保留原 job 正常进度；引息可能先于宽限完成，完成后本包不追溯扣回，不为保证剧情开战而延迟源完成。

被警告人可在原引息中用通信通道作有限说明；这个动词不要求 `actor.active` 全空，也不先取消原引息。若现有统一请求的身体检查不支持这种有限沟通，须添加明确通信入口，不能绕过所有动作占用。

### 6.3 截止时重新核验，符合才开场

在 `due_ms` 重新检查：

1. 原看护安排仍有本 case 的当前范围与资格，尚未撤回/到期；看护仍原自主可决策、能通信和行动。
2. 本人现在仍实际看得见同一被警告人、同一源、同一未结束原 job；不凭首次目击的旧坐标或后台 active 去隔墙追击。
3. 本人没有采信足够说明；不能因根本不知道一条已存在许可，就把后台真值强写进个人理由。
4. 吃饭、休息、伤势、另一项承诺/域占用不阻止；原 `health.can_fight`、真实 stamina、当前 qi 和实际可用手段允许至少一种动作。只会木剑却没实际持有武器，不凭技能名开一个永远不能动手的交锋。
5. 委托中已接受的有限风险/行动范围仍适用；看护选择退让、暂且记下或无力驱离是正常结果。不得读取对方隐藏全属性来判断胜率，也不捏造一次不在场管事发来的新请求。
6. 双方没有别的活交锋/对练/示范所有者；原冲突开场的距离、控制与原不变量仍成立。

通过后，由可信内部入口以**看护人为 initiator、原用源者为 defender** 开一次 `drive_off`，把 warning 与 encounter 双向绑定。只有此时才由原 `interrupt_occupation` 中断双方实际活动：原引息按取消结束，许可释放活绑定，原尚未成功的源不耗量。不得先取消源再用“原 job 已不存在”取消整个争端，也不能先取消后一拍才生成无法验证的虚假新冲突。

中断与开场是一笔不含 await 的共同毫秒提交：开场前复核原 active，保留匹配取消 record/结束毫秒，关联原 warning 与新 encounter；候选能复核它们。源中断会同步触发原结束通知，须在这笔可信开场提交中收集对应 record，完成后统一结束/关联警告；不能被普通“源已结束”回调先删掉依据。提交中间态不暴露给保存/请求，不接受外部布尔值假装处于提交。警告到期本身不等于施法成功，起势与代价仍由原交锋域执行。

开场后按原有限交锋走，不把已消费的看护警告重复转为第二次开场。后续离岗/资格撤回只让看护停止继续执行本次驱离、由原合法终止路径收尾；已在途原气弹、已付代价与已形成挫伤按原规则保留，不用行政状态抹掉物理历史。

## 7. 共同时间、玩家离场与同刻顺序

看护没有专属时钟。安排到期、原查看阶段、原需求临界、有效活源观察和警告截止进入原边界机制；没有活安排/相关过程时不制造高频空扫描。只针对已装配的一项安排及这处源的有限候选采样，不能为一个样本给全世界人物永久每秒 tick。

有活源候选时，可用有预算的一秒级观察边界复核同一原身体；每次都重新检查真实可见条件。原开始/结束通知和墙门/控制/地区失效只让下一次该有限采样重新评估，不直接成为记忆。源结束、警告终止、离岗、到期时停止对应高频边界。

在原地区和共同时间已经推进到该毫秒后处理看护，不重排现有域的结算顺序。推荐在原 `_settle_current_processes` 全部结算完成后、未来自主行动之前收敛本次观察/警告与可能开场；未来自主动作真正启动后登记下一次有限观察边界，不递归重入同刻所有域。

同刻明确优先：原源完成/取消、身体伤害/控制变化及既有交锋结果先结算，再核看护是否还能升级。故源恰好在宽限截止成功，按已完成处理，不再中断追罚；委托恰好到期，不能再开场。当前命令只能在世界已经接续的时间点提交，不能把“在截止后才点说明”伪作截止前。具体集成应以现有真实先后为准写测试，不靠变更全局域排序补剧情。

近处/远处/无人观看均使用这一规则与原身体。玩家离开只影响看到与收到什么，不取消看护安排、不重置警告、不退还伤势、不补源、不换一具满状态 NPC。切换 active region 不重新初始化。这里仍是已有小世界内原有限过程，**不是已经完成大规模远区战争粗算**。

## 8. 后果、消息和玩家入口

新的交互沿原动作/对象补全，只增有限“说明本次借用依据”“询问/撤回本人看护安排”等必要入口。复用原 `pending/observe` 三键 process 形式；只读查询不记录目击、不掷骰、不取消动作、不向对方自动传话。真正说明必须提交一次实际通信。

被警告者能看到谁说话、针对什么、仍有宽限以及当前可选响应。无关远处人没有“全图看护倒计时”或原源精确剩量；玩家回来可从自己记忆、当事人口述或以后实际调查得知。原社会事件明确 actor/target/受众，旁观者要有本次真实观察或通信依据，不能只因为同聚落就自动知道全部许可与理由。

首包最小社会后果是保存具名“曾受劝阻、当面说明、看护采信/未采信、发生驱离与最终停手”的有来源记忆。不自动加全门派恶感、不重复刷个人关系数值。若使用原 `remember_outcome`，只对实际知道该事件的本人、一次幂等应用，不能把“未说明”映射成已经证明的背叛。

原冲突域已有有限现场事件；若本包要让看护警告的原由进入这些事件，须继续使用明确受众和参与者字段，不把私下借用附页塞到公开 details。驱离不改原 case 的签发、所有权或职位。打败看护只影响本人伤势/能否继续值守；公源仍有限、原石仍原归处、原签账制度照常存在。

## 9. 候选、证据与旧局迁移

本包的严格 shape、稳定递增 ID、整数毫秒/精度上界、最大记录预算和规则版本须独立校验。只有全部候选域独立恢复并交叉验证通过后，才能替换活世界；不读当前活会话来替坏档补身份、视线、委托或许可。运行适配临时选择、通知去重与排队命令在换会话时清空。

必须双向核验：

- 每项安排引用同一候选世界真实存在的原 case、机构/指定职位/范围、具名看护人及明确开局来源或真实接受事件。一个人不能有两项互相矛盾的活看护打算；旧空域不能带新 warning。
- 活出勤只能指向看护本人那条原 `actor.active`，action/目标/阶段/开始时刻相符；不能把别人 `check_kitchen` 的 action ID 或已消失的路线当作第二身体。终态用有名结束/失效证据，不要求永久保留每个无关 visit 的完整轨迹。
- 目击引用同一原 source job/record，观察时间落在它真实进行期间；观察人/对象位置、高度、距离范围及身份符合记录。不能把今天的墙门或现在坐标倒写成历史亲见，也不声称重演了完整历史遮挡。活 warning 若正等下一次合法观察边界，可保留“上次曾看见、尚待重核”，不能用同毫秒之后才新建的墙倒判旧警告从未有效；下一次升级必须用候选自己的当前地图重核，保存/恢复不得凭旧目击直接施法。
- 警告必须有本人已接受安排、真实所见、双方实际通信/接收和正确宽限计算；截止、失效、当面说明、采信与原 job 终态的时间不矛盾。不允许孤立 warning、未来接收事件或只改 due 延长宽限。
- 许可说明只引用说话者在该时刻确有的个人记忆/具名说法，以及接收者实际收到的来源快照；不能从后台 notes 直接补一个 `direct=true`。后台合法 note 与被采信记忆可以不同，但各自原引用必须有效。
- 未升级警告不能有新 encounter；已升级警告至多绑定一条与其 case/双方/截止/源中断一致的原交锋，原 encounter 反向引用同一警告。普通无看护理由的原交锋不能偷挂不存在的 warning，也不能删除关联后重新发动。
- 驱离开场中断的原源 record 必须来自同一 job、正确取消时刻与人物；若源先成功，不能伪造取消或倒扣它的 output。原 note 的 attempts/bound/used、源预约和余额仍由原事项/源域验证，不由看护 schema 豁免。
- 原双方自主前态、真实动作支出、在途气弹、挫伤、退让与唯一身体区间继续通过原候选；不能利用“NPC 主动发起”把玩家设为自动，也不能把自主 NPC 恢复成永远 false。

旧存档只通过对应旧包络显式加入**空看护状态**；不补职责、许可传播、既往警告/犯罪、原源量、人物、温石或隐藏初始安排。恢复路径不调用新局装配，不因已有工作间/case 就启用本规则。当前现代包络缺失必填域应拒绝，不能一律当旧档补空。实际根/区域/schema 版本在落地时确定，不在本规格预订数字；历史 fixture 原始字节保持不变。

## 10. 必须交付的验收矩阵

表中的条件由纯规则、独立候选、普通主局命令和实际画面分别覆盖，不靠 UI 截图代替规则证据，也不把测试注入当正常玩法。真实可玩流程不能注料、改坐标、免学方法、改满 qi、关 NPC 自主或调用假内部成功。

| 场景 | 必须观察到的结果 |
|---|---|
| 正常新局装配 | 只一项显式有期限看护、原人物原职责；没有新增源/石/武器、人物瞬移或伪当面对话 |
| 原值守人先有送水/报工 | 原活先收尾，真实携带/预约不丢；其后才能去查看，不出现第二路径 |
| 饥饿、疲劳、伤势 | 正常吃饭/休息/护理或停止升级；不能因在岗永远不离开，也不能假清伤势开战 |
| 有许可并当面说明 | 玩家真实 take/study/签发，原记忆带来源传达并可被采信；有可重复的非战斗完成路线 |
| 有许可但看护未被告知 | 不自动扫描整账；可以先提出有限警告，说明后解除，原 note 没有被二次消费 |
| 无许可、无人在场/隔墙/不同高度 | 原引息仍可真实成功；不远程扣源、没有偷造目击或驱离 |
| 看护真实看见、能听见 | 有具名警告和完整宽限；原 source job 继续、原预约仍唯一，暂不扣 qi/体力/源 |
| 只开 pending/observe/面板 | 不生成说明、目击、警告、关系加减或新随机决定 |
| 宽限内主动取消 | 原取消 record、释放预约、无产出，无交锋；过期许可不能借取消重启 |
| 宽限内收到可信说明 | 正确解除该警告，时间/对象不匹配的说明不被冒充为匹配，不全局同步 |
| 宽限内被遮挡/离岗/另有旧活 | 警告失效或停止升级，不依靠最后坐标自动执法；过去记忆与源实况分别保留 |
| 截止时还在眼前继续且可驱离 | 一条具名警告关联一条原交锋；此时才中断同一原引息，无提前产出/重复成本 |
| 源完成与截止同毫秒 | 原源成功先成立；不追回产出，不再凭已结束 job 开场 |
| 委托到期/撤回/权限失效 | 不新开驱离；已有过程按明确原终止收尾，既有伤势/支出不重置 |
| 无 qi、没武器或伤重的看护 | 不能凭定义会招强行开战或免费御气；留下劝阻/无力处理的有限结果 |
| NPC initiator、玩家 defender | NPC 正常自行走位/发招；玩家保持手动，不能被 defender 分支自动施法 |
| 双 NPC 与非人开局后的原人身 | 依据原自主/控制归属选择双方自动方；不把 actor 名字 player 当永久手动标志 |
| 双方同边界起势/气弹误入 | 提示先统一采样、原代价与命中顺序保留；后处理者不能看见同边界刚生成的未来提示 |
| 任一方退让/看护落败 | 原伤势、消耗、有限退开与自主恢复；无赠产、无满状态看护复活、无重复追打同 job |
| 等候/四倍速收到本人警告 | 首次可响应时仍有合理宽限，停止后续等候并暂停；鸟/魂开局的自主原人身收警告不误暂停玩家，不先打完再弹提示 |
| 玩家离开/切 active region | 原安排/警告/交锋按共同毫秒继续或按真实条件失效；不冷重启、不靠窗口是否打开推进 |
| 进行中停开一致性 | 出勤途中、已警告未到期、已说明、刚开场、气弹途中与退让途中各保存；完整关开后同源推进到固定未来，完整联合状态一致 |
| 历史档/新旧会话替换 | 旧域空迁移且 fixture 字节不改；不偷偷启用看护、继承上局通知或复制初始人/物 |
| 恶意/坏候选 | 错源/人/job、孤立警告/交锋、伪知识来源、未来时间、双身体、已成功却伪取消、余额篡改均拒绝；活世界/钟/地图/记录不变 |

真实主局至少完成三条普通路线：合法说明后和平引息并验还；在可见位置未说明而受警告、主动停手；未采信依据而坚持，发生原驱离并真实退让或击退。另跑不可见时物理使用成功的对照。用原行动与实际需要获得可引息容量，不修改余额造场景。记录日志、正常在途档及画面证据，最终测试数字只写 BASELINE。

双 NPC 实机不应伪称“某时刻自然必然相遇”。可先验证玩家离开后的既有过程连续性，再以原 NPC 自主轨迹得到实际场景；如果普通自然轨迹未出现，纯规则测试可安排合法现有 NPC 的原动作，但需如实区分构造条件与实机自然结果。不得新造一个不吃不睡的敌人来替代验证。

## 11. 实施顺序与本包边界

1. 先修正原交锋自动方与逐参与者提示，覆盖手动/自主/存读；保留普通玩家入口行为，不顺手重写全部战斗。
2. 添加空初始化的看护域/规则与显式新局安排，接原自主选择、查看动作与有限观察边界；先证明原生活和无观察时的自由取用没有退化。
3. 接具名说明、警告、宽限与可信内部开场；一次提交原源中断与警告/交锋因果。补运行入口、本人等候打断和可读结果。
4. 完成严格候选/旧档空迁移、近远与完整停开一致性，再跑主局普通路线和完整回归。只有证据通过后才更新功能状态，保留本规格为实施依据。
