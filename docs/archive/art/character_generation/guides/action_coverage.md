# 站姿、动作参考与完整动画的覆盖范围

> 历史资料：保留原日期与结果，不是现行指令或任务；当前信息查[项目记忆地图](../../../../README.md)。归档于2026-11-11。

这是后置美术方案的动作覆盖参考，不是当前资源制作待办或完整动画已实现的证明；当前素材状态见[提示词索引](../README.md)和[人形技术样本](../../../../../assets/characters/humanoid_sample/README.md)。

这页说明当前外部素材制作包的用途，避免把“有八方向”理解成“已经覆盖全部动作”。实际游戏功能与当前技术样本以[功能清单](../../../../status/features.md)、[构建状态](../../../../status/baseline.md)和[八向方案](../../../../specs/presentation/eight-directions.md)为准。本页不增加战斗、跑步、倒地或施法功能，也不表示对应素材已经生成。

## 1. 当前每张图负责什么

| 当前文件 | 一张图的内容 | 能确认什么 | 尚不能代表什么 |
|---|---|---|---|
| [01 基础衣母版](../01_base_eight.md) | 4列×2行，同一站姿的八方向 | 人物身份、相机、比例、脚点和方向基准 | 八方向动作、呼吸循环、跑步或战斗动画 |
| [14 镜头修正版](../14_base_camera_fix_eight.md) | 沿原人物身份重画俯视与占比的八向站姿 | 修正实际候选的镜头和格内大小；通过后才能成为后续参考 | 第九种方向、全新动作，或最终画风已定 |
| [02–10 衣帽配件](../README.md) | 各一张站姿合成表或独立图层表 | 站姿的换装套合与非对称遮挡 | 在奔跑、挥剑、倒地等姿态中仍能直接使用 |
| [11 行走关键相位](../11_base_walk_keys.md) | 4列×8行，每方向四个行走关键相位 | 步态、左右脚、摆臂与方向的一致性 | 最终完整行走循环、各速度锁脚或转向过渡 |
| [12 呼吸关键相位](../12_base_idle_keys.md) | 4列×8行，每方向四个呼吸关键相位 | 轻微起伏与原站姿是否稳定 | 完整待机循环、所有情绪或持物待机 |
| [13 抬手关键相位](../13_base_gesture_keys.md) | 4列×8行，每方向四个左前臂抬起相位 | 解剖左右与一次简单生活动作 | 通用劳动、挥砍、施法或受击动画 |

**四个关键相位是制作参考，不是完整动画验收。** 模型画出32格，表示八方向各四相位；不能把它写成32个方向，也不能把四帧重复播放直接宣布完整流畅。最终补帧、节奏、首尾衔接、动作中遮挡及实机效果仍须验证。

用户刚回传的旧 JPG 可以保留为身份候选；其镜头与占比未通过时，先使用14修正，不继续据它批量做02–13。修正版通过后，应由开发侧将获选原图和文件映射登记清楚，再作为其余提示词中的“已确认母版”附件；不把旧图仅改名就当作通过，也不要求用户现在重复生成整包。

## 2. 后续按动作逐步建立的矩阵

以下是**待制作/待验证的覆盖计划**，不是当前游戏的已实现动作列表。一个动作先定义实际用途和身体姿势，再制作同相位的八方向与服装响应；帧数按时长、运动幅度和测试决定，不为所有动作预先规定同一个16帧。

| 动作类别 | 必须区分的内容 | 制作/验收重点 |
|---|---|---|
| `idle` 待机 | 普通呼吸、持物待机按需要分别处理 | 身体不漂、脚不挪；与移动和生活动作能接续。12只给当前四关键参考。 |
| `walk` 行走 | 左右支撑/经过等完整周期 | 同一相位、步幅与实际移动相适配，转向不重置脚步。11只给当前四关键参考。 |
| `run` 奔跑 | 跑步的重心、摆臂、腾空/接地节奏 | 独立步态，不能只把行走加快播成跑步；先有实际玩法需求再制作。 |
| `dash` 闪身/突进 | 蓄势、位移段、收势 | 真实位移与视觉姿态分工，站姿偏移不能代替移动；按已有动作规则决定方向与朝向的关系。 |
| `attack` 出招 | 每种实际攻击的前摇、有效段、收招 | 武器握持、轨迹与判定一致，不把抬手姿势当作所有招式。 |
| `hit` 受击 | 打击方向、失衡程度、能否继续活动 | 与主动出招分开；受击姿态不能凭外观重复提交伤害。 |
| `fall` 倒地过程 | 前倒/后倒等实际需要的姿势与落地方向 | 站立到地面连续，不能把站姿旋转90°就当倒地。 |
| `grounded` 地面状态 | 躺卧、伏地、失能等需要时分别定义 | 保持真实接地与层序；不等同死亡，也不自动授予起身能力。 |
| `getup` 起身 | 与原地面姿态相配的支撑/收腿/站稳 | 接续实际倒地状态，不瞬间换回任意站姿。 |
| `cast` 施术 | 起式、引导、释放、结束/中断按实际方法定义 | 手势与能力/器物/媒介相符，不以一张通用发光图代替全部施术。 |
| `work` 生活与劳动 | 搬持、采集、加工、施工、诊疗等实际姿势分别制作 | 每项身体、工具和工作点关系明确，不把13的空手抬臂当通用劳动动画。 |

飞行、游泳、攀爬或非人身体应按该身体家族和实际玩法另建矩阵，不强行套入这套人形站立模板。倒地后的“朝向”也须在制作前明确是人物原朝向、身体长轴还是动作朝向，不能由文件名猜测。

## 3. 衣饰也要覆盖动作

一件外观的制作范围是“身体家族 × 方向 × 动作 × 相位 × 必要姿态变体”。这表示每个组合要有正确表现，不表示每个组合都必须重新生成一整张无关图片。刚性物件可使用验证过的持点、旋转和分片，布料可复用合格姿态或后续骨骼变形；复用后仍须逐方向、逐相位检查。

- 母体、衣袖、帽子、武器和挂件共用动作相位、缩放和身体根，不各播一套会漂移的循环。
- 左手剑始终对应人物的解剖左手，右腰佩玉始终对应解剖右腰；方向变化不能整身镜像换手换腰。
- 远手、剑体、衣摆与挂件可以被合理遮住。层序、前后分片和遮罩随方向/相位变化，不能为看清配件而把它永远盖在身体上面。
- 站姿衣层不能直接硬贴在奔跑、倒地或大幅伸臂的身体上。持物手变体、接触点与衣摆变化要在该动作中核对。
- 动画控制呈现；实际身体位置、衣物穿戴、物件归属与动作结果仍由原模拟系统拥有，不从图片推回业务状态。

## 4. 一次只制作一张，先做可验证样本

1. 先交14修正版，确认相机、比例和原生显示尺度；本轮不要求批量动作。
2. 获选母版固定后，先验少量站姿衣饰，特别是左剑/右玉的遮挡；不等全部衣服齐全才验合成。
3. 下一轮选择一个动作，例如行走。沿11先验关键相位，再决定完整帧与时长，然后给一件衣服和非对称配件补齐相同动作。
4. 后续每份新提示词仍为**一文件、一个可复制文本框、一张输出图片**。每份明确实际上传的母版/动作参考、唯一动作或相位段、方向顺序、画布、脚点和输出名；不让网页模型自动读取目录或一次输出整包。
5. 完整动作较长时，可按明确相位段拆成多个文件，每文件仍只生成一张表；帧序与跨表接续由开发侧登记。不要在一张表里混入无关的跑步、倒地和施法，再猜每格含义。

待机/行走/短动作的当前技术目标与最终内容需求分开维护。现有程序技术样本、外部模型的四关键表、未来正式逐帧动画是不同阶段；只有按[验收流程](acceptance_and_return.md)完成原图、分层、节奏、转向和实际运行核查，才能提升对应阶段的完成状态。
