# 当前版本与历史退役

> 历史记录：版本、测试结果、任务顺序与待办只描述当时，不是当前状态或实施队列。

状态：2026-11-04用户已定工程方向；本页规定后续兼容边界，不表示现有历史分支已经清理。实际受检格式/提交见[BASELINE](../../status/baseline.md)，代码现状见[ARCHITECTURE](../../engineering/architecture.md)。

## 一套当前实现

项目只维护一套当前世界运行模型、领域规则和写档格式，不长期并行维护“旧世界引擎/新世界引擎”、旧UI或每代数据解释器。新局与已有存档是不同世界实例，不是两款游戏；读入支持范围内的旧数据后，都进入当前运行模型。

仍需保留格式、生成器和内容的版本标识，用于校验、迁移和明确拒绝不支持的输入；不能仅修改版本标签便假装转换完成。不同世界的种子、布局、实例状态、已发生历史或合法内容快照可以不同，这种数据差异不等于维护多套旧代码。内容快照本身也须符合当前能解释的格式与规则。

默认只写当前格式。确有保存价值的旧进度，可临时提供范围明确的导入器；每次引入时列出接受的源版本/数据条件、转换结果、测试依据和退役节点。迁移内部可以分步骤，但不要求永久保留从最初版本到现在的完整链，更不为了测试样本不断扩展历史支持。

不支持的旧版、新于当前的格式、未知生成器或缺失必要事实，清楚返回不兼容原因；不静默开新局、不补造库存/经历、不用当前种子生成另一张图冒充原世界。不改变原档文件或活会话。备份及独立候选验证仍是当前版可靠性的要求。

## 按包退役

1. 核查调用者、真实存档、fixture和CI依赖，列出当前实际支持范围与拟删除范围；不要只凭schema数字推断某历史玩法仍可运行。
2. 将有价值的回归场景迁移为当前格式fixture，或按同一语义重新建立当前样本。保留来源/版本/转换方式，并验证关键实物、时间、在途过程和失败隔离；旧文件不原地改写。
3. 需要保留的进度先由经过验证的转换生成新文件。不能可靠转换的版本明确停止支持；不能以默认值抹掉无法证明的历史事实。用户存档不擅自清除。
4. 同包删除已退役的运行分支、旧入口、专用生成器/模板及无效主CI路径，更新支持清单和文档。历史源码与证据可由Git追溯；无需主分支永远承载全部旧资料或让主CI永远执行旧解释器。
5. 验证当前新局、当前存读/完整停开、仍承诺的导入及不支持格式的明确拒绝。退役产生新修改，按范围检查并核对相应SHA结果。

单一当前版本不要求删除Git历史、旧提交或用户工作。原历史证据不追改为“曾通过当前格式”，长期档案可按文档治理归档/精简。保留证据也不等于必须永远保留它依赖的运行代码。

## 固定参考热场导入边界

C1a-2阶段写根48/区域40与热v2；当前C1b-1只写根49/区域41/热v3/器物8。入口接受原有效根47/区域39/器物7/热v1包；现有更早受支持根档先机械达到该边界，再由同一有限导入器验证，不新增直接区域旧版恢复入口。独立村落档没有世界热域，不凭空造天气或来源；联合档不能摘除continuity冒充独立村落，因为它可能保留外域动作和预约。

先验证原digest及绑定的37份内容、独立地图/地表、结构、冻流、来源收据、身体与受体，再在保存时刻把每格转换成当地背景底量加原余热；只转换包内热定义并重算digest，其他定义保持。旧热样本保持原正余热事实，当前之后的样本写完整非负Q（含零格）。不重算过去人体暴露、植物进度或原物成本。完整新候选再次通过后才能替换活世界；输入/原fixture保持只读。

`LegacyHeatV1`是受限的只读验证器，没有推进/注热API，不是保留的第二套运行引擎。下一兼容退役包需先保留有效当前回归，再收缩旧链；本包尚未删除历史fixture或用户存档。真实v1–v31链、v32进行中温石、旧植物档与v42联合/有效独立村落的证据见BASELINE；损坏旧账/内容、混版和未知格式拒绝，不扩展任意旧档支持承诺。

## 固定冷热器物导入边界

根48/区域40/热2/器物7先独立校验原包digest、结构、冻结段及受体，再直接转49/41/3/8并全候选复验。`LegacyHeatV2`只包装当前核校验原形状与冻结锚点，无推进API；不保留第二运行求解器。旧Q、流、样本、来源和外界账不重价，只补明确为空的设备账并推导原冻结终点；只转换包内热定义/重算digest，其余37份中的文档保持，不从当前磁盘补火石/寒石、余额或经历。降标签夹带设备/新余额、旧形状多字段、混版、损坏账均拒绝。原fixture与用户档只读；真实旧代码来源与同未来证据见BASELINE。

## 自然日照内容导入边界

W1a当前只写根50/climate2，区域41/环境状态3/热3/器物8不升版，环境绑定rules_version为2。原49必须严格绑定原climate1、环境rules_version1及原digest，先在独立原候选校所有热账/器物/身体/结构/样本，再复制原气候加入固定北纬30°等太阳默认并重算digest，将环境规则绑定改2；完整当前候选和最终联合运动/旅途校验通过才发布。旧温度曲线/天气/采样、物品、热账、时间与在途过程不改，不补造历史光后果，不从今日磁盘补值。

原47/48热导入固定输出历史49，再进入同一个日照转换；原来的支持范围不扩大。内容包仍为v1的37条路径，新局/普通load只接受climate2，climate1只由显式导入标志绑定到隔离候选。旧根掺solar或新版climate，即使重新计算digest也拒绝；当前根缺solar/降climate或环境rules不匹配也拒绝。此入口是待退役的有限纯转换，不提供第二套日照/世界运行模型；真实49原档保持原字节，后续兼容收缩仍按本页步骤执行。

## 固定热光效果的内容边界

W2b-0没有新增写档格式或历史运行分支。当前热放出器物定义可选声明严格lighting v1；原状态仍为唯一stored_q/enabled/region/container，局部光从当前已接受热流推导。当前包仍是原ContentBundle v1的37份文档，显式新配置计入内容digest；恢复使用档内实际定义，不从安装目录为旧火石补发光能力。旧包没有lighting即没有该效果，原热量、冻流、历史样本和未来温度不重算，真实49活动火石导入后无新增光已定向验证。派生出流索引在独立恢复按原flow重建，不落档、不成为第二余额；坏照明字段或吸热器物声明该效果仍严格拒绝。

## 新局地理编译的内容边界

W1b不改根50、climate2或37文档包格式，不新增历史运行模型。`world_geography.json`只作为创建草稿，编译后的base/seasonal/daily与solar进入完整内容包和digest；恢复从不调用生成器，因此旧50曲线、49正常迁入的原曲线、过去受体样本和热量账均不重算。Main可在入树前选择独立完整内容包或地理草稿，候选失败允许重试、成功后不允许替换；普通开局只接受与原GameClock.start_minutes相同的历法起点，不暗中改共同钟表。已有真实49迁入/保存50和W2b既有原生50完整停开未来均已定向核对，原fixture未改；不是新增任意历史格式支持或永久迁移链。

## 固有发光能力的内容边界

W2b-1保持根50/器物8及37文档包。intrinsic_light是显式新内容能力，单独声明或与weapon/remote_draw组合，严格lighting v1仍只表示相对峰值和半径；与thermal_exchange共用该字段表示两种来源会被拒绝，不隐式重复发光。原对象只保存definition/region/container；派生来源ID索引在接受创建/恢复后重建，不序列化位置或第二储量。旧49/50按档内原定义和原物清单恢复，不从新开局补珠子/薄片，也不把旧火石变成固有光源；真实旧49和W1b既有原生50仍到原完整未来。
