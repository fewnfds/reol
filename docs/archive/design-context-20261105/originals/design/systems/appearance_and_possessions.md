# 衣着、随身物与社会外观：纸娃娃系统设计

成文：2026-11-02；本文为外观与物品目标设计。完整穿搭/真八方向纸娃娃与通用物权尚未完成；实际功能见[FEATURES](../../docs/status/features.md)，证据见[BASELINE](../../docs/status/baseline.md)，当前停点和授权见[HANDOFF](../../docs/status/handoff.md)。

用户方向：装备有换装、生活、审美和社交价值，非人人战士，不能全身堆战斗词条。[世界总纲](self_consistent_world.md)与[众生](beings_and_lifeways.md)优先；六位置、双手、发型与背负只适用于首个人形原型，非人按实际形态/穿法/承载生成入口。未知功能、条件使用、反噬与独立意志见[知物用器](knowledge_artifacts_and_invention.md)。

本文负责衣着/物品与外观观察，具体层位、例物、数量与数值是待验证建议；不建立第二套关系、战斗或存档。世界对象共用接触面、建筑/环境作用见[最新交互原则](world_interaction_principles.md)。


2026-11-03用户明确要求真八方向的全部外观动画，左手持物/右腰挂件保持身体左右，逐朝向与动作遮挡且共享相位。[八方向合同](../../docs/specs/presentation/eight-directions.md)、[来源核查](../research/eight_direction_sources.md)解释目标；当前已有代码生成的八方向待机、行走和有限抬手技术样本，非全动作或正式美术，见[样本证据](../../docs/qa/20261103_eight_direction_sample.md)。

## 1. 要让玩家感到什么

同一人物换一身衣服，可以更适合劳作、远行、赴宴、守夜或出席宗门仪式。衣服帮助别人猜测他的来历与处境，也表达个人偏好。药师、书生、管事、匠人、农户和修士都能有喜欢、需要、爱惜和传承的东西，没必要先成为战士。

一把好剑可以改善握持、刃口、距离与承受真气的能力；它不能使佩剑的账房先生自动掌握剑术。一件礼服可以让懂礼制的人认真接待，也可能在劳作现场显得不合时宜；不能给全世界每个人统一加十点好感。

纸娃娃的主循环是：**看场合与自身需要 → 获得或借用衣物/工具 → 选择穿戴与携带 → 现场使用、被看见 → 清理、修补、转赠或归还**。它连接生产、交易、人情和职位，不以反复刷出一套更高战斗分为唯一目的。

| 内容 | 当前真实情况 | 本文目标 |

## 3. 四种意义分别表达

| 意义 | 例子 | 决定什么 |
|---|---|---|
| 外观与表达 | 款式、颜色、配饰、做旧、修补痕迹 | 人物轮廓、审美、纪念意义与场合选择 |
| 实际用途 | 雨披遮雨、鞋便于行走、药箱保管药品 | 明确情境下的行动条件、成本或便利 |
| 物理性能 | 覆盖范围、材质、重量、破损、刃口 | 实际受击/环境作用和操作约束，不是全身通用战力 |
| 社会线索 | 宗门纹样、制服、佩牌、工匠印、名贵用料 | 观察者有依据的初步推断、核验或礼数反应 |

一件物品可以有其中几种，不必四种齐全。普通布鞋可以只有外观和行走用途；纪念发簪可以只有个人意义和可识别的来历。制作精良不自动等于适合杀人，贵重也不等于防护更强。

物品本体不带“所有人尊敬+5”“掌门信用+10%”等跨情境社交属性。社会反应属于具体观察者在具体场合的判断，正式许可属于机构规则，个人感情仍以交往和记忆为依据。

## 4. 穿戴、携带、运转分别管理

### 4.1 首版穿戴位置

先以少量能产生外观差异的人形位置成立，不做全套人体解剖装备栏；这不是全种族固定装备结构。

| 位置 | 首版表达 | 占用与限制 |
|---|---|---|
| 内层 | 贴身基础衣 | 用作基础轮廓、内衬和遮蔽；公共画面不允许因缺图暴露人体，不强迫玩家管理每件内衣 |
| 常服 | 长袍或上衣/下装组合 | 首版是一套常服外观；以后才拆上/下装，不能让拆分需求阻塞首版 |
| 外层 | 披风、雨披、礼服外罩、轻甲 | 通常一件；体积/穿法冲突按定义，不能把雨披、三件甲和四件袍全套在一起 |
| 头部 | 帽、冠、巾、发饰 | 一项主要可见物；小发饰可以属于同一外观件，不增加一串隐藏加成栏 |
| 足部 | 鞋、靴 | 一双作为一个实例；实用效果按地面/天气，不以品质等级通用增速 |
| 佩饰 | 佩牌、挂坠、纪念物 | 初版一个主要可见位置；徽记能被观察，不自动就是凭证 |

这些是穿法与外观位置，**不等于战斗受击部位**。一件外罩可以覆盖躯干和手臂，覆盖数据由定义表达；不能因位于“外层”就保护全身。一件多部件服饰可以同时占用几个位置，必须明确列出冲突。

主手、副手与背负另作携带位置：

- 双手工具占用两手；一手拿灯，另一手才能做相容动作。收起、放下、换手是有状态的动作，不是白送一只手。
- 护送时手持兵器会改变警戒线索；收鞘仍是同一把剑，保存在身上的携带位置，不重新复制进背包。
- 背篓、药箱、包袱、剑匣是负载或容器，容量与负重独立表达。首版只需一种背负位置，不开启任意容器无限嵌套。
- 物品可在背包内、穿在身上、挂在身上、被握持或放在地面；这些位置互斥。界面可以在“全部随身物”里显示同一物品的引用，不能据此形成第二份货。

发型、体貌与身体基础色通常属于人物外观状态，不作为从背包消耗的装备；理发、装饰等需要改变时是服务或行动。主动招式的准备槽也不属于衣饰位置，换帽不能免费增加可同时准备的技能。

### 4.2 法器不是每个栏位的被动增幅器

佩戴、携带、已经祭炼、正在运转是不同状态。法器有具体作用、使用条件、目标、代价和停止条件，例如提灯照明、护符短时抵挡、飞剑离手操控。人物知道使用方法不等于可同时运转全部法器。

首版推荐一次专注维持一种主要主动法器；特别技艺可改变这个限制，并承担真实取舍。具体心神预算由战斗/修炼设计定参，本文不造第二条战斗资源。

不把“修仙法袍”默认设计成十个随机攻击词条。法袍若确有避尘、耐热或防护功能，应说明作用范围、能量或维护成本、失效状态及能被观察到的现象。普通人可以完全不依赖法器生活。

## 5. 物品定义、实例和位置

### 5.1 堆叠与实例

普通粮食、柴、布料等沿用数量账本。会被穿戴、借用、损坏、题名或作为特定证据的物品采用稳定实例ID。不要给每粒米分配对象，也不要为了省事把两把状态不同的剑合成一条数量。

首版无需让所有衣服生成独立随机属性。定义说明“是什么”；实例只记录这个具体东西真正发生过的变化。

| 数据 | 定义中只读 | 实例/持久关系中保存 |
|---|---|---|
| 基本形态 | 名称、用途、材料、穿戴占用、兼容动作、重量/容量类别 | 定义ID、实例ID |
| 外观 | 基础轮廓、色区、八方向资源、锚点、可见纹样 | 实际染色、修补/污损、后加印记 |
| 状态 | 可磨损/可修补规则、覆盖范围、合法使用动作 | 当前完好状态、剩余消耗、已发生损坏 |
| 位置 | 允许的容器/附件类型 | 唯一实际位置：容器或人物附件；不能两者同时存在 |
| 权利与来历 | 通用转让或借用条件类型 | 所有权依据、保管/借用关系、期限/用途限制、必要历史引用 |

权利记录可由专属关系或账本持有，物品只引用必要ID；不把全部法理、传闻、情感和制造史塞进一个无限增长的Item对象。推导出的重量、防护合计、可见服饰摘要与价格不能另存成第二份权威事实。

### 5.2 所有、保管、使用与借用

宗门公仓的雨披可以借给杂役送药；杂役拿着它，但不能当然出售。朋友送的发簪转让了所有权，纪念意义留在双方记忆里；借来的传家剑则可能只允许随行护卫使用。

- **保管**决定实物在哪，搬运/缴获只改变保管不必然改变合法所有。
- **所有**决定世界内受承认的权利，仍有可能争议、买卖或继承。
- **支取/使用权限**决定当前被允许做什么，制服、钥匙、印信与正式任命可以彼此独立。
- **借用/配发**有可理解的用途、归还条件和失物责任，不预设所有借物都是不计后果的绑定装备。

物理上能穿不代表合法；无权穿用可以发生并被发现。直接拿公仓物资时依据当前保管和阻拦条件处理，不能用一个“禁止”按钮消灭偷拿/争执的世界可能性。首版可以先不开放犯罪交互，但必须保留物权和物理事实的区别。

## 6. 穿脱是一项可中断的行动

换装命令包含人物、实际物品、目标位置和上下文，不由UI直接改图。先核对位置/占用、实际持有、身体能力与已知限制，再安排动作；提交时复核物品仍在、没有被他人取走、位置合法。

普通换帽/换佩饰耗时短，换常服/甲衣需要较长安全窗口。具体秒数留给首版手感测试；不能借此每次交谈前强迫脱穿十次。推荐一次发布整套着装计划，执行器逐项处理，可以中断并保留已完成部分。

- 打开背包、拖拽预览和比较不直接产生变化。正常暂停可排意图，恢复后才花世界时间执行。
- 战斗中不允许瞬时替换整套护具；可快速收放的手持物按动作窗口，解甲等要求安全状态。若受击打断，物品留在上一个已提交合法位置。
- 物品被穿上不会回复生命、体力或真气；卸下也不能制造新的“最大值变化治疗”。
- 修补、换装、丢弃或重新拾取同一法器不重置已有伤势、短时体力、灵力、运转冷却或使用责任；长期精力与战斗体力是两个时间尺度，不在本系统额外收一遍“穿戴能量费”。
- 容器容量不足时提示把旧物放哪，不能删除旧衣或强塞进不存在的背包。
- 换装时的隐私是可设置的场所偏好：优先住所/屏风/更衣处，急需时可用简化过渡表现。它不形成按性别固定惩罚或强制羞辱机制。
- 重伤、被束缚或行动障碍限制实际穿脱能力，可以请求照料者协助；协助需接触/许可或明确强制行为，不能远程拖拽他人衣服。

远区采用同一动作和耗时结果，只省略逐帧表演。切入近景时显示已经穿好的真实衣物和当前阶段，不为玩家到场重新换一次。

## 7. 社交意义来自观察者，不来自全局衣服分

### 7.1 看得见什么，才有依据猜什么

观察链为：**实际可见外观 → 观察条件 → 观察者已有知识 → 当前场合与需要 → 暂时判断 → 对待方式/进一步核验**。

可见线索包括剪影、衣色、公开徽记、显著污损/破口、外露兵器和运转法器现象；包内贵重物、被外袍遮住的护符和物品真实所有权不会凭绘制数据自动公开。

粗远景只允许辨识大类；近处、光线合适、愿意注意时才认出细纹或佩牌。已经熟识玩家的人主要依靠脸、声音、经历与上下文，不因换衣就清空关系。戴帽或换色不等于任何人都会认错人。

| 情境 | 可能的判断和反应 | 不能发生的捷径 |
|---|---|---|
| 访客穿整洁素袍参加礼会 | 懂礼数者认为重视场合，愿意按礼接待 | 自动获赠秘本、提升全宗好感 |
| 穿医者外罩，携药箱到伤者旁 | 可能被询问是否能救治，或被请求帮忙 | 没学医也自动能治病，所有人都相信其资质 |
| 穿宗门服饰进入陌生据点 | 守卫暂按某门派来客处理，必要时查牌或问讯 | 外观即发放仓库/禁地权限 |
| 衣上有血迹、兵器未收 | 警戒、询问或回避，取决于刚发生的情况与认识 | 所有人直接确知是谁杀了谁 |
| 穿工作服接近田地 | 被认为适于劳作，熟人可能招呼帮忙 | 不经过请求就强制认领农活 |
| 名贵服饰进入贫困地区 | 有人赏识、有人防备、有人不关心 | 穷人统一仇富、富人统一崇拜 |

文化、组织、场合和个人偏好只在有意义处出现，默认采用宽松礼节，避免把系统变成到处换制服过门槛的游戏。对当地习俗缺乏知识时可以询问，界面提供有限线索和替代办法。

### 7.2 假扮、核验和识破

穿某宗服饰可形成身份主张，但不改变真实任职和个人知识。守卫可以先按表面放宽态度，也可因禁地、紧张局势、印记异常或熟识名单核验。核验用其实际能取得的证据：认脸、查公开名册、问暗号、查有效凭据或请知情者确认。

不公开的账本不会自动联网核验，伪装也不靠每帧重新骰判决定是否穿帮。同一观察情境和证据实例复用判断，距离、行为、消息或证据有实质变化才重评。识破可能得到盘问、拒绝、通报或指控，其后果取决于具体行为、当地规则与证据，不能一律变成全世界通缉。

授权岗位可以要求正式凭据；就算守卫相信外观，账房执行支取时仍复核权限。系统需允许“门口放行但账房拒绝”成立。佩戴真实腰牌、持有他人腰牌、有权使用腰牌是不同事实。

### 7.3 知道与传播有成本

某人看见新衣或认出一把旧剑，只更新这个人的观察；只有交谈、报告或明确渠道传播后别人获知。出售失窃物可以留下来历线索，不能让每个商人瞬间知道世界上所有赃物。

玩家能查自己的物品与已知来历；检查他人显示当前可见/已知部分。UI可写“像是青岚门服”“他认出了这枚佩牌”“衣袖下似有护甲”，不免费列出他全部背包、真实派系和隐藏法器。

## 8. NPC也有自己的着装理由

NPC根据已知场合、职责、天气、经济能力、习惯与现有衣物安排穿戴。农户先考虑能干活和遮雨，执事可能重视仪式和辨识，隐居修士可以穿旧衣，商人可能整理门面；这些是候选倾向，不是职业必穿的死规则。

默认日程只在换班、出行、仪式、天气变化、明显污损或准备战斗等边界评估，不每tick换衣。已有合适衣服就继续穿；没钱的人可修补、借用或选择宽松场合，不每天因为“体面不足”陷入负反馈。

玩家对普通熟人只能建议、赠送或请求。雇主能规定合同范围内的工作防护与徽记，管事能配发制服，但不直接支配下属私人衣柜。明显危险、不合身、侮辱性或越权要求可以被拒绝，理由来自具体处境。

NPC对衣物可以有少量偏好/纪念关系；不为每件袜子创建长篇情绪日志。传承物、制服、赠礼、贵重器物保留必要来源；日常反复穿脱只保留当前状态或期间摘要。

## 9. 维护、价格与资源循环

首版显示“完好/磨损/破损/不可用”等少量状态。内部可按实际需要使用数值，玩家不必盯每件衣物的耐久百分比。穿在身上不因每过一分钟固定扣一点；损耗来自明确事件或长期使用区间。

整洁度先用干净、沾尘、明显污损等外观状态，只在劳作、涉水、受伤等边界变化。休息时可把清洗修补列为低优先日常任务，消耗合理的水、耗材和时间。不开“每天全套衣物清洁小游戏”。

破损的影响与功能对应：雨披破口影响遮雨，靴底坏影响长途舒适，护具破损降低实际覆盖/防护，礼服旧但干净仍可体面。修补痕迹既可表示困窘，也可表示爱惜或资历；具体人有不同解释。

价格来自材料、工时、实际用途、做工、稀缺、来源、当地需求和双方所知；不从颜色品质表直接决定战斗等级。纪念品可以对本人非常重要、市场无人愿买；精致礼服可以比普通护具贵，但不能因此挡刀更强。

修补、染色、定制服装、洗护、借物和押金都可成为匠人/服务者的生计。先做有实际需求的少量服务，不能把NPC衣物损耗当印钞任务无限发钱。

## 10. 纸娃娃表现契约

本节是资源和表现约定，不指定尚未查证的Godot API。可以先用现有几何绘制扩展，再由正式资源替换。

### 10.1 逻辑占用不等于绘制顺序

模拟只保存穿戴实例、动作状态、朝向和实际位置。表现层读取它们组合，不持有一套“画面穿着”和另一套“实际装备”。换一个贴图、改变绘制偏移或降低细节不能改变负重、防护、权限和身份。

正式角色呈现统一支持真八方向（含四个斜向），动作瞄准仍可采用连续方向；朝向贴图不得限制实际判定。人物解剖左右不随转身互换，左手武器、右腰玉佩及不对称纹样不能无条件镜像；逐朝向/动作选择遮挡层序。已有代码生成的八方向有限动作占位，不能当作全体型、全动作或正式资源已完成；也不要求一次制作完全部体型与动作。

### 10.2 小型骨架与资源约定

每种动作只约定少量锚点：脚底/地影、躯干、头、主手、副手、背负、腰佩。衣物资源说明方向、动作族、帧/姿态、原点、遮挡掩码、色区和缺图回退。图块显示尺寸与世界逻辑格分开，人物不必填满64×64地面格。

| 状态 | 主手/背负的大致排序 | 验证重点 |
|---|---|---|
| 朝南 | 背负在身体后，前手/手持物可在身体前 | 外袍不盖掉举起的药箱或武器预警 |
| 朝北 | 前胸细节减少，背负在可见背部；手持物依实际姿态在身侧/前方 | 佩牌若在胸前，不能背面仍完整显示给观察者 |
| 朝东/西 | 远手/远袖先画，身体居中，近手与手持物后画 | 左右翻转不得把不可镜像文字/宗纹反写，需单独变体或中性图案 |
| 挥动/施法/搬运 | 锚点与前后层可随动作阶段变化 | 几何命中范围由战斗规则决定，不能用贴图大小当伤害框 |

基础绘制顺序为：地影 → 后披/远手/背后物 → 身体/内层 → 常服 → 外层/近袖 → 头发/头饰 → 可见手持/佩物 → 选中与动作提示。每向可以局部覆写排序，不能只用一条全角色通用z值解决所有遮挡。

静止、走、工作、持物、攻击/施法、受伤/倒地先用少量姿态成立。所有服饰遵守同一锚点/比例；缺动作变体时用明确的基础姿态和颜色回退，不显示空身或自动卸装。衣物外观的臂部可用遮罩/分片，首版避免每件衣物都复制完整身体。

远景可合并成缓存轮廓或简化颜色；缓存键只含可见穿戴、色区、方向与姿态。换衣/破损/显示状态变化使缓存失效，不每帧创建完整纸娃娃对象。大规模具体缓存形式必须测量后再选。

### 10.3 可读性优先于无限幻化

首版使用实际物品染色、裁改和穿搭，不开放独立于实际物品的全覆盖幻化层。护具、长柄武器、运转中的法器应保留足够轮廓和反馈，不能外观完全是徒手布衣却无条件享受重甲和巨兵器能力。

这不要求战斗高亮自动揭露衣服下面的一切。自己查看纸娃娃可以知道内藏护具；其他角色只从其实际看见的轮廓、交手现象或检验得到知识。战斗命中仍按真实身体与装备条件，秘密效果可以存在，但须有合法定义、代价和可察觉后果，不能靠美术开关改变碰撞。

内藏护具或伪装法术若以后成为玩法，必须有真实遮蔽、代价、露馅条件和观察手段；这是世界中的行动，不是玩家免费关闭他人识别能力。个人角色窗可完整展示自己的衣层，现场观察仍受遮挡影响。

## 11. 首版物品样本

以下13件只是验证不同用途的最小样本，不是已生成素材，不按稀有颜色排序。实例数量服从真实生产/购买/配发来源。

| 样本 | 位置/用途 | 产生的选择 |
|---|---|---|
| 粗布短衣 | 常服，便宜耐劳 | 日常能用，修补容易；不带攻击词条 |
| 素色长袍 | 常服，普通会客/出行 | 风格与场合选择，不自动给声望 |
| 青岚门服 | 常服，公开组织纹样 | 提供归属线索；配发/归还与穿用授权分别记录 |
| 仪礼外罩 | 外层，宗门仪式 | 适于礼会，不适于搬运；不会提高施法威力 |
| 蓑衣 | 外层，遮雨 | 雨天实用，与厚重外层可能冲突 |
| 斗笠 | 头部，遮日雨/部分遮脸 | 改变可见线索；熟人仍可能认出声音/举止 |
| 布鞋 | 足部，普通行走 | 廉价、轻便，破损可修；不是稀有度增速 |
| 护卫轻甲 | 外层，有限覆盖的物理防护 | 负担和防护取舍；礼会或隐蔽行动未必适用 |
| 执事佩牌 | 佩饰，公开标识/可核凭据载体 | 有效签发与持有人资格决定权利，偷来并不合法任职 |
| 纪念发簪 | 头饰，赠礼/纪念 | 个人价值、辨认线索、交换或归还的故事 |
| 背篓 | 背负容器，搬运/采集 | 增加可携体积而非消除重量；放下才能减少负担 |
| 药箱 | 携带容器，药品组织/保管 | 便于救治工作，拥有药箱不等于会医术 |
| 制式长剑 | 单手持用/收鞘，练习与护卫 | 操作需要训练，刃口/材质有实际用途，无全套装备战力分 |

首个法器例子另在战斗/修炼原型中用一种主动器物验证，不为凑全套同时加入飞剑、护盾、法袍和首饰随机词条。衣物可增加纯审美色款，但不以颜色变体冒称新的机制深度。

## 12. 玩家界面

角色窗以纸娃娃预览和实际随身物为中心：穿搭、持物/背负、包内物品、物品来历/权利说明。物品页优先显示外观、用途、重量/容量、状态、穿法冲突、所有/借用；战斗相关条目只在物品确有此用途时出现，不对礼服显示一排零攻击/零暴击。

可保存“干活”“出行”“礼会”等着装计划，名称由玩家自定。计划只保存偏好/物品引用，不复制装备；缺物时解释并给替代，执行仍需取物和穿脱。NPC计划由自身习惯、职责和场合驱动。

界面分别提供“试穿预览”和“实际更换”，清楚说明需要取物、耗时、是否会中断工作、旧物放哪及公物责任。无钱时可以看到借用/修补等成立选项，不能靠试穿把商店物品穿走。

观察他人时显示有限外观描述，不直接开放完整纸娃娃和背包。请求查看佩牌、询问衣物来历、赞赏/赠送可复用交涉入口；收到的信息有来源，恭维不固定兑换关系收益。

## 13. 实施顺序与状态归属

本文只列领域依赖，实际启动顺序及授权以[世界引擎执行计划](../../docs/archive/specifications/world_engine_execution.md)和[HANDOFF](../../docs/status/handoff.md)为准：

1. **实例与位置**：在数量库存旁引入必要实例，唯一位置/穿戴占用、保存/候选验证先成立。
2. **实际换装与纸娃娃**：少量常服/帽/鞋/手持物，八方向/动作锚点和穿脱流程；现阶段几何占位可用。
3. **用途与代价**：工具、容器、覆盖/损耗、清理；与劳动/战斗动作复用真实条件。
4. **社会观察**：可见特征、单人知识、制服核验与来历，先验证两个观察者有不同反应。
5. **NPC着装与服务**：按场合自主换装、借用/配发、修补/染色生计；不创建第二套日程器。
6. **正式资源族**：玩法和锚点稳定后替换模块图，核对资源许可、八方向/动作缺图与导出。

实例/穿戴由持久模拟模块拥有；现有库存负责数量与预约合作，物权和借用归关系/机构领域；个人知识仍由社会记忆负责。runtime只做意图/可达取物/场景表现，纸娃娃只读可见外观。新模块名和文件在实施包中按真实职责决定，不预建空autoload或通用物品引擎。

## 14. 可判定的验收场景

下列均为未来标准，未在本轮运行：

| 场景 | 必须得到的结果 |
|---|---|
| 同一把剑先握持再出售 | 必须实际卸下/交付，不能身上和买家各一把；读档也不复制 |
| 物品被预约换装后遭他人取走 | 提交失败或计划改选，保留合法旧装，不产生幽灵装备 |
| 普通人穿最贵礼服战斗 | 没学会的剑招仍不可用；贵价不自动减伤或提高攻击 |
| 布衣与轻甲面对同类攻击 | 差异来自实际材质/覆盖/负担，未覆盖部位不凭空受保护 |
| 换外袍遮住佩牌后从背面接近 | 观察者不能读取被遮线索；熟人仍可据其实际知识认人 |
| 两名守卫对同一门服反应 | 知道纹样者可作相关推断，不知道者不凭空知道宗派；均不新增正式权限 |
| 玩家穿借来的执事衣装 | 可以被误当差役或遭核验，账房按真实凭据/任职处理；换衣不改机构账本 |
| 偷来真佩牌并反复接近 | 不每帧重掷穿帮；核验依据、观察与后续消息有明确来源 |
| NPC衣物破损且没钱 | 可以继续、修补或借衣，按能力/场合选择；不能固定羞辱/永久不能谋生 |
| 打开背包换装计划时暂停 | 只排意图，世界恢复后花时间；受击中断保留单一合法位置 |
| 两手工具加提灯 | 冲突明确，必须收放/放置，不免费获得第三只手 |
| 待归还公物的持有人死亡 | 身体/遗物容器保留实物与所有权依据，借用责任有明确处置，不随节点删物 |
| 換装半途保存、切区再载入 | 已提交衣物、剩余动作、旧物位置和预约正确恢复；远区执行不重新开始 |
| 远景简化与八方向转身 | 只改变绘制精度，物理覆盖/容量/社会知识不随LOD变化；不对称佩物及纹样遮挡符合实际朝向 |
| 正式贴图替换代码占位 | 位置、ID、穿戴/命中/权限不变；缺图有回退且不露空身 |
| 玩家要求同伴交出私人衣物 | 对方按实际关系和条件回应；只有合法授权/自愿/明确强制才改变物品关系 |

设计是否成立要看：不参与战斗的人是否仍有值得选择和拥有的物品；一件东西的外观、用途、来历和归属是否能生成行动；玩家是否能理解衣着为何在某个场合影响了待遇。物品数量、装备栏数量与稀有颜色数量都不能代替这些结果。
