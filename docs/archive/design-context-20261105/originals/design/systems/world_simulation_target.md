# 大世界持续模拟：目标架构与行为契约

> 2026-11-02最新方向见[世界总纲](self_consistent_world.md)与[众生](beings_and_lifeways.md)：人形Demo中的身体/背包一对一不再作为宇宙不变量，远区也须尊重不同身体、载体、感知和知识边界。新机制仍是目标，不表示当前区域模拟已经支持。

日期：2026-11-02。状态：**长期目标设计，待分工作包实现与验证**。本文不表示市场、战争、人口世代或完整大世界已完成，不替代[当前构建状态](../../docs/status/baseline.md)。

本文细化[总体框架](living_world_framework.md)和[世界连续性契约](world_continuity.md)，说明如何让不同身份生活在同一个持续运转的世界。实际执行顺序见[世界引擎计划](../../docs/archive/specifications/world_engine_execution.md)，当前授权见[HANDOFF](../../docs/status/handoff.md)，现行代码边界见[ARCHITECTURE](../../docs/engineering/architecture.md)。参考游戏能力与证据边界见[既有研究](../research/social_interaction_game_references.md)；下述算法均为 Reol 设计，不声称是参考游戏内部实现。

## 1. 需要产生的体验

一个农庄先种粮、留种、吃饭，再决定卖多少；一个宗门有灵田、传承、护山能力及对外依赖；一个散修根据消息、盘缠、伤势和人情决定下一站。玩家可以加入其中，也可以改变他们赖以为生的条件。

世界不保证每次返回都有戏剧性大事，但已经发生的事要有结果：粮运到过、有人受伤、旧任退位、道路封锁、账页换了保管者。人物不能因为玩家接近才出生、开始工作或决定结怨。玩家的参与改变过程，玩家的缺席也有成立的过程。

“大世界”首先由距离、依赖、人口与权力网络产生，不用地图平方公里替代玩法密度。先让少数地区形成食物、药材、矿产、功法、护送与政治互赖，再扩展数量。纯空地面积无需逐格模拟。

## 2. 现有基座和必须补齐的边界

下表是成文时的代码调查与当时预计的缺口；后续有更多有限样本，不能把表中“尚需增加”当作当前未实现清单。最新事实见[FEATURES](../../docs/status/features.md)和[ARCHITECTURE](../../docs/engineering/architecture.md)，仍不能将局部机制外推成完整系统。

| 现有模块 | 可以承接什么 | 尚需增加什么 |
|---|---|---|
| `VillageSimulation` / `SimActionExecutor` | 个人状态、有限日常、动作阶段、耗时、取消和结果 | 更通用的目标选择、采集/种植/建造/交易/战斗动作，死亡和迁居清理 |
| `SimInventory` | 容器、预约、实际转移、消费、操作幂等 | 合法所有人与实际保管人分别表达，产出/损耗审计、装备和遗留物 |
| `SimSocialMemory` / `SimInstitutionBook` | 有来源知识、有向关系、请求、职位与记账 | 稀疏长期摘要、多人制度流程、记录传承、争议与继任，不沿用旧原型当通用政治 |
| `RegionalSimulation` | 共同时间、稳定区间、边界失效、在途粮食和延迟消息 | 多路线人员行旅、市场、组织计划、远区冲突、人口、季节与历史压缩 |
| `SettlementServices` | 分步交付、凭据、登记、兑换、许可、托管支付 | 可复用的交易/委托实例；不能把现有固定服务假称完整市场 |
| `WorldSessionSnapshot` / `SimSaveStore` | 一致快照、独立候选验证、文件替换 | 地形差量、建筑、探索、装备、伤势、计划、人口、历史及版本迁移的完整覆盖 |

当前开局以有限初始库存和固定供给职责演示生活，不是可以运行多年的生产经济；河湾运粮人也不是完整的普通人员迁居模型。扩展前先承认这些边界。

## 3. 一个世界，多个状态负责人

### 3.1 事实、记录与判断

| 内容 | 由谁持有或保证 | 如何影响行动 |
|---|---|---|
| 身体、位置、伤势、消耗、实物数量 | 对应人物/容器/地形的模拟状态 | 决定行动实际上能否发生 |
| 私人物品的所有权、机构资产归属 | 明确的权利关系与当地认可程序 | 决定拿走是否被认为合法；不等于物理上拿不走 |
| 公账、任职、通行、契约和判决 | 具体机构、职位、账页或法器 | 提供可核验的依据；须由有能力和权限的人执行 |
| 个人所知与预期 | 该人物的知识和记忆 | 决定其认为有什么选项及如何评价风险 |
| 玩家笔记和猜测 | 玩家观察视图 | 帮助玩家推理，不自动创造官方承认 |
| 已提交的结果与未结责任 | 各领域状态，附有限重要事实 | 防重复结算、恢复事务、追踪后果 |

存储可以集中在内存或一个存档里，语义上仍要知道“谁保管、谁能查、谁有权改”。不用为每个长老创建独立数据库。

特别区分实物的**保管、所有权和支取权**。盗贼可以实际持有不属于自己的灵石；库管可以保管宗门物资而无权私卖；长老可以批准支取而手上没有实物。首版交易先覆盖正常转让，犯罪和赃物后续复用此区别。

### 3.2 固定的不变量

- 持久主体的连续性唯一，身体/载体、控制关系与被识别身份分开；现有人形原型仍是一主体一身体。分身/换载体须显式规则与独立状态，不能复制主体、物资或免费执行责任。
- 同一载体/物品的实际位置或在途状态唯一；一个主体可有多个容器，容器与显示列表不产生额外实物。持有载体不自动拥有其中主体的意志或知识。
- 一个行动实例只有一个负责结算的执行器；一个物品实例或可堆叠份额只有一个实际容器。
- 开始时的判断与提交时的实情分开：NPC 可以错误地以为有货，执行时不得凭空变出货。
- 同一笔交付、工资、战利品、建设和付款使用稳定操作标识，重试及读档不能重复生效。
- 消息到达前不改变接收者的知识；世界调度器知道真实路况，不等于商人已经知道。
- 已发生的事实不因入场或重抽骰子被改写；尚未发生的预测可被新行动打断。
- 模拟预算不足时保留未处理时间，降低推进速度或分帧处理；不丢失世界时间或跳过冲突。

## 4. 模拟精度与时间

### 4.1 精度根据互动需要分配

| 层次 | 保存与计算 | 省略什么 |
|---|---|---|
| 玩家附近的现场 | 逐步移动、碰撞、射程、局部地形、可见行动和战斗 | 不省略正在被玩家干预的关键步骤 |
| 远处的持久人物与事务 | 路线/计划、耗时、资源、需求边界、消息、交付、伤势、责任 | 动画、逐格碰撞、每帧寻路与重复评估 |
| 稳定聚落过程 | 明确劳力和设施支撑的生产批次、消耗、库存边界、公共工程 | 状态未变期间的重复工作选择 |
| 尚未细化的背景人口 | 职业/家庭群体、人数、资源负担、死亡/迁入迁出份额 | 无关联背景人物的逐条日程 |
| 地域和跨域网络 | 通道、生态资源、气候、运输、外交、军队与消息 | 未访问空地的场景节点 |

不是“近区真实规则、远区自由编故事”。距离只改变执行细节与允许的误差，不取消成本、人物差异或社会责任。具名、已交往、承担职位、债务、承诺、战斗或家族联系的人物保持个体；不因远离玩家被聚合掉。背景人物第一次细化后获得持久 ID，原群体同步扣减人口与资产，不额外复制一个人。

### 4.2 按最早必要变化推进

沿用现有关键边界算法，逐领域补齐边界类型：

```text
选全局最早必要边界
→ 把有关区域推进到该时刻
→ 原子提交到达、耗尽、完工、伤害、期限或消息
→ 使相关预测失效
→ 各人物按自己所知重新选择
→ 排定下一边界
```

稳定区间截止于最早约束：材料耗尽、作物成熟、员工到休息阈值、目标移动、敌军接近到可察觉范围、道路被毁、天气变更、借期届满或消息抵达。不能先算出月底盈余，再补上月中缺粮。

同刻顺序要在领域规范中固定，例如先确认已经到达的实物，再开放后续交易；互相冲突的预约用持久的公平顺序或轮转序列，不让字典顺序决定永远占便宜的人。同刻顺序本身要保存并可测试。跨区影响先同步被写地区，不能让两个区域各自跑到未来再合并相互矛盾的结果。

### 4.3 生活、战斗和闭关共享时间

当前已有共同整数毫秒、生活/路线和有限对练，分钟保留为投影/通知；实际语义见[ARCHITECTURE](../../docs/engineering/architecture.md)。未来战斗、持续作用与长时修行继续共用该时间，**不建立会独自流逝的第二个战斗时钟**。新领域须声明期限/相位/打断、粗细推进与迁移策略，不能因旧设计提到分钟便重做已接时基。

暂停停止整个世界的有效行动；1×/2×/4×同样影响移动、生产、需求、战斗和消息。画面插值与按钮响应不承担模拟时间。局部慢放如后期加入，是明确的个体能力规则，不是全世界时间失配。

休息、长途旅行和闭关可推进到下一个与玩家有关的打断点：遇袭、重伤、供应中断、到达、紧急来信、已知期限。玩家可以配置提醒，但不能用“自动休息一百年”跳过身体死亡或实物耗尽。宏观跳时处理周期和重要期限，不逐分钟重放，也不一键随机改全世界关系。

### 4.4 精度切换事务

1. 在共同提交点同步涉及的状态，冻结旧执行责任。
2. 携带当前位置/路线进度、行动阶段、参与者、实物、预约、伤势、随机状态和未结结果。
3. 验证后移交唯一执行责任，再生成或隐藏视图。
4. 保留迟滞范围，避免边界来回走反复重建。

一个没有合格粗算器的战斗可以暂时继续原执行器或限制当前规模，不能卸载时直接判结束。入场可把路线进度映射到合法地点，但不能把原本被围的人放到安全出口。不可达映射须保留阻塞状态并记录诊断，不能偷偷传送解围。

## 5. NPC 与组织如何自己生活

### 5.1 少量需求、目标和有限计划

人物选择由以下信息组成：生存压力与身体、当前职责、未结承诺、偏好与个性、已知机会、风险、资源与关系。先以当事人所知检查选项，再比较少量候选行动；结构合法性和已确知的硬条件可提前过滤，未知真相不得通过候选筛选泄露，实际执行再复核真值。采用短期计划和事件触发重评，不为每人求解无限未来。

目标可以是“今晚吃上饭”“筹齐丹药材料”“完成巡山”“还债”“保持职位”“报复某人”，但只有当前有线索和路径的目标进入候选。连续执行给予适当稳定性，避免每个 tick 换心思；新伤势、危险、期限和被证实的信息能打断。行事失败产生等待、替代、求助、放弃或改变目标，不能永久卡在原任务上。

人格影响倾向，不直接改写事实。多疑者可能要求担保；善意者可能免费帮助；贪利者也会拒绝显然致命的买卖。骰判只用于条件允许后的不确定选择，绑定互动实例和重要条件版本；同样的话重复点十遍不重新抽十次。

### 5.2 组织必须有立足之本

一个组织至少具备成员与招纳方式、职位及办事权限、资产与收入来源、维持成本、内部规则、对外依赖、当前问题和决策者。青岚宗可以靠药圃和护送立足，河湾靠田地和粮食；失去核心来源会造成减薪、缩编、借债、谈判、迁居或争夺，而不是仍按固定面板收入无条件运行。

掌门或会议只能根据收到的信息制定有限计划，再由执事派单、具体人物执行。成员可以因疲惫、私人承诺、派系、贪腐或不信任而改变执行；是否违规、是否被发现、谁来追责分别结算。组织评价、成员私人态度和阵营立场不合成一条全局声望。

宗门关系与国家/阵营关系也分开。两个宗门可以停战却争资源；同一阵营的商人仍可能拒绝亏本交易；敌对组织中的旧友仍可偷偷帮忙。初期只维护发生实际往来的稀疏关系，不做全世界人物两两关系矩阵。

## 6. 物质与经济循环

### 6.1 生产、消费与运输形成约束

每个商品定义基本用途、来源、投入、劳力/设施/土地要求、产出时间、保存或损耗方式。第一批只需粮、饭、水、柴、药、矿材、灵石与少量装备；物品多少服从玩家选择需要。

粮食需要生长时间和耕作，水井与采矿有来源容量或补给规则，烹饪消耗投入，建造把材料转为建筑，生活消耗与腐坏形成去向。劳力被征兵或受伤后，生产计划实际减少。修炼可以降低部分生存需求，但必须有明示境界或功法依据，不能所有远区修士自动免消耗。

运输不是库存间无条件相减相加：货物先进入某人或商队的容器，承受路程、负重、补给、风险与费用。可预约未来货量，但预约不等于已经持有。跨区交易必须同时考虑出价、支付能力、运输能力、现货或约定交期。

### 6.2 钱、贡献和人情承担不同功能

- 货币是有发行/矿产/初始来源的可转移资产；工资、税、押金与交易只是转移，不凭空扩大总量。
- 灵石若兼作货币和修炼材料，修炼消耗是实际货币源汇问题；需要开采、外贸或替代结算方式，不把灵石永久当不可耗的万能钱。
- 宗门贡献是机构发行的受限兑付记录，新增贡献意味着新增负担。机构可以设置适用范围、承兑规则与发行预算，但不能把个人刷任务变成无限免费实物。
- 人情、友情、忠诚和信任通常不能自由转让。它们影响具体人愿意承担什么，不统一折算成市场价。

价格先用少量有界规则：卖方库存覆盖、生产/补货成本、买方紧迫程度、已知近期成交价、风险和地方税费。商人只根据自己的库存及获知信息报价，不实时读取全世界供需。初期不用复杂连续竞价，也不靠全局“经济指数”直接增减每个人的钱。

### 6.3 世界边界不是隐藏作弊口

有限世界可以有外域来商、迁入人口、灾害和野生资源再生，但必须是显式来源：从哪个边界或资源池进入、携带什么、何时到达、有何上限。来自外域的粮食/货币计入输入，腐坏/修炼/销毁计入输出。

每类基础实物可检查：

```text
期末在库 + 在途 + 背包 + 已投入可追踪资产
  = 期初总量 + 采集/生产/外域输入 - 消费/毁损/外域输出
```

不同物品的配方转换分别记投入和产出，不把“做饭”视为粮和饭数量相等。无需从创世保留每次一根柴的流水，但测试和开发诊断应能按期间汇总来源、转移和去向。

### 6.4 可失稳，但要能理解和行动

短缺、通胀、饥荒或破产可以发生；稳定性不是保证世界永远富裕。正常种子须有可维持的基本供给，异常种子或战争冲击须产生自救行动：提高报价、求援、换作物、裁减开支、迁居、占路、投降。

不允许用暗中补库存掩盖死循环；如果作为难度辅助提供赈济，必须以有来源的事件进入，且可在设置中辨认。也不强迫世界定期崩溃来制造内容，长期和平与复苏同样成立。

## 7. 城镇、环境和世界生成

城镇由真实设施、土地、道路、人口、工作能力和治理关系组成。建筑蓝图占位不等于建成；需要合法或事实控制的地点、材料、施工、通行和人员。建成后改变实际生产容量、储物、休息或防御，而非只增加“繁荣值”。

首轮房间判定只服务具体需要，如封闭住所、灶房、仓储或修炼室；复杂风水、温度流体、逐块结构承重另行验证是否有决策价值。道路、桥和关口改变行旅图和局部通行，影响补给与经济，破坏后须使旧路线预测失效。

生成顺序采用约束优先：地形与水源 → 可耕作/矿脉/灵脉等资源 → 可达通道 → 可维持人口的聚落 → 组织与依赖 → 人物与未结事务 → 少量初始历史。保证至少一种基本生计及逃离路径；不把“随机”理解为可以生成无粮无路却全员按普通生活开局。

世界地理用有限区域图连接地形坐标，不要求预先实例化每块地面。当前 512×512 首区和 64×64 渲染块继续保留；增加模拟区域不等于每次都新增一张同样大的场景。局部详细地形按种子与持久差量恢复，地理节点与实际出口一致，跨边不能绕过本应存在的关隘。

## 8. 冲突、战争与修仙强者

### 8.1 战争从目标和动员开始

战争目标可以是夺药田、收贡、报复、救人、解除封锁或占领据点。组织评估可用兵力、指挥者、补给、已知敌情、内部反对和退路，才组成部队；不是固定间隔在玩家视野外刷一波无来源袭击者。

部队由实际人员、装备与容器构成；动员后原岗位缺人。粮药、伤员、道路、士气与回撤影响能打多久。占领需要实际控制关键地点并维持执行者；撤离后可能失去控制。投降、赎人、赔偿、割地和停战可以比全灭更合理，败者可留下伤势、俘虏、逃散、债务与仇怨。

### 8.2 现场与远区共用战斗语义

共享参战者、身体/装备、伤害和防护类型、行动成本、地形标签、侦察、撤退与俘虏规则。现场以移动、射程和技能逐步执行；远区按有界交战阶段和风险模型结算，保留阶段耗时、伤亡与资源变化。

两种精度不承诺逐招相同。验收目标是：实力差距、伏击、补给、地形与撤退条件的方向一致，资源和参战身份守恒，已发生伤势不能进场洗掉。用多种种子比较伤亡与持续时间的合理区间，不能只看某一例结果相同。

预测战果只是估计；一旦阶段实际提交则保存结果与随机状态。玩家进场可以影响后续，不能重抽已提交阶段。离场也不能立刻转成有利速决。大型军团可以按小队与后勤群体聚合，但已持久化的主将、旧友、俘虏和重要修士保留个体，展开时总人数、装备和补给不增加。

### 8.3 修仙能力改变世界的代价

强者能飞行、护送、开矿、治伤、威慑或摧毁防御，这些能力要进入共用动作和成本模型。境界压制可以明显，但应有能量、伤势、时间、阵地、责任或政治后果；具体强度由修炼与战斗工作包定参。

飞行不能默认连背包货物和整支商队一起免运费；法器载重、持续消耗与可带人数单独定义。顶级修士不自动巡遍全世界，也不因系统“坏人数量不足”被凭空生成。高阶毁灭技能对建筑和地形的影响，必须先有可保存、可粗算的规则，才开放给 NPC 使用。

## 9. 事件、任务与信息

事件来自几类明确输入：人物行动结果、持续局势、组织计划、自然过程、有限外域变化和编写的场景条件。少量模板把缺粮、失踪、争地、债务、继位等条件组织为机会，不替玩家预定唯一解。

局势维护关联人物/资产、已知解释、时限、升级条件和结束条件。缺粮可以靠贸易、种植、救济、劫掠或减员改变；不要求玩家接了任务才允许 NPC 运粮。局势完成后释放预约、终止过时招募、处理已付押金、通知有关人，不能只从 UI 删除一行字。

任务是玩家已知的承诺、委托或目标视图。发任务者须有提出需求和兑现报酬的依据；委托被他人先完成、雇主死亡或库房被劫后会产生实际变更。UI 说明玩家知道的主要原因，隐藏内部效用和未知秘密。

消息有发生时间、发送时间、到达时间、来源、渠道、接收者与可信程度。口头转述可以遗漏，公函、见证和法器记录有不同核验条件；传播成本按距离、商旅、通信能力和访问权决定。强力传讯法器可以快，但需要实际设施/使用者和代价，不能用它让一切默认全知。

叙事调度选择哪些已发生变化值得提醒，并可按明确规则引入外来条件；不任意改关系、库存或伤亡凑难度。玩家离开时不强制灾变，接近时不临时创造既定大事件。

## 10. 人口、历史与不同身份

### 10.1 人物连续，人口有容量

个体寿命、成长、婚育或收徒、招募、迁居、死亡与遗产逐步加入。首版人口增长优先做可追踪的外来招募和迁居，世代家庭待基础生活与死亡规则成立后再接。死亡先停止动作，处理背包/遗体、预约、职务、未结承诺、遗产与消息；不能简单删字典让义务一起消失。

长寿修士与凡人的时间体验不同：凡人换代、弟子出师、职位轮换、土地和机构延续都可发生。长寿不意味着所有社会联系按统一折扣衰减。旧掌门故去后，友情、正式授权、机构债务、法器公账和守门礼数分别处理。

### 10.2 历史压缩保留能改变未来的东西

永久或长久保留重要身份、有效权利和授权、未结债务与承诺、重大伤亡、领土变更、师承/家族、关键证据与来源。重复吃饭和日常搬运可按人物/时期/类型汇总，过期噪声清理。

压缩不能删掉仍被事务引用的证据，也不能把不知情者赋予全知历史。死者可以只留下摘要与必要引用，不要求加载完整生活日志。压缩前后对关键决策的输入含义相同；“系统忘记”与“人物忘记”是不同过程，后者需要明确规则。

### 10.3 身份是同一规则下的不同处境

杂役、农户、商旅、散修、管事、宗主、流亡者和军队统领共用身体、物资、行旅、交互和后果，区别在起点、职责、权利、技能、关系、已知消息与资产。每个正式可选身份必须有至少一条生计、成长、冲突和失势后的去路。

经营权来自雇佣、任职、所有权或他人接受的命令；玩家不能只因打开经营界面就能指挥所有同门。操作可以是本人直接行动、向同伴下令、安排授权岗位，或提交组织计划。NPC 的顺从仍经过职责、能力、承诺和风险约束，拒绝要可理解。

多出身不是一次制作所有职业剧情，也不默认随时附身任意 NPC。以同一世界的身份测试开局证明规则成立；存续世界中角色转换、死亡后继承或新角色进入可作为独立功能，不能与新开档随机重建世界混淆。

2026-11-03用户已将主角跨世玩法定为[有限重生与新生候选](rebirth_and_new_lives.md)：世界只前进，机会耗尽结束本局，不能免费接管普通新人继续。出生/群落来源、小幅候选前跳和出生后成长分别结算；候选域/档位不因屠杀普通生命而自动归一到极品。当前区域模拟尚无该机制，普通迁居与新开局装配也不能冒充转生。

## 11. 有限规模、诊断和长期验收

### 11.1 先验证再扩大

下表是成文时建议的容量档位，供规划讨论，不是已验证能力、现行性能硬承诺或最终发行规格；现行压力预算和测试口径以[世界引擎执行计划](../../docs/archive/specifications/world_engine_execution.md)为准：

| 测试档 | 模拟与人口目标 |
|---|---|
| S0：当前回归 | 保留现有双聚落及其固定人物/事务，作为小型正确性基准 |
| S1：一小时切片 | 2–3 聚落、12–30 名持久 NPC |
| S2：系统 Alpha | 4–8 模拟区、60–150 名持久 NPC、本地人物不超过 40 |
| S3：1.0 候选 | 12–24 模拟区、约 12 聚落、3–5 个组织、300–600 名持久 NPC、本地人物不超过 60、现场战斗 20–30 人 |

模拟区、聚落和渲染块不等同。远区部队同时保存实际成员名单和可批算的群组状态；人数与伤亡必须互相校验。每一级还分开记录活跃事务、背景人口、建筑和在途队伍。超预算先限制新开局密度、缩小活跃现场和分散事件，不能把已形成关系的人物删除或换成随机替身。

人口和地图目标由总体计划统一选择并记录参考硬件；先测少量人物下的正确性，再选 1×/2×/4×及长时推进的实际上限。不能用一个静止视野微基准宣称大世界 60 FPS。正式性能目标同时测帧时间、模拟边界处理量、最大追赶延迟、内存、存档大小和读档时间。

限制候选计划、同时在办互动、传播扇出和单帧预算，优先队列/索引只在测量证明需要时引入。人物关系稀疏存储；组织之间只追踪实际往来；消息可聚合相同的低重要性通知；未访问空地没有单位节点。

诊断能回答：哪个过程消耗计算、物资从何而来、谁在占预约、为什么没生产、谁收到什么、某行动因何被选、哪条消息仍在途中。诊断信息不进入正式 NPC 知识或玩家可见真相。

### 11.2 必须通过的场景

| 场景 | 可判定的验收条件 |
|---|---|
| 玩家无操作推进 30 个游戏日 | 基础生产/消费、休息和事务继续；资源/人口变化有来源，等待可恢复或明确结束 |
| 一个地区失去粮源 | 先库存下降，再根据知情与能力补救；没有免费刷新，也不全世界同刻知道 |
| 两人/两商队争最后一份物资 | 仅一次实际取物；其他请求得到等待、改价或失败，不出现负库存 |
| 采集/生产/消费/外域贸易 | 期间源汇平衡可核对，配方投入与产出分别成立 |
| 有钱缺货、有货缺权限、有权缺执行者 | 三种障碍能分别发生，并有不同解决路径 |
| 跨区迁居途中保存及反复进出 | 只有同一个人和背包，职务与责任得到显式处理，不能两地同时工作 |
| 桥毁在商队出发后、消息到达前 | 行程真实受阻，人物在遭遇或获知时改变计划，未提前全知 |
| 城镇施工被断料/施工者受伤 | 已用材料与进度保留；预约清理或交接；不能直接变回未花钱蓝图 |
| 近区/远区分别运行同一供给测试 | 守恒、因果、重要耗时和约定误差达标；不要求每步轨迹相同 |
| 随机交互反复点击、读档和切换 | 同一条件实例不重抽；条件实际变化后才允许新决定 |
| 部队征调农户与返乡 | 劳力、人口、装备和补给同步变化，战争不复制兵也不免费恢复生产 |
| 玩家进出一场未完战斗 | 已发生伤势/消耗保留；无进场洗血、离场重抽、全军传送 |
| 敌强我弱、伏击、断粮、优势地形、可撤退 | 远战与现场的方向合理，多种种子的结果区间可比较 |
| 攻陷与撤出据点 | 实际执行者/仓储/服务/通路改变；撤离后控制可以再次变化 |
| 掌门死亡或被罢免 | 私人帮助、职位、授权、公账与礼数分别延续或争议，不统一清零 |
| 长期历史压缩前后加载 | 有效权利、未结责任和仍引用证据不丢失，个人知识不扩大 |
| 同世界身份测试 | 杂役、散修、商旅和管事各有可执行生计与失败去路，共用成本规则 |
| 多种种子推进 1 年；人口阶段再测 10 年以上 | 无负数/复制/无限增长/永久预约；失稳有可解释因果与自救行为 |
| 暂停、快进及模拟预算耗尽 | 所有领域遵守同一有效世界时间；欠账保留，不静默丢失时间 |
| 任一关键阶段中断存读 | 完整快照恢复并继续；坏档拒绝后原世界完整保留 |

长时测试用小世界/无头执行器加速，年度/世代测试是后续对应工作包的验收，不要求当前 Demo 已能运行百年。每次容量增加都保留双聚落快回归，避免只剩几小时才能执行的整体验证。

## 12. 落地依赖与收敛条件

最先需要补齐的是：可持续资源源汇、人物失败后处理、完整持久化边界与共同时间单位；这些分别支撑经营、战斗、行旅与长期运行。世界调度、社会记忆和账物骨架继续增量扩展，不先重写成 ECS、完整事件溯源或几十个 autoload。

市场依赖生产/消费/运输/货币归属；战争依赖身体/装备/补给/迁移与战斗；世代依赖死亡/遗产/职位/记录传承。缺依赖时用显式有限场景验证接口，不把假库存、临时血量或临时人口接入正式世界充数。

一项新细节只有改变具体人物或玩家的选择，才值得加入。若无法说明谁会因此改做什么、花什么、冒什么风险、留下什么后果，就先不实现。世界的自由来自规则能组合和被干预，而非每个现实细节都有一张表。
