# 八方向纸娃娃：验收与回传

本页是后置外部制作时的历史候选验收合同；当前使用代码像素示意，正式画风尚未确定，不要求用户现在交付。入口和当时的一图一提示词规范见[提示词索引](../README.md)。

本页用于外部文生图成果回收。本次每份编号提示词只输出一张八向表，需要的参考图由用户在网页实际附加；先验证一套能互相套合的八方向站姿，再扩大内容；生成成功、画面好看、合成图完整，均不等于素材已经能接入游戏。当前批次不要求用户制作全部动作或工程 JSON，外部模型无法稳定做到的项目如实标明，由开发侧判断修整或重做。

## 1. 首批范围与固定规格

首批仅交同一名 **25 岁成年人**的中性人形站姿母版，穿无装饰的贴身基础内衣；不要求全裸。随后在同一母版上验证一套常服、一顶帽子，以及“解剖左手持剑＋解剖右腰玉佩”这一组非对称配件。每类均须覆盖八方向，暂不批量生产整套动作、更多人物或大量衣饰。11–13的32格表是八向×四相位参考，不是32个方向，也不是最终16帧动画。

| 项目 | 固定规格 |
|---|---|
| 画风 | 非像素手绘游戏素材；统一轮廓、材质、笔触与光照，按小尺寸可读性取舍细节 |
| 镜头 | 正交投影，固定相机俯角 **55°，相对地面水平面**；等价于离天顶方向 35°，没有透视缩小 |
| 转向 | 只旋转角色；相机、俯角、缩放、灯光位置和画幅不随方向改变 |
| 单向画布 | 256×256 PNG，可作为已有候选回传格式；本次提示词统一八向一张表，透明边距保留，不按人物外框单独紧裁 |
| 本次站姿八向表 | 1024×512，4 列×2 行，每格 256×256，无间距、边框或方向文字 |
| 八向顺序 | 上排 `N NE E SE`，下排 `S SW W NW`；屏幕上方为北，N 看背面，S 看正面 |
| 脚点 | 每格 `[128,174]`，即脚底接地中心；不是脚踝、头顶或人物外框中心 |
| 人物高度 | 站姿母体从足底到头顶约 120 px；帽子、头发附饰和剑不用于反向缩放身体 |
| 姿态 | 同一自然站姿、同一身体比例，双足、双手位置先锁定，添加衣帽配件时不重摆身体 |
| 原生显示 | 后续统一规范化为 96×96、脚点 `[48,65]`，角色实显约 44 px 高 |

256→96 的统一比例是 0.375，120 px 身高约为 45 px，原脚点 y=174 则变为 65.25。开发侧会统一处理约 0.25 px 的对齐差，不要求外部模型凭提示词准确处理这一亚像素；不能逐个方向拉高、压扁或另裁尺寸，来凑一个看似相同的外框。

## 2. 分步骤制作的两种成果

**合成展示图**用于判断形象、透视和遮挡。先交01的八方向母体，再按当前编号文件分别制作常服/戴冠/剑佩/蓑衣效果表；未要求把所有配件合并在一张图，也不用一次交齐。每个文件只生成一张八向表；展示接触表可带方向标签，但标签不能进入素材原图。

**完整可替换层**用于真正换装，必须与同一方向母体使用同一画布、脚点和姿势：

| 层 | 必须保留的内容 |
|---|---|
| 母体 | 内衣、身体、头手脚完整；加衣、加帽之前的原始母版仍保留，不被抹去 |
| 常服 | 衣身与袖子是独立透明层，服装本身应完整；不能带进皮肤、头发或背景 |
| 帽子 | 与头部套合的独立透明层；脱帽后母体的头与头发仍完整 |
| 左手剑 | 独立剑体、护手、剑柄，握点对准母体左手；不把一只新手画在剑层上 |
| 右腰玉佩 | 独立挂绳与佩玉，连接母体右腰；不能把腰带和躯干一起抠进配件层 |
| 必要遮挡片／遮罩 | 前后穿越的剑、袖、挂绳等可另分前后片，或给对应遮罩，并说明层序与方向 |

完整层并不表示每个部件必须永远盖在人体上。母体原图应保留可复用内容，组合时再由分片、层序或遮罩处理遮挡。例如远手应被近侧衣身遮住，不能为露出剑而把远臂强行挪到身体前方。若剑既在躯干前又绕到躯干后，单张整剑贴在最上层无法满足要求。06合成展示的握柄手指与01放松手不同，开发侧须据此制作持物手局部变体和必要遮罩；07剑层仍不夹带手部。本轮不额外增加手部图像任务。

**不能从穿戴完成的合成图直接抠出可见衣片，冒充完整服装层。** 被身体、袖子、帽檐或挂件挡住的区域，并没有因此获得可用的底层内容；仅回传可见碎片会在脱帽、卸剑、换衣时露洞。模型补出的隐藏结构只能作为合理候选，无法唯一恢复参考图没有展示的内容，需要开发侧核对或补画。也不能在分别生成各层时，让模型顺便重新生成另一具身体。若外部工具只能得到合成图，仍可原样回传，但须标为“形象候选，未分层”，开发侧不会将它记作已可换装。

## 3. 回传前的人眼检查

无需先写代码，按下列项目看图即可。做不到的项目在说明中标出，不要为勾选清单而修改或隐藏原始结果。

### 身份、相机与八方向

- [ ] 确实是同一名成年人：身高、头身比、肩宽、脸型、发型、肤色和内衣结构没有换向变人。
- [ ] 八个方向齐全；NE、SE、SW、NW 是各自的斜向，不是正侧面随便改名。
- [ ] N 主要看后脑与后背，S 主要看脸与前胸；俯角、能看见的头顶比例及地面视角一致。
- [ ] E 与 W、NE 与 NW、SE 与 SW 不是把已经包含剑佩的整个人水平翻转所得。
- [ ] 八向脚点、身体比例与站姿一致，原点不因头发、衣摆或剑刃伸出而移动；所有部件均未裁边。
- [ ] 不含人物旁的另一个分身、参考线、标注、文字、水印、地面底座或烘焙到身体里的大阴影。

### 解剖左右与遮挡

- [ ] 南向看正面时，角色左手在**画面右侧**，剑柄由这只手握住；右腰玉佩在角色自身右腰，即画面左侧。
- [ ] 北向看背面时，角色左手在**画面左侧**，右腰在画面右侧；转身没有把剑换手或把玉佩换腰。
- [ ] 所有斜向与侧向都能追踪同一持剑手及挂绳根部；远侧部件允许合理地被挡住，不要求八向都把玉佩完整亮出。
- [ ] 握剑时手指与剑柄相接，没有悬空、多指、多臂、剑柄穿掌或给人物加出另一只手。
- [ ] 帽檐、头发、近远手、衣袖、剑与玉佩的遮挡符合这一方向；没有“所有配件永远画在最上面”。
- [ ] 分别关闭帽、剑、玉佩，再关闭常服，剩下的母体仍完整；关闭配件不带走手、头发或腰部。

### 原图和游戏尺寸

- [ ] PNG 原文件保留，没有经聊天截图、JPEG、网页预览截图或有损压缩重新保存。
- [ ] 背景若宣称透明，透明区域有真正的 alpha；棋盘格不是画进图片中的像素，白底也不是“透明白色”。
- [ ] 透明边缘没有大片白边、黑边或残影，半透明处不夹带原背景色；不要把柔和边缘全部硬切成锯齿。
- [ ] 在约 44 px 的人物显示高度仍能辨认身体朝向、衣服形状、帽子与持剑侧；不靠放大数倍后才能看到的纹样支撑差异。
- [ ] 明暗背景上都可读，身体比例不靠厚重描边补救，发光、光晕、投影等效果没有混入必须调色的衣服底层。

如果工具不支持透明输出，保留原始单色背景版本并说明背景色，不自行声称已经得到透明Sprite。开发侧可评估抠图成本；在透明度修整和复核前，它仍是候选素材。

## 4. 一次回传的文件组织

最简单的回传方式是直接交按编号生成的原始PNG，并说明哪张满意、哪张有问题。下面目录与信息模板供整批交接时选用，不要求先完成这些记录才能交第一张图。本次每个编号文件只生成一张八向表；如果已有旧版单向候选也可保留，不用为它重复生成。若尺寸或排列未达标，保留原图、注明实际情况，不先覆盖原始结果。

```text
reol_character_candidate_01/
├── originals/                     # 外部工具原始 PNG；保留原文件名也可以
├── body/                          # body_n.png ... body_nw.png，或 body_eight.png
├── robe/                          # robe_n.png ...，或 robe_eight.png
├── hat/                           # hat_n.png ...，或 hat_eight.png
├── sword_left/                    # 完整剑层；如需 far/near 分片，一并保留
├── jade_right/                    # 完整挂绳/玉佩层；同上
├── masks/                         # 如有：遮罩、前后片与对应关系
├── composites/                    # 组合展示；不可替代上述完整层
├── prompts.md                     # 实际使用的提示词、负面词、每轮修改与参考图对应
├── generation.json                # 已知生成信息，不知道的字段写 null 或“未知”
├── rights.md                      # 来源、服务条款或用户授权范围
└── notes.md                       # 哪张最接近目标、已知错误、层序和待开发修整项
```

`generation.json` 可直接使用下面的最小模板；一个工具或一轮参数对应一个记录，若各方向种子不同应逐图记录，不要伪填一个统一种子：

```json
{
  "candidate_id": "reol_character_candidate_01",
  "provider": "填写服务或工具名",
  "model": "填写模型名",
  "model_version": null,
  "generated_date": "YYYY-MM-DD",
  "seed": null,
  "actual_canvas_size": [1024, 512],
  "grid_columns_rows": [4, 2],
  "direction_order": ["N", "NE", "E", "SE", "S", "SW", "W", "NW"],
  "camera_depression_degrees": 55,
  "claimed_foot_origin": [128, 174],
  "reference_files": [],
  "known_limitations": []
}
```

需要保留模型版本和 seed **如工具提供**；工具不公开这些信息不意味着回传无效。提示词保留真实用过的版本，包括用于锁定人体和补画的参考图名称。版权资料记录生成服务的具体条款链接、可取得的版本或日期、参考图来源及授权；自有参考图也注明属于用户。有疑点只标记待核，不编造可商用结论，不随意给素材或整个项目冠以 CC0、MIT。

回传时不用提供 API key、账号密码、付费凭证或其他密钥。授权说明应是素材使用范围，例如“这些参考图由我创作，允许用于本项目及商业发行”；仅有“我授权使用生成图”不能替代对参考图和服务限制的核对。

`notes.md` 最少写清：

1. 哪一组是希望采用的母版；其他图是参考、候选还是失败版本。
2. 实际是否透明、是否分层、是否完整八向，尺寸和脚点有没有已知偏差。
3. 剑、玉佩的实际持有侧，可能错误或被遮住的方向，以及前后片的合成次序。
4. 哪些内容希望保留；哪些可以由开发侧对齐、补边、抠图或退回重做。

## 5. 开发侧验收分级

| 结论 | 达到的条件 | 接下来做什么 |
|---|---|---|
| 形象候选 | 可查看的原图、生成与来源信息；允许尚未分层或存在技术偏差 | 选定一组视觉目标，列明缺陷，继续修图；不替换运行素材 |
| 站姿技术通过 | 真八向、统一母体与脚点、真 alpha、完整替换层；非对称组合和遮挡逐向通过 | 离线规范化到游戏合同，制作检查报告与接触表，接入单角色验证 |
| 首批实机通过 | 原生尺寸、玩家/NPC和纸娃娃预览共用采样，在真实背景中换装、转向正确，资源预算可接受 | 冻结母版与导出合同，再逐动作扩展，不马上批量所有衣饰 |

开发侧会检查文件尺寸、透明通道、图集格数、裁边、重复与方向覆盖，量测并统一脚点；保存未修改原图与变换记录。脚点/身高有系统性小偏差可统一对齐，脸型变人、四肢改变、镜头漂移或解剖左右错误不能靠拉伸、镜像和重命名修成合格。

自动化检查只能发现部分技术错误。八张图不完全相同，也不能证明是真八向；E/W 不是逐像素镜像，也不能证明剑始终在同一只手。必须叠合母体、按顺序快速切换方向，并在真实游戏尺寸逐向检查。没有实际运行前不标记“实机通过”。

首批剑佩在游戏里仍是**技术外观预览**，不向普通人物授予真实武器、玉佩、持有权或任何能力。正式换装必须继续引用原物品与实际穿戴状态。

## 6. 通过站姿后，再制作动作

后续内容目标为每方向待机 8 帧、行走 16 帧、短动作 16 帧；这不是本次回传要求，也不是让外部模型一次生成全部内容的建议。当前11–13各用一张表给出八向×四个关键相位，先验方向/姿态，再由开发侧确定完整帧生产；失败时回到同一母版修整。

每一动作帧都须有对应的母体姿势，衣服、帽子、持剑和玉佩使用同一帧与相位；不能给人体和每件衣服各生成一段独立动画再强行拼合。移动距离、脚点、解剖左右与遮挡仍需逐帧验收，方向切换不能把动作相位归零。

GIF 和视频可以辅助判断运动，但不能替代带透明通道的逐帧 PNG、完整图层及帧序/时长说明。它们可能丢失 alpha、改帧率、丢重复帧或混入运动模糊；不能仅把视频截帧便记作完成了可换装动画。
