# 世界装配与领域接入合同

本页说明各框架共用的内容、装配与接入约束；未接能力属于实现目标，实际接入看[技术总表](../../../status/technical-status.md)。领域职责只在[顶层框架](../../../engineering/architecture/05-framework-domains.md)维护，建设依赖和完成标准只在[基础建设计划](../../../plans/foundation-priorities.md)维护。

## 内容、运行与呈现

在Godot上复用现有GDScript规则、原状态所有者、共同时间和存读。Godot继续负责窗口、输入、渲染、音频与基础编辑。

```text
定义/地图/模板/开局 → 校验与独立候选装配 → 各领域原状态
                                                ↓
                                   实际观察与有限认识投影 → 呈现
输入/NPC策略 → 已支持的意图 → 行动协调 → 原领域提交变化
开发编辑 → 同一内容草稿或受控开发命令 → 同一世界合同
```

每个框架随运行能力提供必要编辑、观察和错误定位入口。创作工具使用已实现规则，新的身体结构、传播规律或动作语义仍由所属领域补代码与验证。深层玩法、海量内容和正式视听按产品层次建设。

## 定义与实例

- 共同引用回答对象的原身份、类别、所有者、位置/包含关系、占地和已声明能力；不为每格地块建立人物式实体或单独Node。
- 定义保存材质、身体形态、体型、已支持感知/移动/交互能力和响应参数；实例保存实际位置、数量、伤势、储量、经历和个人知识。原始事实、动态状态、派生能力和观察者所知分别成立。
- 不同生命和对象只接其实际能力，不强塞同样的饥饿、装备或灵气字段；缺少能力、无法判定和真实零值分别返回。
- 会话绑定实际使用的数据定义、开局基线、地图生成描述和版本/digest。编辑同ID定义不应静默重解释现有实例；新世界和预览可选择新包。数据包隔离不承诺执行任意历史规则代码。
- 仍直接读盘的规则和普通呈现限制属于对应框架及公共装配合同的缺口，集中登记技术总表，规格页不再另存一份过期进度。

## 独立装配与恢复

1. 校验定义、开局、地图描述和外部引用，建立独立候选；输入不得借活世界的人员、位置或库存补齐缺失事实。
2. 按原领域的初始化合同生成实例，检查地形、占地、净空、容纳、ID及包含链。生成失败不发布半个对象；视图在候选接受后绑定。
3. 新局只发行开局明确给出的库存、任职、知识和初始状态；恢复从档内事实重建，不再次发行开局物资或补造经历。
4. 从候选原状态重建占地、来源、参与/到期等派生索引，按共同时间核对跨域引用、原成本、位置和在途占用，成功后才替换活世界。
5. 保留地图种子、生成器/内容版本和不可重建变化；显示区块可卸载，原对象和必要远区过程仍存在。支持的旧输入按[兼容政策](../../../engineering/compatibility.md)转换或明确拒绝，原fixture不改写。

具体原有入口由`ReolContentDB`、`ReolWorldAssemblyInputs`、`WorldRestoreFactory`和`WorldSessionSnapshot`承担；这些入口的存在不证明任意地图或多区装配已完成。

## 物品、数量与包含

数量条目与具有独特损伤/储量/铭记的实例保留各自语义，同一原物不同时计为两份。相容批次拆合保持数量、状态、保管及必要归属依据；物品发光、冷热和五行来源沿原位置链解析，场规则按环境合同实现。

保管位置和处分权限分开，委托搬运不自动成为私人财产。容器包含不得成环；容量、负重、透过率等只有实现对应规则后才开放。跨账本转移须保原物、原数量与在途责任，不据局部取放接口推断已经支持。

## 空间、运动与领域效果

地块、真实实体、用途区域和推导房间按[组合空间合同](../../../../design/systems/construction_and_space.md)区分。碰撞占地、接触位置、画面和环境范围可分别投影，覆盖格指向同一对象。

世界空间提供真实地形/结构/净空等事实；单位行动根据身体尺寸和移动方式判断通行、维护路径和执行移动。局部路径与跨区域路线按实际需要组合，预算不足保留待处理工作，不借不可达触发无规则穿墙或瞬移。特殊穿行由实际能力规则成立。连续位置与格子各自用途遵循[现行架构](../../../engineering/architecture/03-time-space-presentation.md)，算法选择由实际范围与测量决定。

命令包含发起者、对象、条件、过程与结果引用等所需信息；受理、理解、意愿和实际执行分别成立。行动协调接近、预约、占用、时序和取消，施工、采集、交易及其他效果仍由原领域提交，不强迫全部动作采用相同阶段或复制旧过程。

## 接入检查

框架接入应能说明：本领域原事实是什么；读取哪些原接口；变更向哪些消费者使依赖失效；共同时间/取消和失败如何处理；哪些状态保存、哪些索引恢复重建；玩家能通过何种实际观察获知结果。

同能力不同内容应复用接口。新增机制归入相应领域并验证跨域效果；算法、编辑面板或单条事件链完成，只证明对应模块范围。框架验收依基础建设计划，具体能力和证据依状态入口。
