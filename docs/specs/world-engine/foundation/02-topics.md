# 结构组合与联合验收参考

本页是环境框架及建筑/空间/行动交接的详细技术参考，未接部分为候选。职责与原owner按[顶层框架](../../../engineering/architecture/05-framework-domains.md)，建设出口按[基础建设计划](../../../plans/foundation-priorities.md)，实际接入和证据按技术总表/BASELINE。

## 6. 自动围墙与功能空间

首选内置TileMapLayer Terrains或四邻位掩码，自动端头、直墙、角、T/十字。增删刷新所在格/邻格，包括跨chunk。逻辑墙归原施工域，贴图不反向决定墙、碰撞或保温。

拖线/框选生成逐格蓝图，反馈非法点和成本；施工仍走原材料、工时、人员和中断，蓝图不提前挡路/保温。房间由真实围合/屋顶/开口派生，功能由家具能力、储物、人员、权限和工作组成。先统一值事房/工地空间查询，不凭命名自动生产，也不先列房型百科。

## 7. 按领域组织联合验收

建筑领域提交真实墙门顶、房间结构和材料变化，世界空间更新占地/开口等事实，环境结算来源与实际响应，单位行动复核通行/接触和相关过程，认识领域过滤可观察结果。各领域职责见顶层框架，完成标准见基础建设计划，不在本页再排W0–W5顺序。

本节的多源、房间、移动及近远区检查是环境和相应消费者的内部验收参考。按声明支持的能力选择负载；未实现的房间、携源或受体规则仍保留为候选，不因单个算法通过宣布框架完成。

自动验收用参数化地图/来源组合：原物资/灵气实际账、场取最大值/响应有界、更新顺序、结构、跨块、移动路径、整段/分段/中途存读、近远误差及容量/预算失败。新环境不再以全世界热量守恒作为门禁，但同一时间轨迹仍须满足声明精度内的连续性。

冷热测试覆盖圆形欧氏距离/衰减边界、单源/八源同位等强、最强者移走后次强接替、同级冰火抵消/强弱交换、季节中性/冷端下限与热端扩表、反复搬物不叠高；室内验一房一温、按面积平均净等级、普通家具不稀释、火冰墙/共享墙、门/拆合/开敞、长时回归及存读。新模型不要求复现旧模型未来，历史证据不改写。

普通主局验可见变化：冷热、照度、五行环境影响调试图和原因查询、搬物/改墙/开门、关特效不改规则、远行和重启。开发热图可精确读数，玩家仍依观察/工具/阅历获知，不强迫以热图玩游戏。

首轮测512×512，并递增活跃单元、源与结构变更；记录硬件、模拟毫秒/步、p95/p99帧时、活跃内存和存读耗时。性能目标沿项目现有预算，未测前不承诺百万平方公里逐格模拟、无限来源或具体帧率。

五行场单列稠密来源候选档位：512×512/1024×1024/2048×2048，覆盖区每格至少一堆确有贡献的地面物品，约26万/105万/419万来源。再将每堆同类数量设为1/4/16/10000，核对源数量和强度不因堆内数量增加；不为此创建同数量的独立模拟实例。不同物品铺到不同合法地面落点，混合五行及半径的布局仍覆盖整片区域，不恢复异类同堆累加。普通地图仍固定512，较大档位先为隔离求解器压力原型，不冒称Main已扩容。五通道int64单层裸值分别10/40/160MiB，另计源图、双缓冲、对象、索引、候选及存档峰值，不能当总内存。小图按最终叠场规则与简单参照核对；大图测不同半径、邻堆重叠与跨块、遮挡/异质材质、静止与1%/10%/全部来源移动或改变，以及离场/存读连续性。实际摆放/移动/销毁改变场，修炼查询不扣场；静态缓存命中和大范围失效分别计时，不能只测无变化的缓存读数。较大档位须限时限内存逐级验证，现有冷热少源基准不作五行容量证据。

### 低收益复杂度检查（候选，未改代码）

恢复实施时先测通用路径，不强行为简化删机制：

- 普通材料以同质批次数量保存，不逐件运行；本轮不算人物内部辐射，也不为未开放的灵气积攒建立吸纳账和过程。
- 稳定来源与结构复用目标最大值，移动/取放/破坏使完整影响范围及跨块邻域失效；不可重建的响应残留和时刻仍保存，不用当前布局倒推旧环境。
- 候选采用少量可复用的半径/衰减预设，环境采样分辨率与画面、连续移动分开；特殊能力确有玩法需要再加异质传播。具体预设与误差仍需验证，不把所有材质影响都提前展开为五行两两反应。
- 已验孤立5×5/D4热压缩减少Q槽却未证明CPU/内存改善；最新方向是不再扩展旧守恒热场分支，先证明新max场和响应原型。旧路径只在实际迁入/退役包处理，讨论期不删代码，证据见BASELINE。
- 现有热/器物恢复的历史重复扫描尚未有函数级瓶颈证据；先决定新格式与必要历史，不为即将退役的全热量收据链再构建复杂索引，仍保原物账、防重复与坏候选拒绝。

现有局部灯光是少源、有界逐源查询，不能原样复制给百万地面五行来源，也不能给每堆挂Light2D。冷热、五行场强、可花灵气仍分域，不自动启用熔岩、燃烧、腐败等未设计后果来增加负载。

## 9. 自然日照的算法与接入参考

此处保留环境框架内自然日照模块的数学与接入参考，不构成独立顶层计划或当前通过证据；实际结果归BASELINE。整张地方地图只设一处宏观纬度/经度与中央经线，home/river不代表纬度带。`climate`定义2在原37路径内容包内增加`solar`，角度以千分度、透射以万分比、亮度以显式相对尺度表达。默认北纬30°、经度与中央经线0°、倾角23.5°，本历法春分日0；参数可由内容编辑，不依赖当前真实日期或OS时间。

太阳赤纬简化为倾角的年度正弦，春分日民用正午为零相位；经度相对中央经线每度平移太阳时4分钟。太阳高度满足`sin(h)=sin(latitude)sin(declination)+cos(latitude)cos(declination)cos(hour_angle)`，日长由几何地平线交点求解，极点与极界显式分类，不对不存在的日出取反余弦。取共同整数毫秒的年/日余数后才转浮点，输出量化为角度/相对照度；浮点投影不参与热量账本。

依据为[NOAA太阳位置公式](https://gml.noaa.gov/grad/solcalc/solareqns.PDF)的几何关系和经度时间偏移，以及[NWS曙暮分类](https://www.weather.gov/lmk/twilight-types)的太阳中心低于地平线6°边界。我们的季相位、零度几何日出、晴雨透射和明暗曲线是游戏简化，不使用NOAA完整历日、均时差、折射或实测气象，不能宣称天文台精度或lux。昼长是此时赤纬下的理想几何日长，不是跨一整天积分的精确日出预报。

`SimSolarRules`为无状态算术；`SimNaturalLight`从已接受世界的environment定义、物理elapsed_ms、原天气epoch/相位和施工屋顶读取。`total_relative=direct_relative+diffuse_relative`，只有总照度送到普通天色；屋面仅按内容定义压低该格自然光，不把进入房间改成全屏变暗，不模拟窗口/侧向散射。曙暮有弱漫射，深夜自然太阳照度为零；画面仍保留可读的夜间基色，不把像素色值当规则亮度。

普通场景DayNight、环境文字及当前可见地块观察读取同一规则。加载/换身份/移动后重读已接受世界；钟表目标领先物理时刻时不能显示未来天光。无缓存写档、第二时钟、光量存储或凭查询发行探索知识。当前包不改变Fog、NPC感知、植物生长、太阳供热、月光或局部法器光源；后续受体沿共同规则接入，不只改玩家视图。

日照随会话已接受的内容、地图与共同时间读取；恢复只接受当前明确支持的版本，不从磁盘补参数或补造历史光后果。具体根格式与迁入/拒绝范围以[兼容政策](../../../engineering/compatibility.md)和BASELINE为准，历史fixture保持只读。

验收覆盖赤道/中纬/南北/极区、春分/至日/年环、经度/午夜/安全最大时间、晴雨/屋面叠加、无副作用和混版拒绝；声明支持格式的进行中接续、坏候选不改活世界；普通新局日夜画面、暂停/读档重绑与完整停开。只通过数学用例不算普通运行出口完成。
