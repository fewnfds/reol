# Reol — 游戏愿景与范围（Direction v0.2）

> 状态：**方向已定稿（2026-11-01）**。2D 正交俯视 + 高度层、单机模拟、可暂停即时战斗。
> 详细技术分析：`docs/DIRECTION-V0.2.md`
> 已接受决策：`docs/DECISIONS.md` ADR-0013 ～ ADR-0019
> 下一步：M2（宗门生活）进行中 —— 数据层与 5 个具名 NPC 已完成，下一步需求/日程/JobBoard，见 `docs/ROADMAP.md`

---

## 1. 一句话

一个**修仙题材的 2D 正交俯视开放世界沙盒**：你是宗门/势力中的一员，从杂役到长老/掌门/散修/邪修；
世界在你不在的时候也运转；战斗是**可暂停的即时战斗**；美术简约，但系统深度像 RimWorld。

## 2. 玩家幻想

- **“我从杂役爬上来”**：挑水、砍柴、偷学、攀附、立功、晋升；身份决定日常。
- **“这个世界像网游一样活着”**：宗门有内政、势力有战争、NPC 有日程/关系/记忆、远处事件会传成传闻。
- **“我可以选择站哪一边”**：正道/邪道/散修/宗门；声望、敌友、通缉、师门恩义。
- **“战斗是我的选择”**：实时 + 暂停；走位、技能、地形、同伴；高阶强者能开“子弹时间”。
- **“每次开档不一样”**：世界种子、势力关系、事件、人物、秘境。
- **“低美术也能好玩”**：RimWorld 式系统生成故事，而不是靠堆美术。

## 3. 设计支柱

1. **身份决定体验（Role & Rank）**
   杂役/外门/内门/长老/掌门/散修/邪修，不只是数值差异，而是可用动作、对话、义务、权限、AI 反应都不同。

2. **活的世界（Living World）**
   分层模拟：World → Region → Settlement → Local → Detail；远区纯数据，近区才实例化；缺席事件算法结算。

3. **势力与声望（Factions & Reputation）**
   WoW 式阵营/敌友/声望；Warhammer 式简约内政；关系网会记住你的选择。

4. **可暂停的即时战斗（Real-time with Pause）**
   WC3 式可读性；暂停下令；子弹时间是高阶修炼者的能力，不是基础操作。

5. **低美术、高玩法（Low-art, High-systems）**
   2D 像素俯视 + 国风色盘；模块化角色/建筑；用系统、事件、关系、文字生成故事。

6. **平面世界，但有高度（2D + Elevation）**
   固定正交俯视，不旋转；正方形格 64×64；高度用 `elevation/altitude` 表达；飞行是 WC3 式视觉高度，不是 3D 空战。

## 4. 核心循环

### 4.1 分钟级
探索/巡逻 → 遭遇（战斗/对话/采集）→ 即时反馈（资源/修为/情报/声望）→ 继续。

### 4.2 小时级
回宗门 → 交任务/领贡献 → 修炼/突破 → 处理关系/内政 → 接任务/下山 → 处理事件（袭击/秘境/贸易）。

### 4.3 长期
杂役→外门→内门→长老/掌门，或叛出宗门/散修/邪修；
建立自己的势力/洞府；参与势力战争；探索秘境；追求更高境界。

## 5. 参考拆解

| 参考 | 借什么 | 不借什么 |
|---|---|---|
| **RimWorld** | 低美术高系统、Pawn 需求/工作/心情、事件导演、可读 AI | 纯 2D 站桩、过多 DLC 式系统 |
| **Dwarf Fortress** | 世界生成、历史感、系统相互作用、失败叙事 | 极端细节、ASCII、陡峭 UI |
| **Amazing Cultivation Simulator（了不起的修仙模拟器）** | 修仙 + RimWorld 式门派经营、风水/炼丹/事件 | 过多并行系统、复杂 UI |
| **Kenshi** | 开放沙盒、无主角光环、派系、基地+冒险 | 粗糙手感、过大数值跨度 |
| **Warcraft III** | 俯视视角、单位可读性、英雄技能、战斗节奏、飞行高度表现 | RTS 多线微操、竞技平衡 |
| **World of Warcraft** | 阵营/声望/敌友、任务、副本、世界感 | 真 MMO 的联网/副本规模 |
| **Tale of Immortal（鬼谷八荒）** | 开放世界修仙、突破、随机事件、人际关系 | 大量重复内容/刷 |
| **The Scroll of Taiwu（太吾绘卷）** | 世界/势力/关系网、传承、系统叙事 | 过度复杂的信息结构 |
| **Path of Immortality（觅长生）** | 时间压力、事件、炼丹/修炼循环 | 线性流程 |
| **Stardew / Necesse** | 亲切的日常节奏、建造/种植 | 纯休闲、无威胁 |

## 6. 已定方向（v0.2）

- **视角**：**2D 正交俯视（正方形格 64×64）**，固定俯视，WC3/SC 式可读性；相机**自由平移 + 缩放**，**不旋转/不俯仰**；玩家视野外战争迷雾。
- **高度**：每格 `elevation`（0–3），实体 `altitude`（0=地面，1=低空，2=高空）；渲染偏移 + 影子；飞行忽略地面障碍，地面近战不能打空中。
- **世界**：512×512 首区；64×64 区块；5×5 加载；远区纯内存/抽象模拟；无缝流式；尽量少过图/加载屏。
- **阵营**：WoW 式阵营/声望/敌友；Warhammer 式简约内政；玩家是势力一员。
- **身份**：杂役/外门/内门/长老/掌门/散修/邪修；数据驱动，后续多出身；Demo 从杂役开始。
- **NPC**：复杂关系网；脚本/效用 AI 优先；LLM 只做后期风味；AI 托管主角是后期功能。
- **战斗**：即时 + 暂停；局部慢放是后期高阶技能（敌人减速、玩家正常）；小规模（玩家 + 3–5 同伴 vs 5–10 敌人）。
- **题材**：修仙；低美术高玩法；简约但有辨识度的国风美术。

## 7. 首个可玩版本：“一山一宗”

> 目标：**45–60 分钟**，证明“杂役逆袭 + 活宗门 + 可暂停即时战斗 + 大世界流式”的核心幻想。
> 这是 vertical slice，不是完整游戏。

### 必须有
- **512×512** 区域；64×64 区块；5×5 加载；战争迷雾；至少 3 级高度。
- **一个小宗门**：山门、练功场、丹房、杂役院、后山。
- **玩家：杂役**；5 个具名 NPC（师父/师兄/对头/商人/神秘散修）+ 普通弟子。
- **日常**：杂役工作（挑水/砍柴/扫地/送药）、修炼、吃饭/睡觉、接任务。
- **成长**：1 条修炼线（炼气→筑基或类似）、2 个技能、1 次职位晋升（杂役→外门）。
- **战斗**：实时 + 暂停；1 个敌对势力前哨；1 个后山秘境/洞府；掉落/资源；至少 1 个飞行/高地场景验证高度规则。
- **阵营**：声望、宗门贡献、1 个敌对势力、1 个中立商人。
- **世界**：昼夜、区块流式、存档/读档、远区事件至少 1 条传闻。
- **UI**：HUD、对话、任务日志、声望/职位、简单地图。

### 明确不做（v0.1）
- 联机、LLM 核心 NPC、AI 托管主角。
- 真 3D、自由旋转/俯仰、体素破坏、真 3D 空战。
- 掌门内政/大规模战争。
- 多宗门/多地图/多生物群系。
- 完整修炼树/炼丹/炼器/阵法（各留 1 个最小循环即可）。
- 100+ NPC、完整世界模拟、模组 API。

## 8. 已拍板（2026-11-01）

| # | 问题 | 决定 | ADR |
|---|---|---|---|
| 1 | 渲染 | **2D 正交俯视 + 高度层**；固定角、平移/缩放、不旋转 | ADR-0013 |
| 2 | 联机 | **单机模拟的网游感**；远区算法结算，不做联机 | ADR-0010 / 0014 |
| 3 | AI NPC | **脚本/效用 AI 优先**；LLM 后期只做对话风味 | ADR-0018 |
| 4 | 起始身份 | **杂役**；架构支持后续多出身（数据驱动） | ADR-0016 |
| 5 | 世界尺寸 | **512×512 首区**；区块流式，后续可扩 | ADR-0015 |
| 6 | 美术 | **像素俯视 + 国风色盘**；先占位，后细化 | ADR-0013 |
| 7 | 飞行/高度 | **WC3 式视觉高度 + 规则层**，不做真 3D 空战 | ADR-0013 / 0017 |
| 8 | 内容生产 | 数据包 + schema + 世界生成管线；agent 只产数据 | ADR-0019 |

**不再讨论**：3D 渲染、联机、LLM 核心模拟、体素世界。除非出现推翻性证据，否则按上表执行。

## 9. 设计原则（用来砍需求）

- **身份先于数值**：每个职位必须改变可用动作/对话/义务，不只是 +10% 攻击。
- **远区抽象，近区细节**：不要模拟每个 NPC 的每秒钟。
- **失败产生故事**：被逐出宗门/受伤/结仇，不等于读档。
- **低美术不等于低风格**：色盘、剪影、UI、VFX 要统一。
- **每个系统必须改变玩家决策**，否则只是背景噪声。
- **先做可玩循环，再做世界模拟**；世界模拟是乘数，不是地基。
- **数据驱动，但不过度抽象**；先写能跑的 100 行。
- **能用 2D 规则解决，就不要上 3D**；高度是数据 + 视觉，不是物理。
