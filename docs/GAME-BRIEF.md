# Reol — 游戏愿景与范围（Draft v0.1）

> 状态：**草案**，用于对齐方向，不是最终 GDD。
> 日期：2026-11-01
> 当前里程碑：**M0 — 脚手架与可运行的空场景**

---

## 1. 一句话

在一个会自己运转的开放世界里，你既是一个可以亲自冒险的角色，也是一个殖民地/聚落的经营者：
探索、建造、招募、战斗、贸易、讲故事，让这个世界在没有你的时候也继续活着。

## 2. 玩家幻想

- **“我有一个家”**：从一块空地开始，造出能住人、能生产、能防御的聚落。
- **“这里真的在运转”**：NPC 有自己的需求、工作、关系和小故事，不是站桩对话机。
- **“我可以亲自去冒险”**：离开聚落，探索遗迹、打怪、做任务、带战利品回家。
- **“每次开档都不一样”**：地图、事件、人物、冲突由种子和系统共同生成。
- **“我的选择留下了痕迹”**：建筑、关系、阵营、世界状态都会持久化。

## 3. 设计支柱（Pillars）

1. **活的世界（Living World）**
   世界在玩家不看的时候也按规则推进；NPC 有需求、工作、记忆和关系。

2. **建造与经营有重量（Base with Weight）**
   建筑不是装饰：影响路径、温度、储物、生产、士气和防御；布局有取舍。

3. **冒险与经营互相供养（Adventure ↔ Settlement）**
   外出冒险带回资源、配方、人物和情报；聚落提供装备、补给和复活点。

4. **可读的战术战斗（Readable Combat）**
   参考 Warcraft 的视角与信息可读性：单位、威胁、技能、地形一眼能看懂；实时 + 暂停。

5. **沙盒优先，叙事托底（Sandbox First）**
   系统生成事件为主，手写主线只做轻量引导，不强迫玩家按剧本走。

## 4. 核心循环

### 4.1 分钟级（Moment-to-moment）
探索 → 采集/拾取 → 遭遇（战斗/对话/解谜）→ 即时反馈（掉落、经验、情报）→ 继续探索。

### 4.2 小时级（Session）
回聚落 → 卸货/治疗 → 分配工作 → 建造/生产 → 接任务/准备出征 → 处理事件（袭击、访客、疾病）。

### 4.3 长期（Campaign）
扩张聚落 → 解锁科技/配方 → 招募特殊 NPC → 处理阵营关系 → 推进主线/发现世界秘密 → 应对更大威胁。

## 5. 参考拆解（只借该借的）

| 参考 | 借什么 | 不借什么 |
|---|---|---|
| **Dwarf Fortress** | 世界生成、历史感、系统相互作用、失败也能讲故事 | 极端细节模拟、ASCII、陡峭 UI |
| **RimWorld** | 殖民者需求/工作/心情、事件导演、可读的 AI、模组化数据 | 纯 2D 站桩、完全随机叙事、过多 DLC 式系统 |
| **Kenshi** | 开放沙盒、无主角光环、派系、探索与基地结合 | 粗糙的操作手感、过大的人类数值跨度 |
| **Warcraft / WC3** | 俯视角、单位可读性、英雄技能、战斗节奏 | RTS 的多线微操、竞技平衡 |
| **传统 RPG** | 成长、装备、任务、对话、地牢 | 线性剧情、过场动画堆砌 |
| **Stardew / Necesse** | 亲切的建造/种植循环、日常节奏 | 纯休闲、无威胁 |
| **Microverse** | LLM NPC 社交/记忆的技术参考 | 依赖外部 LLM API 的核心玩法 |

## 6. 首个可玩版本（v0.1 “One Camp”）— 范围锁死

> 目标：**30 分钟内能完整体验一次“扎营 → 生存 → 建造 → 应对一次袭击 → 存档”的循环。**
> 这是 vertical slice，不是 demo，不追求内容量。

### 必须有
- 一张 **128×128** 的手工/半程序生成地图，至少 1 种生物群系 + 树林/石矿/水。
- 1 个可操控玩家角色：8 方向移动、碰撞、相机跟随、基础攻击。
- 3 个殖民者 NPC：饥饿、疲劳、心情三条需求；能自主寻找并执行 **搬运、砍树、采矿、建造、吃饭、睡觉**。
- 1 个聚落区域：储物区、3 种建筑（墙、床、工作台）、1 种生产配方。
- 昼夜循环 + 简单的夜间威胁。
- 1 次脚本化/半随机袭击。
- 存档/读档（版本化 JSON）。
- HUD：时间、速度、选中单位、需求、工作优先级、建造菜单。
- 无头测试 + 至少 1 张运行截图。

### 明确不做（v0.1）
- 联机、账号、云存档。
- 多地图/多生物群系/大地图无缝流式（先单地图）。
- 复杂温度/气体/流体模拟。
- 完整技能树、附魔、装备词条。
- 大量手写剧情/配音/过场。
- 模组 API、创意工坊。
- 3D / 2.5D 高度层（先纯 2D）。

## 7. 开放问题（需要用户拍板）

> 下面是**建议默认值**。没有特别说明时，AI 按默认值推进，并在 `docs/DECISIONS.md` 记录。

| # | 问题 | 建议默认 | 备选 |
|---|---|---|---|
| 1 | 视角/美术 | **2D 俯视，32×32 像素风**，先用 Kenney/LimeZu 占位 | 16×16、手绘 HD、2.5D |
| 2 | 玩家角色 | **单角色可操控 + 可指挥殖民者**（Kenshi/RimWorld 混合） | 纯上帝视角、纯单角色 ARPG |
| 3 | 战斗 | **实时 + 空格暂停/战术慢放** | 回合制、纯即时 |
| 4 | 世界生成 | **手工骨架 + 程序生成填充**（地图/POI/事件） | 全手工、全程序 |
| 5 | 叙事 | **沙盒事件为主 + 一条轻主线** | 纯沙盒、强主线 |
| 6 | 殖民地规模 | **v0.1 3 人，v1 8–12 人** | 1 人、50+ 人 |
| 7 | 难度/失败 | **失败推进故事**（殖民者死亡/聚落被毁不等于 game over） | 硬核永久失败、轻松无死亡 |
| 8 | 平台 | **Windows 优先**，后续 Linux/Web | 首发多平台 |

**请优先确认 1、2、3。** 这三个会决定美术、输入、相机、AI 和战斗架构。

## 8. 设计原则（用来砍需求）

- **能用一个系统表达，就不要做两个。**
- **先做能被玩家感知的 20%，再补模拟深度。**
- **每个系统必须有“玩家决策”**，否则只是背景噪声。
- **失败要产生故事，不要只产生读档。**
- **数据驱动，但不要为了“未来可能”做过度抽象。**
- **性能预算从第一天开始**：60 FPS，模拟 tick < 8ms。

## 9. 当前里程碑

- **M0（本周）**：工具链、空场景、测试、文档、MCP。
- **M1（2–4 周）**：玩家移动 + 相机 + 地图 + 时间。
- **M2（4–6 周）**：殖民者需求/工作 + 储物 + 建造。
- **M3（3–4 周）**：战斗 + 袭击 + 存档 + 30 分钟可玩切片。
